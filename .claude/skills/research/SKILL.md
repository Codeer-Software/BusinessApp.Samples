# 制度を調べて記録する

**制度は記憶で決めない。省略できる場面は無い**（[CLAUDE.md §2](../../../CLAUDE.md)）。
**迷ったら推測せず開発者に聞く——開発者が法令・税制の最も確かな確認先である。**

**このスキルは順番と道具の打ち方だけを持つ。** 規則と格付けは文書が持つ——
**いつ・何を調べるか**は [32](../../../docs/32_調査のルール.md)、
**何を根拠にしてよいか・出典の書式**は [00 §4-9](../../../docs/00_ドキュメント規約/本文.md)、
**どの版で動くか・条項の記法**は [80](../../../docs/80_参照法令一覧.md)。

## 1. 先に、既にあるものを引く

**書く前に、それが既にどこにあるかを数える**（[30 §9](../../../docs/30_作業のルール.md)）。

1. `docs/research/` を**論点の語**で `git grep` する（日付ではなく語で引く）
2. [80 §2・§2-1](../../../docs/80_参照法令一覧.md) に、その法令の版と出典があるかを見る
3. `docs/decisions/` と [qa/02](../../../docs/qa/02_自己レビュー記録.md) を同じ語で引く
   ——**既に開発者が決めていることを、問いに立て直さない**（[30 §11](../../../docs/30_作業のルール.md)）

**あったら、そこに足す。無いときだけ新しいリサーチを起こす。**

## 2. 一次情報に当たる

**根拠にしてよいものは [00 §4-9](../../../docs/00_ドキュメント規約/本文.md) が決めている。ここには写さない。**
**取り方**だけを置く。

| 何を | どう取るか |
|---|---|
| **法令の条文と版** | **e-Gov 法令 API**。`law_revisions/<法令ID>` で改定の一覧、`law_data/<law_revision_id>` で条文。**手順は [80 §1-1](../../../docs/80_参照法令一覧.md)** |
| **通達** | **e-Gov に無い。** 国税庁の HTML。**Shift_JIS（CP932）で `WebFetch` が読めない**ので `curl … \| iconv -f CP932 -t UTF-8` かブラウザ（実測は [32 §1](../../../docs/32_調査のルール.md)） |
| **Q&A・一問一答** | **e-Gov に無い。** 国税庁。**多くは PDF** なので下の行の取り方になる |
| **告示** | **国税庁でも HTML でもない。** 財務省の原本 PDF で、**スキャン画像なら本文は取れない**——取れなければ未確認として残す（実例: [電子帳簿保存法のリサーチ](../../../docs/research/2026-08-23_電子帳簿保存法.md) §14 の 1） |
| **PDF** | `uv run --with pypdf --with cryptography python <スクリプト> …`（**`cryptography` を落とすと国税庁の PDF は 1 ページも取れない**。[tools/README](../../../tools/README.md)）。抽出スクリプトはスクラッチパッドへ |
| **市販ソフトの実装** | 公開マニュアル・ヘルプ。**何社を見たかを控える**（[32 §3](../../../docs/32_調査のルール.md)） |

- **不在の主張（「〜は書かれていない」）は `WebFetch` に言わせない**——**原文を自分で取って探す**
  （規則と実例は [32 §3](../../../docs/32_調査のルール.md)）
- **`curl` が 403 を返したら、まず `User-Agent` を外して打ち直す。**
  **付けたほうが落ちる相手がある**（2026-09-16 の実測。マネーフォワードは UA 付きで 403、素の `curl` で 200）
- **e-Gov は施行日で条文が切り替わる。見た版の施行日を控える**
- **改正法の附則は、被改正法の全文の附則欄に、条が関わる法律ごとに分かれて載る**
  ——検索が 0 件でも「e-Gov に無い」と書かない（出典は条ごと。[80 §2-1](../../../docs/80_参照法令一覧.md)）
- **他法を改正する法令の略称には、法令番号を必ず添える**（[80 §2](../../../docs/80_参照法令一覧.md)。lint が拒む）

## 3. 書く

**書式は [00 §4-9](../../../docs/00_ドキュメント規約/本文.md)、記法は [80 §3](../../../docs/80_参照法令一覧.md)。**

- ファイル名は `docs/research/YYYY-MM-DD_<主題>.md`（市販ソフトは `..._市販会計ソフト比較_<主題>.md`）
- 題名の日付は「**作成**」と書く（「時点」は制度の基準日の表明に読める。基準日を持つのは [80 §1](../../../docs/80_参照法令一覧.md) だけ）
- **事実と判断を分ける**（[32 §4](../../../docs/32_調査のルール.md)）。設計上の決定は設計文書へ
- **条番号を裸で置かない。** 法令名か「同法」「同」を必ず添える（問いや会話の返信でも同じ）

### 調べていない範囲を、同じ強さで書く

**[32 §3](../../../docs/32_調査のルール.md) を開いて、その節のとおりに書く。ここには写さない**
——写した側だけが古くなる（[00 §4-6](../../../docs/00_ドキュメント規約/本文.md)）。
**未確認を閉じるときも同じ節を開く**（項目が 2 本を抱えていることがある）。

## 4. 迷ったら、推測で埋めずに聞く

**3 手試して一次情報に届かなければ、「未確認」として残して開発者に依頼する。**
**問いは [05](../../../docs/05_開発者への問い.md) に書く**（[30 §11](../../../docs/30_作業のルール.md)）——
どこの機能か・いまの状況・選択肢・Claude の推奨・いつまでに要るか。
**法令名は必ず添える。**「附則 52 ①」と裸で書かない。

## 5. 記録したら

- [docs/README](../../../docs/README.md) の索引と、引く側の文書からリンクする
- **`git add` してから `python tools/docs/lint_docs.py` を流す**（追跡外の文書は検査されない）
- **文書の追加は自己レビューを通す**（`self-review` スキルの文書 5 観点）

## やらないこと

- **記憶で制度を書く**（税率・控除割合・閾値・期限・条番号）
- **[00 §4-9](../../../docs/00_ドキュメント規約/本文.md) を開かずに出典を選ぶ**
  ——何を根拠にしてよいかの格付けは向こうが持っている
- **調べていない範囲を書かずに済ませる**
- **[00 §4-9](../../../docs/00_ドキュメント規約/本文.md) の格付けや
  [32 §3](../../../docs/32_調査のルール.md) の書き方をここに写す**
