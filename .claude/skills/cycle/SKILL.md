# 回の始めと終わり

**このスキルは順番と打ち方だけを持つ。** 規則は文書が持つ——
**判断と Git** は [30](../../../docs/30_作業のルール.md)、
**マージの 6 条件**は [30 §7-1](../../../docs/30_作業のルール.md)、
**検証**は [31](../../../docs/31_検証のルール.md)、
**消し方と守り**は [33](../../../docs/33_失わないためのルール.md)。

## 1. 始める

1. **[04 §1](../../../docs/04_実装計画と現在地.md) の「次にやること」を読む**
2. **この回を期限とする問いが [05](../../../docs/05_開発者への問い.md) に残っていないか数える**
   ——残っていれば先に聞く（[30 §11](../../../docs/30_作業のルール.md)）
3. **主題を決める。**「規則 ＋ それを適用しきること」で取る（[30 §7](../../../docs/30_作業のルール.md)）
4. **ブランチを切る。`git checkout -b` は単独の呼び出しで打つ**
   ——`&&` で繋ぐと、後ろが守りに当たったときに**ブランチ作成ごと実行されない**
5. `git branch --show-current` で確かめてから作業に入る

## 2. 作る

**テストは先に設計してから書く**（[31 §7](../../../docs/31_検証のルール.md)）。
**書く前に、それが既にどこにあるかを数える**（[30 §9](../../../docs/30_作業のルール.md)）。
**画面を作る・変える回は、[06 §4](../../../docs/06_利用者の作業.md) の設計の行を引く。**

**打ち方だけを置く。なぜそうなるかは向こうが持つ。**

- **保護対象の名前と書き込みを、同じ 1 つのコマンド文字列に同居させない**
  （[33 §1](../../../docs/33_失わないためのルール.md)）
- **書き込みはファイルに逃がして `python <ファイル>` で実行する**（同）
- **3 行を超える文字列は、ヒアドキュメントを試さず Write でファイルにする**
  （[30 §8](../../../docs/30_作業のルール.md)）
- **一時ファイルはリポジトリの中に作らない。スクラッチパッドを使う**（同）

## 3. 検証する

**[31 §1](../../../docs/31_検証のルール.md) の検証ループ。**

- **この回に流す計器は差分から決まる**——`python tools/clb/which_gates.py` が印字する
  （判定の正典は [31 §6](../../../docs/31_検証のルール.md)。**流すのは自分**）
- **ソースコードを触ったなら、実機で操作する**（`live-test` スキル。
  範囲は [qa/04 §1](../../../docs/qa/04_実機操作テスト.md)）
- **関門を足した回は、壊して赤くなるかまで確かめる**（[31 §1](../../../docs/31_検証のルール.md)）

## 4. 自己レビューする

**`self-review` スキル。** **文書だけの変更でも省かない**（[CLAUDE.md §4](../../../CLAUDE.md)）。

- **その回に規則を足したなら、その規則で自分の差分を 1 周してからレビューへ出す**
- **指摘を直してコードが変わったら、検証と実機をやり直す**

## 5. コミットする

1. **新しく作った文書は先に `git add`**——追跡外は `lint_docs.py` に見えない
2. `python tools/docs/lint_docs.py` と `python tools/docs/lint_secrets.py`
3. **コミットメッセージは Write でファイルに書き、`git commit -F <ファイル>`**
   （書式は **Conventional Commits**。[30 §7](../../../docs/30_作業のルール.md)）
4. **`git add` は単独の呼び出しにする**
5. **前景で流す。** バックグラウンドに送らない（`timeout` を伸ばして待つ）
   ——**走っている間に別のファイルを `git add` すると、後の変更まで飲み込む**
6. **`--no-verify` を使わない**（機械が止める）

## 6. マージする

**[30 §7-1](../../../docs/30_作業のルール.md) を開いて、6 条件を 1 つずつ数える。**
**条件 6 の「区切り」に当たるかは、§3 で打った `which_gates.py` を読み直して自分で判断する**
（同節）。**そろわなかったときにどうするかも 30 §7-1 が持つ。ここには写さない。**

```
git checkout main
git merge --no-ff <ブランチ> -m "Merge branch '<ブランチ>'"
```

**`git push` はしない**（開発者が行う）。
**マージのコミットもフックの全段を通る**（`pre-merge-commit` が委譲している）。

## 7. 記録する

- **判断の経緯**は ADR、**レビューの採否**は [qa/02](../../../docs/qa/02_自己レビュー記録.md)、
  **漏れの型**は [qa/03](../../../docs/qa/03_テストで漏らした実例.md)、
  **CLB の穴**は [qa/01](../../../docs/qa/01_CLB静かな失敗.md)
- **[04 §1](../../../docs/04_実装計画と現在地.md) を書き換える**（追記しない。済んだことは消す）
- **再発防止の置き場を決める**（[30 §9](../../../docs/30_作業のルール.md)）。
  **その回に Claude のメモリへ書いたものがあれば、ここで行き先を決める**
  （[30 §9-1](../../../docs/30_作業のルール.md)）

## やらないこと

- **`main` に直接コミットする**（止めるフックは無い）
- **ブランチ作成を他のコマンドと `&&` で繋ぐ**
- **コミットをバックグラウンドへ送る**
- **6 条件を「そろったことにする」**
- **規則や事実をこのスキルに写す**（正典は 30・31・33）
