# 実機操作テスト

**実機で操作していない機能は、できていないものとして扱う**（[CLAUDE.md §4](../../../CLAUDE.md)）。
`designcheck` と `dotnet test` の緑は「読み込める」「C# が正しい」までしか言っていない。

**このスキルは順番と依頼文だけを持つ。** 判断と事実は文書が持つ——
**いつ・どこまで流すか**は [qa/04 §1](../../../docs/qa/04_実機操作テスト.md)、
**観測の作法**は [qa/04 §2](../../../docs/qa/04_実機操作テスト.md)、
**台本**は [qa/04 §3](../../../docs/qa/04_実機操作テスト.md)、
**踏んだ穴**は [qa/01](../../../docs/qa/01_CLB静かな失敗.md)、
**授権**は [31 §2・§3](../../../docs/31_検証のルール.md)。

## 1. 流すかどうかと、どこまで流すかを決める

**[qa/04 §1](../../../docs/qa/04_実機操作テスト.md) の表が正典である。**
マージの条件 3 の範囲もこの表が持つ（[30 §7-1](../../../docs/30_作業のルール.md)）。

**流すと決めたら、先に「何を見るか」を書く**（[31 §7](../../../docs/31_検証のルール.md)）。
書く先は [qa/04 §4](../../../docs/qa/04_実機操作テスト.md) が指す**年月のファイル**の節の冒頭で、**流す前に書く**。
**探索的テストの要否も、そこに 1 行書く**（要らないと判断した回も書く）。
**§1 の表の行が複数当たって優先を使ったなら、どれを採ったかも 1 行書く**
（[qa/04 §1](../../../docs/qa/04_実機操作テスト.md) の優先 4）。

**画面や経路を作った回とフェーズの区切りは、[06 §4](../../../docs/06_利用者の作業.md) の実機の行も通す。**

## 2. 配って、起動する

**開発者の確認は要らない**（[31 §2](../../../docs/31_検証のルール.md)。サーバの開始・終了・再起動も同じ）。

1. **サーバが動いているかを見る。** `Get-NetTCPConnection -LocalPort 5085 -State Listen`
   - **`*.mod.cs` か DB スキーマを変えたなら止める**——deploy だけでは反映されないので、
     **止めずに進むと、古いまま動いている画面を見て合格にする**
     （止め方は [tools/README](../../../tools/README.md)）
   - 変えていないなら止めない。**そのまま 4 を飛ばして 6 へ行く**
2. `pwsh -NoProfile -File tools/clb/designcheck.ps1` と `python tools/clb/lint_design.py` を緑にする
3. `pwsh -NoProfile -File tools/clb/deploy.ps1`
4. **別ターミナル（バックグラウンド）で**
   `dotnet run --project BusinessApp/BusinessApp.Server --launch-profile http`
   ——**前景で打つと占有されて 5 に進めない**（[tools/README](../../../tools/README.md) も「別ターミナル」）
5. `pwsh -NoProfile -File tools/server/wait-server.ps1 -TimeoutSec 60`
6. `http://localhost:5085` を開いてログインする（アカウントは [31 §3](../../../docs/31_検証のルール.md)）

**稼働 DB を壊す操作をするなら、先に
`pwsh -NoProfile -File tools/clb/db_snapshot.ps1 -Save -Name <名前>` を打つ**
（[33 §1](../../../docs/33_失わないためのルール.md)）。

## 3. 観測する

**作法の正典は [qa/04 §2](../../../docs/qa/04_実機操作テスト.md) の表である。開く前に読む。**
**ここには写さない**——委譲するときに渡す分は §4 の依頼文が持っている。

**出力は全部読む。** 確かめに行った 1 点だけを見て、残りを背景として流さない
（[qa/03 L-39](../../../docs/qa/03_テストで漏らした実例.md)）。

## 4. 委譲する（ブラウザ操作は積極的にサブエージェントへ）

**`general-purpose` で投げる**——画面を操作して保存させるので、
`self-review` が使う読むだけの `Plan` とは別である。
**同時 3 人まで**（[30 §6](../../../docs/30_作業のルール.md)）。依頼文にはそのまま次を入れる。

```
リポジトリ: {リポジトリのルートの絶対パス}
サーバ: http://localhost:5085（起動済み。**自分で起動・停止しないでください**）

## やってほしいこと
{台本の項目、または確かめたい 1 点}

## 必ず守ること
- **自分が作ったタブ以外を触らないでください。**
- **書けたか・何が残ったかは `sql` CLI で確かめてください**（画面の表示だけで判断しない）。
- **トーストを見るなら、押す前に `document.documentElement` へ `MutationObserver` を張ってください。**
- **画面の状態はスクリーンショットで見てください**（`get_page_text` は入力欄の値を拾いません）。
- **見た文字列は、そのまま報告に写してください**（要約しない）。

## 前提として読むもの
- docs/qa/01_CLB静かな失敗.md の G 節（ブラウザ操作の落とし穴）
- docs/qa/04_実機操作テスト.md の §2（観測の作法）
- tools/README.md（`sql` CLI の打ち方。`pwsh -NoProfile -File tools/clb/sql.ps1 -Query "…"`）

## 出力の形式
**操作した順に、何をして何が出たか。** 画面の文字列は原文のまま。
判断（合格・不合格）は最後にまとめてください。
```

**2 並列にするなら、同じ利用者アカウントで動く台本を組み合わせる**（クッキー壺が 1 つのため）。
**どの台本がどの利用者で流せるかは [qa/04 §3](../../../docs/qa/04_実機操作テスト.md) の前書きの表**が持つ
——**設定のマスタは経理責任者でしか開けない**。
**窓も共有する**ので、依頼文に「クリックの前にスクリーンショットを撮り直す」を入れる（[qa/01 G-14](../../../docs/qa/01_CLB静かな失敗.md)）。

## 5. 記録する

**[qa/04 §4](../../../docs/qa/04_実機操作テスト.md) が指す年月のファイルに 1 回 1 節。見た文字列をそのまま写す**
——写すと読むことになる。

- 流した台本の項目と、結果。**押したときに出た文言は原文のまま**
- 探索的テストの要否と、その判断
- 直した不具合の「漏れの型」は [qa/03](../../../docs/qa/03_テストで漏らした実例.md) へ
- **CLB の穴は [qa/01](../../../docs/qa/01_CLB静かな失敗.md)、アプリ側で直せないものは
  [CLB改善提案](../../../docs/CLB改善提案/README.md)**（発見日と CLB バージョンを必ず）

## 6. 赤かったとき

- **3 回やって進展が無ければ引く**（[30 §3](../../../docs/30_作業のルール.md)）。
  **とくに CLB とブラウザ操作は、開発者が自分で触ると解決することがかなりある**
- 分かったことを [qa/01](../../../docs/qa/01_CLB静かな失敗.md) に残し、次のタスクへ移る
- **直したら、この工程をやり直す**（[30 §7-1](../../../docs/30_作業のルール.md) の「5 でコードが変わったら 2 と 3 をやり直す」）

## やらないこと

- **`designcheck` と `dotnet test` の緑で「できた」と書く**
- **画面の表示だけで「書けた」と判断する**（DB を見る）
- **サーバの起動・停止で開発者に確認を取る**（[31 §2](../../../docs/31_検証のルール.md) の授権）
- **確かめに行った 1 点だけを読む**
- **観測の作法や台本をここに写す**（正典は [qa/04](../../../docs/qa/04_実機操作テスト.md)）
