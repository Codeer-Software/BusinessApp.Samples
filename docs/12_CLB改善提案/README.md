## 記録の運用ルール（継続）

以下のいずれかに該当したら、**その場で** 01/02 に追記する（後でまとめて書こうとすると失われる）:

1. **回避策（ワークアラウンド）を作ったとき** — 回避策の存在自体が改善提案。何を回避したか＋理想の姿を書く
2. **マニュアルに無い事実を実測で確立したとき** — 実測しないと分からなかった＝ドキュメント提案
3. **エラーにならずに壊れる挙動を踏んだとき** — 静かな失敗は最優先の提案（例: ソート無効・保存されない代入）
4. **「designcheck が検出してくれたら」と思ったとき** — designcheck 拡張候補として記録

書式: 連番 ID（FB-/DOC-/GOOD-）＋ 事象 → 困った点 → 提案 → 出典（実測記録の場所）。重要度は 高（データ破壊・静かな失敗・長時間の調査を要した）／中（回避策あり・生産性影響）／低（利便性）。

一次記録の出典: `Designer/Project.md`「作業中に得た知見」・`docs/05_実装計画と進捗台帳.md`・`docs/issues/`・`docs/decisions/`。
