## 記録の運用ルール

次のいずれかに該当したら、**その場で**追記する（後でまとめて書こうとすると必ず失われる）。

1. **回避策（ワークアラウンド）を作ったとき** — 回避策の存在自体が改善提案である
2. **マニュアルに無い事実を実測で確立したとき** — 実測しないと分からなかった＝ドキュメント提案
3. **エラーにならずに壊れる挙動を踏んだとき** — 静かな失敗は最優先の提案
4. **「`designcheck` が検出してくれたら」と思ったとき** — designcheck 拡張の候補として記録

## 書式（必須項目）

```markdown
### FB-001【重大度】一行要約

- **発見日**: 2026-08-23
- **CLB バージョン**: ランタイム 1.3.20 / デザイナ 1.3.20 / Extras 0.5.0
- **症状**: 何が起きるか（再現手順つき）
- **なぜ困るか**: 実害。調査に要した時間・データへの影響
- **提案**: どうなってほしいか
- **回避策**: 現状どうしのいでいるか
- **出典**: 実測記録の場所（ADR / 実装計画と現在地 / チェックリストの該当項）
```

**発見日と CLB バージョンは必須。** CLB は頻繁に更新・修正されるため、
「いつの、どの版で観測したか」が無い報告は検証できない。

重大度は **高**（データ破壊・静かな失敗・長時間の調査を要した）／**中**（回避策あり・生産性への影響）／
**低**（利便性）の 3 段階。
