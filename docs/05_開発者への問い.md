# 開発者への問い

> **開発者の答えが無いと先へ進まないこと**を、判断に要る材料ごと 1 か所に置く文書。
> **運用の規則は [30 §11](30_作業のルール.md) が持つ**（誰がいつ書き、答えはどう伝わり、いつ消すか）。ここは問いの本体だけ。
> **急ぎの順に並べる**——期限のフェーズが近い順 → 同じ期限の中では「決まらないと止まるもの」がある問いを先 → 期限の無いもの。
> 番号 `Q-nn` は付けた順で、**使い回さない**（並びと番号は一致しない。消えた番号は欠番のまま）。
> 答えが出て ADR か設計文書に載ったら、その問いは消す（本文は git log が持つ）。
> **本書の推奨はすべて Claude の判断である。** 開発者の決定は、ここではなく ADR・設計文書に書く（[00 §4-11](00_ドキュメント規約/本文.md)）。
> 制度・法令に触れる箇所で「Claude の読み」と書いたものは、リサーチで裏を取っていない——**法令の当てはめは開発者が最も確かな確認先**（[CLAUDE.md §2](../CLAUDE.md)）。
> 行数の目安（[00 §5](00_ドキュメント規約/README.md)）は本書に当てない——長さは未決の数で決まる。

## Q-08 28年改正法・改正令の正体——候補と出典を置いた。合っているかと、略称をどう書くかを決めてほしい

| | |
|---|---|
| **急ぎ** | **フェーズ 3 の着手前**（[80 §4](80_参照法令一覧.md) の ②） |
| **決まらないと止まるもの** | 止まらない。ただし [80 §2](80_参照法令一覧.md) の 28年改正法・改正令の 2 行が、正式名称・法令番号・版の空いたまま |
| **どこの話か** | [80 §2](80_参照法令一覧.md) 末尾の 2 行（28年改正法・改正令）と、[消費税リサーチ](research/2026-08-23_消費税インボイス制度.md) が引く「28年改正法附則 34 ①・51 の 2・51 の 3・52・53・53 の 2」「改正令附則 24 の 2 ①」「平成15年改正省令附則 2」 |
| **既に決まっていること** | **番号法・番号法令・取適法は一覧に足す**（開発者の決定。2026-09-11。略称を承認し、同日に開発者が [80 §2](80_参照法令一覧.md) の値を埋めた）。国税通則法に略称を置かないことも同日に承認。**28年改正法・改正令を足すか正式名称へ戻すかは決まっていない**（開発者は「正式名称は何か」と問い返しただけ）。**正式名称と法令番号を埋めるのは開発者**（[80 §4](80_参照法令一覧.md) の ②。**理由は述べられていない**）——だから Claude は下の候補を 80 の列には書かず、備考に候補と印だけ置いた |

**状況。** 開発者から「28年改正法と改正令は、そもそも正式名称は何か。調べようがない」と問い返された（2026-09-11）。
Claude が調べた結果を下に置く。**どれも Claude の読みで、法令の当てはめは開発者が確かめる**（[CLAUDE.md §2](../CLAUDE.md)）。

**28年改正法・改正令が何かは、廃止された消税軽減通達の発遣文書が自分で書いている。**
国税庁のページ（https://www.nta.go.jp/law/tsutatsu/kobetsu/kansetsu/160412/index.htm 。Claude 確認 2026-09-11。Shift_JIS なので `curl` ＋ `iconv` で読んだ）の
（理由）と、別冊「用語の意義」1 の (1)〜(3) の逐語（字間の空白は整えた）:

> 「所得税法等の一部を改正する法律」（平成28年法律第15号）附則、「消費税法施行令等の一部を改正する政令」（平成28年政令第148号）附則及び「消費税法施行規則等の一部を改正する省令」（平成28年財務省令第20号）附則の規定により、令和元年10月1日から消費税の軽減税率制度が実施されることによる。
>
> (1) 改正法　所得税法等の一部を改正する法律（平成28年法律第15号）
> (2) 改正令　消費税法施行令等の一部を改正する政令（平成28年政令第148号）
> (3) 改正省令　消費税法施行規則等の一部を改正する省令（平成28年財務省令第20号）

**本書群の使い方と合う根拠が 2 つ。** ①同通達の 2「食品の範囲」は「改正法附則第34条第1項第1号」で軽減税率の対象を引き、リサーチ §10 も「28年改正法附則 34 ①」と同じ条番号で引いている（**その根拠を現行の消税法の側へ改めるかは、リサーチ末尾の未確認事項 14**）。<!-- lint-docs:article-ok 通達の逐語 -->
②[80 §2](80_参照法令一覧.md) の告示の行（平成28年3月31日財務省告示第100号）の正式名称に「消費税法施行令等の一部を改正する政令（平成二十八年政令第百四十八号）」が現れ、
その告示はリサーチ §10 がケータリング例外の金額の基準として引くものである。
**インボイス制度の経過措置（附則 52・53）・2 割特例（附則 51 の 2）・3 割特例（附則 51 の 3）・少額特例（附則 53 の 2）が同じ法律の附則にあるかは、この通達からは読めない**——後の改正で同法の附則に足された規定だ、というのが Claude の読み（未確認）。

| 略称（いまの仮置き） | 候補の正式名称 | 候補の法令番号 | 出典 |
|---|---|---|---|
| 28年改正法 | 所得税法等の一部を改正する法律 | 平成28年法律第15号 | 上の通達の（理由）と「用語の意義」1 (1)（Claude 確認 2026-09-11） |
| 改正令 | 消費税法施行令等の一部を改正する政令 | 平成28年政令第148号 | 同 1 (2)。[80 §2](80_参照法令一覧.md) の告示の行の正式名称にも現れる |

**e-Gov の法令 API に、独立の法令としては 2 本とも無い**（`/laws` で法令番号・題名＋公布日のどちらで引いても 0 件。Claude。原文は開いていない。2026-09-11）。
**ただし改正法の附則は被改正法の側に載る**——消税法の e-Gov 全文（`law_data/363AC0000000108`）に「附則（平成二八年三月三一日法律第一五号）」が 1 本あり、
その中に「第五十一条の二」「第五十三条の二」の字面がある。消税令の全文（`law_data/363CO0000000360`）にも「附則（平成二八年三月三一日政令第一四八号）」が 1 本ある
（Claude 機械検算 2026-09-11——全文 XML の `AmendLawNum` 属性と条番号の字面を数えただけで、**附則の本文は読んでいない**）。
**だから出典は e-Gov の消税法・消税令のページの附則欄に置ける**と見える（Claude の読み）。
[80 §2](80_参照法令一覧.md) の令和8年改正法と同じく、他法を改正する法律なので「その日に施行されている版」の数え方には乗らない。

**略称の書き方（Claude の提案）。** 「改正令」だけでは何年の改正か分からず、令和8年改正法と並ぶと紛れる。**「28年改正令」に改める**
（本書群で使っているのはリサーチ §2 の 1 か所）。リサーチにあった「28 年改正法」「平成28年改正法」の表記揺れは「28年改正法」に揃えた（2026-09-11）。

**「平成15年改正省令」**（リサーチ §5 の「第一表付記事項……欄は使用しない（平成15年改正省令附則 2 の旧経過措置用であり無関係）」の 1 か所）の候補は、
**消費税法施行規則の一部を改正する省令（平成15年財務省令第92号）**——同じ国税庁ページの旧 25 が「以下『15年改正省令』という。」と定義し、
その附則 2 ②〜④《課税標準額に対する消費税額の計算に関する経過措置》を引いている（Claude 確認 2026-09-11。リサーチ §5 の用途と合う。当てはめは開発者）。
使っているのは「無関係である」と言うためだけなので、**Claude の推奨は略称を定義せず、その 1 か所を正式名称で書き直すこと**
（[80 §2](80_参照法令一覧.md) の冒頭の規則は「何度も出てくる場合」に略称を検討するとしている）。

**やってほしいこと。** ① 上の 2 本の候補が合っているか。② 一覧に足すなら略称を「28年改正法」「28年改正令」とするか（足さずに正式名称で書く道も残っている——引いているのはリサーチの 7 か所）。③ 「平成15年改正省令」の候補が合っているか。合っていれば、その 1 か所を正式名称で書き直してよいか（略称は定義しない）。
**いつ**——フェーズ 3 の着手前。

## Q-12 計上検証の「警告」をどこへ届けるか

| | |
|---|---|
| **急ぎ** | **フェーズ 4**（不変条件をまとめて触る回。[04 §5](04_実装計画と現在地.md) の「摘要の必須を不変条件に足すか」と同じ回） |
| **決まらないと止まるもの** | 止まらない。ただし**それまで警告は誰にも届かない**——無効にした科目・部門・取引先・補助科目のまま取消が通っても、利用者は気づかない |
| **どこの話か** | `ViolationSeverity.Warning`。取消・訂正で「止めない」と決めた検査（[10 §6-3](10_会計ドメイン設計.md) の表）が警告に落とすが、本番コードはどこもそれを読んでいない |
| **既に決まっていること** | 取消は止めない（利用者に直す手立てが無い。Q-11 の表）。届け先は決めていない |

**状況。** 「止めない」は「警告に落とす」の意味で作ったが、計上の側は Error だけを読む。自己レビュー（[R69-13](qa/02_自己レビュー記録.md)）が「既存の穴を取引先で 1 種類広げた」と指摘した。
**警告が出る経路は 2 つで、通る道が違う**——取消は Web API（`JournalAmendmentEndpoint`。[ADR-0016](decisions/0016-画面から呼ぶサーバ処理はWebAPIに置く.md)）、
訂正の再計上は「計上する」の標準の保存経路（`this.Submit()` → `AccountingSubmitPipeline`）。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A. 「取り消す」の応答に載せ、画面で黄色のトーストにする** | Web API の応答に `warnings` を足し、`JournalEntry.mod.cs` がトーストにする | 利用者がその場で気づく。帳簿は変えない | **取消しか覆わない**——訂正の再計上（保存の成功）に文言を載せる経路は未計測。トーストを読み飛ばすと残らない |
| B. 計上済みの伝票に注記として残す | 列を足し、詳細と帳簿に出す | 両方の経路を覆う。後から見返せる | 計上済みの伝票に列を足す（[ADR-0004](decisions/0004-優良な電子帳簿への準拠と仕訳の不変性.md) の不変性は保てるが、スキーマが動く） |
| C. ログにだけ書く | サーバのログ | 実装が最小 | 利用者には届かない（いまと同じ） |

**Claude の推奨は A を取消に当て、再計上の側は「保存の成功に文言を載せられるか」を実測してから決める**（[qa/01](qa/01_CLB静かな失敗.md) の型——想像で決めない）。
警告の中身は「無効な相手を使った」で、利用者が直後にできることは「マスタを有効に戻す」か「気にしない」の 2 つしかない。
B は帳簿に出す価値のある情報になった時点で考える。

## Q-13 取引を記さない伝票（取消・期首残高・決算振替・繰越）に、法税規則 55 ① と別表二十四はどう当たるか

| | |
|---|---|
| **急ぎ** | **フェーズ 4**（期首残高・決算振替・繰越を作る回） |
| **決まらないと止まるもの** | 期首残高・繰越の伝票の「内容」欄に何を入れるか。摘要の必須（[10 §4-2-1](10_会計ドメイン設計.md)）をそれらにも当てるか |
| **どこの話か** | [10 §4-1](10_会計ドメイン設計.md)・[ADR-0045 決定 3](decisions/0045-振替伝票1枚には1つの取引だけを記す.md)・[ADR-0048](decisions/0048-伝票の複製は取引の内容だけを写す.md) |
| **既に決まっていること** | 「伝票は 1 取引を 1 伝票とする」（開発者。2026-09-08。逐語）。それ以外は決まっていない |

**状況。** **「取消・期首残高・決算振替・繰越は経済事象ではなく帳簿の上の振替なので、法税規則 54・55 が数える『取引』に当たらない」は Claude の読み**で、諮っていない。
**期首残高と繰越で、何が「内容」（55 ①・別表二十四）を満たすのかも決まっていない。**

| 論点 | Claude の読み |
|---|---|
| 取消伝票は「取引」か | 当たらない（原仕訳の反転で、経済事象を記していない）。**ただし訂正の再計上は当たる**（取引を記し直す） |

| 決算振替の「内容」 | 「損益振替」「利益処分」の固定の摘要で足りる |

上の読みでよいか、違うなら何を記すべきかを教えてほしい。

## Q-14 勘定科目・補助科目・部門の名前も、取引先と同じく計上時に写すか

| | |
|---|---|
| **急ぎ** | **マスタに手を入れる回**（[12](12_マスタ台帳.md) の論点。フェーズ 4 の帳簿を出し切る回までに） |
| **決まらないと止まるもの** | 止まらない。ただし科目・補助科目・部門を改名すると、計上済みの伝票と帳簿の表示が動く |
| **どこの話か** | `journal_lines` の科目・補助科目・部門（写しを持たない）。取引先は `partner_name_snapshot` を持つ |
| **既に決まっていること** | **取引先は写す**——帳簿（[ADR-0018](decisions/0018-帳簿の記載事項は計上時に写して固定する.md)）も伝票の画面（[ADR-0037](decisions/0037-計上済みの伝票は画面でも計上時の姿を見せる.md)。開発者の決定。2026-09-02）も計上時の姿を見せる。**科目・補助科目・部門は決めていない** |

**状況。** 取引先の写しは消税法 30 ⑧ の帳簿記載事項が根拠で、名称で写すのは本プロジェクトの選択（ADR-0018 の注記）。
科目・補助科目・部門の名前は、[40 §4-1](40_優良な電子帳簿の対応表.md) の当てはめでは**別表二十四（六）（十二）（十四）の「名称を付して区分し」と（二）の「口座別に」に当たりうる**ので、
「法定記載事項ではない」とは言い切れなくなった（2026-09-06。**Claude の読み**）。写しを持たないまま改名すると、計上済みの伝票と帳簿の名前が動く。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|

影響範囲は 0013 だけ（0013 の 2026-08-27 追記や他の ADR の追記は、決定を変えていない注記なので対象外）。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A. 規則どおり `superseded` にする** | 0013 を `superseded`、0050 に「0013 から引き継ぐ決定」（プロジェクト参照・機能フォルダ・csproj を分けない・依存表・インターフェースを置かない）の節を足す | 規則が 1 つのまま | 0013 の理由を読む人が減る。0050 が少し長くなる |
| B. 追記を認め、規則に例外を書く | 「決定が変わらず理由の 1 文だけを改めるときは追記でよい」を §3-3 に足す | 0013 が読まれ続ける | 「一部は嘘」を見分ける線が曖昧になる |

**Claude の推奨は A。** 開発者が理由つきで決めた規則で、追記の形はその理由（見分けの付かない状態）を正面から踏んでいる。
費用は 0050 に 1 節足すだけで小さい。

**関連**: [qa/02 R68-01](qa/02_自己レビュー記録.md)・[フロントマター §3-3](00_ドキュメント規約/フロントマター.md)。
