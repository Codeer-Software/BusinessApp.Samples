# 開発者への問い

> **開発者の答えが無いと先へ進まないこと**を、判断に要る材料ごと 1 か所に置く文書。
> **運用の規則は [30 §11](30_作業のルール.md) が持つ**（誰がいつ書き、答えはどう伝わり、いつ消すか）。ここは問いの本体だけ。
> **急ぎの順に並べる**——期限のフェーズが近い順 → 同じ期限の中では「決まらないと止まるもの」がある問いを先 → 期限の無いもの。
> 番号 `Q-nn` は付けた順で、**使い回さない**（並びと番号は一致しない。消えた番号は欠番のまま）。
> 答えが出て ADR か設計文書に載ったら、その問いは消す（本文は git log が持つ）。
> **本書の推奨はすべて Claude の判断である。** 開発者の決定は、ここではなく ADR・設計文書に書く（[00 §4-11](00_ドキュメント規約/本文.md)）。
> 制度・法令に触れる箇所で「Claude の読み」と書いたものは、リサーチで裏を取っていない——**法令の当てはめは開発者が最も確かな確認先**（[CLAUDE.md §2](../CLAUDE.md)）。
> 行数の目安（[00 §5](00_ドキュメント規約/README.md)）は本書に当てない——長さは未決の数で決まる。

**① 条文の出所。** 2026-09-10 に開発者が確認した条文は、e-Gov の被改正法（消税法・消税令・消税規則）の全文の附則欄か。
[80 §2](80_参照法令一覧.md) の 4 行の出典の列は e-Gov の附則欄を指しているが、開発者がそこを開いたとは聞いていない（凡例の「開発者確認」は「出典を開いて原文を見た」の意味）。

**② Claude が置いた略称 2 つ。** 消税令等一部改正令（平成30年政令第135号）と 消税規則一部改正省令（平成15年財務省令第92号）は、
**Claude が開発者の指示の形（「所税法等一部改正法（平成28年法律第15号）」）に倣って置いたもので、承認を得ていない**。
[80 §2](80_参照法令一覧.md) に行を足したことも Claude の判断（2026-09-11。前者は少額特例の政令が平成28年から直ったため、後者は引く箇所が [消費税リサーチ §5-1](research/2026-08-23_消費税インボイス制度.md) と条文リサーチの 2 か所になったため）。この形でよいか。

**③ 附則 52 ① の「一の事業者」と「一の者」。** 上限額の合計の単位は、現行版が「**一の事業者**から行う当該課税仕入れ」、令和8年10月1日施行版が「**一の者**から行う当該課税仕入れ」（[条文リサーチ §2-3](research/2026-09-11_インボイス経過措置の附則条文.md)）。
**Claude の読み**: 現行版では消費者（事業者でない者）からの課税仕入れは十億円の合計に入らず、令和8年10月1日施行版では一億円の合計に入る。
[消費税リサーチ §1-3](research/2026-08-23_消費税インボイス制度.md) は「一の適格請求書発行事業者以外の者」と要旨で書いていて、この違いを持っていない。この読みでよいか。フェーズ 3 の経過措置（上限額の判定）の実装に効く。

**④ 軽減税率の対象の根拠**（[消費税リサーチ の未確認事項 14](research/2026-08-23_消費税インボイス制度.md)）。§10 の表は所税法等一部改正法（平成28年法律第15号）附則 34 ① を引くが、差し替え先の消税基本通達 5-9-1 は消税法 別表第一 一 を引く。
現行法の側へ改めるか、旧の側のままにするか。**Claude の推奨は現行法の側へ改めて附則 34 ① を併記**（通達と同じ条を引くほうが照合しやすいから。ただし別表第一の各号の中身は読んでいない）。
**附則 34 の写しは条文リサーチにも無い**——旧の側を残すなら、附則 34 ① の全文も同じ形で示してほしい（条文リサーチ §2 に足す）。
**一体資産も同じ対である**——§10 が引く消税令等一部改正令（平成28年政令第148号）附則 2 一 は附則 34 ① 一 の委任先で、5-9-4 が引く消税令 2 の 3 一 は読んでいない。

**⑤ 令和8年10月1日施行版の適用関係。** 附則 52 ①（一億円）と 51 の 2 ⑥（届出の特例）の令和8年10月1日施行版が、**どの課税期間・どの課税仕入れから当たるか**は、所税法等一部改正法（令和8年法律第12号）の附則（経過規定）が決める。
[消費税リサーチ §1-3・§3-2](research/2026-08-23_消費税インボイス制度.md) の「令和8年10月1日以後に開始する課税期間から」「2026-10-01 以後に終了する課税期間」は大綱・インボイスQ&A 由来で、**その附則は誰も読んでいない**（同法の附則が決めると見ているのも Claude の読み）。
上限額の判定と届出の特例の実装（フェーズ 3）に効くので、**同法附則の消費税関係の該当条を、条文リサーチと同じ形で示してほしい**。

**⑥ Claude が条文から読んだ当てはめ 5 つ。** 写しを読んで消費税リサーチに足した・直したもので、**法令の当てはめとしては開発者未確認**（2026-09-11）。それぞれでよいか。

## Q-12 計上検証の「警告」をどこへ届けるか

| | |
|---|---|
| **急ぎ** | **フェーズ 4**（不変条件をまとめて触る回。[04 §5](04_実装計画と現在地.md) の「摘要の必須を不変条件に足すか」と同じ回） |
| **決まらないと止まるもの** | 止まらない。ただし**それまで警告は誰にも届かない**——無効にした科目・部門・取引先・補助科目のまま取消が通っても、利用者は気づかない |
| **どこの話か** | `ViolationSeverity.Warning`。取消・訂正で「止めない」と決めた検査（[10 §6-3](10_会計ドメイン設計.md) の表）が警告に落とすが、本番コードはどこもそれを読んでいない |
| **既に決まっていること** | 取消は止めない（利用者に直す手立てが無い。Q-11 の表）。届け先は決めていない |

**状況。** 「止めない」は「警告に落とす」の意味で作ったが、計上の側は Error だけを読む。自己レビュー（[R69-13](qa/02_自己レビュー記録.md)）が「既存の穴を取引先で 1 種類広げた」と指摘した。
**警告が出る経路は 2 つで、通る道が違う**——取消は Web API（`JournalAmendmentEndpoint`。[ADR-0016](decisions/0016-画面から呼ぶサーバ処理はWebAPIに置く.md)）、
訂正の再計上は「計上する」の標準の保存経路（`this.Submit()` → `AccountingSubmitPipeline`）。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A. 「取り消す」の応答に載せ、画面で黄色のトーストにする** | Web API の応答に `warnings` を足し、`JournalEntry.mod.cs` がトーストにする | 利用者がその場で気づく。帳簿は変えない | **取消しか覆わない**——訂正の再計上（保存の成功）に文言を載せる経路は未計測。トーストを読み飛ばすと残らない |
| B. 計上済みの伝票に注記として残す | 列を足し、詳細と帳簿に出す | 両方の経路を覆う。後から見返せる | 計上済みの伝票に列を足す（[ADR-0004](decisions/0004-優良な電子帳簿への準拠と仕訳の不変性.md) の不変性は保てるが、スキーマが動く） |
| C. ログにだけ書く | サーバのログ | 実装が最小 | 利用者には届かない（いまと同じ） |

**Claude の推奨は A を取消に当て、再計上の側は「保存の成功に文言を載せられるか」を実測してから決める**（[qa/01](qa/01_CLB静かな失敗.md) の型——想像で決めない）。
警告の中身は「無効な相手を使った」で、利用者が直後にできることは「マスタを有効に戻す」か「気にしない」の 2 つしかない。
B は帳簿に出す価値のある情報になった時点で考える。

**関連**: [10 §6-3](10_会計ドメイン設計.md)・[qa/02 R69-13](qa/02_自己レビュー記録.md)。

## Q-13 取引を記さない伝票（取消・期首残高・決算振替・繰越）に、法税規則 55 ① と別表二十四はどう当たるか

| | |
|---|---|
| **急ぎ** | **フェーズ 4**（期首残高・決算振替・繰越を作る回） |
| **決まらないと止まるもの** | 期首残高・繰越の伝票の「内容」欄に何を入れるか。摘要の必須（[10 §4-2-1](10_会計ドメイン設計.md)）をそれらにも当てるか |
| **どこの話か** | [10 §4-1](10_会計ドメイン設計.md)・[ADR-0045 決定 3](decisions/0045-振替伝票1枚には1つの取引だけを記す.md)・[ADR-0048](decisions/0048-伝票の複製は取引の内容だけを写す.md) |
| **既に決まっていること** | 「伝票は 1 取引を 1 伝票とする」（開発者。2026-09-08。逐語）。それ以外は決まっていない |

**状況。** **「取消・期首残高・決算振替・繰越は経済事象ではなく帳簿の上の振替なので、法税規則 54・55 が数える『取引』に当たらない」は Claude の読み**で、諮っていない。
**期首残高と繰越で、何が「内容」（55 ①・別表二十四）を満たすのかも決まっていない。**

| 論点 | Claude の読み |
|---|---|
| 取消伝票は「取引」か | 当たらない（原仕訳の反転で、経済事象を記していない）。**ただし訂正の再計上は当たる**（取引を記し直す） |
| 期首残高・繰越の「内容」 | 「前期繰越」のような固定の摘要で足りる（相手方も給付も無い） |
| 決算振替の「内容」 | 「損益振替」「利益処分」の固定の摘要で足りる |

上の読みでよいか、違うなら何を記すべきかを教えてほしい。

| **既に決まっていること** | **取引先は写す**——帳簿（[ADR-0018](decisions/0018-帳簿の記載事項は計上時に写して固定する.md)）も伝票の画面（[ADR-0037](decisions/0037-計上済みの伝票は画面でも計上時の姿を見せる.md)。開発者の決定。2026-09-02）も計上時の姿を見せる。**科目・補助科目・部門は決めていない** |

**状況。** 取引先の写しは消税法 30 ⑧ の帳簿記載事項が根拠で、名称で写すのは本プロジェクトの選択（ADR-0018 の注記）。
科目・補助科目・部門の名前は、[40 §4-1](40_優良な電子帳簿の対応表.md) の当てはめでは**別表二十四（六）（十二）（十四）の「名称を付して区分し」と（二）の「口座別に」に当たりうる**ので、
「法定記載事項ではない」とは言い切れなくなった（2026-09-06。**Claude の読み**）。写しを持たないまま改名すると、計上済みの伝票と帳簿の名前が動く。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A. 取引先と同じ扱いにする** | 明細に科目名・補助科目名・部門名の写しを足し、計上時に焼く。画面も ADR-0037 と同じ切り替え | 帳簿と伝票が計上時の姿で揃う。改名の影響が消える | 列が 3 つ増える。マイグレーションと帳簿クエリの書き換え |
| B. 写さない | 改名は「意味を変える」に当たるとして止める（[ADR-0038](decisions/0038-使用中のマスタは意味を変えられない.md) の線を名前まで広げる） | 列を足さない | 誤字の訂正もできなくなる。ADR-0038 §2 は名前を「変えてよい列」に置いている |
| C. コードだけを写す | 名前は写さず、コードで区分を固定する | 列が小さい | 名前が動く問題は残る |

**Claude の推奨は A**（帳簿の記載を計上時の姿で固定した ADR-0018・ADR-0037 の方針に合わせる。**設計判断であって法令の当てはめではない**）。

| **関連** | [ADR-0048](decisions/0048-伝票の複製は取引の内容だけを写す.md)・[04 §1](04_実装計画と現在地.md) の C |

## Q-10 ADR-0013 を `superseded` にせず、追記で済ませてよいか

| | |
|---|---|
| **急ぎ** | 期限なし（ただし [フロントマター §3-3](00_ドキュメント規約/フロントマター.md) の**開発者の決定に、いま反している**） |
| **決まらないと止まるもの** | 止まらない |
| **どこの話か** | [ADR-0013](decisions/0013-機能単位のモジュール分割と依存方向.md) と [ADR-0050](decisions/0050-会計コアの層はドメイン・アプリケーション・インフラ・プレゼンテーションの4つで読み機能フォルダの下で分ける.md) |
| **既に決まっていること** | 「一部だけを覆すときも、元 ADR は全体を `superseded` にする」（開発者の決定。2026-08-26。**部分的に直すと「current なのに一部は嘘」という、最も見分けの付かない状態ができるから**） |

**状況。** ADR-0050 が `AccountingCore.Server` の内側に 3 つの層を足し、ADR-0013 決定 1 の「用語や層の追加は要らない」を一部覆した。
Claude は 0013 の冒頭に 2026-09-10 の追記を置いて `current` のままにした（[R68-01](qa/02_自己レビュー記録.md)）。**追記の形は上の決定に反している。**
影響範囲は 0013 だけ（0013 の 2026-08-27 追記や他の ADR の追記は、決定を変えていない注記なので対象外）。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A. 規則どおり `superseded` にする** | 0013 を `superseded`、0050 に「0013 から引き継ぐ決定」（プロジェクト参照・機能フォルダ・csproj を分けない・依存表・インターフェースを置かない）の節を足す | 規則が 1 つのまま | 0013 の理由を読む人が減る。0050 が少し長くなる |
| B. 追記を認め、規則に例外を書く | 「決定が変わらず理由の 1 文だけを改めるときは追記でよい」を §3-3 に足す | 0013 が読まれ続ける | 「一部は嘘」を見分ける線が曖昧になる |

**Claude の推奨は A。** 開発者が理由つきで決めた規則で、追記の形はその理由（見分けの付かない状態）を正面から踏んでいる。
費用は 0050 に 1 節足すだけで小さい。

**関連**: [qa/02 R68-01](qa/02_自己レビュー記録.md)・[フロントマター §3-3](00_ドキュメント規約/フロントマター.md)。
