# 開発者への問い

> **開発者の答えが無いと先へ進まないこと**を、判断に要る材料ごと 1 か所に置く文書。
> **運用の規則は [30 §11](30_作業のルール.md) が持つ**（誰がいつ書き、答えはどう伝わり、いつ消すか）。ここは問いの本体だけ。
> **急ぎの順に並べる**——期限のフェーズが近い順 → 同じ期限の中では「決まらないと止まるもの」がある問いを先 → 期限の無いもの。
> 番号 `Q-nn` は付けた順で、**使い回さない**（並びと番号は一致しない。消えた番号は欠番のまま）。
> 答えが出て ADR か設計文書に載ったら、その問いは消す（本文は git log が持つ）。
> **本書の推奨はすべて Claude の判断である。** 開発者の決定は、ここではなく ADR・設計文書に書く（[00 §4-11](00_ドキュメント規約/本文.md)）。
> 制度・法令に触れる箇所で「Claude の読み」と書いたものは、リサーチで裏を取っていない——**法令の当てはめは開発者が最も確かな確認先**（[CLAUDE.md §2](../CLAUDE.md)）。
> 行数の目安（[00 §5](00_ドキュメント規約/README.md)）は本書に当てない——長さは未決の数で決まる。

## Q-32 取引を記さない伝票（期首残高・繰越・決算振替）に、法税規則 別表二十四と「摘要の必須」はどう当たるか

| | |
|---|---|
| **急ぎ** | **フェーズ 4**（期首残高・決算振替・繰越を作る回） |
| **決まらないと止まるもの** | 止まらない。ただし**3 種の伝票を作る回には決まっていないと困る**——計上の関門が摘要を必須にしているので、サーバが生成する伝票にも摘要を入れるのか、種別で外すのかが決まらない |
| **どこの話か** | [40 §4-1](40_優良な電子帳簿の対応表.md) の表（別表二十四の当てはめの現在形）と [10 §4-2-1](10_会計ドメイン設計.md)（摘要の必須） |
| **既に決まっていること** | **法税規則 55 ① の当てはめは決着した**（開発者。2026-09-16。[ADR-0059](decisions/0059-期首残高と繰越と決算振替は仕訳として持ち閉鎖残高勘定は作らない.md)）——期首残高・繰越・決算振替は同 53 が数える「取引」に当たらないが、**55 ① に準じて記載する**。**摘要の文言の「型」も決めた**（**Claude の決め。開発者が委ねた**。字面は決算振替の構造が決まってから） |

**状況。** **旧 Q-13 は「法税規則 55 ① と別表二十四」の 2 本を抱えていた**が、
**答えと ADR-0059 が扱ったのは 55 ① だけである**。
**1 つ確かめただけで項目ごと消さない**（[32 §3](32_調査のルール.md)）ので、残り 2 点をここへ割って戻した。

| 論点 | Claude の読み |
|---|---|
| **別表二十四**の記載事項（六）（十二）（十四）の「事由」を、`開始残高`・`前期繰越` のような固定語で満たせるか | **満たせると読んでいる**——**これらの伝票は取引を記していない**ので、書ける「事由」は「前期から引き継いだ」以上のものが無い。**ただし諮っていない** |
| [10 §4-2-1](10_会計ドメイン設計.md) の**摘要の必須**（`E-DESCRIPTION-EMPTY`）を、3 種にも当てるか | **当てる**と読んでいる——[ADR-0059](decisions/0059-期首残高と繰越と決算振替は仕訳として持ち閉鎖残高勘定は作らない.md) が摘要の文言を決めたので、**サーバが必ず入れる**。関門を種別で緩める必要は無い。**ただしこれも諮っていない** |

**Claude の推奨は、2 つとも上の読みのままで進めること。**
**どちらも「製品が何を書くか」の話で、利用者に負わせるものが増えない**からである。
**違うなら、別表二十四（六）（十二）（十四）の「事由」に何を書くべきかを教えてほしい。**

**関連**: [40 §4-1](40_優良な電子帳簿の対応表.md)・[対象帳簿リサーチ §2](research/2026-09-06_優良な電子帳簿の対象帳簿と記載事項.md)（別表二十四の逐語）・[ADR-0059](decisions/0059-期首残高と繰越と決算振替は仕訳として持ち閉鎖残高勘定は作らない.md)。

## Q-16 登録番号の行を、画面から消す手を作るか

| | |
|---|---|
| **急ぎ** | **フェーズ 6**（公表システムからの取込を設計する回。取込が「削除」の差分を受けたときの形と同じ根） |
| **決まらないと止まるもの** | 止まらない。それまで、誤って足した余分な行は内容を編集して使い回す |
| **どこの話か** | 取引先の詳細の登録番号の一覧（`PartnerInvoiceRegistration`。`CanDelete: false`。[14 §5](14_適格請求書発行事業者の登録.md) の R-I8） |
| **既に決まっていること** | 取消・失効は終わりを記録して残す（[14 §4](14_適格請求書発行事業者の登録.md)）。**正しく入力された行の話**で、入力の誤りを消せないことまでは決めていない |

**状況。** 入力の導線を取引先の詳細 1 本にしたことで逃げ場が消えた（[R29-12](qa/02_自己レビュー記録.md)）。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| A. 作らない | いまのまま。余分な行は編集して使う | 不変性が単純 | 本当に余分な行は永久に残る |
| **B. 計上済みの仕訳が写していない行だけ消せる** | 関門と DDL のトリガで「その行を写した計上済み明細が無い」を条件に削除を許す | 誤入力を消せる。帳簿の写しは守られる | 条件つき削除の形が 1 つ増える |
| C. 取消・失効で終わりを記す | 「誤入力」という終わり理由を足す | 行の削除禁止を保つ | 帳簿に「誤入力の登録番号」が履歴として残る |

**Claude の推奨は B。** 写しが無い行は帳簿のどこにも出ていないので、消しても帳簿は変わらない（**設計上の事実**）。要件への当てはめ（優良な電子帳簿の訂正・削除の履歴に当たらないか）は **Claude の読み**で、確かめてほしい。

**関連**: [14 §4](14_適格請求書発行事業者の登録.md)・[14 の保留](14_適格請求書発行事業者の登録.md)（処理区分 99）。

## Q-25 検索欄に入れた末尾の空白を、どこで落とすか（いまはどこも落としていない）

| | |
|---|---|
| **急ぎ** | 期限なし。ただし**帳簿の検索は利用者が毎日触る導線**で、症状が「該当なし」としか出ない |
| **決まらないと止まるもの** | 止まらない。いまも検索はできる（末尾に空白を入れたときだけ 0 件になる） |
| **どこの話か** | 4 つのクエリモジュールの文字入力欄。いずれも `ShouldTrimAfterEdit: false` |
| **既に決まっていること** | **コードは保存時に前後の空白を落とす**（[ADR-0047](decisions/0047-マスタのコードは空白を落とす以外書き換えず字種で断る.md)）。**検索欄については決めていない** |

**状況。** 登録番号や摘要の検索欄に `T1234… ` と**末尾の空白**を入れると、
`LIKE '%T1234… %'` になって **0 件**になる。画面には「該当なし」としか出ないので、
**利用者は「無い」と判断する**（[qa/01](qa/01_CLB静かな失敗.md) の静かな失敗の形）。
**貼り付けで空白が付くのはよくある**。

| 案 | 何をするか | 利点 | 欠点 |
|---|---|---|---|
| **A（推奨）. 画面のフィールドで落とす** | 検索欄の `ShouldTrimAfterEdit` を `true` にする（4 モジュール分） | **入れた値が見た目でも直る**ので、利用者に何が起きたか分かる。SQL は触らない | デザイン JSON を 4 か所（変更点が散る） |
| B. SQL で落とす | `trim(@p_keyword)` を各条件に入れる | 1 ファイルずつで閉じる | **画面には空白が残る**ので、次に押したときの挙動が読めない。条件式が 1 段深くなる |
| C. 何もしない | いまのまま | 変更ゼロ | 症状が「該当なし」なので、**利用者は自分の入力を疑わない** |

**Claude の推奨は A**（**設計判断であって制度の話ではない**）。
**ただし「検索欄は全部そうする」という規則にするかどうかは開発者に決めてほしい**——
決めれば [21_画面の原則](21_画面の原則.md) に 1 行置いて、以後の画面に自動で効く。

**関連**: [qa/02 のラウンド 91](qa/02_自己レビュー記録.md)（この問いが出た回。**動かさないと決めた**）。

## Q-27 行セットの差分で殺す掃引を、コミット前フックに載せてよいか

| | |
|---|---|
| **急ぎ** | 期限なし。ただし**いま載せないなら、クエリの SQL を触った人が手で流すのを忘れたときに誰も気づかない** |
| **決まらないと止まるもの** | 止まらない。手で流せる（`pwsh -NoProfile -File tools/clb/sql_sweep.ps1 -Mode Rows`）。**計器の配線が腐っていないことは、いまも `dotnet test` の傘下で毎回見ている** |
| **どこの話か** | コミット前フックの段（[tools/README](../tools/README.md) の表）と `tools/clb/sql_sweep.ps1` |
| **既に決まっていること** | **載せない理由は速さではなかった**——[ADR-0056](decisions/0056-SQLミューテーションはクエリのSQLを1箇所ずつ壊し行動テストだけで赤になるかを見る.md) 決定 7 の逐語は「**生き残りが多いうちは、毎回流しても上限を通るだけで誰も読まない**」。同 決定 7 は「**減らしてから、載せるかを開発者に諮る**」と続けている。**前例がある**——[ADR-0012 §8](decisions/0012-テスト方針とカバレッジのゲート.md) の Stryker は、当初「フェーズの区切りで」としたものを**実測の速さを見て開発者の判断で毎回実行へ変えた** |

**状況が変わった。** 2026-09-15 に **B 案（行セットの差分で殺す掃引）** が入った（[ADR-0058](decisions/0058-行セットの差分で殺す掃引は入力コーパスを持たず行動テストが流した入力をその場で当てる.md)）。

- **速さ**: `-Mode Rows` は**端から端まで 7.4 秒**（ビルド込み。掃引そのものは 5 秒）。
  **A 案（`-Mode Tests`）は 6 分 13 秒**なので、**こちらは載せる話にならない**
- **生き残り**: **15 件まで落ち、全部に説明が付いている**（型 A の範囲比較 10・型 B の並び順 4・`CASE` の `DISTINCT` 1。
  内訳は ADR-0058 の実測）。**「誰も読まない」という理由は、もう当たらない**
- **ラチェットは読むものではなく鳴るものである。** 緑のときは何も読まなくてよく、
  **説明の付かない点が 1 つ増えた日にだけ止まる**
- **フック全体の重さから見ると誤差**である。`dotnet stryker` の段は 5 プロジェクトで数分かかる

**選択肢**

| 案 | 中身 | 短所 |
|---|---|---|
| **A（推奨）** | **`-Mode Rows` を 1 段足す**（`dotnet test` の段の後）。`-Mode Tests` は今までどおり手動 | 文書だけのコミットでも 7 秒余分にかかる。**python と dotnet の両方に依存する段が 1 つ増える** |
| B | 載せない（現状のまま）。区切りで手で流す | **流し忘れに誰も気づかない。** いまも [31 §6](31_検証のルール.md) の文章だけが守っている |
| C | `-Mode Rows` も `-Mode Tests` も載せる | **毎回 6 分**。コミットのたびに待たされ、**フックを迂回する習慣ができる**——いちばん避けたい形 |

**Claude の推奨は A。** **7 秒で、流し忘れという人の失敗が 1 つ消える。**
**B の危険は具体的である**——2026-09-14 に `JournalEntryList` の行動テストが
「SQL の絞り込みを 1 つも撃っていない」状態で通っていた（[qa/03 の L-47](qa/03_テストで漏らした実例.md)。
**入れてから 11 日である**——日数の出どころは git log で、L-47 には書いていない）。
**あれを見つけたのは掃引を手で流した回**であって、**流さなければ今も気づいていない。**
**ただし見つけたのは `-Mode Tests` である。** `-Mode Rows` でも同じ点が生き残りに出たはずだ、というのは
**Claude の読みで、当時の検体で回して確かめてはいない**——
根拠は「**どのテストもその引数を束縛していないなら、どの入力でも行は変わらない**」という理屈だけである。

**やってほしいこと。** A・B・C のどれかを教えてほしい（A なら Claude が
`tools/git-hooks/pre-commit` と [tools/README](../tools/README.md) の段の表を直す）。**いつ**——期限なし。
