## 保留リスト

**開発者に確認したいこと**（2026-08-25 時点）。決まったらここから消して、決定は ADR か仕様書へ移す。

1. ~~`posted_by`（計上した人）を今入れるか~~ → **入れる**（2026-08-25 決定）。次に着手する
2. **DB マイグレーションの仕組みが無い。** DDL を変えたとき稼働 DB には `sql` CLI で手で当てている。
   デモデータ（フェーズ 7）や配布を考えると仕組みが要る
3. ~~空文字と NULL の一本化~~ → **画面経路は問題なし**（2026-08-25 実測）。
   CLB は入力して消した場合も空文字ではなく **NULL** を書く（`typeof(description) = 'null'`）。
   仕訳帳の空値検索に入れた「空文字も拾う」防御は、CSV 取込・投入 API（フェーズ 6）に備えて残す
4. ~~摘要の入れ子~~ → **今の仕様でよい**（2026-08-25 決定）。計上済みは不変なので遡って直さない
5. ~~`partner_name_snapshot` の焼き込み方~~ → **[ADR-0018](decisions/0018-帳簿の記載事項は計上時に写して固定する.md) で決着**（2026-08-25）。
   帳簿の記載事項は計上時に写して固定し、制度上の資格（登録番号）は有効期間つきのマスタで持つ
6. ~~`partners` に住所欄が無い~~ → **決着**（2026-08-25 決定）。
   スコープ内で相手方の住所が要るのは**入場券等の回収特例で 1 回 3 万円以上**の 1 類型だけ
   （他の類型は[機能スコープ](03_機能スコープ.md)がスコープ外にしている）。
   **住所は明細の「内容」欄に書く運用**とし、写しの列は作らない。
   `partners` には一般の取引先マスタとして `address TEXT` を 1 本だけ持つ
7. **法人番号を必須にするか任意にするか。** 名寄せの主役は法人番号だが、外国法人・人格のない社団等・
   入力時点で不明な場合があり、必須にすると入力が止まってダミー値が入る。
   任意にして未入力を警告する案と、取引先マスタの画面でだけ必須にする案がある
8. **法人／個人の種別を持つか。** 持つなら値は何か（法人／個人事業者／人格のない社団等／その他）。
   登録番号から法人番号を導いてよいかがこの種別で決まる
9. **法人番号と `parent_partner_id` が食い違ったときどちらを採るか。**
   法人番号は「同じ値なら同一」の自然キー、`parent_partner_id` は人が束ねる手動キーで、
   性質が違う。両方あって矛盾する場合の扱いを決める必要がある
10. **取引先マスタは会計コアの一部か、より上位の別部品か**（開発者の指摘。2026-08-25）。
    依存の向きは既に `Partners → 依存なし` / `Journals → Partners` で
    [ADR-0013](decisions/0013-機能単位のモジュール分割と依存方向.md) の規約テストが守っている。
    物理的に別プロジェクトへ出すかは未決
