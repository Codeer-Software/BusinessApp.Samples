# ドキュメント索引 — 何をするときに何を読むか

## 保留リスト

**開発者に確認したいこと**（2026-08-26 時点）。決まったらここから消して、決定は ADR か仕様書へ移す。
**いま未決なのは 9 だけ**（1〜8 は決着済み。経緯として残してある）。

1. ~~`posted_by`（計上した人）を今入れるか~~ → **入れる**（2026-08-25 決定）。次に着手する
2. ~~DB マイグレーションの仕組みが無い~~ → **決着・実装済み**（2026-08-25）。方式は
   [ADR-0020](decisions/0020-スキーマは現在形の正典で持ち変更は差分で配る.md)、
   手順は [migrations README](../Designer/migrations/README.md)
3. ~~空文字と NULL の一本化~~ → **画面経路は問題なし**（2026-08-25 実測）。
   CLB は入力して消した場合も空文字ではなく **NULL** を書く（`typeof(description) = 'null'`）。
   仕訳帳の空値検索に入れた「空文字も拾う」防御は、CSV 取込・投入 API（フェーズ 6）に備えて残す
4. ~~摘要の入れ子~~ → **今の仕様でよい**（2026-08-25 決定）。計上済みは不変なので遡って直さない
5. ~~`partner_name_snapshot` の焼き込み方~~ → **[ADR-0018](decisions/0018-帳簿の記載事項は計上時に写して固定する.md) で決着**（2026-08-25）。
   帳簿の記載事項は計上時に写して固定し、制度上の資格（登録番号）は有効期間つきのマスタで持つ
6. ~~`partners` に住所欄が無い~~ → **決着**（2026-08-25 決定）。
   スコープ内で相手方の住所が要るのは**入場券等の回収特例で 1 回 3 万円以上**の 1 類型だけ
   （他の類型は[機能スコープ](03_機能スコープ.md)がスコープ外にしている）。
   **住所は明細の「内容」欄に書く運用**とし、写しの列は作らない。
   `partners` には一般の取引先マスタとして `address TEXT` を 1 本だけ持つ
7. ~~取引先マスタの識別・名寄せ・設計の置き場所~~ → **決着**（2026-08-25）。
   分類は [ADR-0019](decisions/0019-マスタは会計が生んだ概念かで分ける.md)、
   設計は [07_取引先設計](07_取引先設計.md) が持つ。個別の未決は 07 の保留リストへ移した
8. ~~「作らないと整理したもの」をどこに残すか~~ → **[03_機能スコープ](03_機能スコープ.md) に
   `×` の 1 行を足す**（2026-08-25 決定）。判断の基準は ADR、個別の可否は 03、
   基準そのものを変えるときだけ新しい ADR を起こす。
   個別機能の可否で ADR を増やすと索引そのものが読めなくなるため
9. **利用者に見せる文言に改行を入れるのをやめるか**（2026-08-26。**未決**）。
   トーストは改行を表示に出さず、違反を複数並べると 1 行に繋がる——**LF でも CRLF でも同じで、
   CLB の制限である**（開発者が実機で確認。[qa/01](qa/01_CLB静かな失敗.md) D-12）。
   独自のエラー表示を作るほどの利得は無さそう、という点は開発者と一致している。
   残るのは「**改行を前提に組み立てている文言を、1 行で読める形に直すか**」で、
   対象は `JournalPostingRejectedException` の違反一覧。**着手順 1 の実装と一緒に決める。**
