# ドキュメント索引 — 何をするときに何を読むか

> **ここが唯一の入口。** 目的の文書はこのページから引く。文書一覧ではなく**タスク起点の案内**である。
> 文書の書き方・`status` の意味・腐り防止の約束は [00_ドキュメント規約](00_ドキュメント規約.md)。

## 1. 実装する

| やること | 読むもの |
|---|---|
| **次に何をやるか知る／作業を再開する** | [05_実装計画と進捗台帳](05_実装計画と進捗台帳.md)（「次にやること」だけ読めば再開できる） |
| **会計の正しさを確かめる**（仕訳・税・締め・繰越） | [04_会計ドメイン設計](04_会計ドメイン設計.md) — 複式簿記の正しさはここで担保する |
| 新しい機能を検討する | [03_機能スコープ](03_機能スコープ.md) → 該当する [ADR](decisions/README.md) |
| 「この機能は入れるのか」を判断する | [02_ペルソナ](02_ペルソナ.md) → [03_機能スコープ](03_機能スコープ.md) |
| 消費税の計算を実装する | [消費税・インボイス制度リサーチ](research/2026-08-23_消費税インボイス制度.md) |
| 帳簿の保存要件を実装する | [電子帳簿保存法リサーチ](research/2026-08-23_電子帳簿保存法.md) |
| CLB の書き方を調べる | `../Designer/CLAUDE.md` → `../Designer/ClaudeCodeForDesigner/CLAUDE.md`（仕様リファレンス） |
| CLB の制約・「静かな失敗」を避ける | [qa/01_CLB静かな失敗](qa/01_CLB静かな失敗.md) |
| **判断の経緯を知りたい** | [decisions/README](decisions/README.md)（ADR。仕様書は What、経緯はこちら） |

## 2. 確かめる

| やること | 読むもの |
|---|---|
| デザインの静的検査 | `designcheck` CLI（`../Designer/CLAUDE.md`） |
| 公開前チェック | `python tools/docs/lint_secrets.py` |
| ドキュメント規約の検査 | `python tools/docs/lint_docs.py` |
| デプロイして実機で確認する | `pwsh -NoProfile -File tools/clb/deploy.ps1` → [tools/README](../tools/README.md) |

## 3. 説明する

| やること | 読むもの |
|---|---|
| 「何を・なぜ作っているか」を説明する | [01_企画概要](01_企画概要.md) → [02_ペルソナ](02_ペルソナ.md) |
| 制度・法令の根拠を示す | [research/](research/)（一次情報。出典 URL と確認日つき） |
| CLB へのフィードバックを見る | [11_CLB改善提案/](11_CLB改善提案/README.md) |
