# 会計ドメイン設計

> 作成: 2026-07-05 / 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映＝権限表記のみ）・2026-08-09（全ドキュメント現行化スイープ。fiscal_years.label・部課2階層・伝票部門=部ノードの不変条件を反映）・**2026-08-14（ADR-0056: 仕訳行の部門を NOT NULL 化。損益科目は実部門必須・BS は全社共通で補完・確定後も部門/案件は編集可）** / **複式簿記の正しさは本書で担保する。実装は必ず本書に従う。**
> 主要判断の経緯は `decisions/0002`〜`0005` を参照。テーブル定義は実装時に `Designer/ddl/` の DDL が正となる（本書と食い違ったら本書を直すか ADR を起こす）。

## 0. 原則

1. **仕訳がすべての起点。** 帳票（元帳・試算表・BS/PL）は仕訳明細行の集計「のみ」から導出する。集計済み残高テーブルは持たない（期首残高を除く。→ `decisions/0004`）。
2. **貸借一致しない伝票は「確定」できない。** 下書き保存は許すが、確定（帳票に載る状態）は借方合計＝貸方合計をアプリ層で強制。
3. **金額は整数円（INTEGER）。** 小数は持たない。端数処理は発生地点（税計算等）で規定する。
4. **締め済み期間の仕訳は変更不可。** 訂正は赤黒（反対仕訳＋正しい仕訳）で行う。
5. **制度値（税率・区分・閾値）はマスタ参照。** ハードコード禁止。

### 3.1 貸借と金額の持ち方（決定）
- **1行1側（dc 列で借/貸を区別）＋正の整数 amount。** 複合仕訳（1:N, N:N）は行の並びで自然に表現。
- 検証（確定時に必須、下書きでは警告のみ）:
  - `Σ(D行 amount) == Σ(C行 amount)`
  - 全行 `amount > 0`、`account_id` 必須
  - `entry_date` の period が open
- 残高・集計の基本式: **残高 = 期首残高 + Σ借方 − Σ貸方**（符号は科目の `dc_normal` で表示時に正負反転）。

### 3.2 消費税の持ち方（決定: 明示税行方式・税抜経理）
- ユーザーは行に「金額（内税/外税）＋税区分」を入力する。
- 保存時にシステムが **仮払消費税(1900)／仮受消費税(2200) の行を自動生成**する（`is_tax_line=1`・`parent_line_no` で紐付け）。元帳・試算表・BS/PL は「行の単純集計」だけで常に正しくなる。
- 元行を編集・削除したら税行は必ず再生成。ユーザーは税行を直接編集できない（税額の手修正が必要なケース＝端数調整は、税額フィールドの上書き入力を許し、その値で税行を再生成する）。
- 端数処理: 内税の税額抽出は `税込額 × 率/(100+率)` を**切り捨て**、外税は `税抜額 × 率/100` を**切り捨て**（実務多数派。マスタで丸め方法を変更可能にする）。
- 免税事業者からの仕入（経過措置）: 税区分「課仕入(経過措置)」を選ぶと、控除割合マスタ（§4）に基づき**控除可能分のみ仮払消費税**、残りは本体に上乗せ（実務標準の処理）。例: 2026-10以降(70%) 税込11,000 → 仮払消費税 700・費用 10,300。

## 5. 帳票の導出規則

| 帳票 | 導出 |
|---|---|
| 仕訳帳 | journal_entries+lines を期間で列挙（posted のみ。draft は入力画面でのみ見える） |
| 総勘定元帳 | 科目×期間の行列挙＋開始残高（期首残高+期間前集計）＋累計残高列 |
| 補助元帳 | 同上を sub_account 単位で |
| 合計残高試算表 | 科目ごとに 前月残・借方計・貸方計・当月残。**借方合計総計＝貸方合計総計の検算列を必ず表示**（複式の健全性をユーザーに見せる） |
| BS | account_categories(statement=BS) 順に残高集計。**当期純利益は PL から算出して純資産の部に差し込む**（繰越利益剰余金＋当期純利益） |
| PL | 同 PL 区分。売上総利益/営業利益/経常利益/税引前/当期純利益の段階計算 |
| 消費税集計表 | tax_category 別に本体額・税額を集計（税行と parent の対応で機械的に出る） |

- 実装は CLB の QueryField（SQL）を正とし、SQL は `Modules/*.{Query}.sql` に置く。

## 6. 締め・繰越

### 月次締め
1. 対象 period の draft 伝票が残っていれば警告（一覧表示）。
2. period.status = closed。以後、該当期間の伝票は新規・変更・削除とも拒否（保存時検証）。
3. 締め解除（reopen）は経理機能フラグ（HasAccountingAccess）保有者のみ可（監査ログ対象）。

### 年次決算（第N期 → 第N+1期）
1. 全 period が closed であること。
2. **損益振替仕訳を自動生成**（entry_type=auto）: 全収益・費用科目の残高を「繰越利益剰余金(3100)」へ振替。これにより PL 科目の翌期繰越は常にゼロ。
3. **翌期の opening_balances を生成**: BS 科目（資産・負債・純資産）の期末残高を科目・補助・部門単位でコピー。
4. fiscal_year.status = closed。締め後の前期修正は翌期の伝票（前期損益修正）で行う。

### opening_balances（期首残高）
| 列 | 備考 |
|---|---|
| id / fiscal_year_id / account_id / sub_account_id(NULL可) / department_id(NULL可) | |
| balance | INTEGER。**符号付き: 借方残=正・貸方残=負** に統一（集計式が単純になる） |

- 導入初年度（第17期）の期首残高は手入力画面から投入。**投入合計が貸借一致しないと確定不可**（複式の入口を守る）。

## 8. 部門・プロジェクト・取引先（フェーズB以降の骨格だけ規定）

- **departments**: id/code/name/is_active に加え **`parent_id`（自己参照）・`node_type`（'dept'部/'section'課）で部課2階層**（ADR-0044・ddl/410。課はオプション）。さらに **`is_common`（共通費の受け皿。code `00` の「全社共通」に立てる）**（ADR-0056）。共通部門配賦はフェーズB'。
  - **不変条件: 伝票・仕訳の部門は部ノード（`node_type='dept'`）のみ**。既定値は起票者の所属部（主所属が課なら祖先の部＝`app_users.business_department_id` キャッシュ、UI 名「所属部」）。課は伝票の部門候補に出ない。
  - **不変条件（ADR-0056）: 仕訳行の部門は必ず埋まる**（`journal_lines.department_id` は NOT NULL）。
    **損益科目（`accounts.account_type` が `expense`/`revenue`）の行には実部門が要り**、人が画面にいる起票経路
    （振替伝票・入出金起票・仕入先請求書・銀行の一括起票）は空ならエラーで止める。
    BS 科目の行は任意で、機械的に決まらないものは `JournalEntry.FillMissingDepartments()` が
    **全社共通**（`is_common`）で埋める（税行は親行から継承）。「未設定（NULL）」という表現は持たない——
    税区分で `NULL` を廃止して「対象外」を明示した ADR-0052 と同じ形。
  - **確定済み伝票でも部門・案件だけは編集できる**（振替伝票の「部門・プロジェクトを修正する」から入るサブ画面。締め済み期間は不可・経理のみ）。
    財務諸表（BS/PL/試算表/消費税集計表）は 1 円も動かない分析の軸だから許される。摘要・金額・科目・日付は不可。
- **projects**: id/code/name/partner_id/project_type(contract受託/ses/saas/internal)/status/受注額等。仕訳行に付与（任意）→ 案件別損益は仕訳集計＋工数配賦で導出。登録・変更は**経理 ∨ 部長（`is_director`）**、SES 精算条件（単価・精算幅）は経理のみ編集（ADR-0046）。
- **partners**: id/code/name/kana/is_customer/is_supplier/invoice_reg_no(T+13桁)/is_tax_exempt(免税事業者=経過措置対象)/締め日・支払条件等。

## 9. 整合性の守り方（実装チェックリスト）

- [ ] 確定時の貸借一致検証（スクリプト。ヘッダに借方計・貸方計・差額を常時表示）
- [ ] 締め済み期間ガード（保存・削除の両方）
- [ ] 税行の再生成（元行の変更・削除に追随。孤児税行を作らない）
- [ ] posted 伝票の編集制御（経理機能フラグ＋open 期間のみ。それ以外は赤黒訂正へ誘導）
- [ ] 年度切替時の journal_no 採番リセット
- [ ] 試算表の総借方＝総貸方検算をデモデータで常時確認（自動テスト的に sql CLI で検算クエリを流す）
- [ ] 期首残高の貸借一致検証
