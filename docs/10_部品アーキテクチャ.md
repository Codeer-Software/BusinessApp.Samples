# 部品アーキテクチャ仕様書

> 作成: 2026-08-02（ADR-0040/0041）。本書が **部品の定義・依存ルール・削除手順・カスタムポイントの正典**。
> 本アプリはテンプレートとして再利用されることを前提に、「使いたい部品だけ組み合わせる／自社に合わせて一部だけ直す」単位＝**部品**で構成される。再利用の単位は PageFrame。

## 1. 部品一覧とレイヤ

依存は**下方向のみ**許可（上のレイヤは下を知らない）。

| レイヤ | 部品 | 必須 | Modules フォルダ | PageFrame | 修正されやすさ |
|---|---|---|---|---|---|
| 0 | 基盤・マスタ | 必須 | `Shell/` `MasterSystem/` `MasterBusiness/` | Main／MasterBusiness／MasterAdmin | 低（組織・制度マスタはデータで吸収） |
| 1 | 会計 | 必須コア | `Accounting/` `Bank/` `FinancialReports/` | Accounting | **低**（法令で決まるためほぼ無修正） |
| 2 | 営業業務 | 任意 | `Sales/` | SalesStaff／SalesBilling | 中（商流は会社ごとに違う） |
| 2 | 購買業務 | 任意 | `Purchasing/` | Purchasing | 中 |
| 2 | 経費精算 | 任意 | `Expense/` | ExpenseStaff／ExpenseApprover／ExpenseAccounting | **高**（申請・承認ルールは各社カスタム前提） |
| 2 | 工数管理 | 任意 | `Timesheet/` | Timesheet／TimesheetAccounting | 高 |
| 3 | 経営管理 | 任意 | `Management/` | ManagementApprover／ManagementFull | 中（全部品を読む最上位の集約） |

- マスタ管理は淡々と CRUD するだけで、**各部品のロジックに依存しない**（完全な葉ノード）
- 各部品のトップページ（ExpenseHome／SalesHome／AccountingHome 等）の参照は自部品内に限定

## 2. 権限モデル（ADR-0041 の要約）

- 真実は「**部門メンバーマスタ**（ユーザー×部門×一般/課長/部長 = `department_members`）」と
  「**AppUser.システム管理者フラグ**」の 2 つだけ。旧ロールは廃止済み
- 見え方＝メンバーシップの合成。フレームゲートは AppUser のキャッシュ列
  （営業アクセス/経理アクセス/承認者）で判定し、**DB トリガーが自動転記**（手入力不可・`ddl/385` で全再計算可）
- 部門マスタの**部門種別**（開発/営業/経理/その他）が「どの部の担当者にどの部品を見せるか」を決める。
  組織改編はマスタ変更だけで追随し、フレーム定義は部門名を知らない

| フレーム | ゲート |
|---|---|
| Main・ExpenseStaff・Timesheet | なし（ログインユーザー全員） |
| ExpenseApprover・ManagementApprover | 承認者（どこかの部門の課長/部長） |
| SalesStaff | 営業アクセス |
| SalesBilling・Accounting・Purchasing・ExpenseAccounting・TimesheetAccounting・ManagementFull・MasterBusiness | 経理アクセス |
| MasterAdmin | システム管理者フラグ |

着地（RoleDispatch）: 管理者→MasterAdmin ／ 経理→Accounting ／ 承認者→ExpenseApprover ／ 営業→SalesStaff ／ 他→ExpenseStaff。

## 3. 部品間依存マップ

### 3.1 正規の依存（下方向・常時）

- 全部品 → 基盤・マスタ（参照マスタ: 取引先・案件・部門・科目・税制・ユーザー）
- レイヤ2 の各業務 → 会計（`JournalEntry` への仕訳生成、`FiscalYear`/`FiscalPeriod` の締めガード）
- 経営管理 → 会計・営業・購買・経費・工数（SQL クエリでの読取集約）

### 3.2 オプション連携（例外は 3 つだけ・削除手順つき）

| 連携 | 実体 | 部品を外すときの手直し |
|---|---|---|
| 営業 → 購買（相殺入金） | `Sales/Receipt`: `OffsetVendorInvoiceRef`（json）＋ `Receipt.mod.cs` の `VendorInvoice` 参照 3 箇所（46,48,300 行付近） | 購買を外す場合: Receipt の相殺入金フィールドとスクリプト該当箇所を除去 |
| 営業 → 工数（SES 精算） | `Sales/SesBilling.mod.cs` の `ModuleSearcher<TimeEntry>`（106 行付近） | 工数を外す場合: SES 精算・請求（SesBilling/SesRunPlan）ごと外すか、工数集計部を除去 |
| 経費 → 会計（少額資産） | `Expense/ExpenseRequest.mod.cs` の `new FixedAsset()`（561 行付近） | 会計は必須部品のため通常発生しない |

既知の逆流 1 件: `ApprovalFlow → ExpenseRequest`（承認エンジンがクライアントを逆参照）。承認一式は
経費精算部品**内**に置くことで許容している。他部品に承認を広げるときはエンジンの汎用化が先（将来課題）。

### 3.3 削除可能性の実測（2026-08-02・受け入れ基準）

部品の「フレーム＋フォルダ＋他フレームからの切替リンク」を削除して designcheck:
経営管理= **0 件**／購買= Receipt 相殺 4 件のみ／工数= SesBilling 1 件のみ（いずれも §3.2 記載どおり）。

## 4. 部品の外し方（テンプレート利用手順）

1. 対象部品の `PageFrames/*.frm.json` を削除
2. 対象部品の `Modules/<フォルダ>/` を削除
3. 残る全フレームの `Left.Links` から、削除したフレームを `PageFrame` に指定する切替リンクを除去
4. §3.2 のオプション連携に該当する場合はその手直しを適用
5. `designcheck` → findingCount 0 を確認 → デプロイ
6. （任意）不要になったテーブルの DROP と、部品別ホームのボタン（ExpenseHome/SalesHome の
   `Go*Btn`）の削除。ボタンは URL 遷移のみで型参照が無いため、残っても designcheck は通る
   （クリック時に「アクセス権限がありません」となるだけ）

## 5. フレーム変種マトリクス（機能追加時のチェックリスト）

同一部品の変種フレームはメニューを重複して持つ（CLB はリンク単位の可視条件を持たない= FB-009）。
**部品にメニューを足すときは、その部品の全変種に同じ変更を入れること。**

| 部品 | 変種 | 差分 |
|---|---|---|
| 経費精算 | ExpenseStaff ⊂ ExpenseApprover ⊂ ExpenseAccounting | Approver=＋承認待ち／Accounting=＋精算処理待ち |
| 工数管理 | Timesheet／TimesheetAccounting | Accounting=＋工数管理（経理）、案件一覧は Staff のみ |
| 営業業務 | SalesStaff ⊂ SalesBilling | Billing=＋請求書・入金・定期請求実行・SES（取引先一覧は Staff のみ） |
| 経営管理 | ManagementApprover ⊂ ManagementFull | Approver=予実対比・予算明細のみ |
| マスタ | MasterBusiness／MasterAdmin | 交差なし（業務・会計マスタ／組織・承認ガバナンス） |

経理系 7 フレームは「ほかの業務」静的リンクで相互接続。新しい経理系フレームを足すときは
7 フレーム全部の「ほかの業務」に追記する。

## 6. カスタムポイント（導入企業が触る場所）

| やりたいこと | 触る場所 |
|---|---|
| 部品を外す | §4 の手順 |
| 部門の新設・分割・種別変更 | 部門マスタのみ（画面・権限は自動追随） |
| 誰にどの業務を見せるか | 部門メンバーマスタの行を足す/消す（例: 開発 PM に見積を作らせる → 営業種別部門の「一般」行を 1 行追加） |
| sysadmin を従来型スーパーユーザーに戻す | 各フレームの `UserReadCondition` に `IsSysAdmin == true` の OR を追加（＋モジュール条件も同様） |
| 承認ルートの変更 | 承認テンプレート・承認ルート判定マスタ（ADR-0023。コード変更不要） |
| 税率・制度変更 | 税制マスタ（MasterBusiness。ハードコード無し） |
| 着地フレームの変更 | `Shell/RoleDispatch.mod.cs` の優先順位（数行） |

## 7. 実装規約（この構成を壊さないために）

- 新モジュールは部品のフォルダに置き、**下方向以外の参照を作らない**。やむを得ない横断は §3.2 に追記して
  「オプション連携＋除去手順」をセットで文書化する
- スクリプトの画面遷移: 同一部品内は `GetModuleUrl`/`GetModuleDataUrl`（現在フレーム解決）、
  部品跨ぎは `/{Frame}/Top` への NavigateTo（Top セグメントは全フレームに登録済み）
- 部品別ホーム（*Home）から他部品のモジュール型を参照しない（ModuleSearcher も不可）。
  他部品の情報を出したくなったら、それは経営管理（レイヤ3）の仕事
- 権限判定はキャッシュ列（`HasSalesAccess`/`HasAccountingAccess`/`IsApprover`/`IsSysAdmin`）のみを使う。
  部門名・ユーザー名でのハードコード判定は禁止
