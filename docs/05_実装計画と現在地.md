## 1. 次にやること

**用語は [ADR-0017](decisions/0017-仕訳と伝票の呼び分け.md) に従う。** 入力の単位は「振替伝票」、帳簿は「仕訳帳」。画面で「仕訳」と単独で書かない。
**利用者に見せる文言は「です・ます」調で、内部表現を出さない**（[CLAUDE.md §2-7](../CLAUDE.md)）。

**取引先まわりは設計だけ決まっていて、実装はこれから。** 分類と設計は
[ADR-0019](decisions/0019-マスタは会計が生んだ概念かで分ける.md)・[07_取引先設計](07_取引先設計.md)。
DB マイグレーションの仕組みは**実装済み**（§2）。スキーマを変える手順は
[migrations/README](../Designer/migrations/README.md)。

**着手順**（上から）

1. **取引先の列とテーブルを足す**（[07_取引先設計](07_取引先設計.md)）。
   `partners.entity_type / corporate_number / parent_partner_id / address` と
   `partner_invoice_registrations`。**登録テーブルの列は 07 §3-2 の案の段階。**
   公表サイトの仕様書（リソース定義書）を読んで確定してから作る
2. **取引先名と登録番号の写しを計上時に焼き込む**（[ADR-0018](decisions/0018-帳簿の記載事項は計上時に写して固定する.md)・07 §4）。
   サーバが書く。明細に取引先が無い行には伝票の取引先の値。登録番号は `tax_point` で引く。
   計上済みの行は直さない
3. **振替伝票に注意書きを出す**（07 §1-4。文言は確定済み）。あわせて取引先の画面に新しい列を出す
4. **帳簿間の相互関連性**（規則 5 ⑤一ロ）。仕訳帳の行から伝票へ辿れるようにする。
   `AnchorTagField`（`Module: JournalEntry` / `IdVariable: EntryId.Value`）が素直。
   `OnClick` は付けない（href とのレースになる。[qa/01](qa/01_CLB静かな失敗.md) D-04）。
   あわせて仕訳帳に**伝票番号での検索**を足す（通達 8-14 (注) の別ルート）
5. **総勘定元帳・補助元帳**。仕訳帳と同じクエリモジュールの形（`Designer/Design/Modules/Books/`）。
   元帳の記録項目は「記載年月日及び取引金額」（通達 8-14）なので仕訳帳の検索をほぼ流用できる。
   **残高は期首残高（フェーズ 4）が無いと出せない**ので、期間内の累計として出す
6. **優良な電子帳簿のチェックシートとの 1 対 1 の対応表**を書く。フェーズ 2 の完了条件
   （[電帳法リサーチ §13.1](research/2026-08-23_電子帳簿保存法.md) の A1〜G2 が素材）

**並行して進めてよいもの**（別ブランチ／ワークツリー。他の作業に影響しない）

- **`JournalsController` を検査の中に入れる**（[qa/02](qa/02_自己レビュー記録.md) R4-03〜R4-05）。

## 3. フェーズ

各フェーズは「**そのフェーズだけで検証できる**」単位に切ってある。

### フェーズ 1 — 会計コアの骨格（仕訳が正しく記録できる）

- C# プロジェクト 4 本の骨格とテスト基盤
- 勘定科目・部門・取引先・税区分のマスタ（DDL ＋ CLB モジュール）
- 会計年度・会計期間・事業所情報
- 仕訳（下書き → 計上）、伝票番号の採番、入力年月日の自動付与
- 不変条件 I-01〜I-06・I-13・I-17 の検証と自動テスト
- **完了条件**: 仕訳を入力して計上でき、計上済みが変更・削除できないことをテストと実機で確認できる

### フェーズ 2 — 訂正と帳簿（優良な電子帳簿の要件を満たす）

- 訂正・取消（反対仕訳）
- 仕訳帳・総勘定元帳・補助元帳
- 法定検索（3 項目・範囲・組み合わせ・Null 検索）
- 帳簿間の相互関連性（伝票番号でのドリルダウン）
- **完了条件**: 優良な電子帳簿のチェックシートの各項目に対して、
  「製品のどの機能が満たすか」を 1 対 1 で説明できる

### フェーズ 3 — 消費税

- 税区分・用途区分・制度ルール（有効期間つき）
- 税抜経理の消費税行の生成、税率ごとの端数処理
- 経過措置（控除割合の日付判定・相手方別上限）
- 課税売上割合・控除方式 3 種
- 税区分別集計表
- **完了条件**: 2026-10-01 をまたぐゴールデンテストが通り、税集計から仕訳へドリルダウンできる

### フェーズ 4 — 残高と決算

- 期首残高、試算表、月次推移、部門別試算表・部門別 P/L
- B/S・P/L・株主資本等変動計算書・個別注記表
- 月次締め・年度締め・再オープン
- 翌期繰越（暫定・確定・陳腐化検知）
- **完了条件**: 不変条件 I-07〜I-12 が自動テストで緑

### フェーズ 5 — 固定資産

- 固定資産台帳、減価償却（定額法・定率法・一括償却・少額減価償却資産）
- 償却仕訳の生成、除却・売却
- **完了条件**: 制度ルール（耐用年数・償却率）を版で切り替えても過去が再現できる

### フェーズ 6 — 入出力と統制

- CSV 取込（冪等性・Dry-run・行単位エラー）
- 完全なエクスポート（データ辞書つき）
- 監査ログ
- 他部品からの仕訳投入 API
- システム関係書類（概要書・操作説明書・事務手続書類のテンプレート）
- **完了条件**: 全データを出して読み戻せる。優良な電子帳簿の一般要件（システム関係書類）が揃う

### フェーズ 7 — 仕上げ

- デモデータ（第 17 期・第 18 期）
- 通しの体験シナリオと実機検証
- 性能確認（年間 3,000〜4,000 仕訳）
