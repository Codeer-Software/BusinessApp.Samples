## 1. 次にやること

**フェーズ 1 は完了条件を満たした。** 仕訳を入力して計上でき、違反は行番号つきで差し戻り、
却下すると伝票も明細も採番も残らず、計上済みは変更・削除できない。実機で確認済み。

次はフェーズ 2 の入口から。

1. **訂正**（`correction`）。取消と正しい内容の再計上を 1 操作にまとめる
   （[ADR-0015](decisions/0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md)）。
   スキーマ変更は不要と決着したので、いつでも着手できる。
   取り消せる種別に correction を加えるのを忘れない
2. **仕訳帳の「取引金額」検索は、明細の金額で引く**
   （[調査](research/2026-08-24_仕訳の取引金額での検索.md)で決着。伝票に金額列は持たない）。
   フェーズ 3 では弥生に倣い、本体金額と消費税額を別の検索軸にする
3. 計上済み伝票の画面に「この伝票を取り消す」ボタンを置く。
   今は新規作成で種別と原仕訳を選ぶので、原仕訳の画面からは辿れない
4. **空値検索**（通達 8-13）と**課税期間ごとの範囲指定**（通達 8-15）。
   どちらも優良な電子帳簿の要件で、未実装（[電帳法リサーチ](research/2026-08-23_電子帳簿保存法.md) §3.5）。
   - 空値検索は「無い＝NULL」の 1 通りに寄せてから作る（[04 §4-4](04_会計ドメイン設計.md)）。
     **CLB の検索レイアウトで NULL 条件が表現できるかは実装時に確認**し、
     できなければ帳簿画面（サーバ側 SQL）で実現する
   - 課税期間ごとの範囲指定は、検索条件に会計年度を残したまま日付・金額の範囲を
     組み合わせられれば満たせる見込み（年度条件は実装済み）

## 3. フェーズ

各フェーズは「**そのフェーズだけで検証できる**」単位に切ってある。

### フェーズ 1 — 会計コアの骨格（仕訳が正しく記録できる）

- C# プロジェクト 4 本の骨格とテスト基盤
- 勘定科目・部門・取引先・税区分のマスタ（DDL ＋ CLB モジュール）
- 会計年度・会計期間・事業所情報
- 仕訳（下書き → 計上）、伝票番号の採番、入力年月日の自動付与
- 不変条件 I-01〜I-06・I-13・I-17 の検証と自動テスト
- **完了条件**: 仕訳を入力して計上でき、計上済みが変更・削除できないことをテストと実機で確認できる

### フェーズ 2 — 訂正と帳簿（優良な電子帳簿の要件を満たす）

- 訂正・取消（反対仕訳）
- 仕訳帳・総勘定元帳・補助元帳
- 法定検索（3 項目・範囲・組み合わせ・Null 検索）
- 帳簿間の相互関連性（伝票番号でのドリルダウン）
- **完了条件**: 優良な電子帳簿のチェックシートの各項目に対して、
  「製品のどの機能が満たすか」を 1 対 1 で説明できる

### フェーズ 3 — 消費税

- 税区分・用途区分・制度ルール（有効期間つき）
- 税抜経理の消費税行の生成、税率ごとの端数処理
- 経過措置（控除割合の日付判定・相手方別上限）
- 課税売上割合・控除方式 3 種
- 税区分別集計表
- **完了条件**: 2026-10-01 をまたぐゴールデンテストが通り、税集計から仕訳へドリルダウンできる

### フェーズ 4 — 残高と決算

- 期首残高、試算表、月次推移、部門別試算表・部門別 P/L
- B/S・P/L・株主資本等変動計算書・個別注記表
- 月次締め・年度締め・再オープン
- 翌期繰越（暫定・確定・陳腐化検知）
- **完了条件**: 不変条件 I-07〜I-12 が自動テストで緑

### フェーズ 5 — 固定資産

- 固定資産台帳、減価償却（定額法・定率法・一括償却・少額減価償却資産）
- 償却仕訳の生成、除却・売却
- **完了条件**: 制度ルール（耐用年数・償却率）を版で切り替えても過去が再現できる

### フェーズ 6 — 入出力と統制

- CSV 取込（冪等性・Dry-run・行単位エラー）
- 完全なエクスポート（データ辞書つき）
- 監査ログ
- 他部品からの仕訳投入 API
- システム関係書類（概要書・操作説明書・事務手続書類のテンプレート）
- **完了条件**: 全データを出して読み戻せる。優良な電子帳簿の一般要件（システム関係書類）が揃う

### フェーズ 7 — 仕上げ

- デモデータ（第 17 期・第 18 期）
- 通しの体験シナリオと実機検証
- 性能確認（年間 3,000〜4,000 仕訳）
