# 再利用性レビューの試作ツール

[抜き取り実験](../02_抜き取り実験.md) で書いた解析・検査・削除の試作。
**まだ正式なツールではない**（正式化の提案は [03_改善提案 P7](../03_改善提案.md#p7)）。

引数を省略するとリポジトリルート（このファイルから 3 つ上）を見る。第 1 引数で上書きできる。

| ファイル | 用途 |
|---|---|
| `check_db_dangling.py [db]` | **検査**: DB のビュー・トリガが存在しないテーブルを参照していないか。部品削除後の必須チェック。引数を省略すると `LocalData/db/business-app_v1.db` を見る。現行 DB で 0 件（誤検出なし）／テーブルを 1 本落としたコピーで正しく 1 件検出、を確認済み。**このツールだけは正式化を提案している**（[03_改善提案 P7](../03_改善提案.md#p7)） |
| `deps_json.py` | モジュール JSON の部品間参照（`ModuleName`/`Module`/`TopPageModule`/`ModuleUrlSegment`） |
| `deps_script.py` | スクリプト `.mod.cs` の部品間**型参照**（`new X()` / `<X>` / `as X` / キャスト） |
| `deps_sql.py` | クエリ SQL の部品間テーブル参照 |
| `deps_ddl.py` | DDL を部品視点で分解（1 ファイルが触る部品・部品をまたぐ FK・トリガ・ビュー） |
| `master_usage.py` | 基盤モジュールの逆引き（どの部品から使われているか） |
| `strip_fields.py <module.mod.json> Field...` | **削除**: モジュールからフィールドを消し、空になったレイアウト列・行も畳む |
| `strip_frame.py <frame.frm.json> Module...` | **削除**: PageFrame からモジュール登録・リンクを消す |

## 既知の限界

- `strip_fields.py` / `strip_frame.py` は JSON を**構造として**扱うので安全だが、
  スクリプト側（`.mod.cs`）は手作業になる。実験では正規表現でブロック除去を試みて
  **括弧が合わなくなった**（[02 §構成C(d)](../02_抜き取り実験.md)）。
  ツール化するならスクリプトはブロック構文を理解する必要がある。
- `deps_*.py` は識別子の一致で見るため、モジュール名と同じ単語がコメントや文字列にあると拾う。
  実験では型参照パターンに絞ることで誤検出をほぼ消した。
- `check_db_dangling.py` は SQLite の `sqlite_master` を正規表現で読む。
  CTE 名とサブクエリ別名を除外しているが、複雑な SQL では取りこぼす可能性がある。
