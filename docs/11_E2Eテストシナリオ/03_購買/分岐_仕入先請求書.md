## A. 保存時の必須項目（PUR-01）

### PUR-01: 必須項目バリデーション（保存ブロック）
- **目的**: 請求書番号・仕入先・請求日・費用科目・金額が必須（mod.json の IsRequired）であることの確認。
- **操作手順**: 【購買管理】仕入先請求書 → 新規作成 → **何も入力せず**「登録」。
- **期待される結果**: 入力検証エラーで保存されない（必須項目が赤枠・エラー表示）。項目を 1 つずつ埋めるたびにエラーが減り、5 項目（番号・仕入先・請求日・費用科目・金額）が揃うと保存できる。
- **後片付け**: 保存まで進めた場合は件名（番号）「PUR-01…」の行を一覧から削除。

## B. 未払計上のガード（PUR-02〜03）

### PUR-02: 締め済み期間・年度外の請求日はブロック
- **目的**: 発生主義計上（仕訳日=請求日）の締めガードを、仕訳を作らずに確認する。
- **前提**: 締め済みの月が存在すること（E2E 完走後 DB は全期間締め済みなのでそのまま使える。まっさら DB なら第18期の 4 月が seed で締め済み）。
- **操作手順**:
  1. 新規作成: 請求書番号「PUR-02」・仕入先「株式会社ベガソフト」・請求日「**2026-04-15**」（締め済み月）・費用科目「外注費」・税区分「課税仕入 10%」・金額 11,000 → 登録。
  2. 「未払計上（仕訳生成）」を押す。
  3. 請求日を「**2024-06-15**」（年度が存在しない）に変更して登録 → もう一度「未払計上」。
- **期待される結果**:
  - 手順 2: 赤トースト「**請求日の期間は締め済みです。手動で起票してください**」。仕訳は作られない（status=received のまま）。
  - 手順 3: 「**請求日に対応する会計年度がありません**」。
- **確認ポイント**: どちらも仕訳帳が無変化・状態が「受領」のままであること（コード根拠: Accrue_OnClick の年度→期間→closed 判定。ブロックは仕訳 Submit より前）。
- **後片付け**: PUR-02 の請求書を一覧から削除。

### PUR-03: ボタンの状態出し分けと二重計上ガード
- **目的**: 「未払計上」は received のときだけ、「支払登録」は accrued のときだけ表示されること（UpdateButtons）と、二重生成ガードの存在確認。
- **操作手順**:
  1. 既存の **AL-7005（受領）** を開く → 「未払計上」ボタンが**見え**、「支払登録」が**見えない**ことを確認（押さない！）。
  2. 既存の **VG-2026-071（支払済）** を開く → **両方のボタンが見えない**（paid は操作終了状態）ことを確認。
  3. 【二重計上ガードの参照】基本シナリオ 3-2 の波及（「もう一度押すと『この請求書の未払計上仕訳は既に生成済みです』」）——ボタンは accrued になった時点で消えるため、このガードは**古い画面を開いたまま**の二重クリック等に対する防御線（コード根拠: source_type='vendor_invoice' の既存仕訳検索。（未実測）UI からの通常操作では到達しない）。
- **期待される結果**: 上記のとおり。ロール面は購買フレーム自体が経理・sysadmin 専用のため、承認者・一般社員は**入口ごと存在しない**（00_初期設定 0-12 で確認済み）。
- **後片付け**: なし（閲覧のみ）。

## C. 複製のガード（PUR-04）

### PUR-04: 未保存の新規画面では複製できない
- **目的**: Duplicate_OnClick の IsNewData ガード。
- **操作手順**: 新規作成画面（何も保存していない状態）で「この請求書を複製」を押す。
- **期待される結果**: 赤トースト「**保存済みの請求書のみ複製できます**」。
- **補足**: 複製のコピー項目（取引先・費用科目・税区分・金額・摘要・支払口座）と非コピー項目（番号・請求日・支払期限・状態=受領に戻る）の検証は基本シナリオ 3-6 で実施済み。

## D. 支払予定表の警告境界（PUR-05）

### PUR-05: 期限超過・まもなく期限・期限なしの 3 分岐
- **目的**: PaymentSchedule.Query.sql の警告判定（days_left < 0 → 「⚠ 期限超過」／ ≤ 7 → 「まもなく期限」／ それ以外は空欄）と、期限なし（NULL）の並び順（末尾）を確認する。
- **操作手順**（すべて「受領」のまま保存＝帳簿外）:
  1. 新規作成 × 3 件（仕入先・費用科目・金額 1,100 は共通。請求日=実行日）:
     - 「PUR-05a」支払期限 = **実行日の前日**（期限超過）
     - 「PUR-05b」支払期限 = **実行日 + 7 日**（境界: まもなく期限）
     - 「PUR-05c」支払期限 = **空欄**（期限なし）
  2. 【購買管理】支払予定表 を開く。
- **期待される結果**:
  - PUR-05a に「**⚠ 期限超過**」・days_left がマイナス表示。
  - PUR-05b に「**まもなく期限**」（+8 日にすると空欄になる——境界は「7 日以内」）。
  - PUR-05c は**期限のある行より後ろ**に並ぶ（sort_key の COALESCE('9999-99-99') による末尾送り）。
  - 合計行に 3 件分（+ 既存の AL-7005 33,000）が加算されている。
- **確認ポイント**: 状態列は 3 件とも「受領」（received も予定表に載る——未払計上前でも支払予定として見える設計。基本 3-1 の波及の再確認）。
- **後片付け**: PUR-05a〜c を一覧から削除 → 支払予定表が AL-7005 のみ（合計 33,000）に戻ることを確認。
