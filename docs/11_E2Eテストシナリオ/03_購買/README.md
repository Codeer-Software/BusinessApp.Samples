# 03_購買 — 章ガイドと分岐マップ

> 購買は「受領 → 未払計上 → 支払」の**一方向ステータス遷移**と、全銀フォーマット生成の**入力検証**が分岐の中心。本章は「基本シナリオ」（本流 1 周・仕訳 No.6〜7 を生成）と「分岐シナリオ PUR-xx / FBX-xx」で構成する。

## ファイル構成と実行順序

| ファイル | 内容 | 本流の帳簿への影響 |
|---|---|---|
| [基本シナリオ.md](基本シナリオ.md) | 受領確認 → 未払計上（No.6・発生主義）→ 支払予定表 → FB データ生成 → 支払（No.7）→ 複製 | **あり**（仕訳 No.6〜7） |
| [分岐_仕入先請求書.md](分岐_仕入先請求書.md) | PUR-01〜06: 未払計上のガード（締め済み・年度外・二重）・複製ガード・ボタンの状態出し分け・支払予定表の警告境界 | なし（ブロック確認と received 止まり・末尾で削除） |
| [分岐_振込データ.md](分岐_振込データ.md) | FBX-01〜04: 委託者情報の入力検証・対象なし・受取人口座の除外理由・様式（120桁/パディング）仕様 | なし（FB 生成は画面表示のみ） |

**順序**: 基本シナリオ → 分岐（PUR→FBX）。分岐は独立実行可。

## ステータス遷移とガードの正（コード: VendorInvoice.mod.cs）

```
received（受領） --未払計上--> accrued（未払計上済） --支払登録--> paid（支払済）
```

- ボタンは**経理・sysadmin のみ**表示（購買フレーム自体も経理・sysadmin 専用＝二重のゲート）。received のときだけ「未払計上」、accrued のときだけ「支払登録」が出る（UpdateButtons）。
- 未払計上のガード（発火順）: 金額 ≤0 → 請求日空 → 費用科目空 → **二重生成**（source_type='vendor_invoice' の既存仕訳）→ 年度なし → 期間なし → **締め済み期間**。
- 支払登録のガード: accrued 以外 → 金額不正 → 二重生成（'vendor_payment'）→ **本日**の年度・期間・締め（支払日=操作当日のため）。
- 支払口座未選択時の貸方は**普通預金 1020 にフォールバック**（コード上の既定。分岐 PUR-05 参照・未実測扱い）。

## 後片付けの原則（重要）

分岐で作る請求書は**「受領」状態のまま**にする（未払計上すると仕訳＝帳簿影響が出る）。received のままなら帳簿の外なので、末尾で一覧から**削除**すれば痕跡ゼロ。受領のまま残すと**支払予定表と資金繰り予測の出金予定に乗り続ける**ので、削除漏れに注意（09_帳票検証 の期待値がずれる）。

## 前提（E2E 完走後の DB で実行する場合）

第18期は全期間締め＋年度クローズ済み。**ブロック系分岐（締め済みガード等）はそのままで実行できる**が、受領請求書の新規保存自体は帳簿外なのでいつでも可。基本シナリオを通し直す場合のみ【会計】設定/会計年度 で対象月を「進行中」に戻すこと。
