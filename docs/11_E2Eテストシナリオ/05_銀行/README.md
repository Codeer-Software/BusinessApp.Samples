# 05_銀行 — 章ガイドと分岐マップ

> 銀行取込は「CSV 解析 → プレビュー → 登録（pending）→ 候補付け（ルール/AI/手動）→ 一括起票 → 残高照合」の**多段パイプライン**で、各段に防御がある。本章は「基本シナリオ」（本流 1 周・仕訳 No.25〜27 を生成）と「分岐シナリオ BNK-xx」で構成する。

## ファイル構成と実行順序

| ファイル | 内容 | 本流の帳簿への影響 |
|---|---|---|
| [基本シナリオ.md](基本シナリオ.md) | 取込プレビュー → 取消 → 再取込 → 登録 → 重複スキップ → 対象外 → AI 推定 → 一括起票（No.25〜27）→ 残高照合 全○ → ルール育成 | **あり**（仕訳 No.25〜27） |
| [分岐_取込.md](分岐_取込.md) | BNK-01〜04: 入力ガード・解析不能行の網羅・重複キーの連番一意化・残高列なし CSV | なし（プレビュー/未起票止まり・末尾で削除） |
| [分岐_起票照合.md](分岐_起票照合.md) | BNK-05〜08: ルールの方向と優先度・起票対象の絞り・確認ダイアログのキャンセル・締め済み/年度外スキップ・照合の未起票カウント | なし（起票は全件ブロック経路のみ） |

**順序**: 基本シナリオ → 分岐（取込 → 起票照合）。分岐は独立実行可。

## パイプラインの状態と防御の正（コード: BankImport.mod.cs）

```
CSV 貼り付け --取込--> preview --登録--> pending --一括起票--> journalized
                 |取消=物理削除（重複キー解放）        |対象外に変更--> excluded
```

- **解析不能行**（badLines）: 列 < 2／日付でない（ヘッダ行含む）／出金・入金とも 0 以下／存在しない日付（2/30 等）。
- **重複キー** = `日付|摘要|出金|入金|同一内容連番`。**残高は含まない**。同一貼り付け内の同一内容は連番で一意化（同じ引き落とし 2 件は両方入る）。
- **ルール適用**は取込（プレビュー生成）時に、優先度昇順で**最初に一致した 1 件**。方向（入金のみ/出金のみ/両方）でフィルタ。
- **AI 推定**の対象 = pending かつ候補未設定のみ。**一括起票**の対象 = pending かつ候補設定済みのみ。
- 一括起票のスキップ/失敗の分類: 年度なし・期間なし・締め済み → 「締め済み等スキップ」／口座の帳簿科目なし・相手科目なし・金額 0 → 「失敗」。
- **残高照合**は preview を除外して日次突合。判定は「明細残高 = 帳簿残高」のみで決まり、pending の有無は「未起票（累計）」列の**参考情報**（判定は変えない）。明細に残高列が無い日は「－ 明細残高なし」。

## 後片付けの原則（重要）

分岐で取り込む明細は**起票（journalized）まで進めない**——起票すると仕訳＝帳簿影響が出て後戻りできない（posted 仕訳は削除不可）。プレビューは「プレビューを取り消す」、pending は【会計】銀行/明細一覧 の削除ボタンで**物理削除**して片付ける。削除すると残高照合の該当日付行も消え、全○の状態に戻る。

## 前提（E2E 完走後の DB で実行する場合）

- 既存明細は 7/1×2（対象外）・7/15・7/21・7/24（起票済）の 5 行で、残高照合は**全日付 ○ 一致**。分岐で追加する明細は **7/25 以降または締め済み月**の日付を使い、既存の照合行を乱さない。
- 起票ブロック系（BNK-07）は締め済み期間を利用するため、**全期間締め済みの現 DB はそのまま好都合**。逆に「起票が通る」分岐は本章には置かない（帳簿影響が出るため。起票の本流は基本シナリオで実証済み）。
