## DIF-02: 差額 1,000 円ちょうど（閾値内の上限）→ 自動処理で入金済

- **帳簿影響: あり**（仕訳 +1 本）。**新規 DB 一周時に基本 7-8 の直後で実行**。
- **前提**: 未消込の請求書が 1 枚あること（新規周回時なら、例えば 07 章の保守売上をもう 1 件作るか、INV-26-002 を使う場合は「期末まで未回収で残す」本流の前提が崩れるため**専用の小さな請求書を作る**——受注→検収→請求で税込 110,000 の INV を用意するのが安全）。
- **操作手順**:
  1. 【販売管理】入金 > 新規作成。入金日は開いている期間の日付・請求書に用意した INV（残額 110,000 が自動セット）→ 入金額を「**109,000**」に上書き（差額 1,000 = 閾値ちょうど）。
  2. 「入金を確定（消込）」。
- **期待される結果**（コード根拠: `diff >= 1 && diff <= diffMax`——**以下判定**なので 1,000 は閾値内）:
  - トースト「仕訳 No.n: 入金 109,000 円＋差額 1,000 円を支払手数料で処理し、INV-xx を消し込みました（入金済）」。
  - 仕訳は **4 行**: 借方 普通預金 109,000／借方 支払手数料 **910**／借方 仮払消費税 **90**（1,000×10÷110 切り捨て）／貸方 売掛金 **110,000**（残額全額）。
  - 売掛残高一覧: 残 0・「入金済」（入金累計は 109,000 のまま表示される——差額は手数料処理された、が読み取れる）。
- **読み替え**: 仕訳番号が 1 本増える（Σ借方 +110,000）。以降の期待値に反映すること。

## DIF-03: 差額 1,001 円（閾値超）→ 一部入金で残る → 2 回目の入金で完済

- **帳簿影響: あり**（仕訳 +2 本）。**新規 DB 一周時に実行**。
- **前提**: DIF-02 と同様に専用の請求書（税込 110,000）を用意。
- **操作手順**:
  1. 入金額を「**108,999**」（差額 1,001）にして「入金を確定（消込）」。
  2. 売掛残高一覧を確認。
  3. もう一度 入金 > 新規作成 → 同じ請求書を選択（**残額 1,001 が自動セット**される＝一部入金済みを差し引いた残り）→ そのまま確定。
- **期待される結果**:
  - 手順 1: トースト「仕訳 No.n: 入金 108,999 円を消し込みました（INV-xx は**一部入金**）」。仕訳は **2 行**（借方 普通預金 108,999／貸方 売掛金 **108,999**——閾値超のため貸方は入金額のみ。売掛金に残 1,001 が残る）。
  - 手順 2: 売掛残高一覧に残額 **1,001**・状態「一部入金」。
  - 手順 3: 残額 1,001 の消込仕訳（2 行）が生成され「入金済」に。**一部入金でも候補セレクトに出続ける**（未消込扱い）ことが確認できる。
- **確認ポイント**: 1,000（DIF-02）と 1,001 の 1 円差で「自動処理」と「一部入金」が分かれる——閾値の**以下判定**の境界実証。

## DIF-04: 過入金ガード → 金額修正 → 再確定（保存整合の回帰確認）

- **帳簿影響: なし**（ガードは何も保存しない・最後は確定せず破棄）。**完成状態 DB で実行可**。
- **この分岐の意味**: 2026-07-10 修正の回帰テスト。修正前は「ガードで弾かれた金額が黙って保存され、金額を直して再確定しても修正が保存されない」バグがあった（仕訳 929,500 vs 入金レコード 1,000,000 の不整合を実測）。
- **操作手順**:
  1. 【販売管理】入金 > 新規作成。請求書に未消込の INV-26-002（残額 1,320,000 自動セット）→ 入金額を「**2,000,000**」に上書き → 「入金を確定（消込）」。
  2. 赤トースト「入金額 2,000,000 円が請求残額 1,320,000 円を超えています。過入金分は前受金(2100)として振替伝票で起票してください」を確認。
  3. **URL が `/Receipt/-`（新規）のまま**であること＝**何も保存されていない**ことを確認（修正前はここで保存されて `/Receipt/{id}` に変わっていた）。sql CLI で `SELECT COUNT(*) FROM receipts` が増えていないことを見てもよい。
  4. そのまま戻るボタンで破棄（**確定しない**——INV-26-002 は期末未回収のまま残す本流の前提を守る）。
- **期待される結果**: ガード発火時に入金レコード・仕訳とも作られない。売掛残高一覧の入金累計も無変化。
- **補足（新規 DB 周回時のフル版）**: DIF-02/03 用の専用請求書で「過入金で弾かれる → 金額を残額以内に修正 → 再確定」まで通し、`receipts.amount` が**修正後の金額で保存されている**ことを sql CLI で確認する（消込仕訳の金額と一致すること）。

## DIF-05: 閾値マスタ RECEIPT_DIFF_MAX の改定 → 判定が動く

- **帳簿影響: 実測する場合はあり**。閾値変更自体は**必ず元へ戻す**こと。
- **この分岐の意味**: 差額の許容額はハードコードではなく制度閾値マスタ（入金日で ValidFrom/ValidTo を期間解決）。「振込手数料の実勢が変わったら行を直すだけ」というマスタ駆動の実証。
- **操作手順**:
  1. admin（sysadmin）でログイン → 【マスタ管理（システム）】制度閾値 → `RECEIPT_DIFF_MAX` の金額を 1,000 → **2,000** に変更して保存（経理では**読み取り専用**で変更できないことも確認——ADR-0018）。
  2. （新規 DB 周回時のみ）差額 1,500 の入金を確定 → 自動処理（4 行仕訳・入金済）になることを確認。完成状態 DB では機上確認に留める（未実測）。
  3. **後片付け**: 閾値を **1,000 に戻して**保存。
- **期待される結果**: 同じ差額 1,500 でも、閾値 1,000 のときは「一部入金」、2,000 のときは「自動処理」——コード変更ゼロで挙動が変わる。

## DIF-06: 締め済み期間への入金 → ガードで仕訳は作られない（入金レコードの後片付けつき）

- **帳簿影響: なし**（仕訳は作られない）。ただし**入金レコードが 1 件保存される**ので後片付け必須。**完成状態 DB で実行可**。
- **この分岐の意味**: 締めガードは全起票経路に共通、の入金版。あわせて「ガードの順序」（過入金→保存→二重生成→**締め**）により、締めで弾かれた時点では入金レコードだけが残る仕様を理解する。
- **操作手順**:
  1. 【販売管理】入金 > 新規作成。入金日「2026-07-31」（締め済みの 7 月）・請求書 INV-26-002（残額 1,320,000 自動セット・**金額はそのまま**）→ 「入金を確定（消込）」。
  2. 赤トースト「**入金日の期間は締め済みです。仕訳は手動で起票してください**」を確認。URL は `/Receipt/{id}` に変わっている＝入金レコードは保存済み（仕訳は無い）。
  3. 【販売管理】売掛残高 を開く → INV-26-002 の入金累計に 1,320,000 が乗って**しまっている**（残 0 に見える）ことを確認——「入金レコードは消込の証拠ではない」ことの実感。
  4. **後片付け（必須）**: 【販売管理】入金 の一覧で当該行を削除（消込仕訳が無い入金は削除できる）→ 売掛残高で INV-26-002 が残 1,320,000・未入金に戻ったことを確認。
- **期待される結果**: 仕訳帳は無変化（試算表・Σ に影響なし）。締めガードの文言と、後片付け後の完全復元。
