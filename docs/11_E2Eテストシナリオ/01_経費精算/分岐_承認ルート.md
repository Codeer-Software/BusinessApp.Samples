## A. 金額境界とルート決定（EXP-R01〜R06）

閾値は 30,000（部長決裁の下限）と 200,000（総務併載の下限）。**境界値の両側**（±1 円）でルートが切り替わることを確認する。いずれも kaihatsu1_ippan でログインし、ホームのショートカット「経費申請」→ 新規作成 → 「申請」まで。共通入力: 申請区分=立替精算・利用日=2026-07-06・利用先「テスト商店」。

### EXP-R01: 29,999 円（通常費目）→ 課長のみ
- **入力**: 件名「R01 境界テスト 29999」・金額（税込）**29,999**・費目「消耗品費」
- **期待される結果**: 申請成功。フロー表示 = 「状態:進行中 …→（**▶開発1部 第一課長 山本由美, ▶開発1部 第二課長 中村拓也**）」の **1 段のみ**（課長 2 名並列）。両課長に通知「経費申請「R01 境界テスト 29999」（29,999円）の承認をお願いします」。
- **確認ポイント**: 総務段・部長段が**無い**こと。

### EXP-R02: 30,000 円ちょうど → 部長のみ
- **入力**: 件名「R02 境界テスト 30000」・金額 **30,000**・費目「消耗品費」
- **期待される結果**: フロー = （**▶開発1部 部長 田中宏, ▶開発1部 部長代理 渡辺剛**）の 1 段。**判定は「30,000 以上」なので境界ちょうどは部長**になる（29,999 との対比が本シナリオの狙い）。
- **確認ポイント**: 課長には通知が**行かない**（kaihatsu1_kacho1 の受信箱に出ない）。

### EXP-R03: 199,999 円 → 部長のみ（総務なし）
- **入力**: 件名「R03 境界テスト 199999」・金額 **199,999**・費目「消耗品費」
- **期待される結果**: R02 と同じ部長 1 段。総務段が**無い**。

### EXP-R04: 200,000 円ちょうど → 部長＋総務の 2 段
- **入力**: 件名「R04 境界テスト 200000」・金額 **200,000**・費目「消耗品費」
- **期待される結果**: フロー = （▶部長 田中宏, ▶部長代理 渡辺剛）→（総務部 第一課長 石川真理）の **2 段**。1 段目が承認されるまで総務には通知が行かない（順次到達）。
- **確認ポイント**: 199,999 との対比。閾値は【マスタ管理（システム）】制度閾値 EXP_APPROVAL_HIGH の値で変えられる（変えた場合はこの境界も動く——改正に強いマスタ駆動の実証）。

### EXP-R05: 交際費 29,999 円 → 課長＋総務（金額によらず総務併載）
- **入力**: 件名「R05 交際費境界」・金額 **29,999**・費目「**交際費**」・相手先「テスト商事 佐藤様」・参加人数「2」・目的「打合せ会食」
- **期待される結果**: フロー = （▶課長 2 名）→（総務部 第一課長 石川真理）の 2 段。**3 万円未満でも交際費は総務が入る**（R01 との対比）。

### EXP-R06: 交際費 30,000 円 → 部長＋総務
- **入力**: 件名「R06 交際費境界」・金額 **30,000**・費目「交際費」・3 項目は R05 と同様
- **期待される結果**: フロー = （▶部長 2 名）→（総務部 第一課長 石川真理）。

## B. 並列 OR 承認の完了動作（EXP-R07〜R08）

基本シナリオ E-1 では第一課長が承認した。ここでは**もう一方**が承認して同じ結果になること（OR の対称性）を確認する。

### EXP-R07: 第二課長側の承認でも段が完了する
- **操作手順**:
  1. R01 の申請（課長 2 名に並列中）を使う。**kaihatsu1_kacho2 / kaihatsu1_kacho2** でログイン → サイドバー【経費精算】の「承認待ち」に R01 が見えることを確認 → 開いて「承認」。
  2. kaihatsu1_kacho1 でログインし、承認待ちを確認。
- **期待される結果**: 第二課長の承認で状態=承認済。フロー表示 = 「（✓開発1部 第二課長 中村拓也, **—開発1部 第一課長 山本由美**）」（— = スキップ）。**第一課長の承認待ちから消えている**。申請者に「最終承認されました」の通知。
- **確認ポイント**: 承認履歴に操作者 = 第二課長 中村拓也 が記録される（誰の承認かの監査証跡）。

### EXP-R08: 部長代理の承認（部長権限の OR）
- **操作手順**: R02 の申請を **kaihatsu1_buchodairi** でログインして承認する。
- **期待される結果**: 承認済。部長 田中宏側は「—」スキップ。**部長代理は department_managers に部長（director）として登録されているため、部長と完全に同格**で承認できる（組織再編 ADR-0018 の設計どおり）。

## C. 自己承認の禁止と代替解決（EXP-S01〜S03）

「自分の申請を自分で承認できてはならない」という統制が、役職者本人の申請でどう解決されるかを 3 パターンで確認する。

### EXP-S01: 課長本人の申請 → 本人が承認候補から除外される
- **操作手順**: **kaihatsu1_kacho1** でログインし、経費を申請する（件名「S01 課長本人の申請」・金額 10,000・費目 消耗品費・利用日 2026-07-06）。
- **期待される結果**: フロー = （**▶開発1部 第二課長 中村拓也**）**のみ**——申請者本人（第一課長 山本由美）は課長候補から自動除外され、もう 1 人の課長だけに回る。
- **確認ポイント**: kaihatsu1_kacho1 自身の承認待ちにこの申請が**出ない**（自分では承認できない）。

### EXP-S02: 総務部内の申請 → 経理ロールの課長が普通に承認できる
- **この分岐の意味**: 総務部は全員が経理ロール。承認権限はロールではなく**役職者登録**で決まるため、経理ロールの課長も承認者として機能する——組織再編で確認必須とされたシナリオ。
- **操作手順**:
  1. **soumu_ippan / soumu_ippan**（総務部 一般 藤井愛・経理ロール）でログインし、経費申請（件名「S02 総務部内の申請」・金額 10,000・費目 消耗品費・利用日 2026-07-06）。
  2. フロー表示を確認 → **soumu_kacho1 / soumu_kacho1** でログインし、承認待ちから開いて「承認」。
- **期待される結果**: フロー = （▶総務部 第一課長 石川真理, ▶総務部 第二課長 岡田隆）→ 第一課長の承認で承認済。**経理ロールでも承認フローが正しく動く**。
- **確認ポイント**: soumu_ippan は経理ロールなので【会計】等も見えるが、承認待ちに出るのは「自分が承認者の案件」だけ（この申請は自分のものなので出ない）。

### EXP-S03: 指定ユーザー（総務段）本人の申請 → 経理代替が発動する
- **この分岐の意味**: 交際費の総務段はテンプレートで「総務部 第一課長 石川真理」を指定している。**その本人**が交際費を申請したら？——自己承認回避の最終手段「経理ユーザーによる代替」が発動する。
- **操作手順**: **soumu_kacho1** でログインし、交際費を申請する（件名「S03 総務担当本人の交際費」・金額 10,000・費目 交際費・相手先「テスト商事」・人数 2・目的「打合せ」・利用日 2026-07-06）。
- **期待される結果**: フロー 2 段 = （▶総務部 第二課長 岡田隆）→（**総務部 部長 山田太郎**）。
  - 1 段目（課長）: 本人除外で第二課長のみ（S01 と同じ）。
  - 2 段目（総務）: 指定ユーザー = 申請者本人のため、**経理ロールのユーザー（申請者以外で ID 最小 = 総務部 部長 山田太郎）に自動で差し替わる**。
- **確認ポイント**: 「承認者を決定できません」で止まらず、代替が選ばれて申請が通ること。
