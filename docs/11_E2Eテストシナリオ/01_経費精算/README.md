# 01_経費精算 — 章ガイドと分岐マップ

> 経費精算は本アプリで**条件分岐が最も多い**機能。本章は「基本シナリオ」（本流 1 周・仕訳 No.8〜15 を生成）と「分岐シナリオ EXP-xx」（あらゆる分岐の網羅）で構成する。

## ファイル構成と実行順序

| ファイル | 内容 | 本流の帳簿への影響 |
|---|---|---|
| [基本シナリオ.md](基本シナリオ.md) | E-1〜E-4: 立替→並列課長承認／交際費（却下→再申請）／備品→固定資産／事前申請→実費超過再承認、経理処理（仕訳→支払→完了）、キャンセル・AI・複製・検索 | **あり**（仕訳 No.8〜15） |
| [分岐_承認ルート.md](分岐_承認ルート.md) | EXP-R01〜R08（金額境界×費目のルート決定）・EXP-S01〜S03（自己承認回避・総務部内承認・経理代替） | なし（承認まで・末尾で削除） |
| [分岐_申請区分と費目.md](分岐_申請区分と費目.md) | EXP-P01〜P05（事前申請の実費 3 パターン・取引先へ支払・必須ブロック）・EXP-A01〜A04（資産境界・不課税費目・税額手入力） | なし（同上） |
| [分岐_例外系.md](分岐_例外系.md) | EXP-X01〜X04（ブロック系・差戻し系・編集ロックの網羅チェックリスト） | なし |

**順序**: 基本シナリオ → 分岐（R→S→P→A→X）。分岐は独立しているので個別実行も可。

## 承認ルート決定マトリクス（仕様の正）

判定額 = 立替: 金額（税込）／事前申請: 金額が未確定なら見込み額。どの申請にどのテンプレートを使うかは【システム管理】**承認ルート判定**マスタ（優先度順に評価し、費目と金額〔下限≦判定額≦上限・上限空欄=無制限〕が最初に一致した行を採用。ADR-0023）。下表は既定 seed（5 ルール）の挙動。

| 判定額 ＼ 費目 | 通常費目 | 交際費 |
|---|---|---|
| 〜29,999 | **課長のみ**（R01） | **課長＋総務**（R05） |
| 30,000〜199,999 | **部長のみ**（R02・R03） | **部長＋総務**（R06） |
| 200,000〜 | **部長＋総務**（R04） | 部長＋総務（R06 と同型） |

- 「課長」「部長」は申請者の**部門の役職者全員に並列**で回り、**1 人の承認で段が完了**する（OR 承認。残りは「—」スキップ表示・受信箱から消える）: R07（第二課長側で承認）・R08（部長代理側で承認）で実証。
- 「総務」段はテンプレートの指定ユーザー（総務部 第一課長 石川真理）。
- **自己承認は禁止**: 承認候補から申請者本人が自動除外される（S01）。段の候補全員が本人なら課長→部長へ格上げ、それも尽きると**経理ユーザーが代替**（S03）。総務部内の申請は経理ロールの役職者が普通に承認する（S02——「経理は承認者の上位互換」の実証）。

## 事前申請の実費確定と再承認の条件

再承認が走るのは「**ルート区分をまたいだ**」**または**「**実費 × 100 ＞ 見込み × 110**（＝110% 超）」のとき:

| 見込み → 実費 | 区分 | 110% | 結果 | シナリオ |
|---|---|---|---|---|
| 25,000 → 26,000 | 課長のまま | 以内（≦27,500） | **再承認なし**・そのまま経理処理可 | P01 |
| 25,000 → 27,501 | 課長のまま | **超** | 再承認（課長ルートで再解決） | P02 |
| 29,000 → 31,000 | **課長→部長に跨ぐ** | 以内（≦31,900） | 再承認（部長ルート） | P03 |
| 25,000 → 40,000 | 跨ぐ | 超 | 再承認（部長ルート） | 基本 E-4 |

## 固定資産の自動判定（資産性費目のみ）

| 金額（税込） | 挙動 | シナリオ |
|---|---|---|
| 99,999 | 自動 ON **されない**（手動 ON は可能） | A01 |
| 100,000 | 自動 ON＋トースト（閾値 SMALL_ASSET_EXPENSE・以上判定） | A02 |
| 165,000 | 自動 ON → 承認・仕訳生成で固定資産台帳へ自動登録 | 基本 E-3 |

## 後片付けの原則（重要）

分岐シナリオの申請は**経理処理（仕訳生成）まで進めない**。これにより帳簿（仕訳・帳票・全仕訳台帳の期待値）への影響はゼロ。ただし「承認済み」のまま残すと**資金繰り予測の出金予定に乗る**ため、各分岐の末尾で片付ける。削除は**申請者本人**が詳細画面の赤ボタン「**この下書きを削除**」で行う（下書き状態のみ・本人のみ。承認済みの申請は本人が「キャンセル」で下書きへ戻してから削除する。実行し忘れると 09_帳票検証 の資金繰り予測の期待値に差が出る）。
