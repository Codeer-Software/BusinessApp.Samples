# 検証のルール

> 作ったものを**どう確かめるか**。**2026-09-06 に [CLAUDE.md](../CLAUDE.md) から切り出した。**
> 検証の**設計**（テスト方針・カバレッジ・ミューテーション）は [ADR-0012](decisions/0012-テスト方針とカバレッジのゲート.md)、
> 実機の**台本**は [qa/04](qa/04_実機操作テスト.md)、**漏れの型**は [qa/03](qa/03_テストで漏らした実例.md) が持つ。
> [CLAUDE.md §0-4](../CLAUDE.md) で、検証・テストの前に読む。

## 1. 検証ループ

| 対象 | 手段 |
|---|---|
| デザイン読込妥当性 | `designcheck` CLI。`findingCount` が 0 になるまで直す |
| C# ロジック | `dotnet test`。テスト・カバレッジ 100%・配置規約を一度に検査（ADR-0012） |
| DB（DDL・投入・確認） | `sql` CLI（自前で DB 接続しない） |
| **稼働 DB を壊す前** | `db_snapshot.ps1 -Save` で退避を取る。戻すのはサーバを止めてから。**打ち方は [30 §10](30_作業のルール.md)**（経緯は [ADR-0046](decisions/0046-稼働DBの退避と復元を戻せる道具に閉じる.md)） |
| 稼働アプリへの反映 | `pwsh -NoProfile -File tools/clb/deploy.ps1` → FileWatcher が hot-reload |
| 画面・挙動 | サーバ起動（`http://localhost:5085`）→ ブラウザで操作・スクショ（§2） |
| ドキュメント規約 | `python tools/docs/lint_docs.py`（節参照の実在まで見る） |
| テストの穴 | `dotnet stryker`（コミット前フックが毎回実行。ADR-0012 §8） |
| **関門・静的検査そのもの** | 各スクリプトの `--selftest` / `-SelfTest`。**緑にして終わりにしない**——**関門を複製して 1 か所ずつ壊し、そのすべてで赤くなることまで確かめる**（緑は「いま鳴らない」しか言っていない） |
| **公開前チェック** | `python tools/docs/lint_secrets.py`（**コミット前に必ず流す**） |
| 上記の自動実行 | `git config core.hooksPath tools/git-hooks`（clone 後に 1 回。ADR-0012）。段の正典は [tools/README](../tools/README.md) |

`designcheck` の緑は「読み込める」までの保証でしかない。計算・状態遷移・見た目は実機で確認する。
**`*.mod.cs` の変更と DB スキーマの変更は deploy だけでは反映されない。サーバ再起動が必要。**

## 2. 最終確認はブラウザで行う（開発者に確認を取らない）

**CLB 実装 → deploy → サーバ再起動 → ブラウザで操作、までを自律的に回す。** 開発者の許可を都度求めない。

**開発サーバの開始・終了・再起動に、開発者の確認を取らない**（開発者の指示。2026-09-08）。逐語:

> 5085 ポートのサーバーは Claude の開発のためのものですから、開発者の確認を取らずに
> 自由に開始・終了・再起動してかまいません。

**稼働 DB を戻すときは停止が要る**ので、この授権が無いと復元が回らない（[30 §10](30_作業のルール.md)）。

前回プロジェクトの実測で、**コード上は正しく見えてもブラウザで操作すると動かない**ことが繰り返し起きた
（[qa/01](qa/01_CLB静かな失敗.md)）。`designcheck` と `dotnet test` の緑は「読み込める」
「C# のロジックが正しい」までしか言っていない。**実機で操作していない機能は、できていないものとして扱う。**

ブラウザ操作の勘所（打鍵が届かない・トーストの捉え方・日付入力）は [qa/01 の G 節](qa/01_CLB静かな失敗.md) と
[qa/04 §2](qa/04_実機操作テスト.md)。

## 3. 開発用アカウントでのログインは、自律作業の範疇である

**開発者は、`Designer/LocalEnvironment.md`（Git 追跡外）の「開発用アカウント」節に開発者自身が書いたアカウントについて、
`http://localhost:5085` に限り、Claude が自由にログイン・ログアウトすることを許可した**
（開発者の指示。2026-09-05。**入力しなければ §2 が回らないから**）。**開発者に都度確認しない。**

- **許可の対象は、その節に書かれている行そのもの**である。行を足すのは開発者の行為であり、足した行にも許可が及ぶ
- **外部サービス・本物の資格情報は対象外**。localhost の外へは、許可があっても入力しない
- 節が無い・アカウントが無いときは、開発者に管理画面で作ってもらう——手順は [`Designer/seed/README.md`](../Designer/seed/README.md)、
  なぜ追跡外か・なぜ SQL で作れないかは [ADR-0039](decisions/0039-開発用アカウントの資格情報はGit追跡外に置く.md)
- 識別名は秘密ではないので書いておく——`admin`（CLB の既定。情報システム管理者。**会計は触れない**）・
  `soumu_bucho`（経理責任者 `manager`）・`soumu_ippan`（経理担当 `staff`）。下 2 つは取引先も編集できる

## 4. 検証そのものを育てる（結果を鵜呑みにしない）

**検証を流したら、結果を使うだけで終わらせない。毎回、検証自体を振り返る**（開発者の指示。2026-08-28。
**検証も成長させるものであり、盲目的に従うと関門が形骸化するから**）。

1. **今回の結果は有用で適切だったか**（本当の問題を指したか、意図どおりの記述を毎回叩いているだけか）
2. **かかった時間に見合っているか**
3. **見合わないならどう良くできるか**（対象を絞る・警告に落とす・置き換える・やめる）

判断が要ったものは [qa/02_自己レビュー記録](qa/02_自己レビュー記録.md) に残す。

**関門は足したときが完成ではない。** 実例: superseded リンクの検査は鳴った 6 件すべてが
「経緯として正しい」もので、しかも**既定の直し方が `decisions/` では誤り**だった（2026-08-28。ラウンド 19）。

**qa/03 に 1 件増えたら、それを機械で守れないか毎回考える**（`self-review` スキル §8）。
守れたら qa/03 の「機械で守れるようにしたもの」の表に移す。**カタログが短くなっていくのが健全な状態**である。

## 5. 規則を決めたら、網羅的にテストを書く

**入力の規則（書式・長さ・使ってよい字）を自分たちで決めたら、決めた範囲を網羅するテストを書く**
（**開発者の指示**。2026-09-05。**必須**）。
**同値分割と境界値で**、少なくとも次の軸を当てる。

- **字種**（英数・記号・かな・漢字）／**長さ**（下限・上限・その前後）
- **見えない文字**（前後の空白・全角空白・制御文字・ゼロ幅）
- **全角と半角**／**大文字と小文字**／**先頭の文字**

**実例は `MasterCodeGuardTests`**——マスタのコードの字種を**符号位置で総当たり**する
（[ADR-0047](decisions/0047-マスタのコードは空白を落とす以外書き換えず字種で断る.md)。現在形の規則は [12 §2-1](12_マスタ台帳.md)）。
**「決めた規則」と「テストの軸」が 1 対 1 で並ぶ形にする**——並ばないものは、決めたつもりで決まっていない。

## 6. テストの強さを測る計器は、区切りごとに自分で流す

**緑は「テストが通った」までしか言っていない。** 「**壊したら気づくか**」は別の問いで、
それを測るのが計器である（[qa/05](qa/05_観点網羅の計器.md)）。

- **コミット前フックに載っているもの**（カバレッジ・ミューテーションテストと、
  **普通のテストとして流れる計器**——不変条件の ID トレーサビリティ
  （[ADR-0054](decisions/0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md)）と
  行動テストの書き忘れ検知
  （[ADR-0055](decisions/0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)）。どちらも走査は 1 秒未満。
  **SQL ミューテーションは掃引そのものは載っていないが、変異点の数え方を守る
  `sql_mutate.py --selftest` と、行セットの差分で殺す計器の配線を守る `SqlMutationProbeTests` は
  毎回流れる**）は、毎回勝手に流れる。**何も考えなくてよい**
- **載っていないものは、流す回を自分で決める。** いまあるのは 2 つ。
  **制約ノックアウト**（`tools/clb/knockout.ps1`。**制約・トリガを足した回とフェーズの区切り**に流す。
  [ADR-0053](decisions/0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md) の決定 6・7）と、
  **SQL ミューテーション**（`tools/clb/sql_sweep.ps1`。**クエリの SQL か行動テストを触った回**に流す。
  [ADR-0056](decisions/0056-SQLミューテーションはクエリのSQLを1箇所ずつ壊し行動テストだけで赤になるかを見る.md) の決定 6・7 と
  [ADR-0058](decisions/0058-行セットの差分で殺す掃引は入力コーパスを持たず行動テストが流した入力をその場で当てる.md)）。
  **まず `-Mode Rows`**（行セットの差分で殺す。秒で終わる）、
  **`-Mode Tests`（分かかる）は 2 つの生き残りの差を知りたい回に**——
  **差は「行は変わるのに、どのアサーションもその列を見ていない」**という意味で、
  **Rows の生き残りは検体かパラメータを足して潰し、差のほうは表明を足して潰す**。
  **どちらも Claude の判断で、開発者は未承認である**（**掃引をフックに載せるかは
  [05 の Q-27](05_開発者への問い.md)**）
- **「拒まれること」のテストを書いたら、その制約を外して赤くなるかを確かめる**——
  `knockout.ps1 -Only <点>`。**`Assert.Throws` は「何で落ちたか」を見ない**ので、
  **別の関門が先に鳴っているだけの空振りは、書いた本人にも見えない**（[qa/03 の L-45](qa/03_テストで漏らした実例.md)）
- **クエリの SQL を書いたら、1 箇所ずつ壊して赤くなるかを確かめる**——
  `sql_sweep.ps1 -Mode Tests -Only <モジュール名>`。**件数だけを見るテストは、条件を反転しても
  件数が偶然一致して緑になる**——**この形は `-Mode Rows` では見つからない**（行セットは変わるので
  「見分けた」に倒れる）。**弱い表明を見つけるのは A 案だけである**（[qa/03 の L-46](qa/03_テストで漏らした実例.md)）
