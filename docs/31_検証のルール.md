# 検証のルール

> 作ったものを**どう確かめるか**。**2026-09-06 に [CLAUDE.md](../CLAUDE.md) から切り出した。**
> 検証の**設計**（テスト方針・カバレッジ・ミューテーション）は [ADR-0012](decisions/0012-テスト方針とカバレッジのゲート.md)、
> 実機の**台本**は [qa/04](qa/04_実機操作テスト.md)、**漏れの型**は [qa/03](qa/03_テストで漏らした実例.md) が持つ。
> [CLAUDE.md §0-4](../CLAUDE.md) で、検証・テストの前に読む。

## 1. 検証ループ

| 対象 | 手段 |
|---|---|
| デザイン読込妥当性 | `designcheck` CLI。`findingCount` が 0 になるまで直す |
| C# ロジック | `dotnet test`。テスト・カバレッジ 100%・配置規約を一度に検査（ADR-0012） |
| DB（DDL・投入・確認） | `sql` CLI（自前で DB 接続しない） |
| **稼働 DB を壊す前** | `db_snapshot.ps1 -Save` で退避を取る。戻すのはサーバを止めてから。**打ち方は [33 §1](33_失わないためのルール.md)**（経緯は [ADR-0046](decisions/0046-稼働DBの退避と復元を戻せる道具に閉じる.md)） |
| 稼働アプリへの反映 | `pwsh -NoProfile -File tools/clb/deploy.ps1` → FileWatcher が hot-reload |
| 画面・挙動 | サーバ起動（`http://localhost:5085`）→ ブラウザで操作・スクショ（§2） |
| ドキュメント規約 | `python tools/docs/lint_docs.py`（節参照の実在まで見る） |
| **作業コピーの改行** | `python tools/claude/normalize_eol.py --check`。**リポジトリ内のファイルは全て LF に統一する**（開発者の要望。2026-09-15。**混ざると、作業コピーを読む道具が環境ごとに違う結果を出すから**）。**リポジトリに入る中身は `.gitattributes` が正規化する**ので常に LF で、**ずれるのは作業コピーだけ**である。`--fix` で直る |
| テストの穴 | `dotnet stryker`（コミット前フックが毎回実行。ADR-0012 §8） |
| **関門・静的検査そのもの** | 各スクリプトの `--selftest` / `-SelfTest`。**緑にして終わりにしない**——**関門を複製して 1 か所ずつ壊し、そのすべてで赤くなることまで確かめる**（緑は「いま鳴らない」しか言っていない） |
| **公開前チェック** | `python tools/docs/lint_secrets.py`（**コミット前に必ず流す**） |
| 上記の自動実行 | `git config core.hooksPath tools/git-hooks`（clone 後に 1 回。ADR-0012）。段の正典は [tools/README](../tools/README.md) |

`designcheck` の緑は「読み込める」までの保証でしかない。計算・状態遷移・見た目は実機で確認する。
**`*.mod.cs` の変更と DB スキーマの変更は deploy だけでは反映されない。サーバ再起動が必要。**

**壊して試すときの第一選択は、上の表のとおり「複製を壊す」である**（原本を触らない）。
**原本を触らざるを得ないときは、先に控えを取り、控えから戻す。**
**守りが拒むのは `git checkout -- ` の形だけで、`--` を書かない `git checkout <パス>` は通る**
（[33 §1](33_失わないためのルール.md)。語彙の正典は `tools/claude/guard_delete.py`）。
**通るということは、そのファイルに乗っているコミット前の作業ごと捨てられるということ**である。
控えはリポジトリの外に置く（[30 §8](30_作業のルール.md)）。python で書き換えたなら、
同じ python で逆向きの置換を書いて戻すほうが確実である。

## 2. 最終確認はブラウザで行う（開発者に確認を取らない）

**回し方の手順と、サブエージェントへの依頼文は [`live-test` スキル](../.claude/skills/live-test/SKILL.md) が持つ。**

**CLB 実装 → deploy → サーバ再起動 → ブラウザで操作、までを自律的に回す。** 開発者の許可を都度求めない。

**開発サーバの開始・終了・再起動に、開発者の確認を取らない**（開発者の指示。2026-09-08）。逐語:

> 5085 ポートのサーバーは Claude の開発のためのものですから、開発者の確認を取らずに
> 自由に開始・終了・再起動してかまいません。

**稼働 DB を戻すときは停止が要る**ので、この授権が無いと復元が回らない（[33 §1](33_失わないためのルール.md)）。

前回プロジェクトの実測で、**コード上は正しく見えてもブラウザで操作すると動かない**ことが繰り返し起きた
（[qa/01](qa/01_CLB静かな失敗.md)）。`designcheck` と `dotnet test` の緑は「読み込める」
「C# のロジックが正しい」までしか言っていない。**実機で操作していない機能は、できていないものとして扱う。**

ブラウザ操作の勘所（打鍵が届かない・トーストの捉え方・日付入力）は [qa/01 の G 節](qa/01_CLB静かな失敗.md) と
[qa/04 §2](qa/04_実機操作テスト.md)。

## 3. 開発用アカウントの登録とログインは、自律作業の範疇である

**開発者は、`Designer/LocalEnvironment.md`（Git 追跡外）の「開発用アカウント」節に開発者自身が書いたアカウントについて、
`http://localhost:5085` に限り、Claude が自由にアカウントを登録し、ログイン・ログアウトすることを許可した**
（開発者の決定。2026-09-19。**あらかじめ定義しておくのが開発者の仕事で、それを実際にアプリへ登録するのは Claude でよい**——
**ログインする権限だけあってもアカウントが無ければ意味がなく、DB を作り直すたびに開発者を呼ぶことになるから**。
ログインの許可そのものは 2026-09-05。**入力しなければ §2 が回らないから**）。**開発者に都度確認しない。**

- **許可の対象は、その節に書かれている行そのもの**である。行を足すのは開発者の行為であり、足した行にも許可が及ぶ。
  **`admin` は表の行ではないが対象に含む**（開発者の承認。2026-09-20）——
  理由は [ADR-0039 §4](decisions/0039-開発用アカウントの資格情報はGit追跡外に置く.md)（本 ADR の対象外・秘密でもない）。
  **`admin` / `admin` は、利用者の表が空のときサーバ起動時に 1 件だけ作られる**
  （仕様は `Designer/ClaudeCodeForDesigner/_specs/Authentication.md`。**実装は本リポジトリの
  `BusinessApp/BusinessApp.Server/CookieAuthentication.cs` の `CreateInitialUserAsync`** で、
  **テンプレート由来だが本プロジェクトが編集できる**。2026-09-20 に両方を読んで確かめた）
- **外部サービス・本物の資格情報は対象外**。localhost の外へは、許可があっても入力しない
- **行はあるがアプリにそのアカウントが無いとき**（新しい DB・[33 §2](33_失わないためのルール.md) の「正典からの作り直し」の後など）は、
  **Claude が `admin` で管理画面に入って登録する**——手順は [`Designer/seed/README.md`](../Designer/seed/README.md)。
  **SQL では作れない**——**ハッシュとソルトの算法が CLB の仕様書に書かれておらず、SQL で再現する手段が無い**
  （作るのは `PasswordHashHelper`。なぜ追跡外かは [ADR-0039](decisions/0039-開発用アカウントの資格情報はGit追跡外に置く.md)）
- **表に行が 1 つも無いときだけ、開発者に頼む**——
  **資格情報を決めて追跡外のファイルに書くのが開発者の担当だから**である（[34 §1](34_開発者とClaudeの分担.md) の 1 と 2。
  **ファイルを新しく作る操作が塞がっているのは別の理由**で、そちらは [34 §2-2](34_開発者とClaudeの分担.md)）
- 識別名は秘密ではないので書いておく——`admin`（CLB の既定。情報システム管理者。**会計は触れない**）・
  `soumu_bucho`（経理責任者 `manager`）・`soumu_ippan`（経理担当 `staff`）。下 2 つは取引先も編集できる

## 4. 検証そのものを育てる（結果を鵜呑みにしない）

**検証を流したら、結果を使うだけで終わらせない。毎回、検証自体を振り返る**（開発者の指示。2026-08-28。
**検証も成長させるものであり、盲目的に従うと関門が形骸化するから**）。

1. **今回の結果は有用で適切だったか**（本当の問題を指したか、意図どおりの記述を毎回叩いているだけか）
2. **かかった時間に見合っているか**
3. **見合わないならどう良くできるか**（対象を絞る・警告に落とす・置き換える・やめる）

判断が要ったものは [qa/02_自己レビュー記録](qa/02_自己レビュー記録.md) に残す。

**関門は足したときが完成ではない。** 実例: superseded リンクの検査は鳴った 6 件すべてが
「経緯として正しい」もので、しかも**既定の直し方が `decisions/` では誤り**だった（2026-08-28。ラウンド 19）。

**qa/03 に 1 件増えたら、それを機械で守れないか毎回考える**（`self-review` スキル §8）。
守れたら qa/03 の「機械で守れるようにしたもの」の表に移す。**カタログが短くなっていくのが健全な状態**である。

## 5. 規則を決めたら、網羅的にテストを書く

**入力の規則（書式・長さ・使ってよい字）を自分たちで決めたら、決めた範囲を網羅するテストを書く**
（**開発者の指示**。2026-09-05。**必須**）。
**同値分割と境界値で**、少なくとも次の軸を当てる。
**この軸は §7 の「先に設計する」の材料でもある**（書く前に、どの軸を当てるかを決める）。

- **字種**（英数・記号・かな・漢字）／**長さ**（下限・上限・その前後）
- **見えない文字**（前後の空白・全角空白・制御文字・ゼロ幅）
- **全角と半角**／**大文字と小文字**／**先頭の文字**

**実例は `MasterCodeGuardTests`**——マスタのコードの字種を**符号位置で総当たり**する
（[ADR-0047](decisions/0047-マスタのコードは空白を落とす以外書き換えず字種で断る.md)。現在形の規則は [12 §2-1](12_マスタ台帳.md)）。
**「決めた規則」と「テストの軸」が 1 対 1 で並ぶ形にする**——並ばないものは、決めたつもりで決まっていない。

## 6. テストの強さを測る計器は、区切りごとに自分で流す

**緑は「テストが通った」までしか言っていない。** 「**壊したら気づくか**」は別の問いで、
それを測るのが計器である（[qa/05](qa/05_観点網羅の計器.md)）。

- **コミット前フックに載っているもの**（カバレッジ・ミューテーションテストと、
  **普通のテストとして流れる計器**——不変条件の ID トレーサビリティ
  （[ADR-0054](decisions/0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md)）と
  行動テストの書き忘れ検知
  （[ADR-0055](decisions/0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)）。どちらも走査は 1 秒未満。
  **SQL ミューテーションは `-Mode Rows` の掃引そのものが載っている**——
  変異点の数え方を守る `sql_mutate.py --selftest` と、計器の配線を守る `SqlMutationProbeTests` も毎回流れる）は、毎回勝手に流れる。**何も考えなくてよい**
- **載っていないものは、流す回を自分で決める**——ただし**判定は機械に当てられる**。
  `python tools/clb/which_gates.py` が、差分から「この回に流すもの」を印字する
  （**流すのは人である**。掃引は分かかるので道具からは起こさない）。
  **下の判定がその正典**で、道具はそれを差分に当てているだけである。いまあるのは 2 つ。
  **制約ノックアウト**（`tools/clb/knockout.ps1`。**制約・トリガを足した回とフェーズの区切り**に流す。
  [ADR-0053](decisions/0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md) の決定 6・7）と、
  **SQL ミューテーションの `-Mode Tests`**（`tools/clb/sql_sweep.ps1`。**クエリの SQL か行動テストを触った回**に流す。
  **`-Mode Rows` はフックに載ったので、ここには入らない**。
  [ADR-0056](decisions/0056-SQLミューテーションはクエリのSQLを1箇所ずつ壊し行動テストだけで赤になるかを見る.md) の決定 6・7 と
  [ADR-0058](decisions/0058-行セットの差分で殺す掃引は入力コーパスを持たず行動テストが流した入力をその場で当てる.md)）。
  **`-Mode Rows`（行セットの差分で殺す。秒で終わる）はフックに載ったので、手で流す必要はもう無い**
  （開発者の決定。2026-09-20。[ADR-0058](decisions/0058-行セットの差分で殺す掃引は入力コーパスを持たず行動テストが流した入力をその場で当てる.md) の決定 9）。
  **手で流すのは `-Mode Tests`（分かかる）だけで、2 つの生き残りの差を知りたい回に流す**——
  **差は「行は変わるのに、どのアサーションもその列を見ていない」**という意味で、
  **Rows の生き残りは検体かパラメータを足して潰し、差のほうは表明を足して潰す**。
  **この「どちらを流すか」の使い分けは Claude の判断である**（開発者が決めたのは、`-Mode Rows` をフックに載せることまで）
- **分単位で終わらないものは、バックグラウンドで回して待ち時間を別の作業に充てる**
  （所要の実測は各 ADR が持つ。**この場で数字を書かない**——[qa/02 の R91-12](qa/02_自己レビュー記録/2026-09.md) で
  3 通りに割れたのを、実測 1 か所に畳んだばかりである）。
  **ただし待っている間に `dotnet build` も `--no-build` 無しの `dotnet test` も走らせない**——
  **掃引が使っているテスト DLL を差し替えてしまう**（Claude の判断）。
  文書の編集・`lint_docs.py`・git の読み取りは安全なので、待ち時間はそちらに充てる
- **「拒まれること」のテストを書いたら、その制約を外して赤くなるかを確かめる**——
  `knockout.ps1 -Only <点>`。**`Assert.Throws` は「何で落ちたか」を見ない**ので、
  **別の関門が先に鳴っているだけの空振りは、書いた本人にも見えない**（[qa/03 の L-45](qa/03_テストで漏らした実例.md)）
- **クエリの SQL を書いたら、1 箇所ずつ壊して赤くなるかを確かめる**——
  `sql_sweep.ps1 -Mode Tests -Only <モジュール名>`。**件数だけを見るテストは、条件を反転しても
  件数が偶然一致して緑になる**——**この形は `-Mode Rows` では見つからない**（行セットは変わるので
  「見分けた」に倒れる）。**弱い表明を見つけるのは A 案だけである**（[qa/03 の L-46](qa/03_テストで漏らした実例.md)）

## 7. 先に設計してから、テストを書く

**開発者の指示**（2026-09-15。マージの条件を決めた回に、あわせて指示された）。

- **原則として、まずテスト設計を行ってから実装・実施する**
- **探索的テストをする価値があるかを毎回検討し、価値があると判断したら行う**

**以下は Claude の敷衍**（[00 §4-11](00_ドキュメント規約/本文.md)）。

**「設計してから」が効くのは、テストを書きながら設計すると
「書けたもの」が「見るべきもの」にすり替わるから**である。
**検体の作り方で漏れた実例は [qa/03](qa/03_テストで漏らした実例.md) にある**——
L-02（区別すべき 2 つが同じ値だった）・L-36（総当たりから端を 1 つ外したら、その端の穴も隠れた）。
**ただし qa/03 の漏れの多くは「壊して鳴らす確認を省いた」型で、設計では防げない**
（L-33・L-35 がそれ。処方は §1 と §6）。**設計と、壊して鳴らす確認は、別々に要る。**

**設計は、その回の成果物の中に残す。** 新しい置き場は作らない（[30 §9](30_作業のルール.md)）。

| 何を設計したか | どこに残すか |
|---|---|
| 単体・DB のテスト | **コミット本文に「何を見るか」を数行**（git log が持つ） |
| 実機で確かめること | [qa/04 §4](qa/04_実機操作テスト.md) が指す年月のファイルの節の冒頭に、流す前に書く |
| どの層で受け持つかの割り振り | 該当する ADR（実例は [qa/04 §3-5](qa/04_実機操作テスト.md) の「単体・DB・実機の分担」） |

**スクラッチパッドに書いて終わりにしない**——セッションごとに消えるので、
**設計したことが残らず、条件 2・5 の側から検算もできない**（[30 §7-1](30_作業のルール.md)）。

**設計の材料はもう散らばっている。** §5 の軸（字種・長さ・
見えない文字・全角と半角・大文字と小文字・先頭の文字）、
[qa/03](qa/03_テストで漏らした実例.md) の漏れの型、[qa/01](qa/01_CLB静かな失敗.md) の静かな失敗、
[`self-review` スキル](../.claude/skills/self-review/SKILL.md) §4 のテスト観点のブロック。
**これらを「テスト設計のときに開く 1 か所」へまとめるかは、[README の保留リスト](README.md)に置いた**
（開発者の提案。2026-09-15。「今すぐでなくていい」）。
**設計を書いた実例は既にある**——[qa/04 §3-5](qa/04_実機操作テスト.md) の
「単体・DB・実機の分担」（2026-09-02）が、不変条件をどの層で確かめるかを先に割り振っている。

**探索的テストは、台本をなぞらずに触るものである。** 価値があるのは
**台本が「作った人の想定」でできている**からで、想定の外は台本では踏めない。
[qa/04](qa/04_実機操作テスト/2026-09.md) の 2026-09-04〜05 の 10 巡がその実例で、
そこで見つけたものは [qa/03 の L-27〜L-32](qa/03_テストで漏らした実例.md)・
[CLB改善提案](CLB改善提案/README.md) の FB-013〜FB-016・[04 §1](04_実装計画と現在地.md) の残りの表に散っている。
**価値があると判断する目安**（Claude の判断）——
新しい画面や経路を作った回・権限や状態遷移に触れた回・フェーズの区切り。
**逆に、直した 1 点を確かめるだけの回には要らない。**

**検討したことを残す。** 実機を流す回は、[qa/04 §4](qa/04_実機操作テスト.md) が指す年月のファイルの節に 1 行書く
（`探索的テスト: 不要。直した 1 点のみ`）。**書かないと「毎回検討している」を誰も確かめられない**
——やった回だけ記録が残り、**要らないと判断した回は跡形も無くなる**。
