# 開発者と Claude の分担

> **何を開発者が担い、それ以外を Claude が確認なしに行うか**の境界を持つ文書。
> **境界の中身は開発者の素案である**（2026-09-17。逐語は「今思い浮かんだものを列挙しただけで、素案です」「これも素案です」——末尾の句点は落とした。以下の逐語も同じで、入れ子の「」は『』に替えた）。
> **素案のまま規則の形に起こすのは Claude の判断**——同じ日の指示「上に挙げたような、開発者とClaudeの担当領域などはドキュメント化する価値がある気がします」
> 「ルール等の整備をお願いします」に従った。**確定させる・改めるのは開発者**——**確定するかは [05 の Q-37](05_開発者への問い.md) で諮っている**。追認があれば日付と理由に替える（[00 §4-11](00_ドキュメント規約/本文.md)）。
> 迷ったときの決め方は [30 §1](30_作業のルール.md)、消す・戻す・上書きの判断は [33](33_失わないためのルール.md)、
> 開発者に決めてもらうことの書き方は [30 §11](30_作業のルール.md)。**ここは境界だけ。**

## 0. なぜ境界を書くか

**開発者の言葉**（2026-09-17。逐語）——

> こういう作業を毎回開発者に頼んでいると自走がすぐに止まってしまうと思います。なんとかならないものでしょうか。

> Claudeが自律的に開発を行っている最中、当該開発用DBに関していちいち開発者に声をかけ、承認を得たり開発者に作業をしてもらう必要があるというのは非合理的です。

> 逆にいえば、上記に該当しないあらゆることは、Claudeが自律的に・開発者の確認なしに行ってよいと考えています。

（「上記」は §1 の 7 つを指す。）

**境界が字になっていないと、Claude は「不可逆に見える操作」の手前で止まる**——
2026-09-16 に稼働 DB の `schema_migrations` の記録を直す手前で止まり、開発者の答えを 1 日待った
（[qa/04](qa/04_実機操作テスト.md) の 2026-09-17）。**何に止められたかの記録は無い**——当日のコミット ffcd5a03 の本文は「止められた」と受動態で書いただけで、
当たる `ask` が `.claude/settings.json` に無いので、**明文の無いところでの Claude の判断だったと読む**（推定）。
**止まるたびに自走が切れる。** だから境界を 1 か所に書き、**それ以外は行う**（Claude の敷衍。§2）。

## 1. 開発者が担うこと

**開発者の素案の逐語を、そのまま表にした**（2026-09-17。末尾の句点だけ落とした）。
**右の列は Claude の敷衍**——いまのプロジェクトで何に当たるか。**当たるかどうかで迷ったら、左の列で決める。**

| # | 開発者が担うこと（逐語） | いまのプロジェクトでは（Claude の敷衍） |
|---|---|---|
| 1 | **機密情報の管理と利用**（アプリ内に暫定作成する開発用アカウントのID・パスワードは機密情報に含まれない。） | .NET User Secrets・接続文字列・API キー・本物の資格情報（[CLAUDE.md §5](../CLAUDE.md)）。**開発用アカウントは含まれない**——ログインは [31 §3](31_検証のルール.md) のとおり Claude が行う（**アカウントを管理画面で作るのは開発者**——同節。追跡外の `LocalEnvironment.md` に書く行だから、2 にも当たる） |
| 2 | **ローカル環境やプロジェクトリポジトリ外に関する整備** | デザイナ exe・`.claude/settings.local.json`・`Designer/LocalEnvironment.md`・新環境のセットアップ（[README](../README.md)）・依存の導入（Playwright 等——`Designer/CLAUDE.md`）・**`.claude/settings.json` の `allow` を広げること**（**ここに置くのは Claude の判断で、開発者に未確認**——足した道具は守りの語彙の外から来るので 6 の高リスクに近い。[33 §1](33_失わないためのルール.md)。[05 の Q-37](05_開発者への問い.md)）。**保護対象を新しく作ること**も、いまは開発者に頼む——**担当としてではなく、機械が経路を塞いでいるから**（[33 §1](33_失わないためのルール.md)） |
| 3 | **プロジェクトのゴールやスコープ、要件、仕様等に関する最終判断**（最終判断に至るまでの調査・素案作成・提案等はClaudeが積極的に行う。） | [01](01_企画概要.md)・[02](02_ペルソナ.md)・[03](03_機能スコープ.md) と、ADR の「開発者の決定」。**Claude は ADR・[05](05_開発者への問い.md) に案を作り、判断を仰ぐ**。**[30 §1](30_作業のルール.md) の「仕様の意思決定まで自分で行う」との線は開発者に未確認**（[05 の Q-37](05_開発者への問い.md)）——Claude の読みでは「最終判断」は 01〜03 と ADR の決定で、後戻りの小さい実装上の選択は 30 §1 の範囲 |
| 4 | **法令及び税制に関する最終判断**（最終判断に至るまでの調査・素案作成・提案等はClaudeが積極的に行う。） | 条文の当てはめ・制度の解釈（[CLAUDE.md §2](../CLAUDE.md)・[32](32_調査のルール.md)）。Claude は `docs/research/` に一次情報を集め、読みを「Claude の読み」と印して諮る |
| 5 | **リモートリポジトリへのプッシュその他のプロジェクトの外部公開に関する作業** | `git push`（[30 §7](30_作業のルール.md)。機械でも禁止）・公開設定・外部サービスへの送信 |
| 6 | **重要な情報が不可逆的に失われる、失敗する可能性があり万が一失敗したときの被害が甚大であるなど、影響重大 and (不可逆的 or 高リスク) な作業** | **退避で戻せないものを消す・素で上書きする**こと（`.git/`・追跡外の環境設定・`LocalData/storages`。[`tools/claude/protected_paths.json`](../tools/claude/protected_paths.json) の一部）、コミットしていない作業を捨てる git（[33 §1](33_失わないためのルール.md)）、**reflog そのものを消す git**（`reflog expire`／`delete`／`drop`・`gc --prune`。同。**戻す手段が消えるので不可逆である**。2026-09-18）。**開発用 DB とその退避は当たらない**（開発者の言葉: 「開発用DBの初期化や変更その他の作業は上記に該当しません」。運用は [33 §2](33_失わないためのルール.md)）——**それでも Claude が退避を消せないのは、担当としてではなく機械が塞ぐから**（2 と同じ形。[33 §2](33_失わないためのルール.md) の 6） |
| 7 | **Claude in Chrome では再現しないブラウザ上の細かな挙動の確認など、Claudeが実施できない作業** | [30 §3](30_作業のルール.md) の「3 回で引く」で残したもの・[qa/01 の G 節](qa/01_CLB静かな失敗.md) の型。**Claude が「できない」と決めつけない**——試して残った分だけを頼む |

**6 の判定は「影響重大」かつ「不可逆か高リスク」の両方**である（開発者の字のとおり）。
**以下は Claude の敷衍。** 退避・ごみ箱・git で戻せる操作は「不可逆」には当たらない——
**残るのは「高リスク」（失敗しうる・失敗時の被害が甚大）かどうか**で、それも低ければ行う。
開発者が述べたのは開発用 DB についてで（「『現在のDBのレコードが消えると困る』という状況があるのであれば、バックアップを取るべきです」）、
**他の操作へ広げたのは Claude である**。

## 2. それ以外は、Claude が確認なしに行う

**§1 に当たらないあらゆることは、Claude が自律的に・開発者の確認なしに行ってよい**（開発者の見解。2026-09-17。逐語は §0）。
**「行ってよい」を「行う」と読み替えて自走の既定にするのは Claude の敷衍**——許されているのに聞くと、自走が切れる（§0）。

**2026-09-17 に加わったもの**——**開発用 DB の管理**（初期化・マイグレーションの適用・記録の訂正・正典からの作り直し。**退避を消すことは除く**——[33 §2](33_失わないためのルール.md) の 6）。
**開発者の決定**（逐語は「本プロジェクトの方針として、DBの管理は全面的にClaudeに任せたいと考えています。あくまで開発用のDBなのですから。」
「そしてその内容はそこまで重要ではありません。万が一作業に失敗しても影響は小さいです。」）。**運用の作法は [33 §2](33_失わないためのルール.md)**。

**それより前から個別に許されているもの**（どれもこの原則の実例として読む——Claude の整理）。

- **ごみ箱送りと、稼働 DB の退避と復元**（[33 §1](33_失わないためのルール.md)）
- **開発用アカウントでのログイン**（[31 §3](31_検証のルール.md)）
- **デプロイ・サーバ再起動・ブラウザ操作**（[31 §2](31_検証のルール.md)・`Designer/CLAUDE.md`）
- **関門（`tools/claude/`・`.claude/settings.json`）の書き換え**（[33 §1](33_失わないためのルール.md)。直したら `--selftest` を通す。
  **ただし `allow` を広げるのは §1 の 2**）
- **`main` へのマージ**（[30 §7](30_作業のルール.md)。6 条件がそろっていれば）

**新しく書くのは境界の側だけである。** §1 に当たるもの、当たるかどうかの線が細いもの、そして当たらないと分かった操作の**作法**（[33 §2](33_失わないためのルール.md) のように「どう行うか」）は書く。
**個別の規則にまだ「開発者に確認する」と書いてあって §1 に当たらないものを見つけたら、その規則を直す**（Claude の敷衍。[30 §9](30_作業のルール.md) の「効く場所に置く」）。

## 3. 開発者が Claude に期待すること

**開発者の素案の逐語**（2026-09-17。「開発者よりもClaudeが優れていると考えていること」「これも素案です」）。

1. **会計・簿記・経理に係る実務に関する豊富な知識と、それに基づく設計等の判断。**
2. **ソフトウェア開発に係る無数の知見と、それに基づく設計・実装・検証等の遂行能力及びそれらのプロセスの改善策。**
3. **Claude（あるいはAI一般）に係る知識と、それに基づく最適なルール・ドキュメント等の整備。**
4. **高速に・24時間働き続けることのできるそのスピードと作業量。**
5. **以上に掲げた知識及びそれら以外のあらゆる知識に基づく開発者への積極的な提案。**

**Claude がこれをどう受けるか**（Claude の敷衍）。

- **1・2 は「判断してよい」の裏づけである**——[30 §1](30_作業のルール.md) の「ベストプラクティスが 1 つに定まるなら聞かない」は、
  この期待に立っている。**ただし §1 の 3・4（最終判断）は開発者のもの**で、Claude は案と根拠を作る
- **3 は、規則を Claude が起こして諮ってよいということである**——起こした規則には「Claude の判断」と印し、開発者が承認したら日付と理由に替える
  （[00 §4-11](00_ドキュメント規約/本文.md)）
- **5 は、気づいたら言う**——問いは [05](05_開発者への問い.md)、判断の経緯は ADR、作業の改善は [30 §9](30_作業のルール.md)。
  **「聞かれていないから言わない」を採らない**
