# 機能スコープ

> **含める／含めないの正典。** 判断の理由は [ADR-0007](decisions/0007-会計コアの機能スコープ.md)、
> 実装の順序は [04_実装計画と現在地](04_実装計画と現在地.md) にある（ここには書かない）。
> **個別の機能の可否は、この表に 1 行足して記録する。ADR は起こさない**——
> 個別機能ごとに ADR を増やすと [decisions/](decisions/README.md) の索引そのものが読めなくなる。
> **判断の基準そのものを変えるときだけ**新しい ADR を起こす（2026-08-25 決定）。
> 基準は「[対象ペルソナ](02_ペルソナ.md)が使うか」。判断に迷うものは
> **市販ソフトがどうしているか**も材料にする（[32_調査の原則 §2](32_調査の原則.md)。調査は [research/](research/) に残す）。

凡例: ○ = 本プロジェクトで作る（原則は会計コアに含める。例外は備考に明示） ／
△ = 連携点だけ持つ ／ × = 含めない（別部品または対象外）

## A. マスタ・設定

まず「**会計をやめても存在し続けるか**」で所有を分ける（[ADR-0029](decisions/0029-所有は相手抜きで存在するかで導き粒度は決断で決める.md)）。
**各マスタの扱い（誰が編集する・版・削除）の現在形は [12_マスタ台帳](12_マスタ台帳.md) が持つ**——
この表が持つのは「含める／含めない」と所有だけである。

| | 機能 | 所有 | 備考 |
|---|---|---|---|
| ○ | 事業所情報（法人名・住所・登録番号・決算期） | 会計 | 詳細 1 枚（[ADR-0005](decisions/0005-単一法人に徹する.md)）。→ [12](12_マスタ台帳.md) |
| ○ | 会計年度・会計期間（月次）と締め状態 | 会計 | → [12](12_マスタ台帳.md) |
| ○ | 消費税設定（課税方式・経理方式・控除方式） | 会計 | → [11](11_消費税設計.md)・[12](12_マスタ台帳.md) |
| ○ | 期首残高（開始残高） | —（マスタではなくデータ） | 貸借一致の検証対象（[10 §8](10_会計ドメイン設計.md)） |
| ○ | 勘定科目（科目区分・決算書表示区分・既定税区分） | 会計 | |
| ○ | 補助科目 | 会計 | 科目配下の内訳 |
| ○ | 取引先（種別・法人番号・所在地・登録番号の有効期間） | **取引先部品** | 会計マスタではない。**独立のアプリ部品として作る**（[ADR-0025](decisions/0025-取引先を部品として分ける.md)）。設計は [13_取引先設計](13_取引先設計.md) |
| ○ | 部門 | 会計 | 単一階層（[ADR-0010](decisions/0010-部門は単一階層とし損益科目でのみ必須にする.md)） |
| ○ | 税区分（課税/非課税/不課税/免税・税率・用途区分） | 会計 | 割当はマスタ、税率は制度ルール（[12](12_マスタ台帳.md)） |
| ○ | 消費税率・経過措置の控除割合・相手方別上限額 | 会計（法令の写し） | → [12](12_マスタ台帳.md) |
| ○ | 法定耐用年数・償却率 | 会計（法令の写し） | → [12](12_マスタ台帳.md) |
| △ | 利用者アカウント・権限・ロール | 認証部品 | **アカウントの管理は認証部品の責務**（既存の `AppUser` を使う）。ただし**画面を役割で分けるための旗**は `app_users` に足す——CLB のフレームの可視条件は `CurrentUser` の列しか参照できないため。**実装形は [ADR-0034](decisions/0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md)**（開発者の要求。2026-08-28） |
| × | **所得税の源泉徴収の事務**（税額計算・支払調書・法定調書） | — | 給与・報酬支払の部品。会計コアが持つのは**預り金の仕訳**まで。**この線引きが「個人番号を持たない」の前提**（[13 §1-3](13_取引先設計.md)） |
| × | 取引先の氏名による重複候補の表示（新規登録時・名寄せの補助） | — | いまは作らない（保留リスト）。**機械が自動で束ねてはならない**（表記ゆれ。[13 §2-4](13_取引先設計.md)） |
| × | セグメント・タグ（部門以外の集計軸） | — | 管理会計部品 |

## B. 記帳（仕訳の生成と保全）

| | 機能 | 備考 |
|---|---|---|
| ○ | 仕訳入力（複合仕訳・諸口） | 振替伝票形式 |
| ○ | 出納帳形式の入力 | 現金・預金の連続入力 |
| ○ | 下書き（draft）と計上（posted）の分離 | 下書きは自由に編集・削除できる |
| ○ | 仕訳番号の自動採番（不可逆） | 訂正削除履歴と相互関連性の前提 |
| ○ | **訂正・取消（反対仕訳方式）** | 計上済みは変更・削除しない（[ADR-0004](decisions/0004-優良な電子帳簿への準拠と仕訳の不変性.md)） |
| ○ | 入力年月日の自動付与（訂正・削除不可） | 優良な電子帳簿の要件 |
| ○ | 通常の業務処理期間の経過後の入力の記録 | 同上 |
| ○ | 仕訳の検証（貸借一致・期間・科目・税区分・部門） | `AccountingCore` で実装しサーバで強制 |
| ○ | 月次締め・年度締め・期間ロック | 締め前チェックを含む |
| ○ | 締めの再オープン（理由の記録つき） | |
| ○ | CSV による仕訳の取込 | 冪等性・Dry-run・行単位エラー |
| △ | 他部品からの仕訳投入 | 元伝票を特定する情報を保持する |
| △ | 証憑との紐付け | 参照キーのみ。実体は証憑部品 |
| × | 仕訳辞書・定型仕訳・自動仕訳ルール | 入力支援。会計の責務ではない |
| × | 銀行・カード明細の取込、OCR、AI 仕訳提案 | 入力支援部品 |
| × | 承認ワークフロー | 承認フロー部品 |

## D. 消費税

| | 機能 | 備考 |
|---|---|---|
| ○ | 税抜経理（仮払・仮受消費税等の自動計上） | ペルソナは税抜経理 |
| ○ | 税率別集計（複数税率・経過措置税率） | |
| ○ | 売上税額の計算（割戻し・積上げ） | 組み合わせ制約を強制する |
| ○ | 仕入税額の計算（積上げ・割戻し） | 同上 |
| ○ | 税率ごとに 1 回の端数処理 | 行ごとに切り捨てない |
| ○ | 課税売上割合の計算 | 切り捨て表示 |
| ○ | 全額控除・個別対応方式・一括比例配分方式 | 課税期間ごとに選べる |
| ○ | 用途区分（課税売上対応／共通対応／非課税売上対応） | 個別対応方式に必須 |
| ○ | 免税事業者等からの仕入れの経過措置 | 日付で控除割合を自動切替 |
| ○ | 相手方別の課税仕入れ累計と上限判定 | **上限は課税期間の開始日で版が変わる**（[消費税リサーチ §1-3](research/2026-08-23_消費税インボイス制度.md)。2026-09-30 までに開始＝施行済みの版、2026-10-01 以後に開始＝次の版）。金額を本書に直書きしない |
| ○ | 帳簿のみ保存で控除できる類型の区分と追加記載事項 | ペルソナが使う 5 類型のみ（下記） |
| × | **少額特例**（税込 1 万円未満） | **ペルソナは適用対象外**（適用要件は[消費税リサーチ §2](research/2026-08-23_消費税インボイス制度.md)） |
| ○ | 税額の手動上書き（履歴を残す） | 積上げ計算のズレを吸収する |
| ○ | 税区分別集計表（申告の根拠） | 取引まで追跡できる |
| × | 簡易課税 | ペルソナは本則課税 |
| × | 2 割特例・3 割特例 | 同上 |
| × | 税込経理 | ペルソナは税抜経理 |
| × | 消費税申告書・付表の様式出力、中間申告 | 申告は税理士が行う |

**帳簿のみ保存で控除できる類型**（[消費税リサーチ §6](research/2026-08-23_消費税インボイス制度.md)）は、ペルソナが実際に行う次の 5 つだけを持つ。
①3 万円未満の公共交通機関 ②入場券等の回収特例 ③3 万円未満の自動販売機・自動サービス機
④郵便ポストに差し出された郵便・貨物サービス ⑤従業員等への出張旅費・宿泊費・日当・通勤手当。
古物商・質屋・宅地建物取引業・特定金属くず・再生資源の各特例は業種特有のため持たない
（区分をマスタとして持つので、必要になれば行を足せる）。
