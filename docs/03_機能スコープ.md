## 5. 横断要件

- **正確性**: 貸借一致はアプリ層で強制（不一致伝票は確定不可）。締め済み期間の仕訳は変更不可。金額は整数円。
- **監査性**: 仕訳に起票者・作成/更新日時（CLB システムフィールド）。確定済み仕訳の修正は赤黒訂正を推奨する UI。
- **証憑**: 仕訳・経費申請へのファイル添付（日付・金額・取引先で検索可能 = 電帳法の実務土台）。
- **国際化**: 単一通貨（JPY）・日本語のみ。
- **性能**: 年間仕訳4,000件×2期分のデモデータで一覧・集計が体感即応であること。

## 6. 実装順序の原則

1. A を完成させてから B へ（会計コアが正しくないと連動機能は全部砂上の楼閣）。
2. B-1（マスタ）だけは A-4（仕訳の部門・プロジェクト付与）の前提なので A の途中で先行実装する。
3. B' は B-4/B-5（請求）との連動が深いため B の後。C は独立性が高く最後（C-2 は B-4 のデータが前提）。

## 7. 見送り（今回作らない）と理由

| 項目 | 理由 |
|---|---|
| 連結会計 | ペルソナは単体決算。中小デモに不要 |
| 多通貨 | 国内取引のみ。設計を歪ませるコストが大きい |
| 電子申告（e-Tax/eLTAX 直結）・法人税申告書作成 | 税理士連携領域。集計資料の出力まで |
| 消費税申告書の様式そのもの | 区分別集計表まで（数字は合う。様式転記は税理士/別ツール） |
| 電子帳簿保存法の完全準拠（JIIMA 認証相当） | タイムスタンプ・事務処理規程等は運用領域。検索性と添付は実装 |
| 給与計算・年末調整・勤怠管理 | 別ドメイン。給与仕訳の受け皿は D-4（定型仕訳）＋ D-5（仕訳 CSV インポート）で用意。**給与専用の取込機能は不採用**（給与ソフトは例外なく会計用仕訳 CSV を出力できるため汎用インポートで吸収。ADR-0011） |
| 収益認識基準（29号)のフル実装 | 中小は適用任意（リサーチ確認済み）。検収基準+繰延で実務充足 |
| 銀行 API 連携（明細の自動取得） | 認証・契約が必要な外部依存でデモ環境では実現不能。**CSV 取込は D-2 に昇格**（ADR-0011） |
| ~~振込データ作成（全銀 FB データ）~~ | **実装済み（2026-07-07）**: D-6 完了により源泉データが揃ったため実装。120桁固定長の様式自己検証つき（実銀行への取込は未検証＝当初整理どおり様式検証まで） |
