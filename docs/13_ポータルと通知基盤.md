# ポータルと通知基盤 仕様書

> 作成: 2026-08-05（ADR-0045）。**「権限→ポータル表示項目」のマッピングと部品の契約、通知基盤の契約の正典。**
> 権限フラグの定義は ADR-0043、組織・承認は ADR-0044 を参照。

## 1. 画面構成の全体像

- **着地**: 全員が業務ポータル（Main/PortalHome）に着地（ADR-0042 維持）
- **業務への導線**: Main の左サイドバー（`Shell/PortalSidebar` モジュール）に一本化。
  PortalHome 中央のタイルボタンは廃止
- **ポータル中央**: ログインユーザーの権限で合成された「やること・アラート・KPI」（§3）
- **各業務フレーム**: 「トップ」廃止。着地＝そのフレームで一番使う業務画面（§5）。
  サイドバー先頭の「ホーム」（→ポータル）は全フレーム存続

## 2. サイドバー（PortalSidebar）仕様

| リンク | 表示条件 | 遷移先（変種解決） |
|---|---|---|
| 経費精算 | `CanUseExpense` | ExpenseAccounting（経理）> ExpenseApprover（承認者）> ExpenseStaff |
| 工数管理 | `CanUseTimesheet` | TimesheetAccounting（経理）> Timesheet |
| 営業業務 | `HasSalesAccess` ∨ `HasAccountingAccess` | SalesBilling（経理）> SalesStaff |
| 会計業務 | `HasAccountingAccess` | Accounting |
| 購買・支払 | `HasAccountingAccess` | Purchasing |
| 経営管理 | `IsApprover` ∨ `HasAccountingAccess` | ManagementFull（経理）> ManagementApprover |
| 業務マスタ | `HasAccountingAccess` | MasterBusiness |
| システム管理 | `IsSysAdmin` | MasterAdmin |
| ログアウト | 全員 | ログアウト処理 |

- 変種解決ロジックは PortalSidebar のスクリプトに集約し、PortalHome・通知リンクからも同じ解決を使う
- 遷移は URL のみ（部品のモジュール型を参照しない）。遷移先 URL は §5 の着地画面

## 3. ポータル表示項目（権限→表示のマッピング）

表示は 4 分類・この順（上ほど個人的・緊急）。各項目は**件数＋クリックで該当一覧へ**が基本、
リスト表示は通知のみ。0 件の項目は行ごと非表示（アラート・キューは「対応が要るときだけ見える」）。

| # | 分類 | 表示条件 | 項目 | データ源（契約） | リンク先 |
|---|---|---|---|---|---|
| 1 | 自分あて | 全ログインユーザー | 未読の通知（リスト表示・既読化つき） | `notifications`（自分宛・未読） | 通知の論理リンクを閲覧時解決（§4） |
| 2 | 自分あて | `CanUseExpense` | 進行中の自分の申請 N 件 | `approval_inbox` 系（MyApplication と同条件） | 経費フレーム変種 / 自分の申請 |
| 3 | 自分あて | `IsApprover` ∨ `HasAccountingAccess` | あなたの承認待ち N 件 | `approval_inbox_view`（current_approver=自分） | 経費フレーム変種 / 承認待ち |
| 4 | 作業キュー | `HasAccountingAccess` | 精算処理待ち N 件 | `expense_request`（approved/accounting/settled） | ExpenseAccounting / 精算処理待ち |
| 5 | 作業キュー | `HasAccountingAccess` | 未起票の銀行明細 N 件／下書き伝票 N 件 | `bank_statement_lines`（pending）／`journal_entries`（draft） | Accounting / 銀行明細・仕訳 |
| 6 | 作業キュー | `HasAccountingAccess` | 定期請求・SES の当月未生成 N 件 | 確定済み有効契約のうち当月請求書が無いもの（BuildPlan の冪等判定と同条件） | SalesBilling / 定期請求・SES |
| 7 | アラート | `HasAccountingAccess` | 支払期限: 超過 N 件／N 日以内 N 件 | `vendor_invoices`（received/accrued × due_date、閾値 `PAY_DUE_SOON_DAYS`） | Purchasing / 支払予定表 |
| 8 | アラート | `HasSalesAccess` ∨ `HasAccountingAccess` | 期限超過の売掛 N 件 | ReceivableBalance と同条件（期限超過・未回収） | 営業フレーム変種 / 売掛残高 |
| 9 | アラート | `IsApprover` ∨ `HasAccountingAccess` | ⚠資金ショート予測（あれば） | CashFlowForecast の alert_mark と同条件 | 経営管理変種 / 資金繰り予測 |
| 10 | アラート | `IsApprover` ∨ `HasAccountingAccess` | ⚠予算警告 N 部門（あれば） | BudgetVsActual の alert_mark と同条件（`BUDGET_ALERT_RATE`） | 経営管理変種 / 予実対比 |
| 11 | KPI | `HasAccountingAccess` | 現預金・売掛・買掛／当月売上・費用・利益 | 旧 AccountingKpiData の SQL（ポータル所有へ移設） | FinancialReports 各帳票 |

- **見送り**: 工数未入力リマインド（アサイン概念が無く「入力すべき」を定義できない。ADR-0045）
- admin（sysadmin）は業務フラグを持たないため #1 のみ＋ユーザー管理への案内が出る（職務分掌の帰結）

### 実装形（部品独立性の維持）

- ポータルは**部品のモジュール型を参照しない**。上表のデータ源は Shell 所有の QueryField モジュール
  （`PortalTodoData`・`PortalAlertData`・`PortalKpiData`）の SQL として実装する
- SQL が参照してよいのは**各部品のテーブル・ビュー（DB 語彙）まで**。この SQL 群が「部品→ポータルの契約」
  であり、部品側の状態設計（ステータス値・警告条件）を変えるときは本表と SQL を同時に更新する
- 部品をテンプレートから外すときは、対応する SQL の SELECT 部を削る（docs/10 §4 の手順に追記）

## 4. 通知基盤（Notification）契約

- **所属**: `Modules/Shell/Notification`（基盤・レイヤ0）。全部品から 部品→基盤 の下方向参照で送信可
- **スキーマ**（現行を踏襲）: RecipientUser／Title／Body／LinkModule／LinkId／IsRead／CreatedAt
- **送信 API**: `Notification.mod.cs` の公開メソッドに一元化

```
Send(recipientUserId, title, body, linkModule, linkId)
```

- 他人宛 INSERT の Submit 戻り値問題（自分宛のみの DataReadCondition により true にならない・2026-07-08 実測）は
  Send 内で吸収し、呼び出し側は戻り値を気にしない契約とする
- Slack/メール連携の mock（Logger）も Send 内。実連携はここ 1 箇所に差し込む
- **リンクは論理**（LinkModule＋LinkId）。閲覧時にポータルが受信者のその時点の権限でフレームを解決して遷移:

| LinkModule | 解決先 |
|---|---|
| ExpenseRequest | 経費フレーム変種 / ExpenseRequest/{id} |
| （将来）Invoice 等 | 対応部品のフレーム変種 / 一覧 or 詳細 |

- 読取条件: 自分宛のみ（現行維持）。既読化はポータルの通知リストで行う
- 保持期間・自動掃除はスコープ外（将来 `system_thresholds` で導入余地）

## 5. フレーム着地（トップ廃止後）

| フレーム | 着地画面 | 備考 |
|---|---|---|
| ExpenseStaff | 経費申請（一覧） | ExpenseHome 廃止 |
| ExpenseApprover | 承認待ち（ApprovalInbox） | 同上 |
| ExpenseAccounting | 精算処理待ち（ExpenseSettlementQueue） | 同上 |
| Timesheet | 工数入力（TimeEntry） | 従来どおり |
| TimesheetAccounting | 工数管理（TimeEntryAdmin） | 従来どおり |
| SalesStaff | 営業サイドバー先頭の業務一覧 | SalesHome 廃止 |
| SalesBilling | 請求書（Invoice） | 同上 |
| Accounting | 仕訳（JournalEntry） | AccountingHome 廃止（件数・KPI はポータルへ） |
| Purchasing | 仕入先請求書（VendorInvoice） | 従来どおり |
| ManagementApprover/Full | 予実対比（BudgetVsActual） | 従来どおり |
| MasterBusiness | 取引先（Partner） | 従来どおり |
| MasterAdmin | ユーザー管理（AppUser） | AdminHome 廃止 |

- 旧 `/{Frame}/Top` 遷移規約は「フレーム名のみ（`/{Frame}` → TopPageModule）」へ簡素化
- 廃止モジュール: ExpenseHome／SalesHome／AccountingHome／AdminHome（担っていた情報の移設先は §3）

## 6. 閾値マスタ

| キー | 意味 | 初期値 |
|---|---|---|
| `PAY_DUE_SOON_DAYS` | 支払期限「まもなく」の日数（支払予定表・ポータル #7 で共用） | 7 |

支払予定表（PaymentSchedule.Query.sql）のハードコード `days_left <= 7` は本キー参照に置換する。
