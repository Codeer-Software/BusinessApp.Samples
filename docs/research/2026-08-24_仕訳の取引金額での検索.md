# 仕訳の「取引金額」での検索

## 調査の目的

優良な電子帳簿の検索要件（規則 5 ⑤一ハ）は、仕訳帳について**取引年月日と取引金額**を
検索条件にできることを求める（通達 8-14）。ところが仕訳は「伝票 1 件に明細が複数」の構造で、
**金額は明細にあって伝票に無い**。「取引金額で検索」が何を指すのかを決められず、実装を止めていた。

## 結論（先に）

**伝票に合計金額の列を持つ必要はない。明細の金額で引く。**

1. **通達も一問一答も、取引金額が明細か合計かを一切定義していない**
2. 調べた 5 製品すべてで、仕訳の永続化単位は**明細行**であり、**伝票ヘッダに合計金額を持たない**
3. **合計を持たない設計のまま JIIMA の優良電子帳簿認証を通っている**製品が複数ある
   （弥生会計・PCA 会計・マネーフォワード・勘定奉行クラウド）。
   「取引金額＝伝票合計」でなければならないという解釈は成り立たない

## 1. 制度が求めていること

### 通達 8-14（記録項目）

> ⑴ **仕訳帳　取引年月日及び取引金額**
> ⑵ **総勘定元帳　記載年月日及び取引金額**
> ⑶ 売上帳及び仕入帳などの補助記入帳　取引年月日、取引金額及び取引先名称
> ⑷ 売掛金元帳、買掛金元帳などの補助元帳　記録又は取引の年月日、取引金額及び取引先名称
> **(注)** 一連番号等により…帳簿間の関連性の確保…の要件を確保することとしている場合には、
> 当該一連番号等により…検索することができるときについても要件を充足するものとして取り扱う。

**粒度の指定が無い。** これが調査の最大の発見である。

### 見落としやすい 3 点

- **通達 8-13**: 「探し出された記録事項**のみ**が出力される」＋
  「**検索項目について記録事項がない電磁的記録を検索できる機能を含む**」→ **空値検索が要る**
- **通達 8-15**: 範囲指定は「**課税期間ごとに**、日付又は金額の任意の範囲を指定して」
- **一問一答 問 32**: 「A 又は B」は不要。**段階的な絞り込み**（A で検索 → 結果を B で再検索）も可

### 税抜・税込（一問一答【電子取引関係】問 57）

> **【回答】** 帳簿の処理方法（税抜経理／税込経理）に合わせるべきと考えられますが、
> 授受した電子取引データに記載されている取引金額を検索要件の記録項目とすることとしても差し支えありません。
> **【解説】** …**基本的には帳簿と同じ金額で検索できるようにしておくべき**と考えられます。

**どちらでもよい。** ただし趣旨は「帳簿と同じ金額で引けること」。
問 58 は、金額が定まらない場合に空欄・0 円でよいが**空欄を対象に検索できる必要がある**とする。

## 2. 市販ソフトの実装

**画面の説明は粒度を書かないので、データ交換仕様（CSV / API）から判断した。**

| ソフト | 仕訳の永続化単位 | ヘッダの合計金額 |
|---|---|---|
| freee `ManualJournal`（振替伝票） | `details[]` のみ | **無い** |
| freee `Deal`（取引） | `details[]` | `amount` はあるが**作成 API に金額欄が無い＝導出値** |
| マネーフォワード（仕訳帳 CSV） | 行＋取引 No でグルーピング | **無い** |
| 弥生会計（仕訳日記帳） | 明細行（複合仕訳は諸口で展開） | **無い** |
| PCA 会計（汎用データ） | **1 レコード＝1 明細行**（伝票日付・伝票番号を各行が反復） | **無い** |
| 勘定奉行クラウド（仕訳伝票連携） | ヘッダ ＋ 明細（本体金額／消費税額） | **無い** |

### 検索機能

- **freee**: 「取引年月日」「取引金額」「取引先」を条件にでき、金額は
  「◯円以上◯円以下」の範囲指定が可能。**値が入っていないことの検索**にも対応。
  抽出結果は**明細のみ**を表示。帳簿入力は**仕訳明細単位**と明記
- **マネーフォワード**: 「範囲指定」にチェックで金額の上限・下限、外すと特定の金額
- **弥生会計**: **本体金額と消費税額を別々の検索軸**として持ち、それぞれに「金額指定／範囲指定」がある。
  金額欄で右クリック →「選択した金額で仕訳を絞り込む」という導線もある
- **PCA**: 取引年月日・勘定科目・補助科目・**取引金額**・摘要を組み合わせて検索できる

### 税抜・税込

どのソフトも「**入力された金額**」と「**消費税額**」を別項目で持ち、
入力金額が税込か税抜かは**税計算モード（内税／外税／別記）で決まる**。

| ソフト | 金額欄の中身 | 消費税額 |
|---|---|---|
| freee | **税込で統一**（`details.amount` は「税込で指定してください」） | `vat` 別項目（未指定なら自動計算） |
| マネーフォワード | 経理方式次第 | 借方税額／貸方税額 別列 |
| 弥生 | 内税入力＝税込／外税入力＝税抜 | 別項目。**検索軸としても独立** |
| PCA | 「内税自動計算」＝税込、それ以外＝税抜 | 別項目 |
| 勘定奉行 | **本体金額（税抜）** | 別項目 |

## 3. 本プロジェクトの決定

### 3-1. 伝票に合計金額の列を足さない

明細（`journal_lines.amount`）で引く。市販ソフトのデータ交換仕様が一致してそう言っており、
合計を持たない設計で JIIMA の優良電子帳簿認証が通っている。

**副産物として、消費税（フェーズ 3）で「取引金額は税込か税抜か」を先に決める必要も消えた。**
明細の金額をそのまま検索対象にすればよく、税額は別項目で引ける。

### 3-2. 弥生に倣い、本体金額と消費税額を別の検索軸にする

フェーズ 3 で消費税行を入れたときの方針として決めておく。
「どちらか一方に正規化する」より、問 57 の「帳簿と同じ金額で検索できるように」という趣旨に素直である。
対象ペルソナ（税理士が触る）にとっても実務価値が高い。

### 3-3. 忘れずに作るもの

- **空値検索**（通達 8-13）。取引先や摘要が「未設定」であることを条件にできる必要がある
- **課税期間ごとの範囲指定**（通達 8-15）。会計年度で絞ってから日付・金額の範囲を指定できること
- 伝票番号での検索は、通達 8-14 の (注) により**要件充足の別ルートになりうる**（実装済み）

## 4. 確認できなかったこと

- 勘定奉行の仕訳伝票検索で金額の範囲指定ができるか（データ構造は取れたが検索画面の一次資料に未到達）
- TKC の検索画面仕様（マニュアルが会員限定）
- MF の金額検索が借方・貸方のどちらを対象にするか
