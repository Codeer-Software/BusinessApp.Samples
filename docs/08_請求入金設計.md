# 請求・入金（B-4）設計

> 作成: 2026-07-05 / スコープ: docs/03（見積→受注→検収→請求書発行→入金消込→売掛管理）
> ペルソナ（IT 受託 55名）: 受託 60%（検収基準）/ SES 25%（月次稼働）/ SaaS 15%（定期請求 B-5）。
> 会計連携は経費精算（B-2）で確立した source_type ＋二重生成ガード方式を踏襲する。
> 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映。画面配置・権限表現の現行形は §6）

## 1. 業務フローとステータス

```
見積(quote) --受注--> 受注(sales_order) --検収--> 検収(acceptance) --請求--> 請求書(invoice) --入金--> 入金(receipt)
  draft/sent            open/closed          ← 売上仕訳(検収基準)      issued/partial/paid   ← 消込仕訳
  /accepted/rejected
```

- **売上計上は検収基準**（役務完了時）。検収の確定で `D 売掛金 / C 売上高＋仮受消費税` を自動仕訳（source_type='acceptance'）。
  - 根拠: ペルソナの主業（受託）は検収基準が原則（収益認識基準の一時点充足）。SES は月次検収として同じ流れに載せる。SaaS（毎月請求・繰延なし簡易）も月次の検収扱いで統一し、繰延収益の厳密化は B'-4 で行う。→ ADR-0008
- **請求書は帳票**（会計イベントではない）。検収済みの案件から請求書を発行し、入金期日・振込先を記載。
- **入金消込**で `D 普通預金 / C 売掛金`（source_type='receipt'）。一部入金は partial、全額で paid。
- 見積・受注は会計イベントなし（管理情報）。

## 2. データモデル（ddl/110_billing.sql）

- `quotes`: id/quote_no/partner_id/project_id/title/issue_date/valid_until/status(draft,sent,accepted,rejected)/note
- `quote_lines`: id/quote_id/line_no/description/qty/unit_price/amount/tax_category_id
- `sales_orders`: id/order_no/quote_id/partner_id/project_id/title/order_date/status(open,closed)/note
  - 受注時に見積明細をコピー（`sales_order_lines`: 同型）。見積なし受注（SES 更新等）も直接作成可
- `acceptances`: id/acceptance_no/sales_order_id/acceptance_date/amount(税抜合計)/tax_amount/status(draft,confirmed)/journal 連携は journal_entries.source_type='acceptance', source_id=id
- `invoices`: id/invoice_no/partner_id/project_id/acceptance_id(NULL可=手動/定期)/title/issue_date/due_date/amount/tax_amount/status(issued,partial,paid,void)/source(manual,acceptance,recurring)
- `invoice_lines`: id/invoice_id/line_no/description/qty/unit_price/amount/tax_category_id
- `receipts`: id/receipt_date/invoice_id/amount/method(bank,cash,offset)/note → source_type='receipt'
- 番号採番: `Q-{yy}-{seq}` / `SO-{yy}-{seq}` / `A-{yy}-{seq}` / `INV-{yy}-{seq}`（スクリプト採番、経費の伝票 No と同じ方式）
- 科目: 売掛金=1100 / 売上高=4000 系（検収時は案件の区分 projects.project_type で 4000 受託/4010 SES/4020 SaaS を解決、既定 4000）/ 仮受消費税=2200 / 普通預金=1020
  ※科目コードは accounts マスタを実行時解決（ハードコード禁止、コードのみ定数）

## 3. 実装ステップ

1. **B4-1 DDL＋見積・受注**: 110_billing.sql、Quote/QuoteLine・SalesOrder/SalesOrderLine 画面（header_detail パターン=ListField）、見積→受注ボタン（明細コピー）
2. **B4-2 検収→売上仕訳**: Acceptance 画面（受注から生成）、確定で売上仕訳自動生成（手動仕訳不要=自動。締めガード・二重生成ガード）
3. **B4-3 請求書**: Invoice/InvoiceLine 画面（検収から生成 or 手動）、入金期日、画面印刷向けレイアウト（PDF 帳票はバックログ）
4. **B4-4 入金消込＋売掛管理**: Receipt 登録→消込仕訳→invoice.status 更新、売掛残一覧（未入金・期日超過の QueryField）
5. **B4-5 E2E**: 見積→受注→検収（売上仕訳）→請求→入金（消込仕訳）→試算表・BS で売掛金/売上/預金を検証

## 4. 判断メモ

- 請求時売上（出荷基準相当）は採らない（検収基準が受託の原則。請求書は検収額の写し）
- 入金手数料差引（振込手数料負担）は v1 見送り（バックログ: 手数料行の自動生成）
- 与信・督促・回収予定はフェーズ C の資金繰りダッシュボードで扱う
- 権限: 見積・受注・検収は営業（営業種別部門のメンバー）と経理の双方が起票できる（営業が起票する業務。現行の画面配置は §6）。ただし**仕訳を伴う確定操作（検収確定・入金消込）は経理専用**（B-8 の原則: 会計イベントは経理）

## 5. 2026-07-23 改訂（販売改修第7弾の差分追記）

> 決定の経緯・根拠の正典は **ADR-0029**（伝票の部門・明細の単位列・検索拡充）と **ADR-0030**（定期請求契約の確定フローと見積変換）。本節は §1〜4 に対する差分メモ（既存本文は当時の設計として据え置き）。

- **定期請求契約の状態フロー**: `recurring_billings` に `status`（draft/confirmed）を追加（ddl/340。既存契約は confirmed へ移行）。契約は「下書き（draft）」で作成され、経理の「確定する」で「確定済（confirmed）」になる（「下書きに戻す」で差し戻し可）。**「定期請求の実行」の対象は「確定済」かつ「有効（is_active）」の契約のみ**——is_active は確定後の一時停止スイッチで、解約は終了月で表す。新規契約の初期値は 状態=下書き・有効=ON・課金サイクル=月額・部門=作成者の所属部門。モジュール表示名・サイドバーリンクは「定期請求契約」に改名（「定期請求の実行」は現名のまま）。
- **権限の変更**: 定期請求契約は一般・承認者にも開放（閲覧＋下書きの作成・編集。一般・承認者フレームの販売グループに「売掛残高」「定期請求契約」リンクを追加）。確定・差し戻し・有効チェックの切替・確定済の編集は経理/sysadmin のみ（確定済の契約は非経理には読み取り専用＋注記表示）。
- **明細の単位列**: `quote_lines` / `sales_order_lines` / `invoice_lines` に `unit TEXT`（自由入力: 式・人月 等）を追加（ddl/320）。数量の右に表示、明細コピーの全経路で引き継ぎ、見積書・請求書の帳票（Excel/PDF）にも出力。定期・SES 生成の明細は「式」。
- **伝票の部門**: `quotes` / `sales_orders` / `invoices` / `recurring_billings` に `department_id` を追加（ddl/330。任意・新規作成時は作成者の所属部門が初期値）。見積→受注→請求書、契約→請求書で引き継がれ、検収確定・定期実行の売上仕訳の明細にも部門が入る（総勘定元帳の部門絞り込みで部門別売上）。
- **見積→定期請求契約の変換**: 見積（下書き/送付済）の「定期請求契約にする」ボタンで下書き契約を作成し契約詳細へ遷移（取引先・案件・部門・件名・備考・見積参照 quote_id をコピー。月額=見積の税抜合計を仮置き・開始月=翌月・サイクル=月額）。見積は「受注」状態になる。
- **検索条件の拡充**: 見積・受注・請求書に「取引先・案件・部門」のドロップダウン検索を追加。売掛残高は「取引先・状態（既定は「入金済を除く」）・支払期限・案件・部門」で検索でき、一般・承認者からも閲覧可。検収の検索は従来のまま（受注経由の取引先等の検索は CLB 制約で見送り）。

## 6. 2026-08-02 改訂（部品アーキテクチャ再編 ADR-0040/0041 の差分追記）

> 業務ロジック（状態遷移・仕訳・金額・採番）は不変。変わったのは画面の置き場所と権限の表現だけ。部品定義の正典は docs/10。

- **画面配置（ワークスペース）**: 見積・受注・検収・売掛残高・定期請求契約は **SalesStaff（営業業務）と SalesBilling（経理）の両方**に、請求書・入金・定期請求の実行・SES精算・請求は **SalesBilling のみ**に配置（取引先一覧は SalesStaff のみ。取引先等のマスタ編集は MasterBusiness＝経理管轄）。
- **権限の表現**: 旧「ロール」は廃止（ADR-0041）。営業起票＝営業アクセス（営業種別部門のメンバー）、経理限定操作（検収確定・入金消込・請求書・定期請求の確定/実行 等）＝経理（経理種別部門のメンバー）。admin（システム管理者）は業務画面に入れないため、§5 の「経理/sysadmin のみ」は現行では「経理のみ」と読む。
- §5 の「一般・承認者にも開放（一般・承認者フレームの販売グループ）」は、現行では「**営業アクセスを持つ一般・承認者**（SalesStaff）」に相当する——開発種別部門のメンバーには営業業務は見えない。開発課長 kaihatsu1_kacho1 は営業部・一般の兼務行（部門メンバーマスタに 1 行追加）で販売操作を継続している。
