# 体験シナリオ: SaaS 案件の一巡（案件作成 → 定期請求契約 → 一括請求 → 入金 → 解約）

> 作成: 2026-07-21 ／ 2026-07-23 改訂（定期請求契約の確定フロー ADR-0030 に追随）。docs/tests/14（受託一巡）の姉妹編。**「定期請求契約」「定期請求の実行」を必ず通る**構成。
> 前提 DB: 第18期・2026-07 以降の月次期間がオープン。既存の定期請求契約は「クラウド勤怠 SaaS 利用料」（月額 100,000・2026-04開始）と「クラウド勤怠 SaaS 年額プラン」（年額 1,200,000・2026-07開始）の2件。
> 採番・仕訳番号は実行時の連番（本書の番号は目安。金額と貸借が合っていれば正常）。
> 所要時間の目安: 25〜35分。

## 登場する物語

自社の新 SaaS プロダクト「請求書クラウド」をホライゾン商事株式会社（C007）に月額 150,000 円（税抜）で提供開始する。9月分から課金を始め、月次の請求ルーチンを回し、入金を確認し、年末に解約を受け付ける——SaaS ビジネスの契約ライフサイクルを一巡する。

## ステップ 1: 案件マスタの新規作成（種別 = SaaS）

**画面**: 【マスタ】案件 > 新規作成

| 項目 | 入力値 |
|---|---|
| 案件コード | `PJ-2026-201` |
| 案件名 | `請求書クラウド` |
| 取引先 | `ホライゾン商事株式会社` |
| 種別 | `SaaS` |
| 状態 | `進行中`／有効 ✓ |

- **確認ポイント**: 種別が SaaS なので **SES 契約条件の欄は表示されない**。

## ステップ 2: 定期請求契約の登録

**画面**: 【一般業務】販売 > 定期請求契約 > 新規作成

| 項目 | 入力値 |
|---|---|
| 取引先 | `ホライゾン商事株式会社` |
| プロジェクト | `請求書クラウド` |
| 件名 | `請求書クラウド 利用料` |
| 課金サイクル | `月額`（既定のまま） |
| 月額（税抜） | `150,000` |
| 開始月 | `2026-09` |
| 有効 | ✓（既定のまま） |

→ 保存。状態は「**下書き**」で登録される（新規の初期値: 下書き・有効 ✓・課金サイクル=月額）。続けて「**確定する**」を押す（経理のみ可）→ 状態「**確定済**」。

- **期待結果**: 契約一覧に3件目として並ぶ（状態「確定済」）。**まだ請求書・仕訳は生成されない**（契約マスタは器。生成は「実行」で行う。実行の対象は「**確定済」かつ「有効」**の契約のみ——下書きのままでは対象外）。

## ステップ 3:（準備）既存契約を一時的に無効化

**画面**: 【一般業務】販売 > 定期請求契約

一括生成は「対象月 × **全『確定済かつ有効』契約**」に対して走るため（既存のクラウド勤怠2契約は確定済で投入されている）、このまま 2026-09 を実行すると既存2契約の9月分も一緒に生成される。**本シナリオの結果を読みやすくするため**、既存契約2件（月額・年額プラン）を開いて「有効」のチェックを外して保存する（有効チェックの切替は経理のみ可）。

- これ自体が「解約・休止は削除ではなく有効フラグで」というマスタ運用の練習になる。
- ※外さずに実行しても業務的には正しい（月次ルーチンとして3契約分が生成される）。その場合は期待結果に クラウド勤怠 月額 110,000 税込の請求書＋按分振替 100,000 が加わる、と読み替えること。

## ステップ 4: 定期請求の一括実行（本シナリオのクライマックス）

**画面**: 【一般業務】販売 > 定期請求の実行

1. 対象月を「**2026-09**」にして「対象月の請求書を一括生成」を押す。

- **期待結果**:
  - 結果ラベル「2026年9月分: 月額請求 1件 ／ …」、トースト「定期請求の処理 1 件を生成しました」
  - 請求書（INV-26-012 目安）: 件名「請求書クラウド 利用料（2026年9月分）」・請求額（税抜）150,000・消費税 15,000・**発行日 9/30・支払期限 10/31**・状態「発行済」・発行元「定期」
  - 仕訳（No.71 目安・9/30）: 借方 **売掛金 165,000** ／ 貸方 **SaaS売上高 150,000**＋**仮受消費税 15,000**
  - 【財務・経営】財務帳票 > 損益計算書: SaaS売上高が 150,000 増える

## ステップ 5: 冪等性の確認（二重請求の防止）

もう一度、対象月 2026-09 のまま「対象月の請求書を一括生成」。

- **期待結果**: 「月額請求 0件 ／ スキップ 1件（既生成・対象外）」。請求書・仕訳は増えない（契約×対象月の冪等キー）。

## ステップ 6: 入金の消込

**画面**: 【一般業務】販売 > 入金 > 新規作成

| 項目 | 入力値 |
|---|---|
| 入金日 | `2026-10-30` |
| 請求書 | ステップ4の請求書（INV-26-012 目安）を選択 → 入金額 165,000 が自動セット |
| 入金方法 | `銀行振込` |

→ 「入金を確定（消込）」。

- **期待結果**: 消込仕訳（借方 普通預金 165,000／貸方 売掛金 165,000）。売掛残高で残額 0・「入金済」。

## ステップ 7: 月次ルーチンの反復（10月分）

対象月「**2026-10**」で一括生成 → 10月分の請求書＋仕訳がもう1本できる。**毎月ボタン1つで請求が回る**のが定期請求の価値。

## ステップ 8: 解約の受付（終了月の設定）

**画面**: 【一般業務】販売 > 定期請求契約 > 「請求書クラウド 利用料」

1. **終了月に「2026-12」**を入力して保存（12月分まで課金・1月から停止という意思表示）。
2. 対象月「**2027-01**」で一括生成 → **期待結果**: 「月額請求 0件 ／ スキップ 1件（既生成・対象外）」——終了月を過ぎた契約は対象外。請求書は生成されない。
   - ※11月・12月分は生成していないので、実務どおり順に生成してから試してもよい。

## ステップ 9: 総仕上げ

## 【発展】年額前払と按分（既存契約で観察）

年額プラン（1,200,000/年・前受）は、毎月の一括生成時に「前受収益 → SaaS売上高 100,000」の**按分振替**仕訳が自動で立つ（もらった＝売上ではなく、役務提供した分だけ売上にする発生主義）。仕訳帳で 7月・8月の「前受収益の按分振替」を検索して、前受収益残高が毎月 100,000 ずつ減っていく様子を試算表で追うと理解が深まる。年額の期中解約（未経過分の返金・前受精算）は自動化外で、振替伝票による手動処理（docs/issues/ISSUE-0002 S8）。

## つまずいたときは

- 「締め済みの期間には…」: 対象月の月次期間を【会計】設定 > 会計年度 から再オープン。
- 生成されない: 契約の状態が「**確定済**」であること（下書きは対象外——経理の「確定する」を押す）、「有効」チェック、開始月・終了月を確認（対象月が範囲外だと対象外としてスキップ）。
- 仕訳番号・請求書番号が本書と違う: 実行順で変わる（金額・貸借が合っていれば正常）。
