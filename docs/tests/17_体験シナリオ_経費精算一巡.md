# 体験シナリオ: 経費精算の一巡（申請 → 承認 → 仕訳 → 支払 → 完了）

> 作成: 2026-07-26。docs/tests/14（受託）・15（SaaS）・16（SES）の姉妹編。**現在のデモDB（第18期・最終仕訳 No.82 時点）の続きとして実行できる**ように、採番・金額を現状に合わせて書いている。
> 開発2部の社員が1週間で使った経費 5 件を、申請 → 承認（並列 OR・却下・再承認）→ 経理の仕訳生成 → 支払 → 完了まで一巡する。経費精算グループの**全機能**（立替／事前申請／取引先へ支払／交際費統制／固定資産自動判定／AI読み取り／複製／キャンセル／精算処理待ち／検索）に触れる構成。
>
> 所要時間の目安: 45〜60分（ログイン切替が多いのはワークフロー体験の宿命。ユーザー名＝パスワード）。

## 登場する物語

開発2部の松本結衣は、顧客訪問・会食・機材購入・出張・外部研修が重なる濃い1週間を過ごした。
使った（使う予定の）経費は 5 件。金額も性質もバラバラなので、承認ルートは課長決裁・課長＋総務・部長決裁と自動で振り分けられる。
週明け、総務部の山田太郎（経理）がまとめて帳簿に載せ、精算金を払い出す——経費精算という業務の最初から最後までを体験する。

## ステップ 1: 立替精算の申請（少額 → 課長ルート・案件直課）

**ログイン**: kaihatsu2_ippan（松本結衣）
**画面**: ホームのショートカット「経費申請」（またはサイドバー【経費精算】申請）> 新規作成

もっとも高頻度の「社員が現場で払った経費の後日精算」。案件を付けると案件別損益に直課される。

| 項目 | 入力値 |
|---|---|
| 件名 | `顧客先訪問の交通費` |
| 申請区分 | `立替精算（支払済み）`（既定のまま） |
| 支払先区分 | `社員へ精算`（既定のまま。精算対象者に本人が自動セット） |
| 金額（税込） | `9,900`（うち消費税は空のまま → 内税で自動計算） |
| 費目 | `旅費交通費` |
| 案件 | `保守運用SES 高橋`（任意項目。付けると案件損益に直課される） |
| 利用日 | `2026-07-21` |
| 利用先 | `JR東日本` |

→ 「申請」。

- **期待結果**: トースト「申請しました」。ステータス「申請中」・入力欄は編集不可（改ざん防止）。承認フロー表示が「状態:進行中 申請者→（**▶開発2部 第一課長 佐々木綾, ▶開発2部 第二課長 山口健太**）」——課長 2 名に**並列**で回っている（▶=現在の担当）。
- **影響先**: 両課長に通知が作られる（次ステップで確認）。**仕訳はまだ作られない**（承認前の申請は帳簿外）。本人のサイドバー【経費精算】「申請中」の一覧に「進行中」で載る。

## ステップ 2: 通知と承認待ち受信箱、そして承認（並列 OR）

**ログイン**: kaihatsu2_kacho1（佐々木綾）→ 確認だけ kaihatsu2_kacho2（山口健太）

1. kaihatsu2_kacho1 でログイン → ホームに「あなたの承認待ち: 1 件」と未読の通知「経費申請「顧客先訪問の交通費」（9,900円）の承認をお願いします」。
2. サイドバー【経費精算】「承認待ち」を開く → 本件が 1 行（申請者 開発2部 一般 松本結衣）。
3. （任意）kaihatsu2_kacho2 でもログインし、**同じ申請が第二課長の承認待ちにも見える**ことを確認（並列 OR）。
4. kaihatsu2_kacho1 に戻り、「開く」→ 内容は閲覧専用（承認者は書き換えられない）→ 「**承認**」。

- **期待結果**: トースト「承認しました」。フローが「状態:承認済 申請者→（✓佐々木綾, **—山口健太**）」（✓=承認済・—=スキップ）。ステータス「承認済」。
- **影響先**: 申請者に通知「…が最終承認されました」。**山口健太の承認待ちからは消える**（OR 承認の完了動作——二重承認や「もう1人待ち」の停滞を防ぐ）。承認履歴に「申請 → 承認（佐々木綾）」が時系列で残る。まだ仕訳なし——経理の処理待ちになる（ステップ 8）。

## ステップ 3: 交際費の申請（必須項目ブロック → 却下 → 再申請 → 総務併載）

**ログイン**: kaihatsu2_ippan → kaihatsu2_kacho1 → soumu_kacho1

交際費は税務調査の定番論点。「誰と・何人で・何のために」の記録が必須で、事業部から独立した総務のチェックが金額によらず併載される。ここでは**入力不備ブロック → 却下 → 修正して再申請**という「うまくいかない場合」も体験する。

1. kaihatsu2_ippan で新規作成: 件名 `取引先との会食`・金額 `27,500`・費目 `交際費` を選ぶ → **「接待の相手先・参加人数・接待の目的」の 3 項目が出現する**ことを確認。
2. 3 項目を**空のまま**利用日 `2026-07-22`・利用先 `炭火焼鳥 とり菊` で「申請」→ 赤トースト「**交際費は相手先・参加人数・目的の入力が必須です**」でブロック。
3. 相手先 `ホライゾン商事株式会社 山下様ほか`・参加人数 `4`・目的 `保守契約更新の御礼` を入れて「申請」→ 成功。フローは「（▶佐々木綾, ▶山口健太）→ 総務部の課長」の **2 段**（交際費は 3 万未満でも総務併載）。
4. kaihatsu2_kacho1 で本件を開き、コメント欄に `参加人数に社内参加者も含めて再確認してください` と入れて「**却下**」。
5. kaihatsu2_ippan に戻る → 通知「…が却下されました（コメント: …）」。申請を開くとステータスが「**下書き**」に戻り編集可能。参加人数を `6` に直して「再申請」。
6. kaihatsu2_kacho1 で承認 → soumu_kacho1（石川真理）でログインし、承認待ちから開いて「承認」。

- **期待結果**: ステータス「承認済」。承認履歴に「申請 → 却下（コメント付き）→ 再申請 → 承認（佐々木綾）→ 承認（石川真理）」が申請回数（1回目→2回目）付きで全部残る。
- **影響先**: 却下時点では帳簿に何も残らない（下書きに戻るだけ）。再申請でルートはルールから**再解決**される（承認済みだった段もリセット）。

## ステップ 4: 備品 10 万円以上の申請（固定資産の自動判定 → 部長ルート）

**ログイン**: kaihatsu2_ippan → kaihatsu2_bucho

10 万円以上の資産性支出は費用でなく「工具器具備品（資産）」に計上して減価償却する——税法の強制。現場にこの判断はさせず、**費目=備品 × 金額 ≥ 10 万でシステムが自動判定**する。

1. kaihatsu2_ippan で新規作成: 件名 `開発用ワークステーション`・費目 `備品`・金額 `132,000`・利用日 `2026-07-23`・利用先 `オリオン事務機 通販`。
2. 金額入力の時点で情報トースト「**金額 132,000 円 ≧ 少額基準 100,000 円のため固定資産計上対象にしました（承認後に固定資産台帳へ登録されます）**」＋「固定資産計上対象」チェックが自動 ON になるのを確認 → 「申請」。
3. フローが「▶開発2部 部長 加藤正雄, ▶開発2部 部長代理 吉田直樹」（部長 2 名の並列・1 段。132,000 は 3 万〜20 万の帯）になることを確認。
4. kaihatsu2_bucho で承認待ちから開いて「承認」。

- **期待結果**: ステータス「承認済」（部長代理はスキップ）。
- **影響先**: 仕訳生成時（ステップ 8）に借方が費目の既定（消耗品費）ではなく**工具器具備品（資産）**に切り替わり、固定資産台帳へ自動登録される。閾値 10 万は制度閾値マスタ `SMALL_ASSET_EXPENSE` 参照——税制改正時はマスタ変更だけで追随できる。

## ステップ 5: 事前申請 → 実費確定 → 超過の自動再承認

**ログイン**: kaihatsu2_ippan → kaihatsu2_kacho1 → kaihatsu2_ippan → kaihatsu2_bucho

出張は「事前に見込み額で承認 → 事後に実費確定」が実務。実費が**承認ルート区分をまたぐ、または見込み×110% 超**なら自動で再承認に回る（事前承認の形骸化防止）。

1. kaihatsu2_ippan で新規作成。申請区分を「**事前申請（これから支払う）**」に変更 → **「見込み額」欄が出現**（立替では非表示）。
2. 件名 `名古屋出張（顧客定例）`・費目 `旅費交通費`・見込み額 `20,000`・利用日 `2026-07-27` で「申請」（金額欄は空のまま）。フローは課長ルート（20,000 < 3万）。
3. kaihatsu2_kacho1 で承認。
4. kaihatsu2_ippan で申請を開く → 「実費（税込）」欄が出現している。`36,300` を入力し「実費を確定」。
5. トースト「**実費が見込みを超過したため再承認を依頼しました**」——36,300 は①区分跨ぎ（3万以上=部長帯）かつ②20,000×110%=22,000 超。フローが「▶加藤正雄, ▶吉田直樹」に**再解決**される。
6. kaihatsu2_bucho で「承認」。

- **期待結果**: 再承認完走。ステータス「承認済」・金額（税込）36,300。承認履歴に再申請理由「実費 36,300 円が見込み 20,000 円を超過したため再承認」が残る。
- **影響先**: 仕訳生成時の金額は実費（税抜 33,000＋税 3,300）。実費が 21,000 円など「区分内かつ 110% 以内」なら再承認なしでそのまま経理処理に進む。

## ステップ 6: 取引先へ支払う経費の申請（社員立替ではないケース）

2. 支払取引先を**空のまま**「申請」→ 赤トースト「**支払取引先を選択してください**」（ブロック確認）。
3. 支払取引先 `株式会社ベガソフト`・金額 `16,500`・費目 `図書研修費`・利用日 `2026-07-24`・利用先 `ベガソフト技術セミナー` で「申請」→ kaihatsu2_kacho1 で承認（16,500 → 課長ルート。ルート規則は社員立替と同じ）。

- **期待結果**: ステータス「承認済」。
- **影響先**: 仕訳の貸方は同じ未払金だが、「誰に払う債務か」が申請の支払取引先で管理される。

## ステップ 7: 入力を楽にする機能（AI 読み取り・複製）と申請のキャンセル

**ログイン**: kaihatsu2_ippan

帳簿を汚さない「練習 3 件」。すべて最後に削除して片付ける。

1. **AI 領収書読み取り（モック）**: 新規作成画面の「AI 読み取り（添付＋自動入力）」に任意の画像をアップロード → トースト「AI読み取り結果を反映しました。…」。件名「会食代（AIモック読み取り）」・金額 12,800・費目 交際費・**交際費の 3 項目まで自動充填**され、領収書欄に画像が付くことを確認（**ボタンを押した時だけ AI が動く**オプトイン設計。実 AI キーを設定すると実物のレシートが読める）。申請せず「この下書きを削除」。
2. **複製**: ステップ 2 で完了した「顧客先訪問の交通費」…はまだ「承認済」なので、一覧から任意の申請（自分のもの）を開き「この申請を複製」→ 件名・金額・費目・案件がコピーされ利用日=本日の**下書き**ができる（領収書と承認履歴は引き継がれない）ことを確認 → 「この下書きを削除」。
3. **キャンセル**: 新規作成: 件名 `勉強会参加費（中止）`・金額 `5,000`・費目 `図書研修費`・利用日 `2026-07-25` → 「申請」→ 直後に「キャンセル」→ ステータスが「下書き」に戻る → 「この下書きを削除」。

- **期待結果**: 3 件とも痕跡なく片付く。承認者の受信箱からも消える。帳簿への影響なし。**キャンセルは申請者本人のみ可能**。

## ステップ 8: 経理処理——精算処理待ち → 仕訳生成 → 支払 → 完了（仕訳 No.83〜92）

**ログイン**: soumu_bucho（山田太郎・経理）
**画面**: サイドバー【一般業務】経費精算 > **精算処理待ち**

本シナリオのクライマックス。承認済みの申請を帳簿に載せ（費用計上）、精算金を払う（支払）。仕訳は 1 件につき 2 本:

- **費用計上**: 借方 費目の科目（税抜）＋仮払消費税 ／ 貸方 **未払金**。仕訳日は**利用日**（発生主義）。
- **支払**: 借方 未払金 ／ 貸方 普通預金。仕訳日は**支払日（操作当日）**。

全行に**申請者の所属部門**（予実管理用）と**案件**（案件損益用）が自動で刻まれる。

1. 「精算処理待ち」を開く → 承認済みの 5 件（ステップ 1〜6 の分）が経理の作業受信箱として一覧に載っている（既存の申請中データが混ざっていても触らない）。
2. 各行の「開く」で詳細へ遷移し、**申請ごとに「仕訳を生成」→「精算済にする」→「完了にする」**を順に押す。ステップ 1 → 3 → 4 → 5 → 6 の順に処理すると:

| 申請 | 計上仕訳（日付=利用日） | 支払仕訳（日付=操作日） |
|---|---|---|
| 交通費 9,900 | **No.83** 借 旅費交通費 9,000＋仮払消費税 900／貸 未払金 9,900（7/21） | **No.84** 未払金 9,900／普通預金 9,900 |
| 会食 27,500 | **No.85** 交際費 25,000＋税 2,500／未払金 27,500（7/22） | **No.86** 27,500 |
| ワークステーション 132,000 | **No.87** **工具器具備品 120,000**＋税 12,000／未払金 132,000（7/23）＋「固定資産台帳に登録しました…」 | **No.88** 132,000 |
| 名古屋出張 36,300 | **No.89** 旅費交通費 33,000＋税 3,300／未払金 36,300（7/27） | **No.90** 36,300 |
| 研修受講料 16,500 | **No.91** 図書研修費 15,000＋税 1,500／未払金 16,500（7/24） | **No.92** 16,500 |

- **確認ポイント**:
  - ワークステーションの計上トーストは借方科目が「工具器具備品」になっている（費目の既定=消耗品費ではない）。続けて固定資産台帳への登録トーストが出る。
  - 「仕訳を生成」をもう一度押すと「この申請の仕訳は既に生成済みです」（二重計上ガード）。
  - 5 件とも「完了」になると精算処理待ちの一覧から消えていく。
- **影響先**（見に行く価値あり）:
  - 【会計】帳簿 > 仕訳帳: 計上 5 本が**利用日**で、支払 5 本が**操作日**で並ぶ（発生主義と決済の日付分離）。

## つまずいたときは

- **「締め済みの期間には起票できません」**: 利用日が締め済み月次に入っている。【会計】設定 > 会計年度 で該当月を再オープンするか、利用日をオープン期間にする。

- **仕訳番号が本書と違う**: 番号は「年度の最終番号+1」で採番されるため、他の操作を挟めばずれる。金額と貸借が合っていれば正常。
