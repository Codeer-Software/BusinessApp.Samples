# 体験シナリオ: SES 案件の一巡（案件作成 → 工数実績 → SES精算・請求 → 入金）

> 作成: 2026-07-21 ／ 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映。画面導線・権限表記のみ現行化——業務の流れ・金額・期待結果は不変）。docs/tests/14（受託）・15（SaaS）の姉妹編。**「SES精算・請求」を必ず通る**構成。
> 前提 DB: 第18期・2026-07 以降の月次期間がオープン。既存の SES 案件は PRJ-003 金融系SES 山田（月額 800,000・幅 140〜180h）と PRJ-005 保守運用SES 高橋（月額 750,000・幅 140〜180h）の2件（いずれも有効）。
> 採番・仕訳番号は実行時の連番（本書の番号は目安）。
> 画面表記: 【◯◯】はワークスペース: 【会計】=Accounting／【営業請求・入金】=SalesBilling／【経営管理】=ManagementFull／【業務マスタ】=MasterBusiness。移動はサイドバー「ほかの業務」の静的リンク。
> 所要時間の目安: 25〜35分。

## 登場する物語

新たに SES 契約が1本決まった。開発2部の松本結衣をホライゾン商事株式会社に常駐させ、**月額 600,000 円（税抜）・精算幅 140〜180h・控除/超過単価 4,000 円/h** の条件で 9月から稼働する。月末に工数実績から精算額を計算し、請求書と売上仕訳を自動生成、翌月末に入金を回収する——SES ビジネスの月次サイクルを一巡する。

## ステップ 1: 案件マスタの新規作成（種別 = SES）

**ログイン**: soumu_bucho / soumu_bucho（経理）
**画面**: 【業務マスタ】案件 > 新規作成

| 項目 | 入力値 |
|---|---|
| 案件コード | `PJ-2026-301` |
| 案件名 | `業務システム保守SES 松本` |
| 取引先 | `ホライゾン商事株式会社` |
| 種別 | `SES` → **ここで SES 契約条件の欄が出現する**（種別連動表示） |
| 状態 | `進行中`／有効 ✓ |
| SES 月額基本料金 | `600,000` |
| 精算下限(h) / 上限(h) | `140` / `180` |
| 控除単価(円/h) / 超過単価(円/h) | `4,000` / `4,000` |

- **設計メモ**: 1案件 = 1つの SES 契約条件（要員1名分）。複数要員は要員ごとに案件を分けるのが本アプリの運用（案件名に要員名を入れる）。

## ステップ 2: 工数実績の入力（現場エンジニア視点）

**ログイン**: kaihatsu2_ippan / kaihatsu2_ippan（開発2部 一般 松本結衣）
**画面**: 工数管理（Timesheet・サイドバー「ほかの業務/工数・案件」）>「工数入力」> 新規作成

2026年9月の稼働 **150時間 = 9,000 分** を登録する（実務では日々入力するが、テストでは数件にまとめてよい。例）:

| 日付 | 時間（分） |
|---|---|
| 2026-09-10 | `4,500` |
| 2026-09-24 | `4,500` |

- 案件はいずれも `業務システム保守SES 松本`。担当者は本人固定。
- **期待結果**: 一覧に自分の 2 行。合計 9,000 分 = 150h（精算幅 140〜180h の**幅内**になる値）。

## ステップ 3:（準備）既存 SES 案件を一時的に無効化

**ログイン**: soumu_bucho に戻る
**画面**: 【業務マスタ】案件

SES の一括生成は「対象月 × **全有効 SES 案件（月額設定済み）**」に走り、**実績 0 の案件も下限割れ（控除）として請求計算される**。本シナリオの結果を読みやすくするため、PRJ-003 と PRJ-005 を開いて「有効」チェックを外して保存する（後片付けで必ず戻す）。

## ステップ 4: 精算の計算（請求書はまだ作らない）

**画面**: 【営業請求・入金】SES精算・請求

1. 対象月「**2026-09**」で「**精算を計算**」を押す。

- **期待結果**: 内訳に「業務システム保守SES 松本: **基本 600,000（精算幅 140〜180h・実績 150h00m）= 600,000（幅内）**」。結果ラベル「2026年9月分: SES 1 件の精算を計算しました（請求書は未生成）」。
- 「精算を計算」は**何度押しても帳簿に影響しない**（BuildPlan→表示のみ）。計算分岐を安全に確認できる。

### 変化形（任意・計算のみで確認）

- **下限割れ**: 対象月を「2026-10」（実績 0）にして計算 → `基本 600,000 − 控除 140h × 4,000 = 40,000` の控除形の式が出る。
- **超過**: 工数入力で 9月にさらに 3,000 分（+50h → 計200h）足して再計算 → `基本 600,000 ＋ 超過 20h × 4,000 = 680,000`。**確認後は追加した工数を削除して 150h に戻すこと**（金額が変わったまま生成しないため）。

## ステップ 5: 請求書の一括生成（売上仕訳込み）

1. 対象月「2026-09」に戻し「**請求書を一括生成（売上仕訳込み）**」を押す。

- **期待結果**:
  - 請求書（INV-26-012 目安）: 件名「SES精算 業務システム保守SES 松本（2026年9月分）」・税抜 600,000・消費税 60,000・発行日 9/30・期限 10/31・発行元「SES」
  - 仕訳（9/30）: 借方 **売掛金 660,000** ／ 貸方 **SES売上高 600,000**＋**仮受消費税 60,000**（科目 4010 = SES 区分の自動解決）
2. もう一度同じ対象月で生成 → **スキップ**（冪等。二重請求されない）。

## ステップ 6: 入金の消込

**画面**: 【営業請求・入金】入金 > 新規作成

入金日 `2026-10-30`／請求書 = ステップ5の請求書 → 660,000 自動セット → 「入金を確定（消込）」。

- **期待結果**: 借方 普通預金 660,000／貸方 売掛金 660,000。売掛残高 0・入金済。

## 【発展】条件改定（変更契約）の注意

単価・精算幅の改定は案件マスタの書き換えで行うが、**条件に履歴がない**ため「未生成の過去月」を後から精算すると新単価で計算されてしまう。**過去月の精算をすべて生成し終えてから条件を書き換える**のが運用ルール（docs/issues/ISSUE-0002 S9。恒久対応の契約履歴管理は将来課題）。

## つまずいたときは

- 「対象の SES 案件がありません」: 案件の「有効」チェックと月額基本料金（未入力/0 は対象外）を確認。
- 実績が拾われない: 工数の日付が対象月に入っているか・案件の選択が正しいかを確認（時間は分単位）。
- 締め済みエラー・番号ずれ: docs/tests/14 の同項参照。
