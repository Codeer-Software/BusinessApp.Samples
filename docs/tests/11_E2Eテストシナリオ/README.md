# E2E テストシナリオ兼 業務理解ドキュメント

> **2026-08-09 現行化の要点**: ①ログイン後は**全員が業務ポータル（Main/PortalHome）に着地**し、業務への移動は **Main 左サイドバー**に一本化（ADR-0042/0045。`/{フレーム}/Top`・「ほかの業務」・部品別ホーム画面は全廃）。②機能権限は**ユーザーの直接フラグ**になった（ADR-0043。部門メンバー行は見え方に影響しない）。③部門は**部課 2 階層**になり承認者は **walk-up** で解決される（ADR-0044）。④承認ルートは**積み上げ方式**（ADR-0048）。⑤通知一覧は **`/Main/Notification`** に一本化（ADR-0045/0046 系レビュー）。⑥アプリ名は「よろず」（ADR-0047）。**仕訳・金額・勘定科目の期待値は一切不変。**
> **目的**: 財務会計の知識が乏しい開発者が、本書に沿ってアプリを操作することで、①「どの画面で何を操作すると、どの帳票・データにどう影響するか」（システムの挙動）と、②「実務では何のために・どの順番で・何の業務を行うか」（会計実務の基本）を同時に理解する。

## 1. 本書の構成（読む順序 = 実行する順序）

会計の 1 年は「**期首の準備 → 日常取引の記帳 → 月次の照合 → 決算 → 翌期への繰越**」というサイクルで回る。本書はこのライフサイクル順のフォルダ構成で、**00 から 09 まで順に実行すると、まっさらな会計帳簿が 1 期分の決算を終えて翌期に繰り越されるまでの全過程**を体験できる。各フォルダには「基本シナリオ」（本流の 1 周）と「分岐シナリオ」（その業務のあらゆる条件分岐を網羅する追加シナリオ群）がある。

| フォルダ | 実務上の位置づけ | 分岐網羅の状態 |
|---|---|---|
| [00_初期設定/](00_初期設定/基本シナリオ.md) | 導入時の器づくり（seed 確認・期首残高・予算・権限境界） | 基本のみ（完） |
| [01_経費精算/](01_経費精算/README.md) | 社員の立替経費: 申請→承認→仕訳→精算 | **分岐網羅済み（EXP-R/S/P/A/X 全 20 本）** |
| [02_販売/](02_販売/基本シナリオ.md) | 見積→受注→検収→請求→入金、定期請求・SES | 基本のみ（分岐は段階納品の次段） |
| [03_購買/](03_購買/基本シナリオ.md) | 仕入先請求書→未払計上→振込→支払 | 基本のみ（同上） |
| [04_会計コア/](04_会計コア/基本シナリオ.md) | 振替伝票・定型仕訳・入出金・CSV インポート | 基本のみ（同上） |
| [05_銀行/](05_銀行/基本シナリオ.md) | 明細取込→自動仕訳→残高照合 | 基本のみ（同上） |
| [06_案件・経営管理/](06_案件・経営管理/基本シナリオ.md) | 工数→配賦→案件損益、予算予実 | 基本のみ（同上） |
| [07_特殊取引/](07_特殊取引/基本シナリオ.md) | 赤黒訂正・貸倒れ・過入金・消込差額 | 基本のみ（同上） |
| [08_決算/](08_決算/基本シナリオ.md) | 月次締め・減価償却・経過勘定・消費税・繰越 | 基本のみ（同上） |

### 2.3 着地・導線・画面の表記法（本書全体のルール／2026-08-09 全面改訂）

#### (a) 着地は全員ポータル（ADR-0042/0045）

- **ログインすると、権限にかかわらず全員が業務ポータル（`/` = Main フレームの `PortalHome`）に着地する。** 旧「権限に応じたフレームへの自動振り分け」は無い。
- 業務への移動は **Main 左サイドバー**（`Shell/PortalSidebar`）に一本化。最上部のブランドは 2 行で「**よろず** ／ 統合業務基盤アプリ」（ADR-0047。旧称「帳合」）、クリックでポータルに戻る。最下部に **Logout**（英語表記・押すと即ログアウト）。
- 各業務フレームは**フレーム素の URL**（`/Accounting`・`/ExpenseStaff` など）で既定業務画面に着地する。**`/{フレーム}/Top` は全廃**（本書の旧記述 `/XXX/Top` はすべて `/XXX` に読み替える）。
- 各業務フレームのサイドバー先頭は「**ホーム**」で、押すとポータルに戻る。**「ほかの業務」リンク・「マイページ」・部品別ホーム画面（ExpenseHome／SalesHome／AccountingHome／AdminHome）とその切替ボタンはすべて廃止**。業務から業務への移動は必ず「ホーム → ポータルのサイドバー → 目的の業務」。
- 通知一覧は **`/Main/Notification`**（`Shell/NotificationCenter`）に一本化（経費フレームの「通知」メニューは廃止）。既定は**未読のみ表示**、「既読の通知を全て削除」（赤・確認ダイアログ）あり。サイドバーのラベルは未読があると「**通知 (3)**」のように件数バッジになる。
- 権限の無いフレームは URL 直打ちで「**ページフレームへのアクセス権限がありません**」でブロックされる（Main フレームだけはゲート無し＝全員が入れる）。

表示条件は §2.5 の機能権限フラグ。遷移先は**変種解決**（経理 > 承認者 > 一般の順で最初に該当したフレーム）。

| 工数管理 | `CanUseTimesheet` | TimesheetAccounting > Timesheet |

#### (c) ポータル中央の表示（`docs/13_ポータルと通知基盤.md` §3 が正典）

上から順に: 挨拶「こんにちは、{表示名} さん」＋日付 →「▶ あなたの承認待ち: N 件」（`IsApprover` ∨ 経理）→「▶ 進行中のあなたの申請: N 件」（`CanUseExpense`）→ 見出し「**未読の通知**」＋未読リスト（各行に「開く」）→「通知をすべて見る →」→ 見出し「**経理の作業キュー**」（精算処理待ち／未起票の銀行明細／下書きのままの伝票／定期請求・SES の当月未生成）→ 見出し「**アラート**」（支払期限／期限超過の売掛／資金ショート予測／予算警告）→ 見出し「**経営ダッシュボード（当月）**」（現預金・売掛金・買掛金／当月売上高・費用・利益。利益が負なら赤字表示）→「ユーザー・組織・承認ルートの管理はこちら →」（`IsSysAdmin`）。

- **キューとアラートは 0 件の行が丸ごと消える**（見出しも配下が全部 0 なら消える）＝「対応が要るときだけ見える」。
- 一方「あなたの承認待ち」「進行中のあなたの申請」は**権限があれば 0 件でも行が出る**（0 件表示）。
- 件数はラベル文字列に埋め込まれ、クリックで該当一覧へ飛ぶ。旧 ExpenseHome／AccountingHome が持っていた件数・KPI・資金繰りアラートはすべてここへ移設された。

#### (e) 表記法と操作の原則

- 本書の画面表記 **`【グループ】リンク`** は維持する（グループ = サイドバーのグループ見出し。例:「【帳簿】仕訳帳」= 会計業務フレームの「帳簿」グループ内「仕訳帳」）。グループの無い浅いメニューはリンク名のみで表記する。
- 業務から業務へ移る手順は「**サイドバー「ホーム」→ ポータルのサイドバー「○○」**」と書く。旧表記「ほかの業務 → ○○」はこの手順に読み替える。
- **リンクやフレームが見えない＝その権限では使えない**が仕様（サイドバー構成がフレーム定義そのもの）。取引先・案件の**マスタ編集画面は MasterBusiness**（経理のみ）で、他のユーザーは SalesStaff の「取引先一覧」・**Timesheet（非経理の工数フレーム）**の「案件一覧」だけを見る（案件は部長〔`IsDirector`〕ならこの一覧から登録・変更も可。SES 精算条件は経理のみ編集。ADR-0046。※経理は TimesheetAccounting に入るため案件一覧は出ず、MasterBusiness の「案件」を使う）。
- **admin（システム管理者）は業務画面に一切入れない**（職務分掌。経費精算・工数入力フラグも OFF。担当は組織・承認ガバナンスのみで、**勘定科目・税率などの会計マスタも経理の管轄** = MasterBusiness）。
- 操作の原則（ADR-0026/0027）: **「状態」は全画面で表示専用**で遷移はボタンのみ（青 = 前進・赤 = 削除/取消）。**一覧に削除ボタンは無く**、削除は詳細画面の赤ボタン（状態条件つき・確認ダイアログつき）。誤操作は「〜を取り消す」「下書きに戻す」で巻き戻す（仕訳を生んだ操作の取消は該当仕訳も削除・締め済み期間は不可）。
- 会計年度の表示は全画面で `fiscal_years.label` の「**第18期（2026年度）**」形式。

### 2.5 権限の全体像（3 軸分離: 機能権限／組織所属／承認構造・2026-08-09 全面改訂）

旧 4 ロールは廃止済み（ADR-0041）。さらに ADR-0043 で「見え方を組織所属から導出する」設計をやめ、**3 つの関心をそれぞれ別の構造に持たせる**ようになった。**部門メンバー行の追加・削除は、もはや画面の見え方に一切影響しない**（これが 2026-08-05 以前との最大の違い）。

| 軸 | 実体 | 編集場所 |
|---|---|---|
| ① 機能権限 | `AppUser` の**直接フラグ 5 本**: 営業機能 / 経理機能 / 経費精算（既定 ON）/ 工数入力（既定 ON）/ システム管理者 | MasterAdmin >【組織】ユーザー管理 の詳細画面の**チェックボックス** |
| ② 組織所属 | `departments`（部課 2 階層。parent なし = 部／あり = 課）＋ `department_members`（ユーザー × ノード × 役職 一般/課長/部長） | MasterAdmin >【組織】部門 の詳細画面 |
| ③ 承認構造 | ②の課長/部長行 ＋ 承認フローテンプレート ＋ 承認ルート判定マスタ | MasterAdmin >【承認】の 2 画面 |

- **導出キャッシュは `IsApprover` と `IsDirector` の 2 本だけ**（DB トリガーが保守・手入力不可の閲覧専用値）。
  - `IsApprover` = どこかの部門に**課長/部長行がある** ∨ **承認テンプレートの個人指名承認者である**
  - `IsDirector` = どこかの部門に**部長行がある**（案件の登録・変更の書込条件。ADR-0046）
- **兼務は部門メンバー行の追加**で表現するが、それは**組織上の事実の表明にすぎない**。「この人に営業画面を見せたい」ならユーザー管理で**営業機能にチェック**を入れる（ADR-0043。旧「営業種別部門にメンバー登録して見せる」手順は廃止。`dept_type`〔部門種別〕列も削除済み）。

#### フレーム（機能領域）とゲート条件

| 機能領域 | フレーム | ゲート条件 |
|---|---|---|
| 経費の申請・申請中 | ExpenseStaff | `CanUseExpense` |
| 承認待ち（受信箱）・承認/却下 | ExpenseApprover | `IsApprover`（**自分が現在の承認担当の案件のみ**表示） |
| 精算処理待ち・仕訳生成・支払 | ExpenseAccounting | `HasAccountingAccess` |
| 工数入力・案件一覧 | Timesheet | `CanUseTimesheet` |
| 工数管理（経理） | TimesheetAccounting | `HasAccountingAccess` |
| 見積・受注・検収・売掛残高・定期請求契約・取引先一覧 | SalesStaff | `HasSalesAccess` |
| 請求書・入金・定期請求の実行・SES精算 | SalesBilling | `HasAccountingAccess` |
| 仕訳・帳簿・銀行・財務帳票・会計年度 | Accounting | `HasAccountingAccess` |
| 仕入先請求書・支払予定表・振込データ | Purchasing | `HasAccountingAccess` |
| 予実対比・予算明細 | ManagementApprover | `IsApprover` |
| ＋ 予算入力・案件損益・人件費配賦・資金繰り予測 | ManagementFull | `HasAccountingAccess` |
| 業務マスタ・会計マスタ・税制の編集 | MasterBusiness | `HasAccountingAccess` |
| 組織・承認ガバナンス（ユーザー・部門・テンプレ・ルート判定） | MasterAdmin | `IsSysAdmin` |

- 経理は承認者フレームの上位互換（変種解決が経理を優先）なので、**経理は承認待ちも精算処理待ちも ExpenseAccounting で扱う**。
- **admin は全業務フラグが OFF** なので、ゲートのある全フレームでブロックされる。ExpenseStaff・Timesheet も `CanUseExpense`/`CanUseTimesheet` のゲートを持つため（ADR-0043）、**URL 直打ちでも開かない**。
- 書込権限が無い画面は、開いても**フィールドが自動で読み取り専用**になる（保存もサーバで拒否）。「新規作成」ボタン自体は見えることがあるが安全（CLB の既知挙動 → docs/12 FB-010）。
- **定期請求契約は例外的に営業一般・承認者へも開放**（ADR-0030）: 営業業務が見えるユーザーは閲覧と**下書きの作成・編集**が可能。「確定する」「下書きに戻す」・有効チェックの切替・確定済の編集は経理のみ（確定済の契約は非経理には読み取り専用＋注記表示）。「定期請求の実行」の対象は「確定済」かつ「有効」の契約のみ。

#### 承認者はどう決まるか（walk-up ＋ 積み上げ）

- 「承認できるか」は機能権限ではなく **②の課長/部長行**で決まる（経理も課長/部長行を持てる——総務部内の承認が動くのはこのため）。
- 役職者の解決は **walk-up**（ADR-0044）: 申請者の**主所属ノードから親方向へ辿り、最初に見つかったノードの該当役職者全員**（申請者本人は除く）に回る。したがって**自分の課の課長だけ**が決裁し、隣の課の課長には回らない。該当者ゼロなら 課長 → 部長 → 経理代替（`HasAccountingAccess` かつ有効な最小 Id・申請者以外）→ それも無ければ申請ブロック。
- 同一ノードに同役職が 2 名以上なら **OR 並列**（1 人の承認で段が完了・残りはスキップ）。この組織では**課長は各課 1 名なので課長段は単独**、**部長は部長＋部長代理の 2 名なので部長段が並列**になる。
- 承認ルートは**積み上げ方式**（ADR-0048）: 金額が上がっても承認者は入れ替わらず**段が増える**（〜29,999 = 課長／30,000〜199,999 = 課長 → 部長／200,000〜 = 課長 → 部長 → 総務。交際費は 29,999 以下でも総務が付く）。
- **直前の役職段と承認者集合が完全一致する段は生成しない**（段の圧縮）。課長空席・課長本人の申請では課長段が部長へ繰り上がり、部長段と畳まれて「部長のみ 1 段」になる。
- **伝票（経費申請・仕訳・請求等）の部門は「部」のみ**。課は候補に出ず、既定値は申請者の所属課の親の部が自動で入る（ADR-0044）。

## 3. 複式簿記の 30 秒サマリ

- すべての取引は「**借方（左）＝貸方（右）**」で記録する。借方合計≠貸方合計の伝票は**確定できない**。
- 科目は 5 区分: **資産**（借方が増）・**負債**（貸方が増）・**純資産**・**収益**（貸方が増）・**費用**（借方が増）。
- 帳票はすべて確定済み仕訳（＋期首残高）の集計: 仕訳帳（日付順）・総勘定元帳（科目別）・試算表（残高一覧）・BS（財政状態）・PL（経営成績）。
- 消費税は**税抜経理・明示税行方式**: 税込 11,000 の課税仕入 → システムが「本体 10,000 ＋ 仮払消費税 1,000」に自動分解。売上側は仮受消費税。期末に相殺して未払消費税等を確定する。

## 5. テスト完了後の総合検算（sql CLI）

```sql
-- ① 全確定仕訳の貸借一致（期待値: 借方=貸方=11,852,675）
SELECT SUM(CASE WHEN dc='D' THEN jl.amount ELSE 0 END) AS 借方,
       SUM(CASE WHEN dc='C' THEN jl.amount ELSE 0 END) AS 貸方
FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
WHERE je.status='posted';

-- ② 伝票番号の重複ゼロ（期待値: 0）
SELECT COUNT(*) FROM (SELECT fiscal_year_id, journal_no, COUNT(*) c
FROM journal_entries GROUP BY fiscal_year_id, journal_no HAVING c > 1);

-- ③ 売掛金の元帳残高（期待値: 1,320,000。売掛残高一覧の残額合計と一致すること）
SELECT (SELECT SUM(CASE WHEN dc='D' THEN amount ELSE -amount END)
        FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
        JOIN accounts a ON a.id=jl.account_id
        WHERE a.code='1100' AND je.status='posted') AS 売掛金元帳残高;

-- ④ 第19期 期首残高の貸借一致（期待値: 0）
SELECT SUM(balance) FROM opening_balances
WHERE fiscal_year_id=(SELECT id FROM fiscal_years WHERE name='第19期');
```
