## 1. 本書の構成（読む順序 = 実行する順序）

| [01_経費精算/](01_経費精算/README.md) | 社員の立替経費: 申請→承認→仕訳→精算 | **分岐網羅済み（EXP-R/S/P/A/X 全 20 本）** |

### 2.3 画面の表記法（本書全体のルール）

ページフレームは**業務部品ごとのワークスペース**（ADR-0040。部品定義の正典は `docs/10_部品アーキテクチャ.md`）。URL は `/{フレーム名}/{セグメント}`、各フレームのトップは `/{フレーム名}/Top`。ログインすると `/` から**権限に応じたフレームへ自動着地**する（システム管理者→MasterAdmin／経理→Accounting／承認者→ExpenseApprover／営業→SalesStaff／その他→ExpenseStaff）。権限の無いフレームは URL 直打ちで「ページフレームへのアクセス権限がありません」でブロックされる。

| ワークスペース | 誰が入れるか | サイドバーの内容 |
|---|---|---|
| ExpenseStaff（経費精算） | ログインユーザー全員 | ホーム（ExpenseHome）・申請・申請中・通知 |
| ExpenseApprover（経費精算・承認者） | 承認者（どこかの部門の課長/部長） | 上記＋**承認待ち** |

| TimesheetAccounting（工数管理・経理） | 経理 | 工数入力・工数管理（経理） |
| SalesStaff（営業業務） | **営業アクセス**（営業種別部門のメンバー） | ホーム（SalesHome）・見積・受注・検収・売掛残高・定期請求契約・取引先一覧（閲覧専用） |

切替導線: **経理系 7 フレーム**（会計／営業請求・入金／購買・支払／経費精算／工数管理／経営管理／業務マスタ）はサイドバー「**ほかの業務**」の静的リンクで相互接続。一般・承認者系は「ほかの業務」の権限に応じたリンク＋「マイページ」（自分のホームへ戻る）と、ホーム画面（ExpenseHome／SalesHome）の切替ボタン（「営業業務へ」「工数・案件へ」「経営管理（予実）へ」等。権限のある人にだけ表示）。

本書の画面表記 **`【グループ】リンク`** は維持する（グループ=サイドバーのグループ見出し。例: 「【帳簿】仕訳帳」= 会計ワークスペースの「帳簿」グループ内「仕訳帳」）。経費精算・営業業務などグループの無い浅いメニューはリンク名のみで表記する。**リンクやワークスペースが見えない＝その権限では使えない**が仕様（サイドバー構成がフレーム定義そのもの）。取引先・案件の**マスタ編集画面は MasterBusiness**（経理のみ）で、他のユーザーは SalesStaff の「取引先一覧」・Timesheet の「案件一覧」（閲覧専用・新規作成・削除・詳細編集なし）だけを見る。**admin（システム管理者）は業務画面に一切入れない**（職務分掌。担当は組織・承認ガバナンスのみで、**勘定科目・税率などの会計マスタも経理の管轄** = MasterBusiness）。
なお操作の原則（ADR-0026/0027）: **「状態」は全画面で表示専用**で遷移はボタンのみ（青=前進・赤=削除/取消）。**一覧に削除ボタンは無く**、削除は詳細画面の赤ボタン（状態条件つき・確認ダイアログつき）。誤操作は「〜を取り消す」「下書きに戻す」で巻き戻す（仕訳を生んだ操作の取消は該当仕訳も削除・締め済み期間は不可）。

## 3. 複式簿記の 30 秒サマリ

- すべての取引は「**借方（左）＝貸方（右）**」で記録する。借方合計≠貸方合計の伝票は**確定できない**。
- 科目は 5 区分: **資産**（借方が増）・**負債**（貸方が増）・**純資産**・**収益**（貸方が増）・**費用**（借方が増）。
- 帳票はすべて確定済み仕訳（＋期首残高）の集計: 仕訳帳（日付順）・総勘定元帳（科目別）・試算表（残高一覧）・BS（財政状態）・PL（経営成績）。
- 消費税は**税抜経理・明示税行方式**: 税込 11,000 の課税仕入 → システムが「本体 10,000 ＋ 仮払消費税 1,000」に自動分解。売上側は仮受消費税。期末に相殺して未払消費税等を確定する。

## 4. 本シナリオの全体ストーリーと期待値台帳

**株式会社アルタイルシステムズ**（IT 受託・3 月決算・第 18 期）が 7 月にアプリを導入し、期首残高投入 → 7 月の全業務 → 決算 → 第 19 期繰越まで行う。基本シナリオの本流で発生する**41 本の仕訳**（№・金額・borrow/貸方）は [全仕訳台帳.md](全仕訳台帳.md) が正（旧版から金額は不変・操作者のみ新ユーザーに変更）。分岐シナリオのうち帳簿に影響するものは各章の README に「本流への影響: あり/なし」を明記する。

主要な着地値: **Σ借方 = Σ貸方 = 11,852,675**／BS 合計 5,868,985／当期純損失 1,797,226／第 19 期期首 Σ=0。

## 5. テスト完了後の総合検算（sql CLI）

```sql
-- ① 全確定仕訳の貸借一致（期待値: 借方=貸方=11,852,675）
SELECT SUM(CASE WHEN dc='D' THEN jl.amount ELSE 0 END) AS 借方,
       SUM(CASE WHEN dc='C' THEN jl.amount ELSE 0 END) AS 貸方
FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
WHERE je.status='posted';

-- ② 伝票番号の重複ゼロ（期待値: 0）
SELECT COUNT(*) FROM (SELECT fiscal_year_id, journal_no, COUNT(*) c
FROM journal_entries GROUP BY fiscal_year_id, journal_no HAVING c > 1);

-- ③ 売掛金の元帳残高（期待値: 1,320,000。売掛残高一覧の残額合計と一致すること）
SELECT (SELECT SUM(CASE WHEN dc='D' THEN amount ELSE -amount END)
        FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
        JOIN accounts a ON a.id=jl.account_id
        WHERE a.code='1100' AND je.status='posted') AS 売掛金元帳残高;

-- ④ 第19期 期首残高の貸借一致（期待値: 0）
SELECT SUM(balance) FROM opening_balances
WHERE fiscal_year_id=(SELECT id FROM fiscal_years WHERE name='第19期');
```
