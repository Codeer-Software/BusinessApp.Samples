## A. 委託者情報（自社側）の入力検証（FBX-01）

画面上部の委託者・仕向銀行欄はデモ用既定値が自動セットされる。**1 項目ずつ壊して**「FBデータを生成」を押し、ガードの発火順と文言を確認する（確認後は元の値に戻す）。

### FBX-01: 委託者情報ガードの網羅
| # | 壊す項目 | 入れる値 | 期待されるエラートースト |
|---|---|---|---|
| 1 | 振込指定日 | 空 | 「振込指定日を入力してください」 |
| 2 | 委託者コード | 「12345」（5桁） | 「委託者コードは数字10桁で入力してください」 |
| 3 | 委託者コード | 「12345678AB」（英字混入） | 同上（数字判定 IsDigitsLen） |
| 4 | 仕向銀行コード | 「12」 | 「仕向銀行コードは数字4桁で入力してください」 |
| 5 | 仕向支店コード | 「1234」 | 「仕向支店コードは数字3桁で入力してください」 |
| 6 | 口座種別 | 未選択 | 「口座種別を選択してください」 |
| 7 | 口座番号 | 「123」 | 「口座番号は数字7桁で入力してください」 |
| 8 | 委託者名（カナ） | 「すたーらいと」（ひらがな） | 「委託者名に使用できない文字があります: す」 |

- **確認ポイント**: ガードは表の順（コードの検証順）に発火する——複数壊した場合は**最初の 1 件だけ**が表示される。使用可能文字は半角ｶﾅ大文字・英大文字・数字・記号 `()｢｣/-.\`（KanaError の許容表）。小文字英字・全角・半角ｶﾅ小書き（ｧｨｩ等）は不可で、**最初の不正文字がトーストに表示**される。
- **後片付け**: 画面をリロード（または各項目を既定値に戻す）。DB には何も残らない。

## B. 対象なし（FBX-02）

### FBX-02: 未払計上済みが 0 件のとき
- **目的**: 生成対象（status='accrued'）が無い場合の空振り動作。
- **前提**: accrued の請求書が 0 件（E2E 完走後 DB はこの状態。AL-7005 は「受領」なので対象外）。
- **操作手順**: 委託者欄は既定値のまま「FBデータを生成」。
- **期待される結果**: 結果ラベル「**対象がありません（未払計上済・未払いの仕入先請求書が 0 件）**」・警告トースト「対象がありません」。テキストエリアは空になる。
- **確認ポイント**: 「受領」の請求書は**対象に入らない**（帳簿に乗った確定債務＝accrued だけを振り込む統制。基本 3-4 の波及で AL-7005 が対象外だったことと同じ根拠）。

## C. 受取人（仕入先）口座の除外理由（FBX-03）【机上分岐・実行は任意】

- **目的**: データレコード生成時の**明細単位の除外**分岐を仕様として押さえる。除外はエラーで止まらず、**その明細だけスキップして理由を結果ラベルに列挙**する（最大 3 件表示＋「ほか」）。
- **注意**: この分岐を実際に動かすには accrued の請求書が必要＝**未払計上仕訳（帳簿影響）が発生する**。本流 DB では実行せず、机上確認またはバックアップ DB でのみ実行すること（未実測）。
- **除外理由の一覧（コード根拠: Generate_OnClick のデータレコード生成ループ）**:

| # | 条件 | 結果ラベルの除外文言 |
|---|---|---|
| 1 | 仕入先の PartnerBank 行が無い | 「{請求書番号}: 仕入先が見つかりません」 |
| 2 | 銀行4桁/支店3桁/口座7桁/種別のどれかが未登録・桁数不正 | 「{番号}: {仕入先名} の振込先口座情報が未登録または桁数不正（業務マスタ &gt; 取引先口座 で銀行4桁/支店3桁/口座7桁/種別を登録）」 |
| 3 | 受取人名（半角カナ）が未登録 | 「{番号}: {仕入先名} の受取人名（半角カナ）が未登録」 |
| 4 | 受取人名に使用不可文字 | 「{番号}: 受取人名に使用できない文字（{文字}）。半角ｶﾅ大文字・英大文字・数字で登録してください」 |
| 5 | 金額 ≤ 0 | 「{番号}: 金額が 0 円以下」 |

- **期待される結果**（除外がある場合）: 結果ラベル末尾に「／ 除外 n 件: …」。**生成できた明細が 1 件も無ければ**警告トースト「生成できる明細がありませんでした（除外理由を確認してください）」＋ヘッダ/トレーラ/エンドだけの 3 レコードが出力される（データレコード 0 件・トレーラ件数 0）。

## D. 様式（120桁・パディング）の仕様確認（FBX-04）【机上】

基本シナリオ 3-4 で「全レコード 120 桁・トレーラ整合 OK」は実測済み。分岐として押さえる仕様:

- **N 項目（数字）**: 右詰め・前ゼロ。桁あふれは**下位桁優先**で切り詰め（PadN）。
- **C 項目（カナ・文字）**: 左詰め・後スペース。桁あふれは**先頭から切り詰め**（PadC）——受取人名 30 桁超は末尾が落ちる。
- **銀行名・支店名はコード優先の空白運用**（多くのインターネットバンキングはコードから補完する）。
- **自己検証**: 生成のたびに全レコードの桁数を数え、120 桁でない行があれば「⚠ 様式検証 NG: … 行n=xxx桁」を表示する（半角のみ構成のため文字数=Shift-JIS バイト数、という前提もコードコメントに明記されている）。
- トレーラの件数・合計は**除外後のデータレコード**と常に整合する（count/total を同じループで加算）。
