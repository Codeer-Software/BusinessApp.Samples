# 01_経費精算 基本シナリオ（申請 → 承認 → 仕訳 → 精算）

> 改訂: 2026-07-19（ロール別フレーム再編 ADR-0028 に追随）／ **更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映: 申請は ExpenseStaff、承認は ExpenseApprover の「承認待ち」、精算処理は ExpenseAccounting の「精算処理待ち」、仕訳・帳票確認は Accounting（会計）。操作アカウント・金額・仕訳番号は不変）**
> **実務上の位置づけ**: 社員が立て替えた経費を会社が精算する業務。会計処理そのものは単純（費用／未払金 → 未払金／預金）だが、実務の本丸は**承認統制**にある——「誰がいくらまで承認できるか」（金額権限）、「交際費は相手先を記録し総務が見る」（税務・コンプライアンス）、「事前承認額を実費が超えたら再承認」（予算統制）。本章はこの統制がシステムでどう強制されるかを 5 つの申請（E-1〜E-5※）で網羅する。
>
> **更新: 2026-08-09 ADR-0048/0044 反映**: ①承認ルートを積み上げ方式に（3 万円以上は「部長のみ」から「**課長 → 部長**」の 2 段、20 万円以上・3 万円以上の交際費は「**課長 → 部長 → 総務**」の 3 段。ステップ 1-5／1-6）。②承認者は所属ノードからの **walk-up** で解決されるため、課長段は**自課の課長 1 名で単独**（ステップ 1-1〜1-3 を全面改訂。**OR 並列の実演は部長段＝ステップ 1-5 に移動**）。**金額・仕訳番号・勘定科目・帳簿スナップショットは不変**。
>
> 承認ルートは申請時に自動決定される（承認者は**入れ替わらず積み上がる**）: **3 万円未満 → 課長／3 万〜20 万 → 課長 → 部長／20 万以上 → 課長 → 部長 → 総務／交際費 → 金額によらず総務併載（3 万未満は 課長 → 総務、3 万以上は 課長 → 部長 → 総務）**（境界は承認ルート判定マスタ）。役職者は申請者の所属ノードから**親方向へ walk-up** して見つかった最寄りの該当役職者**全員**に回り、複数いる場合は**並列で回って 1 人の承認で先へ進む**（OR 承認）——この組織では**部（部長 田中宏・部長代理 渡辺剛の 2 名）で並列が起き、課長は各課 1 名なので単独**。詳細な分岐の期待値は同フォルダの `分岐_承認ルート.md`（EXP-R01〜R08）が正。
>
> 精算ステータスの一生: `下書き → 申請中 → 承認済 → 経理処理中 → 精算済 → 完了`。前半は承認フロー、後半（仕訳生成・支払）は経理の仕事。
>
> ※E-5（締め済み期間フォールバック）のみ決算の文脈で 08_決算 に配置。
>
> **使用ユーザー**（パスワード = 識別名）: kaihatsu1_ippan（開発1部 **第一課** 一般 小林美咲・申請者）／kaihatsu1_kacho1（開発1部 第一課長 山本由美・**申請者の自課の課長＝課長段の承認者**）／kaihatsu1_bucho（開発1部 部長 田中宏）・kaihatsu1_buchodairi（開発1部 部長代理 渡辺剛）＝**部長段の OR 並列**／soumu_kacho1（総務部 第一課長 石川真理・総務段の承認者）／soumu_bucho（総務部 部長 山田太郎・経理）。kaihatsu1_kacho2（開発1部 **第二課長** 中村拓也）は**回らないことの確認用**（隣の課の課長）。

### ステップ 1-5: 経費申請 E-3（備品 10 万円以上 → 固定資産の自動判定・課長 → 部長の 2 段・**部長段の並列 OR 承認**）

- **この業務の目的（実務解説）**: 10 万円以上の資産性支出は「消耗品費（費用）」ではなく「工具器具備品（資産）」に計上し、耐用年数にわたって減価償却する——これは税法の強制。現場の申請者にこの判断はできないので、**費目=備品×金額 ≥ 10 万でシステムが自動的に固定資産フラグを立てる**。金額 165,000 円は 3 万〜20 万の帯なので承認はテンプレート `経費_部長まで` ＝**課長 → 部長の 2 段**（ADR-0048。課長は金額にかかわらず自分の課の支出を把握する）。**開発1部には部長 田中宏と部長代理 渡辺剛の 2 名がいるので、2 段目で並列 OR 承認を観察できる**（本章で OR を見せる唯一の箇所）。
- **操作する画面**: （kaihatsu1_ippan）サイドバー「申請」> 新規作成 →（kaihatsu1_kacho1 → kaihatsu1_buchodairi 確認 → kaihatsu1_bucho・ExpenseApprover の「承認待ち」）承認
- **具体的な操作手順**:
  1. kaihatsu1_ippan で新規作成。件名「開発用ワークステーション」・費目「**備品**」・金額（税込）「165,000」・利用日「2026-07-14」・利用先「オリオン事務機 通販」を入力。
  2. 金額入力の時点で情報トースト「**金額 165,000 円 ≧ 少額基準 100,000 円のため固定資産計上対象にしました（承認後に固定資産台帳へ登録されます）**」が出て、「固定資産計上対象」チェックが自動 ON になることを確認 → 「申請」。
  3. フローが「▶開発1部 第一課長 山本由美 →（開発1部 部長 田中宏, 開発1部 部長代理 渡辺剛）」の **2 段**になることを確認（1 段目=課長・単独／2 段目=部長 2 名の並列）。この時点で部長には通知が**行かない**（順次到達）。
  4. kaihatsu1_kacho1 / kaihatsu1_kacho1 でログインし、承認待ちから開いて「承認」→ **この瞬間に部長 2 名へ承認依頼通知**が飛び、フローが「✓山本由美 →（▶田中宏, ▶渡辺剛）」に進む。
  5. （並列の確認）kaihatsu1_buchodairi / kaihatsu1_buchodairi でログイン → **部長代理 渡辺剛の「承認待ち」にも同じ申請が 1 行見える**（同一段の 2 名に同時に依頼が飛んでいる）。ここでは承認せずログアウトする。
  6. kaihatsu1_bucho / kaihatsu1_bucho でログインし、承認待ちから開いて「承認」。
  7. （OR 完了の確認）再度 kaihatsu1_buchodairi でログイン → **渡辺剛の承認待ちが 0 件**になっている（1 人の承認で段が完了し、残りはスキップ）。
- **期待される結果**:
  - **直接的な結果**: 状態「承認済」。フロー表示は「✓山本由美 →（✓開発1部 部長 田中宏, **—開発1部 部長代理 渡辺剛**）」（✓=承認済・—=スキップ）。承認履歴に「申請 → 承認（山本由美）→ 承認（田中宏）」の 2 段が残る。
  - **OR 承認の意味**: 同一段に同格が複数いる場合は**誰か 1 人の承認で段が完了**し、残りは自動的にスキップされて受信箱から消える——二重承認や「もう 1 人待ち」の停滞を防ぐ設計（部長代理側で承認するケースは `分岐_承認ルート.md` の EXP-R08）。
  - **波及する結果**: 仕訳生成時（1-7）に借方科目が費目の既定（消耗品費）ではなく**工具器具備品（資産）**に切り替わり、固定資産台帳へ自動登録される。閾値（10 万）は制度閾値マスタ `SMALL_ASSET_EXPENSE` を参照しており、税制改正時はマスタ変更だけで挙動が変わる。

### ステップ 1-6: 経費申請 E-4（事前申請 → 実費が見込みを超過 → 自動再承認）

- **この業務の目的（実務解説）**: 出張などは「事前に見込み額で承認を取り、事後に実費を確定する」のが実務。実費が見込みを大きく超えた場合（本アプリでは**承認ルート区分をまたぐ、または見込み×110% 超**）は自動で再承認に回る——事前承認を形骸化させないための統制。
- **操作する画面**: （kaihatsu1_ippan）サイドバー「申請」（経費一覧） →（kaihatsu1_kacho1 → kaihatsu1_bucho）承認
- **具体的な操作手順**:
  1. kaihatsu1_ippan で新規作成。申請区分を「**事前申請（これから支払う）**」に変更 → **「見込み額」欄が出現**する（立替では非表示）。
