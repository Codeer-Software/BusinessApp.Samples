# 分岐シナリオ: 例外系チェックリスト（ブロック・差戻し・編集ロック）

> 改訂: 2026-07-10 新規作成 ／ **更新: 2026-08-17 明細行化を反映（ADR-0066）** — 入力が明細行へ移り、**行単位の検証はメッセージに行番号が付く**。「明細が 1 行も無い」という門が増え、必須の門の並びが変わった（下表 X01-1〜X01-6）。編集ロックは**ヘッダと明細の両方**にかかる。
> 2026-08-09 現行化（ADR-0042〜0048） — 導線を「ポータル → サイドバー」方式に、承認者を **walk-up 前提**（自課の課長・単独／部長段は OR 並列）に改めた。**EXP-X04-2 は手順と期待値が変わるため本文で再定義**（「受信箱の宛先限定」を walk-up の帰結として確認する形にした）。
> **本流の帳簿への影響: なし**。
> 例外系の多くは基本シナリオの中で既に実施している。本ファイルは「経費精算の防御動作を網羅確認するチェックリスト」として、実施場所への参照と、基本シナリオでカバーされない残りの確認（EXP-X04）をまとめる。
> 配役: 申請者 = kaihatsu1_ippan（開発1部 **第一課** 一般 小林美咲）。**自課の課長 = 第一課長 山本由美（kaihatsu1_kacho1）**。パスワード = 識別名。
> **さらに更新: 2026-08-17 夜 ADR-0066 の UI 改訂（4 ブロック構成）**——申請画面が 「（見出し無しの申請ヘッダ）／レシート 1 枚ぶんを入力（1 件ぶんの入力欄＋「この内容で明細に追加」）／この申請の明細（一覧＋合計）／承認」の 4 つのカードに分かれた。**明細はグリッドに行を足すのではなく、入力欄で 1 件ぶん埋めて「追加」で積む**。AI 読み取りと領収書は入力欄（＝その明細）が持つので、1 回のアップロードで抽出値とファイルが同じ明細に載る。既存の明細を直すときは**リストの行をクリックして入力欄に読み込み**、「この明細を更新」を押す。**金額・仕訳・承認ルートの期待値は一切変わらない**（入力の道筋だけが変わった）。

## EXP-X04-1: 未入力ブロックの複合確認

- **操作手順**（kaihatsu1_ippan でログイン → 業務ポータルに着地 → サイドバー「**経費精算**」→ ExpenseStaff の「**申請**」に着地 → 新規作成）:
  1. **何も入力せず**「申請」→ 「**入力内容を確認してください**」（ヘッダの必須＝件名が赤くなる。CLB の入力検証）。
  2. 件名だけ入れて「申請」→ 「**明細を 1 件以上追加してください（レシート 1 枚が 1 件です）**」。
  3. 入力欄を空のまま「**この内容で明細に追加**」→ 「**金額（税込）を入力してください**」。
     （入力欄に何か書いたまま「申請」を押すと「**入力欄に、明細に追加していない内容が残っています…**」で止まる）
  4. 行の金額に 5,000 を入れて「申請」→ 「**1 行目: 利用日を入力してください**」。
  5. 行の利用日を入れて「申請」→ 「**1 行目: 費目を選択してください**」。
  6. 行の費目に 消耗品費 を選んで「申請」→ 今度は成立する。フローは `経費_課長まで` ＝「▶開発1部 第一課長 山本由美」の 1 段。
- **期待される結果**: エラーのたびに**下書きのまま**残り（フローは開始されない）、承認者に通知は飛ばない。成立した申請は次の X04-2 に使う。
- **確認ポイント（2026-08-17）**: 手順 3〜5 のメッセージには**行番号が付く**。明細を 2 行にして 2 行目だけ空にすると
  「**2 行目**: …」になることも見ておくとよい（どの行を直せばいいかが分かる設計）。
- **旧版との差**: 旧文は「何も入力せず申請 → 金額系のブロック」だった。件名の必須化（ADR-0051）と
  明細行化（ADR-0066）で門が増え、**ヘッダの必須 → 支払先 → 明細ゼロ → 行ごと**の順に並んだ。

## EXP-X04-2: 申請後の編集ロックと受信箱の宛先限定（**2026-08-09 改訂**）

- **この分岐の意味**: 「編集ロック」「操作ボタンの本人限定」に加えて、**承認待ち（受信箱）に出るのは自分が現在の承認担当である案件だけ**であることを確認する。承認者は walk-up（ADR-0044）で**申請者の所属ノードから最寄りの該当役職者**に解決されるため、**同じ部の隣の課の課長にも回らない**——旧版の「無関係の部の承認者には出ない」より一段細かい境界になった。
- **操作手順**:
  1. X04-1 で成立させた申請（進行中）を kaihatsu1_ippan で開く → **ヘッダも明細も全入力欄が編集不可**（申請内容の事後改ざん防止）で、明細の「**追加**」ボタンも消えていることを確認。「キャンセル」ボタンは見える（本人のため）。
     - **例外（ADR-0066）**: 事前申請が「承認済・実費未確定」のときだけ**明細だけが編集可能**になる（実費を入れるため）。立替精算では起こらない。
  2. **kaihatsu1_kacho2**（開発1部 **第二課長** 中村拓也）でログイン → サイドバー「経費精算」→ ExpenseApprover の「**承認待ち**」に着地 → **この申請は出ない**。同じ開発1部の課長でも、**第一課の申請は第一課長で解決済み**だから（walk-up は最寄りのノードだけを見る）。
  3. **eigyo_kacho1**（営業部 第一課長 高橋恵子・無関係の部の承認者）でログイン → 「承認待ち」に**やはり出ない**。
  4. **kaihatsu1_bucho**（開発1部 部長 田中宏）でログイン → 「承認待ち」に**出ない**。テンプレートが `経費_課長まで`（1 段）で部長段が積まれていないため（30,000 以上なら課長承認後に回ってくる——ADR-0048 の積み上げ）。
  5. **kaihatsu1_kacho1**（第一課長 山本由美・**唯一の正しい宛先**）でログイン → 「承認待ち」に **1 件出る**。開くと内容は閲覧のみで、「承認/却下」は押せるが「**キャンセル」「再申請」ボタンは出ない**（申請者専用）。ここでは承認しない。
  6. kaihatsu1_ippan に戻り「キャンセル」→ 下書き → 詳細の赤ボタン「この下書きを削除」で削除。手順 5 の山本由美の受信箱から**消えている**ことも確認する。
- **期待される結果**: ①編集ロック ②操作ボタンの本人限定 ③**受信箱の宛先限定（自課の課長ただ 1 人）**、の 3 点が確認できる。②③は「見えないだけ」ではなく、承認操作もサーバ側で現在の承認担当かを再チェックしている。
