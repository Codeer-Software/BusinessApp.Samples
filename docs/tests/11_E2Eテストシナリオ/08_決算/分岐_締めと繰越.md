## A. 締めの統制（CLS-01〜02）

### CLS-01: 下書き残存警告は「警告のみ・ブロックしない」（参照＋仕様確認）

- 基本 8-1 で実施済み。仕様の要点を再確認する:
  - 警告は期間の状態を「締め済み」へ**変更した瞬間**にトースト表示される（保存前）。件数付き「この期間には下書きの伝票が n 件残っています。…（保存すると締めは実行されます）」。
  - **ブロックはしない**——警告を無視して「登録」すれば締めは実行される（締め判断は経理の裁量、システムは情報提供に徹する設計）。
  - 下書きは締め後も削除できる（draft は帳簿外のため締めガードの対象外。コード根拠: 警告は draft の存在チェックのみで、締め自体は Status 保存）。

### CLS-02: 締め解除 → 起票可能に戻る → 締め直し（凍結の可逆性）

- **操作手順**:
  1. 【設定】会計年度 > 第18期 → 年度の状態を「**進行中**」に戻し、月次 4（2026-07）も「進行中」に戻して「登録」。
  2. 【仕訳】振替伝票 > 新規作成: 取引日 2026-07-15・適当な明細 1 行 → 「確定」を**押す直前まで**入力し、締めエラーが出ないこと（＝起票可能に戻った）を日付欄のエラー無しで確認したら、**保存せず破棄**（戻るボタン）。
  3. **後片付け**: 月次 4 を「締め済み」に戻し、年度の状態も「締め済み」に戻して「登録」。
- **期待される結果**: 締め＝凍結であり、経理はいつでも解除・再凍結できる（削除や不可逆処理ではない）。監査上は「いつ誰が解除したか」を運用記録で補う。
- **確認ポイント**: 手順 2 で誤って「確定」まで押すと仕訳 No.42 が生まれ完成状態が崩れる。**必ず破棄**すること。

## B. 償却のガード網羅（CLS-03〜06）

### CLS-03: ガード①③ —— 締め済み年度ブロックと二重生成ブロック

- **操作手順**:
  1. 【帳簿】固定資産台帳 > EXP-3 を開き、対象年度「第18期」で「この年度の償却仕訳を生成」→ 「**対象年度は締め済みです**」（ガード①。基本 8-10 の再確認）。
  2. 【設定】会計年度 > 第18期 の状態を一時「進行中」へ（月次期間はそのまま=全部締め済み）→ 固定資産台帳で再度生成 → 「**期末月の期間は締め済みです。期間を再オープンしてから生成してください**」（ガード②が次に当たる）。
  3. さらに月次 12（2027-03）も一時「進行中」へ → 再度生成 → 「**この年度の償却仕訳は既に生成済みです**」（ガード③。No.38 があるため。**仕訳は作られない**）。
  4. **後片付け**: 月次 12 → 締め済み、年度 → 締め済み に戻して「登録」。
- **期待される結果**: ガードが README の表の順序どおりに 1 つずつ現れる。どの段階でも仕訳は増えない（仕訳帳の最終番号 41 のまま）。

### CLS-04: ガード④ —— 耐用年数未設定なら償却額ゼロ（仕訳を作らずに実測できる）

- **この分岐の意味**: 定額法で耐用年数が空（または 0）のとき、エラーではなく「償却額なし」の情報トーストになる（`life <= 0 → 0`）。第19期は open なのでガード①〜③を素通りし、④だけを安全に観測できる。
- **操作手順**:
  1. 【帳簿】固定資産台帳 > EXP-3 → **耐用年数を空にして**「登録」。
  2. 対象年度「**第19期**」を選び「この年度の償却仕訳を生成」。
  3. **後片付け**: 耐用年数を「4」に戻して「登録」。
- **期待される結果**: 情報トースト「**この年度の償却額はありません（対象外または償却済み）**」。**仕訳は作られない**（第19期の仕訳はゼロのまま——これが重要）。
- **確認ポイント**: 耐用年数を戻し忘れると次回の償却が動かない。後片付け必須。

### CLS-05: 月割の計算式 —— 取得年度 9 ヶ月・2 年目から満額（機上検算）

- **この分岐の意味**: No.38 の 28,125 円がどう出たかを式で確認する（実生成はしない——第19期に仕訳を作ると完成状態が崩れる）。
- **機上検算**（コード根拠: `CalcDepreciationForYear` straight_line）:
  - 年額 = 150,000 ÷ 4 = 37,500。
  - 第18期（取得年度・7 月取得）: 37,500 × 9 ÷ 12 = **28,125**（月数 = 12 −（7−4）= 9。4 月起点の月割）。
  - 第19期〜第21期: 満額 **37,500**／年。
  - 第22期: 残存簿価 1 円を残して調整 = 150,000 − 1 − (28,125 + 37,500×3) = **9,374**（未実測——翌年度以降の実生成は次の年度サイクルで検証）。
  - 検算: 28,125 + 37,500×3 + 9,374 + 1（残存） = 150,000 ✓
- **期待される結果**: 台帳の取得価額・耐用年数から将来の償却スケジュールが手計算で追える（＝ブラックボックスでない）。

### CLS-06: 一括償却資産（3 年均等）の判定ヒント（読み取りのみ）

- **操作手順**: EXP-3 を開き、少額判定欄を確認する。
- **期待される結果**: 「取得価額 150,000 円 < 200,000 円: 一括償却資産（3年均等）を選択できます」——閾値マスタ（LUMP_SUM_ASSET）を取得日で期間解決した提案。償却方法セレクトを「一括償却（3年均等）」に**変えれば** 3 年均等（50,000/50,000/50,000）になるが、本書では定額法のまま**変更しない**（変更すると次回償却額が変わる）。
- **補足**: 10 万未満なら「全額損金」、中小特例（SME_IMMEDIATE=30 万）なら「即時償却可」のヒントに変わる（金額を書き換えれば表示が変わるが、保存はしないこと）。

## C. 繰越の統制（CLS-07〜09）

### CLS-07: 繰越の冪等性 —— 再実行しても同じ期首残高（洗い替えの実証）

- **この分岐の意味**: 繰越は「DELETE→INSERT の洗い替え」（CarryOverSql）。繰越後に第18期の仕訳を直した場合も再実行すれば期首が作り直される。完成状態で再実行しても**同一の 14 行**になるため、安全に実測できる。
- **操作手順**:
  1. 【設定】会計年度 > 第18期 → 「翌期繰越を実行」→ 確認ダイアログ「実行」。
  2. トースト「第19期 への繰越が完了しました」→ 第19期を開き、期首残高が **14 行・期首残高合計 = 0** のままであることを確認（基本 8-9 の表と同一値）。
- **期待される結果**: 何度実行しても結果が変わらない（冪等）。**年度がクローズ済みでも繰越は実行できる**——締め（凍結）が縛るのは起票であり、繰越の再計算は許す設計（コード根拠: CarryOver_OnClick に closed チェックなし）。
- **確認ポイント**: sql CLI で `SELECT COUNT(*), SUM(balance) FROM opening_balances WHERE fiscal_year_id=3` → 14・0。

### CLS-08: 繰越先が無い → 中止（＋月次期間の再生成ガード）

- **操作手順**:
  1. 【設定】会計年度 > **第19期** → 「翌期繰越を実行」。
  2. → 赤トースト「**翌期の会計年度がありません。先に翌期を作成してください**」（第20期が無いため。何も起きない）。
  3. ついでに同画面で「12ヶ月の月次期間を生成」→ メッセージ「**月次期間は既に存在します。生成し直す場合は既存の行を削除してから実行してください。**」（再生成ガード。基本 8-8 の対）。
- **期待される結果**: どちらも安全に中止され、第19期のデータは無変化。

### CLS-09: 空年度からの繰越ガード —— 移行初年度の事故防止

- **この分岐の意味**: 期首残高も確定仕訳も無い年度から繰越を実行すると、翌期の期首残高（移行時の開始残高など）を**空データで洗い替えて破壊**する——総合テストで実測された事故パターンを防ぐガードの確認。
- **操作手順**:
  1. 【設定】会計年度 > 新規作成: 年度名「第20期」・期首日「2028-04-01」→ 「12ヶ月の月次期間を生成」→ 「登録」。続けて「第21期」（期首 2029-04-01）も同様に作成（繰越先が要るため）。
  2. **第20期**（期首残高なし・仕訳なし）を開き「翌期繰越を実行」。
  3. → 赤トースト「**この年度には期首残高も確定仕訳もありません。繰越を実行すると翌期の期首残高が失われるため中止しました**」（確認ダイアログの前に中止される）。
  4. **後片付け**: 会計年度一覧から第21期・第20期を削除（月次期間は年度と一緒に消える。第19期の期首残高が 14 行のまま無事であることを確認）。
- **期待される結果**: ガードにより第21期側は何も作られない。テスト用年度の削除で一覧が第17〜19期の 3 件に戻る。

## D. 期首残高の検算表示（CLS-10）

### CLS-10: 期首残高の Σ≠0 は赤字表示（保存しない）

- **操作手順**:
  1. 【設定】会計年度 > 第19期 → 期首残高のいずれかの行の金額を一時的に +1 する（例: 現金 74,700 → 74,701）。
  2. 「期首残高合計」が **1** になり**赤色表示**に変わることを確認（Σ=0 のときは無色）。
  3. **保存せずに**値を 74,700 に戻す（または画面を破棄して開き直す）→ 合計 0・無色に戻る。
- **期待される結果**: 貸借の崩れがリアルタイムに可視化される（コード根拠: `UpdateOpeningTotal` が合計≠0 で赤 #dc3545）。保存時の強制ブロックの有無は（未実測）——本書の運用では「赤のまま保存しない」を規律とする。
- **確認ポイント**: 誤って保存した場合は CLS-07 の繰越再実行（洗い替え）で正しい期首に復元できる——冪等性が事故復旧にも効く。
