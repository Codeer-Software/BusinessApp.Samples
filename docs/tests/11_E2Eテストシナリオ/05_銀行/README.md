## 本章の導線（現行・ADR-0042/0045）

- ログインすると**全員が業務ポータル**（Main/PortalHome）に着地する。旧「トップ画面」（`/{フレーム}/Top`）と「ほかの業務」リンクは全廃。
- ポータル左サイドバーの「**会計業務**」で会計フレームへ移動する（フレーム素 URL `/Accounting` は既定業務画面＝**振替伝票**に着地）。銀行の 5 画面はサイドバーの「**銀行**」グループ（明細取込・一括起票・明細一覧・残高照合・仕訳ルール）にまとまっており、本書の【銀行】表記はこれを指す。先頭の「ホーム」でポータルへ戻れる。
- アクセス条件は**経理機能フラグ**（`app_users` の直接付与・ADR-0043）。admin（システム管理者）は業務フラグを持たないため会計フレームに入れない。
- 未起票の明細は**ポータルの「経理の作業キュー」**に「**▶ 未起票の銀行明細: N 件**」として出る（クリックで明細一覧へ）。**0 件のときは行ごと消える**——「0 件と表示される」ではなく「行が無い」が正。

## 3 画面の役割分担（v3）

```
【明細取込】  CSV → bank_statement_preview（未登録・原本6列のみ編集可）
              --この内容で登録（ルール適用）--> bank_statement_lines (pending)
【一括起票】  pending だけの作業台: 候補の確認・手修正 / ルール再適用 / AI 推定（すべて保存まで画面上のみ）
              対象外チェック＋保存 --> excluded ／ 候補科目で一括起票 --> journalized（仕訳生成・リンク）
【明細一覧】  全状態の通帳ビュー（表示専用）。詳細画面で単発の例外操作（即 DB 反映・確認ダイアログ付き）:
              pending: 対象外にする／削除　excluded: 未起票に戻す／削除　journalized: 起票を取り消す（仕訳ごと削除）
```

## パイプラインの防御の正（コード: BankImport / BankPosting / BankStatementLine の各 .mod.cs）

- **スキップ行**（badLines）: 列 < 2／日付でない（ヘッダ行含む）／出金・入金とも 0 以下／存在しない日付（2/30 等）。
- **重複キー** = `日付|摘要|出金|入金|同一内容連番`。**残高は含まない**。同一貼り付け内の同一内容は連番で一意化（同じ引き落とし 2 件は両方入る）。照合は**本番・プレビュー両テーブル横断**。
- **プレビューの編集・行削除**は「プレビューの変更を保存」（または登録の暗黙保存）まで**メモリのみ**。保存はスナップショット差分同期（削除行の DELETE＋編集の反映＋キー再計算）。
- **ルール適用**は「この内容で登録」時（＋一括起票の「ルールを適用」ボタン）に、優先度昇順で**最初に一致した 1 件**。方向（入金のみ/出金のみ/両方）でフィルタ。**AI・ルールの結果は保存/起票まで DB に書かれない**。
- **AI 推定**の対象 = pending かつ候補未設定のみ。**一括起票**の対象 = pending かつ候補設定済みのみ。推定元は rule / ai / manual の 3 値。
- 一括起票のスキップ/失敗の分類: 年度なし・期間なし・締め済み → 「締め済み等スキップ」／口座の帳簿科目なし・相手科目なし・金額 0 → 「失敗」。
- **起票の取り消し**（journalized→pending）は紐づく仕訳を**明細行→親の順に削除**して戻す。締め済み期間は拒否（赤伝誘導）。起票済の明細は**直接削除不可**（先に起票取消）。
- **残高照合**は本番テーブルのみを日次突合（プレビューは対象外）。判定は「明細残高 = 帳簿残高」のみで決まり、pending の有無は「未起票（累計）」列の**参考情報**（判定は変えない）。明細に残高列が無い日は「－ 明細残高なし」。

## 後片付けの原則（重要）

分岐で取り込む明細のうち起票まで進めるのは BNK-09（起票取消で往復し帳簿を元に戻す）だけ。プレビューは「全てのプレビューを取り消す」、pending / excluded は【明細一覧】の**詳細画面**の「この明細を削除」で物理削除して片付ける（一覧に削除ボタンは無い）。削除すると残高照合の該当日付行も消え、全○の状態に戻る。

## 前提（E2E 完走後の DB で実行する場合）

- 既存明細は 7/1×2（対象外）・7/15・7/21・7/24（起票済）の 5 行で、残高照合は**全日付 ○ 一致**。分岐で追加する明細は **7/25 以降または締め済み月**の日付を使い、既存の照合行を乱さない。
- 起票ブロック系（BNK-07）は締め済み期間を利用するため、**全期間締め済みの現 DB はそのまま好都合**。BNK-09（起票→取消の往復）は**開いている月**が必要。
