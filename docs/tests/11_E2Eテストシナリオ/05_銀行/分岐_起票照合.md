## A. 仕訳ルールの方向と優先度（BNK-05）

### BNK-05: 方向フィルタ（入金/出金/両方）と優先度勝ち
- **目的**: ルールは「優先度昇順で最初に一致した 1 件だけ」適用され、方向（direction）が合わない行には当たらないことを確認する。v3 ではルール適用は**登録時**（＋一括起票画面の「ルールを適用」ボタン）。
- **操作手順**:
  1. 【銀行】仕訳ルール で 3 本登録する:
     - 「BNK-05a」優先度 **5**・キーワード「ﾃｽﾄｹｲﾋ」・適用方向「**入金のみ**」・相手科目「雑収入」・有効 ○
     - 「BNK-05b」優先度 **10**・キーワード「ﾃｽﾄｹｲﾋ」・適用方向「**出金のみ**」・相手科目「消耗品費」・有効 ○
     - 「BNK-05c」優先度 **20**・キーワード「ﾃｽﾄｹｲﾋ」・適用方向「入出金両方」・相手科目「雑費」・有効 ○
  2. 【銀行】明細取込 で以下を貼り付けて「明細を取り込む」→ プレビューには**候補列が無い**ことを確認 → 「この内容で登録」:
     ```
     2026/07/30,BNK-05 ﾃｽﾄｹｲﾋ ｼﾊﾗｲ,3300,,
     2026/07/30,BNK-05 ﾃｽﾄｹｲﾋ ﾆｭｳｷﾝ,,3300,
     ```
  3. 【銀行】一括起票 を開く。
- **期待される結果**: 登録の結果ラベルが「2 件を未起票の明細として登録しました（**ルール適用 2 件** / …）」。一括起票の一覧で:
  - 出金行の候補 = 「**消耗品費**」（優先度 5 の a は入金のみなのでスキップされ、10 の b が最初の一致。20 の c までは到達しない）
  - 入金行の候補 = 「**雑収入**」（優先度 5 の a が最初の一致）
  - 両行とも推定元 = 「rule」
- **確認ポイント**: 優先度は「小さいほど先に評価」。同一摘要に複数ルールが当たるときの制御手段が優先度そのもの（基本 5-7 の波及の実証版）。
- **後片付け**: 明細一覧で BNK-05 の 2 行を詳細画面から削除 → 仕訳ルールから BNK-05a〜c を削除（残すと今後の取込に影響する）。

## B. 一括起票のガード（BNK-06〜07）

### BNK-06: 起票対象の絞りと確認ダイアログのキャンセル
- **目的**: 一括起票の対象は「pending かつ**候補設定済み**」だけ。候補なしは対象外、ダイアログでキャンセルすれば何も起きない。
- **操作手順**:
  1. 候補が付かない明細を 1 行取り込んで登録する（ルールに当たらない摘要）:
     ```
     2026/07/30,BNK-06 ｺｳﾎﾅｼ,1100,,
     ```
  2. 【一括起票】で「候補科目で一括起票」を押す。
  3. 明細の相手科目（候補）を手動で「消耗品費」に選び「変更を保存」→ もう一度「候補科目で一括起票」→ ダイアログで「**キャンセル**」。
- **期待される結果**:
  - 手順 2: 情報トースト「**起票対象（相手科目候補が設定済みの未起票明細）がありません**」——ダイアログすら出ない。
  - 手順 3: 確認ダイアログ「1 件の明細を仕訳として一括起票します。よろしいですか？」→ キャンセルで**仕訳 0 件・明細は pending のまま**。
- **確認ポイント**: 手動選択すると推定元は「**manual**」になる（v3 で追加。rule/ai/manual の 3 値で由来を監査できる）。候補はドロップダウンでいつでも変更できる。
- **後片付け**: BNK-06 行は次の BNK-07 に**使い回さず**、明細一覧の詳細から削除する（日付が進行中の月だと起票できてしまい事故のもと）。

### BNK-07: 締め済み期間・年度外の明細は起票がスキップされる
- **目的**: PostAll の日付ガード——締め済み月・年度の存在しない日付の明細は「締め済み等スキップ」に分類され、**仕訳が 1 件も作られない**ことを確認する。
- **前提**: 2026-06 が締め済みであること（E2E 完走後 DB は全期間締め済みなのでそのまま可。まっさら DB では 08_決算 8-1 の後に実行）。
- **操作手順**:
  1. 締め済み月と年度外の 2 行を取り込んで登録:
     ```
     2026/06/30,BNK-07 ｼﾒｽﾞﾐﾂｷ,1100,,
     2024/06/30,BNK-07 ﾈﾝﾄﾞｶﾞｲ,1100,,
     ```
  2. 【一括起票】で両行の相手科目（候補）に「消耗品費」を選び「変更を保存」。
  3. 「候補科目で一括起票」→ ダイアログ「2 件の明細を…」→「起票する」。
- **期待される結果**: 結果ラベル「**一括起票: 0 件起票 / 締め済み等スキップ 2 件 / 失敗 0 件**」・警告トースト「起票できた明細がありませんでした」。仕訳帳は無変化・両明細は **pending のまま**（起票済みにならない＝締めが解除されれば後日起票できる）。
- **確認ポイント**: 「スキップ」（締め・年度なし）と「失敗」（口座の帳簿科目なし・相手科目なし・金額 0）は結果ラベルで区別される。年度外（2024）は年度検索が空振りして同じスキップ側に落ちる（コード根拠: fy==null → skippedClosed）。
- **後片付け**: 明細一覧で「BNK-07」2 行を詳細画面から削除。

## C. 明細一覧・詳細画面の例外操作（BNK-09・v3 新設）

### BNK-09: 状態遷移の一巡（対象外⇄差し戻し・起票の取り消し・削除）
- **目的**: v3 で新設された詳細画面の 4 操作を一巡する。特に「**起票を取り消す**」が紐づく仕訳を**明細行→親の順に完全削除**して未起票に戻すこと（B-7/B-8 の恒久対策）を確認する。
- **前提**: 起票する月が**締め済みでない**こと（進行中の月の日付を使う）。
- **操作手順**:
  1. 1 行取り込んで登録し、【一括起票】で候補「消耗品費」を選んで保存 → 「候補科目で一括起票」→「起票する」:
     ```
     2026/07/30,BNK-09 ﾄﾘｹｼﾖｳ,1100,,
     ```
     結果ラベルの「（伝票 No.x）」を控える。
  2. 【明細一覧】で BNK-09 行（起票済・伝票No x）をクリック → 詳細画面。注記「起票済の明細です（仕訳 伝票 No.x）」とボタンが「**起票を取り消す**」だけであることを確認 → 押す → ダイアログ「**仕訳 伝票 No.x を削除して、この明細を未起票に戻します。よろしいですか？**」→「取り消す」。
  3. 状態が未起票に変わり、ボタンが「対象外にする」「この明細を削除」に切り替わる → 「対象外にする」→ 確認 → 状態: 対象外・ボタンが「未起票に戻す」「この明細を削除」に切り替わる。
  4. 「未起票に戻す」→ 確認 → 状態: 未起票。
  5. 「この明細を削除」→ ダイアログ「この明細を削除します。重複キーが解放されるため、同じ明細を再取込できるようになります。…」→「削除する」→ 明細一覧へ戻る。
- **期待される結果**:
  - 手順 2 の後: 仕訳帳から伝票 No.x が**消えている**（明細行ごと削除。孤児行なし）。明細の伝票No も空になる。
  - 手順 3〜4: 状態と表示ボタンが仕様どおり連動（pending: 対象外にする＋削除／excluded: 未起票に戻す＋削除／journalized: 起票を取り消すのみ）。
  - 手順 5 の後: 明細一覧から BNK-09 行が消える。帳簿・明細とも本テスト前と完全に同一。
- **確認ポイント**: 締め済み期間の仕訳に対する「起票を取り消す」は拒否され、赤伝（反対仕訳）に誘導される（`…の期間は締め済みのため起票を取り消せません（赤伝（反対仕訳）で対応してください）`）。起票済の明細は**削除できない**（先に起票取消が必要）——重複キー解放による二重仕訳の道を塞ぐ。

## D. 照合の未起票カウント（BNK-08・チェックリスト）

| # | 確認 | 実施場所 |
|---|---|---|
| BNK-08-1 | 対象外（excluded）は起票対象にならないが、**残高の突合には使われる** | 基本 5-3 |
