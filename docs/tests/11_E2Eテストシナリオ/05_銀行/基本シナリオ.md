# 05_銀行 基本シナリオ（明細取込・一括起票・残高照合）

> 改訂: 2026-07-21（**銀行 v3 再設計に全面追随**——ISSUE-0003。画面が「明細取込／一括起票／明細一覧」の 3 画面に分割され、プレビューは専用テーブル `bank_statement_preview` に分離された。金額・仕訳番号は不変）
> 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映——導線を会計（Accounting）ワークスペースの【銀行】グループに現行化。金額・仕訳番号は不変）
>
> **実務上の位置づけ**: 月次経理の要「銀行勘定合わせ」。ネットバンキングの入出金明細を帳簿に取り込み、**銀行残高＝帳簿残高**を日次で突合する。差異があれば「記帳漏れ」「二重計上」「銀行側の未達」のどれかであり、これを潰すことで帳簿の信頼性が担保される。
>
> 本アプリの流れ（v3・3 画面分業）:
> - **【明細取込】** ①CSV 貼り付け → **プレビュー**（未登録・通帳原本の 6 列だけ）→ ②目視確認・必要なら修正/行削除 → 「**この内容で登録**」で未起票の明細へ確定（このとき仕訳ルールが自動適用される）
> - **【一括起票】** ③記帳済みの明細は「**対象外**」チェックで除外 → ④ルール／AI が相手科目候補を埋め、経理が確認・手修正 → ⑤「**候補科目で一括起票**」（自動仕訳）
> - **【明細一覧】** 全状態の通帳ビューで監査。詳細画面から対象外化・差し戻し・**起票の取り消し**などの例外操作
> - **【残高照合】** ⑥全日付「○ 一致」を確認
>
> 取込はステージング方式なので、**取込しただけでは帳簿は汚れない**。プレビューは本番テーブルにすら入らず（専用テーブル）、起票して初めて仕訳になる。
>
> **保存規律（v3 の芯）**: DB を書くのは「保存」「登録」「起票」「取消系」のボタンだけ。プレビューの編集・行削除も、ルール／AI の候補も、**保存（または登録・起票の暗黙保存）までは画面上だけの変更**。
>
> **使用ユーザー**: soumu_bucho（総務部 部長 山田太郎・経理＝経理種別部門のメンバー）。銀行機能は**会計（Accounting）ワークスペース**（`/Accounting/Top`）のサイドバー【銀行】グループ（明細取込・一括起票・明細一覧・残高照合・仕訳ルール。経理のみアクセス可）。

### ステップ 5-1: 明細 CSV の貼り付け取込（プレビュー）

- **この業務の目的（実務解説）**: 銀行サイトからダウンロードした CSV をそのまま貼り付ける。この時点では**プレビュー（未登録）**——通帳どおり取り込めているかを目視確認してから確定する 2 段階方式で、誤貼り付けをワンクッションで防ぐ。
- **操作する画面**: 【銀行】明細取込
- **具体的な操作手順**:
  1. 「【銀行】明細取込」を開く。取込先口座は「メインバンク 普通預金」が**自動で初期選択**されている（有効な口座が 1 件だけのため。複数口座の環境では手動選択）。
  2. 明細 CSV 欄に以下を貼り付ける（形式: 日付,摘要,出金額,入金額,残高。1 行目のヘッダは自動スキップされる）:
     ```
     日付,摘要,出金額,入金額,残高
     2026/07/01,ﾔﾁﾝ ｽﾀｰﾗｲﾄﾋﾞﾙ,165000,,4835000
     2026/07/01,ｿﾝｶﾞｲﾎｹﾝ ﾈﾝﾊﾞﾗｲ,66000,,4769000
     2026/07/15,AWS ｸﾗｳﾄﾞﾘﾖｳｷﾝ,55000,,4684000
     2026/07/21,振込手数料,550,,4683450
     2026/07/24,ｻｰﾊﾞｰﾎｽﾃｨﾝｸﾞ ﾍﾞｶﾞｿﾌﾄ,33000,,4650450
     ```
  3. 「明細を取り込む」を押す。
  - **補足**: この CSV には 7/25（給与・各種支払の日）の明細行を意図的に含めていない。残高照合は「明細が存在する日付」だけを突合するため、含める場合はその日の**全**入出金行（給与 2,550,000・外注支払 550,000・経費支払 4 件）を漏れなく列挙しないと残高が合わなくなる——月次の実務では銀行 CSV に全行が入っているので自然に満たされる条件だが、本書ではテストを簡潔にするため 4 日付に絞っている。
- **期待される結果**:
  - **直接的な結果**: 結果ラベル「**プレビュー 5 件 / 重複スキップ 0 件 / スキップ行（ヘッダ・明細以外） 1 行 — 内容を確認して「この内容で登録」を押してください**」（スキップ行 1 = ヘッダ行）。「プレビュー（未登録）」の表に 5 行が並ぶ。
  - **波及する結果**:
    - プレビュー表は**通帳原本の 6 列だけ**（口座・日付・摘要・出金・入金・残高）。相手科目の列は無い——科目付けは登録後の【一括起票】の仕事（v3 で役割分担を分離）。各列は**この場でのみ修正でき**、行末のゴミ箱ボタンで行削除もできる（どちらも「プレビューの変更を保存」までは画面上だけの変更）。
    - **帳簿は無変化**。プレビューは専用テーブル `bank_statement_preview` に隔離されており、本番の明細一覧・残高照合には**そもそも現れない**。

### ステップ 5-2: プレビューの取消 → 再取込 → 登録（＋重複スキップの確認）

- **この業務の目的（実務解説）**: 「貼り間違えた」時のやり直しと、確定操作。取消はプレビューを物理削除して**重複キーも解放する**ので、同じ CSV を貼り直せる。登録後に同じ CSV を再度取り込もうとすると重複スキップされる——月末に同じファイルを 2 回取り込んでも明細が二重にならない仕組み。
- **操作する画面**: 【銀行】明細取込
- **具体的な操作手順**:
  1. 「**全てのプレビューを取り消す**」を押す → 確認ダイアログ「プレビュー 5 件をすべて取り消します（重複キーが解放され、同じ CSV を貼り直せます）。よろしいですか？」→「取り消す」→ 「プレビュー 5 件を取り消しました」。プレビュー表が空になる。
  2. もう一度同じ CSV を貼り付けて「明細を取り込む」→ 再びプレビュー 5 件（取消で重複キーが解放された証拠）。
  3. 「この内容で登録」を押す → 「**5 件の明細を登録しました**」。結果ラベル「5 件を未起票の明細として登録しました（**ルール適用 2 件** / 重複スキップ 0 件）。科目の確定と起票は「一括起票」で行います」。プレビュー表が空になる。
  4. 【重複確認】同じ CSV をもう一度貼り付けて「明細を取り込む」→ 「プレビュー 0 件（重複スキップ 5 件 / スキップ行（ヘッダ・明細以外） 1 行）」と警告トースト。**登録済みの明細は二重取込されない**（重複キーはプレビューと本番の両テーブルを横断して照合される）。
- **期待される結果**: 上記のとおり。未起票の明細 5 件が確定。**ルール適用は登録の瞬間に走る**（AWS→通信費、振込手数料→支払手数料。プレビュー時点では走らない）。帳簿はまだ無変化。

### ステップ 5-3: 記帳済み明細を「対象外」にする

- **この業務の目的（実務解説）**: 7/1 の家賃（No.17）と保険料（No.19）は 04_会計コアで**既に仕訳済み**。ここから起票すると二重計上になるため「対象外」として除外する。何が記帳済みかの判断は経理の仕事（照合の頭脳部分）で、システムは状態管理で支援する。
- **操作する画面**: 【銀行】**一括起票**（v3 で新設。未起票の明細だけが並ぶ作業台）
- **具体的な操作手順**:
  1. 「【銀行】一括起票」を開く。サマリ「未起票 5 件 ／ 起票対象（候補設定済み） 2 件 ／ 候補未設定 3 件 ／ 対象外チェック中 0 件」と、未起票 5 行（AWS・振込手数料に候補・推定元 rule が入っている）を確認。
  2. 7/1 の 2 行（ﾔﾁﾝ／ｿﾝｶﾞｲﾎｹﾝ）の「**対象外**」列にチェックを入れる。
  3. 「変更を保存」を押す → 「変更を保存しました（対象外チェックの行は一覧から外れます）」。
- **期待される結果**:
  - **直接的な結果**: 2 行が excluded になり、**一括起票の一覧から消える**（未起票だけの作業台のため）。サマリが「未起票 3 件」に更新される。
  - **波及する結果**: 対象外行は【明細一覧】には残り（状態: 対象外）、残高照合でも**残高の突合には使われる**（明細として存在する事実は変わらない）。誤って対象外にした場合は明細一覧の詳細画面「未起票に戻す」で差し戻せる。

### ステップ 5-4: AI による相手科目の推定と手修正

- **この業務の目的（実務解説）**: ルール辞書にない摘要（新しい取引先など）は AI に推定させ、経理が確認・修正する。「AI は下書き、確定は人間」という役割分担。
- **操作する画面**: 【銀行】一括起票
- **具体的な操作手順**:
  1. 「AIで相手科目を推定」を押す。
  2. 結果ラベル「AI 推定: 対象 1 件 / 反映 1 件（モック応答）（保存または一括起票で確定されます）」（対象=候補未設定の未起票明細、つまり 7/24 ｻｰﾊﾞｰﾎｽﾃｨﾝｸﾞ の 1 件のみ。モック時は「（モック応答）」が付く）。
  3. 該当行の相手科目（候補）に AI の提案が入る（推定元「ai」）。提案が「通信費」以外だった場合は、候補ドロップダウンで「**通信費**」に手修正する（手修正すると推定元は「manual」になる）。
  4. 「変更を保存」を押す。
- **期待される結果**:
  - **直接的な結果**: 全 3 件の未起票明細（AWS・振込手数料・ホスティング）に相手科目候補が揃う。
  - **波及する結果**: まだ仕訳なし。**AI・ルールの推定は保存（または起票の暗黙保存）まで DB に書かれない**——推定させただけでブラウザを閉じれば何も残らない（v3 の保存規律）。

### ステップ 5-5: 候補科目で一括起票（仕訳 No.25〜27）

- **この業務の目的（実務解説）**: 明細から自動仕訳を起こす。出金明細は「借方 相手科目（内税分解）／貸方 普通預金」。相手科目の既定税区分が課税仕入なら仮払消費税行も自動生成される。日付は**明細の日付**（発生日）になる。
- **操作する画面**: 【銀行】一括起票
- **具体的な操作手順**:
  1. 「候補科目で一括起票」を押す → 確認ダイアログ「**3 件の明細を仕訳として一括起票します。よろしいですか？**」→「起票する」。
- **期待される結果**:
  - **直接的な結果**: 結果ラベル「**一括起票: 3 件起票（伝票 No.25, 26, 27） / 締め済み等スキップ 0 件 / 失敗 0 件**」、トースト「3 件を仕訳として起票しました」。3 行が起票済になり**一括起票の一覧から消える**。サマリ「未起票 0 件」。
  - **波及する結果**:
    - **仕訳帳**（日付昇順に採番）:
      - No.25（7/15）: 借方 通信費 50,000＋仮払消費税 5,000／貸方 普通預金 55,000（摘要「銀行明細 AWS ｸﾗｳﾄﾞﾘﾖｳｷﾝ」）
      - No.26（7/21）: 借方 支払手数料 500＋仮払消費税 50／貸方 普通預金 550
      - No.27（7/24）: 借方 通信費 30,000＋仮払消費税 3,000／貸方 普通預金 33,000
    - **明細一覧**: 3 行の状態が「起票済」・伝票No 列に 25〜27 が表示される（明細→仕訳のリンク）。
    - **試算表**: 通信費 80,000／支払手数料 500 が加わる。普通預金残高 2,620,150。
    - **ホーム**: 「未処理: 銀行明細（未起票） 0 件」。
    - 同じ明細をもう一度起票しようとしても対象が無い（「起票対象（相手科目候補が設定済みの未起票明細）がありません」）。

### ステップ 5-6: 残高照合（銀行残高 ＝ 帳簿残高）

- **この業務の目的（実務解説）**: 本章のゴール。明細に記録された銀行側残高と、帳簿（期首残高＋仕訳）から計算した残高を**日付ごとに突合**する。全日付「○ 一致」なら、その口座の帳簿は銀行と完全に同期している。
- **操作する画面**: 【銀行】残高照合
- **具体的な操作手順**:
  1. 「【銀行】残高照合」を開く（対象口座で MB01 を選んで検索。未選択なら全口座）。
- **期待される結果**:
  - **直接的な結果**: 明細が存在する 4 日付が並び、**すべて判定「○ 一致」・差額 0**:
    | 日付 | 明細残高 | 帳簿残高 | 差額 | 未起票（累計） | 判定 |
    |---|---|---|---|---|---|
    | 2026-07-01 | 4,769,000 | 4,769,000 | 0 | 0 | ○ 一致 |
    | 2026-07-15 | 4,684,000 | 4,684,000 | 0 | 0 | ○ 一致 |
    | 2026-07-21 | 4,683,450 | 4,683,450 | 0 | 0 | ○ 一致 |
    | 2026-07-24 | 4,650,450 | 4,650,450 | 0 | 0 | ○ 一致 |
  - **波及する結果（読み方）**: 帳簿残高＝「期首残高＋その日までの確定仕訳の累計」。もし ⚠ 差異が出たら「未起票（累計）」列が原因候補の件数を示す（未起票明細が残っていれば起票せよ、のガイド）。試しにステップ 5-5 の**前に**この画面を見ると、3 件の未起票が差異として見えていたはずである。
  - **【重要・実行日依存】** 上の期待値は、操作日仕訳（03_購買の支払 No.7・01_経費精算の経費支払 No.9/11/13/15、計 785,800 円の出金）が **2026-07-25 以降の日付**で起票された前提。**実行日が 7/24 以前**だとこれらが 7/15〜7/24 の帳簿残高に混入し、3 日付が「⚠ 差異」になる。その場合は 5-1 の CSV の残高列を次の値に差し替えてから取り込むこと（7/1 の 2 行はそのまま）: 7/15 = **3,898,200**／7/21 = **3,897,650**／7/24 = **3,864,650**（各 −785,800）。※実行日が 7/15〜7/24 の間だと日割りで混ざるため、その期間の実行は非推奨。また 08_決算の E-5 支払（No.37・3,300 円）実行後にこの画面を見直すと、実行日が 7/24 以前の場合のみ同様の差異（3,300 円）が出る。

### ステップ 5-7: 仕訳ルールの育成（次回から自動判定）

- **この業務の目的（実務解説）**: 今回 AI に頼った「サーバーホスティング」を辞書（ルール）に登録し、来月からはルールで即決させる。ルール辞書を育てるほど月次照合が速くなる——運用改善のループ。
- **操作する画面**: 【銀行】仕訳ルール > 新規作成
- **具体的な操作手順**:
  1. 新規作成: 優先度「20」・摘要キーワード「ｻｰﾊﾞｰﾎｽﾃｨﾝｸﾞ」・適用方向「出金のみ」・相手勘定科目「通信費」・有効 ○ → 登録。
- **期待される結果**:
  - **直接的な結果**: ルール一覧（優先度順）に追加される。
  - **波及する結果**: 次回以降の**登録時**に同摘要の出金明細へ「通信費／rule」が自動付与される（v3 ではルール適用は「この内容で登録」の瞬間。既存の未起票に後追い適用したい場合は【一括起票】の「ルールを適用」ボタン→保存）。ルールは優先度昇順で**最初に一致した 1 件だけ**が適用される。※仕訳ルールも会計ワークスペースの【銀行】グループ内にあり、登録・編集は経理のみ。

### ステップ 5-8: 明細一覧での横断確認と詳細画面

- **この業務の目的（実務解説）**: 取り込んだ全明細（未起票・起票済・対象外）を通帳ビューで監査する。v3 では一覧は**表示専用**（うっかり削除・編集の事故防止）で、単発の例外操作は行クリックで開く**詳細画面**に集約されている。
- **操作する画面**: 【銀行】明細一覧
- **具体的な操作手順**:
  1. 「【銀行】明細一覧」を開く → 既定では**全状態**が並ぶ（既定絞り込みなし）。状態「起票済」で検索 → 3 件（伝票No 25〜27）。状態「対象外」→ 2 件。日付や口座でも絞れることを確認。
  2. 起票済の行（例: AWS）をクリック → 詳細画面。注記「起票済の明細です（仕訳 伝票 No.25）」と赤ボタン「起票を取り消す」だけが出る（**押さない**——押すと仕訳ごと削除され未起票に戻る。誤起票の救済用）。
  3. 対象外の行（ﾔﾁﾝ）をクリック → 「未起票に戻す」「この明細を削除」が出ることを確認（**押さない**）。
- **期待される結果**: 取り込んだ全明細のステータス・仕訳リンク（伝票No）が一覧で監査でき、状態に応じた例外操作（対象外化⇄差し戻し・起票の取り消し・削除）が詳細画面に揃っている（明細 → 仕訳のトレーサビリティ）。
