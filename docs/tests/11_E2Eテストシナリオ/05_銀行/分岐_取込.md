### BNK-01: 入力ガード（口座未選択・CSV 空）
- **前提**: 有効な口座が 1 件だけの環境では取込先口座が自動選択されるため、手順 1 はドロップダウンで空欄を選び直してから行う。
- **操作手順**:
  1. 取込先口座を**未選択**にして「明細を取り込む」→ 赤トースト「**取込先の口座を選択してください**」。
  2. 口座「メインバンク 普通預金」を選び、CSV 欄を**空**のまま「明細を取り込む」→ 「**明細CSVを貼り付けてください**」。
- **期待される結果**: どちらも何も取り込まれない（プレビュー 0 行のまま）。
- **後片付け**: 不要。

### BNK-02: 解析不能行の網羅（1 行だけ生き残る CSV）
- **目的**: スキップ行に分類される 4 パターン（列不足・日付でない・金額なし・存在しない日付）が**エラーで止まらずスキップ**され、正常行だけがプレビューに入ることを確認する。
- **操作手順**: 口座を選び、以下を貼り付けて「明細を取り込む」:
  ```
  日付,摘要,出金額,入金額,残高
  これは1列だけの行
  2026/13/45,月が13,1000,,
  2026/02/30,存在しない日付,1000,,
  2026/07/29,金額が両方ゼロ,0,0,
  2026/07/29,BNK-02 生存行,1100,,
  ```
- **期待される結果**: 結果ラベル「**プレビュー 1 件 / 重複スキップ 0 件 / スキップ行（ヘッダ・明細以外） 5 行**」（ヘッダ行＋不正 4 行がスキップ。「BNK-02 生存行」だけがプレビュー表に出る）。
- **確認ポイント**: 日付の正規化は `yyyy/M/d`・`yyyy-M-d`・`yyyy.M.d`・和式（2026年7月29日）を受け付け、月範囲・実在日（2/30 拒否）まで検証する（NormalizeDate）。金額はカンマ・引用符・¥・円を除去して解釈（ParseAmount）。
- **後片付け**: 「全てのプレビューを取り消す」→ 確認ダイアログ「取り消す」→ 「プレビュー 1 件を取り消しました」。

### BNK-02b: プレビューの修正・行削除は「保存」まで DB に反映されない（v3 新設）
- **目的**: v1 の致命バグ（B-1: プレビューの行削除が保存されない／B-2: 編集が登録に反映されない）の恒久対策——**スナップショット差分同期**——を確認する。
- **操作手順**:
  1. 以下 2 行を取り込む:
     ```
     2026/07/29,BNK-02b ｹｽﾞﾐ,1100,,
     2026/07/29,BNK-02b ﾉｺﾘ,2200,,
     ```
  2. 1 行目をゴミ箱ボタンで削除し、2 行目の摘要を「BNK-02b ﾉｺﾘ 修正」に書き換える。**保存せずに**サイドバーで別画面（例: 明細一覧）へ移動して戻る。
  3. もう一度手順 2 の削除と修正を行い、今度は「**プレビューの変更を保存**」を押す。
- **期待される結果**:
  - 手順 2 の後: プレビューは**元の 2 行のまま**（削除も修正も消えている＝保存前はメモリのみ、が実証される）。
  - 手順 3 の後: プレビューが 1 行（摘要「BNK-02b ﾉｺﾘ 修正」）になり、再表示しても維持される。重複キーも修正後の摘要で再計算される（同じ行をもう一度貼っても「BNK-02b ﾉｺﾘ」は重複扱いにならず入る）。
- **後片付け**: 「全てのプレビューを取り消す」。
- **補足（U5-1）**: プレビューを残したまま【明細取込】を開き直すと、結果ラベルに「⚠ 登録されていないプレビューが n 件残っています…」の警告が出る（前回作業の続き・他担当者の作業中の検知）。

### BNK-03: 同一内容 2 行の連番一意化と重複スキップの境界
- **目的**: 重複キーは `日付|摘要|出金|入金|連番`。**同じ CSV 内**の同一内容 2 行（例: 同額の引き落とし 2 件）は両方取り込まれ、**再貼り付け**では 2 行ともスキップされることを確認する。
- **操作手順**:
  1. 以下を貼り付けて取込 → 「この内容で登録」:
     ```
     2026/07/30,BNK-03 ﾃｽﾄﾋｷｵﾄｼ,2200,,
     2026/07/30,BNK-03 ﾃｽﾄﾋｷｵﾄｼ,2200,,
     ```
  2. **同じ 2 行**をもう一度貼り付けて「明細を取り込む」。
  3. 1 行だけ（1 行目と同内容）を貼り付けて「明細を取り込む」。
- **期待される結果**:
  - 手順 1: プレビュー **2 件**（同一内容でも連番 |0・|1 で別キー）→ 登録で未起票へ 2 行（「2 件を未起票の明細として登録しました…」）。
  - 手順 2: 「プレビュー 0 件（**重複スキップ 2 件** / スキップ行（ヘッダ・明細以外） 0 行）」＋警告トースト。
  - 手順 3: **重複スキップ 1 件**（同一貼り付け内の 1 件目はキー |0 で既存と衝突。3 件目を足したいときは 3 行貼れば 3 行目だけ |2 で入る——「銀行 CSV は過去分ごと再出力する」運用に合わせたキー設計）。
- **確認ポイント**: 残高列は重複キーに**含まれない**（残高だけ違う行は重複扱い）。重複照合は本番（bank_statement_lines）とプレビュー（bank_statement_preview）の**両テーブル横断**。
- **後片付け**: 【銀行】明細一覧 で「BNK-03」の 2 行（未起票）をそれぞれクリック → 詳細画面「**この明細を削除**」→「削除する」（v3 では一覧に削除ボタンは無い。削除は詳細画面に集約）。

### BNK-04: 残高列なし CSV と照合の「－ 明細残高なし」
- **目的**: 残高列が無い（または空の）明細は balance=NULL で取り込まれ、残高照合では判定不能「－ 明細残高なし」になることを確認する。
- **操作手順**:
  1. 4 列 CSV を貼り付けて取込 → 登録:
     ```
     2026/07/29,BNK-04 ｻﾞﾝﾀﾞｶﾅｼ,1100,
     ```
  2. 【銀行】残高照合 を開く。
- **期待される結果**: 2026-07-29 の行が現れ、明細残高が空・判定「**－ 明細残高なし**」。既存の 4 日付（7/1・15・21・24）は**○ 一致のまま**。
- **確認ポイント**: この明細は pending（未起票）なので、7/29 行の「未起票（累計）」が **1** になる（それでも判定は残高の有無だけで決まる）。
- **後片付け**: 明細一覧で「BNK-04」行の詳細から削除 → 残高照合から 7/29 行が消え、全日付 ○ に戻ることを確認。

## 後片付け（必須）

BNK-02〜04 の明細（プレビュー・未起票とも）がすべて消えていることを【銀行】明細一覧（状態=未起票で検索）と残高照合（既存 4 日付のみ・全○）で確認する。プレビュー残数は【明細取込】を開いて警告が出ないことで確認できる。帳簿（仕訳帳・試算表）は本ファイルの前後で無変化。
