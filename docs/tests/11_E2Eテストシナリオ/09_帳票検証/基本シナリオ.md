# 09_帳票検証 基本シナリオ（BS・PL・TB ほか全帳票の整合性検証）

> 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映——財務帳票は会計（Accounting）ワークスペースの【財務帳票】グループ。**資金繰り予測（9-9）だけは経営管理（ManagementFull）へ移動**。ホーム KPI は会計ホーム（AccountingHome）に現行化。金額・仕訳番号は不変）
> **更新: 2026-08-09 現行化（ADR-0042〜0048）**——①導線を**ポータル着地＋ Main 左サイドバー**に置き換え（「ほかの業務」・`/XXX/Top` は全廃）。②**9-10 を「ホームの経営サマリ KPI」から「業務ポータルの経営ダッシュボード（当月）」に全面差し替え**（AccountingHome は廃止され、KPI は `Shell/PortalKpiData` からポータルが表示する。ADR-0045・docs/13 §3 #11）。**帳票の金額・貸借・仕訳番号・検算値は一切不変。**
> **更新: 2026-08-13（ADR-0052/0053）**——**9-7 消費税集計表の数表は旧仕様の値**（列構成・集計方法とも作り直された）。当該ステップに「要再取得」の注記と、再取得時の確認事項を書いた。**9-7 以外の帳票（BS・PL・TB・C/F・元帳・出納帳）の期待値は不変**（税区分の付き方が変わっても仕訳金額は変わらないため）。
>
> **実務上の位置づけ**: 決算の最後は「帳票同士の突合」。複式簿記が正しく運用されていれば、**どの帳票をどこから見ても同じ数字に辿り着く**——試算表の貸借は一致し、BS の資産合計は負債・純資産合計と一致し、PL の当期純利益は BS・株主資本等変動計算書・翌期の繰越利益剰余金のすべてに同じ額で現れる。この「一致の網」を全部確認するのが本章。1 つでも合わなければ、どこかの処理にバグか操作ミスがある。
>
> **前提**: 00〜08 の基本シナリオをすべて完了していること（第 18 期・全 41 仕訳・繰越済み）。
> **使用ユーザー**: soumu_bucho（総務部 部長 山田太郎・**経理機能フラグ ON**）。本章の画面はすべて `HasAccountingAccess` でゲートされる。
>
> **導線**: ログイン後は**業務ポータル**（`/Main` = `Shell/PortalHome`）に着地。左サイドバーから 3 フレームを使い分ける（フレーム内のサイドバー先頭「ホーム」でポータルへ戻る）:
> - **「会計業務」** → `/Accounting`（素 URL の着地は【仕訳】振替伝票）。本章の **【財務帳票】【帳簿】** はこのフレームのサイドバーグループ
> - **「経営管理」** → 経理なので `/ManagementFull`。**【資金繰り】資金繰り予測**（9-9）はここ
> - **「営業業務」** → 経理なので `/SalesBilling`。**売掛残高**（9-8）はここ
>
> 経営サマリ KPI（9-10）は**フレームではなくポータル中央**に出る（旧 AccountingHome は廃止）。

### ステップ 9-2: 貸借対照表（BS）—— 財政状態と検算行

- **この業務の目的（実務解説）**: 期末時点の「持ち物（資産）と、その調達源泉（負債＋純資産）」の一覧。**資産合計 ＝ 負債・純資産合計**が複式簿記の帰結。当期純利益は PL から差し込まれて純資産の一部になる——PL と BS はここで接続する。
- **操作する画面**: 【財務帳票】貸借対照表（対象年度「第18期」で検索。未選択でも現在年度に自動解決）
- **画面の形式（2026-07-19〜）**: **勘定式**——左 2 列が「資産の部」、右 2 列が「負債・純資産の部」。区分見出し（【流動資産】等）→ 科目（字下げ）→ 「◯◯ 計」の順に並び、**最終行で「資産合計」と「負債・純資産合計」が同じ行で対置**される。Excel ダウンロードも同じ左右 4 列。
- **期待される結果**（金額は従来どおり）:

### ステップ 9-5: 月次推移表（PL / BS）

- **この業務の目的（実務解説）**: 年間合計だけでは「いつ動いたか」が見えない。月次に展開して季節性・異常月を検出する。
- **操作する画面**: 【財務帳票】月次推移表（対象年度「第18期」。表示帳票の既定は PL）
- **具体的な操作手順と期待される結果**:
  1. **PL 表示**: 先頭行「月（暦月）」で第 1 月=4 月…第 12 月=3 月を確認。数値の入る月は 3 つだけ:
     - 第 3 月（6 月）: 外注費 500,000 のみ → 月次利益 △500,000（発生主義で 6 月に計上した No.6）
     - 第 4 月（7 月）: 売上 2,345,500・費用 3,561,101 → **△1,215,601**（日常取引はすべて 7 月）
     - 第 12 月（3 月）: 減価償却 28,125・保険料 △16,500・法人税等 70,000 → △81,625（決算整理）
     - **合計列が 9-3 の損益計算書と全行一致**する。
  2. 表示帳票を「貸借対照表（BS）」に切り替えて検索: 各科目の**月末残高**の推移が出る。**第 12 月列が 9-2 の BS と一致**し、最下段の検算行「負債・純資産合計」が**全 12 ヶ月で資産合計と一致**する（月次レベルでも複式が崩れていない証明）。

### ステップ 9-7: 消費税集計表

- **この業務の目的（実務解説）**: 消費税申告の基礎資料。税区分別に課税標準（本体）と税額を集計する。
- **操作する画面**: 【財務帳票】消費税集計表（対象年度「第18期」・期間指定は任意）

> ⚠ **期待値は要再取得（2026-08-13 時点）**。本ステップの数表は **ADR-0052 で消費税集計表を全面的に作り直す前**の値で、
> 現行版とは列構成も集計方法も違う。**クリーン DB で E2E を再完走したときに実測して差し替えること**。
> 下の「現行版で何が変わったか」は、数字を再取得するときに何を確かめるかのチェックリストとして使える。

- **現行版（ADR-0052/0053 後）の姿**:
  - **列**: 税区分／課税種別／**税込対価**／本体金額／消費税額／**戻し（本体）**／**戻し（税）**／**控除率**／**控除対象税額**。最終行に「**課税売上割合（表示期間）**」と全額控除の可否判定が出る。
  - **符号を持つ差引集計**になった。勘定科目の正残側（`accounts.dc_normal`）に立った金額が ＋、逆側が −。**赤伝で打ち消した分は相殺される**（旧版は単純合計で両建てに積み上がっていた＝改善候補 B-6）。ただし逆側に立った金額は「戻し」列にも出るので、申告で別掲すべき「対価の返還等」の存在は見える。
  - **経過措置は控除割合ごとに行が割れる**。第18期は 80%→70% の改定日 2026-10-01 をまたぐため、同じ「課税仕入 10%(経過措置)」でも 80% 行と 70% 行に分かれうる。
- **再取得時に確かめること（旧版から確実に変わる点）**:
  1. **赤黒訂正の両建てが消える**: 会議費の赤黒（本体 5,000×2・税 500×2）は差引 0 になり、戻し列に 5,000／500 が出る。
  2. **内部振替に課税区分が付かなくなった**: 償却仕訳の貸方 工具器具備品、前受収益の按分振替の貸方は**対象外**で起票される（ADR-0053 決定 1）。旧版で課税仕入・課税売上に混入していた分（工具器具備品 28,125 など）は載らない。
  3. **CSV インポートの税行が税額列に載る**: 税区分コード空欄の行は取込時に補完されるようになった（ADR-0052・改善候補 B-5）。旧版で消えていた仮払消費税 1,363 円が現れる。
  4. **税区分「未設定」が存在しない**: BS 科目にも「対象外」が入る（NOT NULL 化）。旧版の「税区分が空だから集計に出ない」という逃げ道は無い。
  5. **入出金起票**: 受取利息は非課税売上 500（税額 0）として載る。課税科目を相手にした入出金は**本体と税に分かれて**載る（ADR-0053。旧版は税込額が丸ごと本体に載る誤りがあった＝改善候補 B-7）。
- **不変の読み方（仕様理解）**:
  - 課税売上の本体には**年額前受の 1,200,000**（税は前受計上時に全額発生）が含まれ、売上高とは意図的に一致しない。
  - **納税額の確定は必ず試算表の仮受・仮払「残高」で行う**こと（08_決算 ステップ 8-5 でそうした）。集計表は申告の基礎資料であって納税額そのものではない。

### ステップ 9-8: 総勘定元帳・出納帳と債権台帳の三面突合

### ステップ 9-9: 資金繰り予測（未来側の資金管理）

- **この業務の目的（実務解説）**: C/F 計算書が「過去の現金」なら、資金繰り予測は「未来の現金」。未回収請求・未払の請求書・人件費から今後 4 ヶ月の残高を予測し、資金ショートを事前警告する。

### ステップ 9-10: 業務ポータルの経営ダッシュボード（当月 KPI）

- **この業務の目的（実務解説）**: 帳票は「見に行くもの」だが、経営指標は「毎朝ログインした瞬間に目に入る」べきもの。本アプリは決算帳票と同じ確定仕訳から当月 KPI を作り、**ログイン直後のポータルに常設**する（旧 AccountingHome の経営サマリはここへ移設された——ADR-0045）。
- **操作する画面**: **業務ポータル**（soumu_bucho＝経理でログインした直後の画面。フレーム内にいる場合はサイドバー先頭「ホーム」で戻る）。ページ下部の見出し「**経営ダッシュボード（当月）**」——`HasAccountingAccess` を持つユーザーにだけ表示される（データ源は `Shell/PortalKpiData`。docs/13 §3 #11）。
- **期待される結果**（**2026 年 7 月中に実行した場合**。9-1〜9-6 の帳票と同じ確定仕訳から作られる）:

  | 区分 | 項目 | 値 | 突合先 |
  |---|---|---:|---|
  | 残高 | 現預金 | 3,810,610 円 | 9-2 BS の現金 74,700 ＋ 小口現金 80,000 ＋ 普通預金 3,655,910、9-6 C/F の期末残高 |
  | | 売掛金 | 1,320,000 円 | 9-2 BS・9-8 の売掛残高一覧 |
  | | 買掛金 | 0 円 | 9-1 試算表の買掛金残高（期中に立てて期末に消えた） |
  | 当月 | 当月売上高 | 2,345,500 円 | 9-5 月次推移表の第 4 月（7 月）列 |
  | | 当月費用 | 3,561,101 円 | 同上 |
  | | **当月利益** | **△1,215,601 円** | 同上（第 4 月の月次利益） |

  - **当月利益が負のときは赤字表示**になる（△と赤の二重表現）。7 月は日常取引が集中しているため大きな赤字月になる。
  - **KPI は「実行日の月」で集計する**——実行日が 8 月以降なら当月に該当する仕訳が無いため、当月売上高・費用・利益は **0** になる（残高 3 項目は当月に依存しないのでそのまま出る）。日付依存の画面である点は資金繰り予測（9-9）と同じ。
  - この KPI は**経理だけの表示**。一般社員・承認者のポータルには「経営ダッシュボード」の見出しごと出ない（同じポータル画面が権限で合成される設計。ADR-0042/0045）。
  - あわせてポータル上部の「**経理の作業キュー**」も確認する: 完走状態では「精算処理待ち」「未起票の銀行明細」「下書きのままの伝票」「定期請求・SES の当月未生成」がいずれも 0 件のため、**キューの見出しごと画面から消えている**（0 件の行は丸ごと非表示＝「対応が要るときだけ見える」）。旧ホームの「支払期限 7 日以内の仕入先請求書」はポータルの**アラート**「⚠ 支払期限: 超過 N 件／N 日以内 N 件」になり、詳細は購買・支払（Purchasing）の支払予定表で確認する。
