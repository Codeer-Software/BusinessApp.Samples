## B. 検収のガードと値引き（RCV-07〜09）

### RCV-07: 検収の必須ガード
- **操作手順**: SalesBilling > 検収 > 新規作成。受注を選ばず「保存」→ 保存後の画面が無いので、受注だけ選んで検収額を **0** に書き換えて保存 → 「検収を確定（売上計上）」。
- **期待される結果**:
  - 未保存で確定を押した場合: 「**先に検収を保存してください**」（保存前に確定ボタンが見えている場合。UI 上は保存後にのみ出るため通常は到達しない——未実測）。
  - 検収額 0 で確定: 「**検収額を入力してください**」（Amount <= 0 ガード）。仕訳は作られない。
- **後片付け**: この検収（下書き）を詳細の「この検収を削除」で削除。

### RCV-08: 締め済み期間の検収日
- **前提**: 月次 3（2026-06）が締め済みのままであること（08_決算で締めた状態をそのまま使う）。
- **操作手順**: 検収 > 新規作成 → 受注に既存の確定済み以外（なければ SLS 分岐の要領で捨て受注を作る）→ 検収日を「**2026-06-15**」にして保存 → 「検収を確定（売上計上）」。
- **期待される結果**: 赤トースト「**検収日の期間は締め済みです。仕訳は手動で起票してください**」。仕訳・状態変更なし（検収は下書きのまま）。
- **確認ポイント**: 経費（自動フォールバック）と違い、**検収は締め済みでフォールバックせずブロック**する設計——売上計上日は検収日でなければならない（検収基準）ため、日付をずらす判断は人間に委ねる。
- **後片付け**: 検収（と捨て受注）を削除。

### RCV-09: 検収明細の減額 = 請求前の値引き（2026-08-12 改訂・ADR-0049）
> 旧仕様ではヘッダの検収額・消費税額を直接手入力していた。**現在は検収が明細行を持ち、ヘッダは明細合計の自動計算**なので、値引きは「行の検収金額を下げる」操作になった。

- **操作手順**: 検収 > 新規作成 → 受注を選択 → **受注明細がコピーされ、各行の「検収金額」にその行の残額が自動セット**されることを確認 → 摘要・数量・単位・単価・受注金額・税区分が**編集できない**こと、および**行の「追加」「削除」ボタンが無い**ことを確認 → 行の検収金額を**減額**（例: 1,200,000 → 1,000,000）。
- **期待される結果**:
  - ヘッダの検収額（税抜）と消費税額が**即座に追随**する（1,000,000 / 100,000）。両欄は読み取り専用で手入力できない。
  - 消費税は**明細の税区分ごとに集計し、税率ごとに 1 回だけ端数処理**される（ADR-0050）。8% 行と 10% 行が混在する受注なら、行ごとに切り捨てずに税率グループ単位で計算されることを確認できる。
  - 受け入れない行は**金額 0** にする（行を消すのではない）。
- **確定はしない**——確定すると修正後の額で売上仕訳が起きる（基本 2-6 の期待の変形。ここでは金額が動くため実行しない）。
- **後片付け**: 保存した場合は削除（検収明細も一緒に消える）。

### RCV-09b: 請求額が検収額を超えたときの行単位警告（2026-08-12 追加・ADR-0049）
- **操作手順**: 確定済みの検収から「請求書を作成」→ 下書き請求書の明細で、**検収由来の行の金額を検収額より大きく**書き換える（例: 500,000 → 700,000）。
- **期待される結果**: 保存前・発行前に、明細のすぐ下に**赤字**で「⚠ 検収額を超えている明細が N 行あります（超過 合計 …円）。X行目「…」 請求 …円 > 検収 …円（+…） — 増額する場合は変更契約として新しい受注・検収を起こしてください。」が即時表示される。
- **確認ポイント**: **ブロックはしない**（保存も発行もできる）。判断を人に委ねる設計。金額を戻すと警告は消える。手で足した行（検収に紐づかない行）は突合対象外で、合算請求書・定期請求・SES 請求では警告そのものが出ない。
- **確認ポイント（A-1 の回帰テスト）**: 請求書を一覧に戻ってから開き直しても、明細金額が受注全額に戻らないこと。

## C. 入金の境界値（RCV-10〜11）

差額自動処理の閾値は制度閾値マスタ `RECEIPT_DIFF_MAX` = **1,000 円**。コード上の判定は `1 <= 差額 <= 閾値` で自動処理（支払手数料化）、閾値超は「一部入金」になる。**確定は押さない**ため、ここでは境界値の挙動を（未実測）のコード根拠として整理し、UI では入金額の自動セットと上書きだけを確認する。

### RCV-10: 差額境界の整理（コード根拠・未実測）
| 請求残額 | 入金額 | 差額 | 判定 | 結果 |
|---|---|---|---|---|
| 110,000 | 109,560 | 440 | 1〜1,000 | 支払手数料化＋**入金済**（07_特殊取引 7-7 で実測済み） |
| 110,000 | 109,000 | **1,000** | 境界ちょうど（≦判定） | 支払手数料化＋入金済（未実測） |
| 110,000 | 108,999 | **1,001** | 閾値超 | 自動処理なし・**一部入金**（残 1,001。未実測） |
| 110,000 | 110,001 | −1（過入金） | 保存前ガード | 「入金額 … が請求残額 … を超えています」で**拒否**（7-8 で実測済み） |

- 閾値を **Main 左サイドバー「業務マスタ」→ MasterBusiness** >【税制】制度閾値 `RECEIPT_DIFF_MAX` で変えるとこの境界も動く（マスタ駆動）。
- **2026-07-10 修正の確認事項**: 過入金で拒否された金額は**保存されない**（ガードが保存前に走る）。拒否後に金額を直して確定すると、修正後の金額が入金レコードにも仕訳にも入る（同日修正済みバグの回帰確認ポイント）。

### RCV-11: 入金額の自動セットと一部入金の器（確定しない）
- **操作手順**: SalesBilling > 入金 → 消込状態が「**未確定**」の行（未消込の請求書のもの。完走後 DB なら INV-26-002）を「開く」。
  - **現行実装の注意（ADR-0032）**: 入金は**手で新規作成できない**。一覧の「新規作成」を押すと情報トースト「入金は請求書の発行時に自動作成されます（入金一覧の「未確定」から確定してください）」が出て一覧へ戻される。未確定の入金予定は**請求書の発行時に税込全額で自動作成**されている。
- **期待される結果**: 請求書欄のドロップダウン候補は**発行済（issued）と一部入金（partial）だけ**。選び直すと入金額に**残額**（1,320,000）が自動セットされる。値を 500,000 に**上書きできる**（一部入金の入口。確定すると partial になり、**残額 820,000 の入金予定が自動作成**される。確定はしないので本分岐では未実測）。
- **後片付け**: **確定せず**戻る。入金額や入金日を書き換えて保存してしまった場合は、**元の値（税込全額＝支払期限日）に戻して保存**する（Receipt に削除ボタンは無く、未確定行は請求書側の「下書きに戻す」「取消にする」でのみ消える）。金額が実額とずれたまま残ると**売掛残高の入金累計（未確定分も合算する）が狂う**ので必ず戻すこと。

## 後片付け（必須）

1. SalesBilling > 検収: 分岐分（下書き）を各詳細の「この検収を削除」ですべて削除。
2. SalesBilling > 入金: 分岐で入金日・入金額を書き換えたものがあれば元の値に戻す（未確定行は手で増やせず・削除ボタンも無い＝ADR-0032。消込状態が全行「未確定」のままであることを確認する）。
3. SalesBilling > 受注／見積: 捨てデータを削除（受注は「この受注を削除」、見積は下書きへ戻してから「この見積を削除」）。
4. 仕訳帳の最終番号・Σ が分岐前と同じであることを確認（分岐は帳簿の外で完結した）。
