## B. 検収のガードと値引き（RCV-07〜09）

### RCV-07: 検収の必須ガード
- **操作手順**: SalesBilling > 検収 > 新規作成。受注を選ばず「保存」→ 保存後の画面が無いので、受注だけ選んで検収額を **0** に書き換えて保存 → 「検収を確定（売上計上）」。
- **期待される結果**:
  - 未保存で確定を押した場合: 「**先に検収を保存してください**」（保存前に確定ボタンが見えている場合。UI 上は保存後にのみ出るため通常は到達しない——未実測）。
  - 検収額 0 で確定: 「**検収額を入力してください**」（Amount <= 0 ガード）。仕訳は作られない。
- **後片付け**: この検収（下書き）を詳細の「この検収を削除」で削除。

### RCV-08: 締め済み期間の検収日
- **前提**: 月次 3（2026-06）が締め済みのままであること（08_決算で締めた状態をそのまま使う）。
- **操作手順**: 検収 > 新規作成 → 受注に既存の確定済み以外（なければ SLS 分岐の要領で捨て受注を作る）→ 検収日を「**2026-06-15**」にして保存 → 「検収を確定（売上計上）」。
- **期待される結果**: 赤トースト「**検収日の期間は締め済みです。仕訳は手動で起票してください**」。仕訳・状態変更なし（検収は下書きのまま）。
- **確認ポイント**: 経費（自動フォールバック）と違い、**検収は締め済みでフォールバックせずブロック**する設計——売上計上日は検収日でなければならない（検収基準）ため、日付をずらす判断は人間に委ねる。
- **後片付け**: 検収（と捨て受注）を削除。

### RCV-09: 検収額の手修正 = 請求前の値引き
- **操作手順**: 検収 > 新規作成 → 受注を選択（検収額・消費税が自動セット）→ 検収額を自動セット値より**減額**（例: 1,200,000 → 1,000,000）し、消費税欄も 100,000 に修正できることを確認。
- **期待される結果**: 両欄とも自由に手修正できる（07_特殊取引 7-9 の値引きパターン①の入口）。**確定はしない**——確定すると修正後の額で売上仕訳が起きる（基本 2-6 の期待の変形。ここでは金額が動くため実行しない）。
- **後片付け**: 保存した場合は削除。

## C. 入金の境界値（RCV-10〜11）

差額自動処理の閾値は制度閾値マスタ `RECEIPT_DIFF_MAX` = **1,000 円**。コード上の判定は `1 <= 差額 <= 閾値` で自動処理（支払手数料化）、閾値超は「一部入金」になる。**確定は押さない**ため、ここでは境界値の挙動を（未実測）のコード根拠として整理し、UI では入金額の自動セットと上書きだけを確認する。

### RCV-10: 差額境界の整理（コード根拠・未実測）
| 請求残額 | 入金額 | 差額 | 判定 | 結果 |
|---|---|---|---|---|
| 110,000 | 109,560 | 440 | 1〜1,000 | 支払手数料化＋**入金済**（07_特殊取引 7-7 で実測済み） |
| 110,000 | 109,000 | **1,000** | 境界ちょうど（≦判定） | 支払手数料化＋入金済（未実測） |
| 110,000 | 108,999 | **1,001** | 閾値超 | 自動処理なし・**一部入金**（残 1,001。未実測） |
| 110,000 | 110,001 | −1（過入金） | 保存前ガード | 「入金額 … が請求残額 … を超えています」で**拒否**（7-8 で実測済み） |

- 閾値を MasterBusiness（経理）>【税制】制度閾値 `RECEIPT_DIFF_MAX` で変えるとこの境界も動く（マスタ駆動）。
- **2026-07-10 修正の確認事項**: 過入金で拒否された金額は**保存されない**（ガードが保存前に走る）。拒否後に金額を直して確定すると、修正後の金額が入金レコードにも仕訳にも入る（同日修正済みバグの回帰確認ポイント）。

### RCV-11: 入金額の自動セットと一部入金の器（確定しない）
- **操作手順**: SalesBilling > 入金 > 新規作成 → 請求書（未消込のもの。完走後 DB なら INV-26-002）を選択。
- **期待される結果**: 入金額に**残額**（1,320,000）が自動セット。値を 500,000 に**上書きできる**（一部入金の入口。確定すると partial になり、同じ請求書への 2 回目の入金では**残額 820,000 が自動セット**される——SumReceipts が保存済み入金を差し引くため。確定はしないので未実測）。
- **後片付け**: **確定せず**戻る。保存してしまった場合（確定ボタンを押す前に画面遷移で保存された場合を含む）は当該入金を開き「この入金を削除」で削除する（未確定＝消込仕訳なしのみ削除できる）——入金レコードが残っていると**残額の自動セットと売掛残高の入金累計が狂う**。

## 後片付け（必須）

1. SalesBilling > 検収: 分岐分（下書き）を各詳細の「この検収を削除」ですべて削除。
2. SalesBilling > 入金: 分岐で保存してしまったものがあれば「この入金を削除」で削除（未確定のみ削除できる＝仕訳の有無はアプリが担保）。
3. SalesBilling > 受注／見積: 捨てデータを削除（受注は「この受注を削除」、見積は下書きへ戻してから「この見積を削除」）。
4. 仕訳帳の最終番号・Σ が分岐前と同じであることを確認（分岐は帳簿の外で完結した）。
