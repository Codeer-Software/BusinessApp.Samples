## A. 定期請求（RCR-01〜06）

### RCR-01: 冪等スキップ（再実行しても二重請求されない）
- 基本シナリオ 2-11 で実施済み: 対象月 2026-07 で再実行 → 「月額請求 0件 / 年額請求 0件 / 按分振替 0件 / スキップ 3件（既生成・対象外）」。
- コード根拠: 月額は 契約×対象月の請求書存在チェック、年額は 契約×周期起点月の請求書存在＋按分は同一 source 仕訳の**年月一致**（日付範囲検索の境界罠を避けた設計）でスキップ。

### RCR-02: 無効契約は「対象外」（スキップ数にも現れない）
- **操作手順**:
  1. SalesBilling > 定期請求契約 で月額契約「クラウド勤怠 SaaS 利用料」を開き、**有効を ✕**（チェック OFF）にして保存（有効チェックの切替は経理のみ可）。年額契約も同様に ✕。
  2. SalesBilling > 定期請求の実行 → 対象月「2026-07」で「対象月の請求書を一括生成」。
- **期待される結果**: 結果ラベル「2026年7月分: 月額請求 0件 / 年額請求 0件 / 按分振替 0件 / **スキップ 0件**」・トースト「生成対象はありませんでした」。無効契約は検索条件（**確定済かつ有効**の契約だけが実行対象）で**そもそも取得されない**ため、スキップ数にすらカウントされない——「スキップ（既生成）」と「対象外（無効・期間外）」の違いを体感する分岐。状態「下書き」の契約も同様に対象外（取得されない）。
- **後片付け**: **両契約の有効を必ず ○ に戻す**（戻し忘れると以後の定期請求が空振りする）。

### RCR-03: 開始月より前の対象月は対象外
- **操作手順**: 月額契約（開始 2026-04）の**有効を一時 ✕**にした状態で、対象月「**2026-05**」を選んで実行（年額契約=開始 2026-07 だけが有効な状態にする）。
- **期待される結果**: 年額契約は `開始月 > 対象月` で continue（対象外）→ 「月額請求 0件 / 年額請求 0件 / 按分振替 0件 / スキップ 0件」・「生成対象はありませんでした」。**月額契約を無効化せずに 2026-05 で実行すると 5 月分の請求＋仕訳が生成されてしまう**ので注意（本流の帳簿が汚れる——絶対にやらない）。
- **後片付け**: 月額契約の有効を ○ に戻す。
- **補足（未実測・コード根拠）**: 終了月を設定した契約は `終了月 < 対象月` でも同様に対象外になる。

### RCR-04: 締め済み月はガードで全体ブロック
- **操作手順**: 対象月「**2026-06**」（締め済み）で「一括生成」。
- **期待される結果**: 赤トースト「**対象月の期間は締め済みです**」。処理は 1 件も走らない（契約の判定より前に月次期間ガードで return）。
- **確認ポイント**: 会計年度が存在しない月（例 2024-06）なら「対象月に対応する会計年度がありません」。

### RCR-05: 経理専用ガード
- **操作手順**: kaihatsu1_kacho1（承認者。**ユーザー管理で「営業機能」にチェック**が入っているため営業画面に入れる＝ADR-0043。経理機能は無い）でログイン → 業務ポータルに着地 → **Main 左サイドバーの「営業業務」**を押す（経理機能が無いので **SalesStaff** に解決され `/SalesStaff` の着地画面＝見積が開く）。
- **期待される結果**: SalesStaff のサイドバーは **見積 / 受注 / 検収 / 売掛残高 / 定期請求契約 / 取引先一覧** の 6 つだけで、「定期請求の実行」（および請求書・入金・SES精算・請求）のリンクは **存在しない**（SalesBilling＝経理機能ゲートのフレームにだけある）。UI からの実行経路が存在しないこと自体が第一防御。なお 2026-07-23 の改修（ADR-0030）で「**定期請求契約**」リンクは SalesStaff（営業機能を持つ一般・承認者）にも**出る**（閲覧＋下書きの作成・編集が可能）が、「確定する」「下書きに戻す」ボタンと有効チェックの切替は経理のみで、確定済の契約は非経理には読み取り専用＋「確定済の契約です。内容の変更・有効/無効の切替は経理が行います」の注記が出る。
- **補足（コード根拠・多層防御）**: 仮に画面へ到達して「一括生成」を押せた場合も、スクリプトの経理アクセスチェックが赤トースト「**定期請求の実行（売上計上を伴う）は経理のみ実行できます**」で拒否する（メニュー非表示＋サーバ側ガードの二層。この文言が見えたらリンク可視性の退行を疑うこと）。

### RCR-06: 年額の按分と端数（解説のみ・実行しない）
- **コード根拠**（RecurringRun.mod.cs）:
  - 按分月額 = 年額 ÷ 12（切り捨て）。**周期の最終月（12 ヶ月目）だけ「年額 −（月額×11）」**で端数を回収する（例: 年額 1,000,000 → 月 83,333×11 ＋ 最終月 83,337）。デモ契約は 1,200,000 なので割り切れて毎月 100,000。
  - 対象月が周期の**途中月**で年額請求書が未生成（起点月を実行し忘れた）場合は**スキップ**される——「起点月から順に実行する」運用が前提。
  - 周期は開始月の**応当月ごとに自動更新**される（2027-07 に実行すると新しい周期の年額請求書＋前受計上が再び生成される）。
- **実行しない理由**: どの確認も新しい請求書・仕訳を生成してしまうため（2026-08 の按分振替を含む）。翌期のテストサイクルで実測する。

## B. SES 精算（SES-01〜06）

SES の「**精算を計算**」は請求書・仕訳を一切作らない（BuildPlan → 内訳表示のみ）ため、計算分岐は帳簿影響ゼロで自由に確認できる。

### SES-01: 幅内（控除も超過もなし）の計算式
- **操作手順**: SalesBilling > SES精算・請求 → 対象月「2026-07」のまま「精算を計算」——は実績 190h で超過形（基本 6-5）なので、幅内を見るには工数を調整する必要がある。**工数を触らずに確認する場合**は次の SES-02（実績 0 の月）と併せてコード根拠で理解する: 幅内なら内訳が「基本 800,000（精算幅 140〜180h・実績 …） **= 800,000（幅内）**」の形式になる（未実測）。
- **コード根拠**: `下限 ≦ 実績h ≦ 上限` のとき amount = 基本料金のまま。

### SES-02: 実績 0（下限割れ・控除）の計算
- **操作手順**: 対象月を「**2026-08**」（工数が 1 件もない月）に変更して「**精算を計算**」。
- **期待される結果**: 内訳「PRJ-003 金融系SES 山田: 基本 800,000（精算幅 140〜180h・実績 0h00m） **− 控除 140h×（控除単価） = （計算結果）**」——実績 0 は下限割れの極端形。控除単価×140h が基本料金を超える場合、請求額はマイナスになり得る（その場合「一括生成」を押しても「**請求額 0 以下のためスキップ**」で仕訳は作られない——コード根拠。**一括生成は押さない**）。
- **確認ポイント**: 計算だけなら何度でも安全。結果ラベルは「2026年8月分: SES 1 件の精算を計算しました（請求書は未生成）」。

### SES-03: 時間の切り捨てと分表示
- **コード根拠（解説）**: 実績は分単位で合計し、時間 = 分÷60 の**切り捨て**、余り分は「190h00m」の形式で内訳に併記される。基本 6-5 の 11,400 分 = 190h00m がその実例。179h59m は 179h 扱い（上限 180h に**達しない**）——精算境界は「時間の整数部」で判定される。

### SES-04: 契約条件が未設定の SES 案件は対象外
- **操作手順**: **Main 左サイドバー「業務マスタ」→ MasterBusiness** > 案件 で PRJ-003 の**月額基本料金を一時的に空**にして保存 → サイドバー「営業業務」で SalesBilling に戻り、SES精算・請求で「精算を計算」。
- **期待される結果**: 「**対象の SES 案件（契約条件設定済み・有効）がありません**」（SesMonthlyRate が null または 0 以下の案件は計画から除外）。
- **後片付け**: **PRJ-003 の月額基本料金 800,000 を必ず復元**する（精算幅 140〜180・単価 4,500 も変更していれば戻す）。

### SES-05: 冪等スキップ（生成済み月への一括生成）
- **操作手順**: 対象月「2026-07」で「請求書を一括生成（売上仕訳込み）」。
- **期待される結果**: 「2026年7月分: 生成 0件 / スキップ 1件」・内訳「PRJ-003 金融系SES 山田: **生成済みのためスキップ**」・トースト「生成対象はありませんでした」（基本 6-6 の再実行と同じ。案件×対象月の冪等キー）。帳簿は無変化なので分岐でも安全に実行できる。

### SES-06: 経理専用ガード
- **操作手順**: kaihatsu1_kacho1（承認者。**ユーザー管理で「営業機能」にチェック**が入っているため営業画面に入れる＝ADR-0043）でログイン → 業務ポータルに着地 → **Main 左サイドバーの「営業業務」**（経理機能が無いので **SalesStaff** に解決される）。
- **期待される結果**: 「SES精算・請求」のリンクは **SalesStaff のメニューに存在しない**（SalesBilling＝経理機能ゲート専用。2026-07-12 の再編で経理専用化され、2026-08-02 の部品再編でフレームごと分離された）。
- **補足（コード根拠・多層防御）**: 仮に画面へ到達して「請求書を一括生成」を押せた場合も、赤トースト「**SES 請求の一括生成（売上計上を伴う）は経理のみ実行できます**」で拒否される（メニュー非表示＋サーバ側ガードの二層）。
