# 02_販売 — 章ガイドと分岐マップ

> 販売は「見積→受注→検収→請求→入金」の本流に加え、定期請求（月額/年額）・SES 精算という**自動生成系**を持つ。自動生成系の分岐は「実行」ボタンが仕訳を作ってしまうため、**帳簿影響ゼロで確認できる分岐**（ガード発動・計算のみ・対象外判定）と、**コード根拠の解説に留める分岐**（未実測）を明確に区別している。

## ファイル構成と実行順序

| ファイル | 内容 | 本流の帳簿への影響 |
|---|---|---|
| [基本シナリオ.md](基本シナリオ.md) | 見積 Q-26-001 → 受注 → 検収確定（仕訳 No.1）→ 請求 → 入金消込（No.2）→ 定期請求一括（No.3〜5）→ 冪等確認 → 受注クローズ | **あり**（仕訳 No.1〜5） |
| [分岐_見積受注.md](分岐_見積受注.md) | SLS-01〜08（必須ブロック・未保存ガード・明細自動計算・11行超の帳票警告・失注・明細0行の仕様注意） | なし（末尾で削除） |
| [分岐_検収請求入金.md](分岐_検収請求入金.md) | RCV-01〜11（経理専用・必須/締めガード・検収明細の減額=値引き・請求額が検収額を超えたときの行単位赤字警告・過入金境界・差額自動処理の境界 1,000/1,001・一部入金の解説） | なし（確定・消込まで進めない） |
| [分岐_定期請求SES.md](分岐_定期請求SES.md) | RCR-01〜06（冪等・無効契約・開始月前・締め済み・経理専用・按分端数）／SES-01〜06（幅内・下限割れ・契約未設定・計算のみ・冪等・経理専用） | なし（「実行」は安全な条件下のみ） |

**順序**: 基本シナリオ → 分岐（SLS→RCV→RCR/SES）。分岐は独立しているので個別実行も可。

## 実行前の前提（重要）

- **E2E 全章完走後の DB は第18期が全期間締め＋年度クローズ済み**。保存・確定・実行を伴う分岐を動かす前に、サイドバー「会計業務」（Accounting）>【設定】会計年度 > **第18期（2026年度）** を「進行中」に戻し、**月次 4（2026-07）を「進行中」に**戻して登録すること（締めガード分岐はむしろ「締まったままの月」を使う——各分岐に明記）。テスト後は元に戻す。
  - **開発中の作業 DB を使う場合の注記**（2026-08-09 時点）: 第18期は 2026-04〜06 が締め済み・**07 以降は進行中**なので、7 月を使う分岐はそのまま実行できる。締めガード分岐には 2026-06 を使う。
- 配役: 経理 = soumu_bucho（**経理機能**チェックあり。販売操作は Main 左サイドバー「営業業務」→ 経理は **SalesBilling** に解決される）／ガード確認役 = kaihatsu1_kacho1（開発1部 第一課長 山本由美・承認者。**ユーザー管理で「営業機能」にチェックが入っている**ため SalesStaff に入れる＝ADR-0043。営業部の兼務行は組織上の事実にすぎず、画面の見え方には影響しない）。パスワード = 識別名。
  - サイドバー「営業業務」の解決順は **SalesBilling（経理）> SalesStaff（営業）**。経理機能を持つユーザーは常に SalesBilling へ着地する。

## 伝票番号・採番の性質（分岐テストの安全性の根拠）

- 見積/受注/検収/請求書の番号（Q-/SO-/A-/INV-{yy}-{seq}）は**既存の最大番号 +1**で採番される。分岐で作ったデータを**削除すれば次の採番も元に戻る**ため、番号帯を汚さない。
- ただし完走後 DB には 07_特殊取引の SO-26-002／A-26-002／INV-26-005 が既に存在するため、分岐実行時の新規番号は**その時点の連番**になる（本書の番号例は相対的に読むこと）。
- 仕訳番号（年度内連番）は**分岐では 1 本も生成しない**のが原則。生成系の確認は基本シナリオで済んでいる。

## 定期請求・SES の「実行してよい条件」マトリクス

| 操作 | 帳簿影響 | 分岐での可否 |
|---|---|---|
| 対象月 2026-07 で再実行 | なし（全スキップ・冪等） | ○ RCR-01 |
| 締め済み月（例 2026-06）で実行 | なし（締めガードで全体ブロック） | ○ RCR-04 |
| 営業機能のみのユーザー（SalesStaff）で実行 | なし（メニュー非表示＋サーバ側の経理アクセスガード） | ○ RCR-05/SES-06 |
| 全契約を対象外にした月で実行 | なし（生成 0） | ○ RCR-02/03 |
| SES「精算を計算」 | なし（請求書は未生成） | ○ SES-01〜04 |
| 2026-08 など未生成月で「一括生成」 | **あり**（新しい請求書＋仕訳） | ✕ 実行しない（解説のみ） |

## 後片付けの原則（重要）

- 見積（下書き）・検収（下書き）・受注は各**詳細画面の赤い削除ボタン**（「この見積を削除」「この検収を削除」「この受注を削除」。確認ダイアログ付き）で**すべて削除**する（削除で採番も復元される。一覧に削除ボタンは無い＝ADR-0026。見積は下書きのみ・検収は下書きのみ・受注は配下に検収が無い場合のみ削除できる）。
- 検収は**確定（売上計上）まで進めない**。入金は**確定（消込）まで進めない**——ガードのメッセージ確認と自動セットの確認まで。
- 契約マスタの有効フラグ等を変更した分岐は、**必ず元の値に戻す**手順を末尾に置いている。実行し忘れると次回の定期請求実行の結果が変わる。
- 全分岐の後、仕訳帳の最終番号と Σ が分岐実行前と同じであることを確認する（09_帳票検証 9-12 の検算クエリ）。
