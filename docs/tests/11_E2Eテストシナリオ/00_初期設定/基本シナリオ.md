# 00_初期設定 基本シナリオ（seed の確認・期首残高・予算・権限の境界）

> 改訂: 2026-07-19（ロール別ページフレーム再編 ADR-0028 に追随）／ 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041）／ **更新: 2026-08-09 現行化（ADR-0042〜0048）**
> **2026-08-09 現行化の要点**: ①着地は**全員が業務ポータル**（0-1 を全面改訂）。②組織確認を**部課 2 階層**の現行 seed に更新し、手順 4 を「営業部に兼務行を追加」から「**ユーザー管理で kaihatsu1_kacho1 の営業機能フラグを ON にする**」へ差し替え（ADR-0043。部門メンバー行は見え方に影響しなくなった）。③0-3〜0-11 の導線をサイドバー方式に（「ほかの業務」全廃）。④**0-12（権限境界）を「全員ポータル着地・サイドバーの出し分け・直 URL 拒否」の 5 パターンに全面再設計**。**登録するマスタのデータ値・期首残高・予算の金額は一切不変。**
> **実務上の位置づけ**: 会計ソフト導入時に一度だけ行う「帳簿の器づくり」。制度の器（科目・税・期間・組織・承認ルート）は DDL seed で整備済みなので、本章では①それらを**理解しながら確認**し、②導入時に必ず人手で行う **期首残高の投入** と **予算登録**（および**機能権限の付与**）を行い、③**権限の境界**（機能権限フラグ×フレームゲート）を体験する。
> ここで押さえる設計思想は 3 つ——「**組織・承認ガバナンスはシステム管理者、業務・会計マスタは経理**」（ADR-0041）、「**誰に何の画面を見せるかは組織所属ではなく機能権限フラグで決める**」（ADR-0043 の 3 軸分離）、「**帳簿は仕訳と期首残高だけから導出される**」。
>
> **使用ユーザー**: admin（システム管理者）／soumu_bucho（経理）／確認で kaihatsu1_ippan・eigyo_kacho1・kaihatsu1_kacho1・kaihatsu1_bucho。パスワードは全員ユーザー名と同じ。

### ステップ 0-2: 組織とユーザーの確認・機能権限の付与（3 軸分離を体で覚える）

- **この業務の目的（実務解説）**: 誰がどの部・どの課の何者かをシステムで確認する。ユーザーは「{部}_{役職}」の命名規約（ADR-0018）で 26 名 seed 済み。本章最大の学びどころは **3 軸分離**（ADR-0043）——「**何の画面が使えるか（機能権限フラグ）**」「**どこに所属するか（部門メンバー）**」「**誰の稟議を決裁するか（課長/部長行）**」は別物で、別の場所で編集する。あわせて、販売シナリオの前提となる**営業機能フラグの付与**（開発課長 = PM が見積・受注も扱う IT 受託の実態）をここで行う。
- **操作する画面**: （admin でログインし直す）サイドバー「システム管理」→ MasterAdmin >【組織】ユーザー管理／部門
- **具体的な操作手順**:
  1. Logout → **admin / admin** でログインし直す。ポータル左サイドバーの「**システム管理**」を押す（MasterAdmin の**ユーザー管理**に着地する）。
  2. **「ユーザー管理」**: 26 名を確認。**ロール欄は存在しない**。任意の行を開くと詳細に権限チェック群があり、「**業務機能**」グループ（営業機能／経理機能／経費精算／工数入力）と「**システム管理**」（システム管理者）に分かれている。**これが機能権限の真実**で、チェックボックスで直接付け外しする（ADR-0043）。seed の状態は 経理機能 = 総務部の 5 名／営業機能 = 営業部・SaaS事業部の 10 名／経費精算・工数入力 = admin 以外の全員 ON／システム管理者 = admin のみ。**「承認者」だけは読み取り専用表示**で、「部門の課長/部長・承認テンプレートの指名から自動判定（部門管理で編集）」の注記が付く。
  3. **「部門」**: 部門は**部課 2 階層**（ADR-0044）。**部 6 件**（全社共通・総務部・営業部・開発1部・開発2部・SaaS事業部）と、**課 10 件**（全社共通を除く 5 部にそれぞれ「第一課」「第二課」）の計 16 ノードが並び、課の行には親部門が入っている。**部門種別の列は無い**（ADR-0043 で削除。組織マスタから権限概念が除かれた）。
     - 「**開発1部**」（部ノード）を開き、部門メンバーが 部長 田中宏（**部長**）・部長代理 渡辺剛（**部長**）の 2 行であることを確認。
     - 「**開発1部 第一課**」を開き、第一課長 山本由美（**課長**）・一般 小林美咲（**一般**）の 2 行を確認。「**開発1部 第二課**」は 第二課長 中村拓也（**課長**）の 1 行。
     - 全社の部門メンバーは合計 **25 行**（部ノードの部長行 10 ＝ 5 部 × 部長・部長代理／課ノードの課長行 10／課ノードの一般行 5）。**部門メンバー行は「組織の事実」と「承認ルート」だけを決め、画面の見え方には影響しない**（ADR-0043 の眼目）。
  4. **機能権限の付与（必須・02_販売の前提）**: 「ユーザー管理」に戻り、**kaihatsu1_kacho1（開発1部 第一課長 山本由美）**の詳細を開く。「**営業機能**」チェックが OFF であることを確認したうえで **ON にして保存**する（旧版では「営業部に兼務のメンバー行を追加する」手順だったが、ADR-0043 でこの間接付与は廃止された。※デモ用に使い込んだ DB では既に ON になっていることがある。その場合は ON であることの確認だけでよい）。
- **期待される結果**:
  - **直接的な結果**: 上記の確認ができ、山本由美の営業機能フラグが ON になる。**保存した瞬間に見え方が変わる**（キャッシュ列でも導出でもない、直接の真実だから）。
  - **波及する結果**: 山本由美は開発1部 第一課の課長のまま**営業業務（SalesStaff）が使える**ようになる（0-12 と 02_販売で実地確認）。組織上は開発1部のままで、営業部のメンバー一覧は汚れない——「権限を変えるために組織の事実を偽らなくてよい」のが 3 軸分離の効能。
  - **承認との関係**: 部門メンバーの**課長/部長行**が経費承認ルートの自動解決を駆動する（01_経費精算で実証）。承認者は申請者の所属ノードから親方向へ **walk-up** して解決されるので、**小林美咲（第一課）の課長決裁は第一課長 山本由美だけ**に回り、第二課長 中村拓也には回らない（ADR-0044）。
  - 「全社共通」にユーザーも課もいないのは仕様——部門マスタは組織図と**費用集計軸**の 2 役で、全社共通は家賃など共通費の帰属先。なお**伝票の部門は「部」のみ**が候補になる（課は出ない）。

### ステップ 0-6: 費目と承認フローテンプレートの確認

- **この業務の目的（実務解説）**: 費目は経費精算の入口の言葉（裏で勘定科目・税区分に変換）。承認テンプレートは「金額×費目でどのルートが選ばれるか」の定義で、承認者は「申請者の部門の課長／部長」という**動的解決**。組織が変わってもテンプレートは書き換え不要。**費目は経理（MasterBusiness）、承認テンプレートはシステム管理者（MasterAdmin）**——マスタの管轄が分かれていることも確認する。
- **操作する画面**: （soumu_bucho）MasterBusiness >【会計マスタ】費目 →（admin でログインし直す）サイドバー「システム管理」→ MasterAdmin >【承認】承認フローテンプレート
- **具体的な操作手順**:
  1. soumu_bucho のまま【会計マスタ】費目: 10 種を確認（交際費 = 交際費フラグ ○、備品 = 資産性 ○）。
  2. Logout → **admin / admin** でログインし、サイドバー「システム管理」→【承認】承認フローテンプレート: 4 種（**経費_課長まで／経費_部長まで／経費_課長まで＋総務／経費_部長まで＋総務**）を開く。名称の規約は「**〜まで**」= 役職ラインの終端・「**＋総務**」= 合議段で、**段は積み上げ**（`経費_部長まで` は「課長 → 部長」の 2 段、`経費_部長まで＋総務` は 3 段。ADR-0048）。「経費_課長まで＋総務」の総務段に**指定ユーザー「総務部 第一課長 石川真理」が設定済み**であることを確認する。
  3. あわせて【承認】**承認ルート判定**を開き、どの金額帯・費目にどのテンプレートを当てるかの 5 ルールを確認する（全費目 0〜29,999 / 30,000〜199,999 / 200,000〜、交際費 0〜29,999 / 30,000〜。ADR-0023 のマスタ駆動）。
- **期待される結果**: 上記のとおり。まっさら DB でもテンプレートの承認者が解決済みなのは、ユーザー seed（085）がテンプレ seed（090）より先に走る設計になっているため（ADR-0018。旧版で必要だった手動補正は不要になった）。**役職段（課長・部長）は個人を指名せず、申請時に申請者の所属ノードからの walk-up で解決される**ので、組織が変わってもテンプレートは書き換え不要（ADR-0044）。
