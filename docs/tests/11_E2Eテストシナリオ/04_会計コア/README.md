## 本章の導線（現行・ADR-0042/0045）

- ログインすると**全員が業務ポータル**（Main/PortalHome）に着地する。旧「トップ画面」（`/{フレーム}/Top`）と「ほかの業務」リンクは全廃。
- ポータル左サイドバーの「**会計業務**」で会計フレームへ移動する。フレーム素 URL `/Accounting` を直に叩いた場合は**振替伝票**（既定業務画面）に着地する。
- 会計フレームのサイドバーは **仕訳**（振替伝票・定型仕訳・入出金起票・仕訳インポート）／**帳簿**（仕訳帳・総勘定元帳・出納帳・固定資産台帳）／**銀行**／**財務帳票**／**設定**（会計年度）のグループ構成。本書の【仕訳】【帳簿】【設定】表記はこのグループを指す。先頭の「ホーム」でいつでもポータルへ戻れる。
- アクセス条件は**経理機能フラグ**（`app_users` の直接付与・ADR-0043）。部門メンバーシップでは機能の見え方は変わらない。admin（システム管理者）は業務フラグを持たないため会計フレームに入れない（職務分掌）。
- 経理の未処理は**ポータルの「経理の作業キュー」**に集約されている（例:「▶ 下書きのままの伝票: N 件」「▶ 未起票の銀行明細: N 件」）。**0 件の項目は行ごと消える**——「0 件と表示される」ではなく「行が無い」が正。

## 実行時の前提（重要）

- **E2E 完走後の DB は第 18 期が全期間締め＋年度クローズ済み**。起票系の分岐を実行する前に【設定】会計年度 > 第18期 を「進行中」に戻し、**使用する月次期間（分岐ごとに明記）を「進行中」に戻す**こと。終わったら締め直す。
- 逆に「締め済みガード」を確認する分岐は、締まっている今の状態がそのまま前提になる（開け直す前に実行すると効率的）。

## 税行生成の仕様（2026-07-10 改修後の正）

- **税行は「確定」時のみ生成**する。下書きは**入力した金額のまま**保存される（税行なし）。
- 確定に失敗（貸借不一致・保存失敗）すると、変換済みの明細を**入力状態に巻き戻す**（RestoreInputState）。→ そのまま修正して再確定しても二重に税抜化されない（旧バグの回帰確認が JRN-05）。
- 旧仕様（税抜変換済み）の下書きは、**開いた瞬間に入力状態へ復元**して表示される。
- 税行が立たない条件: 税入力「なし」／税率 0／課税売上・課税仕入以外の課税種別（非課税・不課税・対象外・免税）。※税区分そのものは **NOT NULL**（「未設定」は廃止し「対象外」で表す・ADR-0052）。
- **入出金起票も同じ計算を使う**（ADR-0053）。相手科目の既定税区分が課税なら入力額を**内税**として扱い、確定と同時に税行を生成する（下書きを経ないので生成は 1 回だけ）。外税入力は持たない。
- 端数は**常に切り捨て**。内税: 税 = 税込 × 10/110、外税: 税 = 税抜 × 10/100。
- インボイス経過措置は取引日で控除割合マスタを期間解決: **〜2026-09-30 = 80%／2026-10-01〜2028-09-30 = 70%**（期間外は 0%=全額本体）。

## 後片付けの原則（重要）

- **確定（posted）した伝票は削除できない**（詳細画面にも削除ボタンが出ない設計。ADR-0026: 一覧の削除ボタンは全廃）。分岐は原則**ブロック確認または下書きまで**で止め、下書きは**詳細画面の赤ボタン「この下書き伝票を削除」**（確認ダイアログ付き）で削除する。これで帳簿への影響ゼロ。
- **【任意実行】と記した分岐（JRN-08〜12・CSH-03・IMP-07）は伝票を確定させる**。実行すると全仕訳台帳の Σ=11,852,675・09_帳票検証 の総合検算・伝票番号の並びからずれる。実行するなら (a) 検証をやり直す前提の使い捨て環境で行うか、(b) 直後に**赤伝（反対仕訳）で取り消す**（残高は戻るが伝票件数・Σは増える）。迷ったらスキップしてよい——挙動の期待値はコード根拠付きで本文に書いてある。
