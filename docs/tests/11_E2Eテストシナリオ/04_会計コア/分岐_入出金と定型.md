## 入出金起票（CSH-01〜05）

### CSH-01: 必須 5 項目の連続ブロック
- **操作手順**（【仕訳】入出金起票。既定値: 日付=本日・現預金=普通預金・入出金=入金）:
  1. 日付を**空に消して**「起票する」→「**日付を入力してください**」。
  2. 日付を戻し、現預金科目を空に →「**現預金科目を選択してください**」。
  3. 現預金を戻し、入出金を空に →「**入出金を選択してください**」。
  4. 入出金を戻し、相手科目を未選択のまま →「**相手科目を選択してください**」。
  5. 相手科目（受取利息）を選び、金額 空/0 →「**金額を入力してください**」（0 も同メッセージ。`<= 0` 判定）。
- **期待される結果**: 5 種のトーストが順に出る。仕訳は 1 本も作られない（仕訳帳が無変化）。
- **確認ポイント**: フォーム初期値（本日・普通預金・入金）が毎回セットされている（Detail_OnAfterInit）。

### CSH-02: 日付ガード（年度なし・締め済み）
- **操作手順**（明細を正しく埋めた状態で: 現預金=普通預金・入金・相手科目=受取利息・金額 100）:
  1. 日付「**2024-06-15**」→「起票する」→ トースト「**日付に対応する会計年度がありません**」。
  2. 日付「**2026-04-15**」（締め済みの月次 1）→「**日付の期間は締め済みです**」。
- **期待される結果**: どちらもトースト（振替伝票のフィールドエラーと**表示形式が違う**——このモジュールは表示専用でフィールドエラーを使わない）。仕訳は作られない。
- **確認ポイント**: 締め済みメッセージは「**{日付項目名}の期間は締め済みです**」の型に統一されている（改善候補 B-1・2026-08-13）。振替伝票は「取引日の期間は締め済みです」で、差は項目名だけ——文言照合はこの型で行う。揃ったのは文言であって表示形式ではない（上記のとおりトースト対フィールドエラー）。

### CSH-03: 出金方向の仕訳形と消費税行【任意実行・帳簿影響あり】
- **この分岐の目的**: 基本 4-6/4-7 は入金方向・非課税の相手科目のみだった。出金で貸借が反転して「**D 相手科目 / C 現預金**」になること、および**課税科目を選ぶと消費税行が生成される**（ADR-0053）ことの実証。
- **操作手順**（月次 4 を進行中に戻して）: 日付 2026-07-05・現預金「小口現金」・入出金「**出金**」・相手科目「会議費」・金額 1,100・摘要「CSH-03 出金テスト」→「起票する」。
- **期待される結果**: 結果ラベル「仕訳 No.42 を起票しました（CSH-03 出金テスト 1,100 円**／うち消費税 100 円**）」（No は実行時点の次番号）。仕訳帳で **D 会議費 1,000 / D 仮払消費税 100（摘要「消費税（行1）」）/ C 小口現金 1,100** の **3 行**——会議費の既定税区分が課税仕入 10% なので、入力額 1,100 を**内税**として分解する（1,100 × 10/110 = 100）。税行は本体行と同じ借方に付くため貸借は一致（1,100 = 1,100）。
- **確認ポイント**: 出納帳（小口現金）ではこの行の相手科目が「**諸口**」になる（3 行仕訳のため）。非課税・不課税・対象外の相手科目なら従来どおり 2 行で、相手科目名が出る。
- **後片付け**: 赤の入出金（入金・同額 1,100）を起票すると税行込みの鏡像（C 会議費 1,000 / C 仮払消費税 100 / D 小口現金 1,100）になり、仮払消費税も打ち消される。赤伝を振替伝票で切ってもよい。全仕訳台帳からずれるため README の原則に従うこと。

### CSH-04: 成功後のフォームクリア（連続入力）
- 基本 4-6 で実施済み（起票成功後に金額・摘要欄がクリアされ、日付・科目は保持——連続入力向けの挙動）。参照のみ、再実行不要。

### CSH-05: 経理専用の多層防御
- **操作手順**: kaihatsu1_kacho1（開発1部 第一課長。承認者だが**経理機能フラグ OFF**）でログインする。
  1. 着地した**業務ポータル**の左サイドバーに「**会計業務**」が**無い**ことを確認（リンクの表示条件が経理機能フラグのため）。
  2. URL 直打ちで `/Accounting/CashEntry`（入出金起票）を開く。ついでに `/Accounting`（フレーム素 URL＝振替伝票に着地するはずの経路）でも同じことを確認する。
- **期待される結果**: どちらも「**ページフレームへのアクセス権限がありません**」——会計フレーム（`/Accounting`）自体のゲート（`HasAccountingAccess`）が先に効き、着地画面にも個別画面にも到達できない。
- **補足（コード根拠）**: 仮に画面へ到達できてもスクリプト冒頭の権限チェックが「**入出金の起票は経理のみ実行できます**」で拒否する（多層防御。UI から到達不能なため通常この文言は見えない——見えたらフレームゲートの退行を疑うこと）。
- **確認ポイント**: 承認者かどうか・部門メンバーシップの有無は**機能の見え方に影響しない**（権限は `app_users` の直接フラグ＝ADR-0043）。同じ理由で、経理機能フラグを持つユーザーは所属部門に関係なく会計フレームに入れる。

## 定型仕訳（CSH-06〜09）

### CSH-06: 未保存の定型から起票 → ブロック
- **操作手順**: 【仕訳】定型仕訳 > 新規作成 → 名前「CSH-06 テスト定型」だけ入力し、**保存せずに**「この定型から伝票を起票」。
- **期待される結果**: トースト「**定型を保存してから起票してください**」（IsNewData ガード）。
- **後片付け**: 保存せず離脱。

### CSH-07: 明細のない定型から起票 → ブロック
- **操作手順**: 新規作成 → 名前「CSH-07 明細なし」を入力し**明細 0 行のまま**「登録」→ 保存後に「この定型から伝票を起票」。
- **期待される結果**: トースト「**明細がありません。明細を登録してから起票してください**」（明細は DB から取り直して判定——画面の見た目でなく保存済み明細が基準）。
- **後片付け**: この定型を一覧から削除。

### CSH-08: T03（社会保険料）からの起票 → 下書き内容の確認 → 削除
- **この分岐の目的**: 基本シナリオで唯一使わなかった seed 定型 T03 の内容確認と、「起票＝下書き」の後片付け容易性の実証。
- **操作手順**:
  1. 定型仕訳 > 「T03 社会保険料の納付」を開く → 明細構成を確認（会社負担分の法定福利費＋従業員預り分の預り金／貸方 普通預金）。
  2. 「この定型から伝票を起票」→ トースト「**下書き伝票を作成しました。金額を確認して確定してください**」→ 振替伝票の下書きへ自動遷移。
  3. 下書きの内容を確認: 取引日=**本日**・種別=振替・状態=下書き（伝票番号なし）・明細がテンプレートどおりコピーされ、**税行は無い**（税行は確定時に生成する設計——保険料改定に自動追随）。
  4. **確定せず**一覧に戻り、この下書きを**削除**。
- **期待される結果**: 上記のとおり。定型マスタ（T03）自体は起票しても無変化（コピーして使われる）。
- **帳簿への影響**: なし（下書き削除で完結）。

### CSH-09: 起票後の金額修正 → 確定（参照）
- 基本 4-4（T02 給与: 起票→取引日変更→確定 No.18）で実施済み。金額の修正も同じ編集経路（下書きは全項目編集可能）。参照のみ。
