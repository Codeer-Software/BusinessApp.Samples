## 入出金起票（CSH-01〜05）

> **2026-08-14 に方式が変わった（ADR-0055）**。入力しても即仕訳にはならず、**下書きに積んで「まとめて起票する」**。
> 下書きは**入力者ごと**に分かれる（他人の下書きは見えない）。ボタンは「明細に追加」「変更を保存」「まとめて起票する」「下書きをすべて破棄」。

### CSH-01: 入力ガード（下書きに積む前に弾く）
- **操作手順**（【仕訳】入出金起票。既定値: 取引日=本日・入出金=入金。現預金科目と取引日は自分の直近の下書きから引き継ぐ）:
  1. 何も入れずに「明細に追加」→「**取引日を入力してください**」（取引日を消した場合）／既定のままなら「**現預金科目を選択してください**」。
  2. 現預金科目 `小口現金` を選び、相手科目 未選択 →「**相手科目を選択してください**」。
  3. 相手科目 `会議費`・金額 空 →「**金額を入力してください**」（0 も同じ。`<= 0` 判定）。
  4. 金額 1,100・**部門 未選択** →「**部門を選択してください（損益科目の仕訳には部門が必要です）**」（ADR-0056）。
  5. 現預金科目 `普通預金`・相手科目 `普通預金` →「**相手科目に同じ現預金科目は選べません**」。
- **期待される結果**: すべてトースト。**下書きは 1 行も増えない**（仕訳はそもそも作られない）。
- **確認ポイント**: 部門が要るのは**損益科目**の相手科目だけ。相手科目を `普通預金` 等の BS 科目にすると部門なしで通る。
  現預金どうしの振替は**別の科目なら作れる**（普通預金 → 小口現金＝小口現金の補充）。

### CSH-02: 締め済み・年度なしは「その行だけスキップ」
- **操作手順**: 正しく埋めた下書きを 2 行積む。片方の取引日を **2026-04-15**（締め済みの月次 1）にして「まとめて起票する」。
- **期待される結果**: 結果ラベル「**起票 1 件（No.x〜x） ／ スキップ 1 件 ［期間が締め済み］ ／ 失敗 0 件**」。
  **締め済みの行だけ下書きに残り、他の行は起票される**。取引日 2024-06-15 なら理由は「会計年度なし」。
- **確認ポイント（方式の違い）**: 旧方式は 1 本ずつ起票しトーストで弾いていた。現方式は**銀行明細の一括起票と同じ**で、
  1 行の不備で全体が止まらない。理由は結果ラベルに集約される（同じ理由は 1 回だけ出る）。

### CSH-03: 出金方向・消費税行・部門の付き方【任意実行・帳簿影響あり】
- **この分岐の目的**: 出金で貸借が反転すること、課税科目なら消費税行が生成されること（ADR-0053）、
  部門が損益行と税行にどう付くか（ADR-0056）の 3 点をまとめて実証する。
- **操作手順**（月次 4 を進行中に戻して）: 取引日 2026-07-05・現預金「小口現金」・入出金「**出金**」・
  相手科目「会議費」・部門「**開発1部**」・金額 1,100・摘要「CSH-03 出金テスト」→「明細に追加」→「まとめて起票する」。
- **期待される結果**: 結果ラベル「起票 1 件（No.x〜x） ／ **うち消費税 100 円** ／ スキップ 0 件 ／ 失敗 0 件」。
  仕訳帳で **D 会議費 1,000（開発1部）／ D 仮払消費税 100（開発1部・税行）／ C 小口現金 1,100（全社共通）** の 3 行。
  貸借一致（1,100 = 1,100）。
- **確認ポイント（部門）**: 指定した部門が付くのは**損益科目の行**だけ。現預金の行は保険が「全社共通」で埋め、
  **税行は親行（会議費）の部門を継ぐ**。
- **確認ポイント（出納帳）**: 小口現金の出納帳ではこの行の相手科目が「**諸口**」（3 行仕訳のため）。
- **後片付け**: 逆方向（入金・同額・同じ部門）を下書きに積んで起票すると税行込みの鏡像になり、正味 0 に戻る。
  全仕訳台帳からずれるため README の原則に従うこと。

### CSH-04: 下書きの編集・削除（新方式の主眼）
- **操作手順**: 下書きを 1 行積む → 表の金額セルを直接書き換える →「変更を保存」→ 再読込して値が残ることを確認。
  次に行のゴミ箱を押す → **保存せずに再読込すると復活する** → もう一度ゴミ箱 →「変更を保存」→「**変更を保存しました（1 行を削除）**」。
- **期待される結果**: 上記のとおり。**ListField の行削除はメモリ上の操作**で、保存して初めて DB に反映される（FB-040）。
- **確認ポイント**: 「まとめて起票する」は起票の前に画面の編集内容を保存してから走る。
  つまり「直したつもりの金額」で起票されたり、消したはずの行が起票されることは無い。

### CSH-05: 経理専用の多層防御
- **操作手順**: kaihatsu1_kacho1（開発1部 第一課長。承認者だが**経理機能フラグ OFF**）でログインする。
  1. 着地した**業務ポータル**の左サイドバーに「**会計業務**」が**無い**ことを確認（リンクの表示条件が経理機能フラグのため）。
  2. URL 直打ちで `/Accounting/CashEntry`（入出金起票）を開く。ついでに `/Accounting`（フレーム素 URL＝振替伝票に着地するはずの経路）でも同じことを確認する。
- **期待される結果**: どちらも「**ページフレームへのアクセス権限がありません**」——会計フレーム（`/Accounting`）自体のゲート（`HasAccountingAccess`）が先に効き、着地画面にも個別画面にも到達できない。
- **補足（コード根拠）**: 仮に画面へ到達できてもスクリプト冒頭の権限チェックが「**入出金の起票は経理のみ実行できます**」で拒否する（多層防御。UI から到達不能なため通常この文言は見えない——見えたらフレームゲートの退行を疑うこと）。
- **確認ポイント**: 承認者かどうか・部門メンバーシップの有無は**機能の見え方に影響しない**（権限は `app_users` の直接フラグ＝ADR-0043）。同じ理由で、経理機能フラグを持つユーザーは所属部門に関係なく会計フレームに入れる。

## 定型仕訳（CSH-06〜09）

### CSH-06: 未保存の定型から起票 → ブロック
- **操作手順**: 【仕訳】定型仕訳 > 新規作成 → 名前「CSH-06 テスト定型」だけ入力し、**保存せずに**「この定型から伝票を起票」。
- **期待される結果**: トースト「**定型を保存してから起票してください**」（IsNewData ガード）。
- **後片付け**: 保存せず離脱。

### CSH-07: 明細のない定型から起票 → ブロック
- **操作手順**: 新規作成 → 名前「CSH-07 明細なし」を入力し**明細 0 行のまま**「登録」→ 保存後に「この定型から伝票を起票」。
- **期待される結果**: トースト「**明細がありません。明細を登録してから起票してください**」（明細は DB から取り直して判定——画面の見た目でなく保存済み明細が基準）。
- **後片付け**: この定型を一覧から削除。

### CSH-08: T03（社会保険料）からの起票 → 下書き内容の確認 → 削除
- **この分岐の目的**: 基本シナリオで唯一使わなかった seed 定型 T03 の内容確認と、「起票＝下書き」の後片付け容易性の実証。
- **操作手順**:
  1. 定型仕訳 > 「T03 社会保険料の納付」を開く → 明細構成を確認（会社負担分の法定福利費＋従業員預り分の預り金／貸方 普通預金）。
  2. 「この定型から伝票を起票」→ トースト「**下書き伝票を作成しました。金額を確認して確定してください**」→ 振替伝票の下書きへ自動遷移。
  3. 下書きの内容を確認: 取引日=**本日**・種別=振替・状態=下書き（伝票番号なし）・明細がテンプレートどおりコピーされ、**税行は無い**（税行は確定時に生成する設計——保険料改定に自動追随）。**部門も定型の明細から引き継がれる**（ADR-0056。定型側が空なら確定時に「全社共通」で埋まる）。
  4. **確定せず**一覧に戻り、この下書きを**削除**。
- **期待される結果**: 上記のとおり。定型マスタ（T03）自体は起票しても無変化（コピーして使われる）。
- **帳簿への影響**: なし（下書き削除で完結）。

### CSH-09: 起票後の金額修正 → 確定（参照）
- 基本 4-4（T02 給与: 起票→取引日変更→確定 No.18）で実施済み。金額の修正も同じ編集経路（下書きは全項目編集可能）。参照のみ。

## 後片付け（必須）

- 入出金起票に**下書きが残っていないこと**（「下書きをすべて破棄」で片付く）。入力欄に値が残っているだけなら影響なし。
- CSH-07 の定型「CSH-07 明細なし」・CSH-08 の下書き伝票が削除済みであること。
- CSH-03 を実行した場合: 取消の仕訳を確認し、月次 4 と第18期を**締め済みに戻す**。
