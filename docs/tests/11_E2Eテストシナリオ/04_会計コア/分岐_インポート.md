# 分岐シナリオ: 仕訳 CSV インポート（表記ゆれ・スキップ理由・下書き取込）

> 改訂: 2026-07-10 新規作成／2026-07-19 削除経路をADR-0026に追随。**IMP-01〜06 は帳簿への影響なし**——受理系のテストは「下書きとして取り込む」を ON にして draft で取り込み、確認後に各伝票の詳細から「この下書き伝票を削除」で削除する。**IMP-07 のみ確定取込＝【任意実行】**。
> 更新: 2026-08-09 導線・権限記述を現行化（ADR-0042〜0048）＋ IMP-05 の「税行付き下書きが畳まれる」注意書きを**解消済み**に更新。取込内容・期待値は不変。
> 配役: soumu_bucho（総務部 部長 山田太郎・**経理機能フラグ ON**）。画面は**会計フレーム**（ポータル左サイドバー「会計業務」→ 素 URL `/Accounting` は振替伝票に着地）の【仕訳】仕訳インポート。
> 前提: 受理系（IMP-02/05/06）は対象日付の期間が open であること → 月次 4（2026-07）を進行中に戻す。スキップ系（IMP-01/03/04）は現状のままでよい。
> CSV 形式: `伝票グループ,日付,借貸,科目コード,金額,税区分コード,摘要`（税区分・摘要は省略可）。

## IMP-01: 空入力・全行解析不能

- **操作手順**:
  1. CSV 欄を**空のまま**「取り込む」→ トースト「**仕訳CSVを貼り付けてください**」。
  2. 以下（ヘッダ行と日本語文だけ）を貼って「取り込む」:
     ```
     伝票グループ,日付,借貸,科目コード,金額
     これはテストです
     ```
- **期待される結果**: 結果ラベル「**取込 0 伝票（解析不能行 2 行）**」・警告トースト「**取り込める仕訳がありませんでした**」。ヘッダ行・ゴミ行（日付も金額も解析できない行）は**黙ってスキップ**され件数だけ報告される。
- **帳簿への影響**: なし。

## IMP-02: 表記ゆれの受理（借貸・日付・金額）【下書き取込で確認】

- **この分岐の目的**: 他ソフトの出力形式の揺れを 1 伝票に混在させ、正規化が効くことを確認する。
- **操作手順**: 「**下書きとして取り込む」を ON** にして以下を貼り付け →「取り込む」:
  ```
  Z001,2026-07-15,借方,6140,"1,500",,IMP-02 表記ゆれ1
  Z001,2026.7.15,貸,1000,¥500,,IMP-02 表記ゆれ2
  Z001,2026年7月15日,C,1010,1000円,,IMP-02 表記ゆれ3
  ```
- **期待される結果**: 結果ラベル「**取込 1 伝票（3 行）（下書き）** / スキップ 0 伝票 / 保存失敗 0 / 解析不能行 0 行」。受理された揺れ:
  - 借貸: `借方`・`貸`・`C`（ほか `D`・`借`・`貸方` も可）
  - 日付: `2026-07-15`・`2026.7.15`・`2026年7月15日`（すべて同日と解釈——同一伝票の日付一致チェックも通る）
  - 金額: `"1,500"`（引用符＋カンマ）・`¥500`・`1000円`
- **確認ポイント**: 振替伝票一覧に**状態「下書き」・伝票番号なし**で入る。開くと 3 行（借方 消耗品費 1,500／貸方 現金 500・小口現金 1,000）。
- **後片付け**: この下書きを詳細から**「この下書き伝票を削除」で削除**（下書き取込の削除可能性が IMP-06 の主題でもある）。

## IMP-03: スキップ理由の網羅（1 回の取込に NG 伝票を束ねる）

- **操作手順**（下書き ON/OFF どちらでも結果は同じ——全伝票スキップされるため）:
  ```
  G101,2026/07/15,D,9999,1000,,科目コード不存在
  G101,2026/07/15,C,1000,1000,,科目コード不存在
  G102,2026/07/15,D,6140,1000,ZZZ,税区分コード不存在
  G102,2026/07/15,C,1000,1000,,税区分コード不存在
  G103,2026/07/15,X,6140,1000,,借貸が不正
  G103,2026/07/15,C,1000,1000,,借貸が不正
  G104,2026/07/15,D,6140,1000,,日付不一致
  G104,2026/07/16,C,1000,1000,,日付不一致
  G105,2026/07/15,D,6140,0,,金額ゼロ
  G105,2026/07/15,C,1000,0,,金額ゼロ
  G106,2026/07/15,D,6140,5000,,貸借不一致
  G106,2026/07/15,C,1000,4000,,貸借不一致
  ```
- **期待される結果**: 結果ラベル「**取込 0 伝票 / スキップ 6 伝票 [G101: 科目コード 9999 が存在しません] [G102: 税区分コード ZZZ が存在しません] [G103: 借貸が不正です（X）] ほか / 保存失敗 0 / 解析不能行 0 行**」＋警告トースト。
  - スキップ理由の表示は**先頭 3 件＋「ほか」**（G104「同一伝票内で日付が一致しません」・G105「金額は 1 円以上で入力してください」・G106「貸借不一致（借方 5,000 / 貸方 4,000）」はラベルに出ないが同様にスキップ）。
  - 検証は**伝票（グループ）単位のオール・オア・ナッシング**——G101 の 2 行目（科目 1000=正しい行）も伝票ごと落ちる。
- **確認ポイント**: 理由を個別に見たい場合はグループを 3 つずつに分けて 2 回に取り込む。G105 の金額ゼロ行は「日付が解析でき金額 0」のため解析不能でなく**行として読まれた上で**金額検証に落ちる（IMP-01 のゴミ行との違い）。
- **帳簿への影響**: なし（全伝票スキップ）。

## IMP-04: 締め済み期間・年度なしのグループスキップ

- **操作手順**（第18期が締まったままの状態で実行するのが手早い）:
  ```
  G201,2026/04/15,D,6140,1000,,締め済み期間
  G201,2026/04/15,C,1000,1000,,締め済み期間
  G202,2024/06/15,D,6140,1000,,年度なし
  G202,2024/06/15,C,1000,1000,,年度なし
  ```
- **期待される結果**: 「取込 0 伝票 / スキップ 2 伝票 **[G201: 2026/4/15 の期間は締め済みです] [G202: 2024/6/15 に対応する会計年度がありません]** / …」。
- **確認ポイント**: 振替伝票と同じ期間ガードがインポート経路にも入っている（すべての起票経路で共通、という統制の実証）。「下書きとして取り込む」を ON にしても**締め済みガードは免除されない**（draft でも同じ検証を通る）。
- **帳簿への影響**: なし。

## IMP-05: 税科目行（1900/2200）の自動マーク（下書きで開いても畳まれない）

- **操作手順**: 「下書きとして取り込む」**ON** で基本 4-10 と同型の 3 行を貼る:
  ```
  Z002,2026/07/15,D,6220,13637,PUR_10,IMP-05 電気代
  Z002,2026/07/15,D,1900,1363,,IMP-05 電気代 消費税
  Z002,2026/07/15,C,1020,15000,,IMP-05 電気代
  ```
- **期待される結果**: 取込 1 伝票（3 行）（下書き）。科目コード **1900（仮払消費税）の行は税行として自動マーク**される（2200 仮受消費税も同様）——確定取込した場合に消費税集計表で税額側に正しく載るための処理（基本 4-10 で確定側は実証済み）。
- **【旧注意事項は解消済み（2026-08-09 現在）】**: かつては「税行マーク付きで**下書き**取込した伝票を振替伝票画面で開くと、旧仕様下書き互換の復元処理（RestoreInputState）が働いて**税行が本体行へ畳まれた表示**になる」という癖があったが、**現行コードで解消済み**——`JournalEntry.Detail_OnAfterInit` が復元処理の対象から**インポート由来の伝票（`source_type = 'import'`）を除外**している（コード注記:「CSV インポート由来は税行込みの生データが正なので畳まない」）。
  - **確認手順**: 上で取り込んだ Z002 の下書きを【仕訳】振替伝票の一覧（状態「下書き」）から**開く** → 明細が **3 行のまま**（6220 13,637／1900 1,363／1020 15,000）で、金額が 1 円も変わっていないことを確認する。
  - したがって「行を無加工で取り込む」保証は**下書き取込でも維持される**（下書きのまま画面で内容確認 → そのまま確定、という運用が取れる）。移行データを下書き OFF（確定取込）で入れる 4-10 の運用は、伝票番号を即座に確定させたい場合の選択であって、下書き経由が危険だからではない。
- **後片付け**: この下書きを削除。

## IMP-06: 下書き取込の基本動作（番号なし・削除できる）

- **操作手順**: IMP-02 または IMP-05 の実行結果をそのまま使う（単独で行う場合は任意の 2 行一致 CSV を下書き ON で取込）。
- **期待される結果**:
  - 下書き伝票には**伝票番号が振られない**（番号は確定時にのみ採番——欠番を作らない設計）。
  - **業務ポータル**（Main/PortalHome）の「経理の作業キュー」に「**▶ 下書きのままの伝票: n 件**」としてカウントされる（クリックで振替伝票一覧へ）。
  - 詳細を開くと**「この下書き伝票を削除」で削除できる**（posted と違い削除ボタンが出る。一覧に削除ボタンは無い）→ 削除で帳簿・キューの件数とも元通り。IMP-05 のとおりインポート由来の下書きは**開いても税行が畳まれない**ので、内容を確認してから削除してよい。
- **帳簿への影響**: なし（削除まで実施）。

## IMP-07: 確定取込の再採番（出現順）【任意実行・帳簿影響あり】

- **この分岐の目的**: 確定取込は元データの伝票番号を持ち込まず、**年度内連番で出現順に再採番**することの実証。
- **操作手順**（月次 4 を進行中に戻して。下書き OFF）:
  ```
  A1,2026/07/15,D,6140,1100,,IMP-07 先
  A1,2026/07/15,C,1000,1100,,IMP-07 先
  B2,2026/07/15,D,6140,2200,,IMP-07 後
  B2,2026/07/15,C,1000,2200,,IMP-07 後
  ```
- **期待される結果**: 取込 2 伝票（4 行）。仕訳帳で A1 → No.42・B2 → No.43（実行時点の次番号から**CSV の出現順**に連番。伝票ごとに直前最大値+1 を取り直す方式）。
- **後片付け**: 赤伝 2 枚で取り消すか、使い捨て環境でのみ実行（README の原則）。月次 4 と第18期を締め直す。

## 後片付け（必須）

- 下書き取込した Z001・Z002 等が**すべて削除済み**であること（振替伝票一覧を状態「下書き」で確認——0 件が正）。
- 業務ポータルの「経理の作業キュー」から「▶ 下書きのままの伝票」の**行が消えている**ことを確認（0 件の項目は行ごと非表示になる仕様。本流の下書きが別に残っている環境ではその件数に戻っていること）。
- IMP-07 を実行した場合は取消仕訳と期間の締め直しを確認。
