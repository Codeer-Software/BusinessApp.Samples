## COR-01: 赤伝の日付原則 —— 元仕訳と同じ日付にする理由（機上解説＋月次推移で確認）

- **この分岐の意味**: 基本 7-2 では取消仕訳を**元仕訳と同じ 7/18** で切った。もし取消を別の月（例: 8/18）で切るとどうなるか——**両方の月の損益が歪む**（7 月は誤額の費用が立ったまま、8 月にマイナスの費用が出る）。期間損益を動かさないため「赤伝は元仕訳と同日付」が原則。
- **確認手順（読み取りのみ）**:
  1. 【財務帳票】月次推移表（PL・第18期）を開き、会議費の行を見る → 第 4 月（7 月）に **6,000**（誤 5,000 − 取消 5,000 ＋ 正 6,000）だけが載り、他の月は 0。
  2. 「もし取消が 8 月だったら: 7 月 = 11,000・8 月 = △5,000 になっていた」ことを机上で確認（数字の出どころ: 試算表の会議費 借方計 11,000／貸方計 5,000）。
- **期待される結果**: 同日付の赤黒訂正なら月次推移は「正しい金額が正しい月に 1 回だけ」現れる。
- **補足**: 締め済み月の誤りを翌月に訂正する場合は日付を揃えられない（締めガード）。その場合は**処理月で赤黒を切り、摘要に元伝票番号と理由を書く**運用にする（期間損益のズレを注記で補う——経費フォールバック 8-2 と同じ思想）。

## COR-02: 補助科目の付かない自動仕訳 —— 補助元帳の限界と運用

- **この分岐の意味**: 基本 7-6 で貸倒れの貸方 売掛金に補助科目 C003 を**手で**付けた。一方、検収の自動仕訳（No.32）には補助科目が付かない。補助元帳（取引先別の債権管理簿）を完全運用するには何が必要かを理解する。
- **確認手順（読み取りのみ）**:
  1. 【帳簿】総勘定元帳: 科目=売掛金・補助科目=**C003 株式会社テックイノベーション** で検索。
  2. → 出るのは**貸方 110,000（No.33 貸倒れ）の 1 行だけ**。No.32（C003 向け売上の借方 110,000）は補助が無いため**出ない**——補助ベースの残高は △110,000 に見えてしまう。
- **期待される結果**: 上記のとおり（実測済みの事実の再確認）。
- **運用の結論**: 自動仕訳（検収・入金・定期請求・SES）は現状補助科目を刻まないため、**取引先別の債権管理は売掛残高一覧（請求書ベース）が正**。補助元帳を債権管理に使いたい場合は、手動起票時に必ず補助を付ける＋自動仕訳への補助引き継ぎを将来課題とする（docs/05 バックログ）。

## COR-03: 取消（void）請求書は入金候補・売掛残高から消える

- **この分岐の意味**: 貸倒れ処理した INV-26-005 が、債権管理のどの画面からも「回収対象」に見えないこと（督促事故の防止）。
- **確認手順（読み取りのみ）**:
  1. 【営業業務】入金 > 新規作成 → 請求書セレクトを開く → 候補に **INV-26-005 が出ない**（未消込の INV-26-002 のみ出る。実測済み: 消込済みの 001/003/004 も出ない）。保存せず戻る。
  2. 【営業業務】売掛残高 → INV-26-005 の行が**無い**（取消は集計から除外）。
  3. 【営業業務】請求書 の一覧では INV-26-005 が状態「取消」で**参照できる**（記録は消えない——帳簿の貸倒損失 110,000 と突合可能）。
- **期待される結果**: 「回収対象からは消え、記録としては残る」の二面性が 3 画面で確認できる。

## COR-04: 会計マスタの職務分掌 —— 勘定科目は経理の管轄・admin は組織と承認のみ

- **この分岐の意味**: 基本 7-4 では soumu_bucho（経理）が業務マスタ（MasterBusiness）で貸倒損失科目を追加した。逆方向——admin（システム管理者）が会計マスタ・業務画面に**一切入れない**ことを確認する（ADR-0041: 会計マスタ・税制は経理管轄の MasterBusiness、admin は組織・承認の MasterAdmin のみ。旧体制〔ADR-0018: 制度マスタ=sysadmin・経理は閲覧のみ〕とは管轄が**逆転**している点に注意——経緯は基本 7-4 の解説参照）。
- **確認手順**:
  1. soumu_bucho（経理）で 業務マスタ > 会計マスタ/勘定科目 > 貸倒損失（6270）を開く → **編集できる**（有効フラグや表示順の変更が可能。変更した場合は元に戻す）。
  2. admin（システム管理者）でログイン → 着地は**業務ポータル**（Main/PortalHome）だが、業務フラグを持たないため中央には未読通知と「ユーザー・組織・承認ルートの管理はこちら →」しか出ず、左サイドバーも「通知」と「**システム管理**」だけになる（会計業務・営業業務・業務マスタのリンクが**存在しない**）。
  3. admin のまま URL を直打ちして、業務系フレームに**入れない**ことを確認する。いずれも「**ページフレームへのアクセス権限がありません**」:
     - `/MasterBusiness`（業務マスタの素 URL＝取引先に着地するはずの経路）・`/MasterBusiness/Account`（勘定科目）
     - `/Accounting`（会計業務の素 URL＝振替伝票に着地するはずの経路）・`/SalesBilling`（営業業務の素 URL＝請求書）
     - 入れるのは `/MasterAdmin`（システム管理＝ユーザー管理に着地）だけ。**旧 `/{フレーム}/Top` 形式の URL は現行では存在しない**（ADR-0045 でトップ画面全廃・フレーム素 URL が既定業務画面に着地する方式へ）。
  4. soumu_bucho に戻り、経理の業務画面（振替伝票の科目セレクト等）では科目データを**読める**ことも確認（マスタ編集画面と参照の分離は従来どおり）。
- **期待される結果**: サイドバーのリンク非表示とフレームゲート（`UserReadCondition`）の多層で、会計マスタの変更経路が経理（`/MasterBusiness`）に限定され、admin は業務・会計の世界に入れない（職務分掌）。判定は**部門メンバーシップではなく `app_users` の機能フラグ**（ADR-0043）——admin に部門所属を足しても業務画面は開かない。
