# 体験シナリオ: 受託開発案件の一巡（案件作成 → 納品・検収 → 請求 → 銀行入金）

> 作成: 2026-07-20。**現在のデモDB（第18期・最終仕訳 No.68 時点）の続きとして実行できる**ように、採番・金額・残高を現状に合わせて書いている。
> 新しい受託案件をひとつ立ち上げ、見積 → 受注 → 検収（売上計上）→ 請求書 → 銀行振込での入金・消込 → 銀行明細との突合 → 案件クローズまで、実務の一巡を体験する。
>
> 所要時間の目安: 30〜40分。

## 登場する物語

株式会社テックイノベーション（既存顧客 C003）から「販売管理システム構築」の引き合いが来た。
見積 250 万円（税抜）を提示 → 受注 → 8月下旬に納品・検収 → 請求書を発行 → 8月末に銀行振込で入金、という受託開発の典型パターンを最初から最後まで操作する。

## ステップ 3: 受注への変換（契約成立）

## ステップ 6: 請求書の発行

**画面**: 検収 A-26-007 の詳細 → 請求書

1. 「請求書を作成」を押す → トースト「請求書 **INV-26-011** を作成しました」→ 請求書詳細へ自動遷移。
2. 内容確認: 明細 3 行コピー・請求額（税抜）2,500,000・消費税 250,000・発行日=操作日・**支払期限=翌月末**・状態「発行済」・発行元「検収」。

- **期待結果**: 【一般業務】販売 > 売掛残高 に 1 行増える: INV-26-011／請求額（税込）2,750,000／入金済 0／残額 2,750,000／状態「未入金」。**仕訳帳は無変化**（債権は検収時に計上済み。請求書は帳簿外の書面）。
- 【財務・経営】財務帳票 > 資金繰り予測 の入金予定にも 2,750,000 が乗る。

## ステップ 8: 銀行明細との突合（着金の裏付け）

**画面**: 【会計】銀行 > 明細取込

実務では「帳簿に入金を書いた」だけでは終わらず、**銀行の入出金明細と帳簿が一致すること**を確認して締める。銀行サイトから落とした CSV を取り込む——という体で 8/31 の明細を貼り付ける。

1. 取込先口座「MB01 メインバンク 普通預金」を選択し、明細 CSV 欄に以下を貼り付け:

   ```
   日付,摘要,出金額,入金額,残高
   2026/08/31,ﾌﾘｺﾐ ｶ)ﾃｯｸｲﾉﾍﾞｰｼｮﾝ,,2750000,7486020
   ```

2. 「明細を取り込む」→ プレビュー 1 件を確認 → 「この内容で登録」。
3. 「未起票の明細」表に出た 8/31 の行の状態を「**対象外**」に変更 → 「明細の変更を保存」。
   - **理由**: この入金はステップ 7 で既に仕訳済み（No.70）。ここから起票すると**二重計上**になる。「銀行明細にはあるが、帳簿には記帳済み」という行を対象外にマークするのが照合の作法。
4. 【会計】銀行 > 残高照合 を開く（口座 MB01 で検索）。

- **期待結果**: 日付 **2026-08-31** の行が「**○ 一致**」・差額 0（明細残高 7,486,020 ＝ 帳簿残高）。これで「請求どおりの金額が実際に銀行に着金し、帳簿と銀行が一致している」ことが確かめられた。
- **補足（残高がズレた場合）**: CSV の残高列 7,486,020 は「2026-08-31 時点の普通預金の帳簿残高 4,736,020 ＋ 本シナリオの入金 2,750,000」で計算した値（2026-07-20 のDB状態基準）。このシナリオの前後で普通預金を動かす操作（経費支払・他の入金など）をしていた場合は「⚠ 差異」になる。その場合は照合画面の**帳簿残高列の値を見て、CSV の残高をその値に合わせて取り込み直す**（プレビュー取消 → 貼り直しでやり直せる）。

## ステップ 9: 案件のクローズ

プロジェクト完了の後片付け。2箇所ある。

1. **受注のクローズ**: 【一般業務】販売 > 受注 > SO-26-007 を開き、「**完了にする**」を押す → 状態「完了」（受注残管理から消える）。
2. **案件マスタのクローズ**: 【マスタ】案件 > PJ-2026-101 を開き、状態を「**完了**」にして「登録」。
   - 「有効」は ✓ のままにする（無効化すると各画面の選択候補から消える。過去実績の参照があるうちは有効のまま「完了」にするのが運用）。

- **期待結果**: どちらも帳簿への影響なし（管理ステータスのみ）。

## 【発展】工数と原価まで体験したい場合（任意）

受託の実務では開発期間中に工数が積み上がり、案件損益は「売上 − 人件費原価」で評価する。体験する場合:

1. **kaihatsu1_ippan**（開発1部 一般 小林美咲・パスワード同名）でログイン → 工数入力 で 2026-07・2026-08 に案件 PJ-2026-101 へ工数を登録（例: 各月 80h）。
2. soumu_bucho に戻り、【財務・経営】案件 > 人件費コスト・人件費配賦 で月次の標準単価×工数の配賦を実行。
3. 案件損益 で PJ-2026-101 の売上 2,500,000 に対する原価・粗利が出る。

詳細な手順と期待値は `docs/tests/11_E2Eテストシナリオ/06_案件・経営管理/基本シナリオ.md` を参照（配賦は管理会計レイヤで、仕訳は作らない設計。ADR-0009）。

## つまずいたときは

- **「締め済みの期間には起票できません」**: 検収日・入金日が締め済み月次に入っている。【会計】設定 > 会計年度 から該当月を再オープンするか、日付をオープン期間（2026-07 以降）にする。
- **確定・消込ボタンが見えない**: ログインユーザーが経理ロールでない（会計処理は経理専用。soumu_bucho を使う）。
- **PDF が落ちてこない**: Chrome が連続自動ダウンロードをブロックしていることがある。アドレスバー右の通知アイコンを確認。
- **仕訳番号が本書と違う**: 番号は「その年度の最終番号+1」で採番されるため、他の操作を挟めばずれる。金額と貸借が合っていれば正常。
