# 体験シナリオ: 購買の一巡（請求書受領 → 未払計上 → 口座整備 → 振込データ → 支払）

> 作成: 2026-07-26。docs/tests/14〜17 の姉妹編。**現在のデモDB（第18期・最終仕訳 No.82 時点）の続きとして実行できる**ように、既存の仕入先請求書 4 件（受領 2・未払計上済 2）をそのまま物語に組み込んでいる。
> 月末の支払業務を最初から最後まで一巡し、購買グループの**全機能**（受領登録／未払計上とその取消／支払予定表／取引先口座マスタ（口座登録・口座削除）／全銀 FB データ作成と除外理由の解消／支払登録とその取消／複製／削除／検索）に触れる構成。
>
> 所要時間の目安: 30〜40分。

## 登場する物語

7月末。総務部の山田太郎（経理）は月次の支払バッチに取りかかる。
届いていた請求書は、外注のベガソフト（7月分 55 万円）、モニターを買ったアルタイル商事、配送料のスターリンク急便、パンフレット印刷のグランメゾン印刷。
まず全部を帳簿に載せ（未払計上＝発生主義）、ネットバンキングに投げ込む振込ファイル（全銀フォーマット）を作ろうとしたら——**口座マスタの不備で 2 社が弾かれた**。マスタを直し、振込データを完成させ、支払を消し込むまでの月末業務を体験する。

| 会計期間 | 第18期。**2026年7月の月次期間がオープンであること** |
| 既存データ（そのまま使う） | 受領: **AL-7005**（アルタイル商事・33,000・期限 7/31）／**SL-26-0705**（スターリンク急便・11,000・期限 7/10=**期限超過**）。未払計上済: **GM-2607-118**（グランメゾン印刷・66,000）／**GM-2607-200**（同・33,000）→ ホーム KPI の買掛金 99,000 の正体 |
| 採番の目安 | 仕訳 **No.83〜90**（未払計上 3 本＋支払 5 本。17 経費一巡を先に実行した場合は No.93〜に読み替え） |
| 影響 | 仕入先請求書 1 件（VG-2026-072）を追加し、既存 4 件を**支払済みまで進める**（買掛金残高 99,000 → 0）。取引先口座マスタ 2 社（スターリンク・グランメゾン）を整備する |

**業務の骨格（発生主義の 2 段階処理）**:

- ① **未払計上**: 請求書を受け取ったら、支払前に「費用／買掛金」を計上する。仕訳日は**請求日**（役務提供時）。
- ② **支払**: 振込したら「買掛金／普通預金」で義務を消す。仕訳日は**支払日**。
- ①と②の間の買掛金残高＝「これから払う金額」が支払予定表・資金繰り予測・ホーム KPI に現れる。

## ステップ 1: 届いている請求書と支払予定の確認

**画面**: 【一般業務】購買 > 仕入先請求書 ／ 支払予定表

1. 仕入先請求書の一覧を開き、既存 4 件の状態を確認する（受領 2・未払計上済 2）。
2. 支払予定表を開く。`受領` と `未払計上済` の請求書だけを写した「これから出ていくお金」の一覧で、期限順に 4 件・**合計 143,000**。
   - **SL-26-0705 の警告列に「⚠ 期限超過」**（期限 7/10）——支払漏れの検知がこの画面の主目的。AL-7005 は実行日により「まもなく期限」が出る。

- **影響先**: 受領状態の 2 件はまだ帳簿外（仕訳なし）。未払計上済の 2 件（グランメゾン 99,000）だけが試算表の買掛金に載っている。

## ステップ 2: 新しい請求書の受領登録

**画面**: 仕入先請求書 > 新規作成

ベガソフトから 7 月分の外注費請求書が届いた——購買業務の入口。紙や PDF の請求書を「受領」として台帳に載せる（この時点では帳簿外の「処理待ちの箱」）。

| 項目 | 入力値 |
|---|---|
| 請求書番号 | `VG-2026-072`（仕入先の採番をそのまま入れる） |
| 仕入先 | `株式会社ベガソフト` |
| 受領日 | 本日 |
| 請求日 | `2026-07-31`（未払計上の仕訳日付になる） |
| 支払期限 | `2026-08-31` |
| 費用科目 | `外注費` |
| 税区分 | `課税仕入 10%` |
| 金額（税込） | `550,000` |
| 摘要 | `基幹システム改修 外注費 7月分` |
| 支払口座 | `メインバンク 普通預金` |

→ 「保存」。状態「受領」。

- **影響先**: 支払予定表に 5 件目として載る（合計 693,000 に増える）。仕訳帳は無変化。

## ステップ 3: 未払計上と、その取り消し（仕訳 No.83）

**画面**: 仕入先請求書 > VG-2026-072

1. 「**未払計上（仕訳生成）**」を押す → トースト「**未払計上 No.83 を生成しました（借方 500,000 円+税 / 貸方 買掛金 550,000 円）**」。状態「未払計上済」になり、ボタンが「支払登録（消込仕訳）」と赤い「未払計上を取り消す」に入れ替わる。
2. **取り消しも体験する**: 「未払計上を取り消す」→ 確認ダイアログ → OK → 仕訳が削除され状態が「受領」に戻る（誤操作リカバリ。仕訳帳から No.83 が消えることを確認）。
3. もう一度「未払計上（仕訳生成）」→ 再計上（番号は削除後の最終+1。間に他の操作がなければ同じ No.83）。

- **仕訳の中身**: No.83／**2026-07-31**（請求日）／借方 外注費 500,000＋仮払消費税 50,000／貸方 買掛金 550,000。
- **影響先**: 損益計算書の売上原価（外注費）+500,000・**月次推移表は 7 月列**に計上（支払月の 8 月ではない——発生主義の可視化）。ホーム KPI 買掛金 99,000 → 649,000。もう一度押すと「既に生成済みです」（二重計上ガード）。

## ステップ 4: 残りの受領分もまとめて未払計上（仕訳 No.84・85）

1. **AL-7005** を開いて未払計上 → **No.84**／2026-07-01／借方 消耗品費 30,000＋税 3,000／貸方 買掛金 33,000。
2. **SL-26-0705** を開いて未払計上 → **No.85**／2026-07-05／借方 雑費 10,000＋税 1,000／貸方 買掛金 11,000。
   - **確認ポイント**: この請求書の税区分は「**課税仕入 10%(経過措置)**」（免税事業者からの仕入）。仕訳は通常どおり内税分解されるが、消費税集計表では別区分として集計され、控除割合はインボイス経過措置マスタ（令和8年度改正の 4 段階）を参照する——制度改正にマスタ変更だけで追随する設計。

- **影響先**: 支払予定表の 5 件が全部「未払計上済」になる。買掛金残高 693,000（=支払予定表の合計と一致）。資金繰り予測の出金予定にも同額が乗る。

## ステップ 5: 振込データ作成（1回目）——除外理由を読む

**画面**: 【一般業務】購買 > 振込データ作成

複数の振込をネットバンキングへ一括登録する標準ファイル（全銀協フォーマット・120桁固定長）を作る。対象は「未払計上済み＝帳簿に乗った確定債務」のみ——帳簿にない支払いは作らない、という統制でもある。

1. 自社側の委託者情報・仕向口座は既定値のまま、振込指定日を確認（既定=本日）して「**FBデータを生成**」。
2. 結果ラベルを読む: 「データレコード **1 件・合計 550,000 円** … ／ 様式検証 OK … ／ **除外 4 件**:」（表示は支払期限順に 3 件＋「ほか」）
   - `SL-26-0705: スターリンク急便株式会社 — 口座情報が入力されていません（マスタ管理（経理） > 取引先口座 で登録）`
   - `AL-7005: 株式会社アルタイル商事 — 受取人名に使用できない文字があります: ｮ（半角ｶﾅ大文字・英大文字・数字で入力してください）…`
   - `GM-2607-118: グランメゾン印刷株式会社 — 受取人名に使用できない文字があります: グ …`（GM-2607-200 は「ほか」に畳まれる）

- **読み方**: データ化されたのは口座マスタが完全なベガソフト（550,000）だけ。**スターリンクは口座未登録**、**アルタイルは受取人名に半角小文字カナ「ｮ」**（全銀では大文字 ﾖ しか使えない）、**グランメゾンは受取人名が全角カナ**で弾かれている。生成はやり直しが利くので、マスタを直して再生成すればよい。

## ステップ 6: 取引先口座マスタの整備（口座登録・口座削除）

**画面**: 【マスタ】取引先口座

振込先口座は取引先マスタから分離された**経理専用画面**で管理する（口座情報は機微情報のため）。一覧には銀行／支店／**口座種別**／口座番号／受取人名（カナ）が並ぶ。口座 5 項目は「**全て有効か・全て空（未登録）か**」の 2 状態しか許されない——部分入力の口座は振込データ作成で必ず事故になるため、登録時点で弾く設計。

1. **スターリンク急便**を開き、まず**わざと不備のまま**登録してみる: 銀行 `0033`・支店 `21`（2桁）だけ入れて「**口座登録**」→ 赤トースト「**支店コードは数字3桁で入力してください**」で拒否される。
2. 正しく入力して「口座登録」→ 「振込先口座を登録しました」:

| 項目 | 入力値 |
|---|---|
| 銀行コード | `0033` |
| 支店コード | `210` |
| 口座種別 | `普通` |
| 口座番号 | `4567890` |
| 受取人名（半角カナ） | `ｽﾀｰﾘﾝｸｷﾕｳﾋﾞﾝ(ｶ`（小文字カナ ｭ は使えないので ﾕ で登録するのが全銀の作法） |

3. **口座削除も体験する**: 「**口座削除**」（赤）→ 確認ダイアログ「取引先「スターリンク急便株式会社」の振込先口座情報を削除します。よろしいですか？（**取引先自体は削除されません**）」→ OK → 全欄が空に戻る。ボタンの下の**赤字の注意書き**（未払いの支払予定が残っている取引先の口座を消すと振込データ作成がエラーになる）も確認 → 手順 2 の値でもう一度登録し直す。
4. **アルタイル商事**を開き、受取人名を `ｶ)ｱﾙﾀｲﾙｼｮｳｼﾞ` から `ｶ)ｱﾙﾀｲﾙｼﾖｳｼﾞ`（小文字 ｮ → 大文字 ﾖ）に修正して「口座登録」。
5. **グランメゾン印刷**を開き、受取人名を全角「グランメゾンインサツ（カ」から半角 `ｸﾞﾗﾝﾒｿﾞﾝｲﾝｻﾂ(ｶ` に修正して「口座登録」。
6. （空欄ガードの確認）**シリウス設計（取引終了）**（口座未登録）を開き、全欄空のまま「口座登録」→ 「**口座情報が入力されていません**」、「口座削除」→ 「**口座情報は登録されていません**」——どちらも安全に拒否される。

- **影響先**: マスタ変更のみで帳簿は無変化。検証基準（銀行4桁/支店3桁/口座7桁/種別/カナ許容文字）は振込データ作成と**同じロジック**を共有しており、マスタで通った口座が FB で弾かれることはない。

## ステップ 7: 振込データ作成（2回目）——全件そろう

**画面**: 【一般業務】購買 > 振込データ作成

1. 「FBデータを生成」→ トースト「**FBデータを生成しました（5 件・693,000 円）**」。結果ラベル「データレコード 5 件・合計 693,000 円 … ／ **様式検証 OK（全 8 レコードが 120 桁・トレーラ整合: 件数 5・合計 693,000 円）**」——除外なし。
2. テキストエリアの中身を眺める: 1 行目ヘッダ（`1` 始まり・委託者情報）→ データ 5 行（`2` 始まり・各社の口座とゼロ埋め金額）→ トレーラ（`8`・件数と合計）→ エンド（`9`）。**すべて半角・120 桁固定長**という 40 年もののフォーマットが現役で銀行を動かしている。

- **影響先**: 画面表示のみ（実務ではコピーして .txt 保存し、ネットバンキングにアップロードする）。

**画面**: 仕入先請求書 > 各詳細

振込が実行された——という体で 5 件を消し込む。VG-2026-072 → AL-7005 → SL-26-0705 → GM-2607-118 → GM-2607-200 の順に、各詳細で支払口座「メインバンク 普通預金」を確認して「**支払登録（消込仕訳）**」:

| 請求書 | 支払仕訳（日付=操作日） |
|---|---|
| VG-2026-072 | **No.86** 借 買掛金 550,000／貸 普通預金 550,000 |
| AL-7005 | **No.87** 33,000 |
| SL-26-0705 | **No.88** 11,000 |
| GM-2607-118 | **No.89** 66,000 |
| GM-2607-200 | **No.90** 33,000 |

- **期待結果**: 各件、状態「支払済」・支払日=本日。詳細のボタンは赤い「支払を取り消す」だけになる。
- **影響先**:
  - 支払予定表が**空**になる（合計 0——月末の支払業務完了の合図）。
  - ホーム KPI 買掛金 693,000 → **0**。試算表の買掛金残高 0。
  - 【会計】帳簿 > 出納帳（普通預金）: 本日付の出金 5 行（計 693,000）。

## ステップ 9: 支払の取り消し（誤操作リカバリ）

**画面**: 仕入先請求書 > SL-26-0705

「実は振込がエラーで返ってきた」という体で 1 件だけ巻き戻す。

1. 「**支払を取り消す**」→ 確認ダイアログ → OK → トースト（支払仕訳を削除し未払計上済みに戻す）。仕訳帳から No.88 が消え、支払予定表に SL-26-0705 が復活する。
2. もう一度「支払登録（消込仕訳）」で支払済みに戻す（番号は最終+1 で採番し直される）。

- **確認ポイント**: 未払計上取消（ステップ 3）と対になる「状態を 1 段ずつ巻き戻す」設計。received ← accrued ← paid のどこからでも赤ボタンで前の状態に戻れる。

## ステップ 10: 反復請求の複製と削除

**画面**: 仕入先請求書 > VG-2026-072

外注や家賃は**毎月ほぼ同じ請求**が来る。前月分の複製が最速の入力方法。

1. VG-2026-072（支払済）を開き「**この請求書を複製**」→ 複製の詳細へ遷移。**コピーされる項目**（仕入先・費用科目・税区分・金額・摘要・支払口座）と**コピーされない項目**（請求書番号・請求日・支払期限は空、状態は「受領」）を確認。
2. 8 月分はまだ不要なので、赤ボタン「**この請求書を削除**」（受領状態のみ表示・確認ダイアログ付き）で削除する。

- **影響先**: 複製時点では帳簿外（受領）なので、削除しても帳簿は無変化。

## ステップ 11: 総仕上げ——検索と、この月末が残した数字

1. 仕入先請求書の「検索条件」で ①状態「支払済」→ 5 件（+以前からの VG-2026-071）、②仕入先「グランメゾン印刷株式会社」→ 2 件、③請求書番号 `VG` → ベガソフトの 2 件、を順に確認する。
2. 数字の続きは:

| 画面 | 見えるもの |
|---|---|
| 仕訳帳（2026-07-01〜） | 未払計上 No.83〜85 が**請求日**（7/31・7/1・7/5）で、支払 No.86〜90 が**操作日**で並ぶ |
| 損益計算書 | 売上原価（外注費）+500,000／販管費に消耗品費・雑費・（既計上の）広告宣伝費 |
| 月次推移表 | 7 月列に費用が計上（支払した月ではなく役務を受けた月） |
| 貸借対照表 | 買掛金 0／普通預金 −693,000 |
| 消費税集計表 | 課税仕入 10% と **課税仕入 10%(経過措置)** が別区分で集計される |

これで「請求書が届き、発生主義で帳簿に載り、口座マスタを整えて振込ファイルを作り、支払で債務を消す」という購買の一巡が完了。

## つまずいたときは

- **「締め済みの期間には起票できません」**: 請求日が締め済み月次に入っている。【会計】設定 > 会計年度 で該当月を再オープンする。
- **FB データの除外が消えない**: 除外メッセージ末尾の案内どおり【マスタ】取引先口座 を直す。桁数・種別・カナの基準はマスタの「口座登録」と同一なので、マスタで登録できれば FB も通る。
- **【購買】メニューが見えない**: 経理ロール（soumu_bucho）またはシステム管理者でログインしているか確認（一般・承認者のフレームには出ない）。
- **仕訳番号が本書と違う**: 番号は「年度の最終番号+1」で採番されるため、他の操作（17 経費一巡など）を挟めばずれる。金額と貸借が合っていれば正常。
- **分岐を深掘りしたい**: 仕入先請求書・振込データの分岐網羅は `docs/tests/11_E2Eテストシナリオ/03_購買/` の分岐シナリオを参照。
