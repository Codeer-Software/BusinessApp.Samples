# 体験シナリオ マスタ-04: 税制と制度閾値（科目体系・インボイス照合・閾値が画面を動かす）

> 所要時間: 約30分 ／ 影響: **制度閾値 `PAY_DUE_SOON_DAYS` を一時的に 7 → 30 へ変更し、必ず 7 に戻す**。それ以外は**閲覧のみ**（インボイス照合は「登録」を押さないので DB は変わらない）
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理機能）。パスワードはユーザー名と同じ。
> 「税制も会計基準もマスタに逃がしてある」——ハードコードしないという設計方針（CLAUDE.md §3）が、実際にどの画面へどう効くかを 1 本で通す。仕上げに**閾値を 1 個いじって 2 つの画面が同時に変わる**のを見る。

## 物語

経理の山田太郎は、来月（2026-10-01）にインボイス経過措置の控除割合が **80% → 70%** に下がることを思い出した。
「うちのシステムは改正のたびに改修が要るのか？」——確かめるため、勘定科目から税区分・経過措置・制度閾値まで、
**設定だけで追随できる作りになっているか**をマスタ画面で総ざらいする。ついでに、支払期限アラートの「まもなく」日数を
7 日から 30 日に変えて、支払予定表とポータルが**同時に**変わることを確認する。

## ステップ 1: 会計マスタの三段重ねを読む（科目表示区分 → 勘定科目 → 費目）

**soumu_bucho** でログイン → サイドバー「**業務マスタ**」。

### 1-1. 科目表示区分（帳票の骨格）

会計マスタ/**科目表示区分**。

> BS/PL 帳票の表示区分マスタです。

- 17 行。**帳票**（BS / PL）と**帳票内の並び**を持つだけの、極めて素朴なマスタ。

| 帳票 | 並び | 区分 |
|---|---|---|
| BS | 10〜22 | 流動資産 / 有形固定資産 / 無形固定資産 / 投資その他の資産 |
| BS | 30〜31 | 流動負債 / 固定負債 |
| BS | 40〜42 | 資本金 / 資本剰余金 / 利益剰余金 |
| PL | 50〜57 | 売上高 / 売上原価 / 販売費及び一般管理費 / 営業外収益 / 営業外費用 / 特別利益 / 特別損失 / 法人税等 |

- **確認ポイント**: **貸借対照表・損益計算書・合計残高試算表の「セクションの並び」は、このマスタの数字が決めている**。
  「販売費及び一般管理費を営業外費用の後に出したい」といった要望は、**コード修正ではなく並び順の数字**で対応できる。

### 1-2. 勘定科目（何をどこに集計するか）

会計マスタ/**勘定科目**。

> 勘定科目マスタです。科目ごとの区分・既定税区分を管理します。

**`1100 売掛金`** を開く。

| 項目 | 値 | 意味 |
|---|---|---|
| 科目コード / 科目名 | `1100` / `売掛金` | |
| 科目区分 | `資産` | 資産・負債・純資産・収益・費用の 5 分類。BS/PL の振り分けと決算処理に効く |
| **表示区分** | `流動資産` | ↑ 1-1 のマスタへの参照。**帳票のどのセクションに出るか** |
| 正残区分 | `借方` | 残高の向き。BS を勘定式で並べるときの符号 |
| 既定税区分 | （空） | 仕訳明細で科目を選んだときに自動で入る税区分 |
| **役割** | （空） | アプリが科目を**コードではなく役割で引く**ための欄（2026-08-18 追加・`ddl/630`）。
  例: `depreciation_expense`（減価償却費）／`disposal_loss`（固定資産除却損）／
  `sale_gain`・`sale_loss`（固定資産売却益・売却損）／`disposal_receivable`（売却代金の未収）。
  **1 役割 1 科目**（DB に部分 UNIQUE がある）。空でよい——役割を持つのは 5 科目だけ |

- 詳細の下に「**補助科目**」のインライン一覧。売掛金には `C001 株式会社アルタイル商事` `C003 株式会社テックイノベーション` の 2 行。
- **確認ポイント（補助科目の使いどころ）**: 他にも見どころがある。
  - `1020 普通預金` → `MB01 メインバンク 普通預金` / `001 みずほ銀行 本店` / `002 三菱UFJ銀行 神田支店`
  - `5000 外注費` → `001 ベガソフト` / `002 その他外注先`
  → **「科目を増やさずに内訳を持つ」**のが補助科目。取引先が増えるたびに勘定科目を増やすと帳票が読めなくなる。
- **確認ポイント**: 勘定科目には**削除導線が無い**（一覧に削除が出ない）。使わなくなった科目は「有効」を外す。過去の仕訳が参照しているものを消せてしまうと帳簿が壊れるため。

### 1-3. 費目（経費申請の言葉づかい）

会計マスタ/**費目**。

> 経費の費目マスタです。費目ごとの勘定科目・税区分・承認要件を設定します。

- 11 行（旅費交通費・会議費・交際費・消耗品費・印刷製本費・備品・外注費・通信費・図書研修費・諸会費・その他）。

**`ENT 交際費`** と **`EQP 備品`** を開いて、チェックボックスを 2 つ見る。

| チェック | 付いている費目 | 効くところ |
|---|---|---|
| **交際費（例外項目・総務承認必須）** | 交際費 | 経費申請で**相手先・参加人数・目的が必須**になる／承認ルート判定の費目条件に使われる |
| **資産性の支出（備品等）** | 備品 | 金額が `SMALL_ASSET_EXPENSE`（10 万円）以上のとき、経費申請の**固定資産チェックが自動 ON** |

- **確認ポイント（マスタが業務ルールを持つ）**: 「交際費だけ入力項目が増える」という業務ルールが、**スクリプトの `if (費目名 == "交際費")` ではなくマスタのフラグ**で表現されている。
  新しい費目を「交際費扱い」にしたければ、チェックを 1 つ入れるだけ。
- **確認ポイント**: 費目には**既定勘定科目**と**既定税区分**がある。申請者は「旅費交通費」を選ぶだけで、経理が使う勘定科目と税区分が裏で決まる。**現場と帳簿の語彙を分けて、マスタで橋渡ししている**。

## ステップ 2: 税制マスタを読む（税率 → 税区分 → 経過措置）

### 2-1. 税率

税制/**税率**。

> 消費税率マスタです。税率の改正はここに追加します。

| 税率コード | 名称 | 税率(%) | 適用開始日 | 適用終了日 |
|---|---|---|---|---|
| STD10 | 標準税率 10% | 10 | 2019-10-01 | （空＝現在有効） |
| RED8 | 軽減税率 8% | 8 | 2019-10-01 | （空） |

- **確認ポイント**: **期間で持っている**のがすべて。将来 12% になったら「終了日を入れて、新しい行を追加する」だけ。
  過去の伝票は過去の税率で再計算され、税率変更で**過去の帳簿が書き換わらない**。

### 2-2. 税区分

税制/**税区分**。

> 税区分マスタです。取引の種類ごとの課税区分と適用税率を管理します。

- 11 行。売上側 4（課税売上 10% / 8%軽減 / 非課税売上 / 免税売上(輸出等)）、仕入側 5（課税仕入 10% / 8%軽減 / **10%経過措置** / **8%経過措置** / 非課税仕入）、その他 2（不課税 / 対象外）。
- 各行は **課税種別**（`taxable_sales` `taxable_purchase` `exempt_*` `non_taxable` `out_of_scope`）と**税率への参照**を持つ。
- **確認ポイント**: `PUR_10_TR` `PUR_8_TR` の 2 つだけ「**経過措置対象（免税事業者からの仕入）**」にチェックが入っている。
  この 1 つのチェックが、次の「控除割合」マスタを参照するスイッチになる。
- **確認ポイント（構造の意味）**: 税区分は「税率そのもの」を持たず**税率マスタを参照する**。だから税率改正のとき、税区分は 1 行も直さなくてよい。
  税区分 → 税率 → 期間、という 3 段の間接参照が「改正にオープン」の正体。

### 2-3. 経過措置控除割合

税制/**経過措置控除割合**。

> インボイス経過措置（免税事業者等からの仕入の控除割合）を期間付きで管理します。2026年度改正で 80%→70%→50%→30% の4段階です。

| 適用開始日 | 適用終了日 | 控除割合(%) |
|---|---|---|
| 2023-10-01 | 2026-09-30 | **80** |
| 2026-10-01 | 2028-09-30 | **70** |
| 2028-10-01 | 2030-09-30 | **50** |
| 2030-10-01 | 2031-09-30 | **30** |

- **確認ポイント（本書執筆日 2026-08-09 時点）**: いまは **80% の期間**で、**あと 50 日ほどで 70% に切り替わる**。
  切り替えは**日付が来れば自動**——誰かが設定を変える必要も、リリースを打つ必要もない。
- **確認ポイント（誰に効くか）**: 取引先マスタで「**免税事業者（経過措置対象）**」にチェックが付いている取引先——現状は `C004 オリオン事務機` と `C006 スターリンク急便株式会社`——からの仕入で、税区分が `PUR_*_TR` のときに控除額が割合分に絞られる。
  10 月をまたぐ取引で控除額が変わるのを見たい場合は `06_会計_仕訳と帳簿/03_税の変化形.md`（未執筆）で扱う。
- **確認ポイント**: 2031-10-01 以降の行は無い＝**経過措置の終了**（控除なし）。将来の延長が決まったら行を足すだけで済む。

## ステップ 3: インボイス番号照合の 3 分岐（保存はしない）

サイドバー「**取引先**」。

> 取引先マスタを登録・編集できます。得意先・仕入先の区分やインボイス登録番号を管理します。

**`C005 グランメゾン印刷株式会社`**（登録番号 `T5011112222333`）を開く。

> **⚠ このステップでは一度も「登録」を押さない。** 番号欄を書き換えるだけで、確認ボタンはサーバへ問い合わせるだけの読み取り操作。最後に一覧へ戻れば入力は破棄される。

### 3-1. 正常（緑）

登録番号がそのまま `T5011112222333` の状態で「**国税庁で番号を確認**」を押す。

- **期待結果**: 緑のトースト。
  > 適格請求書発行事業者として登録されています（モック応答。実照合は国税庁アプリケーションID設定後）: モック株式会社（疑似応答）（2023-10-01 登録）
- **確認ポイント**: サーバの国税庁アプリケーション ID が未設定のため**モック応答**。形式が `T+13桁` なら「登録あり」を返す。
  実 ID を設定すると、同じボタンが**国税庁の適格請求書発行事業者公表システム Web-API** を叩き、実際の事業者名・住所・登録年月日を返す。
  **WASM から直接叩けない**（CORS とキー秘匿）ので**サーバ経由**にしている——CLB 単体では作れない部分だけを C# に逃がした典型例（CLAUDE.md §2）。

### 3-2. 該当なし（黄）

登録番号を **`T5011112222330`**（末尾を `0` に変える）に書き換えて「**国税庁で番号を確認**」。

- **期待結果**: 黄色のトースト。
  > 該当する事業者が見つかりません（モック応答）
- **確認ポイント**: モックは「**末尾が 0 の番号だけ該当なし**」という約束で、**キー無しの環境でも両分岐を画面から再現できる**ようにしてある。
  実運用では「番号の打ち間違い」「登録が取り消された事業者」がこの応答になる。**警告であってエラーではない**（入力を止めない）。

### 3-3. 形式不正（赤）

登録番号を **`T123`** に書き換えて「**国税庁で番号を確認**」。

- **期待結果**: 赤いトースト。
  > 登録番号の形式が不正です（T+13桁の数字）
- **確認ポイント**: 形式チェックは**サーバ側**で行われる（外部 API を叩く前に弾く＝無駄な問い合わせをしない）。
- **確認ポイント（親切な補完）**: 先頭の `T` は**省略しても通る**。`5011112222333` と入れても、サーバ側で `T` を付けて判定する。大文字小文字・前後の空白も吸収される。

### 3-4. 未入力（黄）

登録番号を**空欄**にして「**国税庁で番号を確認**」。

- **期待結果**: 黄色のトースト。
  > 登録番号（T+13桁）を入力してから確認してください
- **確認ポイント**: これだけはサーバへ行かず**画面側**で止めている。

→ **「登録」を押さずに**サイドバーで取引先一覧に戻る。`C005` を開き直して**登録番号が `T5011112222333` のまま**であることを確認する。

- **確認ポイント（接続失敗）**: サーバが落ちている・ネットワークが切れている場合は「照合サービスに接続できませんでした」が出る。**照合できなくても取引先の保存自体はできる**（照合は任意の補助機能）。

## ステップ 4: 制度閾値ツアー（どの閾値がどの画面に効くか）

税制/**制度閾値**。

> 承認金額の閾値・固定資産の判定額などの制度閾値を管理します。制度改正には設定変更で追随します。

項目は **閾値コード / 名称 / 金額(円) / 適用開始日 / 適用終了日** の 5 つだけ。

| 閾値コード | 現在値 | 効く画面 |
|---|---|---|
| `SMALL_ASSET_EXPENSE` | 100,000 | 経費申請の**固定資産チェック自動 ON**／固定資産台帳の少額判定 |
| `LUMP_SUM_ASSET` | 200,000 | 固定資産台帳「一括償却資産」の判定文言 |
| `SME_IMMEDIATE` | 300,000（〜2026-03-31）／**400,000（2026-04-01〜2029-03-31）** | 固定資産台帳「中小企業者等の少額特例」の判定文言 |
| `SME_ANNUAL_CAP` | 3,000,000 | 同・年間合計上限 |
| `EXP_OVERRUN_RATE` | 110 | 事前申請の**実費超過による再承認**の判定（見込み × 110% 超で再承認） |
| **`BUDGET_ALERT_RATE`** | 80 | 予実対比の「⚠ 予算警告」と**ポータルの予算警告**（同時に変わる） |
| **`RECEIPT_DIFF_MAX`** | 1,000 | 入金消込の**差額自動処理の上限** |
| **`PAY_DUE_SOON_DAYS`** | 7 | 支払予定表の「まもなく期限」と**ポータルの「⚠ 支払期限: … D日以内」**（同時に変わる） |
| **`CASH_ALERT_BALANCE`** | 3,000,000 | 資金繰り予測の「**△ 資金が危険水域**」とポータルの資金アラート（同時に変わる）。**0 にすると 2 段階目が消え、「⚠ 資金ショート」＝マイナスのときだけになる**（BUG-0249・2026-08-18 追加） |

- **確認ポイント（期間で持てる）**: `SME_IMMEDIATE` だけ**同じコードで 2 行**ある。令和8年度改正で 30 万円 → 40 万円に上がったので、**古い行に終了日を入れ、新しい行を追加**した。
  「改正前の取引は改正前の閾値で判定する」を、コードを触らずに表現できている。
- **⚠ 実装の注意（同じコードを 2 行にするときの罠）**: `BUDGET_ALERT_RATE` を参照している SQL は**期間解決していない**（`... WHERE code = 'BUDGET_ALERT_RATE' LIMIT 1`）。
  このコードで期間違いの行を 2 つ作ると、**先頭の 1 行が無条件に使われる**。同じことが `PAY_DUE_SOON_DAYS` にも当てはまる。
  **率・日数系の閾値は 1 コード 1 行で運用する**のが現時点の安全な使い方。
- **確認ポイント**: この一覧には**削除導線がある**。誤って消すと参照側は既定値（`PAY_DUE_SOON_DAYS` なら 7）にフォールバックするが、**閾値ごとに既定値の有無が違う**ので消さないこと。
  とくに `BUDGET_ALERT_RATE` は**フォールバックが無く、消すと予算警告が永久に出なくなる**（BUG-0250）。
  `CASH_ALERT_BALANCE` が消えた／0 になった場合は、不変条件 **H01** が検出する。
  「消せてしまう入口を残す理由が無い」という指摘は **BUG-0337** として台帳にある（要判断）。

## ステップ 5: 閾値を 1 個変えて、2 つの画面が同時に変わるのを見る

### 5-1. 変える前の状態を記録する

サイドバー「**ホーム**」→ ポータル →「**購買・支払**」→ **支払予定表**。

- **期待結果（2026-08-09 実行時）**: 未払（受領 / 未払計上）の仕入先請求書が 4 件、支払期限順に並ぶ。

  ```sql
  SELECT COALESCE((SELECT amount FROM system_thresholds WHERE code = 'PAY_DUE_SOON_DAYS' LIMIT 1), 7) AS days
  ```

## ステップ 6: 触ってはいけないもの — 科目コード直参照の罠（解説のみ）

**この節は読むだけ。実際に変えないこと。**

会計マスタ/勘定科目 の「科目コード」は、**一部の集計 SQL からコード文字列で直接参照されている**。

| 参照している画面 | 直接書かれている科目コード | 変えたときに起きること |
|---|---|---|
| 経営管理 > 資金繰り予測 | `1000`（現金）／`1010`（小口現金）／`1020`（普通預金） | **期首資金が 0 になる**（現預金を集計できなくなる） |
| 経営管理 > 資金繰り予測 | `2020`（未払金） | **買掛（未払）出金が 0 になる**（資金流出を見落とす） |

- **なぜ危ないか**: エラーにならず、**数字が静かに 0 になる**。画面は正常に表示されるので、気づくのが遅れる。
- **どうすべきか**: 科目コードの変更が必要なら、**科目名だけを変える**（コードは温存する）か、参照側の SQL も同時に直す。
  本来は「科目コード直参照」ではなく表示区分や属性で引くべきで、これは既知の改善候補。
- **同種の注意**: 銀行の残高照合・出納帳も自社口座マスタ（`BankAccount`）の**帳簿勘定科目**参照に依存する。科目を差し替えると照合が合わなくなる。

## つまずいたときは

- **サイドバーに「業務マスタ」が出ない**: 経理機能フラグが必要。`soumu_bucho` 系（総務部の 5 名）でログインする。`admin` では出ない（職務分掌）。
- **「国税庁で番号を確認」が毎回同じ会社名を返す**: モック応答なので正常（国税庁アプリケーション ID 未設定）。実照合には .NET User Secrets への ID 設定が必要。
- **末尾 0 なのに「登録あり」が返る**: 実 ID が設定されていて**本物の API を叩いている**。その場合の応答は実在するかどうかで決まる。
- **閾値を変えたのに画面が変わらない**: ① 別の画面を開き直したか（検索結果はキャッシュされる）／② **同じコードの行を 2 つ作っていないか**（`LIMIT 1` で先頭行が使われる）。
- **経過措置の控除割合が想定と違う**: 判定は**取引の日付**で行う。2026-09-30 と 2026-10-01 で 80% / 70% が切り替わる。期間の境界日は**両端とも含む**。
- **勘定科目を消したい**: 削除導線は無い。「有効」を外す。過去の仕訳が参照している科目を消すと帳簿が壊れるため、意図的にそうしてある。
- **税率を改正したい**: 既存行を書き換えず、**古い行に適用終了日を入れて新しい行を追加**する。書き換えると過去の帳簿の税額が変わってしまう。
