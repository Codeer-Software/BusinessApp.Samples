# 体験シナリオ 銀行-01: 明細取込から残高照合まで一巡（CSV 貼付 → 登録 → 一括起票 → ○ 一致）

> 所要時間: 約20分 ／ 影響: 銀行明細 3 行＋仕訳 3 本追加（後片付け手順あり・既存データは変更しない）
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。パスワードはユーザー名と同じ。
> 銀行部品の王道一本道。「銀行サイトから落とした CSV を貼り付け → 帳簿に起票 → 銀行と帳簿が一致していることを確認して締める」という月次の実務をそのまま体験する。

## 物語

経理の山田太郎がネットバンキングから当日の入出金明細 CSV をダウンロードした。
中身は AWS の利用料引き落とし、振込手数料、預金利息の 3 件。これを取り込み、自動仕訳ルールに科目を提案させ、起票し、最後に残高照合で「銀行と帳簿がピッタリ合っている」ことを確かめる。

## 前提

| 項目 | 内容 |
|---|---|
| ログインユーザー | soumu_bucho（経理） |
| 口座 | MB01 メインバンク 普通預金（登録済みの唯一の口座。帳簿科目=普通預金 1020） |
| 明細の現状 | 未起票 0 件（起票済 11・対象外 2 が過去分として存在。**最新の明細は 2026-08-22**） |
| 会計期間 | 2026-08 の月次期間がオープンであること |
| 部門 | 一括起票では、相手科目が**損益科目（費用・収益）の行に部門が必須**（ADR-0056）。空の行は起票されずスキップされる |
| 仕訳番号の目安 | 現在の最終 No. の次から 3 本（ズレたら読み替え。2026-08-19 の実機では No.115〜117 だった） |
| 旧シナリオとの違い | 旧14は CSV の残高列を決め打ちしていたが、本書は**先に帳簿残高を確認してから CSV を組み立てる**方式（DB がどう育っていても実行できる） |

## ステップ 1: 帳簿残高を先に確認する

**画面**: サイドバー「**会計業務**」→ 帳簿 > **出納帳**

1. 検索条件「対象科目」で `普通預金` を選んで検索（対象科目を選ぶまでは 0 件表示——これは仕様）。
2. 一番下の行（直近日付）の「**残高**」列の値をメモする。以下これを **X** と呼ぶ。

3. ついでに**一番下の行の日付**もメモする。以下これを **D** と呼ぶ。

- **なぜ先に見るか**: ステップ 2 の CSV に書く「残高」列は銀行側の残高。今日以降まだ帳簿と銀行がズレていない前提なら「X − 出金 ＋ 入金」で計算できる。ここを実際の帳簿から拾うことで、DB がどんな状態でも「○ 一致」まで到達できる。
- **日付は D より後にする**（**重要**）。デモ DB には過去のシナリオで作った未来日付の伝票が積もっていて、
  2026-08-19 時点では D = **2026-08-22** だった。D 以前の日付で取り込むと、
  X から計算した残高が「その日付の帳簿残高」と合わず、ステップ 5 で ○ 一致にならない。
  以下では **2026/08/23** を使う（自分の環境の D に合わせて読み替える）。
- **検索の操作**: 対象科目を選んだら **青い「検索」ボタン**を押す。
  隣の「クリア」を押すと条件ごと消えて 0 件に戻る（見た目が似ているので押し間違えやすい）。

## ステップ 2: CSV を貼り付けて取り込む

**画面**: 会計業務 > 銀行 > **明細取込**

- **確認ポイント**: 取込先口座に「MB01 メインバンク 普通預金」が**最初から選択されている**（有効な口座が 1 件だけの場合の自動選択）。

「明細CSV貼り付け」欄に以下を貼る。`{X-…}` の 3 箇所は**ステップ 1 の X から計算した実数**に置き換えること（例: X=4,736,020 なら 1 行目 4,703,020）:

```
日付,摘要,出金額,入金額,残高
2026/08/23,AWS ｸﾗｳﾄﾞﾘﾖｳｷﾝ,33000,,{X-33000}
2026/08/23,ﾌﾘｺﾐﾃｽｳﾘﾖｳ,550,,{X-33550}
2026/08/23,ﾘｿｸ,,15,{X-33535}
```

（**前回の作業の残り**があると「⚠ 登録されていないプレビューが n 件残っています」と出る。
その場合は先に「全てのプレビューを取り消す」で片付けてから貼る。この警告が出るのは正しい動き。）

→ 「**明細を取り込む**」。

- **期待結果**: 結果ラベル「プレビュー 3 件 / 重複スキップ 0 件 / スキップ行（ヘッダ・明細以外） 1 行 — 内容を確認して「この内容で登録」を押してください」。ヘッダ行が自動でスキップされている。
- プレビュー表に 3 行（口座・日付・摘要・出金・入金・残高）。この段階ではまだ「明細一覧」には出ない（プレビューは別テーブル）。

→ 内容を確認して「**この内容で登録**」→ 確認ダイアログ「プレビュー中の明細をまとめて銀行明細に登録します。登録後は「取込をやめる」では戻せません。よろしいですか？」→「**登録する**」。

- **期待結果**: 「3 件を未起票の明細として登録しました（**ルール適用 1 件** / 重複スキップ 0 件）。科目の確定と起票は「一括起票」で行います」。
  - 当たるのは `AWS` → 通信費（仕訳ルール・優先度20）**の 1 件だけ**。
  - **`ﾌﾘｺﾐﾃｽｳﾘﾖｳ` は当たらない**。ルールのキーワードは全角の「振込手数料」で、
    **摘要は半角カナ**——キーワード照合は単純な部分一致で**全角と半角を同じものとして扱わない**（銀行-03 と同じ結論）。
    実際の銀行 CSV は半角カナで来ることが多いので、**全角キーワードのルールは実データにはまず当たらない**
    （この使い勝手は BUG-0406 として起票済み）。次のステップで手動設定すればよい。
  - `ﾘｿｸ` はルールなし＝候補未設定。

## ステップ 3: ポータルの作業キューで気づく（導線の確認）

サイドバー「**ホーム**」で業務ポータルへ。

- **確認ポイント**: 経理の作業キューに「**▶ 未起票の銀行明細: 3 件**」が現れている（0 件のときは行ごと消えている項目）。クリックすると **一括起票** 画面（/Accounting/BankPosting）へ直行する。

## ステップ 4: 候補を埋めて一括起票

**画面**: 会計業務 > 銀行 > **一括起票**

- **確認ポイント**: サマリ「未起票 3 件 ／ 起票対象（候補設定済み） N 件 ／ 候補未設定 N 件 ／ 対象外チェック中 0 件」。候補が入った行は「推定元」列が `rule`。
- **確認ポイント（列）**: 行の列は 日付 / 摘要 / 出金 / 入金 / **相手科目（候補）** / **部門** / 推定元 / 対象外。部門は仕訳ルールが持っていれば一緒に入るが、seed のルールは部門を持たないので**空のまま**来る。

1. `ﾘｿｸ` の行の「相手科目（候補）」で `受取利息` を選ぶ（推定元が `manual` になる）。ルールに当たらなかった行があればここで同様に設定。
2. **3 行とも「部門」列に `全社共通` を選ぶ**。通信費・支払手数料・受取利息はいずれも損益科目で、**部門が空だとその行は起票されずスキップされる**（ADR-0056。特定の部門に紐づかない共通費・共通収益なので全社共通が正解）。
3. 「**候補科目で一括起票**」→ 確認ダイアログ →「**起票する**」。

- **期待結果**: 「一括起票: 3 件起票（伝票 No.xxx, xxx, xxx） / 締め済み等スキップ 0 件 / 失敗 0 件」。
  部門を入れ忘れた行があると、そのぶん「**/ 部門未選択でスキップ n 件**」が結果ラベルに足され、警告トースト「n 件は部門が未選択のため起票していません（損益科目の行には部門が要ります）」が出る。**その行は未起票のまま残る**ので、部門を入れて押し直せばよい。
- **帳簿の中身**（仕訳帳・取り込んだ日付）:
  - AWS: 借方 **通信費 30,000** ＋ **仮払消費税 3,000** ／ 貸方 **普通預金 33,000**（相手科目の既定税区分による内税分解）
  - 手数料: 借方 **支払手数料 500** ＋ **仮払消費税 50** ／ 貸方 **普通預金 550**
  - 利息: 借方 **普通預金 15** ／ 貸方 **受取利息 15**（入金は貸借が逆向き・非課税系なら 2 行）
- 明細一覧では 3 行が「**起票済**」になり、黄色ハイライトが消え、「伝票No」列にリンク番号が入る。

## ステップ 5: 残高照合で「○ 一致」を見る

**画面**: 会計業務 > 銀行 > **残高照合**（対象口座 MB01 で検索）

- **期待結果**: 日付 **2026-08-23**（＝取り込んだ日付）の行が
  - 明細残高 = CSV に書いた最終残高（X−33,535）
  - 帳簿残高 = 同額
  - 差額 **0**・未起票（累計） **0**・判定「**○ 一致**」
- これで「銀行の言い分と帳簿の言い分が 1 円単位で一致した」ことが確認できた。月次締め前の照合作業がこの 1 画面で終わる。
- **それより前の日付が「⚠ 差異」でも慌てない。** デモ DB には銀行を通さない仕訳
  （経費の精算・入金消込など）が積もっているので、過去日は差額が残る。
  見るのは**いま取り込んだ日付の行**である。

- **補足（⚠ 差異になった場合)**: 本シナリオと並行して普通預金を動かす操作（経費の精算済にする・入金確定など）をした場合、帳簿残高がその分ズレる。照合画面の**帳簿残高列の実値**を見て、CSV の残高を貼り直せばよい（ステップ 6 の手順で一度削除 → 再取込）。

## ステップ 6: 後片付け（任意）

デモデータとして残しても整合は取れているが、消したい場合:

1. 明細一覧で取り込んだ日付の各行を開き「**起票を取り消す**」（確認ダイアログに伝票 No が出る）→「取り消す」→ 仕訳ごと削除され「未起票」に戻る。
2. 続けて「**この明細を削除**」→「削除する」→ 重複キーが解放され、同じ CSV を再取込できる状態に戻る。

**2026-08-19 の実機確認ではここまでやった**（明細 3 行・仕訳 3 本とも消え、最終伝票 No. も元に戻り、不変条件 44 本すべて緑）。
デモ DB の前提（起票済 11・対象外 2）を動かさないため、このシナリオは**毎回後片付けまでやる**ことを推奨する。

## つまずいたときは

- **プレビューに入らない行がある**: 日付が `2026/08/23` のような `yyyy/MM/dd` 形式で解釈できるか、出金・入金のどちらかが 1 円以上あるかを確認（両方 0 の行とヘッダ行はスキップされる）。
- **「重複スキップ」になる**: 同じ内容（日付|摘要|出金|入金）を過去に取り込んでいる。明細一覧から該当行を削除するとキーが解放される。
- **ルールが当たらない**: 仕訳ルールの摘要キーワードは**単純な部分一致で、全角と半角は別物**。
  seed のルールには全角キーワード（振込手数料・家賃・給与）と半角キーワード（ｻｰﾊﾞｰﾎｽﾃｨﾝｸﾞ・ﾄﾞｺﾓ）が混在していて、
  半角カナの CSV に当たるのは後者だけ。当たらなくても手動設定で先へ進める（ルールの育て方は 銀行-03）。
- **起票がスキップされる**: 明細日付の月が締め済み（「締め済み等スキップ」に計上され pending のまま）。会計年度画面で当該月を再オープンする。
- **「n 件は部門が未選択のため起票していません」**: 相手科目が損益科目の行に部門が入っていない（ADR-0056）。一覧の「部門」列を埋めて「候補科目で一括起票」を押し直す。明細は未起票のまま残っているので取り返せる。
