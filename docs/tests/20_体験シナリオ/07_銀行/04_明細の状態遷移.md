# 体験シナリオ 銀行-04: 明細の状態遷移（未起票 ⇄ 対象外 ⇄ 起票済 と削除）

> 作成: 2026-08-09 ／ 所要時間: 約30分 ／ 影響: 銀行明細 1 行と仕訳 1 本を作り、**すべて取り消して削除する**（末尾で未起票 0 件・帳簿は前後で完全に同一に戻る）。ステップ 7 で **2026-08 の月次期間を一時的に締める**ので、必ず同ステップ内で再オープンする
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。パスワードはユーザー名と同じ。
> たった 1 件の明細を、状態の輪（未起票 → 対象外 → 未起票 → 起票済 → 未起票 → 削除）で一周させる回。**どのボタンがどの状態でだけ現れるか**と、**取り消しがどこまで巻き戻すか**を体で覚える。

## 物語

月次照合をしていた山田太郎が、8/29 の事務用品の引き落とし 1,100 円を取り込んだ。
「これは経費精算で既に起票済みだから対象外かな……いや、やっぱり銀行側から起こそう」——迷って行ったり来たりし、起票したあとで「やっぱり月が違った」と取り消し、最後に明細ごと消して取り込み直す。実務では毎月のように起きる往復を、1 件で全部やってみる。

## ステップ 1: 帳簿残高を先に控える

**soumu_bucho** でログイン → サイドバー「**会計業務**」→ 銀行 > **残高照合**（対象口座 MB01 で検索）。

- **一番下の行（最新日付）の「帳簿残高」をメモ**する。以下これを **X** と呼ぶ。
- **なぜ先に見るか**: 次のステップの CSV に書く「残高」は**銀行側の残高**。1,100 円の出金があった直後の銀行残高は `X − 1,100` になるはずなので、CSV の残高列にはその値を書く。こうしておくと、起票する前は「差異」、起票した後は「一致」と**判定が動くのが見える**（決め打ちの残高を書くとこれが成立しない）。

## ステップ 2: 1 行だけ取り込む

**画面**: 会計業務 > 銀行 > **明細取込**（取込先口座は MB01 が自動選択。残存プレビュー警告が出ていたら先に「全てのプレビューを取り消す」で掃除する）

以下の 1 行を貼る。`{X-1100}` は **X から 1,100 を引いた実数**に置き換える（桁区切りのカンマは付けない。付けるなら `"7,484,920"` のように引用符でくくる）。ヘッダ行は無くてよい:

```
2026/08/29,BNK04 ｼﾞﾖｳﾀｲｾﾝｲ ｼﾞﾑﾖｳﾋﾝ,1100,,{X-1100}
```

→ 「**明細を取り込む**」→ 「プレビュー 1 件 / 重複スキップ 0 件 / スキップ行（ヘッダ・明細以外） 0 行 …」→ 「**この内容で登録**」。

- **期待結果**: 「**1 件を未起票の明細として登録しました（ルール適用 0 件 / 重複スキップ 0 件）。…**」。摘要が仕訳ルールのキーワードを 1 つも含まないので、候補は**空のまま**登録される（これがステップ 6 の手入力の題材になる）。

## ステップ 3: pending の見た目とボタンの出し分け

**画面**: 会計業務 > 銀行 > **明細一覧**（状態 = 未起票 で検索）

- **期待結果**: `BNK04 ｼﾞﾖｳﾀｲｾﾝｲ ｼﾞﾑﾖｳﾋﾝ` の **行全体が黄色**でハイライトされている。未起票＝「まだ帳簿に起こしていない、あなたの宿題」を一目で示す色。
- **確認ポイント**: 一覧に**新規作成ボタンも削除ボタンも無い**。銀行明細は「取り込むもの」であって手で作るものではなく、例外操作はすべて詳細画面に集約されている。

行をクリックして詳細画面を開く。

- **期待結果**:
  - 注記「**未起票の明細です。相手科目の確定と起票は「一括起票」画面で行います**」
  - 表示されるボタンは「**対象外にする**」「**この明細を削除**」の 2 つだけ（項目はすべて編集不可＝表示専用）
- **確認ポイント**: ポータル（サイドバー「ホーム」）の経理の作業キューに「**▶ 未起票の銀行明細: 1 件**」が現れている。0 件のときは行ごと消えている項目なので、この 1 件で復活する。

## ステップ 4: 対象外にする — そして「差異が消えない」ことを見る（BNK-08-1）

詳細画面で「**対象外にする**」。

- **期待結果**: 確認ダイアログ「**この明細を対象外にします（起票されなくなります）。よろしいですか？**」／ボタンは「**対象外にする**」「**キャンセル**」。
  - まず「キャンセル」で何も起きないことを確認してから、もう一度押して「対象外にする」。
- **期待結果**: トースト「明細を対象外にしました」。状態が「**対象外**」になり、注記が「**対象外の明細です（起票されません）。誤って対象外にした場合は「未起票に戻す」で起票対象に戻せます**」に変わる。ボタンは「**未起票に戻す**」「**この明細を削除**」に入れ替わる。
- **確認ポイント**: 明細一覧に戻ると**黄色が消えている**。銀行 > **一括起票** を開くと一覧に出てこない（一括起票の作業台は pending だけ）。ポータルの「未起票の銀行明細」も消える。
- **確認ポイント（仕様・重要）**: 銀行 > **残高照合** を開くと、日付 **2026-08-29** の行はこうなっている:
  - 明細残高 = `X − 1,100`（CSV に書いた値。**対象外にしても消えない**）
  - 帳簿残高 = **X**（まだ仕訳が無い）
  - 差額 = **−1,100** ／ 未起票（累計） = **0**（対象外は pending ではないので数えられない）／ 判定「**⚠ 差異**」

  つまり「**対象外にしたのに差異が消えない**」。照合表が読んでいるのは**明細の残高列**であって状態ではないので、excluded にしても残高の突合からは外れない。「差異を消す」＝「起票する」か「明細を削除する」のどちらかしかない、という設計。**運用でいちばん誤解されやすい点**なので、デモでは必ずここを見せる。

## ステップ 5: 未起票に戻す

同じ詳細画面で「**未起票に戻す**」。

- **期待結果**: 確認ダイアログ「**この明細を未起票に戻します（一括起票の対象に戻ります）。よろしいですか？**」／ボタンは「**未起票に戻す**」「**キャンセル**」→ 実行するとトースト「明細を未起票に戻しました」。
- **確認ポイント**: 黄色ハイライトと一括起票への再登場、ポータルの「未起票の銀行明細: 1 件」が**すべて戻る**。対象外は不可逆ではない、というのがこの往復の意味。

## ステップ 6: 候補科目を入れて一括起票する

**画面**: 会計業務 > 銀行 > **一括起票**

- **期待結果**: サマリ「未起票 **1** 件 ／ 起票対象（候補設定済み） **0** 件 ／ 候補未設定 **1** 件 ／ 対象外チェック中 0 件」。
- **確認ポイント（静かな落とし穴）**: この状態で「候補科目で一括起票」を押すと、トースト「**起票対象（相手科目候補が設定済みの未起票明細）がありません**」で何も起きない。**候補が空の明細はエラーにもならず pending のまま残る**ので、気づく手がかりはサマリの「候補未設定」の件数だけ。押して確かめてよい。

1. 該当行の「相手科目（候補）」で **消耗品費** を選ぶ。
   - **期待結果**: 「推定元」が **`manual`** になり、サマリが「起票対象 1 件 ／ 候補未設定 0 件」に変わる。
2. 「**候補科目で一括起票**」→ 確認ダイアログ「**1 件の明細を仕訳として一括起票します。よろしいですか？**」／ボタンは「**起票する**」「**キャンセル**」→「起票する」。

- **期待結果**: 結果ラベル「**一括起票: 1 件起票（伝票 No.84） / 締め済み等スキップ 0 件 / 失敗 0 件**」＋トースト「1 件を仕訳として起票しました（伝票 No.84）」。一覧から行が消える（pending でなくなったため）。
- **帳簿の中身**: 会計業務 > 帳簿 > **仕訳帳**（2026-08-29）に伝票 No.84 が 3 行:
  借方 **消耗品費 1,000** ＋ **仮払消費税 100** ／ 貸方 **普通預金 1,100**
  （相手科目「消耗品費」の既定税区分が課税仕入 10% なので、税込 1,100 を内税分解している。摘要は `銀行明細 BNK04 ｼﾞﾖｳﾀｲｾﾝｲ ｼﾞﾑﾖｳﾋﾝ`・種別は「自動」・状態は「確定」）
- **期待結果（明細一覧）**: 状態が「**起票済**」になり黄色が消え、「**伝票No**」列に **84** がリンクとして入る。クリックすると振替伝票の詳細に飛べる（明細 → 仕訳の追跡経路）。
- **期待結果（残高照合）**: 2026-08-29 の行が 明細残高 `X − 1,100` ／ 帳簿残高 `X − 1,100` ／ 差額 **0** ／ 未起票（累計） **0** ／ 判定「**○ 一致**」。ステップ 4 で見た ⚠ 差異 が、起票によって解消した。

## ステップ 7: 締め済みの月では取り消せない（赤伝を促す・要復旧）

> このステップは**月次期間の締め状態を一時的に変える**。必ず最後の再オープンまでやり切ること。

1. サイドバー 設定 > **会計年度** → **第18期（2026年度）** を開く → 「月次期間」リストの **2026-08** の行の「状態」を「**締め済み**」に変更 → 「**登録**」。
   - **確認ポイント**: その月に下書き伝票が残っていると、黄色のトースト「この期間には下書きの伝票が N 件残っています。締める前に確定または削除を検討してください（保存すると締めは実行されます）」が出る。**警告するだけでブロックはしない**（締めは保存で実行される）。
2. 銀行 > **明細一覧** → `BNK04 …` の行（起票済）→ 詳細画面 → 「**起票を取り消す**」。

- **期待結果**: 確認ダイアログは**出ない**まま、赤いトースト
  「**仕訳 No.84 の期間は締め済みのため起票を取り消せません（赤伝（反対仕訳）で対応してください）**」
  で止まる。明細も仕訳も何も変わらない。
- **確認ポイント（会計としての正しさ）**: 締めた月の仕訳を後から消すのは、報告済みの数字を書き換えるのと同じ。だから**削除ではなく赤伝（反対仕訳）で打ち消す**のが会計の作法で、システムはその作法へ誘導している。赤伝の手順は 06_会計_仕訳と帳簿/06 が担当。
3. **復旧（必須）**: 設定 > **会計年度** → 第18期 → 2026-08 の状態を「**進行中**」に戻して「**登録**」。

- **確認ポイント**: 締めっぱなしにすると、以降のシナリオで経費の仕訳生成・銀行の起票がすべて「締め済み」で弾かれる。本書を中断する場合も**ここだけは必ず戻す**。

## ステップ 8: 起票を取り消す（仕訳ごと削除）

もう一度 明細一覧 → `BNK04 …` の詳細 → 「**起票を取り消す**」。

- **期待結果**: 確認ダイアログ「**仕訳 伝票 No.84 を削除して、この明細を未起票に戻します。よろしいですか？**」／ボタンは「**取り消す**」「**キャンセル**」→「取り消す」→ トースト「**仕訳 伝票 No.84 を削除し、明細を未起票に戻しました**」。
- **期待結果**: 明細は **pending**（黄色が復活・注記とボタンもステップ 3 と同じ状態）。相手科目（候補）は消耗品費のまま残っている（候補は状態と独立）。
- **期待結果（帳簿）**: 仕訳帳から No.84 が**消えている**（明細行ごと物理削除）。残高照合の 2026-08-29 行は 差額 **−1,100**・未起票（累計） **1**・判定「**⚠ 差異**」に戻る。
- **確認ポイント（採番は乱れない）**: No.84 が空き番になるが、次の採番は「年度内の最大値 +1」なので**次に起票するものがまた No.84 を取る**（自己修復する）。番号が飛んだままにならないのはこのため。

## ステップ 9: リンク切れの救済経路（読むだけ）

「仕訳だけが先に消えていて、明細が起票済みのまま取り残された」場合、「起票を取り消す」は次のダイアログに変わる:

> **紐づく仕訳が見つかりませんでした。明細の状態だけを未起票に戻します。よろしいですか？** ／「未起票に戻す」「キャンセル」

- **確認ポイント（なぜ実演しないか）**: **確定済みの伝票は画面から削除できない**（振替伝票の削除ボタンは「下書きの伝票のみ削除できます（確定済みは赤黒訂正で対応してください）」で弾く＝ADR-0026）。したがってこの分岐は通常操作では発生せず、**データ移行や DB 直修正で仕訳だけが消えたときの整合回復用**の経路。
- **確認ポイント**: この経路では仕訳の削除を試みず、明細側のリンクと状態だけを直す。「壊れたデータを画面から直せる」ようにしてあることが、運用では地味に効く。

## ステップ 10: 明細を削除すると重複キーが解放される

pending に戻っている詳細画面で「**この明細を削除**」。

- **期待結果**: 確認ダイアログ「**この明細を削除します。重複キーが解放されるため、同じ明細を再取込できるようになります。よろしいですか？**」／ボタンは「**削除する**」「**キャンセル**」→「削除する」→ トースト「明細を削除しました」→ **明細一覧に自動で戻る**。
- **確認（キー解放の実証）**: 銀行 > **明細取込** で**ステップ 2 とまったく同じ 1 行**をもう一度貼って「明細を取り込む」。
  - **期待結果**: 「**プレビュー 1 件 / 重複スキップ 0 件** / スキップ行（ヘッダ・明細以外） 0 行 …」。削除していなければ「プレビュー 0 件（重複スキップ 1 件 …）」になっていたはずで、**削除がキーを解放したことがこの 1 件で証明される**。
  - → 「**全てのプレビューを取り消す**」→「取り消す」で片付ける（登録しない）。

これで「未起票 → 対象外 → 未起票 → 起票済 → 未起票 → 削除 → 再取込できる」という状態の輪が一周した。

## 後片付け（必須・元の状態に戻す）

1. 銀行 > **明細取込** を開き、結果ラベルに残存プレビュー警告が**出ていない**こと（プレビュー 0 件）を確認する。出ていたら「全てのプレビューを取り消す」→「取り消す」。
2. 銀行 > **明細一覧**（状態 = 未起票）が **0 件**、状態を空にして日付 2026-08-29 で検索しても **0 件**。
3. 設定 > **会計年度** → 第18期（2026年度）の **2026-08 が「進行中」**（＝ステップ 7 の復旧が済んでいる）。**ここが最重要**。
4. 会計業務 > 帳簿 > **仕訳帳** に 2026-08-29 付の伝票が無い（No.84 も存在しない）。合計残高試算表・出納帳も本書の前後で無変化。
5. 銀行 > **残高照合** から 2026-08-29 の行が消え、ステップ 1 で見た並びに戻っている。

## つまずいたときは

- **「起票を取り消す」ボタンが出ない**: 状態が起票済でない。pending なら「対象外にする」「この明細を削除」、excluded なら「未起票に戻す」「この明細を削除」しか出ない（ボタンは状態でしか出し分けていない）。
- **一括起票で「締め済み等スキップ 1 件」になる**: 明細日付の月が締め済み（ステップ 7 の復旧を忘れていないか）、または明細日付が会計年度の範囲外。締め済みでも**明細は pending のまま残る**ので、期間を開けてもう一度押せばよい。
- **伝票番号が No.84 でない**: 番号は年度内の最終 +1。他の操作を挟めばずれる。**金額と貸借が合っていれば正常**で、以降は本書の 84 を実際の番号に読み替える。
- **残高照合が「○ 一致」にならない**: 本書と並行して普通預金を動かす操作（経費の精算済にする・入金確定・購買の支払登録など）をすると帳簿残高が動く。照合画面の**帳簿残高の実値**を見て、明細を削除 → CSV の残高を書き直して再取込すればよい。
- **対象外にしたのに差異が消えない**: 仕様（ステップ 4）。excluded は残高の突合からは外れない。消したいなら起票するか、明細ごと削除する。
- **明細を削除したのに再取込で「重複スキップ」になる**: 同じ日付・摘要・金額の明細が**他にも**残っている（重複キーに残高は含まれないので、残高だけ違う行は同一扱い）。明細一覧を摘要で確認する。
