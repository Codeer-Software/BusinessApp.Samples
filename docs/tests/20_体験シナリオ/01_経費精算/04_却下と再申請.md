# 体験シナリオ 経費-04: 却下と再申請（差し戻し → 修正 → ルートが変わる）

> 作成: 2026-08-09 ／ **更新: 2026-08-17 ADR-0066（明細行化）を反映——修正するのは「明細の金額」になり、ヘッダの合計がそれに追随する** ／ 2026-08-09 ADR-0048（承認ルートの積み上げ化）を反映——35,000 円への修正後が「課長 → 部長」の2段になった（ステップ4〜5）／ 所要時間: 約20分 ／ 影響: 申請1本が「承認済」で残る（後片付けで経理精算まで進めれば完結。仕訳2本）
> 主役: **kaihatsu2_ippan**（開発2部 第一課 松本結衣）→ **kaihatsu2_kacho1**（第一課長 佐々木綾）→ **kaihatsu2_bucho**（部長 加藤正雄）
> 「一度却下された申請がどう戻ってきて、直すと承認ルートまで変わる」を体験する。差し戻しの動線はこのアプリの承認 UX の要。
> **さらに更新: 2026-08-17 夜 ADR-0066 の UI 改訂（4 ブロック構成）**——申請画面が 「1. この申請について／2. 明細を入力する（1 件ぶんの入力欄＋「この内容で明細に追加」）／3. 追加した明細（リスト＋合計）／4. 申請と承認」の 4 ブロックになった。**明細はグリッドに行を足すのではなく、入力欄で 1 件ぶん埋めて「追加」で積む**。AI 読み取りと領収書は入力欄（＝その明細）が持つので、1 回のアップロードで抽出値とファイルが同じ明細に載る。既存の明細を直すときは**リストの行をクリックして入力欄に読み込み**、「この明細を更新」を押す。**金額・仕訳・承認ルートの期待値は一切変わらない**（入力の道筋だけが変わった）。

## 物語

松本結衣が外部研修の参加費を 25,000 円で申請したが、課長の佐々木綾から「見積書と金額が違う。正しい金額で出し直して」と却下された。
確認すると実際は 35,000 円。修正して再申請すると、30,000 円を超えたので今度は**課長の後ろに部長決裁が積み上がる**。

## 前提

| 項目 | 内容 |
|---|---|
| ルート | 25,000 円=`経費_課長まで`（佐々木綾・単独）／35,000 円=`経費_部長まで`（**佐々木綾 → 加藤正雄・吉田直樹の OR** の2段。ADR-0048 の積み上げ方式） |
| 見どころ | 却下で「下書き」に戻る／再申請で承認ルートが**作り直される**（段が増える）／履歴に試行回数（AttemptNo）が積まれる |

## ステップ 1: 申請（松本結衣）

**kaihatsu2_ippan** でログイン → 経費精算 → 新規作成。

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `外部研修「実践クラウド設計」参加費` |
| 明細 1 行目 | 利用日=本日 ／ 費目=`図書研修費` ／ 金額（税込）=`25,000` |

→ 「申請」。承認フローは `▶佐々木綾` の1段。

## ステップ 2: 却下（佐々木綾）（X02-1）

**kaihatsu2_kacho1** でログイン → 承認待ち → 開く → コメント欄に `見積書は35,000円です。金額を修正して再申請してください` → 「**却下**」（赤）。

- **期待結果**: トースト「却下しました」（Info 色）。フロー表示に `✗佐々木綾`。
- 松本さんに通知「**却下されました** — …（コメント: 見積書は35,000円です。…）」が飛ぶ。コメントが通知本文に入るのがポイント。

## ステップ 3: 差し戻された申請を確認（松本結衣）

**kaihatsu2_ippan** で再ログイン。

- **確認ポイント**:
  - 通知に却下の連絡（コメント付き）。
  - 「**申請中**」一覧に**状態=却下のまま残っている**（承認済は消えるが、却下は申請者のアクション待ちなので残る仕様）。
  - 申請を開くと精算ステータスは「**下書き**」に戻っていて、**ヘッダも明細も再び編集できる**（ブロック 2「明細を入力する」も戻っている。明細を直すときは**リストの行をクリックして入力欄に読み込む**）。ボタンは「申請」でなく「**再申請**」になっている。

## ステップ 4: 修正して再申請 → ルートに段が増える

**明細 1 行目の金額**を `35,000` に修正 → 「**再申請**」。

- **確認ポイント（合計の追随）**: 明細の金額を直した瞬間、ヘッダの「合計金額（税込）」が 25,000 → **35,000** に変わる。
  ヘッダの合計は手で直せない（明細からの導出値）ので、**直す場所は明細の側だけ**。
- **確認ポイント（レシートが増えたときは明細を足す）**: 「研修費に加えて教材費も」というときは、
  金額を書き換えるのではなく、入力欄にもう 1 件ぶん入れて「**この内容で明細に追加**」する。
  合計はその分だけ増え、承認ルートも合計で解決し直される。
- **期待結果**: トースト「再申請しました」。承認フローが**丸ごと作り直され**、`▶佐々木綾→(加藤正雄,吉田直樹)` の **2段**になる（30,000 円を超えて部長段が積み上がった）。
- **確認ポイント**: **却下した佐々木綾がもう一度 1 段目に立つ**。積み上げ方式では課長が抜けないので、差し戻した本人が修正結果を再確認してから部長へ回る——却下→再申請の筋としてはむしろ自然（ADR-0048）。
- **確認ポイント**: 承認履歴に `申請 → 却下 → 再申請` が時系列で積まれている。再申請の試行回数は 2 回目。「**（再）承認依頼**」の通知が飛ぶのは**1段目の佐々木綾だけ**（部長2名にはまだ届かない＝順次到達）。

## ステップ 5: 課長 → 部長の順に承認

1. **kaihatsu2_kacho1**（佐々木綾）で再度ログイン → 承認待ち → 開く → 金額が 35,000 円に直っていることを確認して「承認」。
   - **期待結果**: フローが `✓佐々木綾→(▶加藤正雄,▶吉田直樹)` に進み、部長2名へ承認依頼通知が飛ぶ。
2. **kaihatsu2_bucho**（加藤正雄）でログイン → 承認待ち → 開く → 「承認」。
   - **期待結果**: 最終承認（吉田直樹側は `—` スキップ）。松本さんに「承認されました」。

## 後片付け（任意）

そのままでも他シナリオに影響はないが、精算処理待ちに残るのが気になる場合は **soumu_bucho** で 仕訳生成 → 精算済 → 完了 まで進める（経費-01 と同じ。仕訳: 図書研修費 31,819 ＋ 仮払消費税 3,181 ／ 未払金 35,000）。

## つまずいたときは

- **「再申請」ボタンが出ない**: 申請者本人か確認（他人の却下済み申請には出ない）。
- **再申請しても部長段が増えない（課長1段のまま）**: **ヘッダの合計金額**が 35,000 になっているか確認する（明細の金額を直せば自動で変わる）。再申請は**その時点の明細**でルートを再解決する。テンプレート `経費_部長まで` が「課長 → 部長」の2段構成になっているか（システム管理 > 承認 > 承認フローテンプレート）も確認。旧仕様（〜2026-08-08）は部長のみの1段だった。
- **却下したのに申請者が編集できない**: 精算ステータスが「下書き」に戻っているか確認。戻っていなければ不具合として記録を。
