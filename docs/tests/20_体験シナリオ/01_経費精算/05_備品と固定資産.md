# 体験シナリオ 経費-05: 備品と固定資産（10万円の壁 → 台帳自動登録 → 償却まで）

> 作成: 2026-08-09 ／ **更新: 2026-08-17 ADR-0066（明細行化）を反映——固定資産の判定は「行ごと」になり、1 申請に資産の行と経費の行を混ぜられるようになった** ／ 2026-08-09 ADR-0048（承認ルートの積み上げ化）を反映——132,000 円の承認が「課長 → 部長」の2段になった（ステップ1〜2）／ 所要時間: 約30分 ／ 影響: 仕訳 2〜3 本＋固定資産 1 件追加
> 主役: **kaihatsu1_ippan**（開発1部 第一課 小林美咲）→ **kaihatsu1_kacho1**（第一課長 山本由美）→ **kaihatsu1_buchodairi**（部長代理 渡辺剛）→ **soumu_bucho**（経理 山田太郎）
> 「経費で買った備品が、金額次第で固定資産に化ける」を境界値ごと体験する。少額基準・台帳の自動登録・耐用年数未設定の罠・償却仕訳まで一本道で。
> **さらに更新: 2026-08-17 夜 ADR-0066 の UI 改訂（4 ブロック構成）**——申請画面が 「（見出し無しの申請ヘッダ）／レシート 1 枚ぶんを入力（1 件ぶんの入力欄＋「この内容で明細に追加」）／この申請の明細（一覧＋合計）／承認」の 4 つのカードに分かれた。**明細はグリッドに行を足すのではなく、入力欄で 1 件ぶん埋めて「追加」で積む**。AI 読み取りと領収書は入力欄（＝その明細）が持つので、1 回のアップロードで抽出値とファイルが同じ明細に載る。既存の明細を直すときは**リストの行をクリックして入力欄に読み込み**、「この明細を更新」を押す。**金額・仕訳・承認ルートの期待値は一切変わらない**（入力の道筋だけが変わった）。

## 物語

小林美咲が開発用の 4K モニター（132,000 円）を購入した。10 万円以上の資産性支出なので、アプリが自動で「固定資産計上対象」と判定し、承認後に固定資産台帳へ登録される。経理はさらに決算時の償却仕訳まで進めてみる。

## 前提

| 項目 | 内容 |
|---|---|
| 少額基準 | `SMALL_ASSET_EXPENSE` = 100,000 円（制度閾値マスタ） |
| ルート | 132,000 円 → **課長 → 部長**の2段（テンプレート `経費_部長まで`。1段目=第一課長 山本由美・単独／2段目=田中宏・渡辺剛の OR） |
| 仕訳番号 | 現在の最終+1 以降（目安） |

## ステップ 1: 10 万円の壁を触って確かめる（EXP-A01/A02）

**kaihatsu1_ippan** でログイン → 経費精算 → 新規作成。

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `開発用 4K モニター` |
| 明細 1 行目 | 利用日=本日 ／ 費目=`備品` |

入力欄の下の「**▶ 固定資産として計上する**」を開くと「**固定資産**」のチェックと「**資産管理番号**」がある。

- 明細の金額に `99,999` → 固定資産チェックは **OFF のまま**、トーストも出ない（EXP-A01）。
- 金額を `100,000` に直す → チェックが**自動 ON** ＋ Info トースト「**少額基準以上の資産性支出が 1 行あった**ため固定資産計上対象にしました（承認後に固定資産台帳へ登録されます）」（EXP-A02。境界は「以上」）。
- **確認ポイント（行ごとの判定）**: 判定は**行単位**。文言も「◯ 行あった」と行数で出る。
  1 申請の中に「10 万円のモニター（資産）」と「3,000 円のケーブル（経費）」を並べても、
  **資産になるのはモニターの行だけ**。
- **確認ポイント**: その行の費目を「消耗品費」に変えるとチェックは**無言で OFF** に戻る（資産性の費目ではないため）。備品に戻して続行。

明細の金額を実額 `132,000` にし、同じ行の資産管理番号に `FA-2026-101` を入力 → 「申請」。

- **期待結果**: `▶開発1部 第一課長 山本由美→(開発1部 部長 田中宏,開発1部 部長代理 渡辺剛)` の **2段**（30,000〜199,999 は「課長 → 部長」まで積み上がる＝ADR-0048）。2段目にはまだ `▶` が付かない（順次到達）。

## ステップ 2: 課長 → 部長代理の順に承認（EXP-R07/R08）

1. **kaihatsu1_kacho1**（山本由美）でログイン → 承認待ち → 開く → 「承認」。
   - **期待結果**: フローが `✓山本由美→(▶田中宏,▶渡辺剛)` に進み、**この瞬間に部長2名へ承認依頼通知**が飛ぶ。状態はまだ「進行中」。
   - **確認ポイント**: 課長を通す設計なので、部門の支出は必ず自分の課長が把握する。山本由美が承認するまで部長の承認待ちには出ない。
2. **kaihatsu1_buchodairi**（渡辺剛）でログイン → 承認待ち → 開く → 「承認」。
   - **確認ポイント**: 部長代理の承認でも段は完了する（部長 田中宏側は `—` スキップ）。部の director はどちらも同格。最終承認なので状態が「承認済」になり、申請者に通知が飛ぶ。

## ステップ 3: 仕訳生成 = 資産計上＋台帳登録（経理）

**soumu_bucho** でログイン → 経費精算（精算処理待ち着地）→ 開く → 「**仕訳を生成**」。

- **期待結果**: 借方が費用でなく **工具器具備品 120,000** ＋ **仮払消費税 12,000** ／ 貸方 **未払金 132,000**。
- トースト「仕訳 No.◯ を生成しました（**明細 1 行** / 借方 **工具器具備品（費目: 備品）** ほか / 貸方 未払金 132,000 円）」——費目名ではなく**実際に記帳される科目名**が主で、違うときだけ費目名を併記する（改善候補 B-2・2026-08-13）。資産計上時の借方科目も勘定科目マスタから引いている（旧実装は科目名のハードコード）。
- Info トースト「固定資産台帳に **1 件**を登録しました（耐用年数・償却方法は台帳で確定してください）」。
- **確認ポイント（振り替わるのはその行だけ）**: 資産の行だけ借方が 1520 工具器具備品になり、
  同じ申請に経費の行があればそちらは費目の既定科目のまま。混在した申請でも 1 本の仕訳に収まる。
- 続けて「精算済にする」→「完了にする」。

## ステップ 4: 台帳で耐用年数の罠を踏む

サイドバー「ホーム」→「**会計業務**」→ 帳簿 >「**固定資産台帳**」→ FA-2026-101 を開く。

- **確認ポイント**: 取得価額 **120,000（税抜）**、償却方法=定額法（仮）、**耐用年数が空**、備考に自動登録の注記
  （「経費申請「開発用 4K モニター」**1 行目**から自動登録」と、どの明細から来たかまで書かれる）。
- **確認ポイント（取得日と名前）**: 取得日は**その行の利用日**、資産の名前は**行の摘要**（空ならヘッダの件名）。
  行ごとに違うものを買っていても、それぞれ正しい日付と名前で台帳に載る。
- 対象年度に「第18期（2026年度）」を選び「**この年度の償却仕訳を生成**」→ **期待結果**: Info「この年度の償却額はありません（対象外または償却済み）」——**耐用年数が空だと償却 0** になる罠（登録しただけでは償却は始まらない）。

## ステップ 5: 耐用年数を入れて償却仕訳（任意）

耐用年数に `4` を入力して「登録」→ 再度「この年度の償却仕訳を生成」。

- **期待結果**: 「償却仕訳 No.◯（20,000 円）を生成しました」。年間 30,000 円（120,000÷4）の 8/12 ヶ月分＝**20,000 円**（8月取得・3月決算の月割）。仕訳日は期末 2027-03-31、借方 減価償却費／貸方 工具器具備品（直接法）。
- 同じボタンをもう一度押すと「この年度の償却仕訳は既に生成済みです」（二重生成ガード）。

## つまずいたときは

- **チェックが自動 ON にならない**: **その行の**費目が「備品」（資産性フラグ付き）か、制度閾値マスタの SMALL_ASSET_EXPENSE が 100,000 のままか確認。
- **固定資産の欄が見つからない**: 入力欄の下の「**▶ 固定資産として計上する**」を開く（既定で畳んである）。リスト側では「固定資産」列のチェックで確認できる。
- **台帳に登録されない**: 同じ資産コードが既に存在すると**無言でスキップ**される仕様。コードを変えて確認を。
  資産管理番号を空にした場合のコードは `EXP-{申請Id}-{行番号}`（明細行化で行番号が付くようになった）。
- **償却仕訳の生成が「締め済み」で弾かれる**: 期末月（2027-03）の期間が締まっている場合。会計年度画面で再オープンする。
