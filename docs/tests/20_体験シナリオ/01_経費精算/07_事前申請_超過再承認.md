# 体験シナリオ 経費-07: 実費超過の自動再承認（見込み超過 → ルート格上げ → 再決裁）

> 作成: 2026-08-09 ／ **更新: 2026-08-17 ADR-0066（明細行化）を反映——実費は明細に入れる形になり、再承認の判定が「承認者の段構成が変わったか」の突き合わせになった** ／ 2026-08-09 ADR-0048（承認ルートの積み上げ化）を反映——32,000 円への再承認が「課長 → 部長」の2段になった（ステップ2〜3）／ 所要時間: 約25分 ／ 影響: 仕訳 2 本追加（32,000 円の旅費）
> 主役: **eigyo_ippan**（営業部 第一課 伊藤さくら）→ **eigyo_kacho1**（第一課長 高橋恵子）→ **eigyo_bucho**（部長 佐藤健一）→ **soumu_bucho**（経理）
> 事前申請の「実費が見込みを超えたら自動で承認を取り直す」ガバナンスを体験する。今回は 110% 超過と 30,000 円区分跨ぎの両方を一度に踏む。
> **さらに更新: 2026-08-17 夜 ADR-0066 の UI 改訂（4 ブロック構成）**——申請画面が 「1. この申請について／2. 明細を入力する（1 件ぶんの入力欄＋「この内容で明細に追加」）／3. 追加した明細（リスト＋合計）／4. 申請と承認」の 4 ブロックになった。**明細はグリッドに行を足すのではなく、入力欄で 1 件ぶん埋めて「追加」で積む**。AI 読み取りと領収書は入力欄（＝その明細）が持つので、1 回のアップロードで抽出値とファイルが同じ明細に載る。既存の明細を直すときは**リストの行をクリックして入力欄に読み込み**、「この明細を更新」を押す。**金額・仕訳・承認ルートの期待値は一切変わらない**（入力の道筋だけが変わった）。

## 物語

伊藤さくらが名古屋の顧客訪問を見込み 28,000 円で事前申請し、課長の承認を得た。ところが急な行程変更で実費は 32,000 円に。見込みの 110%（30,800 円）を超え、さらに 30,000 円の決裁区分も跨いだため、アプリは自動で**課長 → 部長の再承認**を要求する。

## 前提

| 項目 | 内容 |
|---|---|
| 再承認の発火条件 | ①実費合計 > 見込み×110% **または** ②**いま必要な承認者の段構成が、実際に承認された段構成と違う**。今回は両方に該当（片方だけでも発火する＝EXP-P02/P03） |
| ルートの変化 | 28,000 円=`経費_課長まで`（高橋恵子・単独）→ 32,000 円=`経費_部長まで`（**高橋恵子 → 佐藤健一・鈴木大輔の OR** の2段。積み上げ方式＝ADR-0048） |
| **②の判定が「段構成の突き合わせ」になった理由（ADR-0066）** | 明細行化で、実費確定のあいだ**明細を編集できる**ようになった。金額区分の比較だけだと「実費を入れるついでに交際費の行を足した」ようなケースを取りこぼす。**必要な承認者の顔ぶれが変わったか**を直接見れば、金額の跨ぎも費目の追加も同じ 1 つの判定で捕まえられる |

## ステップ 1: 事前申請と1回目の承認

**eigyo_ippan** でログイン → 経費精算 → 新規作成:

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `名古屋出張（△△社訪問）` |
| 申請区分 | `事前申請（これから支払う）` |
| 明細 1 行目 | 利用日=来週 ／ 費目=`旅費交通費` ／ 金額（税込）=`28,000`（見込みの内訳） |

→ 「申請」→ フロー `▶高橋恵子`。**見込み額に 28,000 が記録される**。

**eigyo_kacho1** でログインして「承認」→ 承認済。

## ステップ 2: 実費 32,000 円を確定 → 自動再承認（EXP-P02/P03）

**eigyo_ippan** に戻り、申請を開く。承認済なので**明細だけが編集可能**になっている。

明細 1 行目の金額を `32,000` に直す（合計金額が追随する）→ 「**実費を確定**」。

- **期待結果**: トースト「**実費が見込みを超過したため再承認を依頼しました**」。
  - 精算ステータスが「**申請中**」に戻る。
  - 承認フローが**課長 → 部長の2段に作り直される**: `▶高橋恵子→(佐藤健一,鈴木大輔)`。
  - 承認履歴に理由付きの再申請行「実費 32,000 円が見込み 28,000 円を超過したため再承認」。試行回数 2。
  - 「**（再）承認依頼**」通知が飛ぶのは**1段目の高橋恵子だけ**（部長にはまだ届かない＝順次到達）。
- **確認ポイント**: 課長の高橋恵子には**もう一度回る**（積み上げ方式では課長が抜けない＝ADR-0048）。「見込みで承認した課長が、超過した実費も確認したうえで部長へ上げる」という自然な筋になる。旧仕様（〜2026-08-08）では課長を飛ばして部長のみに回っていた。
- **確認ポイント（見込みは動かない）**: 再承認になっても**見込み額は 28,000 のまま**。
  比較の基準が動いてしまうと「何に対する超過なのか」が分からなくなるため、上書きしない設計。

## ステップ 2.5: 金額を変えずに再承認を踏む（任意・2026-08-17 新設）

「110% 以内なのに再承認になる」ケースも試せる。別の事前申請を作って:

1. 明細 1 行（`旅費交通費 20,000`）で申請 → 課長が承認
2. 実費確定のときに**金額はそのままで、入力欄から `交際費 3,000`（3 項目入り）をもう 1 件追加する**
3. 「実費を確定」

- **期待結果**: 合計 23,000 円は見込み 20,000 の 115%（110% 超）なので、まずこの条件で再承認になる。
  さらに**交際費の行が入ったことで総務段が必要になり**、新しいルートは `課長 → 総務` の 2 段。
- **確認ポイント**: 金額の増え方が 110% 以内（例: 見込み 20,000 → 明細 `旅費 18,000` ＋ `交際費 3,000` = 21,000）でも、
  **総務段が増えるので再承認になる**。段構成を突き合わせているからこそ捕まえられるケース。
- 確認できたらこの申請はキャンセル → 下書き削除で片付ける。

## ステップ 3: 課長 → 部長の再決裁

1. **eigyo_kacho1**（高橋恵子）でログイン → 承認待ち → 開く → **明細の金額が 32,000 円になっている**ことを確認して「**承認**」。
   - **期待結果**: フローが `✓高橋恵子→(▶佐藤健一,▶鈴木大輔)` に進み、部長2名へ通知が飛ぶ。
   - **確認ポイント**: 承認者は明細をそのまま読める（何にいくら使ったかが行で並ぶ）。
     見込み額と合計金額が並んで表示されるので、超過の幅も画面で分かる。
2. **eigyo_bucho**（佐藤健一）でログイン → 承認待ち → 開く。
   - **確認ポイント**: 承認フロー欄に1回目の履歴（✓高橋恵子）と2回目の現在地が両方読み取れる。コメント `行程変更を確認。承認します` を入れて「**承認**」。
   - **期待結果**: 最終承認（鈴木大輔側は `—`）。伊藤さんに「承認されました」。

## ステップ 4: 経理精算

**soumu_bucho** → 精算処理待ち → 開く → 「仕訳を生成」。

- **期待結果**: 借方 **旅費交通費 29,091** ＋ **仮払消費税 2,909** ／ 貸方 **未払金 32,000**。部門「営業部」。
- 「精算済にする」→「完了にする」。

## つまずいたときは

- **再承認にならず普通に確定した**: 実費が 30,800 円以下で、かつ承認者の段構成も変わらなかった可能性（それは経費-06 の正常系）。31,000 円なら 110% 超のみ、32,000 円なら区分跨ぎも重なる。
- **再承認に部長段が付かない（課長1段のまま）**: 承認ルート判定マスタの金額範囲と、テンプレート `経費_部長まで` が「課長 → 部長」の2段になっているかを確認。実費（＝明細合計）でテンプレートが再解決される仕様。
- **明細が編集できない**: 精算ステータスが「承認済」で、まだ実費を確定していない状態でのみ編集できる。
- **「実費を確定」を一般ユーザー以外が押してしまった**: 実はこのボタンには操作者の権限ゲートが無い（誰でも押せる）。気づいた点として UX メモに残す価値あり。
