# 体験シナリオ 経費-07: 実費超過の自動再承認（見込み超過 → ルート格上げ → 再決裁）

> 作成: 2026-08-09 ／ **更新: 2026-08-09 ADR-0048（承認ルートの積み上げ化）を反映——32,000 円への再承認が「課長 → 部長」の2段になった（ステップ2〜3）** ／ 所要時間: 約25分 ／ 影響: 仕訳 2 本追加（32,000 円の旅費）
> 主役: **eigyo_ippan**（営業部 第一課 伊藤さくら）→ **eigyo_kacho1**（第一課長 高橋恵子）→ **eigyo_bucho**（部長 佐藤健一）→ **soumu_bucho**（経理）
> 事前申請の「実費が見込みを超えたら自動で承認を取り直す」ガバナンスを体験する。今回は 110% 超過と 30,000 円区分跨ぎの両方を一度に踏む。

## 物語

伊藤さくらが名古屋の顧客訪問を見込み 28,000 円で事前申請し、課長の承認を得た。ところが急な行程変更で実費は 32,000 円に。見込みの 110%（30,800 円）を超え、さらに 30,000 円の決裁区分も跨いだため、アプリは自動で**課長 → 部長の再承認**を要求する。

## 前提

| 項目 | 内容 |
|---|---|
| 再承認の発火条件 | 実費 > 見込み×110% **または** ルート区分が変わる（今回は両方に該当。片方だけでも発火する＝EXP-P02/P03） |
| ルートの変化 | 28,000 円=`経費_課長まで`（高橋恵子・単独）→ 32,000 円=`経費_部長まで`（**高橋恵子 → 佐藤健一・鈴木大輔の OR** の2段。積み上げ方式＝ADR-0048） |

## ステップ 1: 事前申請と1回目の承認

**eigyo_ippan** でログイン → 経費精算 → 新規作成:

| 項目 | 入力値 |
|---|---|
| 件名 | `名古屋出張（△△社訪問）` ／ 利用日 | 来週 ／ 費目 | `旅費交通費` |
| 申請区分 | `事前申請（これから支払う）` ／ 見込み額 | `28,000` |

→ 「申請」→ フロー `▶高橋恵子`。

**eigyo_kacho1** でログインして「承認」→ 承認済。

## ステップ 2: 実費 32,000 円を確定 → 自動再承認（EXP-P02/P03）

**eigyo_ippan** に戻り、申請を開いて実費（税込）`32,000` → 「**実費を確定**」。

- **期待結果**: トースト「**実費が見込みを超過したため再承認を依頼しました**」。
  - 精算ステータスが「**申請中**」に戻る。
  - 承認フローが**課長 → 部長の2段に作り直される**: `▶高橋恵子→(佐藤健一,鈴木大輔)`。
  - 承認履歴に理由付きの再申請行「実費 32,000 円が見込み 28,000 円を超過したため再承認」。試行回数 2。
  - 「**（再）承認依頼**」通知が飛ぶのは**1段目の高橋恵子だけ**（部長にはまだ届かない＝順次到達）。
- **確認ポイント**: 課長の高橋恵子には**もう一度回る**（積み上げ方式では課長が抜けない＝ADR-0048）。「見込みで承認した課長が、超過した実費も確認したうえで部長へ上げる」という自然な筋になる。旧仕様（〜2026-08-08）では課長を飛ばして部長のみに回っていた。

## ステップ 3: 課長 → 部長の再決裁

1. **eigyo_kacho1**（高橋恵子）でログイン → 承認待ち → 開く → 実費が 32,000 円になっていることを確認して「**承認**」。
   - **期待結果**: フローが `✓高橋恵子→(▶佐藤健一,▶鈴木大輔)` に進み、部長2名へ通知が飛ぶ。
2. **eigyo_bucho**（佐藤健一）でログイン → 承認待ち → 開く。
   - **確認ポイント**: 承認フロー欄に1回目の履歴（✓高橋恵子）と2回目の現在地が両方読み取れる。コメント `行程変更を確認。承認します` を入れて「**承認**」。
   - **期待結果**: 最終承認（鈴木大輔側は `—`）。伊藤さんに「承認されました」。

## ステップ 4: 経理精算

**soumu_bucho** → 精算処理待ち → 開く → 「仕訳を生成」。

- **期待結果**: 借方 **旅費交通費 29,091** ＋ **仮払消費税 2,909** ／ 貸方 **未払金 32,000**。部門「営業部」。
- 「精算済にする」→「完了にする」。

## つまずいたときは

- **再承認にならず普通に確定した**: 実費が 30,800 円以下だった可能性（それは経費-06 の正常系）。31,000 円なら 110% 超のみ、32,000 円なら区分跨ぎも重なる。
- **再承認に部長段が付かない（課長1段のまま）**: 承認ルート判定マスタの金額範囲と、テンプレート `経費_部長まで` が「課長 → 部長」の2段になっているかを確認。実費でテンプレートが再解決される仕様。
- **「実費を確定」を一般ユーザー以外が押してしまった**: 実はこのボタンには操作者の権限ゲートが無い（誰でも押せる）。気づいた点として UX メモに残す価値あり。
