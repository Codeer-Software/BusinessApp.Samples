# 体験シナリオ 経費-08: 承認の繰上げと代替（課長本人の申請・部長の OR 並列・経理代替）

> 作成: 2026-08-09 ／ **更新: 2026-08-09 ADR-0048（承認ルートの積み上げ化）を反映——テンプレート名を新名称に改め、ステップ 1.5 として「段の圧縮」を追加** ／ 所要時間: 約25分 ／ 影響: **仕訳ゼロ**。申請 2〜3 本を作るが最後にキャンセル → 下書き削除で消す（承認者へ飛んだ「承認依頼」通知だけは残る）
> 主役: **kaihatsu1_kacho1**（開発1部 第一課長 山本由美）と **soumu_kacho1**（総務部 第一課長 石川真理）。承認側で **kaihatsu1_buchodairi**（部長代理 渡辺剛）・**soumu_buchodairi**（総務部 部長代理 森田和夫）が登場。パスワードは全員ユーザー名と同じ。
> 「承認する人が申請したらどうなるか」を 2 パターン体験する。自己承認の禁止が**特例分岐ではなく walk-up の帰結として**解決される様子を、承認フロー欄の記号だけで読み取れるようになる。

## 物語

承認する側の人も経費を使う。第一課長の山本由美が自分で立て替えた 25,000 円を申請したら、承認者は誰になるのか。総務段の指名先である石川真理が交際費を申請したら、誰が「総務」の役を代わりに務めるのか。
このアプリは「自分で自分を承認する」ことを絶対に許さない。そのぶん承認者が自動で繰り上がる。その繰上げ先を、実際に申請して目で確かめる。

## 前提

| 項目 | 内容 |
|---|---|
| walk-up（ADR-0044） | 申請者の所属ノードから親方向へ辿り、**最初に該当役職者が見つかったノードの全員**（申請者本人は除外）。課長が居なければ部長へ繰上げ → それも居なければ**経理代替** → それも無ければ申請ブロック |
| 経理代替 | 経理機能フラグを持つ有効ユーザーのうち **Id が最小・申請者以外**。この seed では **総務部 部長 山田太郎**（id=22） |
| 開発1部の役職 | 部ノード: 部長 田中宏・部長代理 渡辺剛（**director が 2 名**）／第一課: 課長 山本由美／第二課: 課長 中村拓也。**部ノードに課長（manager）は 1 人も居ない** |
| 総務部の役職 | 部ノード: 部長 山田太郎・部長代理 森田和夫（director 2 名）／第一課: 課長 石川真理／第二課: 課長 岡田隆 |
| 使うルート | 一般費目 0〜29,999 = テンプレート「**経費_課長まで**」（課長段 1 つ）／一般費目 30,000〜199,999 = 「**経費_部長まで**」（課長段 → 部長段の 2 段）／交際費 0〜29,999 = 「**経費_課長まで＋総務**」（課長段＋**個人指名 石川真理**の 2 段） |
| 段の圧縮（ADR-0044・ADR-0048） | 直前の**役職段**と承認者集合が完全一致する段は生成されない。積み上げ方式（課長段と部長段が同居する）になって初めて実用的に働くようになった |
| 影響 | 仕訳・固定資産・帳簿はいっさい動かない。承認まで進めるが精算はしない |

## ステップ 1: 課長本人が 25,000 円を申請する（EXP-S01）

**kaihatsu1_kacho1**（山本由美）でログイン。

- **確認ポイント（着地）**: 山本由美は承認者なので、サイドバー「**経費精算**」を押すと **承認待ち**に着地する（一般社員は「申請」に着地する）。申請するには経費フレームのサイドバーで「**申請**」を選ぶ。同じ「経費精算」というラベルでも、権限によって開く画面が違う（変種解決: 経理 > 承認者 > 一般）。

「申請」→ 一覧 → 「新規作成」で入力:

| 項目 | 入力値 |
|---|---|
| 件名 | `課長会 手土産代（立替）` |
| 金額（税込） | `25,000` |
| 利用日 | 本日 |
| 目的 | `部門横断の課長会で使用` |
| 申請区分 | `立替精算（支払済み）`（既定のまま） |
| 支払先区分 | `社員へ精算`（既定のまま。精算対象者=山本由美） |
| 費目 | `消耗品費`（交際費ではない。交際費にすると総務段が付いて話が混ざる） |

→ 「**申請**」を押す。

- **期待結果**: トースト「申請しました」。承認フロー欄が

  `状態:進行中  ✓開発1部 第一課長 山本由美→(▶開発1部 部長 田中宏,▶開発1部 部長代理 渡辺剛)`

- **確認ポイント（ここが本題）**: テンプレートは「経費_課長まで」なのに、**課長は 1 人も承認者になっていない**。理由は walk-up:
  1. 申請者の所属ノード＝開発1部 第一課の課長を探す → 山本由美 1 名 → **申請者本人なので除外** → 該当者ゼロ
  2. 親ノード＝開発1部の課長を探す → 部ノードに課長行は無い → 該当者ゼロ
  3. 課長段が解決できないので **director（部長）へ自動繰上げ** → 開発1部の田中宏・渡辺剛の 2 名
- **確認ポイント**: 第二課長の中村拓也は出てこない。walk-up は「最寄りのノード**だけ**」を見るので、隣の課の課長は無関係（ADR-0044）。
- **確認ポイント**: 先頭の `✓開発1部 第一課長 山本由美` は**申請者**であって承認者ではない。フロー文字列は「申請者→段→段…」の順に並ぶ。

## ステップ 1.5: 金額を上げても段は増えない——重複段が畳まれる（EXP-S01b）

ここが ADR-0048（積み上げ方式）の眼目。**同じ山本由美のまま**、もう 1 本申請する。

| 項目 | 入力値 |
|---|---|
| 件名 | `課長会 会場費（立替）` |
| 金額（税込） | `35,000`（3 万円以上 = テンプレートは `経費_部長まで`） |
| 利用日 | 本日 ／ 費目 | `消耗品費` |

→ 「**申請**」を押す。

- **期待結果**: 承認フロー欄が

  `状態:進行中  ✓開発1部 第一課長 山本由美→(▶開発1部 部長 田中宏,▶開発1部 部長代理 渡辺剛)`

  ——ステップ 1（25,000 円）と**まったく同じ 1 段**。テンプレートは「課長 → 部長」の 2 段なのに、段が 1 つしか出ない。
- **確認ポイント（ここが本題）**: 段が消えたのではなく**畳まれた**。
  1. 1 段目（課長段）: 本人除外 → 第一課に他の課長なし → 親ノードにも課長なし → **director へ繰上げ**して田中宏・渡辺剛
  2. 2 段目（部長段）: walk-up の結果はやはり田中宏・渡辺剛
  3. 直前の役職段と**承認者集合が完全一致**するので、2 段目は**生成されない**（同一人物に連続 2 回承認させない・ADR-0044）
- **確認ポイント**: この「課長を飛ばす」挙動は、**特例ルールをどこにも書かずに組織の実態から自動的に導かれている**。承認フローテンプレートにも承認ルート判定にも「課長本人のときは…」という分岐は 1 行も無い。同じ 35,000 円を kaihatsu1_ippan（一般の小林美咲）が申請すれば、ちゃんと `▶山本由美→(田中宏,渡辺剛)` の 2 段になる。
- **確認ポイント**: **課長が空席の課からの申請でも同じことが起きる**（本人除外ではなく「該当者ゼロ」で繰り上がるだけで、機構は同一）。組織図を変えるだけで承認ルートが追随するので、課長不在の期間にテンプレートを差し替える運用が要らない。
- この申請はステップ 2 では使わない。後片付けでキャンセル → 削除する（承認まで進めてしまうとキャンセルできなくなるので注意）。

## ステップ 2: OR 並列の片方が承認すると、もう片方が「—」になる（EXP-R08）

**kaihatsu1_buchodairi**（渡辺剛）でログイン → サイドバー「**経費精算**」→ 承認待ちに着地 → 該当行の「**開く**」（ステップ 1.5 も実施した場合は山本由美の申請が 2 行並ぶ。開いて件名が `課長会 手土産代（立替）`・25,000 円の方を承認する）。

- **確認ポイント**: 承認待ち一覧には件名も金額も列が無い（申請種別・状態・申請者・申請日時だけ）。中身は開いてから見る。

コメントに `了解` と入れて「**承認**」。

- **期待結果**: トースト「承認しました」。承認フロー欄が

  `状態:承認済  ✓開発1部 第一課長 山本由美→(—開発1部 部長 田中宏,✓開発1部 部長代理 渡辺剛)`

- **確認ポイント**: 部長 田中宏は押していないのに `—`（スキップ）に変わり、**段は 1 人の承認で完了**した。カッコ内は OR 並列（`approval_type = any`）で、部長と部長代理は部の director として完全に同格。
- **確認ポイント**: 精算ステータスは「承認済」に進む。**田中宏でログインしても、この申請はもう承認待ちに出ない**（二重承認の防止。時間があれば kaihatsu1_bucho で確認するとよい）。

## ステップ 3: 総務段の指名先が本人だと、経理代替に差し替わる（EXP-S03）

**soumu_kacho1**（石川真理）でログイン。

- **確認ポイント（着地）**: 石川真理は経理機能フラグを持つので、サイドバー「**経費精算**」は **精算処理待ち**に着地する（経理変種）。ここでも申請するには経費フレームのサイドバー「**申請**」へ。

「新規作成」で入力:

| 項目 | 入力値 |
|---|---|
| 件名 | `協力会社との情報交換会` |
| 金額（税込） | `20,000` |
| 利用日 | 本日 |
| 費目 | `交際費` |
| 接待の相手先 | `株式会社ベガソフト 木村様・大野様` |
| 参加人数 | `4` |
| 接待の目的 | `次期案件の体制相談` |

→ 「**申請**」を押す。

- **期待結果**: 承認フロー欄が

  `状態:進行中  ✓総務部 第一課長 石川真理→(▶総務部 部長 山田太郎,▶総務部 部長代理 森田和夫)→総務部 部長 山田太郎`

- **確認ポイント（1 段目）**: ステップ 1 と同じ理屈。総務部第一課の課長＝石川真理本人なので除外 → 総務部ノードに課長は居ない → **director へ繰上げ**して山田太郎・森田和夫の OR 並列。
- **確認ポイント（2 段目・ここが本題）**: テンプレート「経費_課長まで＋総務」の 2 段目は**個人指名で石川真理**が設定されている。しかし申請者が石川真理本人なので、指名がそのまま**経理代替**に差し替わった。代替の選び方は「経理機能フラグを持つ有効ユーザーのうち Id 最小・申請者以外」＝ **山田太郎**。役職も部門も見ていない（純粋に Id 順）。
- **確認ポイント（この体制ならではの癖）**: 1 段目と 2 段目に **山田太郎が二度出てくる**。重複段の圧縮（ステップ 1.5 で見たあれ）は**連続する役職段どうしにしか効かない**ため——`prevRoleApprovers` が個人指名段でリセットされる——役職段と個人指名段の重複は圧縮されない。
  - つまり **1 段目を山田太郎が承認すると、2 段目でもう一度山田太郎が承認する**ことになる。1 段目を森田和夫が承認すれば、別人の 2 名決裁になる。押す人によって「実質何人の目を通ったか」が変わるという、業務的には気になる挙動。改善提案のネタとして覚えておくとよい。

## ステップ 4: 記号と凡例の読み方をまとめる

いま開いている申請（石川真理の交際費）のまま、承認フロー欄の下を見る。

- 常設の凡例ラベル: 「**凡例: ✓=承認済　▶=承認待ち（カッコ内の複数名は並列＝1人の承認で先へ進みます）　—=スキップ**」
- 記号の意味（実装どおり）:

| 記号 | 意味 | いつ付くか |
|---|---|---|
| `✓` | 承認済 | その人が承認したとき（**先頭の 1 つだけは申請者**を表す） |
| `▶` | 承認待ち | **現在の段**のメンバー全員に付く。まだ回ってきていない後続の段は**記号なし** |
| `—` | スキップ | OR 並列で他の人が先に承認した／却下・キャンセルで段ごと飛ばされた |
| `✗` | 却下 | 却下した人 |
| `(A,B)` | 並列 | カッコ内は OR。**1 人の承認で段が完了**する |
| `→` | 段の区切り | 左から順に回る（順次到達）。次の段の人には**まだ通知が飛んでいない** |

- **確認ポイント**: 先頭の `状態:` はフロー全体の状態（下書き／進行中／承認済／却下／キャンセル）。精算ステータス（下書き／申請中／承認済／経理処理中／精算済／完了）とは**別物**で、画面には両方出ている。
- **確認ポイント**: 「**現在の承認者：**」欄には並列でも **1 名しか出ない**（検索用の代表者）。誰と誰に回っているかを正確に知りたいときは、この欄ではなく承認フロー欄の `(…)` を読む。
- **確認ポイント**: 承認履歴リストには日時・操作（申請／承認／却下／再申請／キャンセル）・操作者・コメントが積まれる。ステップ 2 で入れた `了解` はここに残っている。

## つまずいたときは

- **ステップ 1 で山本由美が承認者に出てしまう**: 別ユーザーで申請していないか確認（申請者本人の除外は「申請した人」基準）。承認者の顔ぶれがそもそも違う場合は システム管理（admin）> 組織 > 部門 で開発1部の director 行（田中宏・渡辺剛）と第一課の manager 行（山本由美）を確認。
- **ステップ 1.5 で 2 段（課長 → 部長）になってしまう**: 山本由美**以外**のユーザーで申請している可能性が高い（他人が申請すれば課長段は山本由美として正しく生成され、圧縮は起きない）。本人で申請しているのに 2 段になる場合は、第一課または開発1部に**別の課長行**が増えていないかを システム管理 > 組織 > 部門 で確認する（別人の課長が居れば繰上げが起きないので圧縮もされない）。
- **「承認者を決定できません…」で申請がブロックされる**: walk-up でも経理代替でも承認者が決まらなかったとき。部門の役職行が全部消えている、または経理機能フラグを持つ有効ユーザーが申請者しか居ない状態。マスタ設定不備なので、システム管理 > 組織 で復旧する。
- **ステップ 3 の 2 段目が石川真理のまま**: 石川真理**以外**のユーザーで申請している。他人が申請すれば指名はそのまま生きる（差し替えは自己承認になるときだけ）。
- **経理代替が山田太郎にならない**: 経理機能フラグの付け外しが変わっている可能性。システム管理 > 組織 > ユーザー管理で「経理機能」にチェックが入っている有効ユーザーを Id 順に見て、いちばん上の人が代替先になる。
- **承認待ちに出ない／通知が来ない**: 通知と受信箱は「**現在の段の Waiting メンバー**」にだけ届く。次の段の人にはまだ届かないのが正しい（順次到達）。
- **キャンセルしたのに承認者へ通知が飛ばない**: 仕様。キャンセルと経理操作（仕訳生成・精算・完了）は通知を出さない。
