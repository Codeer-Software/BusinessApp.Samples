# 体験シナリオ 経費-11: 入力ガードと AI 読み取り（門番の総ざらい・複製・下書き削除）

> 作成: 2026-08-09 ／ 所要時間: 約25分 ／ 影響: **仕訳ゼロ**。申請 1 本と複製の下書き 1 本を作るが、最後にキャンセル → 下書き削除で消す（山本由美へ飛ぶ「承認依頼」通知だけ残る）
> 主役: **kaihatsu1_ippan**（開発1部 第一課 小林美咲）。承認はしない（門番の動きを見るだけ）。パスワードはユーザー名と同じ。
> 申請ボタンを押したときに何がどの順で検査されるかを、**一つずつ埋めながら**体験する。ついでに「件名が空でも申請が通ってしまう」という穴と、AI 読み取り・複製・下書き削除を触る（EXP-X04-1 の拡張）。

## 物語

新人に経費申請のやり方を教えることになった小林美咲は、「どこで怒られるか」を先に自分で確かめておくことにした。
何も入れずに申請ボタンを押し、怒られるたびに一つずつ埋めていく。最後まで行ったところで、**件名を一度も入れていないのに申請が通ってしまった**ことに気づく。

## 前提

| 項目 | 内容 |
|---|---|
| 必須項目 | **利用日・申請区分・支払先区分・費目** の 4 つだけ。申請区分（立替精算）と支払先区分（社員へ精算・対象者=自分）は**新規時に既定値が入る**ので、実際に自分で埋めるのは **利用日と費目**。**件名と金額は必須ではない** |
| 検証の順番（最初の NG で中断） | ① 必須未入力 →「入力内容を確認してください」 ② 事前申請で判定額 0 以下 →「事前申請では見込み額を入力してください」 ③ 立替精算で判定額 0 以下 →「金額を入力してください」 ④ 取引先が空 →「支払取引先を選択してください」 ⑤ 精算対象者が空 →「精算対象者を選択してください」 ⑥ 費目が解決できない →「費目を選択してください」 ⑦ 交際費 3 項目 →「交際費は相手先・参加人数・目的の入力が必須です」 ⑧ 領収書未添付 → **警告のみ・ブロックしない** |
| AI 読み取り | **オプトイン**（このコントロールを使ったときだけ走る）。プロバイダは既定で **Mock**＝キー不要・ファイルの中身は読まず**固定の疑似応答**を返す |
| 影響 | 仕訳・固定資産・マスタ・会計期間はいっさい動かない |

## ステップ 1: 何も入れずに申請する（EXP-X04-1）

**kaihatsu1_ippan** でログイン → サイドバー「**経費精算**」→ 申請一覧に着地 → 「新規作成」。

**何も入力せず**に、いきなり「**申請**」を押す。

- **期待結果**: 赤トースト「**入力内容を確認してください**」。未入力の必須欄（**利用日**と**費目**）が赤くマークされる。
- **確認ポイント**: 申請区分と支払先区分も必須だが、新規作成時に既定値（立替精算／社員へ精算）が入っているので怒られない。精算対象者にも自分が既に入っている。
- **確認ポイント**: 何度押しても**下書きのまま**で、承認フローは開始されず承認者に通知も飛ばない。エラーで止まった申請は「申請中」一覧にも出ない。
- **確認ポイント**: エラーメッセージは 1 本だけ。「何が足りないか」は書かれておらず、赤枠を見て探すことになる（改善提案のネタ）。

## ステップ 2: 利用日だけ埋める

利用日に**本日**を入れて → 「**申請**」。

- **期待結果**: また「**入力内容を確認してください**」。今度は**費目**だけが赤い。
- **確認ポイント**: 必須の門を全部くぐるまで、この先のチェックには一切進めない。金額を入れても状況は変わらない（金額は必須ではないので赤くならず、かといって先へも進まない）。

## ステップ 3: 費目を埋める —— ここで初めて業務チェックに入る

費目に「**消耗品費**」を選び、**金額は空のまま** → 「**申請**」。

| 項目 | 状態 |
|---|---|
| 件名 | 空のまま |
| 金額（税込） | **空のまま** |
| 利用日 | 本日 |
| 費目 | `消耗品費` |

- **期待結果**: 赤トースト「**金額を入力してください**」。
- **確認ポイント**: メッセージが「入力内容を確認してください」から変わった＝**必須チェック（CLB の入力検証）を抜けて、スクリプトの業務チェックに入った**合図。ここから先は必須マークの赤枠ではなく、トーストの文言だけが手がかりになる。
- **確認ポイント**: 立替精算だから「金額を入力してください」。もし申請区分を「事前申請（これから支払う）」にすると、同じ空欄でもメッセージが「**事前申請では見込み額を入力してください**」に変わる（判定に使う欄が金額から見込み額に切り替わるため）。余裕があれば申請区分を切り替えて 1 回試すとよい——見込み額の欄は**事前申請のときだけ現れる**。

## ステップ 4: 支払取引先の門（EXP-P05 の入口）

金額に `12,000` を入れる → 支払先区分を「**取引先へ支払**」に変える（**支払取引先は空のまま**）→ 「**申請**」。

- **期待結果**: 赤トースト「**支払取引先を選択してください**」。
- **確認ポイント**: 支払先区分を切り替えた瞬間、「精算対象者」欄が消えて「支払取引先」欄が現れている（排他）。
- **確認ポイント**: 金額を空のままこれを試すと**このエラーには辿り着けない**（③ が先に止める）。門は必ず上から順に開く。

## ステップ 5: 精算対象者の門

支払先区分を「**社員へ精算**」に戻す → 再び現れた「精算対象者」欄の値（小林美咲）を**クリア（×）**して空にする → 「**申請**」。

- **期待結果**: 赤トースト「**精算対象者を選択してください**」。
- **確認ポイント**: 既定で自分が入るので、普通に使っている限りこのエラーは出ない。**わざと消さないと踏めない防御**。他人の立替を代理申請するときに選び直す欄でもある。

## ステップ 6: 交際費 3 項目の門

精算対象者に自分（小林美咲）を選び直す → 費目を「**交際費**」に変える → 「接待の相手先／参加人数／接待の目的」の 3 欄が現れるので**全部空のまま** → 「**申請**」。

- **期待結果**: 赤トースト「**交際費は相手先・参加人数・目的の入力が必須です**」。
- **確認ポイント**: 3 つのうち 1 つでも欠けると同じメッセージ。**参加人数は 0 も未入力扱い**（1 以上が必要）。
- **確認ポイント**: この 3 欄には必須マーク（赤い星）が付かない。CLB ではスクリプトから必須フラグを立てられないため、**見た目は任意なのに実際は必須**という状態になっている（改善提案のネタ）。
- **確認ポイント（順番の証拠）**: 交際費のチェックは**いちばん最後**。だから金額を空にして交際費にすると、交際費のエラーではなく「金額を入力してください」が出る。

## ステップ 7: 件名を空のまま申請が通ってしまう

費目を「**消耗品費**」に戻す（3 欄が消える）→ **件名は最後まで空のまま** → 「**申請**」。

| 項目 | 最終的な状態 |
|---|---|
| 件名 | **空** |
| 金額（税込） | `12,000` |
| 利用日 | 本日 |
| 費目 | `消耗品費` |
| 支払先区分 | `社員へ精算`（対象者=小林美咲） |
| 領収書 | 未添付 |

- **期待結果**: 黄色の警告「**領収書が添付されていません。後から添付するか、紙の原本を保管してください**」→ 緑「**申請しました**」。**通ってしまう。**
- **確認ポイント（穴 1: 領収書）**: 領収書の未添付は**警告だけでブロックしない**（添付できない実務ケースを許容する意図的な設計）。ただし申請後は入力欄が全部ロックされるので、**領収書を後から添付することもできない**——警告文が言う「後から添付する」は、実際には**やろうとしてもできない**。文言と実装が食い違っている（改善提案のネタ）。
- **確認ポイント（穴 2: 件名）**: 件名が必須ではないため、**件名なしの申請が成立する**。実害を順に見る:
  - 申請一覧: 件名の列が**空欄**の行が並ぶ。どの申請か区別できない。
  - サイドバー「**申請中**」: 件名列が空欄。承認担当（代表）=山本由美 だけが手がかり。
  - **山本由美に届く通知**: 「承認依頼 — 経費申請「」（12,000円）の承認をお願いします」。**カギカッコの中が空**。
  - もしこのまま承認して仕訳を生成すると、仕訳の摘要が `経費精算 `（末尾スペースのみ）、各行の摘要も空になる。**帳簿に説明のない仕訳が残る**。
  - 件名は仕訳の摘要・通知本文・固定資産台帳の資産名にまで使われるので、実質的には必須にすべき項目。改善提案としてはいちばん優先度が高い。
- ここではこれ以上進めず、後片付けで消す（→ `## 後片付け`）。

## ステップ 8: AI 読み取り（オプトイン・Mock）

サイドバー「**申請**」で一覧に戻り、「新規作成」で**もう 1 枚**開く。まず AI を使わない状態を作る:

| 項目 | 入力値 |
|---|---|
| 件名 | `AI読み取りの練習` |
| 費目 | `備品` |
| 金額（税込） | `150,000` |

- **確認ポイント（AI 前の状態）**: 費目を「備品」にすると「**固定資産計上対象（10万円以上の資産性支出で自動ON）**」チェックが現れ、金額 150,000 円を入れた瞬間に**自動 ON** ＋ Info トースト「金額 150,000 円 ≧ 少額基準 100,000 円のため固定資産計上対象にしました（承認後に固定資産台帳へ登録されます）」。チェックが ON になったので「**資産管理番号**」欄も出ている。

ここで「**AI読み取り（添付＋自動入力）**」の欄からファイルを選ぶ（領収書らしい画像・PDF なら何でもよい。**Mock プロバイダは中身を読まない**）。解析が終わるまで待つ。

- **期待結果（値の反映）**: Mock の固定応答が各欄に入る。

  | 項目 | 反映される値 |
  |---|---|
  | 件名 | `会食代（AIモック読み取り）` |
  | 金額（税込） | `12,800` |
  | うち消費税 | `1,163` |
  | 利用日 | 本日 |
  | 利用先 | `炭火焼鳥 とり菊 神田本店` |
  | 費目 | `交際費` |
  | 接待の相手先 | `株式会社アルタイル商事 佐藤様ほか` |
  | 参加人数 | `4` |
  | 接待の目的 | `プロジェクト完了の御礼` |

- **期待結果（トースト）**: 青（Info）「**AI読み取り結果を反映しました。内容を確認・修正のうえ申請してください**」。
- **確認ポイント（本題: 判定の再評価）**: 費目が「備品」から「**交際費**」に書き換わった結果、
  - 「固定資産計上対象」チェックが**無言で OFF**（交際費は資産性の費目ではない）
  - 「資産管理番号」欄が**消える**
  - 代わりに「接待の相手先／参加人数／接待の目的」の 3 欄が**現れ、AI の値で埋まっている**

  AI がプログラム的に値を書き換えたときは通常の「値が変わった」イベントが発火しないため、読み取り完了時に**出し分けと固定資産判定を明示的にやり直している**（`AiImport_Completed`）。これが無いと「費目は交際費なのに固定資産チェックが ON のまま」という不整合が残る。
- **確認ポイント（添付も同時に済む）**: 選んだファイルは領収書欄にも添付される（だから「添付＋自動入力」）。この申請で「申請」を押すと、**領収書未添付の警告は出ない**。
- **確認ポイント（モックの限界）**: 何度やっても同じ値が返る。実際に画像を読ませたい場合はサーバ側の `AISettings.Provider` を `Claude` に切り替える（API キーが必要）。デモではキー無しのままこの Mock で「体験」だけ見せられるのが利点。

**この申請は保存も申請もせず**、サイドバー「**申請**」を押して一覧に戻る（未保存の新規データは破棄される）。

- **注意（既知の癖）**: ここで「申請」ボタンを押さずに**保存だけ**すると、承認フローが進行中・履歴なしという中途半端な状態になり、**申請・承認・キャンセルのどのボタンも出ない詰み状態**になることがある。新規申請は「申請まで押す」か「保存せず捨てる」のどちらかにするのが安全。

## ステップ 9: 「この申請を複製」は承認済でも押せる

申請一覧（既定で申請者=自分に絞られている）から、**過去の完了済み申請**「**開発用ワークステーション**」（165,000 円・備品・状態=承認済／精算=完了）を開く。

- **確認ポイント**: 完了した申請なのに「**この申請を複製**」（青）が出ている。このボタンは**状態でもユーザーでも絞られておらず、保存済みなら常に押せる**（他人の申請を開いても押せる）。定期券・毎月の会費など反復する経費を過去申請から起こすための機能。

「**この申請を複製**」を押す。

- **期待結果**: トースト「**申請を複製しました。利用日・金額を確認して申請してください**」→ 複製された**新しい下書き**の画面に自動で遷移する。
- **確認ポイント（コピーされるもの）**: 件名・金額（165,000）・目的・申請区分・支払先区分・費目（備品）・案件・見込み額・支払取引先・接待 3 項目・**固定資産計上対象のチェック（ON のまま）**。
- **確認ポイント（コピーされないもの）**: **利用日は本日**にリセット／**領収書の添付**は引き継がれない／**資産管理番号**も引き継がれない（固定資産チェックだけ ON なので、そのまま申請すると台帳のコードが `EXP-{申請Id}` の自動採番になる）／承認履歴・実費・精算ステータス（＝下書き）はまっさら。精算対象者は**複製した本人**。
- **確認ポイント（複製直後の見え方）**: サイドバー「**申請中**」を見ると、この複製が**状態の列が空欄の行**として並んでいる。複製の承認フローは「下書き」で作られるが、申請中ビューがその状態を表示できていないため。見た目のノイズなので改善提案のネタ（→ 下書き削除すれば消える）。

## 後片付け

作ったものを 2 つ消す。**仕訳は 1 本も作っていないので、消せばほぼ痕跡は残らない。**

1. **複製した下書き**（開発用ワークステーションのコピー）を開く → 「**この下書きを削除**」（赤）→ 確認ダイアログ「下書き「開発用ワークステーション」を削除しますか？（元に戻せません）」で「**削除する**」→ トースト「下書きを削除しました」→ 申請一覧に戻る。
   - **確認ポイント**: 「この下書きを削除」は **起案者本人 かつ 精算=下書き** のときだけ出る。申請後・承認後は出ない（意思決定履歴の抹消を防ぐ設計）。一覧側に削除ボタンは無い。
   - **既知の癖**: 削除しても子の承認フロー行は DB に孤児として残る（画面には出ない）。掃除が必要なら経理・管理者に `sql` CLI での物理削除を依頼する。
2. **ステップ 7 の件名なし申請**（金額 12,000・状態=申請中）を開く → 「**キャンセル**」（赤）→ トースト「キャンセルしました」→ 精算ステータスが「下書き」に戻る → 「**この下書きを削除**」→「削除する」。
   - **確認ポイント**: キャンセルしても山本由美には通知が飛ばない（キャンセルと経理操作は通知しない仕様）。ステップ 7 で飛んだ「承認依頼」通知は残るので、気になる場合は山本由美の通知一覧で既読化・一括削除する。
3. ステップ 8 の AI 申請は保存していないので、何も残っていない（申請一覧に無いことを確認）。

## つまずいたときは

- **ステップ 1 で「金額を入力してください」が出る**: 利用日と費目が既に埋まっている（前の入力が残っている）。「新規作成」からやり直す。
- **「費目を選択してください」が出せない**: 出せなくて正しい。費目は必須項目なので、空なら手前の「入力内容を確認してください」で必ず止まる。⑥ のチェックは「費目 Id は入っているのにマスタから引けない」という異常時の保険で、通常操作では踏めない（11_E2E の X01-5 は現行実装では「入力内容を確認してください」になる）。
- **精算対象者をクリアできない**: 欄の値の横にあるクリア（×）を使う。見つからない場合はこの分岐は飛ばしてよい（既定で埋まる欄なので実運用では踏まない）。
- **AI 読み取りが何も起きない／エラーになる**: サーバの AI プロバイダ設定を確認（既定は Mock でキー不要）。`Claude` や `AzureOpenAI` に切り替わっているとキーが必要になる。
- **AI 読み取り後も固定資産チェックが ON のまま**: 費目が資産性の費目（備品）のままになっている。Mock は費目に「交際費」を返すので、候補解決に失敗して費目が書き換わらなかった可能性がある（業務マスタ > 会計マスタ > 費目 に「交際費」があるか確認）。
- **「この申請を複製」が出ない**: 未保存の新規申請では出ない（保存済みの申請に対する操作）。一覧から既存の申請を開き直す。
- **削除ダイアログの件名が空**: ステップ 7 の申請を削除しようとしている（件名を入れていないため）。それで正常。
