# 体験シナリオ 経費-11: 入力ガードと AI 読み取り（門番の総ざらい・複製・下書き削除）

> 作成: 2026-08-09 ／ **更新: 2026-08-17 夜 ADR-0066 の UI 改訂（4 ブロック構成）を反映——明細は「入力欄で 1 件ぶん埋めて『追加』」で積む方式になり、AI 読み取りと領収書は**入力欄がその行として持つ**（1 回のアップロードで抽出値とファイルが同じ行に載る）** ／ 所要時間: 約30分 ／ 影響: **仕訳ゼロ**。申請 1 本と複製の下書き 1 本を作るが、最後にキャンセル → 下書き削除で消す（山本由美へ飛ぶ「承認依頼」通知だけ残る）
> 主役: **kaihatsu1_ippan**（開発1部 第一課 小林美咲）。承認はしない（門番の動きを見るだけ）。パスワードはユーザー名と同じ。
> 申請ボタンを押したときに何がどの順で検査されるかを、**一つずつ埋めながら**体験する。ついでに領収書の警告文の穴と、AI 読み取り・複製・下書き削除を触る（EXP-X04-1 の拡張）。

## 物語

新人に経費申請のやり方を教えることになった小林美咲は、「どこで怒られるか」を先に自分で確かめておくことにした。
何も入れずに申請ボタンを押し、怒られるたびに一つずつ埋めていく。門を全部くぐったところで、
**領収書だけは無くても通ってしまう**こと、しかも一度申請したら**後から添付する手段が無い**ことに気づく。

## 前提

| 項目 | 内容 |
|---|---|
| 画面の構成（ADR-0066 の UI 改訂） | 枠（カード）で 4 つに分かれる: **（見出し無しの申請ヘッダ）** ／ **レシート 1 枚ぶんを入力**（1 件ぶんの入力欄＋「この内容で明細に追加」） ／ **この申請の明細**（一覧＋合計） ／ **承認** |
| ヘッダの必須項目 | **件名・計上日・申請区分・支払先区分**。申請区分（立替精算）・支払先区分（社員へ精算・対象者=自分）・計上日（本日）は**新規時に既定値が入る**ので、実際に自分で埋めるのは **件名**だけ |
| **明細の必須項目** | **金額（税込）・利用日・費目**。費目が交際費のときだけ **接待の相手先・参加人数・接待の目的**が加わる。CLB の必須マークではなく**「追加」を押したときのスクリプト検証**で見るので、赤枠は付かず**トーストの文言**が手がかりになる |
| 「追加」の検証順（最初の NG で中断） | ① 金額（税込） ② 利用日 ③ 費目 ④ 交際費 3 項目 ⑤ うち消費税（負値・税込以上はエラー／乖離は警告） ⑥ 領収書未添付 → **警告のみ・追加はされる** |
| 「申請」の検証順（最初の NG で中断） | ① ヘッダの必須未入力 →「入力内容を確認してください」 ② 取引先が空 ③ 精算対象者が空 ④ **入力欄に書きかけが残っている** ⑤ **明細が 0 件** ⑥ 各明細の再検査（金額 → 利用日 → 費目 → 交際費 3 項目 → うち消費税） ⑦ 合計が 0 ⑧ 計上日が空 ⑨ **承認ルートが解決できない** ⑩ 領収書未添付 → **警告のみ・ブロックしない** |
| AI 読み取り | **オプトイン**（このコントロールを使ったときだけ走る）。プロバイダは既定で **Mock**＝キー不要・固定の疑似応答を返す。**読み取った内容は入力欄（＝明細 1 件ぶん）に載り、領収書もその行に付く** |
| 影響 | 仕訳・固定資産・マスタ・会計期間はいっさい動かない |

## ステップ 1: 何も入れずに申請する（EXP-X04-1）

**kaihatsu1_ippan** でログイン → サイドバー「**経費精算**」→ 申請一覧に着地 → 「新規作成」。

**何も入力せず**に、いちばん下の「**申請**」を押す。

- **期待結果**: 赤トースト「**入力内容を確認してください**」。未入力の必須欄（**件名**）が赤くマークされ、下に「必須項目です」が出る。
- **確認ポイント**: 申請区分・支払先区分・**計上日**は新規作成時に既定値（立替精算／社員へ精算／本日）が入っているので怒られない。精算対象者にも自分が既に入っている。
- **確認ポイント（明細はまだ見られていない）**: 明細が 0 件でも、この段階では「明細を…」とは言われない。
  **ヘッダの必須（CLB の入力検証）が先**で、それを抜けて初めてスクリプトの業務チェックに入る。
- **確認ポイント**: 何度押しても**下書きのまま**で、承認フローは開始されず承認者に通知も飛ばない。エラーで止まった申請は「申請中」一覧にも出ない。

## ステップ 2: 件名を埋める —— ここで初めて業務チェックに入る

件名に `入力ガードの練習` を入れて → 「**申請**」。

- **期待結果**: 赤トースト「**明細を 1 件以上追加してください（レシート 1 枚が 1 件です）**」。
- **確認ポイント**: メッセージが「入力内容を確認してください」から変わった＝**必須チェックを抜けてスクリプトの業務チェックに入った**合図。ここから先は赤枠ではなく、トーストの文言だけが手がかりになる。
- **確認ポイント（明細行化で新しくなった門）**: 旧仕様では「金額を入力してください」で止まっていた。
  いまは**そもそも明細が無いと先へ進めない**——申請の中身は明細にしか無いため。

## ステップ 3: 入力欄で 1 件ぶん埋めて「追加」する

「**レシート 1 枚ぶんを入力**」のカードは**最初から開いている**（グリッドに行を足す操作は無くなった）。
**何も入れずに**「**この内容で明細に追加**」を押す。

- **期待結果**: 赤トースト「**金額（税込）を入力してください**」。
- **確認ポイント（行番号が消えた）**: 旧仕様の「1 行目: …」という前置きが無くなった。
  **見えているのは 1 件だけ**なので、どの行の話かを言う必要がない。

金額に `12,000` を入れて → 「追加」。

- **期待結果**: 「**利用日を入力してください**」。

利用日に**本日**を入れて → 「追加」。

- **期待結果**: 「**費目を選択してください**」。

費目に「**消耗品費**」を選ぶ。

- **確認ポイント（税区分の自動補完）**: 費目を選んだ瞬間、**税区分に「課税仕入 10%」が自動で入る**（費目マスタの既定）。
  税区分が空のまま保存されることはない。

もう一度「**この内容で明細に追加**」。

- **期待結果**: 黄色の警告「**領収書が添付されていません。紙の原本を保管してください（申請後は添付できません）**」→
  緑「**明細に追加しました（1 件目）**」。**警告は出るが追加は通る。**
- **確認ポイント（入力欄が空に戻る）**: 追加した瞬間、入力欄は**空**に戻る。次のレシートをすぐ入れられる。
- **確認ポイント（リストと合計）**: 「この申請の明細」に 1 行現れ、**合計金額（税込）12,000 / うち消費税（合計）1,090** が付く。
  どちらも**入力欄が無い**（明細からの導出値なので読み取り専用・ADR-0062）。
- **確認ポイント（ここで下書きが保存される）**: 1 件目を追加した時点で申請に Id が振られ、URL が `.../ExpenseRequest/{Id}` に変わり、
  「**この下書きを削除**」ボタンが現れる。**明細を 1 件足す＝下書きとして保存する**、という関係。

## ステップ 4: 支払取引先の門（EXP-P05 の入口）

支払先区分を「**取引先へ支払**」に変える（**支払取引先は空のまま**）→ 「**申請**」。

- **期待結果**: 赤トースト「**支払取引先を選択してください**」。
- **確認ポイント**: 支払先区分を切り替えた瞬間、「精算対象者」欄が消えて「支払取引先」欄が現れている（排他）。
- **確認ポイント（順番）**: **支払先の検証は明細より先**。「ヘッダの話はヘッダで、明細の話は明細で」と分かれている。

## ステップ 5: 精算対象者の門

支払先区分を「**社員へ精算**」に戻す → 再び現れた「精算対象者」欄の値（小林美咲）を**クリア（×）**して空にする → 「**申請**」。

- **期待結果**: 赤トースト「**精算対象者を選択してください**」。
- **確認ポイント**: 既定で自分が入るので、普通に使っている限りこのエラーは出ない。**わざと消さないと踏めない防御**。他人の立替を代理申請するときに選び直す欄でもある。

## ステップ 6: 書きかけの門 —— 追加し忘れは黙って捨てない

精算対象者に自分（小林美咲）を選び直す → **入力欄の金額欄に `5,000` だけ入れて**（追加は押さない）→ 「**申請**」。

- **期待結果**: 赤トースト「**入力欄に、明細に追加していない内容が残っています。「この内容で明細に追加」（または「この明細を更新」）を押すか、「入力内容をクリア」（編集中なら「編集をやめる」）で消してください**」。
- **確認ポイント（今回の UI で新しくできた門）**: 入力欄に書いたのに「追加」を押し忘れる、が**いちばん起きやすい事故**。
  黙って捨てず、押し忘れとして止める。
- **確認ポイント**: 「**入力内容をクリア**」を押すと入力欄だけが空になり、**件名などヘッダの入力は残る**。
  追加済みの明細（1 件目）にも影響しない。

「**入力内容をクリア**」を押して次へ。

## ステップ 7: 交際費 3 項目の門 —— 行ごとに効く

「この申請の明細」の **1 件目の行をクリック**する。

- **期待結果**: その明細が**上の入力欄に読み込まれ**、見出しが「**この明細を編集**」に変わる。
  ボタンも「**この明細を更新**」「**編集をやめる**」に変わる。
- **確認ポイント（編集の入口はここ 1 つ）**: 明細リストの中では直接編集できない。**必ず入力欄に読み込んでから直す**。

費目を「**交際費**」に変える → 「**この明細を更新**」。

- **期待結果**: 赤トースト「**交際費は相手先・参加人数・目的の入力が必須です（「交際費の記録」を開いてください）**」。
- **確認ポイント（畳んである）**: 交際費 3 項目は入力欄の下の「**▶ 交際費の記録（費目が交際費のとき必須）**」を開くと出る。
  普段は畳まれているので、1 件あたりの見た目が重くならない。
- **確認ポイント**: 3 つのうち 1 つでも欠けると同じメッセージ。**参加人数は 0 も未入力扱い**（1 以上が必要）。
- **確認ポイント（行ごとに効く）**: 交際費の行だけが怒られる。消耗品費の行は 3 項目が空でも通る。

費目を「**消耗品費**」に戻す。

## ステップ 8: うち消費税の門（ADR-0051 → ADR-0066）

入力欄の「**うち消費税**」に `12,000` （金額と同額）を入れて → 「**この明細を更新**」。

- **期待結果**: 赤トースト「**「うち消費税」12,000 円が金額（税込）12,000 円以上です。税込金額に含まれる消費税額を入力してください**」。
- `-100` を入れると「**「うち消費税」に負の金額は入力できません**」。
- `900` を入れる（10% の計算値は 1,090・許容は ±10%＝109）と、**警告だけ出て更新は通る**——
  「「うち消費税」900 円は税率 10% での計算値 1,090 円と離れています。…（軽減税率や非課税品が混ざったレシートなら問題ありません）」。
- **確認ポイント**: 桁ミスは止めるが、軽減税率の混在は通す。この線引きは明細ごとに判定される。

うち消費税を**空**に戻して「**この明細を更新**」。入力欄が空に戻る。

## ステップ 9: 最後の門は「警告だけ」——領収書未添付

**領収書は添付しないまま** → 「**申請**」。

| 項目 | 最終的な状態 |
|---|---|
| 件名 | `入力ガードの練習` |
| 計上日 | 本日 |
| 支払先区分 | `社員へ精算`（対象者=小林美咲） |
| 明細 1 件目 | 利用日=本日 ／ 費目=`消耗品費` ／ 金額=`12,000` ／ 領収書=未添付 |

- **期待結果**: 黄色の警告「**領収書が添付されていない明細が 1 行あります。紙の原本を保管してください（申請後は添付できません）**」→ 緑「**申請しました**」。**警告は出るが通る。**
- **確認ポイント（数える）**: 「**N 行あります**」と**件数で言う**。10 件のうち 3 件だけ添付し忘れた、という状況が数字で分かる。
- **確認ポイント（穴: 領収書）**: 領収書の未添付は**警告だけでブロックしない**（添付できない実務ケースを許容する意図的な設計）。申請後は明細も含めて全部ロックされるため**後から添付することはできず**、警告文もそう明言している。添付し忘れたら**取り下げて申請し直す**しかない。
- **確認ポイント（申請すると入力欄のカードが消える）**: 申請後は「明細を入力する」ブロックごと画面から消える。
  編集できない状態が**見た目で分かる**（グレーアウトしたフォームが残らない）。
- ここではこれ以上進めず、後片付けで消す（→ `## 後片付け`）。

## ステップ 10: AI 読み取り（オプトイン・Mock）—— 1 枚読むと入力欄が埋まる

サイドバー「**申請**」で一覧に戻り、「新規作成」で**もう 1 本**開く。まだ明細は 0 件のまま。

入力欄の「**AI で読み取る**」からファイルを選ぶか、「Text」ボタンでレシートの文面を貼り付けて解析する
（**Mock は中身を読まず固定の疑似応答を返す**）。

- **期待結果（入力欄が埋まる）**: 解析が終わると**入力欄に値が載る**。

  | 入力欄の項目 | 反映される値 |
  |---|---|
  | 利用日 | レシートの日付 |
  | 費目 | 内容に合う費目（Mock では `交際費`） |
  | 税区分 | `課税仕入 10%`（費目から自動補完） |
  | 金額（税込） | レシートの合計 |
  | うち消費税 | レシート記載の消費税額 |
  | 利用先 | 店名 |
  | 摘要 | 買ったものの要約 |
  | 接待の相手先／参加人数／接待の目的 | AI が読み取れた分だけ入る |

- **期待結果（領収書もその行に付く）**: 読ませたファイルが**そのまま入力欄の「領収書」欄**に入り、画像がプレビューされる。
  **アップロードは 1 回だけ**——リストに改めて添付し直す操作は要らない。
- **期待結果（トースト）**: 青（Info）「**レシートを読み取りました。内容を確認して「この内容で追加」を押してください**」。
- **本題: 2 枚目を読ませても 1 枚目は無事**。「この内容で明細に追加」を押して 1 件目を確定させると入力欄が空に戻る。
  そこで**もう 1 枚**読ませると、**1 件目には一切触れずに** 2 件目ぶんが入力欄に載る。
  レシートを順番に「読む → 追加」していけば、そのまま「10 枚 = 10 件の 1 申請」ができあがる——**これが明細行化の狙い**。
  **明細それぞれが自分の領収書を持つ**ので、どの金額がどの証憑かが 1 対 1 で追える。
- **確認ポイント（1 枚を 2 件に分けたいとき）**: 高価な機器を 2 台まとめて買ったレシートを、**別々の固定資産として登録したい**場合は、
  AI に読ませて金額を 1 台ぶんに直して追加 → 空になった入力欄に 2 台目を**手入力**して追加、とする。
  2 件目に領収書は付かないが（同じファイルをもう一度選べば付く）、1 枚目の証憑で足りることが多い。
- **確認ポイント（手入力でも同じ）**: AI を使わずに、入力欄をそのまま手で埋めて「追加」でもよい。
  **AI は入力欄を先に埋めてくれる補助**であって、AI 専用の画面ではない。
- **確認ポイント（モックの限界）**: 何度やっても同じ値が返る。実際に画像を読ませたい場合はサーバ側の `AISettings.Provider` を `Claude` に切り替える（API キーが必要）。デモではキー無しのままこの Mock で「体験」だけ見せられるのが利点。

**この申請は「追加」も「申請」も押さずに**、サイドバー「**申請**」を押して一覧に戻る（未保存の新規データは破棄される）。

## ステップ 11: 「この申請を複製」は明細ごとコピーされる

申請一覧（既定で申請者=自分に絞られている）から、**過去の完了済み申請**「**開発用ワークステーション**」（165,000 円・備品・状態=承認済／精算=完了）を開く。

- **確認ポイント**: 完了した申請なのに「**この申請を複製**」（青）が出ている。このボタンは**状態でもユーザーでも絞られておらず、保存済みなら常に押せる**（他人の申請を開いても押せる）。定期券・毎月の会費など反復する経費を過去申請から起こすための機能。

「**この申請を複製**」を押す。

- **期待結果**: トースト「**申請を複製しました（明細 N 行）。利用日・金額を確認して申請してください**」→ 複製された**新しい下書き**の画面に自動で遷移する。
- **確認ポイント（コピーされるもの）**: 件名・目的・申請区分・支払先区分・支払取引先・合計金額、そして**明細の全件**
  （費目・税区分・金額・うち消費税・案件・利用先・摘要・接待 3 項目・**固定資産のチェック**）。
- **確認ポイント（コピーされないもの）**: **明細の利用日は本日**にリセット／**領収書の添付**は引き継がれない
  （レシートは都度の実物が正）／**資産管理番号**も引き継がれない（固定資産チェックだけ ON なので、そのまま申請すると台帳のコードが `EXP-{申請Id}-{行番号}` の自動採番になる）／承認履歴・精算ステータス（＝下書き）はまっさら。精算対象者は**複製した本人**。
- **確認ポイント（明細行化の効き目）**: 「毎月ほぼ同じ 5 枚のレシート」を出す人は、**複製 1 回で 5 件そろう**。
  あとは利用日と金額を直すだけでよい。

## つまずいたときは

- **ステップ 1 で「明細を 1 件以上…」が出る**: 件名が既に埋まっている（前の入力が残っている）。「新規作成」からやり直す。
- **明細の「追加」ボタンが見つからない**: グリッドの中ではなく、**入力欄の下**にある「この内容で明細に追加」。申請後・承認後は入力欄のカードごと消える。
- **交際費の 3 項目／固定資産の欄が見つからない**: 入力欄の下の「▶ 交際費の記録」「▶ 固定資産として計上する」を**開く**（既定で畳んである）。
- **明細を直したいのにリストで編集できない**: 仕様。**行をクリックして入力欄に読み込んでから**直し、「この明細を更新」を押す。
- **申請できない・「入力欄に…残っています」が消えない**: 入力欄に何か入っている。「この内容で明細に追加」か「入力内容をクリア」を押す。行を読み込んだままなら「編集をやめる」。
- **費目を選んでも税区分が入らない**: その費目に既定税区分が設定されていない。業務マスタ > 会計マスタ > 費目 で確認する。
- **合計金額を直接入力したい**: できない（明細からの導出値）。直すのは明細の金額のほう。
- **AI 読み取りが何も起きない／エラーになる**: サーバの AI プロバイダ設定を確認（既定は Mock でキー不要）。`Claude` や `AzureOpenAI` に切り替わっているとキーが必要になる。
- **AI に読ませたのに領収書が付かない**: 「AI で読み取る」ではなく別の欄に入れている可能性がある。読み取り後は**同じブロックの「領収書」欄**にファイル名とプレビューが出るのが正しい状態。
- **「この申請を複製」が出ない**: 未保存の新規申請では出ない（保存済みの申請に対する操作）。一覧から既存の申請を開き直す。
