# 体験シナリオ 経費-09: 取引先支払と税の変化形（支払先区分・不課税・税額の手入力）

> 所要時間: 約35分 ／ 影響: **仕訳 6 本追加**（申請 3 本 × 計上仕訳＋支払仕訳）。申請 3 本は完了まで進める。マスタ・会計期間は変更しない
> 主役: **kaihatsu1_ippan**（開発1部 第一課 小林美咲）→ **kaihatsu1_kacho1**（第一課長 山本由美）→ **soumu_bucho**（経理 山田太郎）。パスワードは全員ユーザー名と同じ。
> 経費精算の「金額と費目以外」が仕訳をどう変えるか——支払先区分・不課税費目・税額の手入力——を 3 本の申請で並べて確かめる。結論の 1 つは「**支払先区分は仕訳を 1 円も変えない**」。

## 物語

小林美咲の手元に、性格の違う 3 枚の伝票が集まった。
① 印刷会社（グランメゾン印刷）への支払——立て替えたのではなく、会社から業者に直接払うもの。
② 業界団体の年会費——消費税がかからないもの。
③ 開発定例のケータリング——レシートの消費税額が、税込金額から計算した額と合わないもの。
3 本とも 30,000 円未満なので承認は第一課長ひとりで済む。仕訳がどう変わる（変わらない）かに集中できる。

## 前提

| 項目 | 内容 |
|---|---|
| 承認ルート | 3 本とも一般費目 30,000 円未満 → テンプレート「**経費_課長まで**」→ **開発1部 第一課長 山本由美のみ**（自課の課長・ADR-0044） |
| 費目の既定 | 印刷製本費 → 科目 **消耗品費(6140)**・課税仕入10%／諸会費 → 科目 **諸会費(6260)**・**不課税**／会議費 → 科目 会議費(6120)・課税仕入10% |
| 税額の決め方 | 費目の既定税区分が**課税仕入のときだけ**計算する。「うち消費税」に入力があればそれを採用、無ければ `税込 × 率 ÷ (100+率)` の**切り捨て** |
| 仕訳番号の目安 | 現在の最終が No.83。以降 +1 ずつ 6 本（他の操作を挟めばずれるが、金額と貸借が合っていれば正常） |
| 会計期間 | 第18期（2026年度）。当月（2026-08）がオープンであること |

## ステップ 1: 支払先区分を切り替えて欄の入れ替わりを見る（EXP-P05）

**kaihatsu1_ippan**（小林美咲）でログイン → サイドバー「**経費精算**」→ 申請一覧に着地 → 「新規作成」。

まず **支払先区分**のドロップダウンを触るだけで、下の欄が入れ替わることを確認する。

- 既定は「**社員へ精算**」。このとき「**精算対象者**」欄が出ていて、自分（小林美咲）が既に入っている。
- 「**取引先へ支払**」に変える → **精算対象者の欄が消え**、代わりに「**支払取引先**」欄が現れる。
- 「社員へ精算」に戻す → 元どおり。**両方が同時に出ることはない**（排他）。

「取引先へ支払」にしたうえで、**支払取引先を空のまま**残りを入力:

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `会社案内パンフレット 増刷代` |
| 目的 | `展示会配布用の増刷。グランメゾン印刷へ直接支払` |
| 申請区分 | `立替精算（支払済み）`（既定のまま） |
| 支払先区分 | `取引先へ支払` |
| 明細 1 行目 | 利用日=本日 ／ 費目=`印刷製本費` ／ 金額（税込）=`22,000` ／ 利用先=`グランメゾン印刷` |

→ 「**申請**」を押す。

- **期待結果**: 赤トースト「**支払取引先を選択してください**」でブロック。申請は開始されず、精算ステータスは「下書き」のまま・承認者に通知も飛ばない。
- **確認ポイント（検証の順番・ADR-0066 で整理された）**: 「必須入力 → **支払先**（取引先／精算対象者）→ **明細が 1 行以上あるか** → **行ごとの検証**（金額 → 利用日 → 費目 → 交際費 3 項目 → うち消費税）」の順。
  **支払先はヘッダの話なので明細より先に見る**——明細を空にしたままでもこのエラーに辿り着ける（旧仕様では金額が先だった）。
  行の検証で止まったときはメッセージの先頭に**行番号**が付く。エラーは一度に 1 つずつしか出ない。

支払取引先に「**C005 グランメゾン印刷**」を選び直して → 「**申請**」。

- **期待結果**: 黄色の警告「領収書が添付されていません。…」（ブロックしない）→ トースト「申請しました」。承認フロー欄は `▶開発1部 第一課長 山本由美` の 1 段 1 名。
- **確認ポイント**: 申請が通ると入力欄が全部ロックされる。**支払先区分も後から変えられない**。

## ステップ 2: 不課税の費目で申請する（EXP-A03）

続けて「新規作成」でもう 1 本:

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `情報サービス産業協会 年会費` |
| 目的 | `2026年度 団体年会費` |
| 支払先区分 | `社員へ精算`（既定のまま） |
| 明細（入力欄） | 利用日=本日 ／ 金額（税込）=`20,000` ／ **うち消費税**=`1,818`（**費目より先に**入れる。次で消えることを確認する） |
| そのあと同じ入力欄の費目 | `諸会費` |

→ 「**この内容で明細に追加**」→ 「**申請**」。

- **確認ポイント（ADR-0051 → ADR-0066 で行単位に）**: 費目に `諸会費` を選ぶと、その行の**税区分が「不課税」に自動で入り**、
  同じ行の「うち消費税」に入れていた 1,818 円が**クリアされる**。Info トースト
  「**消費税の対象外の費目の行があった**ため、「うち消費税」を **1 行分**クリアしました」が出る。
  不課税の費目では手入力の税額は仕訳に一切効かないため、値を残さない。
  - **明細行化での違い**: 入力欄は明細ごとに費目が違いうるので、ヘッダ時代のように**欄そのものが消えることはない**。
    代わりに**値をクリアして、何行分クリアしたかを伝える**形になった。
- **確認ポイント**: 諸会費の行では接待の 3 項目も固定資産チェックも意味を持たない（交際費フラグ・資産性フラグが立っていない費目）。折りたたみを開けば入力できてしまうが、入力しても仕訳には出ない。
- **期待結果**: 承認フローは同じく `▶山本由美`。金額 20,000 円は 30,000 円未満なので課長 1 段（部長段は積み上がらない）。

## ステップ 3: レシートの消費税額を手入力する（EXP-A04）

3 本目:

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `開発定例 ケータリング` |
| 目的 | `開発1部 週次定例の軽食（軽減税率の飲食料品を含む）` |
| 明細 1 行目 | 利用日=本日 ／ 費目=`会議費` ／ 金額（税込）=`10,800` ／ 利用先=`デリカ神田` ／ **うち消費税**=`800`（レシート記載額。10% で計算すると 981 円になるはずの金額） |

→ 「**申請**」。

- **確認ポイント**: 「うち消費税」は Placeholder のとおり任意項目。ここに入れた値が**計算より優先**される仕組みで、軽減税率 8% の品が混ざったレシートや、端数処理が事業者ごとに違うケースを吸収するための逃げ道。
- **確認ポイント（ADR-0051 → 行単位に）**: 申請を押した時点で警告トースト「**1 行目**: 「うち消費税」800 円は税率 10% での計算値 981 円と離れています。桁の間違いがないか確認してください（軽減税率や非課税品が混ざったレシートなら問題ありません）」が出る。これは**警告であって禁止ではない**——まさに今回のような軽減税率混在が正当なケースなので、そのまま申請できる（乖離が計算値の ±10% を超えると出る）。
  - 一方、**桁を間違えて `10,800` 以上**を入れると、エラー「**1 行目**: 「うち消費税」… が金額（税込）… 以上です」で**申請自体が止まる**。負の値も同様に止まる。試すなら申請前に戻すこと。
  - **明細行化での違い**: 検算は**行ごと**に走り、メッセージに**行番号**が付く。10 枚のレシートを 1 申請にまとめても、どの行の税額を疑えばいいか分かる。

## ステップ 5: 経理が仕訳を生成して 3 つの形を見比べる

**soumu_bucho**（山田太郎）でログイン → サイドバー「**経費精算**」→ **精算処理待ち**に着地。3 件が並んでいる。

### 5-1. 「会社案内パンフレット 増刷代」（取引先へ支払・22,000）

開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 **消耗品費（費目: 印刷製本費）** 20,000 円 / 貸方 未払金 22,000 円）」。
- **帳簿の中身**（会計業務 > 帳簿 > 仕訳帳、本日付）: 3 行。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | **消耗品費** | 20,000 |
  | 借方 | 仮払消費税 | 2,000 |
  | 貸方 | 未払金 | 22,000 |

- **確認ポイント（費目名と科目名がずれる）**: 選んだ費目は「**印刷製本費**」だが、記帳される科目は費目マスタの既定勘定科目「**消耗品費**(6140)」。トーストは**実際に記帳される科目名を主**にし、費目名と違うときだけ「消耗品費（費目: 印刷製本費）」と括弧で併記する（改善候補 B-2・2026-08-13。以前は費目名だけを出していて、仕訳を見た人が「違うものが記帳された」と戸惑った）。ずれるのは 備品・印刷製本費 → 消耗品費／図書研修費 → 新聞図書費／その他 → 雑費 の 4 費目。
- **確認ポイント（本題）**: 仕訳のどこにも「**グランメゾン印刷**」は出てこない。取引先は申請レコードにしか残らず、**買掛金(2010) ではなく未払金(2020)** に立つ。つまり取引先別の未払残高には乗らない。業者別に債務を管理したいなら経費精算ではなく「購買・支払」部品（仕入先請求書）を使う、という部品分担になっている。
- 全行に部門「**開発1部**」（申請者の所属**部**。課ではない）が付く。

### 5-2. 「情報サービス産業協会 年会費」（諸会費・20,000）

戻って開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 諸会費 20,000 円 / 貸方 未払金 20,000 円）」。
- **帳簿の中身**: **2 行だけ**。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 諸会費 | 20,000 |
  | 貸方 | 未払金 | 20,000 |

- **確認ポイント**: 仮払消費税の行が**生成されない**。費目の既定税区分が「不課税」で、税額計算は課税仕入のときだけ動くため。借方の金額は税抜本体ではなく**税込全額**（そもそも税が無い）。
- **確認ポイント（ステップ 2 の伏線）**: 手入力の優先は「課税仕入と判定された後」の話で、不課税ならその手前で税額 0 が確定する。だからステップ 2 で入れた 1,818 円は費目を選んだ時点でクリアされ、**DB にも残っていない**（ADR-0051。2026-08-12 以前は欄が生きたまま値だけ黙って無視されていた＝改善候補 A-4）。
- **確認ポイント**: 消費税集計表（会計業務 > 財務帳票）に、この 20,000 円は**課税仕入として現れない**。

### 5-3. 「開発定例 ケータリング」（税額手入力・10,800）

戻って開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 会議費 **10,000** 円 / 貸方 未払金 10,800 円）」。
- **帳簿の中身**: 3 行。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 会議費 | **10,000** |
  | 借方 | 仮払消費税 | **800** |
  | 貸方 | 未払金 | 10,800 |

- **確認ポイント（本題）**: 10% で内税計算すると `10,800 × 10 ÷ 110 = 981`（切り捨て）→ 本体 9,819 になるはず。実際は **手入力の 800 が採用され、本体は 10,000**。手入力が計算に勝っている。
- **確認ポイント**: 本体額は「税込 − 税額」で機械的に引き算されるだけ。つまり**手入力の税額が誤っていても検算も警告もされない**（例: 5,000 と入れれば本体 5,800 の仕訳が黙って作られる）。レシートの転記ミスがそのまま帳簿に入る余地がある——ここも改善提案のネタ。

## ステップ 6: 支払先区分が仕訳に効かないことを確認する（本シナリオの結論）

3 本とも「**精算済にする**」→「**完了にする**」まで進める。

- **期待結果（各件）**: トースト「支払仕訳 No.◯（{金額} 円）を生成し精算済にしました」→ 「完了にしました」。精算処理待ち一覧から消える。
- **支払仕訳の中身**（3 本とも同じ形・本日付・税処理なし）:

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 未払金 | 申請金額 |
  | 貸方 | 普通預金 | 申請金額 |

- **確認ポイント（結論）**: 「取引先へ支払」の 22,000 円も、「社員へ精算」の 20,000 円・10,800 円も、**支払仕訳の形はまったく同じ**。支払先区分は仕訳生成にも支払仕訳にも一切影響しない。効いているのは
  1. 申請フォームの**欄の出し分け**（精算対象者 ⇔ 支払取引先）
  2. **申請時の必須チェック**（どちらか一方が空だとブロック）
  の 2 つだけで、会計処理は完全に共通。
- **確認ポイント**: したがって「誰に払うのか」を帳簿から知る手段は無い（摘要にも入らない）。振込作業は支払予定表・振込データ作成（購買・支払部品）ではなくこの一覧を見ながら手作業になる。中小企業の実運用ではここが実務上の穴になりうるので、デモで質問が出たら「経費は社員立替が主で、業者支払は仕入先請求書で回す想定」と答えられるようにしておく。
- **確認ポイント**: 出納帳（普通預金）に 3 件の出金が並ぶ。合計 52,800 円。

## ステップ 7: 同じことを 1 申請 3 明細でやってみる（任意・2026-08-17 新設）

明細行化で、**性格の違うレシートを 1 申請にまとめられる**ようになった。
ステップ 2・3 の 2 本（どちらも「社員へ精算」）は、本来 1 本にできる。
時間があれば新規作成でもう 1 本作って、仕訳の形を見比べてみる。

| 項目 | 入力値 |
|---|---|
| 件名（ヘッダ） | `8月分 経費まとめ` |
| 支払先区分 | `社員へ精算`（既定のまま） |
| 明細 1 行目 | 費目=`会議費` ／ 金額=`10,800` ／ うち消費税=`800` |
| 明細 2 行目 | 費目=`諸会費` ／ 金額=`20,000`（不課税） |
| 明細 3 行目 | 費目=`旅費交通費` ／ 金額=`3,300` |

- **確認ポイント（ヘッダの合計）**: 合計金額 **34,100**、うち消費税 **1,100**
  （800 ＋ 0 ＋ 300。**行ごとに確定して単純合計**する。不課税の行は 0）。
- **確認ポイント（承認ルート）**: 合計 34,100 円なので `課長 → 部長` の 2 段。
  1 本ずつ出していたら 3 本とも課長 1 段だった——**まとめると合計で判定される**（経費-02 ステップ 5）。
- **確認ポイント（仕訳の形）**: 承認後に仕訳を生成すると **7 行**になる。

  | 貸借 | 科目 | 金額 | 備考 |
  |---|---|---|---|
  | 借方 | 会議費 | 10,000 | 明細 1 行目（手入力 800 が優先） |
  | 借方 | 仮払消費税 | 800 | 行 1 の税行 |
  | 借方 | 諸会費 | 20,000 | 明細 2 行目・**税行なし**（不課税） |
  | 借方 | 旅費交通費 | 3,000 | 明細 3 行目 |
  | 借方 | 仮払消費税 | 300 | 行 4 の税行 |
  | 貸方 | 未払金 | 34,100 | **1 行にまとめる** |

  借方は**明細 1 行につき 1 行**、その直後に**その行の税行**（税額 0 なら付かない）、
  最後に**貸方 1 行**。同じ科目でも畳まないので、総勘定元帳で何にいくら使ったかが行で追える。
