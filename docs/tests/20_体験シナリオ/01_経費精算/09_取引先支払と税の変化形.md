# 体験シナリオ 経費-09: 取引先支払と税の変化形（支払先区分・不課税・税額の手入力）

> 作成: 2026-08-09 ／ **更新: 2026-08-09 ADR-0048/0044 反映**（承認テンプレート名を新名称に。3 本とも 3 万円未満なのでルート＝自課の課長 1 段は不変）／ 所要時間: 約30分 ／ 影響: **仕訳 6 本追加**（申請 3 本 × 計上仕訳＋支払仕訳）。申請 3 本は完了まで進める。マスタ・会計期間は変更しない
> 主役: **kaihatsu1_ippan**（開発1部 第一課 小林美咲）→ **kaihatsu1_kacho1**（第一課長 山本由美）→ **soumu_bucho**（経理 山田太郎）。パスワードは全員ユーザー名と同じ。
> 経費精算の「金額と費目以外」が仕訳をどう変えるか——支払先区分・不課税費目・税額の手入力——を 3 本の申請で並べて確かめる。結論の 1 つは「**支払先区分は仕訳を 1 円も変えない**」。

## 物語

小林美咲の手元に、性格の違う 3 枚の伝票が集まった。
① 印刷会社（グランメゾン印刷）への支払——立て替えたのではなく、会社から業者に直接払うもの。
② 業界団体の年会費——消費税がかからないもの。
③ 開発定例のケータリング——レシートの消費税額が、税込金額から計算した額と合わないもの。
3 本とも 30,000 円未満なので承認は第一課長ひとりで済む。仕訳がどう変わる（変わらない）かに集中できる。

## ステップ 1: 支払先区分を切り替えて欄の入れ替わりを見る（EXP-P05）

**kaihatsu1_ippan**（小林美咲）でログイン → サイドバー「**経費精算**」→ 申請一覧に着地 → 「新規作成」。

まず **支払先区分**のドロップダウンを触るだけで、下の欄が入れ替わることを確認する。

- 既定は「**社員へ精算**」。このとき「**精算対象者**」欄が出ていて、自分（小林美咲）が既に入っている。
- 「**取引先へ支払**」に変える → **精算対象者の欄が消え**、代わりに「**支払取引先**」欄が現れる。
- 「社員へ精算」に戻す → 元どおり。**両方が同時に出ることはない**（排他）。

「取引先へ支払」にしたうえで、**支払取引先を空のまま**残りを入力:

| 項目 | 入力値 |
|---|---|
| 件名 | `会社案内パンフレット 増刷代` |
| 金額（税込） | `22,000` |
| 利用日 | 本日 |
| 目的 | `展示会配布用の増刷。グランメゾン印刷へ直接支払` |
| 申請区分 | `立替精算（支払済み）`（既定のまま） |
| 支払先区分 | `取引先へ支払` |
| 費目 | `印刷製本費` |
| 利用先 | `グランメゾン印刷` |

→ 「**申請**」を押す。

- **期待結果**: 赤トースト「**支払取引先を選択してください**」でブロック。申請は開始されず、精算ステータスは「下書き」のまま・承認者に通知も飛ばない。
- **確認ポイント**: 検証の順番は「必須入力 → 金額 → 支払取引先 → 精算対象者 → 費目 → 交際費 3 項目」。金額を空にしたままだと**支払取引先のエラーには辿り着かない**（先に「金額を入力してください」で止まる）。エラーは一度に 1 つずつしか出ない。

支払取引先に「**C005 グランメゾン印刷**」を選び直して → 「**申請**」。

- **期待結果**: 黄色の警告「領収書が添付されていません。…」（ブロックしない）→ トースト「申請しました」。承認フロー欄は `▶開発1部 第一課長 山本由美` の 1 段 1 名。
- **確認ポイント**: 申請が通ると入力欄が全部ロックされる。**支払先区分も後から変えられない**。

## ステップ 2: 不課税の費目で申請する（EXP-A03）

続けて「新規作成」でもう 1 本:

| 項目 | 入力値 |
|---|---|
| 件名 | `情報サービス産業協会 年会費` |
| 金額（税込） | `20,000` |
| 利用日 | 本日 |
| 目的 | `2026年度 団体年会費` |
| 支払先区分 | `社員へ精算`（既定のまま） |
| **うち消費税** | `1,818`（**費目より先に**入れる。次の行で消えることを確認する） |
| 費目 | `諸会費` |

→ 「**申請**」。

- **確認ポイント（ADR-0051）**: 費目に `諸会費` を選んだ瞬間、**「うち消費税」欄がラベルごと消え**、Info トースト「「諸会費」は消費税の対象外の費目のため、入力済みの「うち消費税」1,818 円をクリアしました」が出る。不課税の費目では手入力の税額は仕訳に一切効かないため、欄自体を出さず値も残さない。
- **確認ポイント**: 諸会費を選んでも接待欄も固定資産チェックも出ない（交際費フラグ・資産性フラグが立っていない費目）。
- **期待結果**: 承認フローは同じく `▶山本由美`。金額 20,000 円は 30,000 円未満なので課長 1 段（部長段は積み上がらない）。

## ステップ 3: レシートの消費税額を手入力する（EXP-A04）

3 本目:

| 項目 | 入力値 |
|---|---|
| 件名 | `開発定例 ケータリング` |
| 金額（税込） | `10,800` |
| 利用日 | 本日 |
| 目的 | `開発1部 週次定例の軽食（軽減税率の飲食料品を含む）` |
| 費目 | `会議費` |
| 利用先 | `デリカ神田` |
| **うち消費税** | `800`（レシート記載額。10% で計算すると 981 円になるはずの金額） |

→ 「**申請**」。

- **確認ポイント**: 「うち消費税」は Placeholder のとおり任意項目。ここに入れた値が**計算より優先**される仕組みで、軽減税率 8% の品が混ざったレシートや、端数処理が事業者ごとに違うケースを吸収するための逃げ道。
- **確認ポイント（ADR-0051）**: 入力した瞬間に警告トースト「「うち消費税」800 円は税率 10% での計算値 981 円と離れています。桁の間違いがないか確認してください（軽減税率や非課税品が混ざったレシートなら問題ありません）」が出る。これは**警告であって禁止ではない**——まさに今回のような軽減税率混在が正当なケースなので、そのまま申請できる（乖離が計算値の ±10% を超えると出る）。
  - 一方、**桁を間違えて `8,000`（金額 10,800 円に対して過大）や `10,800` 以上**を入れると、エラー「「うち消費税」… が金額（税込）… 以上です」で**申請自体が止まる**。試すなら申請前に戻すこと。

## ステップ 5: 経理が仕訳を生成して 3 つの形を見比べる

**soumu_bucho**（山田太郎）でログイン → サイドバー「**経費精算**」→ **精算処理待ち**に着地。3 件が並んでいる。

### 5-1. 「会社案内パンフレット 増刷代」（取引先へ支払・22,000）

開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 **印刷製本費** 20,000 円 / 貸方 未払金 22,000 円）」。
- **帳簿の中身**（会計業務 > 帳簿 > 仕訳帳、本日付）: 3 行。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | **消耗品費** | 20,000 |
  | 借方 | 仮払消費税 | 2,000 |
  | 貸方 | 未払金 | 22,000 |

- **確認ポイント（気づいてほしい癖）**: トーストは「**印刷製本費**」と言うのに、仕訳の科目は「**消耗品費**」。トーストは**費目名**を、仕訳は費目マスタの**既定勘定科目**を出しているため。印刷製本費の既定科目が消耗品費(6140)に設定されているのが原因で、間違いではないが**読み手を確実に戸惑わせる**。改善提案のネタ。
- **確認ポイント（本題）**: 仕訳のどこにも「**グランメゾン印刷**」は出てこない。取引先は申請レコードにしか残らず、**買掛金(2010) ではなく未払金(2020)** に立つ。つまり取引先別の未払残高には乗らない。業者別に債務を管理したいなら経費精算ではなく「購買・支払」部品（仕入先請求書）を使う、という部品分担になっている。
- 全行に部門「**開発1部**」（申請者の所属**部**。課ではない）が付く。

### 5-2. 「情報サービス産業協会 年会費」（諸会費・20,000）

戻って開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 諸会費 20,000 円 / 貸方 未払金 20,000 円）」。
- **帳簿の中身**: **2 行だけ**。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 諸会費 | 20,000 |
  | 貸方 | 未払金 | 20,000 |

- **確認ポイント**: 仮払消費税の行が**生成されない**。費目の既定税区分が「不課税」で、税額計算は課税仕入のときだけ動くため。借方の金額は税抜本体ではなく**税込全額**（そもそも税が無い）。
- **確認ポイント（ステップ 2 の伏線）**: 手入力の優先は「課税仕入と判定された後」の話で、不課税ならその手前で税額 0 が確定する。だからステップ 2 で入れた 1,818 円は費目を選んだ時点でクリアされ、**DB にも残っていない**（ADR-0051。2026-08-12 以前は欄が生きたまま値だけ黙って無視されていた＝改善候補 A-4）。
- **確認ポイント**: 消費税集計表（会計業務 > 財務帳票）に、この 20,000 円は**課税仕入として現れない**。

### 5-3. 「開発定例 ケータリング」（税額手入力・10,800）

戻って開く → 「**仕訳を生成**」。

- **期待結果**: トースト「仕訳 No.◯ を生成しました（借方 会議費 **10,000** 円 / 貸方 未払金 10,800 円）」。
- **帳簿の中身**: 3 行。

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 会議費 | **10,000** |
  | 借方 | 仮払消費税 | **800** |
  | 貸方 | 未払金 | 10,800 |

- **確認ポイント（本題）**: 10% で内税計算すると `10,800 × 10 ÷ 110 = 981`（切り捨て）→ 本体 9,819 になるはず。実際は **手入力の 800 が採用され、本体は 10,000**。手入力が計算に勝っている。
- **確認ポイント**: 本体額は「税込 − 税額」で機械的に引き算されるだけ。つまり**手入力の税額が誤っていても検算も警告もされない**（例: 5,000 と入れれば本体 5,800 の仕訳が黙って作られる）。レシートの転記ミスがそのまま帳簿に入る余地がある——ここも改善提案のネタ。

## ステップ 6: 支払先区分が仕訳に効かないことを確認する（本シナリオの結論）

3 本とも「**精算済にする**」→「**完了にする**」まで進める。

- **期待結果（各件）**: トースト「支払仕訳 No.◯（{金額} 円）を生成し精算済にしました」→ 「完了にしました」。精算処理待ち一覧から消える。
- **支払仕訳の中身**（3 本とも同じ形・本日付・税処理なし）:

  | 貸借 | 科目 | 金額 |
  |---|---|---|
  | 借方 | 未払金 | 申請金額 |
  | 貸方 | 普通預金 | 申請金額 |

- **確認ポイント（結論）**: 「取引先へ支払」の 22,000 円も、「社員へ精算」の 20,000 円・10,800 円も、**支払仕訳の形はまったく同じ**。支払先区分は仕訳生成にも支払仕訳にも一切影響しない。効いているのは
  1. 申請フォームの**欄の出し分け**（精算対象者 ⇔ 支払取引先）
  2. **申請時の必須チェック**（どちらか一方が空だとブロック）
  の 2 つだけで、会計処理は完全に共通。
- **確認ポイント**: したがって「誰に払うのか」を帳簿から知る手段は無い（摘要にも入らない）。振込作業は支払予定表・振込データ作成（購買・支払部品）ではなくこの一覧を見ながら手作業になる。中小企業の実運用ではここが実務上の穴になりうるので、デモで質問が出たら「経費は社員立替が主で、業者支払は仕入先請求書で回す想定」と答えられるようにしておく。
- **確認ポイント**: 出納帳（普通預金）に 3 件の出金が並ぶ。合計 52,800 円。

## 後片付け

**このシナリオは仕訳を 6 本残す。仕訳は画面から削除できないため、完全な原状復帰はできない。**

- 申請 3 本は「完了」まで進んでいるので、精算処理待ち一覧からは消えている（一覧を汚さない）。
- **元に戻したい場合（任意）**: 会計業務 > 仕訳 > 振替伝票 で赤伝（貸借を逆にした訂正伝票）を切るか、経理・管理者に `sql` CLI での物理削除を依頼する。デモ目的なら**残したままで問題ない**（3 つの税パターンが帳簿に並んでいる状態は、むしろ説明の材料になる）。
- マスタ（費目・税区分・取引先）と会計期間は一切変更していないので、戻す作業は不要。

## つまずいたときは

- **「支払取引先を選択してください」ではなく「金額を入力してください」が出る**: 検証の順序どおり。金額を先に埋めてから取引先を空にして試す。
- **支払取引先のドロップダウンにグランメゾン印刷が出ない**: 業務マスタ > 取引先 で C005 が有効（取引終了になっていない）か確認。C008 シリウス設計は無効なので出ないのが正しい。
- **諸会費なのに 3 行仕訳になる**: 業務マスタ > 会計マスタ > 費目 で諸会費の既定税区分が「不課税」から変えられている。税制 > 税区分 で「不課税」の課税区分が `non_taxable` であることも合わせて確認。
- **「うち消費税」を入れたのに計算値のままになる**: 申請後に入力しようとしていないか（申請後は全欄ロック）。手入力は**申請前**に入れる必要がある。
- **仕訳番号が本書と違う**: 番号は年度内の最終+1。他の操作を挟めばずれる。金額と貸借が合っていれば正常。
- **「仕訳を生成」ボタンが出ない**: 経理機能フラグを持つユーザーでログインしていない。soumu_bucho で操作する。
- **「この申請の仕訳は既に生成済みです」**: 二重生成ガード。すでに経理処理中に進んでいるので、次は「精算済にする」を押す。
