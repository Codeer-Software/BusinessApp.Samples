# 体験シナリオ 定期-03: 実行対象の分岐（なぜこの契約は生成されないのか、を全部読む）

> 作成: 2026-08-09 ／ 所要時間: 約35分 ／ 影響: 既存契約の状態（確定/下書き・有効/無効・月額金額）を**一時的に**変更する（後片付けで全て戻す）。ステップ 8 で 2026-09 分の請求書・仕訳を **1 件だけ**生成するが、ステップ 10 の「発行を取り消す」で請求書・仕訳・入金予定ごと削除し、**帳簿は元どおりに戻る**。
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。権限確認だけ **eigyo_ippan**（営業部 一般 伊藤さくら）。パスワードはユーザー名と同じ。
> 参照分岐: 11_E2E の RCR-01（冪等）／RCR-02（無効・下書き）／RCR-03（開始月前）／RCR-04（締め済み）／RCR-05（経理専用）。
> 「定期請求の実行」の一覧は**判定結果の説明書**。黄色（生成予定）以外の行がなぜそうなのかを、6 通りの理由すべてについて自分の手で作って読む。
>
> **更新履歴**: 2026-08-11 テスト残骸の削除に伴い数字を更新。除外理由の材料に使っていた契約④「請求クラウドサービス年額バージョン」が DB から消えたため、**ステップ 3 でテスト契約を自分で 1 件作り、後片付けで削除する方式**に変更した（既存契約は 3 件）。

## 物語

月初、経理の山田太郎は「定期請求の実行」を開く前に必ずプランを一覧して、**身に覚えのない請求が黄色（生成予定）になっていないか**を点検する。
今回はその点検力を鍛えるため、既存の契約 3 件と自分で作る使い捨ての契約 1 件を材料に「下書き」「無効」「金額 0」「期間外」「締め済み」「取消済み」の 6 通りの除外理由を意図的に作り出し、最後に「void（取消にする）は再生成されない／発行取消なら再生成される」という、月次バッチの一番きわどい分かれ道を確かめる。

## ステップ 1: プランの読み方を覚える（soumu_bucho）

**soumu_bucho** でログイン → サイドバー「**営業業務**」→ 経理は請求書に着地 → フレーム内サイドバー「**定期請求の実行**」。

- **確認ポイント（画面の構成）**: 上から「対象月」（**既定 = 今月 = 2026-08**）／ボタン「**対象月の請求書・仕訳を一括生成**」／説明 2 行／一覧「**対象月の生成プラン**」／結果ラベル。
- **確認ポイント（列）**: 契約・取引先・部門・種別・処理種別・**状態**・**内容**・請求額（税抜）・消費税・按分振替額・周期起点月・周期内月番号・請求書番号。**「状態」と「内容」がこのシナリオの主役**。
- **確認ポイント（色）**: 状態「生成予定」の行だけが**黄色**。一括生成が消費するのはこの黄色行だけで、「生成済み」「対象外」は何度押しても動かない。
- ここでは**まだボタンを押さない**（8 月分の本番バッチになってしまう）。

## ステップ 2: 開始月より前は「行すら出ない」（RCR-03）

対象月を **2026-07** に変える（対象月を変えるたびにプランは**全行洗い替え**される）。

- **期待結果**: 契約③「請求クラウドサービス」（2026-08 開始）の行が**一覧から消える**。対象外の行としても出ない。
- **確認ポイント**: 「対象外（＝理由つきで表示）」と「期間外（＝そもそも表示されない）」は別物。期間フィルタ（開始月が未設定／開始月 > 対象月／終了月 < 対象月）に当たった契約は、プランに 1 行も作られない。
- **解約との関係**: 終了月を入れた契約も、翌月以降は同じく行ごと消える（→ 定期-01 ステップ 7）。「契約を消さずに請求を止める」手段が終了月、というのがこの設計。
- ここでも**ボタンは押さない**（7 月分が未生成なら黄色行が残っている可能性がある）。

## ステップ 3: 下書きの契約は対象外（RCR-02 の片割れ）— 材料は自分で作る

> 以前この節ではテスト残骸の契約を材料にしていたが、その契約は **2026-08-11 に DB から削除済み**（README §4）。
> **使い捨てのテスト契約を 1 件作って**「下書き＝対象外」を体験し、後片付けで削除する。金額を小さくしてあるので、万一実行してしまっても被害は軽い。

対象月を **2026-09** にしてから、フレーム内サイドバー「**定期請求契約**」→「**新規作成**」。

| 項目 | 入力値 |
|---|---|
| 件名 | `【テスト】除外理由の確認用` |
| 取引先 | `ホライゾン商事株式会社` |
| 部門 | 既定のまま（総務部） |
| 課金サイクル | `月額` |
| 月額（税抜） | `50,000` |
| 開始月 | `2026-09-01` |
| 終了月 | 空 |
| 有効 | ON |

→「**保存**」。新規作成した契約の状態は **「下書き」**（＝経理が「確定する」を押すまで実行対象にならない）。

ここで「下書きに戻す」ダイアログも見ておく: 「**確定する**」→「確定する」で状態「確定済」→ 続けて「**下書きに戻す**」（赤）→ ダイアログ「この契約を下書きに戻します（「定期請求の実行」の対象から外れます）。よろしいですか？」→「**下書きに戻す**」。

- **確認ポイント（ガード）**: 下書きに戻せるのは**請求実績が無い契約だけ**（ADR-0057）。この契約はまだ 1 件も請求書を作っていないので通る。請求書を発行済みの契約で押すと「この契約から請求書が N 件発行されているため下書きに戻せません（請求を止めるだけなら「有効」のチェックを外してください）」で止まる（ステップ 11 で ① を使って確かめてもよい）。

「定期請求の実行」に戻り、対象月を選び直す（別の月にしてから 2026-09 に戻すとプランが洗い替えされる）。

- **期待結果**: ④ の行が **状態「対象外」／内容「契約が下書き（経理確認前）のため対象外」**。
- **確認ポイント**: 下書きの契約も「行は出る」。**見えないのは期間外だけ**——ここがステップ 2 との対比。
- **この契約は下書きのままにしておく**（後片付けで削除する）。

## ステップ 4: 無効化した契約は対象外（RCR-02）

「定期請求契約」で ① **クラウド勤怠 SaaS 利用料** と ② **クラウド勤怠 SaaS 年額プラン** を 1 件ずつ開き、「**有効**」チェックを **OFF** にして「**保存**」。

- **確認ポイント（権限）**: 「有効」チェックと「部門」は**経理のみ操作可**。非経理が確定済の契約を開くと画面全体が閲覧専用になり、赤い注記「確定済の契約です。内容の変更・有効/無効の切替は経理が行います」が出る（ステップ 11 で実際に見る）。

「定期請求の実行」→ 対象月 2026-09 を選び直す。

- **期待結果**: ①② が **「契約が無効化されているため対象外」**。これで 2026-09 の**黄色行は契約③ の 1 行だけ**になる（＝以降の実験を 1 契約に隔離できた）。
- **確認ポイント（使い分け）**: 「有効 OFF = 一時停止（契約は生きている）」「**終了にする** = 解約（終了月とセットで確定する）」「下書きに戻す = 経理の差し止め（請求実績が無いときだけ）」。3 つとも結果は「生成されない」だが、意味も表示も違う。

## ステップ 5: ポータルの作業キューと連動する

サイドバー「**ホーム**」でポータルへ戻る。

- **期待結果**: 「経理の作業キュー」の「**▶ 定期請求・SES の当月未生成: N 件**」の N が、**ステップ 4 の無効化の分だけ減っている**（下書き・無効の契約は「未生成」に数えない）。ステップ 3 で作った ④ は下書きかつ 2026-09 開始なので、はじめから当月のカウントに入らない。
- **確認ポイント（当月固定）**: このキューが見ているのは常に**当月（2026-08）**であり、実行画面で選んだ対象月とは無関係。「実行画面の黄色行の数」と一致しないことがあるのはそのため。
- **確認ポイント（内訳）**: N は「定期請求の当月未生成」＋「SES の当月未生成」の合算（→ SES-01・SES-02）。クリックすると SalesBilling の定期請求の実行へ着地する。
- **気づきメモ（要検証）**: 年額契約は本来「周期起点月だけ」未生成に数えたいはずだが、キューの集計 SQL が課金サイクルを `annual` と比較しているのに対し、契約側の実データは `yearly`（画面の「年額」）。**年額契約が毎月カウントされていないか**を、②を有効に戻したあと（後片付け後）の件数で確かめておく価値がある。ズレていれば CLB ではなく本アプリ側の不具合。

## ステップ 6: 金額 0 の契約は対象外

「定期請求契約」→ ③「**請求クラウドサービス**」を開き、「**月額（税抜）**」を **0**（または空）にして「**保存**」。

- **確認ポイント**: 金額のチェックが走るのは「**確定する**」を押すときだけ（「月額（税抜）を入力してから確定してください」）。**確定済の契約を後から 0 円に書き換えるのは保存できてしまう**——だからこそ実行前のプラン点検が要る、という設計の裏側。

「定期請求の実行」→ 対象月 2026-09 を選び直す。

- **期待結果**: ③ が **「月額金額が未設定（0円）のため対象外」**。この時点で 2026-09 の黄色行は **0 行**。
- ここで「**対象月の請求書・仕訳を一括生成**」を押してみる → トースト（Info）「**生成対象はありませんでした**」。結果ラベルは「2026年9月分: 月額請求 0件 / 年額請求 0件 / 按分振替 0件 / **対象外 4件**」。**請求書も仕訳も 1 件も増えない**（安全に押せる状態を自分で作った、ということ）。
- **確認ポイント（対象外の件数の読み方）**: 「対象外 N件」の N は、**対象月に期間該当する契約のうち黄色でない行の数**。ここでは ①（無効）②（無効）③（0円）④（下書き）の 4 行。期間外で行が作られなかった契約は N に入らない（ステップ 2）。契約を増減させた状態で実行すれば N も変わる。

確認したら ③ の「月額（税抜）」を **150,000** に戻して「保存」。

## ステップ 7: 締め済み月は全体ブロック（RCR-04）

対象月を **2026-06**（締め済み）にして「**対象月の請求書・仕訳を一括生成**」を押す。

- **期待結果**: 赤トースト「**対象月の期間は締め済みです**」。**プランの中身に関係なく 1 件も処理されない**（会計年度 → 月次期間 → 締め判定が、契約ループより**前**で return する）。
- **確認ポイント（似た文言の見分け）**: 会計年度が無い月（例 2024-06）なら「対象月に対応する会計年度がありません」、年度はあるが月次期間が無ければ「対象月に対応する月次期間がありません」。3 つは別のガード。
- **確認ポイント**: 締め済み月でも**プランの表示自体はできる**（何が生成されるはずだったかは読める）。止まるのは実行だけ。

## ステップ 8: 隔離された 1 件だけを生成する（実験材料づくり）

対象月を **2026-09** に戻す。黄色行が ③「請求クラウドサービス」の 1 行（内容「月額請求書＋売上仕訳を生成」・請求額 150,000・消費税 15,000）であることを確認して「**対象月の請求書・仕訳を一括生成**」。

- **期待結果**: トースト「定期請求の処理 1 件を生成しました（月額 1 / 年額 0 / 振替 0）」。結果ラベル「2026年9月分: 月額請求 1件 / 年額請求 0件 / 按分振替 0件 / 対象外 3件 / 仕訳 No.…」。
- 生成物 3 点: 請求書「請求クラウドサービス（2026年9月分）」（**発行済**・請求日 9/30・支払期限 10/31・税込 165,000）／仕訳（9/30）借方 **売掛金 165,000** ／ 貸方 **SaaS売上高 150,000** ＋ **仮受消費税 15,000** ／ 入金一覧に「**未確定**」の入金予定（期日 10/31・銀行振込・165,000）。
- プランの ③ は **「生成済み」＋「月額請求書＋売上仕訳を生成済み」**、請求書番号列に番号が入る。
- **もう一度ボタンを押す** → 「生成対象はありませんでした」（**RCR-01** 冪等。二重請求されない）。

## ステップ 9: 「取消にする」（void）は再生成されない

フレーム内サイドバー「**請求書**」→ ステップ 8 の請求書を開き「**取消にする**」（赤）→ ダイアログで「取消にする」。

- **期待結果**: トースト「請求書 INV-26-0XX を取消にしました」。状態「取消」。**売上仕訳はそのまま残る**（帳簿から消えたわけではない）。

「定期請求の実行」→ 対象月 2026-09 を選び直す。

- **期待結果**: ③ が **「請求書が取消（void）済みのため再生成しません」**（状態=対象外）。
- ここで一括生成を押しても「生成対象はありませんでした」。**void は「この月はもう請求しない」という意思表示**であり、バッチを何度回しても復活しない。
- **確認ポイント（使いどころ）**: 過去の締め済み期間にかかっていて仕訳を消せないときの停止手段がこれ（年額契約なら「以後の按分振替を止める」用途 → 定期-02 ステップ 7）。

## ステップ 10: 「発行を取り消す」なら再生成できる（後片付けを兼ねる）

同じ請求書で「**取消を戻す**」→ 状態が「発行済」に戻る（入金予定も作り直される）。

続けて「**発行を取り消す**」（赤）→ ダイアログ「請求書「INV-26-0XX」の発行を取り消します。生成された仕訳 1 本・未確定の入金予定・請求書本体を削除し、未生成の状態に戻します（「定期請求の実行」「SES精算・請求」で再生成できます）。よろしいですか？」→「**発行を取り消す**」。

- **期待結果**: トースト「請求書 INV-26-0XX の発行を取り消しました（必要なら定期請求の実行／SES精算・請求で再生成できます）」。請求書一覧に戻る。**請求書・売上仕訳・未確定の入金予定がすべて消え**、仕訳帳の最終番号がステップ 8 の前に戻る。
- 「定期請求の実行」→ 対象月 2026-09 を選び直すと、③ が**再び黄色（生成予定）**に戻っている。**ここでは実行しない**（9 月分の先行生成になる）。
- **2 つのボタンの覚え方**: 「取消にする（void）= 請求を取りやめた事実を残す・再生成しない」「発行を取り消す = 生成そのものをなかったことにする・やり直せる」。**やり直したいときは必ず後者**。
- **できないケース**: 消込済みの入金があるとどちらも不可（「消込済みの入金記録があるため…（先に入金の取消を行ってください）」）。関連仕訳が締め済み期間にあると発行取消も中止され、「…過去分は赤黒訂正で修正し、以後の按分振替を止めたい場合は「取消にする」を使ってください」と誘導される。

## ステップ 11: 経理専用ガード（RCR-05）

ログアウト → **eigyo_ippan** でログイン → サイドバー「**営業業務**」（SalesStaff に解決される）。

- **期待結果**: フレーム内サイドバーは「見積 / 受注 / 検収 / 売掛残高 / **定期請求契約** / 取引先一覧」。**「定期請求の実行」「請求書」「入金」「SES精算・請求」は存在しない**（メニュー非表示が第一防御）。
- 「定期請求契約」は開ける。確定済の契約（例 ①）を開くと**画面全体が閲覧専用**＋赤い注記「確定済の契約です。内容の変更・有効/無効の切替は経理が行います」。「確定する」「下書きに戻す」ボタンも出ない。
- **確認ポイント（多層防御）**: 万一この画面に到達して実行できたとしても、スクリプト側が赤トースト「**定期請求の実行（売上計上を伴う）は経理のみ実行できます**」で拒否する。この文言が実際に見えたら、メニューの可視性が退行している合図。

## つまずいたときは

- **プランに変更が反映されない**: プランが洗い替えされるのは「画面を開いたとき」と「対象月を変えたとき」だけ。契約やマスタを直したら、**対象月を別の月にしてから戻す**（または画面を開き直す）。なお「一括生成」は押した瞬間に必ずプランを作り直すので、**表示が古くても実行結果は最新データが正**。
- **「対象外」なのに件数に入らない**: 期間外（開始月前・終了月後）は行が作られないので、結果ラベルの「対象外 N件」にも含まれない。表示されていない契約を数えたいときは対象月を変えて確かめる。
- **③ を 0 円に戻せない／確定できない**: 「確定する」は経理かつ下書きのときだけ出る。確定済のまま金額を直すなら「保存」でよい（0 円チェックは確定時のみ）。
- **発行を取り消せない**: ①消込済みの入金がある ②関連仕訳が締め済み期間にある ③定期請求・SES 以外で作った請求書（「この操作は定期請求・SES で生成された請求書専用です」）——の 3 つが主な原因。
- **仕訳番号が本書と違う**: 番号は年度内の最終 +1。他の操作を挟めばずれる。金額と貸借が合っていれば正常。なお現在のデモ DB は **No.77・78・80・81 が欠番**（テスト残骸の削除跡）なので、連番が飛んでいても異常ではない。
- **テスト契約 ④ を削除できない**: 「この契約を削除」が出るのは**下書き かつ 請求書 0 件**のときだけ。①確定済のままなら「下書きに戻す」で戻す ②うっかり請求書を生成してしまった場合は、先にその請求書を開いて「**発行を取り消す**」（請求書・仕訳・未確定入金予定ごと消える）→ そのうえで削除する。取消（void）にしただけの請求書は行が残るため削除できない（「この契約から請求書が N 件作成されているため削除できません」）。
- **一覧に契約が出てこない**: サイドバーから開いた直後の一覧は**状態が「下書き」「確定済」に絞られている**（終了した契約は既定で出ない・ADR-0057）。終了した契約を見たいときは検索条件の「状態」で「終了」にもチェックを入れて検索する。
