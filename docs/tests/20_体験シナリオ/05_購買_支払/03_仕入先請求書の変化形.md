# 体験シナリオ 購買-03: 仕入先請求書の変化形（1 枚の請求書を前後に動かす）

> 所要時間: 約30分 ／ 影響: 仕入先請求書を 2 件（本体＋複製）一時的に作り、仕訳を最大 2 本作って**すべて取り消し・削除する**。終了時の DB は開始時と同じ（仕訳番号の採番位置だけ進む可能性がある）
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。パスワードはユーザー名と同じ。
> 購買-01 が「まっすぐ進む一本道」なら、本書は**同じ 1 枚を止める・戻す・写す・消す**。入力ガード → 期間ガード → 未払計上と取消 → 支払と取消 → 複製 → 削除 → インボイス番号照合、を一続きで体験する。

## 物語

経理の山田太郎のもとに、株式会社ベガソフトから外注費の請求書（165,000 円・税込）が届いた。
ところが今日は朝からミスが続く——項目を入れ忘れて登録し、請求日を先月（締め済み）と打ち間違え、
計上したあとで「金額が違う」と連絡が来て取り消し、翌月も同じ請求が来るので複製し、
最後は「そもそもこの仕入先、インボイス登録は生きているのか」を確かめる。
**アプリが誤操作をどう受け止め、どう巻き戻させるか**を一巡で見る。

## 前提

| 項目 | 内容 |
|---|---|
| 画面 | 業務ポータル → Main 左サイドバー「**購買・支払**」（Purchasing フレーム。ゲート = 経理機能）。着地は**仕入先請求書の一覧** |
| 会計期間 | 第18期（2026年度）。**2026-04〜06 は締め済み**、07 以降オープン。2019 年には会計年度が存在しない（第17期＝2025年度が最古） |
| 使う仕入先 | **株式会社ベガソフト（C002）**。課税事業者・取引先口座も登録済み |
| 仕訳番号の目安 | その時点の最終 +1（本書執筆時は最終が No.83 なので No.84・No.85）。他の操作を挟めばずれるが、**金額と貸借が合っていれば正常** |
| 影響 | 作った請求書と仕訳は**後片付けですべて消す**。既存の 5 件には触れない |

## ステップ 1: 必須項目のブロック（PUR-01）

サイドバー「**購買・支払**」→ 仕入先請求書の一覧 →「**新規作成**」。

**何も入力せずに**「**登録**」を押す。

- **期待結果**: 保存されない。必須項目が赤枠になり、入力検証エラーが出る。
- **確認ポイント**: 必須は **請求書番号 / 仕入先 / 請求日 / 費用科目 / 金額（税込）** の 5 つ。
  「状態」も内部的には必須だが、新規作成時に**受領**が自動で入っている（受領日も本日が自動セット）ので、人が意識することはない。
- **確認ポイント（設計の意図）**: 支払期限・**部門**・税区分・**案件**・摘要・支払口座は**任意**。請求書は「届いた事実を先に記録する」ものなので、
  期限や口座が読み取れなくても登録を止めない。逆に**金額と請求日と科目が無いと後の仕訳が作れない**ので、そこだけを必須にしている。
- **確認ポイント（部門だけは「保存では任意・未払計上では必須」）**: 費用科目が損益科目のとき、部門が空だと
  ステップ 3 の未払計上が「**部門を選択してください（損益科目の仕訳には部門が必要です）**」で止まる（ADR-0056）。
  **登録は通るのに次の操作で止まる**ので、必須マーク（*）だけを見ていると引っかかる。

項目を 1 つずつ埋めると赤枠が 1 つずつ消える。次のように入れて「**登録**」。

| 項目 | 入力値 |
|---|---|
| 請求書番号 | `VG-2608-311` |
| 仕入先 | `株式会社ベガソフト` |
| 受領日 | 本日（自動セット済み） |
| 請求日 | **2026-06-30**（＝締め済み月。ステップ 2 でわざと踏む） |
| 支払期限 | 空欄のまま |
| 費用科目 | `外注費` |
| **部門** | **`開発1部`**（損益科目なので未払計上に必須） |
| 税区分 | `課税仕入 10%` |
| **案件（任意）** | **`ECサイト構築`**（外注は案件に紐づく。ステップ 3 で案件別損益に乗ることを確かめる） |
| 金額（税込） | `165,000` |
| 摘要 | `会員サイト改修 外注費（6月分）` |

- **確認ポイント**: **保存自体は通る**。請求日が締め済み月でも、締めガードが働くのは「未払計上（仕訳生成）」のときだけ。
  受領登録は帳簿の外の出来事なので、期間で縛らない設計になっている。

## ステップ 2: 期間・年度のガードを 2 つ踏む（PUR-02）

保存した詳細画面で「**未払計上（仕訳生成）**」を押す。

- **期待結果**: 赤トースト。
  > 請求日の期間は締め済みです。仕訳は手動で起票してください
- **確認ポイント（フォールバックしない）**: 経費精算の「仕訳を生成」は締め済みのとき**本日へフォールバック**して起票するが、
  仕入先請求書は**止まる**。買掛の計上日は請求日そのもの（発生主義）で、勝手に日付をずらすと**買掛残高の月次推移が狂う**ため。
  どうしても計上したいなら、案内どおり 会計業務 > 仕訳 > 振替伝票 で手起票するか、会計年度画面で当該期間を再オープンする。
- **確認ポイント**: 状態は「**受領**」のまま。仕訳帳も無変化（ガードは仕訳の保存より前に効いている）。

次に、請求日を **`2019-06-30`** に書き換えて「**登録**」→ もう一度「**未払計上（仕訳生成）**」。

- **期待結果**: 赤トースト。
  > 請求日に対応する会計年度がありません
- **確認ポイント（ガードの順序）**: 未払計上のガードは上から順に、
  ① 受領状態か ② 金額が 0 でないか ③ 請求日があるか ④ 費用科目があるか ⑤ 二重生成でないか
  ⑥ **年度があるか** ⑦ **月次期間があるか** ⑧ **締め済みでないか** ⑨ **部門があるか**（費用科目の行に
  部門が要る・ADR-0056）⑩ 買掛金(2000)の科目があるか——の 10 段。
  **最初に引っかかった 1 つだけ**がトーストに出る。だから「年度が無い」と「締め済み」は同時には見えない。
- **確認ポイント**: 会計年度は 第17期（2025年度）が最古。2019 年はどの年度にも属さないので ⑥ で止まる。
  年度はあるが月次期間だけ無い、という状態（＝年度作成直後に期間生成をしていない）なら ⑦ の「請求日に対応する月次期間がありません」になる。

## ステップ 3: 正しい日付で未払計上し、取り消す（PUR-03）

請求日を **本日**（オープン期間）に直して「**登録**」→「**未払計上（仕訳生成）**」。

- **期待結果**: 緑トースト。
  > 未払計上 No.84 を生成しました（借方 150,000 円+税 / 貸方 買掛金 165,000 円）

  （番号はその時点の最終 +1。以下 **No.A** と呼ぶ）状態が「**未払計上済**」に進む。
- **帳簿の確認**: サイドバー「ホーム」→「**会計業務**」→ 帳簿 > 仕訳帳。**請求日**の日付で 3 行:

  | 貸借 | 勘定科目 | 金額 |
  |---|---|---|
  | 借方 | 外注費 | 150,000 |
  | 借方 | 仮払消費税 | 15,000 |
  | 貸方 | 買掛金 | 165,000 |

  摘要は `仕入先請求 VG-2608-311 会員サイト改修 外注費（6月分）`。種別は「自動」、状態は「確定」。
- **確認ポイント（税の出どころ）**: 税額は**税区分が「課税仕入」のときだけ**内税で割り戻す（`165,000 × 10 ÷ 110 = 15,000`）。
  非課税仕入・不課税・対象外を選んでいれば税は 0 で、**仕訳は 2 行**になる。
- **確認ポイント（部門と案件が全明細に乗る・ADR-0064）**: 伝票を開くと、**3 行すべて**の「部門」が `開発1部`、
  「プロジェクト」が `ECサイト構築` になっている。**買掛金の行にも付く**——案件別損益が見るのは費用・収益科目だけなので
  数字は動かないが、**総勘定元帳を案件で絞ったときにその案件の入出金まで追える**ようにするため。
- **確認ポイント（案件別損益に乗ることを確かめる）**: サイドバー「ホーム」→「**経営管理**」→ 案件損益 > 「**案件損益**」→
  会計年度 `第18期（2026年度）` で検索。**`PRJ-004 ECサイト構築` の「直課費用」が 150,000 増えている**
  （税抜の本体額。仮払消費税は資産科目なので原価に乗らない）。
  **2026-08-16 まで、仕入先請求書には案件の項目が無く、外注費は案件別損益に 1 円も乗らなかった**（ADR-0064 で解消）。
  確認したら、この後のステップで取り消すので元に戻る。

「購買・支払」に戻り、**ボタンの顔ぶれが変わっている**ことを見る（PUR-03）。

| 状態 | 出るボタン |
|---|---|
| 受領 | この請求書を複製 ／ **未払計上（仕訳生成）** ／ **この請求書を削除**（赤） |
| 未払計上済 | この請求書を複製 ／ **支払登録（消込仕訳）** ／ **未払計上を取り消す**（赤） |
| 支払済 | この請求書を複製 ／ **支払を取り消す**（赤） |

- **確認ポイント（ADR-0026）**: 状態は**ボタンでしか動かない**（詳細画面の「状態」欄は読み取り専用。支払日も同じ）。
  前進ボタンと巻き戻しボタンは**同時に出ない**ので、「いま何ができるか」が画面から一意に読める。
- **確認ポイント（二重計上ガード）**: 未払計上済みになった瞬間に「未払計上」ボタンは消えるので、通常操作では二重に押せない。
  それでも古い画面を開いたまま押した場合に備えて「**この請求書の未払計上仕訳は既に生成済みです**」というガードが残してある（防御線）。

ここで「**未払計上を取り消す**」（赤）を押す。

- **期待結果**: 確認ダイアログ。
  > 未払計上を取り消しますか？（仕訳 No.84 を削除し、受領状態に戻します）

  ボタンは「**取り消す**」「**キャンセル**」。
- まず「**キャンセル**」を押す。**何も起きない**（状態は未払計上済のまま・仕訳も残る）ことを確認する。
- もう一度押して「**取り消す**」。
- **期待結果**: 緑トースト「**未払計上を取り消しました（仕訳 No.A を削除）**」。状態が「**受領**」に戻り、赤い「この請求書を削除」が復活する。
- **確認ポイント（削除される仕訳番号がダイアログに出る）**: 「何が消えるか」を押す前に見せているのが要点。
  仕訳帳を開くと **No.A が丸ごと消えている**（明細行も一緒に削除される）。
- **確認ポイント（番号は詰め直さない）**: 採番は「年度内の最終番号 +1」なので、消した No.A が最後の番号だった場合、
  **次の起票が同じ番号を取り直す**。連番の欠番を許容する設計（過去番号の再利用は年度内の最終番号に限る）。
- **確認ポイント（締め済みは取り消せない）**: 仕訳の日付が締め済み期間に入っていると、ダイアログの前に赤トーストで止まる。
  > 未払計上仕訳の期間が締め済みのため取り消せません（決算修正仕訳で対応してください）

  締めた月の帳簿を後から書き換えないための線引き。支払側にも同じ文言の対（「支払仕訳の期間が締め済みのため…」）がある。

## ステップ 4: 仕訳だけ先に消えていたときの分岐（文言と発生条件）

> **このステップは通常 UI から再現できない。** 読んで理解するだけでよい。

取消は「対応する仕訳を探す → あれば削除して状態を戻す」という順で動く。**仕訳が見つからなかった場合**、
ダイアログの文言が次に変わる。

> 対応する仕訳が見つかりません。状態だけを受領に戻しますか？

（支払取消の側は「**対応する仕訳が見つかりません。状態だけを未払計上済みに戻しますか？**」）
ボタンは同じく「取り消す」「キャンセル」。「取り消す」を選ぶと**仕訳の削除をスキップして状態だけ**を巻き戻し、
トーストは No. の付かない「**未払計上を取り消しました**」になる。

- **発生条件**: 状態が「未払計上済」なのに、`source_type='vendor_invoice'` の仕訳が存在しない状態。具体的には——
  - 取消の途中でスクリプトが失敗した（仕訳は消えたが状態更新に失敗した、の逆パターン）
  - 別のブラウザ／別セッションで先に取り消され、こちらの画面が古い
  - DB を直接触って仕訳だけ消した／他システムから移行したデータで仕訳リンクが欠けている
- **なぜ UI から再現できないか**: 確定済み（posted）の仕訳には**削除導線が無い**（会計業務 > 振替伝票で削除できるのは「保存済みの下書き」だけ。確定分は赤黒訂正で消す＝ADR-0026）。
  そのため「仕訳だけ消す」を画面から起こせない。
- **確認ポイント（設計の意図）**: ここで黙って例外にせず**人に選ばせている**のが要点。
  「帳簿は既に無いのに、請求書だけ未払計上済のまま」という**宙ぶらりんを画面から解消できる出口**を残してある。

## ステップ 5: 支払登録と、その取消

もう一度「**未払計上（仕訳生成）**」を押して未払計上済みに戻す（新しい No.A' が振られる）。
続けて「**支払登録（消込仕訳）**」。

- **期待結果**: 緑トースト。
  > 支払仕訳 No.85（165,000 円）を生成し支払済にしました

  （以下 **No.B**）状態が「**支払済**」、**支払日に本日**が自動で入る（手入力は不可）。
- **仕訳**: 借方 **買掛金 165,000** ／ 貸方 **普通預金 165,000**。**取引日は本日**（請求日ではない）。
  - **確認ポイント（2 つの日付）**: 費用の計上日＝**請求日**、資金の動いた日＝**本日**。同じ 1 枚の請求書から
    発生主義（費用・買掛）と現金主義（預金）の 2 本が出る、という複式簿記の要が体験できる。
  - **確認ポイント（口座のフォールバック）**: 支払口座を選んでいないので、貸方は **普通預金(1020) にフォールバック**する。
    支払口座に「MB01 メインバンク 普通預金」を選んでも、その口座の帳簿科目が 1020 なので結果は同じ。口座が複数ある会社では差が出る。
- **確認ポイント**: 支払予定表（サイドバー）から**この行が消えている**。予定表に載るのは受領・未払計上済だけ。

「**支払を取り消す**」（赤）を押す。

- **期待結果**: ダイアログ「**支払を取り消しますか？（仕訳 No.B を削除し、未払計上済みに戻します）**」→「取り消す」。
  緑トースト「**支払を取り消しました（仕訳 No.B を削除）**」。状態が「**未払計上済**」に戻り、**支払日が空**になる。
- **確認ポイント**: 支払予定表に**戻ってくる**。取消は状態だけでなく「予定表に載る／載らない」まで含めて元通りになる。
- **確認ポイント（相殺は取り消せない・ADR-0035）**: 売掛金との相殺で消し込まれた支払だけは、ここで巻き戻せない。
  > この請求書は売掛金との相殺で消し込まれています。取消は 販売＞入金 の該当入金（入金を取り消す）から行ってください

  買掛側だけ戻すと入金側の消込仕訳が残り、**二重払いができてしまう**ため、取消経路を入金側に一本化してある。
  （相殺そのものの体験は `02_営業_受託/06_相殺入金.md`。本書では踏まない）

最後に「**未払計上を取り消す**」も押して、**受領**まで戻しておく（後片付けのため）。

## ステップ 6: 複製（PUR-04）

まず「**新規作成**」を開く。

- **確認ポイント**: 新規（未保存）の画面には「**この請求書を複製**」ボタンが**そもそも出ない**。
  「押せるのに怒られる」ではなく「押せない」——驚き最小の原則で 2026-08-03 に非表示化された（スクリプト側のガード
  「**保存済みの請求書のみ複製できます**」は二重の防御として残っている）。

一覧に戻り、**VG-2608-311**（受領）を開いて「**この請求書を複製**」。

- **期待結果**: 緑トースト。
  > 請求書を複製しました。請求書番号・請求日・支払期限・金額を実物に合わせて入力してください

  **複製先の詳細画面へ自動で遷移**する。
- **コピーされる / されない**:

  | コピーされる | コピーされない |
  |---|---|
  | 仕入先 ／ 費用科目 ／ **部門** ／ **案件** ／ 税区分 ／ 金額（税込）／ 摘要 ／ 支払口座 | **請求書番号** ／ **請求日** ／ **支払期限** ／ **支払日** ／ 仕訳リンク ／ **証憑** |

  受領日は**本日**、状態は**受領**で作られる。
  - **確認ポイント（証憑はコピーされない・2026-08-19 追加）**: ヘッダの「**証憑（受領した請求書）**」欄は
    複製で引き継がれない。電子帳簿保存法で保存するのは**実際に受け取った書類**なので、
    先月の PDF が今月の請求書に付いていては困る。**毎回、実物を添付し直す**。
  - **確認ポイント（部門・案件もコピーされる・ADR-0064）**: 反復的な仕入は**同じ部門・同じ案件**であることがほとんどなので、
    毎月選び直さずに済ませる。逆に「先月と違う案件の請求書」を複製で作ったときは**案件を直し忘れると静かに誤配賦になる**——
    エラーにならないので、複製後は必ず案件欄を見る。
- **確認ポイント（なぜこの切り分けか）**: 家賃・保守料・月次の外注費のように**毎月ほぼ同じ請求書**を写す機能。
  「毎回変わるもの（番号・日付・場合により金額）」は**意図的に空**にして、実物を見ながら埋めさせる。
  日付までコピーすると、先月の日付のまま計上する事故が起きる。トーストの文言自体が「次に何を直すか」の指示になっている。
- **確認ポイント**: 複製直後は請求書番号が空なので、**そのままでは登録できない**（ステップ 1 の必須ガード）。
  `VG-2609-312`・請求日=本日 を入れて「登録」しておく（後片付けで消す）。

## ステップ 7: 削除の 2 つの条件

複製した **VG-2609-312**（受領）で「**この請求書を削除**」（赤）。

- **期待結果**: ダイアログ「**仕入先請求書「VG-2609-312」を削除しますか？（元に戻せません）**」ボタンは「**削除する**」「**キャンセル**」。
  「削除する」→ トースト「仕入先請求書を削除しました」→ **一覧へ戻る**。
- **確認ポイント（条件 1: 受領のときだけ）**: 未払計上済・支払済では削除ボタンが**出ない**。
  消したければ先に「未払計上を取り消す」「支払を取り消す」で受領まで戻す——**仕訳を残したまま請求書だけ消える事故**が起きない構造。
- **確認ポイント（条件 2: 仕訳が残っていたら拒否）**: 受領であっても、この請求書に紐づく仕訳（`vendor_invoice` / `vendor_payment`）が
  1 本でも見つかると赤トーストで止まる。
  > この請求書に紐づく仕訳があるため削除できません

  通常は「受領 = 仕訳なし」なので到達しない**最後の砦**（ステップ 4 と同じく、取消の途中失敗や DB 直接操作で状態と帳簿がずれたときに効く）。
- **確認ポイント**: **一覧に削除は無い**。削除は必ず詳細を開いてから——誤爆防止（2026-07-19 改修）。

## ステップ 8: インボイス番号照合の 3 分岐（保存しない）

「請求書は届いたが、この仕入先の適格請求書発行事業者登録は生きているのか？」を確かめる導線。

サイドバー「ホーム」→「**業務マスタ**」（着地が**取引先**）→ **`C005 グランメゾン印刷株式会社`** を開く。

> **⚠ このステップでは一度も「登録」を押さない。** 登録番号欄の値を書き換えて確認ボタンを押すだけ。
> 確認ボタンはサーバへ問い合わせるだけの**読み取り操作**で、DB は 1 バイトも変わらない。
> 念のため、**開いた時点の登録番号を控えてから**始める（執筆時点は `T5011112222333`）。

| # | 登録番号欄の値 | 「**国税庁で番号を確認**」を押した結果 |
|---|---|---|
| 8-1 | `T5011112222333`（そのまま） | **緑**「適格請求書発行事業者として登録されています（モック応答。実照合は国税庁アプリケーションID設定後）: モック株式会社（疑似応答）（2023-10-01 登録）」 |
| 8-2 | `T5011112222330`（**末尾を 0 に**） | **黄**「該当する事業者が見つかりません（モック応答）」 |
| 8-3 | `T123`（形式不正） | **赤**「登録番号の形式が不正です（T+13桁の数字）」 |

- **確認ポイント（なぜ末尾 0 なのか）**: 国税庁のアプリケーション ID が未設定の環境では**モック応答**が返る。
  モックは「形式が `T+13桁` なら登録あり、**ただし末尾が 0 の番号だけ該当なし**」という約束で、
  **キーが無い環境でも 3 分岐すべてを画面から再現できる**ようにしてある（デモ用の意図的な設計）。
- **確認ポイント（3 色の意味）**: 該当なしは**警告（黄）**であってエラーではない。番号の打ち間違い・登録取消の可能性を知らせるだけで、
  取引先の保存を止めない。止めるのは形式不正（赤）だけ。
- **確認ポイント（なぜサーバ経由か）**: 実 ID を設定すると同じボタンが国税庁の公表システム Web-API を叩き、実在の事業者名・住所・登録年月日を返す。
  ブラウザ（WASM）から直接叩くと CORS とキー秘匿で詰むので、**サーバ側の API 経由**にしている——CLB 単体では作れない部分だけ C# に逃がした典型例。
- **補足**: 空欄で押すと**黄**「登録番号（T+13桁）を入力してから確認してください」（これだけはサーバへ行かず画面側で止まる）。
  サーバが落ちていれば**赤**「照合サービスに接続できませんでした」。
  税制マスタ全体のツアーは `11_マスタ_組織_権限/04_税制と制度閾値.md` にある。

→ **「登録」を押さずに**サイドバーで取引先一覧に戻る。`C005` を開き直し、登録番号が**元の値のまま**であることを確認する。

## つまずいたときは

- **「未払計上（仕訳生成）」ボタンが無い**: 状態が受領でない／未保存／経理機能フラグが無いユーザー。`soumu_bucho` で、保存済み・受領の請求書を開く。
- **「部門を選択してください（損益科目の仕訳には部門が必要です）」で止まる**: 部門が空のまま未払計上を押した（ADR-0056）。ステップ 1 の表のとおり `開発1部` を入れて「登録」してから押し直す。**既存のデモデータ 5 件は部門が空のまま**（このガードが入る前に作られたもの）なので、それらで試すと同じ所で止まる。
- **案件損益の直課費用が増えない**: 案件を選び忘れている（案件は最後まで任意なので、空でも登録も未払計上も通る）。詳細画面で案件を入れて「登録」→ 未払計上を**取り消して打ち直す**（仕訳生成時の値が焼き込まれるため、後から案件だけ直しても既存の仕訳は変わらない）。
- **締め済みエラーを出したいのに出ない**: 実行日が 2026-07 以降なら 04〜06 月が締め済み。実行時期によっては締め済み月が変わっているので、
  会計業務 > 設定 > 会計年度 で現在 closed の月を確認してから請求日に使う。
- **取消のダイアログに仕訳 No. が出ない**（「対応する仕訳が見つかりません」になる）: ステップ 4 の状態。
  「取り消す」で状態だけ戻し、仕訳帳に孤立した仕訳が無いか確認する。
- **仕訳番号が本書と違う**: 年度内の最終 +1 で採番される。取消で消すと番号が空くので、押した回数だけずれていくのが正常。**金額と貸借が合っていれば問題ない**。
- **複製ボタンを押しても何も起きない**: 未保存の新規画面ではボタンが出ない。一度「登録」してから押す。
- **削除ボタンが赤くない／見当たらない**: 削除・取消系は赤、前進系は既定色という 2 色規約（ADR-0027）。見当たらないのは状態が受領でないため。
- **照合が毎回同じ会社名を返す**: モック応答なので正常。実照合には .NET User Secrets への国税庁アプリケーション ID 設定が必要。
