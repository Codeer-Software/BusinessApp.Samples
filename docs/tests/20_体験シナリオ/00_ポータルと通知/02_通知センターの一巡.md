# 体験シナリオ ポータル-02: 通知センターの一巡（未読バッジ → 開く → 未読に戻す → 既読の一括削除）

> 作成: 2026-08-09 ／ 所要時間: 約15分 ／ 影響: 通知の既読状態が変わる。**最終ステップの「既読の通知を全て削除」は元に戻せない**（実行するアカウントの既読通知が消える。手前で止めてもよい）
> 主役: **kaihatsu2_shinjin**（開発2部 一般 高橋健）と **kaihatsu2_kacho2**（開発2部 第二課長 山口健太）。パスワードはユーザー名と同じ。
> 通知は 2026-08-06 に /Main/Notification（通知センター）へ一本化された。バッジ・既定検索・リンクの権限別解決・一括削除まで、通知基盤（docs/13 §4）の全機能を一巡する。

## 物語

高橋健の経費申請が、課長 山口健太への「承認依頼」通知になり、承認されると高橋への「承認されました」通知になる。
この 2 人の受信箱を舞台に、通知が生まれてから消えるまでの一生を追いかける。

## 前提

| 項目 | 内容 |
|---|---|
| 通知の材料 | 両者に未読通知が 1 件以上あること。無ければ **経費-01 のステップ 1〜2**（申請→承認）を先に実行すると、山口宛「承認依頼」と高橋宛「承認されました」が 1 通ずつ生まれる |
| 見える範囲 | 通知は**自分宛だけ**が見える（DataReadCondition）。他人の通知は URL 直叩きでも読めない |
| 削除の影響 | ステップ 6 は高橋アカウントの既読通知を全削除する。過去の通知を残したい場合はステップ 6 を読むだけにする |

---

## ステップ 1: 未読バッジを確認する（山口健太）

**kaihatsu2_kacho2** でログイン。

- **確認ポイント**: サイドバーの通知リンクが「**通知 (N)**」と未読件数付きで表示されている（未読 0 なら「通知」とだけ出る）。
- ポータル中央の「未読の通知」にも同じ通知が**最新 5 件まで**リスト表示されている（列: 日時／タイトル／内容／「開く」）。6 件以上ある場合は「通知をすべて見る →」から全量を見る。

## ステップ 2: 通知センターを開く

サイドバー「通知」をクリック → **/Main/Notification** の「通知」画面へ。

- **確認ポイント**:
  - 冒頭の説明文: 「あなた宛の通知一覧です。「開く」で対象の画面へ移動できます。既定では未読のみを表示しています（検索条件をクリアすると既読も表示されます）」。
  - 検索条件パネル「検索条件」が開いた状態で、条件は「**既読：**」の 1 つだけ。**既定で未読のみ**に絞られている。
  - 一覧は新しい順・最大 50 件。列は 日時／タイトル／内容／既読（チェック表示）／「開く」／「未読に戻す」。

## ステップ 3: 「開く」でリンク先へ飛ぶ（権限別のフレーム解決）

「承認依頼」の行の「**開く**」を押す。

- **期待結果**: 通知が既読になり、リンク先の経費申請詳細へ遷移する。山口は承認者なので **/ExpenseApprover/ExpenseRequest/{id}** に着地する。
- **確認ポイント（リンクは論理）**: 通知にはフレーム名が焼き込まれておらず、**開いた人のその時点の権限**でフレームが解決される。あとでステップ 5 で高橋（一般）が同種のリンクを開くと /ExpenseStaff 側に着地する——同じ仕組みの別解決を見比べる。soumu_bucho なら /ExpenseAccounting 側になる。
- ブラウザバック等で通知センターに戻ると、既定検索が未読のみのため**今開いた行は一覧から消えている**。

## ステップ 4: 「未読に戻す」と既読の表示

1. 検索条件の「既読：」を**クリアして検索** → 既読も含めた全通知が並ぶ。ステップ 3 で開いた行が「既読 ✓」で見える。
2. その行の「**未読に戻す**」（青いボタン）を押す。

- **期待結果**: トースト「通知を未読に戻しました」。サイドバーのバッジ件数が 1 増える。
- **確認ポイント**: もともと未読の行で「未読に戻す」を押すと、トースト「この通知は未読です」が出るだけで何も起きない（行単位でボタンを出し分けられない CLB 制約をガードで無害化している）。
- 確認が済んだらもう一度「開く」で既読に戻しておく（リンク先へ飛ぶ。リンクの無い通知なら「既読にしました」のトーストのみ）。

## ステップ 5: 申請者側の通知を見る（高橋健）

ログアウト → **kaihatsu2_shinjin** でログイン。

- **確認ポイント**: サイドバー「通知 (N)」。通知センターに「**承認されました** — 経費申請「…」（…円）が最終承認されました」が未読で並ぶ。
- 「開く」→ 高橋は一般社員なので **/ExpenseStaff/ExpenseRequest/{id}** に着地する（ステップ 3 と同じ通知種別・違うフレーム）。

## ステップ 6: 既読の通知を全て削除する（元に戻せない・任意）

高橋のまま通知センターに戻り、右上の「**既読の通知を全て削除**」（赤いボタン）を押す。

- **期待結果**: 確認ダイアログ「**既読の通知 N 件をすべて削除します（元に戻せません）。よろしいですか？**」（ボタン: 「削除する」／「キャンセル」）。「削除する」でトースト「既読の通知 N 件を削除しました」、一覧が再読込される。
- **確認ポイント**:
  - 削除されるのは**自分宛の既読だけ**。未読は残る。他人（山口）の通知には一切影響しない。
  - 既読が 0 件の状態で押すと「既読の通知はありません」のトーストのみ。
  - 検索条件をクリアして検索しても、削除した通知はもう出てこない。

これで「発生 → バッジ → 未読のみの受信箱 → 開いて既読＋権限別リンク解決 → 未読に戻す → 既読の掃除」という通知の一生を一巡できた。

## つまずいたときは

- **バッジの数字が本書と違う**: 未読件数は DB 状態依存（目安）。過去のテストで溜まった通知が混ざっていても、この一巡の確認には影響しない。
- **「開く」で遷移しない**: リンクを持たない通知（タイトルだけのお知らせ）は既読化のみ行い「既読にしました」と出る。正常な挙動。
- **通知が 1 件も無い**: 経費-01 のステップ 1〜2 を実行して作る。承認・却下・再申請が通知の主な発生源（キャンセルでは飛ばない）。
- **経費フレームに「通知」メニューが見当たらない**: 2026-08-06 に廃止済み。通知は Main サイドバーの「通知」（/Main/Notification）に一本化されている。
