# 体験シナリオ ポータル-01: 権限別ポータルツアー（5つの視点でログインし直す）

> 所要時間: 約20分 ／ 影響: なし（閲覧のみ。データは一切変更しない）
> 主役: **kaihatsu2_shinjin**（一般）→ **kaihatsu1_bucho**（承認者・部長）→ **eigyo_ippan**（営業）→ **soumu_bucho**（経理）→ **admin**（システム管理者）。パスワードは全員ユーザー名と同じ。
> 全員が同じ「業務ポータル」に着地するのに、権限フラグによってサイドバーと中央の表示がまったく違う姿になる——8/5 再編（ADR-0043/0045）の核心を一巡で体感する。

## 物語

アルタイルシステムズでは、新人からシステム管理者まで全員がログイン直後に同じ URL＝業務ポータルに着地する。
だが見えているものは人によって違う。5 人分のメガネを順にかけ替えて、「権限 → 表示」のマッピング（正典: docs/13 §3）が実際にどう出るかを見て回る。

## 前提

| 項目 | 内容 |
|---|---|
| 操作 | ログイン → 眺める → ログアウト（サイドバー最下部「**Logout**」）の繰り返し。クリックして遷移した場合も、各フレームのサイドバー先頭「ホーム」でポータルに戻れる |
| 件数表示 | 「▶ …: N 件」「⚠ …」の N は現在の DB 状態に依存する（本書の数値は目安）。**アラート（⚠）と経理の作業キューは 0 件なら行ごと消える**（「対応が要るときだけ見える」）。ただし**「あなたの承認待ち」「進行中のあなたの申請」の 2 行は 0 件でも出る**——自分の担当分は「今やることが無い」ことも情報だから（2026-08-18 実測） |
| 見出しの出没 | 「経理の作業キュー」「アラート」の見出し行も、配下が全部 0 件なら見出しごと消える |

## ステップ 1: 最小権限の一般社員（kaihatsu2_shinjin 高橋健）

**kaihatsu2_shinjin** でログイン。

- **サイドバー（上から）**: 「よろず」（ブランド。直下に小さく「統合業務基盤アプリ」）／「通知」（未読があれば「通知 (N)」）／「経費精算」／「工数管理」／「設定」／「Logout」——**これだけ**。営業業務・会計業務・購買・支払・経営管理・業務マスタ・システム管理は出ない。
- **ポータル中央**: 「こんにちは、開発2部 一般 高橋健 さん」＋今日の日付／「▶ 進行中のあなたの申請: N 件」（**0 件でも出る**。自分の担当分は「今やることが無い」ことも情報だから）／「未読の通知」リスト（最新 5 件・「開く」ボタン付き）／「通知をすべて見る →」。
- **確認ポイント**: 「▶ あなたの承認待ち」は出ない（承認者ではない）。「経理の作業キュー」「アラート」「経営ダッシュボード（当月）」の見出しも一切出ない。
- サイドバー「経費精算」をクリック → **/ExpenseStaff（申請一覧）に着地**する。「ホーム」でポータルへ戻り、ログアウト。

## ステップ 2: 承認者・部長（kaihatsu1_bucho 田中宏）

**kaihatsu1_bucho** でログイン。

- **サイドバー**: ステップ 1 の構成に「**経営管理**」が加わる（承認者は予実対比が見られる）。営業業務・会計業務などは依然出ない。
- **ポータル中央**: 「**▶ あなたの承認待ち: N 件**」が加わる（承認者の証）。加えて条件が揃っていれば「⚠ 資金ショート予測: 今後4ヶ月中 N ヶ月」（承認者にも表示）と「⚠ 予算警告: あなたの部門（開発1部）」（**自部門に警告がある時だけ**）が出る。
- **確認ポイント（変種解決）**: サイドバー「経費精算」をクリック → 高橋健とは違い **/ExpenseApprover（承認待ち一覧）に着地**する。同じラベルでも権限で行き先が変わる（経理 > 承認者 > 一般）。
- **確認ポイント**: 「⚠ 資金ショート予測」が出ている場合にクリックすると、遷移はせずトースト「**資金繰り予測の詳細は経理アクセスを持つユーザーが確認できます**」が出る（詳細画面は経理専用のため）。
- 「経営管理」をクリック → **/ManagementApprover（予実対比）に着地**。サイドバーは「ホーム／予実対比／予算明細」だけの小さな構成。

## ステップ 3: 営業の一般社員（eigyo_ippan 伊藤さくら）

**eigyo_ippan** でログイン。

- **サイドバー**: 通知／経費精算／工数管理／「**営業業務**」／Logout。経営管理は出ない（承認者ではない）。
- **ポータル中央**: 承認待ちは出ない。営業フラグ保有者なので「**⚠ 期限超過の売掛: N 件**」が（該当があれば）出る。
- **確認ポイント**: 「⚠ 期限超過の売掛」をクリック → **/SalesStaff/ReceivableBalance（売掛残高）**へ。経理なら同じ行が /SalesBilling 側へ飛ぶ。
- 「営業業務」をクリック → **/SalesStaff（見積一覧）に着地**。サイドバーに請求書・入金が**無い**ことを確認（それは経理の SalesBilling 側だけ）。

## ステップ 4: 経理（soumu_bucho 山田太郎）— フル表示

**soumu_bucho** でログイン。

- **サイドバー**: 「通知／経費精算／工数管理／営業業務／会計業務／購買・支払／経営管理／業務マスタ」——**システム管理以外の全リンク**が出る。
- **ポータル中央（上から順に）**:
  1. 「▶ あなたの承認待ち: N 件」「▶ 進行中のあなたの申請: N 件」
  2. 「未読の通知」リスト＋「通知をすべて見る →」
  3. 「**経理の作業キュー**」見出し＋「▶ 精算処理待ちの経費」「▶ 未起票の銀行明細」「▶ 下書きのままの伝票」「▶ 定期請求の当月未生成」「▶ SES 請求の当月未生成」（**2 行に分かれている**——合算すると「3 件と言われた画面に 2 件しかない」が起きるので意図的に分けてある・ADR-0060）「▶ **SES の当月工数が未入力**（入力されるまで請求を作れません）」（各 0 件なら行ごと消える）
  4. 「**アラート**」見出し＋「⚠ 支払期限: 超過 X 件 ／ N日以内 Y 件」「⚠ 期限超過の売掛」「⚠ 資金ショート予測」「⚠ 予算警告: N 部門」
  5. 「**経営ダッシュボード（当月）**」見出し＋「現預金 ／ 売掛金 ／ 買掛金」「当月売上高 ／ 当月費用 ／ 当月利益」（**利益がマイナスなら赤字表示**）
- **確認ポイント（変種解決の総仕上げ）**: 「経費精算」→ /ExpenseAccounting（精算処理待ち）、「工数管理」→ /TimesheetAccounting、「営業業務」→ /SalesBilling（請求書）、「経営管理」→ /ManagementFull。すべて経理変種に解決される。
- **確認ポイント**: 「▶ 下書きのままの伝票: N 件」をクリック → /Accounting/JournalEntryBoard（振替伝票一覧）。「⚠ 支払期限」→ /Purchasing/PaymentSchedule（支払予定表）。件数と一覧の中身が矛盾していないかを見る。
- **確認ポイント**: 「⚠ 予算警告: N 部門」をクリック → 予実対比が**現在年度で検索済み**の状態で開く（`?initialize_search=true` の効果）。

## ステップ 5: システム管理者（admin）— 職務分掌の姿

**admin** でログイン。

- **サイドバー**: 「通知」「**システム管理**」「**設定**」「Logout」。業務リンクは 1 本も出ない（admin は経費精算・工数入力フラグも OFF）。
  「設定」（パスワード変更）は**全ログインユーザーに出る**——誰でも自分のパスワードは変えられる必要があるため。
- **ポータル中央**: あいさつ・日付・未読の通知に加えて、最下部に「**ユーザー・組織・承認ルートの管理はこちら →**」の案内リンクが出る。クリック → /MasterAdmin（ユーザー管理）に着地。
- **確認ポイント**: 「進行中のあなたの申請」すら出ない（CanUseExpense=OFF）。admin は業務に一切参加できない——これが職務分掌の設計（ADR-0041/0043）。

これで「同じ着地・同じサイドバー部品・同じポータル部品が、権限フラグ 5 本の組み合わせだけで 5 通りの顔になる」ことを確認できた。

## つまずいたときは

- **「▶」「⚠」の行が本書より少ない**: アラートと経理の作業キューは 0 件なら行ごと消えるのが仕様（自分の承認待ち・申請の 2 行は 0 でも出る）。件数を作りたければ該当ドメインのシナリオ（経費-01 など）を先に実行する。
- **予算警告が部長に出ない**: 非経理の承認者には「自部門に警告がある時だけ」表示される仕様（2026-08-06）。経理でログインすれば全部門分が「N 部門」で見える。
- **サイドバーのリンク構成が本書と違う**: ユーザーの権限フラグが変更されている可能性。admin のユーザー管理でチェックボックスの状態を確認する。
