# 体験シナリオ SES-01: SES 精算の一巡（契約条件 → 工数実績 → 精算プラン → 請求生成 → 入金）

> 作成: 2026-08-09 ／ 所要時間: 約35分 ／ 影響: 2026-08 の工数 2 行を追加＋ SES 請求書 1 件・仕訳 2 本（売上・入金消込）・入金 1 件を生成。既存 SES 案件 2 件を一時無効化する（**後片付けで必ず戻す**）。生成物は後片付け手順ですべて巻き戻せる。
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）→ **kaihatsu2_bucho**（開発2部 部長 加藤正雄・権限確認のみ）→ **kaihatsu2_ippan**（開発2部 一般 松本結衣・現場）→ **soumu_bucho**。パスワードはユーザー名と同じ。
> 参照分岐: 11_E2E の SES-01（幅内）／SES-05（冪等）／SES-06（経理専用）。精算幅の変化形は SES-02 へ。
> SES は「人月ではなく**実績時間**で請求額が動く」商売。工数入力が請求書の金額を直接決める、という一本の線を通しで体験する。

## 物語

開発2部の松本結衣は、ホライゾン商事に常駐して業務システムの保守にあたっている。契約は **月額 600,000 円（税抜）・精算幅 140〜160h・控除 5,000 円/h・超過 4,000 円/h**。
8 月の稼働は 150 時間——ちょうど精算幅の内側だったので、請求は基本料金どおり 600,000 円。この「工数を入れる人」と「請求を起こす人」が別であること、そして**精算条件は経理しか触れない**ことを、実際にアカウントを替えながら確かめる。

| 他の SES 案件 | PRJ-003 金融系SES 山田（800,000・140〜180h）／PRJ-005 保守運用SES 高橋（750,000・140〜180h）。**実績 0 でも下限割れ（控除）で請求額が正になるため、放っておくと一緒に生成される**。ステップ 4 で一時無効化する |

| 会計期間 | 第18期（2026年度）。**2026-08 の月次期間がオープン**であること（締まっていると実行がブロックされる） |
| 採番の目安 | 請求書 = その時点の最終 +1（現在の最終は INV-26-016）。仕訳 = 年度内の最終 +1（現在 No.83）。ずれても金額と貸借が合っていれば正常 |

## ステップ 1: 契約条件を確認する（soumu_bucho・経理）

**soumu_bucho** でログイン → サイドバー「**業務マスタ**」→ フレーム内サイドバー「**案件**」→ **PJ-2026-301** を開く。

- **確認ポイント（種別連動）**: 「**種別**」が `SES` のときだけ、下に SES 契約条件の 3 ブロックが現れる。

| 画面の項目 | 値 |
|---|---|
| 　SES 契約条件（月額・精算幅） → **SES 月額基本料金** | `600,000`（税抜） |
| 精算幅 下限〜上限(h) → **精算下限(h)** / **精算上限(h)** | `140` / `160` |
| 控除／超過単価(円/h) → **控除単価** / **超過単価** | `5,000` / `4,000` |

- **確認ポイント（表示の出し分け）**: 種別を `受託` に変えると 5 項目が**丸ごと消える**。`SES` に戻すと**値はそのまま残っている**（種別を触っても契約条件は失われない設計）。**保存はせずに** SES のまま画面を離れる。
- **設計メモ**: 1 案件 = 1 名分の SES 契約条件。複数要員なら要員ごとに案件を分ける（案件名に要員名を入れる運用）。

## ステップ 2: 部長には契約条件が編集できない（ADR-0046）

ログアウト → **kaihatsu2_bucho**（開発2部 部長 加藤正雄）でログイン。

- **確認ポイント（導線）**: 部長は経理機能を持たないのでサイドバーに「業務マスタ」は**出ない**。案件には サイドバー「**工数管理**」→ フレーム内サイドバー「**案件一覧**」から入る。

PJ-2026-301 を開く。

- **期待結果**: 案件名・取引先・状態・有効などの**基本情報は編集できる**（部長は案件の管理者）。しかし **SES 月額基本料金・精算下限/上限・控除単価・超過単価の 5 項目は読み取り専用**（グレー表示で入力できない）。
- **なぜ**: 精算条件は請求額＝売上に直結する会計項目なので、経理だけが変えられる（ADR-0046）。「案件は現場が管理し、金額は経理が握る」という職務分掌がフィールド単位で効いている。
- **確認ポイント（一般社員）**: kaihatsu2_ippan で同じ画面を開くと**案件全体が閲覧専用**になる（→ 工数-02）。

## ステップ 3: 現場が 8 月の工数を入れる（kaihatsu2_ippan・松本結衣）

ログアウト → **kaihatsu2_ippan** でログイン → サイドバー「**工数管理**」→ 工数入力に着地。

- **確認ポイント**: 検索条件「担当者」に**自分が既定セット**されている。8 月の行はまだ 1 件も無い。

「新規作成」で 2 行登録する（実務では日々入力するが、本シナリオではまとめて 2 行にする）。

| 日付 | 案件 | 時間（分） | メモ |
|---|---|---|---|
| `2026-08-14` | `ホライゾン商事様・業務システム保守SES 松本` | `4,500` | `8月前半 常駐分まとめ` |
| `2026-08-31` | 同上 | `4,500` | `8月後半 常駐分まとめ` |

→ それぞれ「**保存**」。

- **確認ポイント（既定値）**: 担当者 = 自分（**読み取り専用**。一般社員は他人名義で登録できない）、日付 = 今日、時間 = 480 分。日付は 8 月に直す。
- **期待結果**: 合計 **9,000 分 = 150h00m**。精算幅 140〜160h の**内側**に入る値（＝控除も超過も発生しない）。
- **確認ポイント（工数の性格）**: 工数は仕訳を作らないので、月次の締めにブロックされない（→ 工数-01 ステップ 3）。ただし**それを読む SES 精算の側は締めで止まる**。

## ステップ 4: 他の SES 案件を一時隔離する（soumu_bucho）

ログアウト → **soumu_bucho** でログイン → サイドバー「**業務マスタ**」→「**案件**」。

**PRJ-003 金融系SES 山田** と **PRJ-005 保守運用SES 高橋** を開き、「**有効**」チェックを **OFF** にして保存する。

- **なぜ必要か**: SES の一括生成は「対象月 × **有効かつ月額設定済みの全 SES 案件**」に走る。この 2 件は 8 月の実績が 0h のため、**下限割れの控除計算**で PRJ-003 = 800,000 − 140h×5,000 = **100,000 円**、PRJ-005 = 750,000 − 140h×5,000 = **50,000 円** となり、**どちらも「生成予定」として黄色行になってしまう**。本シナリオの結果を読みやすくするため（そして身に覚えのない請求を作らないため）に隔離する。
- **後片付けで必ず有効に戻す**（ステップ 9）。

## ステップ 5: 精算プランを読む（幅内の式）

サイドバー「**営業業務**」→ フレーム内サイドバー「**SES精算・請求**」。対象月は既定で今月（**2026-08**）。

- **期待結果**: 「対象月の生成プラン」に **1 行だけ黄色（生成予定）**。

| 列 | 値 |
|---|---|
| 案件 | ホライゾン商事様・業務システム保守SES 松本 |
| 取引先 | 株式会社ホライゾン商事 |
| 実績時間 | **150h00m** |
| 請求額（税抜） | **600,000** |
| 消費税 | **60,000** |
| 状態 | 生成予定 |
| 内容 | **基本 600,000（精算幅 140〜160h） = 600,000（幅内）** |

- **確認ポイント（式がそのまま残る）**: 「内容」列の式は、このあと**請求書明細の摘要にそのまま転記される**。計算過程が請求書に残るので、客先に「なぜこの金額か」を説明できる。
- **確認ポイント（隔離の効き）**: PRJ-003・PRJ-005 は「**案件が無効化されているため対象外**」。
- **確認ポイント（プレビューは無害）**: 対象月を変えるたびにプランは全行洗い替えされるだけで、請求書も仕訳も作られない。何度見ても安全。

## ステップ 6: 一括生成（SES-01）

「**対象月の請求書・仕訳を一括生成**」を押す。

- **期待結果**: トースト「**SES 請求 1 件を生成しました**」。結果ラベル「2026年8月分: 生成 1件 / 対象外 2件 / 仕訳 No.…」。プランの行は「**生成済み**」に変わり、請求書番号列に番号が入る。
- **請求書**（フレーム内サイドバー「請求書」で確認）:

| 項目 | 値 |
|---|---|
| 件名 | `SES精算 ホライゾン商事様・業務システム保守SES 松本（2026年8月分）` |
| 取引先 | 株式会社ホライゾン商事 |
| **部門** | **全社共通** |
| 発行日 / 支払期限 | **2026-08-31** / **2026-09-30** |
| 状態 | **発行済** |
| 明細 1 行 | 摘要 `基本 600,000（精算幅 140〜160h） = 600,000（幅内）（実績 150h00m）`・数量 1・単位「式」・単価 600,000 |
| 合計 | 税抜 600,000 ／ 消費税 60,000 ／ 税込 660,000 |

- **なぜ部門が「全社共通」か**: 案件にも SES 契約にも部門の持ち主がいないため、部門必須化（ADR-0031）の受け皿として「全社共通」を既定にしている。要員の所属部（開発2部）ではない点に注意——部門別 P/L で SES 売上を見たいときはここが効いてくる。
- **仕訳**（会計業務 > 帳簿 > 仕訳帳、8/31）: 借方 **売掛金 660,000** ／ 貸方 **SES売上高 600,000** ＋ **仮受消費税 60,000**。**全行に案件 PJ-2026-301 が転記される**（部門は転記されない）。SaaS の定期請求が 4020 SaaS売上高だったのに対し、SES は **4010 SES売上高**に立つ。
- **入金予定も自動作成**される（入金一覧に「未確定」・期日 9/30・銀行振込・660,000）。
- **既知の見た目**: 請求書の「発行元」欄が**空表示**になる（選択候補に `ses` が無いだけで、DB には値が入っている）。

## ステップ 7: 冪等（SES-05）

もう一度「**対象月の請求書・仕訳を一括生成**」を押す。

- **期待結果**: トースト（Info）「**生成対象はありませんでした**」。結果ラベル「2026年8月分: 生成 0件 / 対象外 2件」。プランは「生成済み」のまま、請求書も仕訳も増えない。
- **冪等の根拠**: 「案件 × 請求対象月 × 発行元 = ses」の請求書が実在するかどうかで判定している（フラグではなく実データ）。だから**請求書を消せば再生成できる**（→ SES-02）。

フレーム内サイドバー「**入金**」→ 消込状態「未確定」の当該行を「開く」。

- 入金日を `2026-09-30` のまま（または実着金日に修正）→「**入金を確定（消込）**」。
- **期待結果**: トースト「仕訳 No.…: 入金 660,000 円を消し込みました（INV-26-0XX は入金済）」。仕訳（入金日付）借方 **普通預金 660,000** ／ 貸方 **売掛金 660,000**。入金一覧の消込状態が「消込済」になり伝票 No が入る。
- **確認ポイント（総仕上げ）**: 会計業務 > 財務帳票 > 損益計算書 に **SES売上高 600,000** が増えている。経営管理 > 案件損益 > 案件損益 で PJ-2026-301 の売上 600,000 が見える（**人件費配賦を実行すると松本さんの人件費が原価に載り、SES の粗利が出る** → 経営管理-02）。

## 後片付け

**soumu_bucho** で以下を実施する。**1 は必須**（戻し忘れると翌月以降の SES バッチが空振りする）。2〜4 は帳簿を元に戻したい場合。

1. **必須**: 業務マスタ >「案件」で **PRJ-003・PRJ-005 の「有効」を ON に戻す**（ステップ 4）。
2. 任意（入金の巻き戻し）: 営業業務 >「入金」→ 当該行を開いて「**入金を取り消す**」→ 消込仕訳が削除され、入金予定（未確定）に戻る。**消込済みのままだと次の発行取消ができない**。
3. 任意（請求と売上の巻き戻し）: 「請求書」→ 当該請求書を開いて「**発行を取り消す**」→ 請求書・売上仕訳・未確定の入金予定がまとめて削除され、SES 精算は「未生成」に戻る（同じ月をもう一度やり直せる）。
4. 任意（工数の削除）: kaihatsu2_ippan（または経理の「工数管理（経理）」）でステップ 3 の 2 行を削除する。工数は仕訳を持たないので、削除しても帳簿には影響しない。

## つまずいたときは

- **プランに「対象の案件が出ない」**: ①案件の「有効」が OFF ②「SES 月額基本料金」が空か 0（「SES 契約条件（月額精算額）が未設定のため対象外」）③種別が SES でない——のいずれか。
- **実績時間が 0h00m になる**: 工数の**日付が対象月に入っていない**か、案件の選択違い。時間は**分**で入力する（480 = 8 時間）。
- **プランが古いまま**: プランが作り直されるのは「画面を開いたとき」と「対象月を変えたとき」だけ。工数を直したら対象月を選び直す。なお「一括生成」は押した瞬間に必ず作り直すので、**実行結果は常に最新データが正**。
- **「対象月の期間は締め済みです」**: 会計業務 > 設定 > 会計年度 で 2026-08 をオープンにする。工数入力は締めに縛られないのに SES 精算は止まる、という非対称を覚えておく。
- **請求額が想定と違う**: 実績時間が精算幅の外に出ている（控除・超過）。式は「内容」列にそのまま出るので読む（→ SES-02）。
- **仕訳番号・請求書番号が本書と違う**: 番号は最終 +1。他の操作を挟めばずれる。金額と貸借が合っていれば正常。
