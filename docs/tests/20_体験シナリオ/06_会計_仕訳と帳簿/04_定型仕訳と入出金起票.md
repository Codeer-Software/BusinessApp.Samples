# 体験シナリオ 会計-04: 定型仕訳と入出金起票（毎月の決まり仕事を速く回す）

> 所要時間: 約30分 ／ 影響: 確定伝票 **1 本**（家賃）＋ 入出金起票 **4 本**（2 本は相殺用）。マスタは T03 の「一覧に表示する」を一時的に触って戻す
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。パスワードはユーザー名と同じ。
> 毎月同じ形で切る仕訳を「定型」から起こし、現預金の出入りを「入出金起票」で片付ける。**振替伝票を開かずに済ませる 2 つの近道**を味わう回。
> 参照分岐: CSH-01（入力ガード）／CSH-02（締め済みはスキップ）／CSH-03（出金方向と税行）／CSH-04（連続入力）／CSH-06（未保存）／CSH-07（明細なし）／CSH-08（定型から下書き）／CSH-09（起票後の金額修正 → 確定）

## 物語

月初、山田太郎の机には毎月まったく同じ形の仕訳が 3 つ並ぶ——事務所家賃・給与・社会保険料。
金額だけが少し違う。今月は家賃が改定で 165,000 円から **176,000 円**に上がった。
定型仕訳から下書きを起こし、金額だけ直して確定する。ついでに、小口の入出金を「入出金起票」で片付ける。

## 前提

| 項目 | 内容 |
|---|---|
| 会計期間 | 第18期（2026年度）。当月（2026-08）がオープン・**2026-06 は締め済み**であること（設定 > 会計年度 で確認できる） |
| 定型仕訳 | seed の 3 種（T01 事務所家賃の支払 ／ T02 給与の支払 ／ T03 社会保険料の納付）がある |
| 現預金科目 | 現金(1000) / 小口現金(1010) / 普通預金(1020)。自社口座は MB01 メインバンク 普通預金 の 1 件 |
| 仕訳番号 | 相対表記。**No.(+1)** = その時点の最終番号 +1。入出金起票は「まとめて起票する」を押した瞬間に、**下書き 1 行ごとに**採番される |
| 影響 | 家賃 176,000 の確定伝票 1 本（後片付けは赤伝）＋ 入出金 4 本（うち 2 本は相殺用で正味 0）。**下書きは起票すると消える**ので画面には残らない |

## ステップ 1: 定型仕訳 3 種の中身を読む

**soumu_bucho** でログイン → サイドバー「**会計業務**」→ 仕訳/**定型仕訳**。

一覧の列は コード / 定型名 / メモ / **表示** の 4 つ。上に検索条件（定型名・表示）があり、**既定は「表示」＝○ で絞られている**（ADR-0054）。3 行を順に開いて中身を見る。

| コード | 定型名 | 明細 | メモ |
|---|---|---|---|
| **T01** | 事務所家賃の支払 | 借方 `地代家賃` 165,000（課税仕入 10%・**内税**）／ 貸方 `普通預金` 165,000（税入力なし） | 毎月末の口座振替。金額固定 |
| **T02** | 給与の支払 | 借方 `給料手当` 3,000,000（不課税・なし）／ 貸方 `預り金` 450,000 ／ 貸方 `普通預金` 2,550,000 | 毎月25日。金額は給与計算の結果で修正する |
| **T03** | 社会保険料の納付 | 借方 `法定福利費` 280,000（不課税・なし）／ 借方 `預り金` 140,000 ／ 貸方 `普通預金` 420,000 | 毎月末の口座振替。会社負担分＋従業員預り分 |

- **確認ポイント（金額列の名前）**: 明細の金額欄は「**金額（税込）**」。定型は**税込の入力額**を持ち、税の分解は伝票を**確定**したときに初めて行われる。だから税率が改正されても定型を作り直す必要がない。
- **確認ポイント（日付は持てない）**: 定型に日付項目は無い。起票すると**常に本日**の伝票になる。「毎月25日」のような情報はメモ欄に書いておく運用（自動実行のスケジューラは無い）。
- **確認ポイント（3 行以上も持てる）**: T02・T03 のように貸借が 1 対多／多対 1 の仕訳も定型にできる。
- **確認ポイント（「税計算」は必須・2026-08-19・BUG-0441）**: 明細の「**税計算**」欄は必須で、空のままでは保存できない。
  **空の定型を作れてしまうと、そこから起票した伝票に消費税行が 1 本も立たない**——
  税区分が「課税仕入 10%」でも税額 0 円で確定し、貸借は合うので警告も出ず、
  消費税集計表に「本体 110,000・税額 0」と並ぶだけになる。プリセットの T01〜T03 は値が入っているので、
  **自分で定型を 1 つ作った瞬間に踏む**型だった。

## ステップ 2: T01 から伝票を起こす（CSH-08 と同じ経路）

**T01 事務所家賃の支払** を開いた状態で、「**この定型から伝票を起票**」（青ボタン）を押す。

- **期待結果**: トースト「**下書き伝票を作成しました。金額を確認して確定してください**」。そのまま**振替伝票の下書き画面へ自動遷移**する。
- **確認ポイント（できた下書きの姿）**:
  - 取引日 = **本日** ／ 伝票種別 = 振替 ／ 状態 = **下書き** ／ **伝票番号は空**
  - 摘要 = **定型名がそのまま**（`事務所家賃の支払`）
  - 明細 2 行が定型どおりコピーされ、**税行はまだ無い**（借方 地代家賃 165,000 ／ 貸方 普通預金 165,000）
- **確認ポイント（導線は一方通行）**: 振替伝票の側から「定型を選ぶ」ボタンは**無い**。定型 → 伝票の一方向だけ（迷子になりにくい代わりに、伝票を書き始めてから定型を思い出しても呼べない）。

## ステップ 3: 金額を当月の実額に直して確定する（CSH-09）

家賃が改定されたので、**2 行とも `176,000`** に直す。

→ 「**確定**」を押す。

- **期待結果**: トースト「**伝票 No.(+1) を確定しました**」。明細が 3 行になる:
  借方 **地代家賃 160,000** ／ 借方 **仮払消費税 16,000**（摘要「消費税（行1）」）／ 貸方 **普通預金 176,000**。
  176,000 × 10/110 = 16,000（ちょうど割り切れる）。
- **確認ポイント（定型は無傷）**: 定型仕訳に戻ると **T01 の金額は 165,000 のまま**。定型はコピー元であって、起票しても書き換わらない。恒久的に変わったのなら定型側も 176,000 に直して「登録」する（ここでは直さない）。
- **確認ポイント（起票後の修正が確定仕訳に乗る・CSH-09）**: 下書きは**全項目が編集可能**——金額だけでなく**取引日・摘要・明細の科目**も直せる。直した値がそのまま確定仕訳になる（定型の 165,000 ではなく、打ち直した **176,000** で税が分解されている）。給与のように毎月金額が変わる定型は、この「起票 → 実額に直す → 確定」が通常運転。
- **確認ポイント（下書きを経由する意味）**: 定型からの起票は必ず**下書き**で止まる。金額を確認しないまま帳簿に載ることがない、という安全設計（締めチェックも確定時に初めて走る）。

## ステップ 4: 定型のガードを 2 つ叩く（CSH-06・CSH-07）

1. 定型仕訳 > 「**新規作成**」→ 定型名に `テスト定型` とだけ入れ、**保存せずに**「この定型から伝票を起票」。
   - **期待結果**: トースト「**定型を保存してから起票してください**」。
2. 定型コードに `T99`・定型名 `テスト定型` を入れ、**明細 0 行のまま**「**登録**」→ 保存できたら、そのまま「この定型から伝票を起票」。
   - **期待結果**: トースト「**明細がありません。明細を登録してから起票してください**」。
   - **確認ポイント（見た目ではなく DB を見ている）**: 明細の判定は**画面の行ではなく保存済みの明細**で行われる。試しに明細を 1 行だけ画面上で足して（保存せずに）もう一度起票すると、**やはり同じエラー**が出る——「登録」してから起票する、が正しい順番。

## ステップ 5: 定型を一覧から隠す（隠しても起票はできる）

**T03 社会保険料の納付** を開き、「**一覧に表示する**」のチェックを**外す**。

- **期待結果（その場で出る）**: タイトルのすぐ下に灰色の案内「**この定型は一覧に表示されない設定です（この画面からの起票はできます）。**」が現れる。チェックを戻すと消える。
- 外したまま「**登録**」→ トースト「更新しました」。

サイドバーの 仕訳/**定型仕訳** をもう一度クリックして一覧に戻る。

- **期待結果**: 件数が **(1-2 /2件)** になり、**T03 が消えている**。
- 検索条件の「**クリア**」→「**検索**」で **(1-3 /3件)** に戻り、T03 の表示列は「**—**」。「表示」は 空／○／— の 3 択なので、「—」を選べば非表示のものだけを拾える。

そのまま T03 を開き直して（一覧の T03 行、または URL 直打ち）「**この定型から伝票を起票**」。

- **期待結果**: **起票できる**。トースト「下書き伝票を作成しました。金額を確認して確定してください」→ 下書き伝票へ遷移する。
- **確認ポイント（これは穴ではなく仕様）**: このフラグは「一覧に出すかどうか」だけを表す（ADR-0054）。使えなくするフラグではないので、隠した定型でも直接開けば起票できる——廃止した契約の取消仕訳を当時の定型で起こす、といった例外が救える。**もう使わせたくない定型は削除する**、が正しい運用。
- できた下書きは**確定せず**、詳細の「**この下書き伝票を削除**」（赤）→ 確認ダイアログ「この下書き伝票を削除しますか？（元に戻せません）」→ 「**削除する**」で消す。
- T03 の「**一覧に表示する」を元どおりチェックして「登録」**（後片付け）。

## ステップ 6: 入出金起票の姿を見る（下書き方式）

サイドバー 仕訳/**入出金起票**。

説明文「現預金の入出金を下書きに積み、まとめて仕訳にします。金額は実際に動いた額（税込）を入れてください。相手科目が課税区分なら消費税を自動で分けます。下書きは入力者ごとに分かれていて、起票するまで何度でも直せます。複数行にわたる仕訳は振替伝票から。」

画面は上から **入力欄 → 現預金の残高 → 未起票の下書き → ボタン 3 つ** の 4 段（ADR-0055）。

- **確認ポイント（入力欄は「次に足す行の初期値」）**: 取引日・現預金科目・入出金・相手科目・**部門**・金額・摘要。
  押すボタンは「**明細に追加**」で、**この時点では仕訳は作られない**。銀行明細取込と同じ考え方（起票はあとでまとめて）。
- **確認ポイント（既定値）**: 取引日 = **本日**／入出金 = **入金**。現預金科目と取引日は、**自分の直近の下書き**があればそれを引き継ぐ
  （毎回同じ口座を選び直さずに済む。下書きが無ければ空）。
- **確認ポイント（現預金科目の候補）**: 現金・小口現金・普通預金・**定期預金**の 4 つ。これは勘定科目マスタの
  「**現預金科目**」チェックで決まる（業務マスタ > 会計マスタ > 勘定科目 で見られる）。口座科目を増やしたら
  このチェックを入れるだけでこの画面に出る——以前は画面側に 3 科目が直書きされていて、増やしても出なかった。
- **確認ポイント（相手科目の候補）**: **全勘定科目**が並ぶ（現預金科目も含む）。小口現金の補充のように
  **現預金どうしの振替**が実務で要るため。ただし現預金科目と相手科目が**同じ**ものは弾かれる（ステップ 9）。
- **確認ポイント（残高が 2 段で出る）**: 「帳簿残高」「未起票の増減」「起票後の見込み」の 3 列。
  **帳簿残高は「今日まで」の確定仕訳で作る**（BUG-0414）——先日付の支払仕訳を引いた額を出すと、
  実際より少ない残高で起票の判断をさせてしまうため。ポータルの経営ダッシュボード「現預金」・
  資金繰り予測の「期首資金」も同じ定義なので、3 画面の合計は必ず一致する。
  帳簿残高には**基準時刻**が添えてある（「2026/08/14 02:45 現在」）——他の人が同時に起票すれば変わるので、
  常に正しい今の残高は原理的に作れない。**小口現金の実査で見るのは「起票後の見込み」**（今日の分を記帳し終えた額）。

## ステップ 7: 下書きに 2 本積む

1 本目（茶菓の支払い）:

| 項目 | 入力値 |
|---|---|
| 取引日 | 本日（既定） |
| 現預金科目 | `小口現金` |
| 入出金 | **`出金`** |
| 相手科目 | `会議費` |
| 部門 | `開発1部` |
| 金額 | `1,100` |
| 摘要 | `打合せ用の茶菓（入出金起票の練習）` |

→ 「**明細に追加**」。

- **期待結果**: トースト「**下書きに追加しました**」。下の表に 1 行増える。
- **確認ポイント（連続入力）**: **金額と摘要だけがクリア**され、取引日・現預金科目・入出金・相手科目・部門は残る。
  カーソルは金額欄に戻る——同じ相手の入出金を続けて打つための設計。別の取引に移るときは相手科目の消し忘れに注意。
- **確認ポイント（残高が動く）**: 小口現金の「未起票の増減」が **−1,100**、「起票後の見込み」が **98,900**（帳簿残高 100,000 のとき）。
  **帳簿残高はまだ動かない**——仕訳になっていないから。

2 本目（預金利息）: 現預金科目 `普通預金`／入出金 `入金`／相手科目 `受取利息`／部門 `全社共通`／金額 `100`／摘要 `普通預金の利息（入出金起票の練習）` → 「明細に追加」。

- **確認ポイント（見出し）**: 表の上に「**未起票の下書き 2 件（入金 100 円 ／ 出金 1,100 円）**」。
- **確認ポイント（受取利息にも部門が要る）**: 受取利息は**収益**なので損益科目＝部門必須。
  特定の部門に紐づかないので「**全社共通**」を選ぶ（ADR-0056。共通費・共通収益の受け皿）。

## ステップ 8: 表の中で直す・消す

**直す**: 1 行目の金額を `1,100` → `3,300` に書き換える（表のセルがそのまま入力欄）。→ 「**変更を保存**」。

- **期待結果**: トースト「**変更を保存しました**」。残高の「未起票の増減」が −3,300 に変わる。
- **確認ポイント（ここが下書き方式の主眼）**: 起票する前なら**何度でも直せる**。確定してから気づくと赤伝が要る——
  その手間が丸ごと消える。

**消す**: 行の右端のゴミ箱を押す → 表から消える → **ここで一度画面を再読込してみる**。

- **期待結果**: **消したはずの行が復活する**。ゴミ箱は画面の上の操作でしかない。
- もう一度ゴミ箱を押し、今度は「**変更を保存**」→ トースト「**変更を保存しました（1 行を削除）**」。再読込しても消えたまま。
- **確認ポイント（仕様の癖）**: 「消す」も「直す」も**保存して初めて確定**する。迷ったら保存を押す、が正しい運用。

（このシナリオでは 2 行とも残しておく。消した行は同じ内容で入れ直す。）

## ステップ 9: 入力のガードを 4 つ叩く

**エラーが出ても下書きは 1 行も増えない**（仕訳はそもそも作られない）。

| # | やること | 出るトースト |
|---|---|---|
| 1 | 金額を空のまま「明細に追加」 | **金額を入力してください** |
| 2 | 相手科目を未選択にする | **相手科目を選択してください** |
| 3 | 現預金科目 `普通預金`・相手科目も `普通預金` にする | **相手科目に同じ現預金科目は選べません** |
| 4 | 相手科目 `会議費`・部門を空にする | **部門を選択してください（損益科目の仕訳には部門が必要です）** |

- **確認ポイント（3 の意味）**: 現預金どうしの振替は**別の科目なら作れる**（普通預金 → 小口現金＝小口現金の補充）。
  弾かれるのは同じ科目どうし＝増減が相殺する無意味な仕訳だけ。
- **確認ポイント（4 の意味）**: 部門が要るのは**損益科目**（費用・収益）の取引だけ。
  相手科目を `普通預金` のような BS 科目にすると部門なしでも通る——現預金の行に部門は要らない（ADR-0056）。
- **確認ポイント**: 4 つとも**トースト**で出る（振替伝票の日付ガードが「フィールドエラー」だったのと表示形式が違う）。
  この画面は表示専用モジュールなので、項目の下に赤字が出る仕組みを持っていない。

## ステップ 10: まとめて起票する（採番はここで起きる）

下書きが 2 件ある状態で「**まとめて起票する**」。

- **期待結果**: 結果ラベル「**起票 2 件（No.(+1)〜(+2)） ／ うち消費税 100 円 ／ スキップ 0 件 ／ 失敗 0 件**」＋
  トースト「2 件を起票しました（No.(+1)〜(+2)）」。**下書きは 0 件になり**、残高の「帳簿残高」が動いて
  「未起票の増減」が 0 に戻る。
- **確認ポイント（下書き 1 行 = 仕訳 1 本）**: 2 件まとめて押しても、**伝票は 2 本**できる（1 本にまとまらない）。
  日付も相手科目も違うものを 1 伝票にする理由がないため。番号は押した瞬間に**行ごとに**振られる。
- **仕訳の中身**（帳簿/**仕訳帳**）:

| 伝票 | 明細 |
|---|---|
| 茶菓 3,300 | 借方 **会議費 3,000**（開発1部）／ 借方 **仮払消費税 300**（開発1部・摘要「消費税（行1）」）／ 貸方 **小口現金 3,300**（全社共通） |
| 利息 100 | 借方 **普通預金 100**（全社共通）／ 貸方 **受取利息 100**（全社共通） |

- **確認ポイント（税は自動で分かれる）**: 会議費は課税仕入 10% なので、3,300 を**内税**として 300 に分ける（ADR-0053）。
  受取利息は非課税売上なので税行は付かない。
- **確認ポイント（部門の付き方）**: 指定した部門が付くのは**損益科目の行**。現預金の行には「全社共通」が入り、
  **税行は親行（会議費）の部門を継ぐ**（ADR-0056）。
- **確認ポイント（出納帳では諸口）**: 帳簿/**出納帳** で `小口現金` を見ると、茶菓の行の相手科目は「**諸口**」——
  税行が付いて 3 行仕訳になったため。利息のような 2 行仕訳なら相手科目名が出る。
- **確認ポイント（締め済みはスキップ）**: 取引日を締め済み月（`2026-06-15`）にした下書きを混ぜて起票すると、
  その行だけ起票されず「**スキップ n 件 ［期間が締め済み］**」と出る。**他の行は起票される**——
  1 行の不備で全部が止まらないのが一括起票の設計（銀行明細の一括起票と同じ）。

## つまずいたときは

- **「この定型から伝票を起票」が見当たらない**: 定型を**開いた詳細画面**にあるボタン。一覧には無い。
- **起票したのに伝票が見つからない**: 定型からの起票は**下書き**なので、振替伝票一覧の検索で 状態「下書き」に絞ると早い。ポータルの「▶ 下書きのままの伝票: N 件」からクリックすると、**状態＝下書きで絞り込まれた状態で着地する**（2026-08-19・BUG-0440。それまでは全伝票が混ざって並んでいた）。
- **定型から起こした下書きの取引日が今日になっている**: 仕様（定型は日付を持たない）。月末付で起こしたいなら下書きの取引日を手で直してから確定する。締めチェックは確定時に走るので、締め済み月に直すと「取引日の期間は締め済みです」で止まる。
- **入出金起票のボタンが効かない／権限エラー**: 「入出金の起票は経理のみ実行できます」が出るのは経理フラグの無いユーザー。そもそも会計業務フレーム自体が経理ゲートなので、通常この文言は見えない（見えたらゲートの退行を疑う）。
- **他の人が入れた下書きが見えない**: 仕様。下書きは「打ちかけているメモ」なので**入力者ごとに分かれている**（他人の打ちかけを勝手に起票しないため）。全社の未起票件数はポータルの経理の作業キューで見える。
- **起票してしまった仕訳を消したい**: **削除できない**（確定済み）。逆方向の入出金を同額で下書きに積んで起票し、相殺する（下記「後片付け」）。**起票する前なら表の中で直せる**ので、まず下書きの段階で確かめる習慣にしたい。
- **費用の金額が打った額と違う**: 相手科目が課税科目なら**入力額は税込**として本体と消費税に分けられる（1,100 → 会議費 1,000 ＋ 仮払消費税 100）。結果ラベルの「うち消費税 n 円」で確認できる。税抜額を打つと本体がさらに小さくなるので、**必ず実際に動いた額**を入れる。
- **消費税集計表に入出金の分が載っている**: 仕様。課税科目なら本体・税額とも正しく載り、非課税・不課税の科目でも**相手科目の既定税区分が行に刻まれる**ため本体金額の列には載る（受取利息 → 非課税売上）。以前は税込額が本体として載る誤りがあったが ADR-0053 で解消済み。
