# 体験シナリオ 会計-05: 仕訳インポート（CSV 貼り付けで一括取込・スキップ理由を読む）

> 作成: 2026-08-09 ／ 所要時間: 約30分 ／ 影響: 下書き伝票 4 本（**すべて後片付けで削除**）＋ ステップ 8 を実行した場合のみ確定伝票 1 本
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。パスワードはユーザー名と同じ。
> 他社ソフトからの移行・給与ソフトの仕訳取込を想定した画面。**表記ゆれをどこまで飲むか**と、**ダメなときに何を教えてくれるか**を体で覚える回。
> 参照分岐: IMP-01（解析不能行）／IMP-02（表記ゆれ）／IMP-03（スキップ理由の網羅）／IMP-04（締め済み・年度なし）／IMP-05（税行の自動マーク）／IMP-06（下書き取込）／IMP-07（確定取込の再採番）

## 物語

山田太郎の会社は、来期から給与計算を外部サービスに切り替える。
毎月そのサービスから出てくる仕訳 CSV を、手打ちせずに取り込めるかを確かめておきたい。
ついでに「壊れた CSV を投げたらどうなるか」も試す。エラーで黙って半分だけ入る、というのが移行で一番怖いからだ。

## 前提

| 項目 | 内容 |
|---|---|
| 会計期間 | 第18期（2026年度）。**2026-08 がオープン・2026-06 が締め済み**であること |
| CSV 形式 | `グループ,日付,借貸,科目コード,金額,税区分コード,摘要`（税区分・摘要は省略可。1 行 = 1 明細行、同じグループ名の行が 1 伝票になる） |
| 使う科目コード | 6130 通信費 ／ 6140 消耗品費 ／ 6220 水道光熱費 ／ 1000 現金 ／ 1010 小口現金 ／ 1020 普通預金 ／ 1900 仮払消費税 |
| 使う税区分コード | `PUR_10`（課税仕入 10%） |
| 影響 | 基本は**下書きだけ**なので後片付けで完全に消せる。ステップ 8（確定）だけが例外で、消すには赤伝が要る |

## ステップ 1: 画面を読む

**soumu_bucho** でログイン → サイドバー「**会計業務**」→ 仕訳/**仕訳インポート**。

画面はごく単純で、上から 説明文 → 「仕訳CSV貼り付け」テキストエリア → チェックボックス「**下書きとして取り込む（確定せず伝票番号も振らない）**」→ ボタン「**取り込む**」→ 結果ラベル。

説明文にこの画面の思想がそのまま書いてある:

> 他の会計ソフトや給与ソフトから出力した仕訳を CSV 貼り付けで一括取込します。行は**無加工で取り込まれ（金額の再計算なし）**、**伝票単位で**貸借一致・科目実在・締め状況を検証して、問題のある伝票は**理由付きでスキップ**されます。

- **確認ポイント**: 検証の単位が「行」ではなく「**伝票（グループ）**」であること。1 行でも欠陥があれば、その伝票は**まるごと**取り込まれない（部分取込で貸借が壊れた伝票が生まれないため）。
- 空のまま「取り込む」を押すと トースト「**仕訳CSVを貼り付けてください**」。

## ステップ 2: まず正常な 2 伝票を取り込む（IMP-06）

「**下書きとして取り込む**」を **ON** にして、次を貼り付け → 「**取り込む**」。

```
S001,2026/08/03,D,6130,8800,PUR_10,携帯電話料金 8月
S001,2026/08/03,C,1020,8800,,携帯電話料金 8月
S002,2026/08/05,D,6140,3300,PUR_10,コピー用紙
S002,2026/08/05,C,1000,3300,,コピー用紙
```

- **期待結果**: トースト「2 伝票（4 行）を取り込みました（下書き）」。結果ラベル:
  `取込 2 伝票（4 行）（下書き） / スキップ 0 伝票 / 保存失敗 0 / 解析不能行 0 行`
- **確認ポイント**: 仕訳/振替伝票 の一覧に 2 行増えている。状態は「**下書き**」、**伝票No は空**（採番は確定時だけ＝欠番を作らない設計）。摘要は**そのグループの先頭行の摘要**がヘッダに使われる。
- ポータル（サイドバー「ホーム」）に戻ると 経理の作業キューの「**▶ 下書きのままの伝票: N 件**」が 2 増えている。

## ステップ 3: 表記ゆれを全部投げてみる（IMP-01・IMP-02）

「下書きとして取り込む」は **ON** のまま、**わざとヘッダ行を付けて**次を貼り付け → 「取り込む」。

```
伝票グループ,日付,借貸,科目コード,金額,税区分コード,摘要
S003,2026-08-06,借方,6140,"1,500",,表記ゆれ1
S003,2026.8.6,貸,1000,¥500,,表記ゆれ2
S003,2026年8月6日,C,1010,1000円,,表記ゆれ3
```

- **期待結果**: `取込 1 伝票（3 行）（下書き） / スキップ 0 伝票 / 保存失敗 0 / **解析不能行 1 行**`
- **確認ポイント（受理された揺れ）**: 3 行はすべて **2026/8/6 の同じ伝票**として解釈される。

| 種類 | 受理される書き方 |
|---|---|
| 借貸 | `D` `C` ／ `借` `貸` ／ `借方` `貸方`（大小文字・前後の空白は無視） |
| 日付 | `2026-08-06` ／ `2026.8.6` ／ `2026年8月6日` ／ `2026/8/6`（ゼロ埋めの有無も自由。`2026/2/30` のような**存在しない日付は不可**） |
| 金額 | `"1,500"`（引用符＋カンマ）／ `¥500` ／ `1000円` ／ `1500` |

- **確認ポイント（ヘッダ行）**: 1 行目のヘッダは「日付も金額も読めない行」として**黙って捨てられ**、`解析不能行 1 行` として数だけ報告される。**エラーにはならない**ので、他社ソフトの出力をヘッダごと貼ってよい。
- 伝票を開くと 借方 消耗品費 1,500 ／ 貸方 現金 500 ／ 貸方 小口現金 1,000 の 3 行（1,500 = 500 + 1,000 で貸借一致）。

## ステップ 4: スキップ理由ツアー（IMP-03）

NG な伝票を 6 つ束ねて 1 回で投げる。**下書き ON / OFF どちらでも結果は同じ**（全部スキップされるため）。

```
G101,2026/08/07,D,9999,1000,,科目コード不存在
G101,2026/08/07,C,1000,1000,,科目コード不存在
G102,2026/08/07,D,6140,1000,ZZZ,税区分コード不存在
G102,2026/08/07,C,1000,1000,,税区分コード不存在
G103,2026/08/07,X,6140,1000,,借貸が不正
G103,2026/08/07,C,1000,1000,,借貸が不正
G104,2026/08/07,D,6140,1000,,日付不一致
G104,2026/08/08,C,1000,1000,,日付不一致
G105,2026/08/07,D,6140,0,,金額ゼロ
G105,2026/08/07,C,1000,0,,金額ゼロ
G106,2026/08/07,D,6140,5000,,貸借不一致
G106,2026/08/07,C,1000,4000,,貸借不一致
```

- **期待結果**: 警告トースト「**取り込めた伝票がありません。スキップ理由を確認してください**」。結果ラベル:
  `取込 0 伝票（0 行） / スキップ 6 伝票 [G101: 科目コード 9999 が存在しません] [G102: 税区分コード ZZZ が存在しません] [G103: 借貸が不正です（X）] **ほか** / 保存失敗 0 / 解析不能行 0 行`
- **確認ポイント（先頭 3 件＋「ほか」）**: 理由は**最初の 3 グループ分しか出ない**。残りは「ほか」で丸められる。大量に流し込むときは、**通ったものだけ本番に載せて、落ちたものを分割して投げ直す**運用になる。
- **確認ポイント（オールオアナッシング）**: G101 の 2 行目（科目 1000 = 正しい行）も**伝票ごと**落ちている。片肺の伝票が帳簿に載らない。

残り 3 件の理由を読むために、**G104・G105・G106 の 6 行だけ**を貼り直して「取り込む」。

- **期待結果**: `取込 0 伝票（0 行） / スキップ 3 伝票 [G104: 同一伝票内で日付が一致しません] [G105: 金額は 1 円以上で入力してください] [G106: 貸借不一致（借方 5,000 / 貸方 4,000）] / 保存失敗 0 / 解析不能行 0 行`
- **確認ポイント（貸借不一致は数字を教えてくれる）**: `（借方 5,000 / 貸方 4,000）`——どちらがいくら足りないかが読める。移行時に一番よく踏むエラーなので、ここだけ理由に金額が入る。
- **確認ポイント（金額 0 は「解析不能」ではない）**: G105 は日付が読めているので**行としては読まれ**、そのうえで金額検証に落ちている（ヘッダ行の扱いとの違い）。マイナス金額も同じく「1 円以上」で弾かれる。
- **確認ポイント（日付は伝票の先頭行が正）**: G104 は 1 行目の 08/07 が伝票の日付と決まり、2 行目の 08/08 が食い違いと判定される。

## ステップ 5: 締め済み・年度なしは下書き取込でも免除されない（IMP-04）

「**下書きとして取り込む」を ON にした状態で**次を投げる（下書きなら通るのでは？ を確かめる）。

```
G201,2026/06/15,D,6140,1000,,締め済み月
G201,2026/06/15,C,1000,1000,,締め済み月
G202,2024/06/15,D,6140,1000,,年度なし
G202,2024/06/15,C,1000,1000,,年度なし
```

- **期待結果**: `取込 0 伝票（0 行） / スキップ 2 伝票 [G201: **2026/6/15 の期間は締め済みです**] [G202: **2024/6/15 に対応する会計年度がありません**] / 保存失敗 0 / 解析不能行 0 行`
- **確認ポイント（統制の一貫性）**: 締め済みガードは **振替伝票・入出金起票・インポートの 3 経路すべて**に入っている。「取込なら締めを回避できる」という抜け道は無い。**下書き取込でも免除されない**のがポイント（下書きは番号を振らないだけで、期間の判定は同じ）。
- **確認ポイント（日付の表示形式）**: 理由文の日付は正規化後の `2026/6/15`（ゼロ埋めなし）。貼った文字列そのままではない。

## ステップ 6: 下書き取込の性質を確かめる（IMP-06）

ステップ 2・3 で作った下書き（S001・S002・S003）を眺める。

| 見るところ | 期待 |
|---|---|
| 振替伝票 一覧（検索 状態 = 下書き） | 3 件。**伝票No 列が空** |
| 伝票の詳細 | 「下書き保存」「確定」に加えて、**赤い「この下書き伝票を削除」**が出る（確定済みには出ない） |
| 帳簿/仕訳帳 | **出てこない**（帳簿は確定済みのみ） |
| ポータル > 経理の作業キュー | 「▶ 下書きのままの伝票」に数えられている |

- **確認ポイント（移行の作法）**: 「下書きで取り込む → 一覧で件数と金額を確かめる → 問題なければ確定、ダメなら削除してやり直す」が、**やり直しの効く**唯一の順路。確定取込（下書き OFF）は伝票番号まで振ってしまい、**取り消すには赤伝が要る**。

## ステップ 7: 税科目行（1900 / 2200）は自動で税行になる（IMP-05）

移行元がすでに税抜経理で、消費税を別行に切り出している CSV を想定する。「下書きとして取り込む」を **ON** のまま:

```
S004,2026/08/07,D,6220,13637,PUR_10,電気代 7月分
S004,2026/08/07,D,1900,1363,PUR_10,電気代 7月分 消費税
S004,2026/08/07,C,1020,15000,,電気代 7月分
```

- **期待結果**: `取込 1 伝票（3 行）（下書き） / スキップ 0 伝票 / 保存失敗 0 / 解析不能行 0 行`
- **確認ポイント（自動マーク）**: 科目コードが **1900（仮払消費税）または 2200（仮受消費税）**の行は、取込時に自動で「**税行**」の印が付く。これをやらないと消費税集計表の**本体金額**に 1,363 円が混入してしまう（本体と税の二重計上）。
- **確認ポイント（税区分コードは税行にも付ける）**: 消費税集計表は「**税区分が付いている行**」だけを集計する。1,363 の行の税区分コードを空にすると、その行は集計表に**まったく現れない**（税額 0 に見える）。移行 CSV では**税行にも税区分コードを入れる**のが正解。
- **確認ポイント（開いても畳まれない）**: この下書きを開いても 3 行のまま。取込由来（連動元種別 = import）の伝票は、旧仕様下書きの復元処理（税行を本体に畳む処理）の**対象外**になっている。11_E2E の IMP-05 に「開くと畳まれる」という注意書きがあるが、現行コードでは解消済み。

## ステップ 8: 確定しても金額が 1 円も動かない（本シナリオの核心）

> **ここから DB に確定伝票が 1 本残る**。後片付けは赤伝になる。読むだけで済ませてもよい。

ステップ 7 で作った **S004 の下書きを開いて「確定」**を押す。

- **期待結果**: トースト「**伝票 No.(+1) を確定しました**」。明細は **3 行のまま、金額も 13,637 / 1,363 / 15,000 のまま**。
- **確認ポイント（ここが売り）**: 通常の振替伝票なら、確定時に 水道光熱費 13,637（課税仕入 10%・内税）は **12,397 + 税 1,240** に分解され、既存の 1,363 の税行と合わせて**税が二重に立つ**はずだった。取込由来の伝票は「**行を無加工で確定する**」という別ルートを通るので、**移行元と 1 円もズレない**。会計データの移行でこれが崩れると、前期比較が全部やり直しになる。
- 帳簿/**仕訳帳** で 8/7 の 3 行を確認。財務帳票/**消費税集計表**（対象年度 第18期）では 課税仕入 10% の 本体金額 **+13,637** ／ 消費税額 **+1,363** と、正しく 2 列に分かれる。
- **確認ポイント（採番）**: 確定取込（下書き OFF）で複数伝票を一度に投げた場合は、**CSV の出現順**に年度内連番が振られる。元データの伝票番号は持ち込まれない（IMP-07）。

## つまずいたときは

- **「取込 0 伝票（解析不能行 N 行）」＋「取り込める仕訳がありませんでした」**: 1 グループも成立しなかったとき。1 列目（グループ名）が空、または列数が 5 未満の行しかない。列区切りが**タブや全角カンマ**になっていないか確認する。
- **金額が 10 分の 1 になる／0 になる**: `1,000.50` のような**小数点付き**は数字として読めず 0 になる。円未満のない整数で出力する。マイナス記号は読めるが「1 円以上」の検証で弾かれる。
- **同じ CSV を 2 回取り込んでしまった**: 重複チェックは無い（銀行明細取込と違い、キーの概念が無い）。下書きなら削除、確定済みなら赤伝で取り消す。**まず下書きで取り込む**のはこの事故を避けるためでもある。
- **摘要が「インポート G101」になっている**: グループの先頭行の摘要が空だと、ヘッダ摘要が自動で `インポート {グループ名}` になる。
- **理由が 3 件しか出ない**: 仕様（先頭 3 件＋「ほか」）。落ちたグループを分割して投げ直すと全部読める。
- **確定取込した伝票を消したい**: 削除できない。赤伝で相殺する（→ 会計-06）。**移行作業は必ず「下書き取込 → 目視 → 確定」の 3 段**で行うこと。

## 後片付け

1. **下書き 3 本（S001・S002・S003）を削除**: 仕訳/振替伝票 の一覧で 状態「下書き」を検索 → 1 件ずつ「開く」→ 赤い「**この下書き伝票を削除**」→ 確認ダイアログ「この下書き伝票を削除しますか？（元に戻せません）」→ 「**削除する**」。
   - ポータルの「▶ 下書きのままの伝票」の件数が元に戻ることを確認する。
2. **S004（確定済み）を取り消す**: 削除できないので赤伝を切る。仕訳/振替伝票 > 新規作成 → 取引日 `2026-08-07`（**元伝票と同じ日**）／摘要 `No.(+1) 取消（インポート練習）`。

   | 行 | 貸借 | 勘定科目 | 税入力 | 金額 |
   |---|---|---|---|---|
   | 1 | 借方 | `普通預金` | （空） | `15,000` |
   | 2 | 貸方 | `水道光熱費` | **なし**に変更 | `13,637` |
   | 3 | 貸方 | `仮払消費税` | （空） | `1,363` |

   → 「**確定**」。**税入力を「なし」にするのを忘れない**（内税のままだと 13,637 が再分解されて赤伝の金額が合わなくなる）。
3. **残り物チェック**: 振替伝票一覧を 状態「下書き」で検索して **0 件**（もともと存在した下書き 2 本は残してよい）。
4. **戻らないもの（任意）**: 伝票番号は欠番にならず前進する。**消費税集計表の本体金額・消費税額は差引で元に戻る**が、赤伝の分は「戻し（本体）／戻し（税）」列に残る（ADR-0052 で符号付きの差引集計になった）。納税額は仮払・仮受消費税の**残高**ベースで計算する。
