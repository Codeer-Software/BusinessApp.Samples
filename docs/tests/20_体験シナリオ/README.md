## 1. これは何か・何のためのものか

- **1 ファイル = 実務で実際に起こる「一本道」**。物語 → 前提 → ステップ → 期待結果 → つまずいたときは、の順で書く。
- **ライブラリ全体で条件分岐を網羅する。**「一巡」を 1 本書いて終わりにせず、境界値・例外・逆操作・権限差を別ファイルに割り、
  執拗に分岐を通す。だからファイル数が多い。
- 各ステップには、`docs/tests/11_E2Eテストシナリオ/` の分岐 ID（`EXP-R02` `SLS-07` `DIF-03` など）を**参照タグ**として付ける。
  11_E2E は「期待値の正典（金額・仕訳番号まで固定）」、本ライブラリは「人が読んで順に触れる台本」という役割分担。

## 2. 読み方・使い方

| 項目 | 約束 |
|---|---|
| ログイン | パスワードは**ユーザー名と同じ**（例: `soumu_bucho` / `soumu_bucho`） |
| 導線の書き方 | 現行体制に統一。**全員が業務ポータル（Main/PortalHome）に着地** → **Main 左サイドバー**から各業務へ。各フレームの先頭「ホーム」でポータルへ戻る |
| 画面名 | サイドバーに実際に出るラベル文字列をそのまま書く（例: 「経費精算」「会計業務」「購買・支払」「業務マスタ」） |
| 採番・仕訳番号 | **相対表現**（「その時点の最終番号 +1」）。決め打ちしない。他の操作を挟めばずれるのが正常 |
| 影響 | ヘッダに「このシナリオが DB に何を残すか」を明記。元に戻せない操作は**任意ステップ**にする |
| 後片付け | マスタ・期間・閾値を変える手順は、必ず最後に原状復帰の手順を置く |

**推奨の入口**: 初めて触るなら `00_ポータルと通知/01_権限別ポータルツアー.md`（閲覧のみ・DB を汚さない）→ `01_経費精算/01_立替精算の一巡.md`（最短の一巡）。

### 承認ルートは積み上げ方式（ADR-0048・2026-08-09 確定）

金額が上がると承認者が入れ替わるのではなく、**承認段が積み上がる**。

| 適用条件 | テンプレート | ルート |
|---|---|---|
| 全費目 0〜29,999 | 経費_課長まで | 課長 |
| 全費目 30,000〜199,999 | 経費_部長まで | **課長 → 部長** |
| 全費目 200,000〜 | 経費_部長まで＋総務 | **課長 → 部長 → 総務** |
| 交際費 0〜29,999 | 経費_課長まで＋総務 | 課長 → 総務 |
| 交際費 30,000〜 | 経費_部長まで＋総務 | **課長 → 部長 → 総務** |

この組織では**課に課長が 1 名ずつなので課長段は常に単独**、**部に部長と部長代理の 2 名が居るので
OR 並列は部長段**で起きる。課長が空席の課・課長本人の申請では、課長段が walk-up で部長へ繰り上がり、
次の部長段と同じ人になるため**段が 1 つに圧縮**されて「部長のみ」になる（ADR-0044 の機構）。
DB・seed（`Designer/ddl/460_approval_stacked_route.sql`）・関連ドキュメントはすべて反映済み。
