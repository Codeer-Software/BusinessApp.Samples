# 体験シナリオ 営業-03: 分割検収と請求金額の罠（残額自動セット → 超過警告 → 請求額の上書き問題）

> 作成: 2026-08-09 ／ 所要時間: 約25〜35分 ／ 影響: 受注 1・検収 2・請求書 2・仕訳 2 本（売上計上のみ。入金はしない）。末尾に全ロールバック手順あり（任意）
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）。
> 大型案件を 2 回に分けて検収するときの支援機能（残額自動セット・進捗ラベル・超過警告）と、**分割検収から作った請求書の金額が受注全額に上書きされる罠**（既知の要注意挙動）を実体験する。

## 物語

テックイノベーションから 200 万円（税抜）の受託案件。フェーズ1（120 万円）とフェーズ2（80 万円）の 2 回に分けて検収・請求することになった。

## 前提

| 項目 | 内容 |
|---|---|
| 取引先・案件 | `株式会社テックイノベーション`・案件 `テックイノベーション様・販売管理システム構築`（PJ-2026-101・既存） |
| 採番の目安 | 受注 SO-26-0XX／検収 A-26-0XX×2／請求書 INV-26-0XX×2／仕訳 No.（最終+1）から 2 本 |
| ポイント | 受注は**見積を経ずに直接作成できる**（実務の「随意契約」パターン） |

## ステップ 1: 受注の直接作成

**soumu_bucho** でログイン → 営業業務（請求書一覧に着地）→ サイドバー「**受注**」→「新規作成」。

| 項目 | 入力値 |
|---|---|
| 取引先 | `株式会社テックイノベーション` |
| プロジェクト | `テックイノベーション様・販売管理システム構築` |
| 件名 | `販売管理システム 追加開発（フェーズ1・2）` |
| 部門 | `営業部` に変更（経理は部門を変更できる） |

明細 1 行: 摘要 `追加開発一式`・数量 1・単位 `式`・単価 `2,000,000` → 「保存」。

## ステップ 2: 検収 1 回目（フェーズ1・1,200,000）

サイドバー「検収」→「新規作成」→ 受注に今作った SO を選択。

- **確認ポイント**: 検収額に **2,000,000 が自動セット**され、進捗ラベルは「受注額 2,000,000 円 ／ 検収済み累計（確定） 0 円 ／ 残額 2,000,000 円」。

検収額を **`1,200,000`** に手修正（消費税額が 120,000 に追随）・検収日=本日 → 「保存」→「**検収を確定（売上計上）**」。

- **期待結果**: トースト「仕訳 No.XX を生成し検収を確定しました（売掛金 1,320,000 円 / 売上 1,200,000 円）」。

## ステップ 3: 請求書を作る → 金額の罠を観察（INV-金額の上書き）

検収詳細で「**請求書を作成**」→ 下書き請求書へ自動遷移。

- **⚠ 観察ポイント（本シナリオの核心）**: 生成直後の請求書はヘッダに検収額 1,200,000 を持っているが、**明細は受注明細のコピー（2,000,000 の 1 行）**。詳細画面を開いた瞬間に合計再計算が走るため、**請求額（税抜）が 2,000,000・消費税 200,000 に上書きされている**。このまま発行すると 220 万円の過大請求になる。

**対処（実務の作法）**: 明細の単価を **`1,200,000`** に修正し、摘要を `追加開発一式（フェーズ1検収分）` に直す → 請求額（税抜）1,200,000・消費税 120,000 に戻ることを確認 → 「保存」→「**発行する**」。

- **期待結果**: トースト「請求書 INV-26-0XX を発行しました（入金予定を自動作成。…）」。

## ステップ 4: 売掛残高の「発行直後は入金済に見える」注意（AR-発行直後の見え方）

サイドバー「**売掛残高**」を開く（既定フィルタ=「入金済を除く」）。

- **観察ポイント（改善候補）**: 今発行した請求書が**一覧に出てこない**。状態フィルタを空にして検索すると、**状態=入金済・残額 0** で表示される。これは発行時に自動作成される「未確定の入金予定」も入金済額として合算されるため。実際にはまだ 1 円も入金されていないので、消込前の債権管理はサイドバー「入金」の**未確定一覧**とセットで見るのが現状の作法。

## ステップ 5: 検収 2 回目 — 残額自動セットと超過警告

サイドバー「検収」→「新規作成」→ 同じ受注を選択。

- **確認ポイント**: 検収額に**残額 800,000 が自動セット**され、進捗ラベルは「受注額 2,000,000 円 ／ 検収済み累計（確定） 1,200,000 円 ／ 残額 800,000 円」。

わざと検収額を **`900,000`** に書き換え、検収日=本日で「保存」→「**検収を確定（売上計上）**」。

- **期待結果（超過警告）**: 確認ダイアログ「確定済みの検収累計 1,200,000 円にこの検収 900,000 円を加えると、受注額 2,000,000 円を **100,000 円超過**します。このまま確定しますか？」→ 「**キャンセル**」を押す（何も起きない。**警告はブロックではない**＝押せば超過のまま確定できる設計であることを覚えておく）。

検収額を **`800,000`** に戻して「保存」→ 再度「検収を確定（売上計上）」。

- **期待結果**: トースト「仕訳 No.XX を生成し検収を確定しました（売掛金 880,000 円 / 売上 800,000 円）」。進捗ラベルの残額が 0 になる。

## ステップ 6: 2 枚目の請求書（罠の再確認と対処）

「請求書を作成」→ **今回も請求額が 2,000,000 に上書きされている**ことを確認 → 明細単価を `800,000`・摘要 `追加開発一式（フェーズ2検収分）` に修正 → 保存 →「発行する」。

## ステップ 7: 総仕上げ

| 画面 | 見えるもの |
|---|---|
| 仕訳帳 | 売上計上 2 本（1,320,000 と 880,000）。合計が受注額の税込 2,200,000 と一致 |
| 総勘定元帳（売掛金） | 2 回の発生。入金はまだ無いので残高 +2,200,000 |
| 検収一覧 | A-26-0XX×2 が確定済・それぞれ「請求書 INV-26-0XX 作成済み」 |

## 後片付け（任意・完全ロールバック）

売掛が 2,200,000 残るのが気になる場合は、逆順にすべて取り消せる:

1. 各請求書: 「**下書きに戻す**」（未確定の入金予定が消える）→「**この請求書を削除**」
2. 各検収: 「**確定を取り消す**」（ダイアログ→売上仕訳が削除され下書きに戻る）→「**この検収を削除**」
3. 受注: 「**この受注を削除**」（検収が消えると削除ボタンが現れる）

## つまずいたときは

- **請求額の上書きが再現しない**: 明細を検収額に合わせて直した後は上書きされない（明細合計=ヘッダの再計算なので一致していれば無害）。罠が出るのは「明細合計 ≠ 検収額」のときだけ。
- **「確定を取り消す」が拒否される**: 「請求書 INV-… が作成済みのため取り消せません」→ 先に請求書側を削除する（後片付けの順序どおりに）。
- **仕訳番号のずれ**: 最終+1 で採番されるため他シナリオ実行済みならずれる。金額が合っていれば正常。
