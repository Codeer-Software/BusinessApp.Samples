# 体験シナリオ 営業-01: 受託案件の一巡（案件 → 見積 → 受注 → 検収 → 請求 → 入金 → クローズ）

> 所要時間: 約30〜40分 ／ 影響: 仕訳 2 本＋案件・見積・受注・検収・請求書・入金 各 1 件追加（既存データは変更しない）
> 主役: **soumu_bucho**（総務部 部長 山田太郎・経理）と **eigyo_ippan**（営業部 一般 伊藤さくら）。パスワードはユーザー名と同じ。
> 営業担当が見積〜受注を作り、経理が売上計上〜入金消込を行う、受託開発の王道を **2 つの視点** で通す。

## 物語

株式会社テックイノベーション（既存顧客 C003）から「EC サイト リニューアル」の引き合いが来た。
営業の伊藤さくらが見積 180 万円（税抜）を提示 → 受注。納品・検収を経て、経理の山田太郎が売上計上 → 請求書発行 → 銀行振込での入金消込 → 案件クローズまでを行う。

## 前提

| 項目 | 内容 |
|---|---|
| 会計期間 | 第18期（2026年度）。当月（2026-08）の月次期間がオープンであること |
| 採番の目安 | 見積 **Q-26-011**／受注 **SO-26-009**／検収 **A-26-009**／請求書 **INV-26-017**／仕訳 **No.84・No.85**（現在の最終: Q-26-010／SO-26-008／A-26-008／INV-26-016／No.83。他の操作を挟むとずれるが読み替えでよい） |
| 会計的な流れ | 見積・受注は帳簿に影響しない。**検収の確定＝売上計上**（検収基準・ADR-0008）、入金の確定＝売掛金の消込 |

## ステップ 1: 案件マスタの新規作成（山田太郎）

**soumu_bucho** でログイン → サイドバー「**業務マスタ**」→ 取引先一覧に着地 → サイドバー「**案件**」→「新規作成」。

| 項目 | 入力値 |
|---|---|
| 案件コード | `PJ-2026-102` |
| 案件名 | `テックイノベーション様・ECサイト リニューアル` |
| 取引先 | `株式会社テックイノベーション` |
| 種別 | `受託` |
| 状態 | `進行中` |
| 有効 | ✓ |

→ 「登録」。

- **確認ポイント**: 種別が「受託」の間、SES 契約条件の入力欄は表示されない（種別を一度「SES」にすると現れ、戻すと消える）。
- **補足**: 案件の登録・編集は経理だけでなく**部長（is_director）も工数管理フレームの「案件一覧」から行える**（ADR-0046。SES 精算条件だけは経理専用）。

## ステップ 2: 見積の作成（伊藤さくら）

ログアウト → **eigyo_ippan** でログイン。

- **確認ポイント（権限の見え方）**: ポータルのサイドバーは「通知／経費精算／工数管理／営業業務」のみ。会計業務・購買・業務マスタは出ない。

サイドバー「**営業業務**」→ 見積一覧に着地（営業一般の営業フレームは見積が既定画面）→「新規作成」。

| 項目 | 入力値 |
|---|---|
| 見積番号 | 自動採番（**Q-26-011** 目安・編集不可） |
| 取引先 | `株式会社テックイノベーション` |
| プロジェクト | `テックイノベーション様・ECサイト リニューアル` |
| 件名 | `ECサイト リニューアル 一式` |
| 発行日 | 本日（既定） |
| 部門 | `営業部`（既定） |

明細（3 行）:

| # | 摘要 | 数量 | 単位 | 単価 | 税区分 |
|---|---|---|---|---|---|
| 1 | `要件定義・画面設計` | 1 | 式 | `500,000` | 課税売上 10% |
| 2 | `開発・テスト一式` | 1 | 式 | `1,000,000` | 課税売上 10% |
| 3 | `データ移行・リリース支援` | 1 | 式 | `300,000` | 課税売上 10% |

→ 「保存」。

- **期待結果**: 合計（税抜）= **1,800,000**・状態「下書き」。
- **確認ポイント**: **部門欄は閲覧専用**になっている（伝票の部門を変更できるのは経理のみ）。
- 「**送付済にする**」を押す → トースト「見積を送付済にしました」・状態「送付済」・入力欄がロックされる。
- **任意**: 「見積書を出力（PDF）」で書面確認（小計 1,800,000・消費税 180,000・合計 ¥1,980,000）。

## ステップ 3: 受注への変換（伊藤さくら）

見積詳細で「**受注にする**」。

- **期待結果**: トースト「受注 **SO-26-009** を作成しました」→ 受注詳細へ自動遷移。明細 3 行・取引先・案件・部門がコピーされ、受注日=本日・状態「進行中」。見積側は「受注」に変わる。
- **会計的な意味**: まだ売上ではない（帳簿は無変化）。検収基準なので「顧客が受入確認するまで収益認識しない」。

## ステップ 4: 検収の登録（伊藤さくら → 下書きまで）

サイドバー「**検収**」→「新規作成」。

| 項目 | 入力値 |
|---|---|
| 検収番号 | 自動採番（**A-26-009** 目安） |
| 受注 | `SO-26-009` を選択 → **受注明細がコピーされ、各行の「検収金額」に残額が自動セット**。ヘッダの検収額（税抜）1,800,000・消費税額 180,000 は明細合計からの自動計算（読み取り専用） |
| 検収日 | 本日 |

→ 「保存」（状態: 下書き）。

- **確認ポイント（進捗ラベル）**: 「受注額 1,800,000 円 ／ 検収済み累計（確定） 0 円 ／ 残額 1,800,000 円」。
- **確認ポイント（職務分掌）**: 営業一般には「**検収を確定（売上計上）**」ボタンが**表示されない**（経理専用）。サイドバーにも「請求書」「入金」メニューが無い（RCV-01）。

## ステップ 5: 検収の確定 = 売上計上（山田太郎・仕訳 No.84）

ログアウト → **soumu_bucho** でログイン → サイドバー「**営業業務**」→ 経理は**請求書一覧に着地** → サイドバー「**検収**」→ A-26-009 を開く。

「**検収を確定（売上計上）**」を押す。

- **期待結果**: トースト「仕訳 No.84 を生成し検収を確定しました（売掛金 1,980,000 円 / 売上 1,800,000 円）」。状態「確定済」・閲覧専用になり、「請求書を作成」「確定を取り消す」（赤）が現れる。
- **帳簿の確認**: 「ホーム」→「会計業務」→ 帳簿 > 仕訳帳。本日付 3 行 — 借方 **売掛金 1,980,000** ／ 貸方 **受託開発売上高 1,800,000** ＋ **仮受消費税 180,000**。全行に案件・部門（営業部）が付く。

## ステップ 6: 請求書の作成と発行（山田太郎）

検収詳細で「**請求書を作成**」。

- **期待結果**: トースト「請求書 **INV-26-017** を下書きで作成しました（内容を確認して「発行する」を押してください）」→ 請求書詳細へ自動遷移。明細 3 行コピー・支払期限=**翌月末**・状態「下書き」。

内容を確認して「**発行する**」。

- **期待結果**: トースト「請求書 INV-26-017 を発行しました（**入金予定を自動作成**。入金一覧の「未確定」から消込できます）」。
- **確認ポイント**: サイドバー「**入金**」→ 消込状態「未確定」の行が 1 つ増えている（入金日=支払期限・銀行振込・1,980,000 円・備考に自動作成の注記）。
- **仕訳帳は無変化**（債権は検収時に計上済み。請求書は帳簿外の書面）。

## ステップ 7: ポータルの売掛アラートを見る（観察）

サイドバー「ホーム」でポータルへ。

- **確認ポイント**: 「**⚠ 期限超過の売掛: N 件**」は**支払期限を過ぎた未回収**があるときだけ表示される。今回の INV-26-017 は期限内なので対象外（表示されなくて正しい）。既存データに期限超過があれば件数が出て、クリックで売掛残高一覧へ飛べる。

## ステップ 8: 入金の確定 = 消込（山田太郎・仕訳 No.85）

サイドバー「営業業務」→「**入金**」→ INV-26-017 の未確定行の「開く」。

| 項目 | 入力値 |
|---|---|
| 入金日 | 本日に変更 |
| 入金方法 | `銀行振込`（既定のまま） |
| 入金額 | `1,980,000`（自動セットのまま） |

→ 「**入金を確定（消込）**」。

- **期待結果**: トースト「仕訳 No.85: 入金 1,980,000 円を消し込みました（INV-26-017 は入金済）」。
  - 仕訳帳: 借方 **普通預金 1,980,000** ／ 貸方 **売掛金 1,980,000**
  - サイドバー「売掛残高」: INV-26-017 は既定フィルタ「入金済を除く」では出ない → 状態を「入金済」にして検索すると 残額 0 で確認できる
  - 会計業務 > 帳簿 > 出納帳（普通預金）: 入金 1,980,000 の行

## ステップ 9: クローズ（山田太郎）

1. **受注**: SO-26-009 を開き「**完了にする**」→ トースト「受注を完了にしました」。
2. **案件**: 業務マスタ > 案件 > PJ-2026-102 を開き、状態を「**完了**」にして「登録」（「有効」は ✓ のまま＝過去実績の参照用）。

## ステップ 10: 総仕上げ — この案件が残した数字

| 画面 | 見えるもの |
|---|---|
| 会計業務 > 帳簿 > 仕訳帳 | No.84（売上計上 3 行）と No.85（入金消込 2 行） |
| 会計業務 > 帳簿 > 総勘定元帳（科目=売掛金） | 発生 1,980,000 → 回収 1,980,000 で債権の一生が見える |
| 経営管理 > 案件損益 > 案件損益 | PJ-2026-102 の売上 1,800,000（原価はまだ 0） |
| 会計業務 > 財務帳票 > 損益計算書 | 売上高 +1,800,000 |

## つまずいたときは

- **「検収を確定」ボタンが見えない**: ログインユーザーが経理でない（soumu_bucho で操作する）。営業アカウントでは出ないのが正しい挙動。
- **「締め済みの期間には…」系のエラー**: 検収日・入金日がオープン期間（2026-07 以降）にあるか確認。会計業務 > 設定 > 会計年度 で再オープンできる。
- **入金を「新規作成」で作ろうとした**: 案内トーストが出て入金一覧に戻される。入金は請求書の発行時に自動作成された「未確定」行から確定する設計。
- **伝票番号・採番が本書と違う**: 番号は最終+1 で振られる。金額と貸借が合っていれば正常。
