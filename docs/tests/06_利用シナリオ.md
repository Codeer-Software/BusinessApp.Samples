# 利用シナリオ集（総合テスト用）

> 作成: 2026-07-06 ／ 全面追随: 2026-07-19（ロール別ページフレーム再編 ADR-0028・状態遷移のボタン一元化 ADR-0026・ボタン色2色化 ADR-0027 に更新）
> 目的: 典型的なユーザーストーリーに沿って「こんな操作をしたらこんな結果が得られる」を確認する総合テストの台本（ユーザー要望）。
> 実装済みの全機能（フェーズ A 会計コア／B 周辺業務／B' 管理会計／D 拡張）を、**一般社員・承認者・経理・システム管理者**の4ロール視点で網羅する。
> 各シナリオは独立して読めるが、S-01→S-19 の順に流すと「申請→承認→会計→帳票→経営分析」の一連のストーリーになる。
> **より詳細な期待値（金額・トースト文言・仕訳番号まで固定した完全版）は docs/tests/11_E2Eテストシナリオ が正**。本書は機能単位の再確認・回帰テスト用の軽量版。
> 画面表記（ADR-0028）: ページフレームは**ロールごとに1枚**（General=一般社員／Approver=承認者／Accounting=経理／Sysadmin=システム管理者）。ログインすると `/` から自ロールのフレームのホームへ自動転送され、**他ロールのフレームは見えない**（直URLも「ページフレームへのアクセス権限がありません」）。URL は `/{ロールフレーム}/{モジュール}`（例: 経理の振替伝票=/Accounting/JournalEntry、一般の経費申請=/General/ExpenseRequest）。サイドバーは折りたたみ式のカテゴリグループで、本書のメニュー表記は「グループ/リンク」（例:「販売/見積」「帳簿/出納帳」）。グループ構成: 経理=ホーム・経費精算・販売・購買・仕訳・帳簿・銀行・財務帳票・予算・案件・マスタ・設定／sysadmin=＋システム管理／承認者=ホーム・経費精算・販売・案件・予算／一般=ホーム・経費精算・販売・案件。ホームのショートカットは全ロール共通=経費申請・工数入力、経理/sysadmin のみ追加=振替伝票・銀行明細取込・月次推移表・資金繰り予測。Logout はサイドバー下端（英語表記・確認ダイアログなしで即ログアウト）。
> 操作の原則（ADR-0026/0027）: **「状態」は全画面で表示専用**、遷移は青ボタン（前進）と赤ボタン（削除・取消・巻き戻し）だけで行う。一覧に削除ボタンは無く、削除は詳細画面の赤ボタン（状態条件つき・確認ダイアログつき）。誤操作は各画面の「〜を取り消す」「下書きに戻す」で巻き戻せる（仕訳を生んだ操作の取消は該当仕訳も削除。締め済み期間は不可＝赤伝対応）。

## S-01 経費申請（立替・少額）→ 課長承認 【一般社員・承認者】

**ストーリー**: 開発部の社員が 3 万円未満の旅費を立て替えたので精算したい。

1. kaihatsu1_ippan でログイン → ホームのショートカット「経費申請」> 新規作成
2. 件名・金額（例 8,000）・利用日・費目=旅費交通費 を入力 → 申請区分は既定の「立替精算」、精算対象者は既定で本人
3. 「申請」を押す
- **期待**: トースト「申請しました」。フロー表示「状態:進行中 ✓(申請者)→(▶第二課長 中村拓也,▶第一課長 山本由美)」（3万未満 → **課長のみ**ルートが自動選択。課長2名に**並列**で回る）。精算ステータス=申請中。**山本由美・中村拓也の両方に通知**（承認依頼）が作成される
4. kaihatsu1_kacho1 でログイン → ホームの「未読の通知」に承認依頼 → 「開く」
- **期待**: 該当申請へ遷移し通知が既読化。申請内容は編集不可（グレーアウト）
5. 「承認」を押す
- **期待**: 状態=承認済・精算ステータス=承認済。**申請者に「承認されました」通知**。もう1人の課長（中村拓也）は Skipped になり、中村拓也の承認待ち一覧から消える

**バリエーション**: 金額 3万〜20万 → 承認者が**部長（部長 田中宏・部長代理 渡辺剛の並列）**に変わる。20万以上 → **部長並列→総務**の2段。却下するとステータスが下書きへ戻り申請者が再申請できる。

## S-02 交際費申請（例外項目＋総務併載） 【一般社員】

**ストーリー**: 取引先との会食費を精算したい。交際費はコンプライアンス上、相手先の記録と総務の確認が必須。

1. kaihatsu1_ippan で経費新規作成 → 費目=**交際費** を選ぶ
- **期待**: 「接待の相手先・参加人数・接待の目的」の3項目が**出現**する
2. 3項目を空のまま「申請」
- **期待**: 赤トースト「交際費は相手先・参加人数・目的の入力が必須です」で**ブロック**される
3. 3項目を入力して申請
- **期待**: 金額が3万未満でも**課長→総務**の2段ルート（交際費は常に総務併載。総務段の承認者は総務部の役職者＝soumu_kacho1 等）

## S-03 事前申請 → 実費超過 → 自動再承認 【一般社員・承認者】

**ストーリー**: 出張前に見込み 25,000 円で事前申請し承認を得たが、実費は 40,000 円かかった。

1. kaihatsu1_ippan で経費新規作成 → 申請区分=**事前申請** に変更
- **期待**: 「見込み額」欄が出現（立替では非表示）
2. 費目=旅費交通費・見込み額 25,000 で申請 → 山本由美または中村拓也（課長）が承認
3. kaihatsu1_ippan で申請を開く → 「実費（税込）」欄に 40,000 → 「実費を確定」
- **期待**: 区分跨ぎ（3万超え）＋見込み×110%超のため**自動で再承認へ**。トースト「実費が見込みを超過したため再承認を依頼しました」。ルートが**部長（部長 田中宏・部長代理 渡辺剛の並列）**に再解決され、履歴に超過理由が記録される（再解決は**申請者基準**——経理が代行確定しても申請者本人が承認者に入らない）
4. kaihatsu1_bucho（または buchodairi）が承認 → 経理処理へ進める

**バリエーション**: 実費 26,000（区分内・110%以内）なら再承認は走らず、そのまま仕訳生成可能になる。

## S-04 経理処理: 仕訳生成 → 支払 → 出納帳 【経理】

**ストーリー**: 承認済の経費を会計に取り込み、精算金を支払う。ここからは経理専用の世界（A×B 一体化の接点）。

1. soumu_bucho（経理）で承認済の経費を開く
- **期待**: 「仕訳を生成」ボタンが見える（**承認者ロールでは見えない**）
2. 「仕訳を生成」
- **期待**: トーストに伝票 No と金額。仕訳は D 費目の既定科目（税抜本体）＋ D 仮払消費税 ／ C 未払金（税込）。仕訳帳・試算表に即反映。ステータス=経理処理中。**備品×10万円以上の申請は D が工具器具備品になり、固定資産台帳へ自動登録**（EXP-{id}、取得価額=税抜）。利用日の期間が締め済みなら**本日日付に自動フォールバック**（摘要に利用日を記載・トーストで通知）
3. 「精算済にする」
- **期待**: 支払仕訳（D 未払金／C 普通預金）が自動生成。「帳簿/出納帳」（普通預金）に出金行が現れ残高が減る
4. 「完了にする」 → ステータス=完了

## S-05 販売サイクル: 見積→受注→検収→請求→入金 【営業＋経理】

**ストーリー**: 受託案件の商談から入金までを一気通貫で管理する。売上計上は検収基準（ADR-0008）。

1. 「販売/見積」> 新規作成: 取引先・件名・明細（数量×単価で金額自動計算・税抜合計表示）→ 保存（Q-26-xxx 採番）。「見積書を出力（Excel/PDF）」で帳票も確認できる。状態は表示専用で、下書きでは「送付済にする」「受注にする」「失注にする」「この見積を削除」のボタンが並ぶ
2. 「受注にする」
- **期待**: 受注 SO-26-xxx が明細コピー付きで生成され自動遷移。見積は「受注」状態になり、遷移ボタンは「下書きに戻す」（赤）だけになる（受注が存在する間は押してもガードされる）
3. 「販売/検収」> 新規作成: 受注を選択
- **期待**: 検収額（受注の**未検収残額**。初回検収では受注全額）と消費税額が自動セットされ、「受注額／検収済み累計（確定）／残額」のガイドが表示される。累計が受注額を超える確定は警告ダイアログ（増額検収は続行可能）。**検収が1件でも登録された受注は編集不可**（ロック理由と変更契約への誘導が受注画面に表示される）
4. 保存 → 「検収を確定（売上計上）」（**経理のみ実行可**。営業ロールにはボタン自体が出ない）
- **期待**: 売上仕訳（D 売掛金=税込／C 受託開発売上高／C 仮受消費税）が自動生成。案件が仕訳に引き継がれる。確定後は編集不可となり保存ボタンも消える（誤確定は「確定を取り消す」で売上仕訳ごと巻き戻せる——請求書作成後は不可）
5. 「請求書を作成」→ 請求書詳細で「発行する」
- **期待**: INV-26-xxx が明細コピー・支払期限=翌月末で**下書き**生成され、「発行する」で発行済みになる（自動発行しない・2026-07-21 改修）。検収側はボタンが消え「**請求書 INV-26-xxx 作成済み**」のラベル表示に変わる（押しても必ずエラーになるボタンは見せない設計）
6. 「販売/入金」> 新規作成: 請求書を選択（**未消込のものだけ候補に出る**）
- **期待**: 入金額に残額が自動セット
7. 「入金を確定（消込）」（経理のみ）
- **期待**: 消込仕訳（D 普通預金／C 売掛金）生成、請求書が「入金済」に。「販売/売掛残高」で残額 0 を確認。期限超過の未入金は「期限超過」表示になる
- 補足（2026-07-23）: 売掛残高は取引先・状態・支払期限・案件・部門で検索できる（既定は「入金済を除く」。入金済も見たいときは状態を空欄にして検索）。一般・承認者の販売グループからも閲覧できる

**バリエーション**: 先方が振込手数料を差し引いた入金（差額≦1,000円）は支払手数料として**自動処理**され全額消込。請求残額を超える入金は**過入金ガード**で拒否（前受金の手動起票へ誘導）。誤入金の確定は「入金を取り消す」で消込仕訳を削除し請求書ステータスを再計算できる。

**変更契約の運用規約**（詳細な検討は docs/issues/ISSUE-0002）:

1. **増額・追加スコープは「差分文書の追加」で表す**: 変更契約分を新しい見積として起こし（件名規約: 「元件名 変更契約①: 追加内容」）、「受注にする」→ **元契約と同一の案件**に紐付ける。以後は独立した受注として検収・請求まで流す（案件損益は案件単位で自動合算）。既存の受注明細を直接書き換えない——検収が登録された受注はシステム側でも編集不可。
2. **減額・値引きは検収額の手修正で表す**: 検収時に検収額を減額する（マイナス明細の受注は作らない。検収確定は金額>0のため単独検収できない）。
3. **合算請求**: 当初契約と変更契約の請求を1枚にまとめたい場合は、**手動請求書**（請求書>新規作成）に両方の明細を記載して発行する。その後、各検収の「合算先請求書」欄でその請求書を選択すると「請求書を作成」ボタンが消えて合算済みラベルに変わる（二重請求防止）。
4. **検収確定後の変更**は逆操作チェーン（入金取消→請求書取消→確定取消）で巻き戻してからやり直す。締め済み期間は赤黒訂正。

## S-06 SaaS 定期請求の一括生成 【経理】

**ストーリー**: 月初に当月分の SaaS 利用料請求をまとめて発行する。

1. 「販売/定期請求契約」: 契約マスタ（取引先・月額/年額・開始月・状態）を確認。契約は「**下書き**」で作成され、経理の「**確定する**」で「**確定済**」になる（「下書きに戻す」で差し戻し可）。閲覧と下書きの作成・編集は一般・承認者も可、確定・差し戻し・有効チェックの切替・確定済の編集は経理（と sysadmin）のみ。不要契約の削除は行わず有効フラグで無効化
2. 「販売/定期請求の実行」: 対象月を選び「対象月の請求書を一括生成」（経理のみ。対象は「**確定済」かつ「有効」**の契約だけ——下書きは対象外）
- **期待**: 「生成 n件 / スキップ m件 / 仕訳 No.…」。請求書（INV、明細1行、月末発行・翌月末期限）と売上仕訳（C SaaS売上高）が同時生成。**生成順は年額→月額**
3. **もう一度実行**
- **期待**: 「生成 0件 / スキップ n件（既生成・対象外）」— 二重請求されない（冪等）

## S-07 工数入力 → 人件費配賦 → 案件別損益 【全社員＋経理】

**ストーリー**: エンジニアが日々の工数を付けると、経理は案件がいくら儲かっているかを見られる（市販会計ソフトにない領域）。

1. kaihatsu1_kacho1（一般視点）で ホームのショートカット「工数入力」> 新規作成: 案件・日付・時間（分）を入力（担当者は本人固定）
- **期待**: 他人の行は一覧で見えるが**削除ボタンが出ず読み取り専用**（書き込みは本人のみ、のサーバ強制が UI に自動反映）。人件費コスト・配賦・案件損益は経理フレームの「案件」グループ内リンクで、承認者・一般のサイドバーには出ない（一般・承認者の「案件」グループは工数入力・案件一覧のみ）。経理の代理修正は「案件/工数管理（経理）」から
2. soumu_bucho（経理）で 「案件/人件費コスト」に月次コストを登録（会計年度×ユーザー×月No。月No は期首からの月番号＝4月開始なら7月=4）→ 「案件/人件費配賦」で年度と月Noを選び検索
- **期待**: ユーザー×案件の工数（時間）・比率(%)・配賦額。**1ユーザーの配賦額合計＝その月の人件費コストに一致**
3. 「案件/案件損益」: 年度を選び検索
- **期待**: 案件ごとに 売上／直課費用／配賦人件費／粗利／粗利率(%)。受託は黒字、工数過多の案件は赤字が見える。前受計上（負債）は売上に入らない——発生主義が管理会計にも一貫

## S-08 予算登録 → 予実対比・超過警告 【経理＋承認者】

## 検算クエリ（テスト後の整合確認）

sql CLI（`AccountingApp.Designer.exe sql ... --datasource AccountingSQLite`）で:

```sql
-- 全 posted 仕訳の貸借一致（常に等しいこと）
SELECT SUM(CASE WHEN dc='D' THEN jl.amount ELSE 0 END) AS 借方,
       SUM(CASE WHEN dc='C' THEN jl.amount ELSE 0 END) AS 貸方
FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
WHERE je.status='posted';

-- 伝票番号の重複ゼロ（年度内連番）
SELECT COUNT(*) FROM (SELECT fiscal_year_id, journal_no, COUNT(*) c
FROM journal_entries GROUP BY fiscal_year_id, journal_no HAVING c > 1);

-- 売掛金残高 = 未入金請求の残額合計（導出主義の照合）
SELECT (SELECT SUM(CASE WHEN dc='D' THEN amount ELSE -amount END)
        FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
        JOIN accounts a ON a.id=jl.account_id
        WHERE a.code='1100' AND je.status='posted') AS 売掛金残高;

-- 期首残高の貸借一致（繰越後の翌期。0 であること）
SELECT fiscal_year_id, SUM(balance) FROM opening_balances GROUP BY fiscal_year_id;
```
