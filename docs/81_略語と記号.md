# 略語と記号

> **本書は「引くための文書」である。** 読んでいて `L-nn` や `FB-nnn` のような番号や、このリポジトリの中だけで使う語が出てきたとき、
> **それが何で、どの文書が持っているか**をここで引く。
> **法令の類**（法令・告示・通達・Q&A）は [80_参照法令一覧](80_参照法令一覧.md)。**境界の定義もあちらが持つ。**
> **呼称の約束**（利用者・開発者・Claude・CLB 開発元）は [CLAUDE.md §3](../CLAUDE.md)。**ここには混ぜない。**
> **語を作る前に読むもの**は [00 §4-13](00_ドキュメント規約/本文.md)——**安易に新しい語・略語・記号を作らない**（開発者の指示。2026-09-21）。
> **1 つの文書でしか使わない語は、ここに載せない。** その文書の中で説明し、外では説明的に書く。

## 1. 語

**「言い換えていく」と書いた語は、新しく書くときは使わず、その後ろに挙げた言い方で書く**（既に使われている箇所は、触った文書から直す——[00 §4-7](00_ドキュメント規約/本文.md) と同じ運用）。

| **当てはめ** | **決まった規則を個別の事実に当てた結論**（法的三段論法の語）。**制度・法令の文脈でだけ使う**。制度以外では「適用する」「当てる」と書く |

## 2. 記号——番号の体系

**同じ形の番号が複数あるので、接頭辞で見分ける。** 「どの文書が持つか」が分かれば、そこへ引きに行ける。
**これから作る接頭辞は 2〜3 文字にし、何の略かをここに書く**（開発者の指示。2026-09-21）。**既にある 1 文字の接頭辞（`I`・`L`・`Q`・`W`・`R`・`A`・`D`）は替えていない**——替えると記録と ADR の指し先が読めなくなるので、体系ごと決め直す回に扱う（[README の保留リスト](README.md)）。

| 記号 | 何の略か | 何の番号か | 持っている文書 |
|---|---|---|---|
| **ADR-nnnn** | Architecture Decision Record（一般の略語） | 判断とその理由 | [decisions/](decisions/README.md) |
| **I-nn** | invariant（不変条件）。コードは `InvariantTraceabilityConvention` と名乗る（[ADR-0054](decisions/0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md)） | **不変条件**（計上済み仕訳が満たすべきこと） | [10 §1](10_会計ドメイン設計.md) |
| **L-nn** | 略ではない。通し文字（由来は記録に無い） | **漏れの型**——作り込んだ不具合と、それをテストが見逃した理由 | [qa/03](qa/03_テストで漏らした実例.md) |
| **FB-nnn** | feedback と読めるが、定めた記録は無い（前回プロジェクトから引き継いだ字） | **CLB への機能改善提案** | [CLB改善提案/01](CLB改善提案/01_機能改善提案.md) |
| **DOC-nnn** | 頭文字（document） | **CLB のマニュアルへの指摘** | [CLB改善提案/02](CLB改善提案/02_マニュアル改善提案.md) |
| **R*nn*-nn** | 頭文字（round＝自己レビューの回） | **自己レビューの指摘**（前が回、後ろが指摘の番号。`R35-01` = ラウンド 35 の 1 件目） | [qa/02](qa/02_自己レビュー記録.md) |
| **Q-nn** | question（問い）と読めるが、[05](05_開発者への問い.md) は定めていない | **開発者への問い**（急ぎの順。番号は使い回さない） | [05](05_開発者への問い.md) |

| **A1〜G2** | （略ではない。要件を並べた通し記号） | **優良な電子帳簿の要件**（A1 A2 A3・B1・C1 C1' C2・D1〜D4・E1〜E3・F1 F1' F1''・F2・G1 G2） | [40](40_優良な電子帳簿の対応表.md) |

### 2-1. 実機操作テストの手順の記号（[qa/04 §3](qa/04_実機操作テスト.md)）

**1 文字をやめたのは開発者の指示**（2026-09-21。逐語は「2文字や3文字使えばいいじゃないですか」。1 文字では qa/01 の A〜X と **31 個**の番号——A 13・B 11・C 6・J 1——が別物を指して重なっていた）。**3 文字に揃えたのは Claude の判断**——7 つを同じ長さにし、2 文字だと `AM`・`PM`・`CC` が一般の略語と重なるため。**番号（`-nn`）は動かしていない。**

| 記号 | 何の略か | 何の手順か | 2026-09-21 より前の記録での字 |
|---|---|---|---|
| **MST-nn** | **M**a**st**er | マスタ（読み出しの経路） | M-nn |
| **JNL-nn** | **J**our**n**a**l** | 振替伝票（入力と計上） | J-nn |
| **AMD-nn** | **Am**en**d**ment | 取消・訂正（Web API の経路） | A-nn |
| **BOK-nn** | **Bo**o**k** | 帳簿 | B-nn |
| **REG-nn** | **Reg**istration number | 登録番号（インボイス） | R-nn |
| **PRM-nn** | **P**e**rm**ission | 権限 | P-nn |
| **CNC-nn** | **C**o**nc**urrency | 同時操作 | C-nn |

**記録（[qa/02](qa/02_自己レビュー記録.md)・[qa/04](qa/04_実機操作テスト.md) の年月ファイル）と ADR は書き換えないので、2026-09-21 より前に書かれたものは右端の字で指している**（[00 §3-3](00_ドキュメント規約/フロントマター.md)。例: [ADR-0052](decisions/0052-訂正のやり直しは「訂正する」が兼ね取消済みで訂正の無い原仕訳には再計上の下書きだけを起こす.md) の `A-13` ＝ `AMD-13`）。番号は同じなので、数字でそのまま引ける。
**記録の中だけで使った番号**（「見るもの」に振った `D-01`・`E-01` など）**は、その節の中の定義が優先する。他の文書からは指さない。**

## 3. 番号の振り方

**ここは記号（`L-nn`・`FB-nnn`・`MST-nn` など）の番号の話である。**
`docs/` 直下の**文書番号**は十の位がカテゴリを表し、
**役割が変われば動く**（[00 §8-1](00_ドキュメント規約/README.md)）。規則が違うので混ぜないこと。

- **一度どこかから指された番号（`-nn` の部分）は動かさない。** 新しい体系を起こすときに**空き番から始める**ことはある
  （実例: 登録番号の手順は REG-20 から始めた——R-07〜R-13 を 2026-08 の記録が別の意味で使っていたため）
- **接頭辞は、指し先が変わらないなら替えてよい**（`A-12` を `AMD-12` にしても、指している手順は同じ）。**替えた回は、旧⇔新の対応を §2-1 に残す**
- **欠番は正常**。`削除` を置いた欠番は経緯として正しい（[00 §4-12](00_ドキュメント規約/本文.md)）
- **新しい記号を作るときは、ここに 1 行足す**（何の略かも書く。元の文書が定めていなければ「定めていない」と書く）。足さないと、半年後に読む人が引けない
