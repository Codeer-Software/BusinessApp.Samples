# 略語と記号

> **本書は「引くための文書」である。** 読んでいて `L-nn` や `FB-nnn` のような番号や、このリポジトリの中だけで使う語が出てきたとき、
> **それが何で、どの文書が持っているか**をここで引く。
> **法令の類**（法令・告示・通達・Q&A）は [80_参照法令一覧](80_参照法令一覧.md)。**境界の定義もあちらが持つ。**
> **呼称の約束**（利用者・開発者・Claude・CLB 開発元）は [CLAUDE.md §3](../CLAUDE.md)。**ここには混ぜない。**
> **語を作る前に読むもの**は [00 §4-13](00_ドキュメント規約/本文.md)——**安易に新しい語・略語・記号を作らない**（開発者の指示。2026-09-21）。
> **1 つの文書でしか使わない語は、ここに載せない。** その文書の中で説明し、外では説明的に書く。

## 1. 語

**「言い換えていく」と書いた語は、新しく書くときは使わず、右の言い方で書く**（既に使われている箇所は、触った文書から直す——[00 §4-7](00_ドキュメント規約/本文.md) と同じ運用）。

| **機械** | **人ではなく道具が自動で見ていること**。**言い換えていく**——「機械で守る」「機械が拒む」と書かず、**どの道具か**（コミット前フックの `lint_docs.py`・`SchemaConstraintTests`・DDL の CHECK 制約・自動拒否）を名指しする |

| **敷衍**（ふえん） | **開発者の決定から Claude が導いた規則や当てはめで、開発者の承認を得ていないもの**。印を付けて分ける（[00 §4-11](00_ドキュメント規約/本文.md)・[34](34_開発者とClaudeの分担.md) の前書き）。**言い換えていく**——「Claude が足した規則（開発者未承認）」 |
| **当てはめ** | **決まった規則を個別の事実に当てた結論**（法的三段論法の語）。**制度・法令の文脈でだけ使う**。制度以外では「適用する」「当てる」と書く |

## 2. 記号——番号の体系

**同じ形の番号が複数あるので、接頭辞で見分ける。** 「どの文書が持つか」が分かれば、そこへ引きに行ける。
**接頭辞は 2〜4 文字で、何の略かをここに書く**（開発者の指示。2026-09-21。1 文字にしない）。

| 記号 | 何の略か | 何の番号か | 持っている文書 |
|---|---|---|---|
| **ADR-nnnn** | Architecture Decision Record | 判断とその理由 | [decisions/](decisions/README.md) |
| **I-nn** | Invariant | **不変条件**（計上済み仕訳が満たすべきこと） | [10 §1](10_会計ドメイン設計.md) |
| **L-nn** | Leak（漏れ） | **漏れの型**——作り込んだ不具合と、それをテストが見逃した理由 | [qa/03](qa/03_テストで漏らした実例.md) |
| **FB-nnn** | Feedback | **CLB への機能改善提案** | [CLB改善提案/01](CLB改善提案/01_機能改善提案.md) |
| **DOC-nnn** | Document | **CLB のマニュアルへの指摘** | [CLB改善提案/02](CLB改善提案/02_マニュアル改善提案.md) |
| **R*nn*-nn** | Review round | **自己レビューの指摘**（前が回、後ろが指摘の番号。`R35-01` = ラウンド 35 の 1 件目） | [qa/02](qa/02_自己レビュー記録.md) |
| **Q-nn** | Question | **開発者への問い**（急ぎの順。番号は使い回さない） | [05](05_開発者への問い.md) |
| **W-nn** | Work | **利用者の作業**（使いやすさの物差し。番号は使い回さない） | [06](06_利用者の作業.md) |
| **A1〜G2** | （略ではない。要件を並べた通し記号） | **優良な電子帳簿の要件**（A1 A2 A3・B1・C1 C1' C2・D1〜D4・E1〜E3・F1 F1' F1''・F2・G1 G2） | [40](40_優良な電子帳簿の対応表.md) |

### 2-1. 実機操作テストの手順の記号（[qa/04 §3](qa/04_実機操作テスト.md)）

**2026-09-21 に 1 文字から 3 文字にした**（開発者の指示。1 文字では qa/01 の A〜X と 33 個の番号が別物を指して重なっていた）。
**番号（`-nn`）は動かしていない。** 2 文字にしなかったのは、`AM`・`PM`・`CC` が一般の略語と同じ字になるからである。

| 記号 | 何の略か | 何の手順か | 2026-09-21 より前の記録での字 |
|---|---|---|---|
| **MST-nn** | **M**a**st**er | マスタ（読み出しの経路） | M-nn |
| **JNL-nn** | **J**our**n**a**l** | 振替伝票（入力と計上） | J-nn |
| **AMD-nn** | **Am**en**d**ment | 取消・訂正（Web API の経路） | A-nn |
| **BOK-nn** | **Bo**o**k** | 帳簿 | B-nn |
| **REG-nn** | **Reg**istration number | 登録番号（インボイス） | R-nn |
| **PRM-nn** | **P**e**rm**ission | 権限 | P-nn |
| **CNC-nn** | **C**o**nc**urrency | 同時操作 | C-nn |

**[qa/02](qa/02_自己レビュー記録.md) と [qa/04](qa/04_実機操作テスト.md) の年月ファイル（記録）は書き換えないので、2026-09-21 より前の記録は右端の字で書かれている**（[00 §3-3](00_ドキュメント規約/フロントマター.md)）。番号は同じなので、数字でそのまま引ける。
**記録の中だけで使った番号**（「見るもの」に振った `D-01`・`E-01` など）**は、その節の中の定義が優先する。他の文書からは指さない。**

## 3. 番号の振り方

**ここは記号（`L-nn`・`FB-nnn`・`MST-nn` など）の番号の話である。**
`docs/` 直下の**文書番号**は十の位がカテゴリを表し、
**役割が変われば動く**（[00 §8-1](00_ドキュメント規約/README.md)）。規則が違うので混ぜないこと。

- **一度どこかから指された番号（`-nn` の部分）は動かさない。** 新しい体系を起こすときに**空き番から始める**ことはある
  （実例: 登録番号の手順は REG-20 から始めた——R-07〜R-13 を 2026-08 の記録が別の意味で使っていたため）
- **接頭辞は、指し先が変わらないなら替えてよい**（`A-12` を `AMD-12` にしても、指している手順は同じ）。**替えた回は、旧⇔新の対応を §2-1 に残す**
- **欠番は正常**。`削除` を置いた欠番は経緯として正しい（[00 §4-12](00_ドキュメント規約/本文.md)）
- **新しい記号を作るときは、ここに 1 行足す**（何の略かも書く）。足さないと、半年後に読む人が引けない
