# 参照法令一覧

> **本書は「引くための文書」である。** 制度の中身は [`research/`](research/) が持ち、
> 設計上の決定は各設計文書が持つ。ここにあるのは**どの法令のどの版を見ているか**だけ。
> **本書が持つのは、法令・告示と、その解釈を示す通達・Q&A**である——略称・前提とする版・出典（種別の列で格が見える）。
> **それ以外の略語と記号**は [81_略語と記号](81_略語と記号.md)。

**並びは法令の群ごと**（電帳法の群 → 消費税の群 → 法人税の群 → 所得税の群 →
租税特別措置法の群 → その他の法律 → 告示）。**群の中は 法律 → 政令 → 省令 → 通達 → Q&A の順**。
**他法を改正する法律・政令・省令は §2 の表に載せず、§2-1 の表が本則・附則を条ごとに 1 行で持つ**（出典が条ごとに違うから。§2-1）。
**「種別」の列で格が見える**——通達と Q&A（一問一答を含む）は法令ではなく、国税庁の解釈と説明である（根拠の格付けは [00 §4-9](00_ドキュメント規約/本文.md)）。

**「出典」の列はその行の記述がどこにあるかを、「確認日・確認者」の列は誰がいつ開いて確かめたかを表す**（[32 §3](32_調査のルール.md)。**「根拠」1 列をこの 2 列＋備考に割ったのは Claude で、開発者の承認は 2026-09-13**）。
**2 つは別物である**——出典があっても、誰も開いていなければ確かめたことにはならない。
**どちらのラベルでも、見た範囲が原文の一部にとどまるときは括弧で限る**
（版まで見ていないなら「制定のみ」。限定が長いときは備考へ送り、確認者の欄に「範囲は備考」と書く。
**「確かめた」と「確かめた範囲」は別物である**——[qa/02 R41-06](qa/02_自己レビュー記録/2026-09.md)）。

| 確認日・確認者 | 意味 |
|---|---|
| **開発者確認** | **開発者**が出典を開いて原文を見た。日付を書く |
| **Claude 確認** | **Claude** が出典を開いて原文を見た。日付を書く |
| **Claude 機械検算** | **Claude** が法令 API のメタデータ（改定の一覧・施行日）で突き合わせた。**原文は開いていない** |
| **リサーチ経由** | [`research/`](research/) が出典つきで持っている値を写した。**この一覧を書いた者は原文を開いていない** |
| **未確認** | まだ誰も確かめていない |

**告示・通達・Q&A は e-Gov に無い**（告示は [電帳法リサーチ §14](research/2026-08-23_電子帳簿保存法.md)、通達と Q&A は 2026-09-13 開発者確認）。

## 1. 前提とする版

**基準日 2026-09-08。この日に施行済みの制度で動作し、成立済みで未施行のものまで考慮する。**
**値を 2026-09-08 とすることが開発者の決定である**（2026-09-09）。
**「施行済み＋成立済み未施行まで考慮する」という方針のほうは 2026-08-30 の開発者の決定**で、
理由は「**後の改正は先の改正の上に乗るので、先を外すと積み上がらないから**」である（値が動いても方針は動いていない）。
**この決定の正典は本節である**——[CLAUDE.md §0-2](../CLAUDE.md) はここへ誘導するだけ。

**以下は Claude の敷衍で、開発者は述べていない**（[00 §4-11](00_ドキュメント規約/本文.md)）。
**開発者が答えたのは値だけ**である。

- **基準日を「今日」に追随させない**——追随させると、どの版で動くアプリなのかが決まらなくなる
- **2026-09-08 を選んだのは、開発者が §2 の版を確かめ直した日だから**である
  （**選んだ理由であって、基準日の定義ではない**。確認の済んだ日を選べば、版を言い直す手戻りが無い）
- **動かすのは、下の手順を踏んだときだけ**とする

**基準日の値を持つのは本節だけである**（写しをリサーチ 3 本から落としたのは Claude。**開発者の承認は 2026-09-13**）。引く側は**値を写さず、ここへリンクする**
（**列挙で数えない**——誰が引いているかは増えるので、下の手順 5 で毎回 grep する）。
**`[施行済]` / `[今後施行]` の印**（[消費税リサーチ §0](research/2026-08-23_消費税インボイス制度.md) が定義）**と、
[電帳法リサーチ §0](research/2026-08-23_電子帳簿保存法.md) の「現行」は、この基準日で付いている。**

**「成立済みで未施行のもの」の本体は 2 つある**——
**所得税法等の一部を改正する法律（令和7年法律第13号）のうち、デジタルシームレス保存の規定**（令和 7 年度税制改正。2027-01-01 施行）と、
**所税法等一部改正法（令和8年法律第12号）**（令和 8 年度税制改正。2026-03-31 成立・公布）。
**この 2 つは独立していない**（後者の青色申告特別控除 75 万円が、前者を要件の選択肢に含む）。
**前者は「法律まるごとが未施行」ではない**——同法は**電帳法に 2025-04-01 で既に効いており**、
それが §2 の電帳法の行の「前提とする版＝令和7年4月1日施行版」である
（**2026-09-16 Claude 機械検算**。`410AC0000000025` の改正の一覧で、同法による版が
2025-04-01＝施行済み・2027-01-01＝未施行の 2 つに分かれる）。**法律ではなく規定で数える。**
**これで全部ではない。** 一覧は
[電帳法リサーチ](research/2026-08-23_電子帳簿保存法.md)・[消費税リサーチ](research/2026-08-23_消費税インボイス制度.md)。

**基準日と確認日は別物である。** 基準日は「どの時点の法令で動くか」、確認日は「いつ原文を見たか」。
**確認日は節ごとに違ってよい**——リサーチの出典行がそれぞれ持っている
（例: 電帳法リサーチ §1 の電帳法 2 二・電帳通達 2-1・4-1・4-2・4-4・8-7 の塊は 2026-09-02 確認）。

### 1-1. 基準日を動かすときにやること

**2026-09-09 に 2026-08-23 → 2026-09-08 を実際にやった手順である**（やった順にそのまま残す。
Claude が起こし、**2026-09-13 に開発者が承認した**）。
**`lint_docs.py` に置けないので文書に置いた**（[30 §9](30_作業のルール.md) が求める「上が使えない理由」）——
**基準日を動かすのは開発者の決定で、いつ動かすかを機械は判定できない。機械にできるのは手順 1〜3 の実行だけ**である。

1. **e-Gov の法令 API で、§2 の法令の行の「その日に施行されている版」を機械的に出し直す**
   （**告示・通達・Q&A は e-Gov で引けない**ので、**この手順に載るのは法律・政令・省令だけ**である。今回は 14 本）
   （`https://laws.e-gov.go.jp/api/2/law_revisions/<法令ID>` の `law_revision_id` は
   `<法令ID>_<施行日>_<改正法令ID>` の形なので、施行日で仕分ければよい）
2. **新旧の基準日の間に施行日がある法令を数える。** そこだけが動きうる範囲である
3. **その法令の全条文を新旧 2 版で取得し、機械的に差分を取る**
   （`https://laws.e-gov.go.jp/api/2/law_data/<law_revision_id>`。条の抜き出しは `Article` タグ。
   `attr.Num` が条番号で、`70_9` は 70 の 9 である）。
   **動いた条が、我々の引いている条かを見る**——引いている条の名簿は無いので `docs/` を
   **`消税令 ?[0-9]`** のように grep する。**空白を許すこと**（§3 が空白の入れ方を自由にしているので、
   `消税令[0-9]` だけでは `消税令 49` の側を 1 件も拾えない。実測で 14 件）
4. **動いた条を引いているリサーチの記述と、施行の印を直す**——
   **印は 2 通りある**（`[施行済]` / `[今後施行]` と、電帳法リサーチの「現行」。[81 §3](81_略語と記号.md)）
5. **`基準日` を `docs/` 全体に grep し、当たった行を全部見る**——
   本節と §2 の版の列、3 つのリサーチのほか、**[04](04_実装計画と現在地.md) のように
   「基準日時点」の語で判断を書いている文書**が漏れる（列挙で持つと必ず取りこぼす）

**結果は本節に書かない**（[00 §4-3](00_ドキュメント規約/本文.md)。経過は git log と
[qa/02 のラウンド 56](qa/02_自己レビュー記録/2026-09.md)、動いた条の中身は [消費税リサーチ §6・§7](research/2026-08-23_消費税インボイス制度.md) が持つ）。
**1 つだけ手順に残す価値のある事実がある**——**当たりを付けたのは人だった**。
開発者が口頭で「消税令 49」と指したので、手順 3 の grep より先に突合先が決まっていた。

## 2. 一覧

**数字はアラビア数字で書く**（正式には漢数字。**引きやすさを採った**。開発者の許可。2026-09-05）。
ただし、法令名は固有名詞であるから、法令名の中に出てくる漢数字は変えない。
なお、ここで略称を定義した法令等に言及する際は常に略称を用いること（開発者の指示。2026-09-06）。ここで略称が定義されていない法令等に言及する際は正式名称を用いること（何度も出てくる場合は、当該ドキュメント内に限り「××法（以下○○という。）」と略称を定めるか、本文書で略称を定義することを検討する。）。

**他法を改正する法律・政令・省令は、「○年改正法」「改正令」「改正省令」のような略称で呼ばない。略すなら「所税法等一部改正法（平成28年法律第15号）」のように法令番号を必ず添える**（開発者の指示。2026-09-11。<!-- lint-docs:abbrev-ok 規則そのものの説明 -->
**「所得税法等の一部を改正する法律」は歴史上無数にあり、同じ年に複数あることもある**ので、括弧書きの法令番号は省略できない。
通達が「改正法」「法」と略せるのは前後の文脈があるからで、それを引いて本書群で使うときは文脈が違う——**逐語引用だけが例外**）。
**`lint_docs.py` が「○年改正法」「改正法附則」「○○法改正法」「番号を落とした一部改正法」の形を error で拒む**（[00 §6](00_ドキュメント規約/README.md)）。<!-- lint-docs:abbrev-ok 規則そのものの説明 -->
**外してよいのは 4 つだけ**——①逐語引用 ②当時の記録（[qa/02](qa/02_自己レビュー記録.md)）③規則そのものの説明 ④検査の検体（`tools/docs/`）。
行末に `lint-docs:abbrev-ok 理由` を書く（**理由の無い印は効かない**。理由が 4 つのどれかは人が見る）。
**§2 の正式名称・法令番号・版を埋めるのは開発者である**（開発者の決定。2026-09-09。**理由は述べられていない**）。

**告示には略称を付けない**（開発者の指示。2026-09-09。
**「軽減税率のケータリング例外の金額を定める告示」のような呼び名は Claude が説明のために作った字で、
世間で通用していない**。通用しない名前を略称として定義すると、全文書がそれを使う羽目になる）。
**告示は告示番号で引き、内容の説明は備考の列か、引く側の文書で述べる。**

| 単位 | 書き方 | 例 |
|---|---|---|
| 条 | **アラビア数字** | 電帳規則 **5** |
| 項 | **丸数字** | 電帳規則 5 **⑤** | <!-- lint-docs:switch-ok 記法の例 -->
| 号 | **漢数字** | 電帳規則 5 ⑤ **一** | <!-- lint-docs:switch-ok 記法の例 -->
| 号の細分 | **イロハ** | 電帳規則 5 ⑤ 一 **イ** | <!-- lint-docs:switch-ok 記法の例 -->
| 号の細分のさらに細分 | **半角括弧つき数字** | 消税令 49 ① 一 ハ **(4)** |
| 枝番号の項 | **囲み数字**（1 文字） | 電帳通達 8-12 **⑵** |
| 条の枝番号 | 「の」でつなぐ | 税特措規則 **9 の 6**、消税規則 **15 の 4** |

`電帳規則 5 ⑤一イ` = 第 5 条第 5 項第 1 号イ。<!-- lint-docs:article-ok 記法そのものの説明 --> <!-- lint-docs:switch-ok 記法の例 -->

**この記法で書く。「5 条 1 項」「第 5 条第 1 項」と書かない**（開発者の指示。2026-09-06。<!-- lint-docs:article-ok 記法そのものの説明 -->
**揃っていないと grep が効かないから**。条がアラビア数字・項が丸数字・号が漢数字は
日本でよく使われる書き方である）。**`lint_docs.py` が error で拒む**（[00 §6](00_ドキュメント規約/README.md)）。

**条番号だけを裸で置かない**——直前に法令名か「同法」「同」を必ず添える
（`番号法 20 は、同法 19 各号に該当する場合を除いて`）。**何の条か分からなくなるから。**
なお、直前の法令名が略称か正式名称かにかかわらず、条番号の書き方は本項で定める記法に従うこと。

**空白の入れ方は文書によって揺れている**——
`消税法30⑦` と詰めている場合と `電帳規則 5 ⑤一イ` と開けている場合がある（フォーマッター等によって変動してしまい、統一が困難。）。**どちらでもよい**（読めるので）。 <!-- lint-docs:switch-ok 記法の例 -->

### 3-1. 「条・項・号」と書いてよい 4 つ

**この 4 つは条項の引用ではない。** 1 つ目は検査が形で外し、**残る 3 つは行末の印で外す**（下）。

| 何 | 例 | なぜ |
|---|---|---|
| **法令番号（公布番号）** | 令和3年政令**第128号**、平成10年大蔵省令**第43号** | **条項ではなく法令の識別子**である。書き換えるとその法令を指せなくなる |
| **法令の正式名称の一部** | 所得税法施行規則**第五十六条第一項**ただし書……の規定に基づき……を定める件 | **法令名は固有名詞である**（§2 の冒頭）。**漢数字のままなら検査に当たらない**ので印は要らない——印が要るのは、**原文がアラビア数字で書いている名称を逐語で引くとき**である |
| **逐語引用** | 「規則**第2条第2項**各号又は第3条第1項各号の要件に従って……」 | 国税庁の原文が書いている字である（開発者の指示。2026-09-06） |<!-- lint-docs:article-ok §3-1 の例 -->
| **記法そのものの説明** | 本節の `電帳規則 5 ⑤一イ` = 第 5 条第 5 項第 1 号イ | **規則が自分で落ちる** |<!-- lint-docs:article-ok §3-1 の例 --> <!-- lint-docs:switch-ok 記法の例 -->

**法令番号だけは検査が形で見分ける**——「〈法令の種類〉〈第〉〈N〉号」（「第」は無くてもよい）は条項の引用と紛れない。
**法令でない複合語**（「12 項目」「4 条件」「3.1 条文」など）も外れる——**外す字の一覧は `ARTICLE_UNIT_RE` が持つ**。
**残る 3 つは、行末に `<!-- lint-docs:article-ok 理由 -->` を置いて外す**（[00 §6](00_ドキュメント規約/README.md)）。
**汎用の `lint-docs:ignore` を使わない**——あれは節への参照の検査まで一緒に黙らせる
（2026-09-06 の自己レビューで、実際に 3 行が黙った）。
**走査した行数と外した行数を毎回印字する**ので、除外が黙って広がっても、走査が死んでも見える。
**条番号は改正で動く。** 優良な電子帳簿の要件は**現行が電帳規則 5 ⑤**、**2027-01-01 以後は電帳規則 5 ④**に移る
（新しい 5 ⑤ はデジタルシームレス保存の要件になる）。**本書とリサーチは新旧を併記し、設計文書とコードには現行番号だけを書く**——
経緯と決め方は [電帳法リサーチ §0-1](research/2026-08-23_電子帳簿保存法.md)。

**号の中の項目も動く。** 2026-09-01 に**消税令 49 ① 一 ハ (4)** が挿入され、
**従前の (4) は (5) へずれた**（§1-1）。**条番号だけでなく、号の細分まで版で変わる**ということである。
