# 参照法令一覧

> **本書は「引くための文書」である。** 制度の中身は [`research/`](research/) が持ち、
> 設計上の決定は各設計文書が持つ。ここにあるのは**どの法令のどの版を見ているか**だけ。
> **本書が持つのは、法令・告示と、その解釈を示す通達・Q&A**である——略称・前提とする版・根拠（種別の列で格が見える）。
> **それ以外の略語と記号**は [81_略語と記号](81_略語と記号.md)。

**並びは法令の群ごと**（電帳法の群 → 令和 8 年改正法 → 消費税の群 → 法人税の群 → 所得税の群 →
租税特別措置法の群 → その他の法律 → 告示）。**群の中は 法律 → 政令 → 省令 → 通達 → Q&A の順**。
**「種別」の列で格が見える**——通達と Q&A（一問一答を含む）は法令ではなく、国税庁の解釈と説明である（根拠の格付けは [00 §4-9](00_ドキュメント規約/本文.md)）。
**「根拠」の列は、この一覧の記述をどこまで確かめたか**を表す（[32 §3](32_調査のルール.md)）。

| 根拠 | 意味 |
|---|---|
| **e-Gov 確認** | e-Gov で原文またはリビジョンを見た。確認日を書く |
| **国税庁 確認** | 国税庁のページで原文を見た。確認日を書く。**何をどこまで見たかを括弧で限る**（版まで見ていないなら「制定のみ」）。**告示が e-Gov に収録されていないことは確認済み**（[電帳法リサーチ §14](research/2026-08-23_電子帳簿保存法.md)）。**通達と Q&A も e-Gov では引けないが、その裏は取っていない**——未確認 |
| **リサーチ経由** | [`research/`](research/) が出典つきで持っている値を写した |
| **開発者提供** | 開発者が示した値。**e-Gov では引き直していない** |
| **未確認** | まだ誰も確かめていない |

## 1. 前提とする版

**基準日 2026-08-23。この日に施行済みの制度で動作し、成立済みで未施行のものまで考慮する**
（開発者の決定。2026-08-30。**後の改正は先の改正の上に乗るので、先を外すと積み上がらないから**）。
**この決定の正典は本節である**——[CLAUDE.md §0-2](../CLAUDE.md) はここへ誘導するだけ。

**この基準日は 3 か所で一致している**（2026-09-05 に突き合わせて確認）——本節・
[電帳法リサーチ §0](research/2026-08-23_電子帳簿保存法.md)・
[消費税リサーチ §0](research/2026-08-23_消費税インボイス制度.md)。

**「成立済みで未施行のもの」の本体は 2 つある**——
**令和 7 年度改正**（本体は**デジタルシームレス保存の新設**。2027-01-01 施行）と、
**令和 8 年法律第 12 号**（令和 8 年度税制改正。2026-03-31 成立・公布。**「大綱」ではなく成立済みの法律**）。
**この 2 つは独立していない**（後者の青色申告特別控除 75 万円が、前者を要件の選択肢に含む）。
**これで全部ではない。** 一覧と、基準日を動かすときの洗い直しは
[電帳法リサーチ](research/2026-08-23_電子帳簿保存法.md)・[消費税リサーチ](research/2026-08-23_消費税インボイス制度.md)。

**基準日と確認日は別物である。** 基準日は「どの時点の法令で動くか」、確認日は「いつ原文を見たか」。
**確認日は節ごとに違ってよい**——リサーチの出典行がそれぞれ持っている
（例: 電帳法リサーチ §1 の電帳法 2 二・電帳通達 2-1・4-1・4-2・4-4・8-7 の塊は 2026-09-02 確認）。

## 3. 条番号の書き方

| 単位 | 書き方 | 例 |
|---|---|---|
| 条 | **アラビア数字** | 電帳規則 **5** |
| 項 | **丸数字** | 電帳規則 5 **⑤** |
| 号 | **漢数字** | 電帳規則 5 ⑤ **一** |
| 号の細分 | **イロハ** | 電帳規則 5 ⑤ 一 **イ** |
| 枝番号の項 | 括弧つき数字 | 電帳通達 8-12 **⑵** |
| 条の枝番号 | 「の」でつなぐ | 税特措規則 **9 の 6**、消税規則 **15 の 4** |

`電帳規則 5 ⑤一イ` = 第 5 条第 5 項第 1 号イ。

**この略記法でよい**（開発者の指示。2026-09-05。**条がアラビア数字・項が丸数字・号が漢数字は
日本でよく使われる書き方だから**）。**空白の入れ方は文書によって揺れている**——
リサーチは `消税法30⑦` と詰め、設計文書は `電帳規則 5 ⑤一イ` と空ける。**どちらでもよい**（読めるので）。
**条番号は改正で動く。** 優良な電子帳簿の要件は**現行が電帳規則 5 ⑤**、**2027-01-01 以後は電帳規則 5 ④**に移る
（新 5 項はデジタルシームレス保存の要件になる）。**本書とリサーチは新旧を併記し、設計文書とコードには現行番号だけを書く**——
経緯と決め方は [電帳法リサーチ §0-1](research/2026-08-23_電子帳簿保存法.md)。

## 4. 埋めるもの

**本節の宿題はすべて「フェーズ 3 の着手前」が期限である**（4 件。2026-09-06 に数え直した）。
[04 の「着手の前に済ませるもの」](04_実装計画と現在地.md)がここを名指しで引いている。

**「未確認」の法令番号を e-Gov で埋める。** 消税令・消税規則・法税法・所税令・所税規則・税特措法・税特措規則の 7 本と、
**法税規則の公布番号**（法令 ID は分かっているので、番号だけ）。
[00 §4-9](00_ドキュメント規約/本文.md) が一次情報を求めているので、**二次資料からは埋めない**。

**消税基本通達の最終改正を国税庁で確かめる。** 制定の日付と番号は原文で確認済みだが、
**いまの版がいつの改正か**を見ていない（通達は e-Gov に無いので、国税庁のページで見るしかない）。

**根拠の格が 2 行だけ揃っていない。** どちらも**この一覧の書き方の問題で、制度の中身の問題ではない**。

- **電帳通達**は出典に国税庁の PDF と確認日（2026-08-25）を持っているのに、根拠が「リサーチ経由」である。
  **誰が原文を開いたのかが分からない**ので、確かめ直して「国税庁 確認」に上げるか、リサーチ経由のまま残すかを決める
- **消税法**の法令番号は「開発者提供」で、凡例が自ら**e-Gov では引き直していない**と断っている。
  **「未確認」の 7 本と一緒に e-Gov で引き直す**

**消税軽減通達の差し替え先を国税庁で確かめる。** 廃止の事実は §2 の行と
[消費税リサーチ §10](research/2026-08-23_消費税インボイス制度.md) が持つ。
**未確認なのは「内容が消税基本通達のどの項へ移ったか」だけ**である。

**法令番号と根拠の格は急ぎではない**——条文の中身は各リサーチが出典つきで持っており、番号が無くて困るのは
「同じ略称の別の法令と取り違える恐れがあるとき」だけである。
**ただし消税軽減通達の差し替えは急ぐ。** 制度の当てはめが変わりうるので、
**フェーズ 3 で消費税に入る前に開発者に聞く**（[32 §1](32_調査のルール.md)）。
