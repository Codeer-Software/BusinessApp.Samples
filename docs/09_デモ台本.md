## 1. オープニング — ホーム画面（2分）【メッセージ: 経理の朝が1画面で始まる】

admin でログイン → ホーム。

> 「ログインした瞬間に、**今日やること**と**会社の今**が見えます。承認待ち、未処理の銀行明細、支払期限、当月の売上・費用・利益——そして**資金繰りの警告**。ここまでが標準画面です」

- 指差し: ⚠「2026-08 に資金ショートの予測」→ クリックせず「後でこの正体をお見せします」と引きを作る

## 2. 看板デモ① — 銀行明細の取込→AI仕訳→残高照合（5分）【freee/MF の核心機能】

銀行 > 明細取込。

1. 用意した CSV を貼り付け → 「明細を取り込む」
   > 「銀行サイトの CSV をそのまま貼るだけ。**摘要のルール**（AWS→通信費、家賃→地代家賃…）はマスタで、経理が自分で育てられます」
2. ルール未該当の行を指して「AIで相手科目を推定」→ 候補が入る（実 Azure OpenAI）
   > 「ルールで拾えない明細は **AI が科目を提案**。もちろん人が最終確認して直せます」
3. 「候補科目で一括起票」→ 消費税が自動で税抜分解されるのを仕訳帳で1件見せる
4. 銀行 > 残高照合 → 全日付「○ 一致」
   > 「**銀行残高と帳簿がいつでも突合**。月次締めの銀行勘定調整が一瞬です」

## 3. 看板デモ② — AI 領収書読み取り（3分）【実AIの実演】

ichiro（一般社員）の窓に切替 → 申請 > 経費精算 > 新規。

1. スマホで撮った領収書を「AI読み取り（添付＋自動入力）」でアップロード
   > 「日付・金額・支払先・**費目まで自動入力**。領収書も同時に添付されます。AI を使うかはユーザーの選択（オプトイン）です」
2. 案件を選んで申請 → 「承認ルートは**金額×費目で自動決定**。3万未満は課長、20万超は部長＋総務の2段です」
3. （時間があれば）hanako で承認 → admin で仕訳生成 → 「承認が終われば**仕訳は自動**。固定資産なら台帳にも自動登録されます」

## 4. 会計コアの実力 — 財務三表＋月次推移（4分）【「弥生の代替」の根拠】

帳票メニューを上から順に。

- 合計残高試算表 → 「最下段に**貸借検算行**。合わない状態では確定できない設計です」
- 貸借対照表・損益計算書 → 年度切替
- **月次推移表** → PL/BS 切替 → 「BS も**全12ヶ月で貸借一致**を検算済み」
- **キャッシュ・フロー計算書** → 「財務三表が揃っています。中小向けソフトで C/F まで出るものは実は少ない」
- 資金繰り予測 → ホームの⚠の正体を回収 → 「未回収請求・未払い・人件費から**4ヶ月先の資金**を予測します」

## 5. IT受託の決め手 — 案件損益・SES・年払い（3分）【ペルソナ特化＝market gap】

> 「ここからが**受託ソフトハウスのための機能**——市販ソフトが一番弱いところです」

- 案件 > 案件損益 → 「売上も経費も人件費配賦も**案件別**に。経費申請で案件を選ぶだけで直課されます」
- 案件 > SES精算・請求 → 精算計算 → 「**精算幅（140-180h）と超過・控除単価**で請求額を自動計算。内訳ごと請求書になります」
- 販売 > 定期請求の実行 → 「SaaS の月額も**年額の前受・按分**も自動。冪等なので何度実行しても安全です」
- 販売 > 請求書 → 詳細の「請求書を出力（Excel/PDF）」→ 「見積書・請求書は**レイアウト帳票で1枚ずつ出力**。テンプレートは Excel ファイルなので、御社のロゴ・様式への差し替えは Excel を編集するだけです」

## 6. 購買と支払 — 請求書受領から振込データまで（2分）

- 購買 > 仕入先請求書 → 未払計上 → 支払予定表（⚠期限警告）
- 購買 > 振込データ作成 → 「**全銀フォーマットの総合振込データ**まで出ます。バンキングに貼り付けるだけ」

## 7. 導入提案パート — 移行・権限・改正対応（2分）【「御社で使える」】

- 仕訳 > 仕訳インポート → 「**弥生等からの移行は CSV 貼り付け**。行を無加工で取り込むので1円もズレません。給与ソフトの仕訳もこれで入ります」
- 権限: ichiro の画面と admin の画面を並べて → 「**3ロール**。経理業務は経理だけ、URL 直打ちもサーバで拒否します」
- 改正対応: マスタ > 税区分・設定 > 制度閾値 → 「税率・インボイス経過措置・少額資産の閾値は**全部マスタ**。改正は行を足すだけです」

## 8. クロージング — CLB の生産性（1分）

> 「このアプリは **73画面**をローコード定義で作り、コンパイルが必要な追加 C# は **約1,000行だけ**——それも AI 呼び出しと国税庁 API という『CLB の外の世界』とつなぐ部分に限定しています。**業務の作り込みはすべてローコード側**。だから御社の業務に合わせた改造も、この速度でできます」

## 想定 Q&A

| 質問 | 答え |
|---|---|
| 請求書の PDF は？ | 見積書・請求書とも1枚ずつの帳票出力に対応（Excel/PDF・検証済み）。テンプレは Excel なので様式変更が容易 |
| スマホ対応は？ | CLB は PageFrame のデバイス出し分けに対応（本デモは PC 最適化。スマホ用フレームは追加実装） |
| 銀行 API 連携は？ | 契約・認証が必要なため CSV 取込を標準に。API は個別導入で拡張可能 |
| 電子帳簿保存法は？ | 証憑添付と検索性は実装済み。タイムスタンプ等の完全準拠は運用要件に合わせて拡張 |
| 決算期が3月でないが？ | 会計年度マスタで任意に設定可能。月次推移表なども自動追随 |
| 既存データの移行は？ | 仕訳 CSV インポート＋開始残高（期首残高画面）で移行。デモ可能 |
