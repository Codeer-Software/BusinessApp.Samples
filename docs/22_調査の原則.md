# 調査の原則

> **記憶で決めない。** 制度も市販ソフトの実態も、確かめてから書く。
> **調べた結果の書き方**（出典 URL・確認日・施行日・何を根拠にしてよいか）は
> [00 §4-9](00_ドキュメント規約/本文.md) が正典である。本書は**いつ・何を調べ、どう使うか**を書く。

**この文書の育て方**

- **手順ではなく判断を書く。** 検索のやり方は書かない。「調べるかどうか」「調べ終わったと言えるか」を書く
- **00 §4-9 の内容を写さない**（[00 §4-6](00_ドキュメント規約/本文.md)）。根拠の格付けはあちらが持つ
- 原則が覆るときは ADR を起こす

## 1. 調べてから実装する（省略できる場面は無い）

税制・会計基準・電子帳簿保存法は毎年変わる。**記憶や思い込みで決めない。**
`WebSearch` / `WebFetch` で確かめ、**`docs/research/` に記録してから**実装する。

**何を根拠にしてよいかは [00 §4-9](00_ドキュメント規約/本文.md) が持つ**（ここに写さない）。

**少しでも怪しければ開発者に聞く。** 法令・税制については**開発者が最も確かな確認先**であり、
一次情報に当たってなお迷うときは推測で埋めずに確認する。過去のリサーチへの不安も同じ。

**どの時点の制度に合わせるか**は [13 §1](13_参照法令一覧.md) が決めている。

## 2. 市販ソフトも調べる

目標は「対象ペルソナが他の会計ソフトを使わなくて済むこと」なので、
**freee・マネーフォワード・弥生・PCA・勘定奉行が何をどう実装しているかは、市場ニーズの一次データ**である。
機能の要否・入力制御の厳しさ・帳票の粒度・**画面での呼び名**で迷ったら、**まず調べる**。

- **合わせることが目的ではない。** 市販ソフトの仕様は「多数の顧客に売るための妥協」を含む。
  本プロジェクトは対象ペルソナが決まっているので（[02](02_ペルソナ.md)）、あえて違う選択をしてよい
- ただし**違う選択をするなら理由を書く**。「市販ソフトはこうだが、本プロジェクトはこうする。なぜなら〜」
- 記録は `docs/research/` に `YYYY-MM-DD_市販会計ソフト比較_<主題>.md` の名前で残す

## 3. どこまで調べたかを必ず書く

**「調べた」と「調べ尽くした」は違う。** 調査記録には、**調べていない範囲**を同じ強さで書く。

- **何社を見たか**（実例: 登録番号の呼び名は**弥生 1 社だけ**で、他社は未調査。
  [市販会計ソフト比較 — 登録番号の呼び名](research/2026-08-28_市販会計ソフト比較_登録番号の呼び名.md)）
- **ページを開いて確かめたか、検索結果の要約から読んだだけか**（同じ調査に両方が混ざっている。
  見分けが付く形で並べる）
- **確認できなかったこと**を独立した節にする（実例:
  [取引先の識別番号と公表システム](research/2026-08-25_取引先の識別番号と公表システム.md) の「確認できなかったこと」）

**この節が守っているのは、後から読む人が「もう調べなくてよい」と誤解しないことである。**
未確認を書き落とすと、次に読んだ人はそれを確定事実として使う。**本プロジェクトで実際に起きた**——
[ADR-0015](decisions/0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md) は当初
「税理士業界標準の TKC が同方式」と書いたが、「業界標準」に出典が無く、あとで限定を戻している。

## 4. 事実と判断を分ける

**調査記録には事実を、設計文書には判断を書く**（[06 の冒頭](06_消費税設計.md)がこの分離を宣言している）。

- リサーチに「本プロジェクトはこうする」を書くのは構わないが、**事実の節とは分ける**
- 設計文書に制度そのものの説明を写さない。**リンクする**（[00 §4-6](00_ドキュメント規約/本文.md)）
- **「〜と思われる」で書いた推測を、別の文書で事実として使わない**

自己レビューの文書 5 観点のうち (2) と (5) がこの分離を見ている
（[`self-review` スキル](../.claude/skills/self-review/SKILL.md) §5）。

## 5. 調べ直す契機

- **制度に触れる実装の前**に、該当する `research/` の節を読む（[05 §4](05_実装計画と現在地.md)）
- **確認日が古い記述を使うとき**は、最終改正が今年でないかを見る（[00 §4-9](00_ドキュメント規約/本文.md)）
- **未確認として残した項目に実装が到達したとき**は、そこで調べ直す。
  各文書の保留リストが「いつ決めるか」を持っている（[00 §4-4](00_ドキュメント規約/本文.md)）

**調査そのものも振り返る。** その調査は判断を変えたか、かけた時間に見合ったかを毎回考える。
[31 §4](31_検証のルール.md) が**検証**について定めた考え方を、**調査にも当てる**
（Claude の判断。2026-08-29。31 §4 の指示は検証ループが対象で、調査は含んでいない）。
