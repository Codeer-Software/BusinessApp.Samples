# ペルソナ — 株式会社アルタイルシステムズ（架空）

> 作成: 2026-07-05 / 更新: 2026-08-02（部品アーキテクチャ再編 ADR-0040/0041 反映） / 本アプリの機能・データモデル・デモデータはすべてこの会社を基準に設計する。
> 選定理由（上位方針）: CLB の買い手＝ソフトを作る会社。デモの聴衆とペルソナが一致し、「自分ごと化」が最速で起きる。

```
代表取締役（オーナー）
├─ 管理部（6名）: 部長1・経理2・総務労務2・情シス1
├─ 営業部（5名）: 部長1・営業4
├─ 開発1部（受託・20名）: 部長1・PM3・エンジニア16
├─ 開発2部（受託/SES・18名）: 部長1・PM2・エンジニア15
```

- 部門コード: 管理／営業／開発1／開発2／SaaS の5部門＋全社共通。

## 5. 現状の痛点（本アプリが解決するもの）

1. **案件別の損益がリアルタイムに見えない。** 会計ソフト（弥生）は科目別集計のみ。案件別は経理が月末に Excel で工数×単価を手集計 → 翌月中旬にやっと判明し、赤字案件の手当てが常に手遅れ。
2. **工数原価が会計とつながっていない。** 勤怠・工数は別システム。人件費の案件配賦が「どんぶり」。
3. **SaaS 年額プランの繰延処理が Excel 管理。** 前受収益の月次按分を経理が手作業で仕訳化しており、ミス・漏れが怖い。
4. **経費精算が紙とメール。** 領収書のり付け→部長ハンコ→経理が弥生へ手入力の二度手間。月末に集中して残業の温床。
5. **資金繰りが経営者の勘。** 受託の入金は検収ずれで凸凹が激しく、賞与月・納税月の残高不安が常にある。
6. **SES の精算計算が属人化。** 精算幅（140-180h）の超過/控除計算を営業が個別 Excel で行い、請求ミスが年数回起きる。
7. インボイス対応で、フリーランス外注（免税事業者が数名残る）の**経過措置の控除計算（2026年10月から70%）**を手管理するのが不安。

## 6. デモデータの基準値（フェーズAで作成するサンプルの前提）

- 会計年度: 第17期（2025-04-01〜2026-03-31、締め済み）と第18期（2026-04-01〜、進行中）。
- 月間仕訳数: 200〜400件程度（年間約 3,000〜4,000件）を想定したデータ量で性能も確認する。
- 主要取引先: 得意先10社（受託5・SES3・SaaS法人2）、仕入先/外注先10社（うち免税事業者2）。
- 進行中案件: 受託4件（うち1件は赤字傾向）・SES 8名分・SaaS 契約120社（デモでは集約管理）。
