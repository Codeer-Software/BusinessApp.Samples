# 経費精算（案）

> 注: 2026-08-02 の部品再編（ADR-0040/0041）以前の記述を含む。現行の権限・画面は docs/10 参照。

これは別プロジェクトにおいて作成した機能仕様の案。
これに完全に従う必要はないし、今回のペルソナや機能スコープに合わない部分もあるので、それは今回のペルソナや機能スコープを優先すること。
ただ、フェーズBの経費精算は大きな流れとして基本的にこんな感じだとユーザーはイメージしているので、参考とすること。


## 1. 概要・目的

社員が支出した／する経費を、**申請 → 承認 → 経理処理（仕訳確定）→ 精算/支払**まで一気通貫で扱うモジュール。

- **科目×金額による承認ルートの自動決定**（条件分岐ワークフロー）
- **AI領収書読み取り → 事実の自動入力＋仕訳案の自動生成**
- ファイル添付・承認権限者へのSlack/メール通知

## 2. 登場人物（ロール）

| ロール | 役割 |
|---|---|
| **申請者（一般社員）** | 経費を申請する。費目・事実情報は入力するが、仕訳（会計処理）には関与しない |
| **承認者（課長／部長）** | 金額区分に応じて支出の妥当性を承認する |
| **総務部（経理担当）** | 交際費・高額支出の承認に加え、**全件の仕訳を確定**し、精算/支払を実行する |

## 3. 申請の2軸

経費は次の2軸の組み合わせで表現する。1モジュール＋区分フィールドで吸収する。

**軸1：申請区分（承認と支出の前後関係）**
- **立替精算（事後）**：社員が既に支払済み。領収書あり。金額は実費で確定。
- **事前申請（事前）**：これから支払う/買う。申請時は**見込み額**、購入後に**実費**が確定。

**軸2：支払先区分（誰に払うか）**
- **社員へ精算**：社員が立て替えた分を本人へ返金。
- **取引先へ支払**：会社が業者へ直接支払（請求書払い・法人カード等）。

代表的な組み合わせ：

| ケース | 申請区分 | 支払先 | 例 |
|---|---|---|---|
| 立替精算 | 事後 | 社員へ | 駐車場代 500円（もう払った） |
| 事前申請＋社員立替 | 事前 | 社員へ | 書籍 3,000円（承認後に社員が購入して精算） |
| 事前申請＋会社払い | 事前 | 取引先へ | 備品 15万円を業者に発注、会社が振込 |

## 4. AIの関与（AI領収書読み取り）

**呼び出しは申請時の1回のみ**（領収書画像は大きく、複数回のAI読み込みはトークンの無駄）。1回の呼び出しで**事実項目＋費目案＋仕訳案をまとめて取得し、DBに保存**する。

| AIが出すもの | 保存先 | 誰が使う/直すか |
|---|---|---|
| **事実**：利用日・金額・支払先・消費税額 | 各事実フィールド | 申請者が確認・修正（自分が使ったので検証可能） |
| **費目案**（経費区分） | 費目フィールド | 申請者が確認・選択（承認ルートを決める） |
| **仕訳案**：借方勘定科目・税区分・補助科目・摘要 | 仕訳フィールド群 | 申請者には**非表示 or グレーアウトの参考情報**。**経理が経理処理段階で確認・修正・確定** |

- 実装は **サーバ経由のカスタムC#サービス**（`AppInfoService.cs` に登録）。ブラウザ(WASM)直叩きは CORS/APIキーの都合で不可（[03](../03_機能スコープ.md) 技術メモ参照）。
- OCR＋LLM（Claude API 等）に領収書画像を渡し、構造化JSON（日付/金額/支払先/税額/費目/勘定科目/税区分）を受け取る。

## 5. 画面・入力項目（申請フォーム）

`ExpenseRequest` を拡張する。★＝AIが申請時に自動入力する項目。

### 共通項目

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| 件名 | Text | ○ | 申請の件名 |
| 申請日 | Date | ○ | 既定は当日。編集可（さかのぼり申請に対応）。※システムの申請日時（監査用 `CreatedAt`）とは別の業務項目 |
| 申請区分 | Select | ○ | 立替精算 / 事前申請 |
| 支払先区分 | Select | ○ | 社員へ精算 / 取引先へ支払 |
| 費目（経費区分）★ | Select | ○ | 旅費交通費・会議費・交際費・消耗品費・備品・外注費・通信費・図書研修費・諸会費・その他。**承認ルートを決める**。候補は**費目マスタで追加・編集可能** |
| 利用日★ | Date | ○ | 経費の発生日（店舗での支払日）。申請日とは別 |
| 利用先（店名・相手先）★ | Text | ○ | **どこで使ったか**（レシートの発行元）。AIが抽出。※会社が払う相手（下記「精算先／支払先」）とは別概念 |
| 消費税額★ | Number | － | AIが抽出。税区分の判断材料 |
| 目的・内容 | Text(複数行) | ○ | 何のための支出か |
| 部門／プロジェクト | Link | ○ | 予算管理・部門別集計の軸 |
| 領収書 | File | 立替は○ | 画像/PDF。AI読み取りの入力。事前申請は購入後に添付 |

### 精算先／支払先（支払先区分で出し分け）

「利用先（お金を払った店）」とは別に、**会社が誰に払うか**を持つ。ここが第3節・軸2の実体。

| 支払先区分 | 項目 | 型 | 説明 |
|---|---|---|---|
| 社員へ精算 | 精算対象者 | Link(社員) | 立て替えた社員。**既定＝申請者本人**、社員一覧から変更可（代理申請に対応） |
| 取引先へ支払 | 支払取引先 | Link(取引先マスタ) | 支払先の業者。支払期日の管理に使う |

### 表示項目（入力ではない・自動表示）

| 項目 | 説明 |
|---|---|
| 予算（自動表示） | **部門×費目**が確定すると、その組み合わせの**予算額・消化額・残額**を読み取り専用で表示。申請者が予算状況を意識できる。予算超過警告はこの値を基に発火する。予算は「部門×費目×年度（期）」で保持

### 金額（申請区分で出し分け）

| 項目 | 型 | 説明 |
|---|---|---|
| 見込み額 | Number | **事前申請のみ**。承認ルート判定に使う申告値 |
| 金額（実費）★ | Number | 立替＝申請時に確定（AI抽出）。事前＝購入後に入力 |

### 費目による例外項目

**交際費のとき（必須表示）**
| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| 接待の相手先 | Text | ○ | 「誰と」 |
| 参加人数 | Number | ○ | 1人あたり金額の把握 |
| 接待の目的 | Text | ○ | 「何のために」 |

**備品（資産性のある支出）のとき**
| 項目 | 型 | 条件 | 説明 |
|---|---|---|---|
| 固定資産フラグ | Boolean | 金額10万円以上で自動ON | 会計上の固定資産計上対象 |
| 資産管理番号 | Text | フラグON時に必須 | 資産台帳登録用 |

### 仕訳案（AI生成・経理が確定）

申請者には非表示 or グレーアウト。経理処理段階で編集可能になる。

| 項目 | 型 | 説明 |
|---|---|---|
| 借方勘定科目★ | Link/Select | 費目に対応する勘定科目のAI提案 |
| 貸方勘定科目 | Link/Select | 既定＝未払金（精算/支払前）。経理が確定 |
| 税区分★ | Select | 課税仕入10%／軽減8%／対象外 等 |
| 補助科目★ | Text | AI提案 |
| 仕訳摘要★ | Text | AI生成の摘要 |
| 仕訳確定フラグ | Boolean | 経理が確認・確定したらON |

## 6. 承認ルートの自動決定

### 6.1 承認テンプレート（既存エンジンを流用）

`SampleProject_AuthPatterns` の承認エンジン（`ApprovalFlowTemplate` → `ApprovalFlowTemplateOrder`（順番）→ `ApprovalFlowTemplateMember`（承認者・必須/任意））をそのまま使う。以下4テンプレートを用意する：

| テンプレート名 | 承認順 |
|---|---|
| `課長のみ` | ①課長 |
| `部長のみ` | ①部長 |
| `課長＋総務` | ①課長 → ②総務 |
| `部長＋総務` | ①部長 → ②総務 |

> 承認者の解決（誰が課長/部長か）は申請者の所属部門から引く。デモでは部門マスタに「課長」「部長」を持たせる想定（詳細は `マスタ.md` で）。

### 6.2 テンプレート選択ロジック

`ExpenseRequest.mod.cs` の `SelectTemplateName()`（既存は金額のみ）を、**費目×金額**を見るよう拡張する。判定は **事前申請なら見込み額、立替なら実費**で行う。

```
string SelectTemplateName()
{
    var amount = (申請区分 == 事前申請) ? 見込み額 : 実費;
    // 上長レベル：3万円未満は課長、以上は部長
    var level = (amount < 30000) ? "課長" : "部長";
    // 総務チェックが要るか：交際費は金額不問で必須／20万円以上も必須
    var needsSomu = (費目 == 交際費) || (amount >= 200000);
    return level + (needsSomu ? "＋総務" : "のみ");
}
```

この1関数で承認ルール（3万/20万の3段階＋交際費の総務必須）が表現できる。備品の固定資産は**ルートを変えず**、フラグと資産管理番号の入力を課すだけ。

### 6.3 実費が見込みを超過したとき（事前申請）

「上限承認」の考え方：事前申請の承認は「この金額を上限に支出してよい」という枠の承認。購入後に実費を入れた時点で判定する。

| 条件 | 扱い |
|---|---|
| 実費で算定したテンプレートが承認済と**変わる**（区分跨ぎ） | **必ず再承認**（新テンプレートで承認フローをやり直す） |
| 区分は同じだが実費 > 見込み × **1.10** | 再承認 |
| 区分が同じ かつ 実費 ≤ 見込み × 1.10 | 追加承認なし。そのまま経理処理へ |

- 精算/支払額は**常に実費**。見込み額で精算することはない。
- 再承認は既存エンジンの「再申請」機構（`Resubmit`：古いOrderを削除しテンプレから再構築）を流用する。

## 7. ステータス遷移

承認フェーズ（`ApprovalFlow.Status`＝ Pending/Approved/Rejected/Cancelled）に加え、経費全体の進行を表す**精算ステータス**を `ExpenseRequest` に持つ。

### 立替精算（事後）

```
下書き → 申請中(承認中) → 承認済 → 経理処理中(仕訳確定) → 精算済 → 完了
              │
              ├─ 却下 →（再申請）→ 申請中
              └─ 取消
```

### 事前申請（事前）

```
下書き → 申請中(承認中) → 承認済(購入可) → 購入・実費入力
     → ［実費判定：超過なら再承認へ戻る］
     → 経理処理中(仕訳確定) → 精算/支払済 → 完了
```

- **経理処理中**は全件共通の下流フェーズ。ここで経理が仕訳案を確認・修正して確定 → 精算/支払を実行 → `出納帳` へ出金記録、`会計ソフト連携` の仕訳CSV対象になる。
- 却下・取消は既存エンジンの `Reject` / `Cancel`、残りの承認者は `Skipped` になる（`ApprovalFlow.mod.cs` 実装済み）。

## 9. 設計判断

- **経理の仕訳確定は承認ルートの外の下流フェーズ**。承認は承認で完結し、実費確定後に全件共通の「経理処理中」フェーズを通す（承認テンプレートに経理を足さない）。
- **精算対象者**は既定＝申請者本人、**社員一覧から変更可**（代理申請対応）。
- **申請日**は当日既定・編集可（さかのぼり申請）。
- **利用先（店名）／精算対象者（社員）／支払取引先** を別項目として分離。
- 部門×費目の**予算を申請フォームに自動表示**（読み取り専用）。予算超過警告の発火点。
