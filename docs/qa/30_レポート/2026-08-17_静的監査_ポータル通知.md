### 1.1 `date('now')` の UTC ずれ（重点確認事項 #8）— 白

`Designer/Design` 配下の全 `*.sql` / `*.mod.cs` を対象に、`date('now'` / `'now'` /
`strftime` / `CURRENT_TIMESTAMP` / `CURRENT_DATE` / `julianday` を全数走査した結果、
**`localtime` 修飾を欠いた `'now'` の使用は 1 件も無い**（唯一のヒットは
`PortalQueueData.Query.sql:10` の注意書きコメント本文）。

- `PortalQueueData.Query.sql` — `date('now','localtime','start of month')` および
  `strftime('%Y','now','localtime')` / `strftime('%m','now','localtime')` を一貫使用（25〜73 行）。
- `PortalKpiData.Query.sql` — `date('now','localtime')` を一貫使用（6・11・32〜33 行）。
- `PortalTodoData.Query.sql` — 日付判定を持たない。
- `MonthlyTrend.Query.sql:16` / `CashFlowForecastData.Query.sql:105` の `strftime` は
  **列の値**に対する整形であり `'now'` を含まないため無関係。

結論: ポータルの「今日」「今月」判定に JST/UTC ずれの経路は残っていない。確度: **確定**。

- `[Authorize]` + `[AutoValidateAntiforgeryToken]`（23-24 行）。

クライアント側（`PasswordChange.mod.cs:49-63`）が持つのは
「空欄」「新旧確認の不一致」だけで、**ポリシー判定をクライアントに複製していない**

### [P1-1] ホームの「進行中のあなたの申請」と MyApplication 画面が別ソースで、却下された申請で食い違う

- 症状: ホームは 0 件と言うのに、「申請中」画面には行が残る（またはその逆）。
- 根拠:

### [P1-3] PortalTodoData だけ読み取りガードが無く、全ユーザー分の承認待ち・申請中件数が読める

- 場所: `Designer/Design/Modules/Shell/PortalTodoData.mod.json`
- 症状: 全有効ユーザーの「承認待ち N 件 / 申請中 N 件」が、権限に関係なく読み取り可能。
- 根拠:
  - `PortalTodoData.Query.sql:5-11` は `FROM app_users u WHERE u.is_active = 1` で
    **1 ユーザー 1 行を全件返す**（`user_id` 付き）。

    `UserReadCondition = {"ModuleName": ""}`（空）。

    `PortalKpiData` / `PortalQueueData` は `UserReadCondition = AppUser.HasAccountingAccess == true`、

    **PortalTodoData だけが例外**で、意図的な設計判断の記録も docs/13 に無い。

- 確度: 条件が空であることは**確定**。実際に外部から読めるかは CLB のモジュール読み取り API の
  到達性に依存するため **要実機確認**。

### [P1-4] 会計期間が未整備だと KPI 6 項目が無言で全て 0 円になる

- 場所: `Designer/Design/Modules/Shell/PortalKpiData.Query.sql:4-12, 37-43`
- 症状: 決算期末〜新年度作成前など、**今日を含む `fiscal_years` / `fiscal_periods` が無い**期間に
  ポータルを開くと、現預金・売掛金・買掛金・当月売上高・当月費用・当月利益が
  すべて「0 円」と表示される。エラーも警告も出ない。
- 根拠:
  - `cur` CTE（4-7 行）が空になると、`bs` の `opening_balances`（15-16 行）も

  - `per` CTE（8-12 行）が空になると、`pl` の `date(e.entry_date) >= (SELECT date(start_date) FROM per)`
    がスカラサブクエリ NULL との比較になり全行 false。当月売上・費用・利益が 0。
  - `PortalHome.mod.cs:196-208` は `kpiRows.Count > 0` しか見ておらず、
    「値が 0」と「期間が無いので計算できない」を区別できない。1 行は必ず返るので分岐しない。
- 「現預金 0 円／当月売上 0 円」は経理にとって虚偽の情報であり、
  ブランクや「会計年度が未設定です」の表示と区別されるべき。
- 確度: **確定**（SQL の字面から導ける）

### [P1-5] 通知の宛先は申請時のスナップショットで、以後の部門メンバーシップ変更に追随しない

- 場所: `Designer/Design/Modules/Expense/ApprovalFlow.mod.cs:23(LoadFromTemplate), 118, 131, 724-747`

- 症状: 申請の進行中に承認者が交代（課長の異動・新任・`department_managers` の付け外し）しても、

### [P2-3] Acceptance の「請求書を開く」が SalesStaff フレームで解決できない（FB-023）

### [P3-6] SES 精算幅の下限・上限を C# 側だけ int にキャストしている

- 場所: `Designer/Design/Modules/Sales/SesBilling.mod.cs:147, 154` vs
  `Designer/Design/Modules/Shell/PortalQueueData.Query.sql:57-60`
- 症状: `ses_lower_hours` / `ses_upper_hours` が整数でない場合、
  ホームの SES 未生成件数と SesBilling 画面の plan 件数が境界案件でズレる。
- 根拠: C# は `int shortage = (int)lower - hours;` / `int over = hours - (int)upper;` と
  **切り捨ててから**差を取る。SQL は `(s.lo - (s.mins / 60)) * s.deduct` と生値で計算する。
  時間の切り捨て（`minutes / 60` と `s.mins / 60`）は両者一致しているので、
  差が出るのは lo/hi が小数のときだけ。
- なお、それ以外の SES 判定条件（`is_active` / `status='active'` / `ses_monthly_rate > 0` /
  実績 1 分以上 / 精算後金額 1 円超 / 当月 SES 請求書の不存在）は
  SQL（`PortalQueueData.Query.sql:37-60`）と `BuildPlan`（`SesBilling.mod.cs:91-211`）で**一致**していた。
  対象月の既定値も両者 `DateTime.Today` の月初（`SesBilling.mod.cs:20-23` /
  `RecurringRun.mod.cs:17-20`）で一致している。
- 確度: 計算式の差は **確定**。実害の有無は lo/hi のカラム型とデータ次第で **要実機確認**。
