# 実機操作テスト

**サーバを起動してブラウザで操作し、画面の挙動を確かめる。**
[31 §2](../31_検証のルール.md) の「実機で操作していない機能は、できていないものとして扱う」を
実行するための手順書である。

**`dotnet test` が全部通っても、それは「C# のロジックが正しい」までしか言っていない。**
前回プロジェクトの実測で、**コード上は正しく見えてもブラウザで操作すると動かない**ことが
繰り返し起きた（[qa/01](01_CLB静かな失敗.md)）。CLB は静的検査がほとんど効かない層なので、
画面・保存・遷移は実際に触るまで分からない。

**この文書の育て方**: 本書は**規則（§1・§2）と手順（§3）だけ**を持ち、書き換える。**記録は §4。**
**記録の中で「何を見るか」に番号を振るなら、`MST-01` のような字は使わない**——
§3 の手順と [qa/01](01_CLB静かな失敗.md) の記号に当たる（[81 §2-1](../81_略語と記号.md)）。
**「見るもの 1」のように書く。**

実機で確かめられることが何も無いからである。

**「1 点だけの修正」の行は開発者の決定である**（2026-09-20。
**§3 の手順は 149 項目（全件は印の 4 件を除いた 145 項目。2026-09-20 の数——2026-09-24 には 157 項目、2026-09-25 には 158 項目）あるので、1 行の修正に全件を課すと、規則のほうが先に折れるから**）。
**判定の中身を変える修正はこの行に入らない**——判定はどの画面からも通るので、触った画面だけでは足りない。

**「挙動を変えないリファクタリング」でも流す。** 変えないつもりだったかどうかは、
画面が動くかどうかと関係が無い。

**複数の行が同時に当たったときの優先**（開発者の決定。2026-09-20。「3 日以上」を 1 に足したのは 2026-09-21。権限と保存の関門の 2 行と、

1. **「フェーズの区切り」か「3 日以上」が当たるなら、§3 は全件流す。**
   ほかの行の「＋ …」の部分（触った画面・変えたテーブルを使う画面）**は足す**——
   フェーズの行は手順の中しか言っていないので、そのままでは他の行を含まない。
   **全件は毎回実施する項目を含む**ので、別に数えない。
2. **「1 点だけの修正」は、フェーズの区切り・権限・保存の関門の 3 行を除く他の行に勝つ。**
   **この行が免除するのは毎回実施する項目である。**
   **権限と保存の関門に負けるのは、「その節を全部実行する」理由が 1 行の修正でも変わらないからである。**
   **当たるかどうかは表の行の括弧が決める**（判定の中身・画面・スキーマを変えていないこと）。
3. **それ以外は、当たった行の和を採る。**「広いほう」では決まらない組がある——
   CLB のデザインの行と DB スキーマの行は、**どちらも他方を含まない**。
   **どの行に当たるかで迷うなら、流す側に倒す。**
4. **優先を使った回は、§4 が指す年月のファイルの記録にそう書く。**
   「1 点だけ」かどうかを決めるのは Claude なので、**後から読み直せる形で残す。**

**§3 を全件流すのにかかる時間とトークンは、[記録](04_実機操作テスト/2026-09.md) の 2026-09-21 と 2026-09-24 の節が持つ。**

## 2. 観測の作法

| 見たいもの | 正しい見方 | やってはいけないこと |
|---|---|---|
| **書けたか・何が残ったか** | **DB を見る**（`sql` CLI） | 画面の表示だけで判断する |
| 画面の状態（入力値・活性/非活性） | **スクリーンショットを見る** | `get_page_text` で読む（`<input>` の value を拾わない。[qa/01](01_CLB静かな失敗.md) G-07） |
| トーストの文言 | **押す前に `MutationObserver` を仕込む**（下） | 押してから捉えに行く（消えている。[qa/01](01_CLB静かな失敗.md) G-05） |
| 一覧の件数 | 削除のあとは**再検索してから**読む | 削除の直後の件数を信じる（行だけ減って件数が古い。[qa/01](01_CLB静かな失敗.md) D-14） |
| 遷移したか | URL とスクリーンショット | |

**操作が Blazor に届かないことがある**（[qa/01](01_CLB静かな失敗.md) G-01〜G-04）。
入力は実クリック＋実タイピングで行い、**結果は必ず DB で確かめる**。

**出力は全部読む。確かめに行った 1 点だけを見て、残りを「確認済みの背景」として流さない**
（実行した形と処方は [qa/03 L-39](03_テストで漏らした実例.md)）。**見た文字列は §4 が指す年月のファイルの記録に写す**——
写すと読むことになる。

### 2-0. 道具の作法（2026-09-23 に実測）

- **パスワードの欄は `form_input` で入れる。** `computer` の `type` で打つと、
  **ハーネスの分類器が「Credential Exploration」として続けて拒む**（[qa/01 G-15](01_CLB静かな失敗.md)）。
  **同じ字が 1 回目は拒まれ 2 回目は通る形も 5 回以上あった**ので、**拒まれたら書き方を変える**のが速い。
- **件数の書式は 0 件のときだけ違う。** ふだんは `(1-50 /105件)` だが、**0 件のときは `(0件)`** になる。
  **件数で判定する項目を機械で読むときは、両方の形を当てる。**
- **赤字の注意書きが出る画面では、開いた直後の座標で叩かない。**
  注意書きが入ると**その下の欄やボタンが下へずれる**（登録番号の追加画面で実測。2026-09-23 は注意書きが上段にあり、入力欄が 170px ほどずれた。
  **2026-09-24 に注意書きをボタンの行の直前（本文の末尾）へ移したので、いまずれるのはボタンの行のはずである**——Claude の読み。注意書きの出る画面のボタンの位置は測ったが、出ない画面と比べてはいない）。**撮り直して取り直す。**

### 2-1. トーストを捉える

**押す前に**張っておけば取れる。押してから捉えに行くと間に合わない。

**探す語は目印にだけ使う。そこから `slice` しない**——**探す語より前にある字が、必ず落ちる。**
**2026-09-23 に実際に踏んだ**（「いま開いているのは」を目印にしたので、
**その前の「取消を計上しました。」が定義上ぜったいに入らなかった**。
アプリは正しいのに「トーストが途中から出ている」と読み、確かめ直す 1 往復を使った）。
**読むのはトーストの要素の `innerText` 全体**である。

**読むのは `#toast-container` である。** **`.toast` というクラスは付いていない**——
実物は `#toast-container`（`toast-bottom-right`）の中の **`div.toaster.toast-error`** で、
**`closest('.toast')` は 1 つも当たらない**（2026-09-23 に実測。
**その形の雛形をここに書いて、同じ日の実機で「1 つも取れない」を踏んだ**）。

```js
window.__cap = [];
new MutationObserver(() => {
  const box = document.querySelector('#toast-container');
  if (!box) return;
  const now = box.innerText.trim();
  if (!now) return;
  window.__cap.push(now);                                           // 足された瞬間
  setTimeout(() => {
    const later = box.innerText.trim();
    if (later) window.__cap.push(later);                            // 描き終わった後
  }, 450);
}).observe(document.documentElement, { childList: true, subtree: true, characterData: true });
```

押したあと `[...new Set(window.__cap)]` を読む。
**`document.body` ではなく `document.documentElement` に張る**（トーストは body の外に出ることがある）。
**2 通り（足された瞬間・450ms 後）を両方押すのは、描き途中を拾っていないことを自分で確かめるため**である
——**字が違えば描き途中で、同じなら描き終わっている。** 2026-09-23 の 2 本は、どちらも一致した。
**要素をそのまま読むと、頭に閉じるボタンの `×` が付く**ので落として比べる。
**トーストは 2 枚同時に出ることがある**（保存の関門の断りと「更新に失敗しました」）ので、
**`#toast-container` をまとめて読むと 2 枚ぶんが改行で連なる。**

これで 2026-08-26 に
`計上できません（2 件）。①借方合計 1,000 円と貸方合計 900 円が一致していません。②行 1: …`
を実際に捉えた。**「トーストは開発者に頼むしかない」は解消した**（前回プロジェクトからの積み残し）。

### 2-2. ブラウザ操作の落とし穴（このハーネス固有）

| 症状 | 事実 | どうするか |
|---|---|---|
| クリックが効かない | **要素参照（ref）経由のクリックは Blazor に届かないことがある** | **スクリーンショットの座標で実クリックする** |
| 座標がずれる | スクリーンショットは幅 1568 に**縮尺されている**。CSS 座標とは別物 | `k = 1568 / window.innerWidth` を掛けて変換する。**2 回掛けない** |
| `<input type="date">` に入力できない | **届かない回と届いた回がある。** 届かない回は、CDP のキー送出も `insertText` も値が空のまま（フォーカスは当たる）。**2026-09-24 には、空の欄への `type` が毎回届いたサブエージェント（実機操作テストを流した 1 人）がいる**——**月日の区画を先に打ち、年の区画を最後に打つと値が確定した**（年を先に打つと、あとで月を打ったときに年が消える）。**何で分かれるかは分かっていない。** **値の入った欄を区画の座標クリックで直すと壊れた**（年の区画に 6 桁入る・年と月が消える。同日） | **先に `type` を試し、届かなかったときだけ代わりを使う**（Claude の判断。2026-09-24）——代わりはネイティブ setter ＋ `change` イベントで値を入れ、**検索ボタンは実クリックする**（値の入れ方だけが代替で、検索の経路は本物を通る）。**値の入った欄を直すときは、区画ごとに `Backspace` で空にしてから、月日 → 年の順に打ち直す** |
| 文字の欄に `type` が届かない | ページを開いた直後や検索欄で、`type` の文字が入らないことがある（2026-09-10・11。フォーカスは当たる） | `value` を入れて `input`・`change` を発火させる（Blazor の束縛はこれで更新され、関門まで届く——2026-09-11 の S-03）。**日付の欄と同じ形** |
| スクリーンショットが `timed out` | 描画の途中に当たると落ちる | **もう一度撮る**（2 回目はほぼ通る）。バッチの末尾に置かず単独で撮ると安定する。**`timed out` の次の 1 枚が「拡大された一部」や「縮小した絵」になることがある**（縮小の側は 2026-09-22 に踏んだ——`innerWidth` は変わっていないのにページ全体が左上 1/4 に写った）ので、**2 回で足りるとせず、絵が期待と違ったらもう一度撮る**（2026-09-20） |
| 描画途中を撮ってしまう | 件数やボタンが**まだ出ていない**状態が写る | 「無い」と判定する前にもう一度撮る |
| 手順のために変えたデータを戻せない | **`UPDATE` は変える前の値を返さない。** 一括で変えると、どれが元からその値だったのかが消える（2026-09-08 に取引先の `is_active` で実行した） | **変える前に `SELECT` で控える。** 控えを取らずに変えてしまったら、**画面のスクリーンショットが唯一の証拠**になる |

**複数のサブエージェントで並行して操作する回は、先に [qa/01](01_CLB静かな失敗.md) の G-11〜G-13 を読む**（背面のタブ・`navigate` の直後・`ctrl+a` の 3 つの落とし穴）。

## 3. 手順（実機操作テストの項目）

前提: `pwsh -NoProfile -File tools/clb/deploy.ps1` → サーバ起動
（`dotnet run --project BusinessApp/BusinessApp.Server --launch-profile http`）→

#### 振替伝票の画面に出る字の期待値

**この 12 本は、画面が出す字と 1 文字も違わない**——
**`- 振替伝票の期待値 n:` で始まる行を、`JournalAmendmentEndpointTests` の `台本の期待値は画面の組む文と一致する` が
画面の定義（`JournalEntry.mod.cs` の文字列と `JournalEntry.mod.json` の `Text` / `RawHtml`）と突き合わせている。**
**日付と会計年度の表示名は伝票ごとに変わる**ので、機械はそこだけ潰してから比べる。
**印を `振替伝票の` で始めているのは、この文書が全画面の台本を 1 枚に持つから**である
——ただの「期待値」にすると、別の節が同じ印を使った瞬間にこの検体が赤くなる。

- 振替伝票の期待値 1: この伝票を取り消します。よろしいですか？
- 振替伝票の期待値 2: この伝票を取り消します。取引日（2025/05/20）は「第 17 期（2025 年度）」にあります。その年度の消費税等に影響します。よろしいですか？
- 振替伝票の期待値 3: この伝票を訂正します。取消を計上し、内容を写した訂正の下書きを開きます。取引日（2025/05/20）は「第 17 期（2025 年度）」にあります。その年度の消費税等に影響します。よろしいですか？
- 振替伝票の期待値 4: この伝票を訂正します。取消は既に計上されているので作らず、内容を写した訂正の下書きだけを開きます。取引日（2025/05/20）は「第 17 期（2025 年度）」にあります。その年度の消費税等には、取消の分が既に影響しています。よろしいですか？
- 振替伝票の期待値 5: この伝票を取り消します。取引日（2024/05/20）は、いまの会計年度より前です。その日を含む年度の消費税等に影響します。よろしいですか？
- 振替伝票の期待値 6: 入力の決まり／1 枚の伝票には 1 つの取引を記します。／「摘要」には取引の内容を書きます（帳簿の記載事項です）。下書き保存では空のままでも保存でき、「計上する」ときに必要です。／明細の「貸借」「勘定科目」「金額」「税区分」は、下書き保存のときにも必要です。／明細の「補助科目」は、勘定科目の「補助科目を使う」がオンのとき、計上のときに必要です。オフのときは空にします。／明細の「部門」は、勘定科目の「科目区分」が「収益」「費用」のとき、計上のときに必要です。／伝票の「取引先」は、勘定科目の「取引先を要する」がオンの明細があるとき、計上のときに必要です。明細の「取引先」が空のときは伝票の「取引先」が使われるので、行ごとに相手方が違うときだけ、その行の「取引先」を選んでください。
- 振替伝票の期待値 7: 取消と訂正／取消は、記した取引をはじめから無かったことにする操作です——記帳を誤ったときと、取引がはじめから無かったことになったときに使います。／正しい内容で記し直すなら、「訂正する」を押してください。／取引はあったうえで、あとから返品・値引き・割戻しがあったときは、元の伝票を取り消さずに、新しい伝票で記してください。／できた取消伝票は帳簿に残り、あとから消せません。
- 振替伝票の期待値 8: 「*」は必須項目です。ただし「摘要」は「計上する」ときに必要で、伝票の「取引先」は明細の全行で選べば空のままでも計上できます。
- 振替伝票の期待値 9: 入場券等の回収特例（1 回 3 万円以上）に当たる仕入れは、明細の「内容」欄に取引先の住所を記載してください。
- 振替伝票の期待値 10: 取り消しました。いま開いているのは取消伝票です。
- 振替伝票の期待値 11: 取消を計上しました。いま開いているのは訂正の下書きです。内容を直して計上してください。
- 振替伝票の期待値 12: いま開いているのは訂正の下書きです。取消は増えていません。内容を直して計上してください。

**期待値 6・7 の `／` は箇条書きの区切りである**（画面では 1 つずつ別の行に、黒丸つきで出る）。
**先頭の「入力の決まり」「取消と訂正」は見出しで、黒丸は付かない。**
**期待値 8 は画面の冒頭の凡例**（`*` の打ち消しがここにある——[21 §1](../21_画面の原則.md)）、
**期待値 9 は明細の直前の 1 文**（欄を名指しして打鍵を指示するので、欄から離さない）。
**期待値 10〜12 は「はい」を押したあとに出るトースト**である
（10 が取消、11 が通常の訂正、12 がやり直しの訂正。**AMD-13・AMD-14・AMD-15 の「はい」の側で出る**）。
**2026-09-23 に足した**——**それまで機械に守られていなかった**。
