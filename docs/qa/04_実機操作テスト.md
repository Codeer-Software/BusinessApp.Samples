# 実機操作テスト

**サーバを起動してブラウザで操作し、画面の挙動を確かめる。**
[CLAUDE.md §4-1](../../CLAUDE.md) の「実機で操作していない機能は、できていないものとして扱う」を
実行するための台本である。

**`dotnet test` が緑でも、それは「C# のロジックが正しい」までしか言っていない。**
前回プロジェクトの実測で、**コード上は正しく見えてもブラウザで操作すると動かない**ことが
繰り返し起きた（[qa/01](01_CLB静かな失敗.md)）。CLB は静的検査がほとんど効かない層なので、
画面・保存・遷移は実際に触るまで分からない。

**この文書の育て方**: §4 の記録は 1 回 1 節。**節が 12 を超えたら**古いものを年月ごとの
ファイルへ移す。台本（§3）は移さない。

## 1. いつ流すか

| 契機 | 流す範囲 |
|---|---|
| CLB のデザイン（`*.mod.json` / `*.mod.cs`）を変えた | 触った画面 ＋ §3 の通し |
| `AccountingCore` / `AccountingCore.Server` を変えた | **§3 の通し**（画面の裏は全部ここを通る） |
| DB スキーマを変えた | §3 の通し ＋ 変えたテーブルを使う画面 |
| フェーズの区切り | §3 の全件 |

**「挙動を変えないリファクタリング」でも流す。** 変えないつもりだったかどうかは、
画面が動くかどうかと関係が無い。

## 2. 観測の作法（ここを間違えると半日溶ける）

| 見たいもの | 正しい見方 | やってはいけないこと |
|---|---|---|
| **書けたか・何が残ったか** | **DB を見る**（`sql` CLI） | 画面の表示だけで判断する |
| 画面の状態（入力値・活性/非活性） | **スクリーンショットを見る** | `get_page_text` で読む（`<input>` の value を拾わない。[qa/01](01_CLB静かな失敗.md) G-07。**この誤診で半日溶かした**） |
| トーストの文言 | **押す前に `MutationObserver` を仕込む**（下） | 押してから捉えに行く（消えている。[qa/01](01_CLB静かな失敗.md) G-05） |
| 一覧の件数 | 削除のあとは**再検索してから**読む | 削除の直後の件数を信じる（行だけ減って件数が古い。[qa/01](01_CLB静かな失敗.md) D-14） |
| 遷移したか | URL とスクリーンショット | |

**操作が Blazor に届かないことがある**（[qa/01](01_CLB静かな失敗.md) G-01〜G-04）。
入力は実クリック＋実タイピングで行い、**結果は必ず DB で確かめる**。

### 2-1. トーストを捉える

**押す前に**張っておけば取れる。押してから捉えに行くと間に合わない。

```js
window.__cap = [];
new MutationObserver(() => {
  const t = document.documentElement.innerText || '';
  const i = t.indexOf('計上できません');      // 探す文言
  if (i >= 0) window.__cap.push(t.slice(i, i + 400));
}).observe(document.documentElement, { childList: true, subtree: true, characterData: true });
```

押したあと `[...new Set(window.__cap)]` を読む。
**`document.body` ではなく `document.documentElement` に張る**（トーストは body の外に出ることがある）。

これで 2026-08-26 に
`計上できません（2 件）。①借方合計 1,000 円と貸方合計 900 円が一致していません。②1 行目: …`
を実際に捉えた。**「トーストは開発者に頼むしかない」は解消した**（前回プロジェクトからの積み残し）。

### 2-2. ブラウザ操作の落とし穴（このハーネス固有）

| 症状 | 事実 | どうするか |
|---|---|---|
| クリックが効かない | **要素参照（ref）経由のクリックは Blazor に届かないことがある** | **スクリーンショットの座標で実クリックする** |
| 座標がずれる | スクリーンショットは幅 1568 に**縮尺されている**。CSS 座標とは別物 | `k = 1568 / window.innerWidth` を掛けて変換する。**2 回掛けない** |
| `<input type="date">` に入力できない | **CDP のキー送出も `insertText` も届かない**（フォーカスは当たる。値は空のまま） | ネイティブ setter ＋ `change` イベントで値を入れ、**検索ボタンは実クリックする**。値の入れ方だけが代替で、検索の経路は本物を通る |
| スクリーンショットが `timed out` | 描画の途中に当たると落ちる | **もう一度撮る**（2 回目はほぼ通る）。バッチの末尾に置かず単独で撮ると安定する |
| 描画途中を撮ってしまう | 件数やボタンが**まだ出ていない**状態が写る | 「無い」と判定する前にもう一度撮る |

#### 見つけて直したもの

1. **新規作成の画面から直接「計上する」を押すと必ず失敗していた**（本番不具合）。
   CLB は仮 ID の対応を `SourceId` / `DestinationId` で返すのに、`TemporaryIdMap` だけを見ていた。
   **テストの土台が同じ勘違いをしていたので、緑のまま通っていた**。[qa/03 L-10](03_テストで漏らした実例.md)
2. **保存が失敗しても計上へ進んでいた**（本番不具合）。本当の理由が捨てられ、
   利用者には「ID を解決できない」という二次的な内部エラーだけが届いていた。同 L-10
3. **金額の書式が画面とトーストで食い違っていた**（画面「1,000」／トースト「1000」）。
   `Yen.ToString()` を 3 桁区切りにして**型に持たせた**——呼ぶ側に選ばせると必ずまた分かれる

#### 分かった作法

- **トーストは捉えられる**（§2-1）。前回プロジェクトからの積み残しが 1 つ消えた
- `<input type="date">` にはこのハーネスから打鍵できない（§2-2）。B-02 の日付だけ値を注入し、
  **検索は実クリック**で通した

### 2026-08-26（取引先名と登録番号の写しを計上時に焼き込む）

登録の手入力画面（`PartnerInvoiceRegistration`）を作り、写しを焼く経路を通した。

| # | ねらい | 結果 |
|---|---|---|
| R-01 | 登録の一覧・新規作成が開く | ○ |
| R-02 | **壊れた登録番号を関門が止める** | ○ 「登録番号の形が違います。登録番号は「T」で始まる 14 桁（T のあとに数字 13 桁）です。」。**DB に 1 行も残らない** |
| R-03 | 正しい登録番号は保存できる | ○ `source` は DB の既定で `manual` が入る（画面に出していない） |
| J-06 | **計上すると写しが焼かれる** | ○ 取引先を伝票に持つ伝票を計上 → 両行に `partner_name_snapshot` と `registration_no_snapshot` が入る |
| J-07 | **計上後に改名しても帳簿の記載は変わらない** | ○ マスタ「株式会社アルタイル」／帳簿「株式会社アルタイル商事」 |

#### 見つけて直したもの

1. **二重登録の関門が本番だけ死んでいた。** CLB は日付を `"2023-10-01 00:00:00"` と時刻付きで
   書くので、`valid_from = '2023-10-01'` という文字列の比較がいつも外れていた。
   テストは素の `'2023-10-01'` を入れていたので緑だった（[qa/03 L-12](03_テストで漏らした実例.md)）
2. **`tax_point` を入力する画面が無く全行 NULL** だったので、登録番号の写しが永久に空になる
   状態だった。取引日で引くように変えた（[07 §4-1](../07_取引先設計.md)）
3. **テストの土台が NULL を空文字に化けさせていた**ので、「写しが入っていない」という表明が
   必ず通っていた（[qa/03 L-11](03_テストで漏らした実例.md)）

#### 分かった作法

- **新しい列を足したら、実機で 1 件通して値が入ることを見る。**
  「入れる画面が無いので永久に空」は単体テストでは絶対に見えない
- **画面の入力は座標がずれやすい**（ページ拡大率が操作中に変わる。§2-2）。
  入力そのものが目的でない検査では、**下書きを `sql` で用意して「計上する」だけを押す**と速い。
  計上の経路は本物を通るので、確かめたいことは確かめられる
