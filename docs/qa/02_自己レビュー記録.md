# 自己レビュー記録

[CLAUDE.md §3-2-1](../../CLAUDE.md) の自己レビューで出た指摘と、**採否の判断**を残す。

**指摘をそのまま全部反映しない。** レビューは意見であって仕様ではないので、
直すもの・直さないもの・後回しにするものを決める。

**ここに残すのは「後から理由を聞かれるもの」だけ**である。直した軽微な指摘は
コミットが記録しているので書かない。**直さないと決めたもの**と**後回しにしたもの**を、
理由つきで残すことに価値がある。

分割方針: 1 ラウンド 1 節。節が 10 を超えたら年ごとのファイルに分ける。

## 2026-08-24 ラウンド 2（仕訳の入力と計上が通った時点）

観点を分けて 2 人に読ませた。**会計ドメインと計上経路の穴**と、
**設計・依存の向き＋テストの十分性**。後者には「カバレッジ 100% に騙されていないか」を明示して問うた。

結果: 37 件（会計 14 / 設計 23）。直したものはテスト 373 件緑・
`AccountingCore` と `AccountingCore.Server` のカバレッジ 100% のまま反映した。

**この 2 件は、放っておけば必ず帳簿を壊していた。**

- **金額に小数が入る余地があった。** CLB の数値フィールドに小数桁の制限が無く、
  SQLite の `INTEGER` は `100.5` を整数に落とせず REAL のまま格納し、読み出し側の
  `Convert.ToInt64` が黙って丸めていた。借方 1000.5 / 貸方 1000.4 が
  「どちらも 1000」として貸借一致で計上され、DB には 0.1 円ずれた値が残る（I-01 が破れる）。
  画面・DDL（`typeof`）・読み出しの 3 か所すべてで塞いだ
- **最初から計上済みとして INSERT する道が DB に開いていた。** 他のトリガが UPDATE も DELETE も
  明細の追加も止めるので、**貸借不一致・明細ゼロの計上済み伝票が恒久的に残り、訂正も取消も
  できなくなる**。`BEFORE INSERT` のトリガで塞いだ

**テストの指摘で最も効いたのは次の 2 つ。**

- 本番の呼び順（`Prepare` → 保存 → `CompleteAsync`）は、並べ替えても `Prepare` を消しても
  47 件すべて緑のままだった。しかも `Prepare` を消すと関門が**完全に迂回される**。
  入口を `SubmitAsync(data, save)` の 1 本にして、順番を型で保証した
- 会計年度が初期データに 1 本しか無いので、`where fiscal_year_id = @p1` を**消しても
  100% のまま緑**だった。I-17 は製品の中核なのに DB 層では未証明だった。年度を 2 本にして検査した

### 解決済み: 「仕訳の新規画面が初期値を出さない」は**私の誤診だった**

半日をこれに溶かしたので、原因と教訓を残す。

- **実際には画面は最初から正常だった。** 開発者が手で開くと初期値も計上も問題なく動いた
- **誤診の原因**: `get_page_text` で画面を読んでいたが、**この API は `<input>` の value を拾わない**。
  伝票番号を読み取り専用に変えたあたりから、値付きで見える項目と見えない項目が混ざり、
  「全部空」と読み違えた（[qa/01](01_CLB静かな失敗.md) G-07）
- **なぜ長引いたか**: 誤った観測を疑わず、**原因の側だけを 9 通り切り分けた**
  （デザインを戻す・DB を作り直す・キャッシュを消す・C# を戻す…）。
  すべて「再現する」と出たので、そのたびに「原因は別にある」と結論した。
  **観測が間違っていれば、切り分けは何回やっても収束しない**
- **教訓**: 画面の状態を判定するときは**スクリーンショットを見る**。
  テキスト抽出は補助に留める。§3-2-0 で引く前に、**まず観測手段そのものを疑う**

なお、この過程で拡張機能の接続不良も重なった（[qa/01](01_CLB静かな失敗.md) G-08）。
Chrome とセッションの再起動で復旧した。

### 実機で確認したこと（2026-08-24）

観測手段を直したうえで、フェーズ 1 の完了条件をすべて実機で確認した。

- 新規作成で取引日・計上日・会計年度・状態に初期値が入る
- 明細の行番号・借貸が自動で入り、税区分が勘定科目の既定から入る
- 貸借不一致で計上すると**行番号つきの違反**が返り、**伝票も明細も採番も残らない**
- 貸借一致で計上すると伝票番号が付き、画面がその場で閲覧専用になる
- 金額は `typeof(amount) = 'integer'` を満たして保存されている
