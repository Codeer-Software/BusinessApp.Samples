# 利用シナリオ集（総合テスト用）

> 作成: 2026-07-06 / 目的: 典型的なユーザーストーリーに沿って「こんな操作をしたらこんな結果が得られる」を確認する総合テストの台本（ユーザー要望）。
> 実装済みの全機能（フェーズ A 会計コア／B 周辺業務／B' 管理会計）を、**一般社員・承認者・経理**の3ロール視点で網羅する。
> 各シナリオは独立して読めるが、S-01→S-10 の順に流すと「申請→承認→会計→帳票→経営分析」の一連のストーリーになる。

## S-01 経費申請（立替・少額）→ 課長承認 【一般社員・承認者】

**ストーリー**: 開発部の社員が 3 万円未満の旅費を立て替えたので精算したい。

1. admin でログイン → 申請 > 経費精算 > 新規作成
2. 件名・金額（例 8,000）・利用日・費目=旅費交通費 を入力 → 申請区分は既定の「立替精算」、精算対象者は既定で本人
3. 「申請」を押す
- **期待**: トースト「申請しました」。フロー表示「状態:進行中 ✓(申請者)→▶承認 花子」（3万未満 → **課長のみ**ルートが自動選択）。精算ステータス=申請中。**花子に通知**（承認依頼）が作成される
4. hanako でログイン → ホームの「未読の通知」に承認依頼 → 「開く」
- **期待**: 該当申請へ遷移し通知が既読化。申請内容は編集不可（グレーアウト）
5. 「承認」を押す
- **期待**: 状態=承認済・精算ステータス=承認済。**申請者に「承認されました」通知**

**バリエーション**: 金額 3万〜20万 → 承認者が**部長 次郎**に変わる。20万以上 → **部長→総務**の2段。却下するとステータスが下書きへ戻り申請者が再申請できる。

## S-02 交際費申請（例外項目＋総務併載） 【一般社員】

**ストーリー**: 取引先との会食費を精算したい。交際費はコンプライアンス上、相手先の記録と総務の確認が必須。

1. admin で経費新規作成 → 費目=**交際費** を選ぶ
- **期待**: 「接待の相手先・参加人数・接待の目的」の3項目が**出現**する
2. 3項目を空のまま「申請」
- **期待**: 赤トースト「交際費は相手先・参加人数・目的の入力が必須です」で**ブロック**される
3. 3項目を入力して申請
- **期待**: 金額が3万未満でも**課長→総務**の2段ルート（交際費は常に総務併載）

## S-03 事前申請 → 実費超過 → 自動再承認 【一般社員・承認者】

**ストーリー**: 出張前に見込み 25,000 円で事前申請し承認を得たが、実費は 40,000 円かかった。

1. admin で経費新規作成 → 申請区分=**事前申請** に変更
- **期待**: 「見込み額」欄が出現（立替では非表示）
2. 費目=旅費交通費・見込み額 25,000 で申請 → 花子（課長）が承認
3. admin で申請を開く → 「実費（税込）」欄に 40,000 → 「実費を確定」
- **期待**: 区分跨ぎ（3万超え）＋見込み×110%超のため**自動で再承認へ**。トースト「実費が見込みを超過したため再承認を依頼しました」。ルートが**部長 次郎**に再解決され、履歴に超過理由が記録される
4. jiro が承認 → 経理処理へ進める

**バリエーション**: 実費 26,000（区分内・110%以内）なら再承認は走らず、そのまま仕訳生成可能になる。

## S-04 経理処理: 仕訳生成 → 支払 → 出納帳 【経理】

**ストーリー**: 承認済の経費を会計に取り込み、精算金を支払う。ここからは経理専用の世界（A×B 一体化の接点）。

1. admin（経理）で承認済の経費を開く
- **期待**: 「仕訳を生成」ボタンが見える（**承認者ロールでは見えない**）
2. 「仕訳を生成」
- **期待**: トーストに伝票 No と金額。仕訳は D 費目の既定科目（税抜本体）＋ D 仮払消費税 ／ C 未払金（税込）。仕訳帳・試算表に即反映。ステータス=経理処理中。**備品×10万円以上の申請は D が工具器具備品になり、固定資産台帳へ自動登録**（EXP-{id}、取得価額=税抜）
3. 「精算済にする」
- **期待**: 支払仕訳（D 未払金／C 普通預金）が自動生成。帳票 > 出納帳（普通預金）に出金行が現れ残高が減る
4. 「完了にする」 → ステータス=完了

## S-05 販売サイクル: 見積→受注→検収→請求→入金 【営業＋経理】

**ストーリー**: 受託案件の商談から入金までを一気通貫で管理する。売上計上は検収基準（ADR-0008）。

1. 販売 > 見積 > 新規作成: 取引先・件名・明細（数量×単価で金額自動計算・税抜合計表示）→ 保存（Q-26-xxx 採番）
2. 「受注にする」
- **期待**: 受注 SO-26-xxx が明細コピー付きで生成され自動遷移。見積は「受注」状態に
3. 販売 > 検収 > 新規作成: 受注を選択
- **期待**: 検収額（受注明細合計）と消費税額が自動セット
4. 保存 → 「検収を確定（売上計上）」（**経理のみ実行可**）
- **期待**: 売上仕訳（D 売掛金=税込／C 受託開発売上高／C 仮受消費税）が自動生成。案件が仕訳に引き継がれる
5. 「請求書を作成」
- **期待**: INV-26-xxx が明細コピー・支払期限=翌月末で生成
6. 販売 > 入金 > 新規作成: 請求書を選択（**未入金のものだけ候補に出る**）
- **期待**: 入金額に残額が自動セット
7. 「入金を確定（消込）」（経理のみ）
- **期待**: 消込仕訳（D 普通預金／C 売掛金）生成、請求書が「入金済」（一部入金なら「一部入金」）に。販売 > 売掛残高で残額 0 を確認。期限超過の未入金は「期限超過」表示になる

## S-06 SaaS 定期請求の一括生成 【経理】

**ストーリー**: 月初に当月分の SaaS 利用料請求をまとめて発行する。

1. 販売 > 定期請求: 契約マスタ（取引先・月額・開始月）を確認（登録・編集は経理）
2. 販売 > 定期請求の実行: 対象月を選び「対象月の請求書を一括生成」（経理のみ）
- **期待**: 「生成 n件 / スキップ m件 / 仕訳 No.…」。請求書（INV、明細1行、月末発行・翌月末期限）と売上仕訳（C SaaS売上高）が同時生成
3. **もう一度実行**
- **期待**: 「生成 0件 / スキップ n件（既生成）」— 二重請求されない（冪等）

## S-07 工数入力 → 人件費配賦 → 案件別損益 【全社員＋経理】

**ストーリー**: エンジニアが日々の工数を付けると、経理は案件がいくら儲かっているかを見られる（市販会計ソフトにない領域）。

1. hanako（一般視点）で 案件 > 工数入力 > 新規作成: 案件・日付・時間（分）を入力（担当者は既定で本人）
- **期待**: hanako のサイドバー「案件」グループには**工数入力しか見えない**（人件費コスト・配賦・案件損益は経理専用）
2. admin（経理）で 案件 > 人件費配賦: 年度と月を選び検索
- **期待**: ユーザー×案件の工数（時間）・比率(%)・配賦額。**1ユーザーの配賦額合計＝その月の人件費コストに一致**
3. 案件 > 案件損益: 年度を選び検索
- **期待**: 案件ごとに 売上／直課費用／配賦人件費／粗利／粗利率(%)。受託案件は黒字、工数過多の案件は赤字が見える

## S-08 予算登録 → 予実対比・超過警告 【経理＋部門長】

1. admin（経理）で 予算 > 予算入力: 年度・部門・費用科目・年間額 → 「12ヶ月均等で登録」（端数は期末月に寄る）
2. 予算 > 予実対比: 年度を選び検索
- **期待**: 部門×科目の 年間予算／実績（仕訳の部門集計）／差異／消化率(%)。**消化率80%以上に「⚠ 超過警告」**（閾値は制度閾値マスタで変更可）。部門が付いていない実績は「(部門未設定)」行で漏れが見える
- 補足: 経費仕訳には申請者の所属部門が自動で付く（S-04 で生成した仕訳が対象部門の実績に乗る）。予実対比は**全ロール閲覧可**（予算の透明性）、登録・編集は経理のみ

## S-09 権限の境界 【承認者 vs 経理】

**ストーリー**: 「会計コアは経理だけ」の原則（A×B モデルの要）が守られているか。

1. hanako（承認者）でログイン
- **期待**: サイドバーに**仕訳・帳票・会計系マスタ（勘定科目/税区分等）・会計設定が出ない**（申請・販売・共有マスタ・予実対比などの B 側のみ）
2. URL 直打ちで http://localhost:5085/Main/JournalEntry を開く
- **期待**: 「不正なアクセスです」で**ブロック**（画面は出ない）
3. 承認済の経費を開く
- **期待**: 経理ボタン（仕訳生成/精算/完了）が**見えない**
4. 共有マスタ（取引先等）は**閲覧できる**が、保存しようとするとサーバ側で拒否される（書込は経理のみ）
5. 通知一覧には**自分宛しか出ない**（他人の URL を叩いても見えない）

## S-10 月次・年次の会計サイクル 【経理】

1. 帳票 > 合計残高試算表: 年度を選ぶ → 借方合計＝貸方合計（最下段の検算行）
2. 帳票 > 貸借対照表・損益計算書: 資産合計＝負債純資産合計、当期純利益が BS/PL で一致
3. 帳票 > 消費税集計表: 仮受・仮払が税区分別に集計される（インボイス経過措置は控除割合分のみ仮払計上）
4. 設定 > 会計年度: 月次期間のステータスを「締め」に変更 → その期間日付の仕訳を起票しようとするとブロック
5. 年度末: 会計年度画面の「翌期繰越」→ 翌期の期首残高が生成（BS 科目=期末残高、繰越利益剰余金に当期純利益が合算。損益振替仕訳は作らない方式=ADR-0006）。期首残高の貸借一致（Σ=0）は保存時検証
6. 仕訳 > 固定資産台帳: 資産を選び対象年度の「償却仕訳を生成」→ 減価償却費（部門付き）が計上される

## 検算クエリ（テスト後の整合確認）

sql CLI（`AccountingApp.Designer.exe sql ... --datasource AccountingSQLite`）で:

```sql
-- 全 posted 仕訳の貸借一致（常に等しいこと）
SELECT SUM(CASE WHEN dc='D' THEN jl.amount ELSE 0 END) AS 借方,
       SUM(CASE WHEN dc='C' THEN jl.amount ELSE 0 END) AS 貸方
FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
WHERE je.status='posted';

-- 伝票番号の重複ゼロ（年度内連番）
SELECT COUNT(*) FROM (SELECT fiscal_year_id, journal_no, COUNT(*) c
FROM journal_entries GROUP BY fiscal_year_id, journal_no HAVING c > 1);

-- 売掛金残高 = 未入金請求の残額合計（導出主義の照合）
SELECT (SELECT SUM(CASE WHEN dc='D' THEN amount ELSE -amount END)
        FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
        JOIN accounts a ON a.id=jl.account_id
        WHERE a.code='1100' AND je.status='posted') AS 売掛金残高;
```
