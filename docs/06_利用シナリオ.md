## S-01 経費申請（立替・少額）→ 課長承認 【一般社員・承認者】

**ストーリー**: 開発部の社員が 3 万円未満の旅費を立て替えたので精算したい。

1. kaihatsu1_ippan でログイン → ホームのショートカット「経費申請」> 新規作成
2. 件名・金額（例 8,000）・利用日・費目=旅費交通費 を入力 → 申請区分は既定の「立替精算」、精算対象者は既定で本人
3. 「申請」を押す
- **期待**: トースト「申請しました」。フロー表示「状態:進行中 ✓(申請者)→(▶第二課長健太,▶第一課長花子)」（3万未満 → **課長のみ**ルートが自動選択。課長2名に**並列**で回る）。精算ステータス=申請中。**花子・健太の両方に通知**（承認依頼）が作成される
4. kaihatsu1_kacho1 でログイン → ホームの「未読の通知」に承認依頼 → 「開く」
- **期待**: 該当申請へ遷移し通知が既読化。申請内容は編集不可（グレーアウト）
5. 「承認」を押す
- **期待**: 状態=承認済・精算ステータス=承認済。**申請者に「承認されました」通知**。もう1人の課長（健太）は Skipped になり、健太の承認待ち一覧から消える

**バリエーション**: 金額 3万〜20万 → 承認者が**部長（部長一郎・部長代理次郎の並列）**に変わる。20万以上 → **部長並列→総務**の2段。却下するとステータスが下書きへ戻り申請者が再申請できる。

## S-02 交際費申請（例外項目＋総務併載） 【一般社員】

**ストーリー**: 取引先との会食費を精算したい。交際費はコンプライアンス上、相手先の記録と総務の確認が必須。

1. kaihatsu1_ippan で経費新規作成 → 費目=**交際費** を選ぶ
- **期待**: 「接待の相手先・参加人数・接待の目的」の3項目が**出現**する
2. 3項目を空のまま「申請」
- **期待**: 赤トースト「交際費は相手先・参加人数・目的の入力が必須です」で**ブロック**される
3. 3項目を入力して申請
- **期待**: 金額が3万未満でも**課長→総務**の2段ルート（交際費は常に総務併載。総務段の承認者は総務部の役職者＝soumu_kacho1 等）

## S-03 事前申請 → 実費超過 → 自動再承認 【一般社員・承認者】

**ストーリー**: 出張前に見込み 25,000 円で事前申請し承認を得たが、実費は 40,000 円かかった。

1. kaihatsu1_ippan で経費新規作成 → 申請区分=**事前申請** に変更
- **期待**: 「見込み額」欄が出現（立替では非表示）
2. 費目=旅費交通費・見込み額 25,000 で申請 → 花子または健太（課長）が承認
3. kaihatsu1_ippan で申請を開く → 「実費（税込）」欄に 40,000 → 「実費を確定」
- **期待**: 区分跨ぎ（3万超え）＋見込み×110%超のため**自動で再承認へ**。トースト「実費が見込みを超過したため再承認を依頼しました」。ルートが**部長（部長一郎・部長代理次郎の並列）**に再解決され、履歴に超過理由が記録される（再解決は**申請者基準**——経理が代行確定しても申請者本人が承認者に入らない）
4. kaihatsu1_bucho（または buchodairi）が承認 → 経理処理へ進める

**バリエーション**: 実費 26,000（区分内・110%以内）なら再承認は走らず、そのまま仕訳生成可能になる。

## S-04 経理処理: 仕訳生成 → 支払 → 出納帳 【経理】

**ストーリー**: 承認済の経費を会計に取り込み、精算金を支払う。ここからは経理専用の世界（A×B 一体化の接点）。

1. soumu_bucho（経理）で承認済の経費を開く
- **期待**: 「仕訳を生成」ボタンが見える（**承認者ロールでは見えない**）
2. 「仕訳を生成」
- **期待**: トーストに伝票 No と金額。仕訳は D 費目の既定科目（税抜本体）＋ D 仮払消費税 ／ C 未払金（税込）。仕訳帳・試算表に即反映。ステータス=経理処理中。**備品×10万円以上の申請は D が工具器具備品になり、固定資産台帳へ自動登録**（EXP-{id}、取得価額=税抜）。利用日の期間が締め済みなら**本日日付に自動フォールバック**（摘要に利用日を記載・トーストで通知）
3. 「精算済にする」
- **期待**: 支払仕訳（D 未払金／C 普通預金）が自動生成。【会計】帳簿/出納帳（普通預金）に出金行が現れ残高が減る
4. 「完了にする」 → ステータス=完了

## S-05 販売サイクル: 見積→受注→検収→請求→入金 【営業＋経理】

**ストーリー**: 受託案件の商談から入金までを一気通貫で管理する。売上計上は検収基準（ADR-0008）。

1. 【販売管理】見積 > 新規作成: 取引先・件名・明細（数量×単価で金額自動計算・税抜合計表示）→ 保存（Q-26-xxx 採番）。「見積書を出力（Excel/PDF）」で帳票も確認できる
2. 「受注にする」
- **期待**: 受注 SO-26-xxx が明細コピー付きで生成され自動遷移。見積は「受注」状態に（再度押すと「既に受注済みです」）
3. 【販売管理】検収 > 新規作成: 受注を選択
- **期待**: 検収額（受注明細合計）と消費税額が自動セット
4. 保存 → 「検収を確定（売上計上）」（**経理のみ実行可**。承認者が押すと「経理ロールのみ実行できます」）
- **期待**: 売上仕訳（D 売掛金=税込／C 受託開発売上高／C 仮受消費税）が自動生成。案件が仕訳に引き継がれる
5. 「請求書を作成」
- **期待**: INV-26-xxx が明細コピー・支払期限=翌月末で生成（再度押すと「既に作成済みです」）
6. 【販売管理】入金 > 新規作成: 請求書を選択（**未消込のものだけ候補に出る**）
- **期待**: 入金額に残額が自動セット
7. 「入金を確定（消込）」（経理のみ）
- **期待**: 消込仕訳（D 普通預金／C 売掛金）生成、請求書が「入金済」に。【販売管理】売掛残高で残額 0 を確認。期限超過の未入金は「期限超過」表示になる

**バリエーション**: 先方が振込手数料を差し引いた入金（差額≦1,000円）は支払手数料として**自動処理**され全額消込。請求残額を超える入金は**過入金ガード**で拒否（前受金の手動起票へ誘導）。

## S-06 SaaS 定期請求の一括生成 【経理】

**ストーリー**: 月初に当月分の SaaS 利用料請求をまとめて発行する。

1. 【販売管理】定期請求: 契約マスタ（取引先・月額/年額・開始月）を確認（登録・編集は経理）
2. 【販売管理】定期請求の実行: 対象月を選び「対象月の請求書を一括生成」（経理のみ）
- **期待**: 「生成 n件 / スキップ m件 / 仕訳 No.…」。請求書（INV、明細1行、月末発行・翌月末期限）と売上仕訳（C SaaS売上高）が同時生成。**生成順は年額→月額**
3. **もう一度実行**
- **期待**: 「生成 0件 / スキップ n件（既生成・対象外）」— 二重請求されない（冪等）

## S-07 工数入力 → 人件費配賦 → 案件別損益 【全社員＋経理】

**ストーリー**: エンジニアが日々の工数を付けると、経理は案件がいくら儲かっているかを見られる（市販会計ソフトにない領域）。

1. kaihatsu1_kacho1（一般視点）で ホームのショートカット「工数入力」> 新規作成: 案件・日付・時間（分）を入力（担当者は本人固定）
- **期待**: 他人の行は一覧で見えるが**削除ボタンが出ず読み取り専用**（書き込みは本人のみ、のサーバ強制が UI に自動反映）。人件費コスト・配賦・案件損益は【案件管理】内の経理専用リンクで、承認者・一般のメニューには出ない（フレーム内に工数入力しか見えない）。経理の代理修正は【案件管理】工数管理（経理）から
2. soumu_bucho（経理）で 【案件管理】人件費コスト に月次コストを登録（会計年度×ユーザー×月No。月No は期首からの月番号＝4月開始なら7月=4）→ 【案件管理】人件費配賦 で年度と月Noを選び検索
- **期待**: ユーザー×案件の工数（時間）・比率(%)・配賦額。**1ユーザーの配賦額合計＝その月の人件費コストに一致**
3. 【案件管理】案件損益: 年度を選び検索
- **期待**: 案件ごとに 売上／直課費用／配賦人件費／粗利／粗利率(%)。受託は黒字、工数過多の案件は赤字が見える。前受計上（負債）は売上に入らない——発生主義が管理会計にも一貫

## S-08 予算登録 → 予実対比・超過警告 【経理＋承認者】

1. soumu_bucho（経理）で 【予算管理】予算入力: 年度・部門・費用科目・年間額 → 「12ヶ月均等で登録」（端数は期末月に寄る）
2. 【予算管理】予実対比: 年度を選び検索

## S-09 権限の境界 【4ロール】

**ストーリー**: 「制度はシステム管理者・帳簿は経理・承認は承認者・申請は全員」の職務分掌が守られているか。

1. kaihatsu1_ippan（一般社員）でログイン
- **期待**: サイドバーの入口は**経費精算・販売管理・案件管理の3つだけ**（購買管理・会計・予算管理・システム管理は出ない）。ホームのショートカットは経費申請・工数入力の 2 つ。申請中・通知は【経費精算】フレーム内のリンクで、**承認待ちリンクは一般には出ない**
2. URL 直打ちで http://localhost:5085/Accounting/JournalEntry を開く
- **期待**: 「**ページフレームへのアクセス権限がありません**」で**ブロック**（画面は出ない）
3. kaihatsu1_kacho1（承認者）で承認済の経費を開く
- **期待**: 経理ボタン（仕訳生成/精算/完了）が**見えない**。UI をすり抜けてもサーバ側でロール再チェック（「〜は経理ロールのみ実行できます」）
4. soumu_bucho（経理）で【システム管理】へ → 入口自体が出ない・直URLもブロック。ただし勘定科目・税区分の**データは読める**（仕訳入力のセレクトで科目を選べる——読取と編集の分離）。取引先・案件・会計年度など**業務マスタは経理が編集可**（取引先・案件の編集画面は【会計】マスタ/）、勘定科目・税区分・費目・閾値・ユーザー・承認テンプレなど**制度マスタは sysadmin のみ編集可**（ADR-0018。経理で開くと読み取り専用になる）
6. 一般・承認者で【販売管理】の「取引先一覧」「案件一覧」を開く
- **期待**: 検索して閲覧できるが、**新規作成・削除・詳細編集の UI が存在しない**（閲覧専用の確認ページ。マスタ編集画面には画面ごと到達できない——「押せるのに実行できないボタン」を見せない設計）
5. 通知一覧には**自分宛しか出ない**（他人の URL を叩いても見えない）

## S-10 月次・年次の会計サイクル 【経理】

1. 【会計】帳票/合計残高試算表: 期間を指定 → 借方合計＝貸方合計（最下段の検算行）
2. 【会計】帳票/貸借対照表・損益計算書: 資産合計＝負債純資産合計、当期純利益が BS/PL で一致
3. 【会計】帳票/消費税集計表: 税区分別に集計（インボイス経過措置は控除割合分のみ仮払計上）。**納税額の確定は試算表の仮受・仮払「残高」で行う**（集計表は赤黒両建て・自動仕訳の税区分も載る単純合計）
4. 【会計】設定/会計年度: 月次期間のステータスを「締め済み」に変更 → その期間日付の仕訳は全経路（振替伝票・検収・入金・経費・銀行取込・インポート）でブロック。締める際に**下書き伝票が残っていれば警告**
5. 年度末: 会計年度画面の「翌期繰越を実行」→ 翌期の期首残高が生成（BS 科目=期末残高、繰越利益剰余金に当期純利益が合算。損益振替仕訳は作らない方式=ADR-0006）。期首残高の貸借一致（Σ=0）は保存時検証。**洗い替え式なので再実行で作り直せる（冪等）**
6. 【会計】仕訳/固定資産台帳: 資産に耐用年数を設定し対象年度の「この年度の償却仕訳を生成」→ 減価償却費（部門付き・期末日・月割）が計上される。再実行は「既に生成済みです」、締め済み年度は「締め済みの年度には生成できません」

## S-11 月次推移表で経営の月次トレンドを見る 【経理】（フェーズ D-1）

1. 【会計】帳票/月次推移表 → 既定で当期 PL の12ヶ月横並び（先頭行「月（暦月）」が第n月の実際の月を示す）
- **期待**: 各科目の月次発生額＋区分計＋段階利益5種（売上総利益〜当期純利益）。合計列＝損益計算書と一致
2. 検索条件 > 表示帳票=貸借対照表（BS）→ 検索
- **期待**: 各科目の**月末残高**の推移＋当期純利益（累計）差込。最下段「負債・純資産合計」が全月で資産合計と一致（月次の貸借検算）

## S-12 キャッシュ・フロー計算書（間接法） 【経理】（フェーズ D-3）

- **期待**: 税引前当期純利益から始まる間接法。末尾の「現金及び現金同等物の期末残高」= BS の現預金合計。「増減額」= 期首→期末の現預金の実増減

## S-13 銀行明細の取込 → AI 自動仕訳 → 残高照合 【経理】（フェーズ D-2）

**ストーリー**: 月次締めで、ネットバンキングの入出金明細を帳簿に反映し、銀行残高と帳簿残高を突合する。

1. 【会計】銀行/明細取込 → 口座を選び、銀行サイトの CSV（日付,摘要,出金,入金,残高）を貼り付け →「明細を取り込む」
- **期待**: まず**プレビュー（未登録）**に入る。「プレビューを取り消す」で貼り直し可、「この内容で登録」で未起票の明細へ確定。摘要に AWS/家賃/振込手数料等を含む行は**仕訳ルールで相手科目が自動セット**（推定元=rule）。同じ CSV を再取込しても**重複スキップ**
2. 既に帳簿計上済みの明細（入金消込・経費支払など）は 状態=対象外 に変更 →「明細の変更を保存」
3. 「AIで相手科目を推定」
- **期待**: ルール未該当の明細に AI が科目を提案（推定元=ai。実キー設定時は実 AI）。候補はドロップダウンで手修正できる
4. 「候補科目で一括起票」→ 確認ダイアログ
- **期待**: 明細ごとに仕訳が生成（課税科目は本体＋仮払/仮受消費税の税行に分解・日付は明細の日付）。明細は起票済みになり仕訳IDが付き、未起票一覧から消える
5. 【会計】銀行/残高照合
- **期待**: 日付ごとに 明細残高＝帳簿残高・差額0・判定「○ 一致」。未起票明細が残っていれば差額の原因として件数表示
6. 【会計】銀行/仕訳ルール: 新しい摘要パターン（例: 新しい取引先）をルール登録 → 次回から自動判定（優先度昇順で最初の1件だけ適用）

## S-14 定型仕訳で毎月の繰り返し仕訳をワンタッチ起票 【経理】（フェーズ D-4）

1. 【会計】仕訳/定型仕訳 → 「給与の支払」を開く（給与総額/預り金/振込額の3行構成）
2. 「この定型から伝票を起票」
- **期待**: 本日日付の**下書き伝票**が作成され、振替伝票画面へ自動遷移
3. 金額を当月の給与計算結果に修正 → 「確定」
- **期待**: 貸借一致チェック→採番→確定。家賃テンプレ（課税仕入・内税）は確定時に消費税行が自動生成される（定型には税行を持たせない＝税率改正に自動追随）

## S-15 仕訳 CSV インポート（他ソフトからの移行・給与データ取込） 【経理】（フェーズ D-5）

**ストーリー**: 移行元ソフト（弥生等）や給与ソフトが出力した仕訳データを一括で取り込む。

1. 【会計】仕訳/仕訳インポート → CSV（伝票グループ,日付,借貸,科目コード,金額,税区分コード,摘要）を貼り付け → 「取り込む」
- **期待**: 伝票グループ単位で検証（科目実在・貸借一致・締め済み期間ガード）し、OK の伝票のみ確定で取込・再採番。NG 伝票は理由付きでスキップ報告。**行は無加工で取り込む**ため移行元と1円もズレない。税科目行（1900/2200）は税行として自動マークされ消費税集計の税額側に載る
2. 「下書きとして取り込む」を ON にすると draft で入る（内容を確認してから個別に確定する運用）
3. 取込後、試算表・仕訳帳で検算（Σ借方=Σ貸方）

## S-16 買掛・支払管理と支払予定表 【経理】（フェーズ D-6）

1. 【購買管理】仕入先請求書 → 新規（仕入先・請求日・支払期限・費用科目・税込金額）→ 保存。反復請求は「この請求書を複製」で前月分から起こせる
2. 「未払計上（仕訳生成）」
- **期待**: D 費用科目(本体)+仮払消費税 / C 買掛金 の仕訳（請求日で発生主義計上）。状態=未払計上済
3. 【購買管理】支払予定表 → 期限順に一覧・合計行・期限超過は「⚠」/7日以内は「まもなく」
4. 「支払登録（消込仕訳）」→ D 買掛金 / C 支払口座。状態=支払済・予定表から消える
5. 【購買管理】振込データ作成 → 未払計上済の請求書から全銀フォーマット（120桁固定長）の総合振込データを生成・様式自己検証つき
6. 検算: 買掛金残高 = 未払計上済かつ未払いの請求額合計

## S-17 SES 精算幅の自動請求 【経理】（B'-5）

1. 【会計】マスタ/案件（経理）→ SES 案件に契約条件（月額基本・精算幅 140〜180h・控除/超過単価）を設定
2. ホームのショートカット「工数入力」で当該月の実績を入力（例: 190h）
3. 【販売管理】SES精算・請求 → 対象月 → 「精算を計算」
- **期待**: 「基本 800,000（精算幅 140〜180h・実績 190h00m）＋ 超過 10h×4,500 = 845,000」の内訳プレビュー（請求書は未生成）
4. 「請求書を一括生成（売上仕訳込み）」→ INV（税込）＋ SES売上高の売上仕訳（全行に案件付き→案件損益へ自動反映）。再実行はスキップ（冪等）

## S-18 SaaS 年額プランの前受計上と按分 【経理】（磨き: 年払い）

1. 【販売管理】定期請求 → 課金サイクル=年額・年額（税抜）を設定
2. 【販売管理】定期請求の実行 → 起点月に実行
- **期待**: 年額請求書＋前受計上仕訳（D 売掛金税込 / C 前受収益＋仮受消費税）＋当月分の按分振替（D 前受収益 年額/12 / C SaaS売上高）
3. 翌月以降の実行 → 按分振替のみが毎月積み上がる（前受収益残高が月次で減少）。再実行は常にスキップ（冪等）

## 検算クエリ（テスト後の整合確認）

sql CLI（`AccountingApp.Designer.exe sql ... --datasource AccountingSQLite`）で:

```sql
-- 全 posted 仕訳の貸借一致（常に等しいこと）
SELECT SUM(CASE WHEN dc='D' THEN jl.amount ELSE 0 END) AS 借方,
       SUM(CASE WHEN dc='C' THEN jl.amount ELSE 0 END) AS 貸方
FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
WHERE je.status='posted';

-- 伝票番号の重複ゼロ（年度内連番）
SELECT COUNT(*) FROM (SELECT fiscal_year_id, journal_no, COUNT(*) c
FROM journal_entries GROUP BY fiscal_year_id, journal_no HAVING c > 1);

-- 売掛金残高 = 未入金請求の残額合計（導出主義の照合）
SELECT (SELECT SUM(CASE WHEN dc='D' THEN amount ELSE -amount END)
        FROM journal_lines jl JOIN journal_entries je ON je.id=jl.journal_entry_id
        JOIN accounts a ON a.id=jl.account_id
        WHERE a.code='1100' AND je.status='posted') AS 売掛金残高;

-- 期首残高の貸借一致（繰越後の翌期。0 であること）
SELECT fiscal_year_id, SUM(balance) FROM opening_balances GROUP BY fiscal_year_id;
```
