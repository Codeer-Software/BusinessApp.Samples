# 経費精算（B-2）設計

> 作成: 2026-07-05 / 基底仕様: **`references/経費精算.md`（ユーザー提供・大きな流れの正）**。
> 本書は参照仕様を本プロジェクトのペルソナ・スコープ・既存実装（承認エンジン移植済み）に合わせて確定させたもの。差分・段階分けを明記する。

## 0. 位置づけ（ユーザーの A/B モデル）

- **A＝会計コア（フェーズA）**: 市販の財務会計専門ソフト相当。**経理担当（管理部）専用**。他ロールに触られてはならない（→B-8 で経理ロールゲート必須）。
- **B＝業務フロー部分**: 市販ソフトが対応しにくい「会社ごとの業務フローに合わせたアプリ」。**全社員が触る**。原課（営業部・開発部）が申請→金額や科目に応じて決裁権限者が変わる。
- **本アプリの価値は A と B の一体化**。経費精算は B の代表であり、承認完了後に A へ自動連携（仕訳）される。

## 2. データモデル差分（ddl/080_expense.sql 予定）

- `expense_categories`（費目マスタ）: id/code/name/default_account_id(FK accounts)/default_tax_category_id(FK tax_categories)/is_entertainment/is_asset_candidate/display_order/is_active ＋ seed（旅費交通費・会議費・交際費・消耗品費・備品・外注費・通信費・図書研修費・諸会費・その他）
- `expense_request` に ALTER TABLE で追加: request_type(立替/事前) / payee_type(社員/取引先) / expense_category_id / used_date DATE / used_at TEXT(利用先) / tax_amount INTEGER / estimated_amount INTEGER(見込み額) / payee_user INTEGER(精算対象者) / payee_partner_id INTEGER(支払取引先) / entertainment_guest TEXT / entertainment_count INTEGER / entertainment_purpose TEXT / is_fixed_asset INTEGER / asset_no TEXT / settlement_status TEXT / 領収書 FileField 3列
- `departments` に ALTER TABLE: manager_user INTEGER(課長=AppUser) / director_user INTEGER(部長=AppUser)
- `app_users` に ALTER TABLE: department_id INTEGER（所属部門）→ AppUser モジュール・ユーザー管理画面にも項目追加

## 3. 実装ステップ（台帳と連動）

1. **B2-1 移植品の動作確認**: サーバ起動→承認者ユーザー作成（花子=課長役・admin=申請者）→テンプレ手動1件→経費申請→承認 E2E。移植した素の状態が動くことを先に確定させる
2. **B2-2 データモデル＋フォーム拡張**（§2。2軸出し分け・費目・事実項目・交際費例外・添付）
3. **B2-3 承認ルート自動決定**（テンプレ4種 seed・SelectTemplateName 拡張・承認者の部門役職差し替え）
4. **B2-4 経理処理フェーズ**（精算ステータス・経理の仕訳生成→A連携・固定資産誘導）
5. **B2-5 実費超過再承認＋総合 E2E**

## 4. 設計判断（参照仕様からの重要な引き継ぎ）

- 経理の仕訳確定は**承認テンプレートに含めない**（承認と経理処理を分離）
- 精算対象者は既定＝申請者本人・変更可（代理申請）
- 申請日は業務項目（編集可）。監査は CreatedAt（自動）
- 利用先（店）・精算対象者（社員）・支払取引先（業者）は別項目
