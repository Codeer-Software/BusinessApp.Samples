# 失わないためのルール

> **消すとき・稼働 DB を戻すとき・保護対象を上書きするときの判断**を持つ。
> **2026-09-15 に [30_作業のルール](30_作業のルール.md) の §10 から出した**——
> 30 は毎タスク読む文書なので、**工程のときにだけ要るものを分けた**（[00 §5](00_ドキュメント規約/README.md)）。
> **コマンドの書式と道具ごとの使い方は [tools/README](../tools/README.md) が持つ。ここは判断だけ。**

## 1. 消すときは `trash`、稼働 DB を戻すときは `db_snapshot`。保護対象を素で上書きしない

**ごみ箱送り（`trash.ps1`）も、稼働 DB の退避と復元（`db_snapshot.ps1`）も、
開発者の確認を待たずに実行してよい**（開発者の指示。2026-09-07 と 2026-09-08）。
**確認プロンプトで自律作業が止まるのを避けるためであり、許せるのは「戻せる」からである**——
ごみ箱は復元でき、`db_snapshot` は何も消さず、戻す前に必ず現状を退避する
（経緯は [ADR-0044](decisions/0044-削除はごみ箱送りに一本化しrmを機械で止める.md)・[ADR-0046](decisions/0046-稼働DBの退避と復元を戻せる道具に閉じる.md)）。

**稼働 DB は、退避を取ってから壊す。**

- **マイグレーションを稼働 DB へ当てる前と、壊す実験の前に `-Save` を打つ**（[31 §1](31_検証のルール.md) の検証ループ）
- **`cp` で写しを取らない**（使用中の SQLite を複製すると壊れた写しができる。
  **一次情報と機序は [ADR-0046](decisions/0046-稼働DBの退避と復元を戻せる道具に閉じる.md) の理由**）。**関門は素の `cp` を今までどおり拒む**
- **`db_snapshot.ps1 -Restore` は、保護対象（稼働 DB）を無確認で上書きする経路として認めた唯一のものである**
  （`Edit` は確認つきで通る。下。**機械の側にはまだ穴②が残っている**ので「機械的に唯一」ではない）。
  §1 の見出しが「**素で**上書きしない」と言っているのはそのため——**素の `cp` は拒み、戻せる道具に閉じた 1 本だけを通す**。
  **2 本目の予定がある**——[README](../README.md) の「ワークツリーにも同じものが要る」。
  **作ったらこの行を直す**
- **溜まった退避もごみ箱の中身も、開発者が消す。** Claude は触らない
  （`LocalData/backup/` は保護対象なので消せない。**`LocalData/temp/` は守らない**——
  いつ消えてもいいものの置き場。開発者の指示。2026-09-10。守るのは正典に載せた行だけである）

**機械が何を拒むか。語彙の正典は `tools/claude/guard_delete.py` の正規表現**であって、この箇条書きではない。

**守りは呼び出し全体を拒む。だから呼び出しを分ける。** 保護対象の名前と書き込み（`>`・`sed -i`・
python の書き込みなど）が**同じ 1 つのコマンド文字列に同居**すると、`&&` で繋いだ無害な `git add` まで
道連れに、**何も実行されない**。**守りはコマンド文字列の字面しか見ないので、引用の中でも設定値でも同じ**
——保護対象の名前を含む**文章**をヒアドキュメントで書き足そうとしても拒まれる。
**書き込みはファイルに逃がして `python <ファイル>` で実行し、`git add` は単独の呼び出しにする。**

- **削除にあたるコマンドは、当たり先によらず拒まれる**（`rm`・`Remove-Item`・`shutil.rmtree`・
  `[IO.File]::Delete` など）。**拒むときは代わりのコマンドが理由文で示される**
- **コミットしていない変更を消す git（`clean`・`reset --hard`・`stash drop`・`stash clear`・`checkout -- `）も拒まれる**
  ——**「Git で戻せないものを守る」と決めた以上、git 自身の破壊コマンドを外す理由が無いから**である。
  **副作用がある**（`git clean -n` の空打ちや、1 ファイルだけの `git checkout -- ` も止まる）。
  **逆に、`--` を書かない `git checkout <パス>` と `git restore` は通る**——
  **語彙は「`checkout` の後ろに `--` が続く形」しか見ていない**ので、
  **コミットしていない作業ごと捨てられる経路がここに残っている**（[31 §1](31_検証のルール.md) の控えの話）。
  **要るときは開発者に声をかける**（開発者の指示。2026-09-07）
- **保護対象への `Write`（全上書き）と、保護対象の名前が出る上書きのコマンド**（`sed -i`・`Copy-Item`・
  `> ファイル` など）**も拒まれる。上書きは削除より強い**——ごみ箱は前の中身を残すが、上書きは残さない。
  しかも `Write` は中身を照合しないので、**想定と違うファイルでも黙って通る**。
  **`Write(...)` の形の権限規則は参照されない**ので、`.claude/settings.json` に**同じ形の控えは置けない**
  （[ADR-0044](decisions/0044-削除はごみ箱送りに一本化しrmを機械で止める.md)）。**控えは `ask` の側が兼ねており、
  フックが起動しなければ上書きは拒否ではなく確認に落ちる**
- **保護対象を直すときは `Edit` を使う**（拒まれないが、**確認が入る**）。
  `Edit` は `old_string` の照合があるので**取り違えでは壊れない**。
  ただし**照合を通す字は読めば手に入るので、意図すれば空にもできる**——だから確認を挟む
- **保護対象を新しく作る素直な経路は、どれも塞がっている。開発者に頼む**
  （`Write` はフックが拒み、`Edit` は既存のファイルにしか当たらない。
  **`.sample` からの複製 4 通りを 2026-09-08 に打ったところ、4 つとも行き先の名前で拒まれた**）。
  **ただし「できない」と決めつけない**——関門の語彙は網羅ではないので、
  **語彙に無い書き方は通りうる**（`guard_delete.py` の「限界」）。
  新環境の手順は [README](../README.md) の「セットアップ（新環境）」にあり、**これは開発者の作業**である
- **消せないものがある**——**一覧も、載せる基準（消えたとき、戻す操作が現実的か・戻し損ねたことに気づけるか）も、
  正典は [`tools/claude/protected_paths.json`](../tools/claude/protected_paths.json) の 1 ファイル**で、
  フックと `trash` の両方がそれを読む。**消す必要が出たら開発者に頼む**
- **保護対象を 1 つでも内側に含むフォルダは、丸ごとは消せない**（`trash` が拒む）。
  リポジトリの根・`Designer`・`LocalData` などが該当する
- 追跡ファイルを消すのは怖がらなくてよい——ただし**コミット済みであれば**である。
  **コミットしていない変更は git でも戻せない**

**「戻せる」には穴が 2 つある**（**どちらも埋めないまま進むと開発者が決めた**。2026-09-08。
**材料は「該当する保護対象がまだ 1 つも無い」と「絞ると正当な作業まで止まる」**——
[ADR-0044](decisions/0044-削除はごみ箱送りに一本化しrmを機械で止める.md) の決定 12）。
①**ごみ箱の容量を超えるものは完全削除になるとされ、`trash` は拒めない**
（**未確認**。実測も一次情報も取っていない）。
②**削除の語が字面に出ない形**（変数に入れる・パスを組み立てる）**と、保護対象の名前が出ない上書き**は、
開発者への確認ではなくそのまま実行になる（`.claude/settings.json` に白紙の許可があるため）。
**削除は、語さえ出ていれば当たり先によらず拒まれる**——名前の有無で決まるのは上書きだけである。
**`Write` ツールの上書きも違う**（フックが落ちれば確認に落ちる）。
**だから「機械が止めてくれる」に寄りかからない。**

**関門そのもの（`tools/claude/`・`.claude/settings.json`）は保護対象に載せない**
（開発者の判断。2026-09-08。逐語は「**これらは Git 追跡されていますよね？ よしとしましょう**」——
**Git 追跡下にあり、壊しても戻せる**ので載せる基準に当たらない。載せると `trash` まで拒み、
正当な作業が止まる。[ADR-0046](decisions/0046-稼働DBの退避と復元を戻せる道具に閉じる.md) の決定 8）。
**つまり Claude は関門を無確認で書き換えられる。** 直したら `--selftest` を通し、
**「壊したら鳴るか」まで確かめる**（[31 §1](31_検証のルール.md)）。
