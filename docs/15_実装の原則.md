> [CLAUDE.md](../CLAUDE.md) のスリム化と合わせて起こした）。
> **コードをどう書くか**（§1〜§4）と、**それを作るときの手の動かし方**（§5・§6）の原則を置く。
> CLB での書き方は [`Designer/Project.md`](../Designer/Project.md)、
> 踏むと静かに壊れる挙動は [qa/01](qa/01_CLB静かな失敗.md) が持つ。

**この文書の育て方**（09 と同じ）

- **原則だけを置く。** 個別の判断は ADR、CLB の書き方は Project.md
- **「なぜ」の無い項目を足さない。** 理由が書いていない規則は、例外に出会った人が判断できない
- **厳選して書く。** 原則が増えるほど 1 件あたりの重みが下がる
- **ここに書いてあるのは「こうする」であって「こうなっている」ではない。**
  実装の現在地は [05](05_実装計画と現在地.md)。**原則と現況を混ぜて読まない**
- **まだ確かめていない項目は想像である。** 確かめたら、確かめたと書く
- 原則が覆るときは ADR を起こす。ここを黙って書き換えない

**まだ入っていないもの**——**「どこで実行するか・どの層に置くか」の集約**。
いま [ADR-0008](decisions/0008-CLBとCSharpライブラリの責務分担.md)・[0013](decisions/0013-機能単位のモジュール分割と依存方向.md)・[0016](decisions/0016-画面から呼ぶサーバ処理はWebAPIに置く.md)・[0022](decisions/0022-明細を並べる帳簿はクエリモジュールで作る.md)・[0027](decisions/0027-入力の一覧はラップモジュールとクエリモジュールで作る.md)
の 5 本に散っている。**別の回にまとめる**（[05 §1](05_実装計画と現在地.md) の項目 1）。

## 1. ロジックは C#、CLB は薄いプレゼンテーション層

**会計の計算・検証・集計は、外部依存ゼロの C# ライブラリ（`AccountingCore`）に置き、ユニットテストで守る。**
スクリプトに書いてよいのは、画面上の値の出し入れと C# サービスの呼び出しだけ。
**理由は CLB スクリプト（`*.mod.cs`）がツリーウォーク型インタプリタで、静的検査がほぼ効かないこと**——
論拠と構成の決め方は [ADR-0008](decisions/0008-CLBとCSharpライブラリの責務分担.md) が持つ。

## 2. 制度値をハードコードしない

税率・控除割合・閾値・耐用年数は、**有効期間つきのルールデータ**として持つ
（各マスタへの当てはめは [08_マスタ台帳](08_マスタ台帳.md)）。
**仕訳には適用したルールの版を固定して保存し、後日マスタを更新しても過去を再計算しない。**

## 3. マジックナンバーを使わない

**意味を持つ数値をコードに直接書かない**（開発者の指示。2026-09-05）。名前の付いた定数にする。

**理由は「読む人が『この 100 は何か』を推測しなくて済む」こと**である。
**だから境目もそこで決まる**——`value >= 1m`（1 円未満は無い）や `BETWEEN 1 AND 12`（月）のように
**その場で読めば意味が分かる数値は、そのまま書いてよい。** 名前を付けても情報が増えない。

**複数の場所に要る値は、読めても定数にする。** それは §4 の話になる。

## 4. 重複定義を避ける。已むを得ないなら、機械で突き合わせる

**同じ事実を 2 か所に置かない**（開発者の指示。2026-09-05）。
**ただし C# と CLB で別々に定義せざるを得ない場合は許容する**——
CLB のデザインは JSON、DDL は SQL テキストで、**どちらも C# の定数を読めない**からである。

**許容するときは、必ず機械で突き合わせる。** 人が揃えると、いつか片方だけ直る。

**先例が 2 つある。2 者でも 3 者でも同じ形である。**

- **`EnumConsistencyTests`**——**DB の `CHECK` の値・CLB のデザイン enum・C# の列挙子**の
  **3 者一致**（`AccountingRole` がその例）。C# 側を持たない行は 2 者一致で守っている
- **`Designer/migrations/baseline/`**——`ddl/` の凍結コピーを**同値テスト**で守る（[ADR-0020](decisions/0020-スキーマは現在形の正典で持ち変更は差分で配る.md)）

**当てはまる場面と、いま守れているか**（2026-09-05 に実物と突き合わせた）

| 値 | どこに要るか | いま |
|---|---|---|
| 選択肢（列挙） | DB の `CHECK`・CLB のデザイン enum・C# の列挙子 | **守れている**（`EnumConsistencyTests`） |
| 桁の書式 | DB の `GLOB '[0-9]…'`・CLB の `MaxLength`・C# の定数 | **守れていない。** 法人番号 13 桁が 3 か所にあり、突き合わせるテストが無い |

**金額の上限は、この表に載せない**——`journal_lines.amount` の上限を決めているのは
`CHECK` ではなく**格納型**（SQLite の 64 ビット INTEGER）であり、**重複した定義が存在しない**からである。

## 5. 一時ファイル・一時フォルダを作らない

**作ると必ず消すことになり、削除のたびに開発者の確認で作業が止まる。** 作らない方法を先に探す。

- **DB の検査・投入**: `sql` CLI に `--query` を渡し、`--out` を省いて標準出力で受ける
  （PowerShell からは `ProcessStartInfo.ArgumentList`。`Start-Process -ArgumentList` は引用符が壊れる）
- **スキーマのテスト**: インメモリ SQLite（`:memory:`）。接続を閉じれば消える
- **DDL の適用**: `Designer/ddl/` の追跡ファイルをそのまま `--file` に渡す

やむを得ず作るならスクラッチパッドの**同じパスを上書きし続ける**（増やさない・消さない）。
**削除処理をスクリプトに紛れ込ませて確認を迂回しない。**

## 6. 検証そのものを育てる（結果を鵜呑みにしない）

**検証を流したら、結果を使うだけで終わらせない。毎回、検証自体を振り返る**（開発者の指示。2026-08-28。
**検証も成長させるものであり、盲目的に従うと関門が形骸化するから**）。

1. **今回の結果は有用で適切だったか**（本当の問題を指したか、意図どおりの記述を毎回叩いているだけか）
2. **かかった時間に見合っているか**
3. **見合わないならどう良くできるか**（対象を絞る・警告に落とす・置き換える・やめる）

判断が要ったものは [qa/02_自己レビュー記録](qa/02_自己レビュー記録.md) に残す。

**関門は足したときが完成ではない。** 実例: superseded リンクの検査は鳴った 6 件すべてが
「経緯として正しい」もので、しかも**既定の直し方が `decisions/` では誤り**だった（2026-08-28。ラウンド 19）。
