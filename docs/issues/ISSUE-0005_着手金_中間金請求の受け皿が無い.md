# ISSUE-0005: 着手金・中間金（マイルストーン請求）の受け皿が無い

- 起票: 2026-08-17（ADR-0067 の検討中に発見）
- 状態: **未着手**（設計・実装とも GO 待ち。ユーザー判断: 起票のみ・別タスクとする）
- 影響範囲: 販売（受託）。**帳簿の正しさに関わる**（現状の回避策を使うと売掛金が帳簿に載らない）
- 種別: **機能追加**（バグではない）。バグ狩りのスコープには入れない

## 何が無いのか

受託開発では「着手時 30%・中間 30%・検収後 40%」のような**マイルストーン請求**が契約書に書かれる。
**検収より前にお金を請求する**のが普通で、ペルソナ（受託 60% の IT ソフトハウス・`docs/02`）の
実務でも中〜大型案件では常態のはずである。

本アプリにはこれを表す道が無い。

| 使えそうな道 | なぜ使えないか |
|---|---|
| 検収から生やす請求書 | **検収がまだ無い**。着手金の時点で検収額は 0 |
| 手動の合算請求書（`acceptance_id` が NULL） | **仕訳を一切作らない**。売上仕訳は検収確定時に作られるため、売掛金が帳簿に載らない。入金消込すると貸方 売掛金 に対応する借方が無く、総勘定元帳の売掛金 ≠ 売掛残高一覧（不変条件 C08 の違反）になる |
| 定期請求 / SES | 別の契約形態（月額・稼働ベース）。一括請負の分割払いは表せない |

**つまり現状は「請求できない」か「帳簿を壊して請求する」の二択**になっている。

なお ADR-0067 で「検収に紐づく請求書の明細金額は読み取り専用」と決めたため、
**「検収を先に作って金額を水増しする」という抜け道も塞がる**。受け皿を用意する必要性は上がった。

## 会計的な正解ははっきりしている

勘定科目は既にある（**前受金 2100**・`docs/04_会計ドメイン設計.md` §2.1）。

| 時点 | 仕訳 |
|---|---|
| 着手金を請求 | D 売掛金 / C **前受金** |
| 入金 | D 現預金 / C 売掛金 |
| 検収（売上計上） | D **前受金** ＋ D 売掛金 / C 売上高 |

売上は検収時にしか立たない（ADR-0008 を壊さない）。前受金は「まだ売上ではないお金」を
負債として持つための科目なので、**検収基準の設計とそのまま両立する**。

## 設計の論点（GO をもらったら詰めること）

1. **どこに置くか**
   - 案A: **受注に「請求スケジュール」の子リストを持たせる**（着手 30%・中間 30%・検収後 40%）。
     受注確定時に請求予定を展開し、各行から請求書を起こす。契約の実態に近い
   - 案B: 請求書に「請求区分（着手金／中間金／検収請求）」を持たせ、着手金・中間金は
     受注に紐づける（検収ではなく）。軽いが、契約全体の消化状況が見えにくい
   - 案C: 前受金の入金だけを別画面で扱う（請求書を介さない）。実務と合わない（請求書は出す）
2. **検収時の充当**: 検収確定の売上仕訳で、既存の前受金残高をいくら取り崩すか。
   受注単位で前受残を持ち、検収額の範囲で自動充当するのが素直
3. **売掛残高一覧・資金繰り予測への反映**: 前受金の請求も未入金なら売掛金なので、
   両画面に出る必要がある（ADR-0032 の入金予定自動作成の対象にもする）
4. **不変条件**: 「前受金残高 ≦ 受注額」「検収完了後に前受金残高が残らない」を追加する
5. **消費税**: 前受金の請求時点で仮受消費税を立てるか、検収時にまとめるか。
   **税法上は原則として資産の譲渡等の時（＝検収時）**なので、前受金請求では税を立てない設計が素直。
   ただし請求書には消費税を記載するのが商慣行なので、**請求書の表示と仕訳を分ける**必要がある。要リサーチ

## なぜ優先度が高いと考えるか（判断材料）

- **ペルソナの実務に直結する。** 受託 60%・中〜大型案件ありという設定で、着手金が扱えないのは不自然
- **市販ソフト比較（`docs/14`）で刺さりうる。** 「機能が多い」で負けている項目ではなく、
  受託業に固有の**業務フローの穴**なので、デモで指摘されると痛い
- **回避策が帳簿を壊す。** 「手動請求書で出せばよい」は、売掛金が載らないので使ってはいけない
