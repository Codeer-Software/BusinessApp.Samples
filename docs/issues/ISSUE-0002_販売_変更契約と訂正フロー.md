# 販売業務の変更契約・訂正フロー検討（考慮漏れの棚卸し）

> 作成: 2026-07-21。ユーザー指摘「実務では変更契約がある。本アプリではどんなフローが自然か、販売全業務で考慮漏れがないか」への検討結果。
> 現行仕様の根拠: Quote/SalesOrder/Acceptance/Invoice/Receipt/RecurringBilling/SesBilling の各 mod.cs・docs/08・docs/tests/11/07（特殊取引）を精査（2026-07-21 時点のコード）。

## 0. 結論（推奨原則）

本アプリの設計思想（文書は状態で凍結・訂正はボタン化された逆操作・会計イベントは検収/入金のみ）に変更契約を載せると、次の 2 原則に収束する:

- **原則A: 契約変更は「文書の書き換え」ではなく「差分文書の追加」で表現する。**
  増額・追加スコープは新しい見積→受注（変更契約）として起こし、**同一案件（Project）に紐付けて束ねる**。案件損益が案件単位で合算される設計なので、契約が何本に分かれても収益管理は壊れない。
- **原則B: 会計イベント（検収確定・請求発行・入金）の後の変更は、逆操作チェーンで巻き戻してからやり直す。**
  巻き戻しボタンは全段に実装済み（入金取消 → 請求書 void → 検収確定取消 → 下書き修正）。締め済み期間だけは巻き戻さず赤黒訂正（振替伝票）で前に進める。

「見積は下書き以外編集不可」（2026-07-21 実装）はこの原則Aの第一歩。対になる**受注側のロックが未実装**（→ P1）。

## 1. シナリオ別の推奨フローと現状評価

### S1. 受注前の変更（金額・スコープの練り直し）
- **推奨**: 見積を「下書きに戻す」→修正→再送付。
- **現状**: ○ 完全対応（送付済は編集不可・明示的な差し戻しのみ）。

### S2. 受注後・検収前の増額変更契約（追加開発など）
- **推奨**: **変更契約分を新規見積として起こす**（件名規約: 「◯◯ 変更契約①: △△追加」）→「受注にする」→ 同一案件に紐付け。以後は独立した受注として検収・請求まで流す。
- **現状**: ○ 運用で対応可能。案件損益は案件単位で自動合算。
- **注意**: 元受注の明細を直接書き換える方法も現状は可能だが、**顧客に提示した契約額の証跡が消える**ので推奨しない（→ P1 でロック）。

### S3. 減額変更（検収前の値引き・スコープ縮小）
- **推奨**: 軽微な値引き＝**検収時に検収額を手修正で減額**（docs/tests/11/07 に記載の公式手順。検収額が売上計上額）。スコープ縮小＝受注が未検収なら受注明細を修正（P1 導入後は「検収前のみ可」になる）。
- **現状**: ○。マイナス明細の変更契約受注は**作らない**こと（検収確定は金額 > 0 ガードがあり単独検収できない。減額は検収額修正で表す設計）。

### S4. 分割検収（フェーズ検収・出来高）
- **推奨**: 同一受注に検収を複数作り、検収額を各フェーズ分に手修正する。
- **現状**: △ **可能だが無防備**。検収は受注ごとの重複ガードがなく複数作れる（設計どおり）。ただし検収額の初期値が毎回「受注全額」で、**検収済み累計・残額の表示も超過警告もない**。フェーズ2で全額を再セットしたまま確定すると二重売上になる（気づく手段は帳票のみ）。→ **P2**
- **参考**: 変更契約（S2）で受注を分けておくと、この問題は自然に小さくなる（1受注=1検収に近づく）。

### S5. 検収確定後の変更（期間オープン中）
- **推奨**: 逆操作チェーンで巻き戻す。入金済→「入金を取り消す」、請求済→「取消（void）」、確定済→「確定を取り消す」（売上仕訳を削除）→ 下書きで修正 → 再確定・再請求。
- **現状**: ○ 全段ボタン実装済み・各段に前提ガードあり（請求書があると検収取消不可、等の誘導つき）。

### S6. 締め済み期間の売上の訂正
- **推奨**: 巻き戻さない。**赤黒訂正**（振替伝票で反対仕訳＋正しい仕訳、当月日付）＋ 請求書は void → 手動で再発行。検収取消は締め済みガードで拒否され、エラーメッセージが赤伝へ誘導する。
- **現状**: ○（docs/tests/11/07 に手順あり）。

### S7. 中途解約（プロジェクト打ち切り）
- **推奨**: 出来高分を検収（金額手修正）→ 請求・回収 → 受注「完了にする」＋ 備考に解約経緯 → 案件マスタ状態「中断」or「完了」（案件の編集は経理∨部長=ADR-0046。業務マスタの案件画面のほか、工数フレームの案件一覧からも可）。
- **現状**: △ フローは通るが、受注状態が open/closed の 2 値で**「解約」を区別できない**（見積には rejected があるのに対し非対称）。検索・受注残分析で「完済の完了」と「打ち切り」が混ざる。→ **P5**（低優先。備考運用で回る）
- 回収不能が出た場合は貸倒処理（docs/tests/11/07）へ接続。

### S8. SaaS（定期請求）の改定・解約
- **推奨**: **旧契約に終了月をセット → 新金額の新契約を翌月開始で追加**。月次の一括生成は契約×対象月の冪等キーなので、月境界で切り替われば二重請求しない。解約は終了月セット（または有効オフ）のみ。
- **現状**: ○ 開始月・終了月・有効フラグで表現可能。日割りは仕様外（月単位課金）。
- **残ギャップ（レア）**: **年額前払の期中改定・中途解約**。前受収益の按分振替は月次自動だが、解約時の未経過分返金・前受残の精算仕訳は自動化がなく、振替伝票での手動処理になる（許容範囲と判断。docs/03 の B'-4 繰延厳密化の系）。

### S9. SES の条件改定（単価・精算幅の変更契約）
- **推奨**: 案件マスタの SES 契約条件を**改定月の精算実行前に**書き換える（精算計算は実行時点のマスタ値を使う）。SES 精算条件（単価・精算幅）の編集は**経理のみ**——部長は案件を編集できるが SES 条件欄は読取専用（ADR-0046。旧 ProjectView は廃止され Project 本体に一本化）。
- **現状**: △ **条件に履歴がない**ことによる2つの罠:
  1. 改定後に「未生成の過去月」を精算実行すると**新単価で過去月を計算**してしまう（生成済み月は冪等スキップで安全）。
  2. 月の途中からの改定（日割り・時間割）は表現できない。
  → 運用ルール「過去月の精算を締めてから条件を書き換える」で回避。恒久対応は**契約条件の期間管理（SES 契約明細）**で、「1案件=1契約（複数要員は案件を分ける）」の簡略化と同根の将来課題。→ **P4**
- 途中参画・離任は現行どおり案件を分ける／精算幅で吸収。

### S10. 請求書レベルの誤り（金額・宛先ミス）
- **現状**: ○ void（取消）→ 再発行が実装済み。入金済みは先に入金取消。

### S11. 返金（過入金・解約返金）
- **現状**: △ 入金前の過入金は少額差額の自動処理（支払手数料閾値）があるが、**顧客へ金を返す出金フローは販売側にない**。振替伝票（D 売掛金 or 雑収入戻し / C 普通預金）＋ 購買側の振込データ作成で手動対応。発生頻度からして許容（帳票上は問題なく表現できる）。

### S12. 税率改正を跨ぐ変更契約
- **現状**: ○ 税率・税区分はマスタ化済み。検収時の税額は SALES_10 の**現在率**で自動計算（手修正可）なので、旧率適用が必要な経過措置ケースだけ手修正する。

## 2. 提案（優先度順）

| # | 提案 | 狙い | 規模 |
|---|---|---|---|
| P1 | **受注のロック**: 検収が1件でも存在する受注は明細・金額を編集不可にする（見積と同じ「状態で凍結」思想。変更は S2 の変更契約受注へ誘導するガイドをボタン/メッセージで示す） | 契約証跡の保全。S2 の「直接書き換え」抜け道を塞ぐ | 小 |
| P2 | **検収画面に「受注額 / 検収済み累計 / 残額」を表示し、累計が受注額を超える確定に警告**（ブロックはしない——増額検収は実務上ありうる） | 分割検収・変更契約時の二重売上防止 | 中 |
| P3 | **変更契約の運用規約を docs/tests/06（利用シナリオ）に明文化**: 件名規約「元件名 変更契約①」・同一案件に紐付け・減額は検収額修正、の3点 | 実装なしで今すぐ効く | 極小 |
| P4 | SES/SaaS の**契約条件の期間管理**（単価履歴・要員別契約） | S9 の恒久対応 | 大（将来課題として docs/03 へ） |
| P5 | 受注状態に「解約」を追加（open/closed/cancelled） | 受注残分析の精度 | 小（優先度低） |

## 3. まとめ（フロー俯瞰）

```
既存契約                 変更契約の性質            使う機能
──────────────────────────────────────────────
未受注                   何でも                    見積を下書きに戻して修正
受注済・未検収           増額/追加スコープ         変更契約の新見積→新受注（同一案件）
                         減額/縮小                 検収額の手修正（または受注修正※P1後は検収前のみ）
受注済・分割納品         フェーズ検収              同一受注に複数検収（P2で安全化）
検収確定後（期間open）   金額・内容の誤り          入金取消→請求void→確定取消→修正→再確定
検収確定後（締め済み）   同上                      赤黒訂正＋請求void/再発行
進行中の打ち切り         中途解約                  出来高検収→請求→受注完了（＋備考）
SaaS 月額の改定/解約     単価変更・解約            旧契約に終了月＋新契約を翌月開始
SES 条件の改定           単価・精算幅変更          精算締め後にマスタ書き換え（過去月未生成に注意）
```
