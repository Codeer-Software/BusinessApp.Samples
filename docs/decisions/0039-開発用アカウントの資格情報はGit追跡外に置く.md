# ADR-0039 開発用アカウントの資格情報は Git 追跡外に置く

## 状況

**開発機の会計コアには、実機確認のためのアカウントが 3 つある**——CLB の既定 `admin` と、
管理画面で手作りした `soumu_bucho`（経理責任者）・`soumu_ippan`（経理担当）。
Claude は [17 §2](../17_検証のルール.md) により、実装したものを毎回ブラウザで操作して確かめる。**ログインが要る。**

**この資格情報をどこに置くかが、3 度揺れた。**

1. **[ADR-0031](0031-デモ用の利用者アカウントは開発用のseedに置く.md)（2026-08-30）**は
   「`Designer/seed/dev/` に固定の平文パスワードを書く」と決めた。**しかし実装できなかった**——
   `hash` と `salt` は CLB の `PasswordHashHelper` が作るもので、**SQL では作れない**
   （CLB 仕様リファレンス `_specs/Authentication.md`）。実際に動いていたのは ADR-0031 が却下した選択肢 C
   （`admin` で画面から手作りする）で、**パスワードはリポジトリのどこにも無く、Claude は開発者に毎回聞いていた**
2. **2026-09-05**、開発者の指示で **CLAUDE.md に平文で書いた**。自己レビューで、これは ADR-0031 が
   パスで固定した例外を**広げる**ことだと指摘され、本 ADR の初版を「CLAUDE.md に置く」として起こした
3. **2026-09-06**、開発者が「開発者がこう言ったという事実を外し、ゼロベースで比べ直せ」と求め、結論が反転した

## 決定

**識別名とパスワードは `Designer/LocalEnvironment.md`（Git 追跡外）の「開発用アカウント」節に置く。**
**追跡下には、雛形（`Designer/LocalEnvironment.md.sample`。プレースホルダのみ）と、
「Claude は開発用アカウントで自由にログインしてよい」という許可だけを書く**（[17 §3](../17_検証のルール.md)）。
（開発者の決定。2026-09-06。**理由は下のとおり**）

### 1. 追跡下に置く案の長所は、幻だった

追跡下に置く長所は「clone しても値が残る」だと考えていた。**しかしアカウント自体が clone では残らない。**
`hash` を SQL で作れない以上、新しい開発機では**人が管理画面で作る**しかなく、
**その同じ手で LocalEnvironment.md に書けばよい**。アカウントと記録は必ず同じ瞬間に生まれる。
**追跡下に前もって書いておく必要が、そもそも無い。**

**片方だけ失われる場面はある**——DB（`LocalData/db/`）は残るのに LocalEnvironment.md だけ消したとき。
**それでも致命ではない**: `admin` で管理画面に入り、2 人のパスワードを付け直して書き直せばよい。

### 2. 追跡下に置く短所は、本物である

- **[CLAUDE.md §1](../../CLAUDE.md) の目的③（製品化）と [05](../05_実装計画と現在地.md) のフェーズ 7（デモ）は、
  この DB を localhost の外へ出す場面を必ず作る。** そのとき「値を変える」は手順に頼る守りで、
  **忘れれば公開済みの資格情報で誰でも入れる**。追跡外なら構造的に漏れない
- [CLAUDE.md §5](../../CLAUDE.md) に**例外を 1 つ抱え、ADR と `lint_secrets_allow.txt` で柵を作り続ける**ことになる。
  追跡外なら**例外はゼロ**——「環境固有設定は `*.sample` だけ追跡し、実体は `.gitignore`」という
  **既にある規則そのもの**であり、例外ではない
- 公開リポジトリを読む人に「平文パスワードがある」と見える。守っているものが無くても、**説明が要る状態**になる

### 3. 追跡外の短所「Claude が読むか」は、既に解けている

[17 §3](../17_検証のルール.md) が置き場を指し、Claude は [CLAUDE.md §0-4](../../CLAUDE.md) で検証の前に 17 を読む。
**「開発者に毎回聞かない」という当初の目的は満たせる。**

### 4. `admin` は CLB の既定であり、本 ADR の対象外

`admin` / `admin` は**ユーザーテーブルが空のときサーバ起動時に自動生成される**もので、
本プロジェクトが決めた値ではない。**秘密でもない**（CLB の仕様書に載っている）。
ADR-0031 も同じ判断をしていた。**追跡下の文書に識別名を書いてよい**——[17 §3](../17_検証のルール.md) は 3 つの識別名を書いている。

### 5. ADR-0031 から、生きている決定を引き継ぐ

**開発・デモ専用の初期データを `Designer/seed/dev/` に分け、本番相当の投入手順（`001`〜`004`）に入れない。**
理由も引き継ぐ——導入手順どおりに流した環境に、**デモ用の役割が構造的に入らない**。
`dev/001_demo_user_roles.sql` が付けるのは**役割だけ**である。
依存している先: `DevSeedDataTests`・`TestDatabase`・[ADR-0032](0032-認証部品のapp_usersを正典に迎え入れる.md)・
[ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md)・[05](../05_実装計画と現在地.md)・
[`Designer/seed/README.md`](../../Designer/seed/README.md)。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 追跡下の文書（CLAUDE.md や 17）に平文で書く | **§1・§2。** 長所が幻で、短所が本物 |
| `Designer/seed/dev/` の SQL に書く（ADR-0031 の決定） | **実装できない**（状況 1）。**「そこに置ける」を確かめてから置き場所を決める**——これは決め方の教訓でもある |
| 値を伏せ、聞かれたら開発者が答える | **これまでがそれで、実機確認のたびに止まっていた**（状況） |
| .NET User Secrets に置く（[CLAUDE.md §5](../../CLAUDE.md) が秘密の置き場と定めている） | **Claude が読めない**——`.claude/settings.json` が `secrets.json` の読み取りを拒んでいる。秘密ではない値のためにそれを緩めるのは本末転倒 |

## 帰結

- **`Designer/LocalEnvironment.md.sample` を追跡する**（いままで無かった。[CLAUDE.md §5](../../CLAUDE.md) の
  「`*.sample` だけ追跡」に対する既存の穴でもあった）
- `lint_secrets_allow.txt` から CLAUDE.md の登録を外す。**例外は無いので、痕跡も要らない**
- [`Designer/seed/README.md`](../../Designer/seed/README.md) の手順に「作ったら LocalEnvironment.md に書く」を足す
- **開発者が意見を問うたときは、開発者の過去の発言を根拠にしない。** 「こう言った」を外して比べ直したら
  結論が反転した。**ゼロベースで考える**（[30 §4](../30_作業のルール.md)）の実例である
