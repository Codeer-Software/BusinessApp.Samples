# ADR-0048: 承認ルートを「入れ替え」から「積み上げ」方式へ

- 日付: 2026-08-09
- 状態: 採用（DB のテンプレート再編・`ddl/460` 適用済み）
- 関係: ADR-0023（承認ルート判定のマスタ化）・ADR-0044（部課階層と walk-up 承認・重複段の圧縮）・ADR-0010（自己承認の禁止）

## 背景

従来のテンプレート構成は、金額が上がると**承認者が入れ替わる**設計だった。

| 判定額 | 旧ルート |
|---|---|
| 0〜29,999 | 課長 |
| 30,000〜199,999 | **部長**（課長は関与しない） |
| 200,000〜 | **部長** → 総務 |

これには 2 つの問題があった。

1. **実務と合わない。** 日本の稟議は上位者が下位者の承認を経て回ってくるのが通例で、
   入れ替え方式だと**自分の課の支出なのに課長が知らないまま部長決裁される**。
   3 万円を境に、課長が把握する支出と把握しない支出が生まれるのは運用上おかしい（ユーザー指摘 2026-08-09）。
2. **ADR-0044 で作った「重複段の圧縮」がほとんど働かない。** 圧縮は
   「課長段が walk-up で部長へ繰り上がった結果、次の部長段と承認者集合が一致したら段を 1 つに畳む」機構だが、
   テンプレートに課長段と部長段が同居していなければ発火しようがない。

## 決定

**承認段を積み上げる。** テンプレート名は「**〜まで**」が役職ラインの終端、「**＋総務**」が合議段を表す規約に統一する。

| 適用条件（approval_route_rules） | テンプレート | ルート |
|---|---|---|
| 全費目 0〜29,999 | `経費_課長まで` | 課長 |
| 全費目 30,000〜199,999 | `経費_部長まで` | **課長 → 部長** |
| 全費目 200,000〜 | `経費_部長まで＋総務` | **課長 → 部長 → 総務** |
| 交際費 0〜29,999 | `経費_課長まで＋総務` | 課長 → 総務 |
| 交際費 30,000〜 | `経費_部長まで＋総務` | **課長 → 部長 → 総務** |

- **`approval_route_rules` の割り当ては変更していない**（同じテンプレートを指したまま、テンプレートの中身が変わった）
- 少額の交際費だけ部長を飛ばすのは、5,000 円の会食に部長決裁を求めるのは重いという判断。
  部長を通したい導入企業は、交際費のルール 2 行をどちらも `経費_部長まで＋総務` に向ければよい
- テンプレートは**申請時にコピーされる**ため、進行中・過去の申請には影響しない（ADR-0023 の性質）

### walk-up との相互作用（この変更の眼目）

積み上げにしたことで、ADR-0044 の一般則が特例なしに正しく効くようになった。

| 状況 | 挙動 |
|---|---|
| 課長が居る通常のケース | 課長 → 部長の 2 段 |
| **申請者の課の課長が空席** | 課長段が walk-up で部長へ繰り上がり、次の部長段と同一集合になるため**段が 1 つに圧縮**され「部長のみ」になる |
| **課長本人が申請** | 本人が除外されて同じく部長へ繰り上がり、圧縮されて「部長のみ」になる |
| 部長も居ない | 経理代替 1 名 |

つまり「課長を飛ばしたい」ケースは、**組織の実態から自動的に導かれる**ようになり、
テンプレートを分ける必要がなくなった。

## トレードオフ

- **承認の手数が 1 つ増える。** 3 万円以上の申請は課長と部長の 2 人が触る。
  デモでもログインの切り替えが 1 回増える
- 20 万円以上は 3 段（課長 → 部長 → 総務）になり、体験としては長い。
  一方で「多段承認が正しく動く」ことを見せる題材にはなる
