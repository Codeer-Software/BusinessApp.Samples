# ADR-0055 クエリモジュールには、行を入れて読み戻すテストを必ず置く

## 状況

**クエリモジュールの SQL は別ファイルにあり、`designcheck` は中身を実行しない。**
`QueryModuleTests` が**全モジュールに自動で**かかるが、見ているのは
**宣言（`QuerySetting.Parameters`）と SQL の整合**だけである。
**結合の向きも、並び順も、部分一致の逃がし方も、日付の境界も、
行を入れて読み戻さないと分からない**（[qa/03 の L-12・L-19・L-20](../qa/03_テストで漏らした実例.md)）。

**その「行動テスト」は帳簿ごとの手書きで、書き忘れを止める仕組みが無かった**
（[qa/05 §6](../qa/05_観点網羅の計器.md) の 1 項目め。開発者の方針の GO は 2026-08-26 で、
**GO の対象は「4 つの計器を作る」までで細部は未決**）。

**実際に 1 本抜けていた。** `PartnerRegistrationList`（2026-08-31 に入った）は、
**宣言の整合しか見られていない状態で 2 週間動いていた。**
**ここに書いた決定は、2026-09-20 に開発者が承認した**（旧 Q-11。**もとは Claude のものだった**）。

## 決定

### 1. モジュール 1 本につき、`<モジュール名>QueryTests` を 1 つ要求する

**母数は `QueryModuleTests` と同じ数え方で取る**——`*.mod.json` のうち
`QueryFieldDesign` を持つもの。**サイドカーのファイル名（`*.Query.sql`）で数えない**
——名前は `<モジュール名>.<クエリ項目の名前>.sql` で、**項目の名前は `Query` に決まっていない**。
**2 つの計器が別の母数を数えると、片方から静かに漏れる**ので、一致をテストで見る。

**対応は名前で付ける。** 一覧表を持たない——
**表を作ると、モジュールを足した人が表も直さねばならず、直さなければ黙って外れる**
（[ADR-0012 §4](0012-テスト方針とカバレッジのゲート.md) の「許容リストは必ず腐る」）。
**名前の規約なら、規約から外れたクラスは最初から数えられない。**

### 2. ファイルではなく型で見る

**ソースのファイル名で探さない。** ファイルなら、
**プロジェクトから外れていても・中身が空でも、置いてあるだけで通る**。
**アセンブリを反射で見て、`[Fact]` か `[Theory]` を 1 つ以上持つことまで要求する。**

### 3. 測れるのは「クラスがあるか」までである

**中身が薄いテストは見えない。** [ADR-0054 決定 2](0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md) と同じ限界で、
**測れないものを測ったふりをしない**。それでも**「1 本も無い」は機械が言える**。

### 4. 母数そのものにラチェットを置く

**列挙が壊れて 0 件になると、下の検査は「全部通った」ように見える。**
`MinimumQueryModules` を置く（[ADR-0054 決定 1](0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md) と同じ作法）。
**`QueryModuleTests.クエリモジュールが一つ以上ある` より強く、いまの本数で縛る。**

### 5. 行動テストの十分性は、SQL を 1 箇所ずつ壊して確かめる

**クラスがあることは、検査があることではない**（決定 3）。
**書いたその場で、SQL の変異を手で当てて赤くなるかを見る**
（[qa/05 §3](../qa/05_観点網羅の計器.md) の自動化はまだ無い）。
**当て先は WHERE と ORDER BY だけでは足りない**——
**SELECT 句の列の取り違えは、`QueryModuleTests` が別名しか見ていないので
行動テストだけが唐門**である。
**等価ミュータント（壊しても振る舞いが変わらないもの）は、見つけたら記録して先へ進む。**

## 実測（2026-09-14）

| 測ったもの | 値 |
|---|---|
| `Designer/Design/Modules` の `QueryFieldDesign` を持つモジュール | **4 本** |
| 行動テストを持っていたもの | **3 本**（`JournalBook`・`GeneralLedger`・`JournalEntryList`） |
| 持っていなかったもの | **1 本**（`PartnerRegistrationList`。この回で書いた） |
| 書いた行動テスト | **10 メソッド・24 ケース**（`[Theory]` の組を 1 ケースと数える） |
| 当てた変異 | **18 個**——**14 個を殺し、4 個は等価**だった |

**測り方**——`PartnerRegistrationList.Query.sql` を**1 箇所だけ**書き換えて
`dotnet test --filter FullyQualifiedName~PartnerRegistrationListQueryTests` を流し、
**赤になるかを見て、原本に戻す**（`--no-build` で 1 個あたり 7 秒ほど）。
**同時に 1 箇所しか変えない**のがミューテーションテストの原則である。
**自動化は [qa/05 §3](../qa/05_観点網羅の計器.md) の計器で、まだ無い。**

**殺した 14 個**——並びを識別子（`p.id`）にする／登録年月日を新しい順にする／
始まりの境界を外す（`>=` → `>`）／終わりの境界を外す（`<=` → `<`）／
検索値側の `date()` を外す（`>=` の行）／列側の `date()` を外す（`<=` の行）／
登録番号の逃がしを丸ごとやめる／逃がす順序を逆にする／`%` だけ素通し／`_` だけ素通し／
`\` だけ素通し／取引先の未指定を空文字で受けるのをやめる／
編集リンクの列を取り違える（`r.id` → `r.partner_id`）／列の別名を取り違える（`ended_on`）。

**生き残った 4 個は、どれも「スキーマを読めば等価と分かる」形である**——
**テストの弱さではなく、変異の生成の側で外せる**（下の「帰結」）。

| 生き残り | なぜ等価か |
|---|---|
| `JOIN` を `LEFT JOIN` にする | **外部キーがある**ので、取引先の無い登録は存在しない |
| 登録番号の未指定を空文字で受けるのをやめる | 空文字は `LIKE '%%'` に落ち、**`NOT NULL` 列には全件当たる** |
| 列側の `date()` を外す（`>=` の行） | 値が ISO に正規化されていれば（011 のトリガが入口で保証）、`date(列)` は列の先頭 10 文字。**`>=` では列側の `date()` が結果を変えない** |
| 検索値側の `date()` を外す（`<=` の行） | 同じ理由で、**`<=` では検索値側が結果を変えない** |

**日付の 2 件は総当たりで確かめた**——15 通りの格納形 × 15 通りの検索値（225 組）で、
**差が出る組が 0** である（残る 2 つの向き、すなわち `>=` の検索値側と `<=` の列側は、
**それぞれ 60 組で差が出る**。だから殺せる）。

**最初に書いたテストは、これらを 1 つも殺していなかった。** 直した点が 3 つある。

- **`date()` の検体が「列に時刻が付いている場合」しか無かった。**
  **列側は終わりの境界を、検索値側は始まりの境界を落とす**——**壊れ方が逆**なので、
  片側の検体ではもう片側の `date()` を外しても緑のままだった。4 通りの組み合わせを全部通す形に直した
- **逃がしの検体に、逃がしても外しても 0 件のものが混ざっていた**（`T1%4`）——
  **どう壊しても赤くならない**（[ADR-0012 §2](0012-テスト方針とカバレッジのゲート.md) が禁じた「通るだけのテスト」）。
  検体の登録番号に `\` を入れ、**5 通りの壊し方を 1 つずつ殺す**組に置き換えた
- **12 列のうち 6 列を読み戻していなかった。**
  `QueryModuleTests` が突き合わせるのは**列の別名だけ**なので、
  `r.confirmed_on AS ended_on` のような取り違えは 2 つの関門を素通りする。
  とくに `reg_id` はデザインの編集リンク（`EditLink.IdVariable`）が使う値で、
  **取り違えれば別の登録行が開く**。**いまその列は画面に出ていない**が
  （一覧は読み取り専用。[14 §4](../14_適格請求書発行事業者の登録.md)）、
  **誰も見ていない列こそ、壊れても誰も気づかない**。行まるごとの表明を 3 行ぶん置いた

## 検討したが採らなかった案

- **`QueryModuleTests` の中に足す。** あちらは「宣言と SQL の整合」の道具で、
  **こちらは「行動テストがあるか」を測る計器**である。**混ぜると、どちらが鳴ったのか分からなくなる**
- **行動テストのクラス名を属性で宣言させる**（`[QueryBehaviorFor("JournalBook")]`）。
  対応を明示できるが、**属性を付け忘れたら外れる**——決定 1 と同じ理由で採らない
- **表明の本数や種類まで要求する。** 測れない（決定 3）。
  **本数を要求すると、数合わせのテストが書かれる**（[ADR-0012 §2](0012-テスト方針とカバレッジのゲート.md) が禁じている形）

## 帰結

- **クエリモジュールを足した人は、行動テストを書くまで赤いままになる**
- **等価ミュータントの持ち方は、まだ決めていない。** この回は 4 件をここに書き留めただけである
  ——**自動化（[qa/05 §3](../qa/05_観点網羅の計器.md)）を入れる回に、仕分け結果の持ち方ごと決める**
  （[同 §8 の保留](../qa/05_観点網羅の計器.md)）。
  **4 件とも「スキーマを読めば等価と分かる」形**だったので、
  **仕分けの前に、生成の段階で外せる見込みがある**（外部キー・`NOT NULL`・日付の正規化）——
  **これが今回得た一番大きな手がかりである**
