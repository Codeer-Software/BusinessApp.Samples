# ADR-0068 docs の文書だけを変えた回は、ミューテーションの段を流さない

## 状況

**2026-09-22 に開発者が問うた**（逐語）——

> docs/ 以下しか編集していないときはStrikerやC#の自動テストは不要な気がしました。どう思いますか？

**Claude は「切るべきはミューテーションの段だけである」と答えた**（`dotnet test` と行セットの掃引は残す。理由は下）。
**開発者はその答えに「オッケーです」と述べ、実装を指示した**（同日。逐語は「オッケーです。①②ともその順番で行ってください」。
**①は [ADR-0067](0067-マージコミットは木がブランチ先端と同じなら木から決まる段を流さない.md) の仕組みが効いていなかったことの修正**で、②が本書である）。

**判断の材料は 3 つある。**

- **コミット前フックの所要は全段で 382 秒、うちミューテーションが 302 秒（79%）、残りの段が合計 80 秒である**
  （**2026-09-20 の実測**。ADR-0067 の状況節。この日の値をそのまま引いている）。
  **その 80 秒の内訳のうち、`dotnet test` が 38 秒**（1529 件）、**行セットの掃引が 10 秒**である
  （**2026-09-22 に、`dotnet test BusinessApp.slnx` と `sql_sweep.ps1 -Mode Rows` を単独で流して測った**）
- **`main` のマージを除く 356 コミットのうち、76 本（21.3%）が不活性な文書だけを変えている**
  （下の 2 本を除いた `docs/` の下の `.md`）。**直近 50 本では 14 本（28.0%）**である
  （**`bd3e5bb7` 時点の `main` を数えた**）
- **C# のテストがリポジトリの中から読むのは、`*.cs`・`Designer/Design/**` の JSON・`.editorconfig`・
  `.gitattributes`・`*.csproj`・`BusinessApp.slnx` と、`Directory.Build.props`／`.targets` である**
  （最後の 2 つは**読みに行く先で、いまは置かれていない**——置かれた日から入力になる）。
- **そして `docs/` の下の 2 本も読んでいる**——`docs/10_会計ドメイン設計.md`（不変条件のカタログ）と
  `docs/40_優良な電子帳簿の対応表.md`（制度要件のカタログ）である。
  読んでいるのは `InvariantTraceabilityConvention`・`RequirementTraceabilityConvention`・`JournalViolationCodesTests` で、
  **どれも `BusinessApp.AccountingCore.Tests`**——**ミューテーションが使うテストプロジェクトそのもの**である。
  **Claude は初め「`docs/` を読む経路は 1 つも無い」と書いた。誤りだった**——
  `File.ReadAllText` の引数を正規表現で探したが、**実物は定数と `Path.Combine` で組まれていて引っかからなかった**
  （自己レビューで指摘され、実物を開いて確かめた。型は [qa/03 の L-64](../qa/03_テストで漏らした実例.md)）

## 決定

**開発者が決めたのは次の 2 つである**（2026-09-22。上の逐語）。

1. **これからコミットする木と `HEAD` の差が、全部「不活性」なら、ミューテーションの段を流さない。**
   **不活性**＝ミューテーションの段の入力になりえない、ということ。
   いまそれに当たるのは「`docs/` の下の `.md`」のうち、**上の 2 本を除いたもの**である
2. **飛ばすのはその 1 段だけである。** ほかの段はすべて流す（**段の一覧の正典は [tools/README](../../tools/README.md)**）

**以下 3 つは Claude の敷衍である**（実装の方針。開発者未承認）。

3. **判定は「全部が不活性なら飛ばす」と足し算で書く。** **「`.cs` が無ければ飛ばす」と引き算で書かない**（理由節）
4. **判定できないときは流す**（最初のコミットで `HEAD` が無い・git が動かない）。
   **差分が 0 件のときも流す**（これは「判定できない」ではなく「飛ばす条件を満たさない」側である）
5. **飛ばすときも、飛ばす理由を印字する。** 黙って飛ばさない（ADR-0067 決定 5 と同じ）

**Claude の読み**——機械が見る契機を減らす向きなので [34 §1](../34_開発者とClaudeの分担.md) の 8「品質測定基準を下げる決定」に当たると読み、開発者に諮った（ADR-0067 と同じ型）。

## 理由

- **1 段で 79% が浮く。** 飛ばす回は 382 秒 → 約 80 秒になる。**そういう回は直近 50 本のうち 14 本（28%）ある**
- **`dotnet test` と行セットの掃引は残す。** 飛ばしても**48 秒しか浮かない**のに、
  **判定が壊れたときに鳴るものを失う**——**C# の変更を「docs だけ」と読み違えても、
  テストとカバレッジが赤くなる**からである。
  **ただし、この 2 つは「ミューテーションが見ているもの」までは見ない**
  ——**テストが緑のまま生き残る変異**は掛からない（そのためにミューテーションの段が別に置いてある。[ADR-0012 §8](0012-テスト方針とカバレッジのゲート.md)）。
  **残す価値は「判定の誤りに気づける」ことであって、ミューテーションの代わりになることではない**
- **「全部が不活性なら飛ばす」と書くのは、「`.cs` が無ければ飛ばす」が腐るからである。**
  C# のテストは `*.cs` 以外も読んでいる（状況）。**入力の種類を書き下すと、種類が増えた日に、既定が「飛ばす」へ倒れる**
  ——[ADR-0025 §6](0025-取引先を部品として分ける.md) が分割の受け入れ条件として警戒している
  「**分割時にゲートを持ち出し忘れると、テストは全部緑のまま、取引先だけが静かに検査の外へ落ちる**」と同じ形である
- **`HEAD` と比べれば足りる。** 差が不活性なものだけなら、
  **`HEAD` のコミット前フックが、この段の入力を同じ姿で検査している**
  （ADR-0067 が「木が同じならブランチの最終コミットが検査済み」と言うのと同じ筋である）

## 検討したが採らなかった案

| 案 | 採らない理由 |
|---|---|
| **`dotnet test` と行セットの掃引も飛ばす**（開発者の問いが挙げた範囲。**ただし逐語は「C#の自動テスト」までで、行セットの掃引には触れていない**） | **浮くのは 48 秒で、失うのは「判定が壊れたときに鳴るもの」である。** 割に合わない |
| **「`.cs` が無ければ飛ばす」と書く** | **入力の種類を書き下すことになり、種類が増えた日に腐る。** 腐り方が「既定で飛ばす」側なので気づけない |
| **[`which_gates.py`](../../tools/clb/which_gates.py) に相乗りする** | あちらは**流す契機を印字するだけの道具で、関門を開け閉めしない**（同ファイルの冒頭と [31 §6](../31_検証のルール.md)）。**判定と印字の責務が混ざる** |
| **ミューテーションの入力になるパスだけを集めた部分木を作り、`HEAD` のものと比べる**（ADR-0067 の木の比較を、段ごとに絞った形） | **どのパスが入力かを書き下すことになる**（上の引き算と同じ腐り方）。**ADR-0067 が比べているのは木そのもの**で、書き下しが要らない——**段ごとに絞った瞬間に、その利点が消える** |

## 帰結

- **判定は [`tools/git-hooks/docs_only.py`](../../tools/git-hooks/docs_only.py) が持つ**（**不活性と認めるパスの正典もそのファイル**。
  いまは「`docs/` で始まり `.md` で終わり、テストが読む 2 本ではない」である。`docs/` の下の下でも当たる）。
- **「テストが読む 2 本」の一覧が腐らないように、自己検査が C# の側を走査して突き合わせる。**
  見るのは「**注記でない行に、文書のパスらしい文字列がある**」ことで、
  **文書のパスらしい**＝`"docs"` そのものか、`docs` と `.md` を両方含む字である。
  **それを書いている C# の顔ぶれと、そこで名指しされる文書の両方**を一覧と突き合わせる。
  **`Path.Combine` で分けても、`@"docs\…"` でも、`"../../../docs/…"` でも掛かる**
  ——**初めの走査は読み取りの呼び出しの形だけを見ていて、どれも取りこぼした**（qa/03 の L-64）。
  **`.csproj` の `EmbeddedResource` と `.razor` は見ていない**（いまは該当が無い）
- **Claude の読み**——**不活性と認めるパスを広げるのは開発者の決定である**。
  [34 §1-3](../34_開発者とClaudeの分担.md) の箇条に「不活性なパスを足す」は無いが、
  **広げるほど流れない回が増える**ので、型としては同じ側だと読む
- **検体は本物の `git add` で索引を作ってから判定する**（[qa/03 の L-63](../qa/03_テストで漏らした実例.md)。
  手で作ったパスの一覧を渡す検体は、**本番の入力を一度も通らない**）
- **段は [`tools/git-hooks/mutation_stage.sh`](../../tools/git-hooks/mutation_stage.sh) に切り出してある。**
  **検体から流せるようにするため**である——`dotnet` と判定を切り株に差し替えてこのファイルを実際に流し、
  次の 5 つを見る。**飛ばす回に `dotnet` が 1 度も呼ばれないこと**、**判定を引数なしで呼んでいること**
  （`--selftest` を足すだけで毎回飛ぶ書き換えが通ってしまうため）、
  **流す回に 5 つのプロジェクトへ、決めた引数**（ラチェットの値を含む）**で撃つこと**、
  **その作業ディレクトリも決めたとおりであること**、**最初の 1 本が落ちたらそこで止まって非 0 で終わること**。
  **初めは「`dotnet stryker` の行が判定の内側にあるか」を字で読むだけだった。**
  **それでは判定の反転（`!` を 1 つ足す）も、骨抜き（`|| true`）も、5 段のうち 4 段を消すのも素通りした**
  （自己レビューのレビュアが変異体を作って実測した）。**しかも `else` に注記を足しただけで誤って赤くなった**
  ——**守れないのに、直すと鳴る**。字で読む検査をやめて、切り株で流す検査に替えた
- **フックがその段を呼んでいることは、字で見ているだけである**（`pre-commit` に
  `sh tools/git-hooks/mutation_stage.sh` の行があるか）。**段ごと消されたときに黙らないための最低限**で、
  **それ以上は見ていない**——本物の `pre-commit` を通しで流すには全段が要り、検体からは重すぎる
- **差分は `--raw -z --no-renames` で引く。** 3 つとも理由がある——
  **`--raw` はモードを見るため**（名前が `.md` でも、**シンボリックリンクや gitlink は不活性と言い切れない**）、
  **`--no-renames` は改名の両側を数えるため**（**既定の `git diff` は改名を 1 行にまとめて消えた側を隠し**、
  `code.cs` を `docs/code.md` へ改名した回が「docs だけ」に見える）、**`-z` は引用を無効にするため**。
  **印とパスの数が合わないときは「判定できない」へ倒す**——改名の検出が効くと 1 件が 3 つ組になり、
  **`zip` が黙って余りを捨てて 1 件を落とす**（どれも 2026-09-22 に実測して塞いだ。検体を置いてある）
- **マージのコミットでもこの判定は走る。** ADR-0067 の全段の経路（`pre-merge-commit` が `pre-commit` を `exec` する）を通るときで、
  **そのときの `HEAD` は第 1 親、つまり `main` である**——**そのマージが `main` へ持ち込む差分**を見ることになる。
  差が文書だけなら、その木のミューテーションの入力は `main` と同じ姿なので、筋は同じである。
  **軽い経路（木が同一）ではこの判定まで来ない**——ADR-0067 が `migrate.ps1 -Verify` だけを流すからである
  （**決定 2 の「ほかの段はすべて流す」は、この段が流れる回についての話である**）
- **本番の判定は、git が渡した環境をそのまま使う。検体だけが落とす。**
  **git は `pre-commit` に `GIT_INDEX_FILE` を渡す**——`git commit -a` や `git commit -- <パス>` では
  **一時の索引の絶対パス**である。**落とすと、コミットに入る `.cs` を見落として飛ばす**
  （2026-09-22 に実測。**初めは落としていた**——ADR-0067 の回の直しをそのまま当てて、やりすぎた）。
  **落とすのは、使い捨てのリポジトリを撃つ検体の側だけ**である
  （[`_gitenv.py`](../../tools/git-hooks/_gitenv.py)。落とさないと**本番の索引を壊す**）。
  **検体のリポジトリには `core.hooksPath=` と `init.templateDir=` を空で渡す**
  ——グローバル設定やテンプレートから**本番のフック一式を拾って走らせてしまう**からである（同日に実測）
- **判定は本番の起動経路でも撃つ。** 使い捨てのリポジトリに判定の写しとフックを置き、
  **git に `git commit -a` させて印字を受け取る**——**`judge()` を直に呼ぶ検体だけでは、
  git が渡す一時の索引を一度も通らない**（qa/03 の L-63 と同じ型が、別の面で残っていた）
- **失うものは ADR-0067 と同じ**——`--no-verify`・rebase・cherry-pick・`--amend` で作った先端では、
  「`HEAD` は検査済み」という前提が切れる。それを作らないのは [30 §7](../30_作業のルール.md) の規則の側が守る
- **ミューテーションの下限（ラチェット）は動かしていない**（[ADR-0012 §8](0012-テスト方針とカバレッジのゲート.md)）。
  **文書だけの回に流さないだけで、C# を触った回は今までどおり毎回流れる**
