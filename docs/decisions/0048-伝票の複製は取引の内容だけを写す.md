# ADR-0048 伝票の複製は取引の内容だけを写し、出来事の記録は写さない

## 状況

**訂正の下書きを消すと、原仕訳は取り消されたまま残り、内容を写す手段が無くなる**
（[qa/04](../qa/04_実機操作テスト.md) の 2026-09-04。探索的テストの 3 巡目で実測）。
**訂正の流れは「打ち直さなくてよい」ためにある**（[ADR-0015](0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md)）のに、
下書きを 1 つ消した瞬間に打ち直しになる。

同じテストの「直すこと」は、こう書いてある（**中の 1 文を省いている**）——

> 既存の伝票を写して新しい下書きを起こす導線を置く。（…）
> 取消済み・訂正済みでも押せてよい（**新しい記帳**だから）。

[04 §1](../04_実装計画と現在地.md) の C（画面）は**伝票の複製から始める**と決めている
（**着手の順は開発者の承認**。2026-09-05）。

**複製は会計コアではなく、会計補助（ステートレス）である**
（[ADR-0049](0049-会計補助はステートレスなものだけを作り会計コアのドメイン層には置かない.md)。2026-09-10 の開発者との往復で位置づけた）。
入力を容易にするだけで、無くても帳簿は作れる。新しい永続化を 1 つも要しない。
**0007 が外した「定型仕訳・仕訳辞書」との違いは、雛形（新しい状態）の有無**であって、
会計の判断が要るかどうかではない——当初この ADR は「何を写すかは会計の判断だから内側」と書いたが、
**「何が定型かは会計の判断」とも言えてしまう**ので、その論は取り下げた（開発者の指摘）。
**複製は「既に画面にある情報の打ち直しを避ける」段階（0049 の ②）に当たる**
（後からの当てはめ。作った理由は上の受け皿である）。訂正の下書きを消したとき・同じ取引をもう一度起こすときの両方で効く。

**市販ソフトは調べていない。** 呼び名（「複製する」）も、写す欄の線引きも、
[32 §2](../32_調査のルール.md) が求める比較を行わずに決めている
——**訂正の下書きを消したときの受け皿**という 1 つの用途から決めたので、
**他社がこの機能をどう呼び、何を写しているかは分からないまま**である。

## 決定

**「複製」は、原仕訳と同じ内容の下書きを 1 本作る。取消・訂正とは別の操作である。**

### 1. 写すのは「取引の内容」だけ

伝票は `TransactionDate`・`Description`・`PartnerId`。
明細は `DebitCredit`・`AccountId`・`SubAccountId`・`DepartmentId`・`PartnerId`・
`Amount`・`TaxCategoryId`・`TaxTreatment`・`TaxPoint`・`ItemDescription`・`BookOnlyDeduction`。

**`TaxPoint`（課税仕入れの時点）を写すのは、この欄が画面に無いからである**
（`JournalLine.mod.json` は欄を定義だけ持ち、**どのレイアウトにも出していない**。2026-09-09 に実測）。
**空のままなら、登録番号を引く日として取引日が使われる**
（`LedgerSnapshotWriter.TaxPointOf` の `line.TaxPoint ?? entry.TransactionDate`。
**列の値が書き換わるわけではない**）——つまり**写しても、空の伝票では取引日に従う**。
入っている値は**取引の事実**である——支払日で起票した未払金の決済や締め日基準の一括計上では、
取引日と課税仕入れの日がずれる（[qa/02 R10-03](../qa/02_自己レビュー記録.md) が挙げた例。
恒久の解は画面に `tax_point` を持たせることで、[13 の保留リスト](../13_取引先設計.md)に積んである）。
**その日で経過措置の控除割合が決まり**（[11 §5](../11_消費税設計.md)）、
**税率も課税仕入れの時点で決まる**（[10 §2](../10_会計ドメイン設計.md)）。だから
落とすと同じ取引なのに課税仕入れの日が黙って変わり、**利用者は入れ直せない**。
**「写さない」の既定は「利用者が入れ直せる」ことを前提にしている**——
この欄だけその前提が成り立たない（2026-09-09 の自己レビュー）。

### 2. 写さないのは「出来事の記録」

**その伝票 1 本にしか意味の無いもの**は、1 つも写さない。

| 項目 | 新しい値 | 理由 |
|---|---|---|
| `Id` | なし | 新しい行である |
| `EntryNo` | なし | 計上時に採る。欠番を埋め直さず再利用もしない（[10 §4-1](../10_会計ドメイン設計.md) の I-17） |
| `Status` | 下書き | |
| `EntryType` | 通常 | **訂正を複製しても、できるのは通常の記帳である** |
| `OriginalEntryId` | なし | 原仕訳との関係は複製に無い（I-06 は訂正・取消だけの規則） |
| `PostingDate` | **複製した日** | 決定 5 |
| `FiscalYearId` | 計上日の属する年度 | 取消・訂正と同じ考え方 |
| `PostedAt` / `PostedBy` | なし | 下書きだから |
| `EnteredAt` | いま | 入力年月日はシステムが付ける（[10 §2](../10_会計ドメイン設計.md)）。利用者は変えられない |
| `IdempotencyKey` | なし | 一意（I-14）。写せない |
| `SourceComponent` / `SourceDocumentId` | なし | **投入元は「その部品が投げた」という事実**。手で複製したものは手入力である（[10 §10](../10_会計ドメイン設計.md)） |
| 明細 `PartnerNameSnapshot` / `RegistrationNoSnapshot` | なし | **計上時点の写し**（[ADR-0018](0018-帳簿の記載事項は計上時に写して固定する.md)）。新しい計上のときに取り直す |
| 明細 `AppliedRuleVersion` | なし | **I-16**。適用した制度の版は伝票ごとに決まる。写すと新しい日付に古い版が付く |
| 明細 `EvidenceRef` | なし | 証憑はその取引のもの |
| 明細 `IsTaxLine` / `ParentLineNo` | なし | 税行ごと落とす（決定 3） |

**「写さない」を既定にする。** 迷ったら写さない側に倒す——
**写し忘れは利用者が入れ直せるが、写しすぎは帳簿に嘘の記録を残す。**

### 3. 消費税行は落とし、行番号を 1 から振り直す

**消費税行はシステムが生成する**（[11 §2](../11_消費税設計.md)）——
**生成の実装はフェーズ 3 で、いまは無い**。それでも税行のある伝票は
`sql` CLI と手打ちの SQL で作れる（DDL は `is_tax_line` を許す）ので、
**複製がそれを写す経路は先に塞いでおく**。
落とさないと、**利用者が直せない行だけが古い金額のまま残る**。
落とすと行番号に穴が空くので、**残した本体行を 1 から振り直す**
（`ParentLineNo` は税行と一緒に消える）。

### 4. 訂正を複製したら、摘要の接頭辞は落とす

**複製でできるのは通常の伝票である**（決定 2）。それなのに摘要を丸ごと写すと、
**「伝票番号 44 の訂正」と名乗る通常の伝票**ができる。

**摘要は帳簿の記載事項「内容」に当たる**と本製品は当てはめている
（**Claude の当てはめ**。現在形は [40 §4-1](../40_優良な電子帳簿の対応表.md)、
条文の要旨と出典は [10 §4-2-1](../10_会計ドメイン設計.md) が持つ。[ADR-0045](0045-振替伝票1枚には1つの取引だけを記す.md) と同じ読み）。
その当てはめに立てば、**していない訂正を帳簿に書くことになる**。

**取消伝票そのものに条文がどう当たるかは、まだ決まっていない**
（[README の保留リスト](../README.md)。**開発者に諮っていない**。フェーズ 4）。
**ここで決めているのは「複製した通常の伝票の摘要」の話**で、その未決には触れない。

**接頭辞を落として本文だけを引き継ぐ**（訂正の摘要を作るときと同じ規則。`AmendmentRules`）。
**本文が空になるなら摘要も空にする**——引き継ぐものが無い。
**計上には摘要が要る**ので、利用者はそこで何の取引かを書くことになり、それが正しい。

**通常の伝票の摘要は、同じ形をしていても剥がさない。** 利用者が
「伝票番号 12 の取消について」と書くことはあり、剥がすと本文を落とす。

**2026-09-09 の実機確認で見つけた。** 取消伝票を複製したら、摘要がそのまま付いてきた
（当時は取消伝票も元にできた。決定 6 で外したので、いま接頭辞が写りうるのは訂正だけである）。

### 5. 取引日は写す。計上日は今日にする

**取引日を写すのは、複製がいちばん効く場面が「同じ取引をもう一度起こす」だから**である
（訂正の下書きを消した受け皿がまさにこれで、**原仕訳と同じ取引日でなければ意味が無い**）。
[訂正](0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md)が取引日を写すのと同じ理由で、**利用者は直せる**。
**計上日を今日にするのは、複製が「いま起こす記帳」だから**である。
原仕訳の計上日を写すと、**締め済みの期間へ新しい伝票を落とせる**（[10 §1](../10_会計ドメイン設計.md) の I-04）
——計上の関門が断るので落ちはしないが、**利用者は押すまで気づけない**。

### 6. どの状態の伝票からでも複製できる。ただし元にできる種別は、取消・訂正の対象にできる種別と同じ

下書きからも、計上済みからも、**取消済み・訂正済みの原仕訳**からも押せる。
**複製は新しい記帳であって、原仕訳の状態に何も依存しない**
（対して取消・訂正は原仕訳の状態を見る。`AmendmentRules.ValidateOriginal`）。

**元にできる種別は通常と訂正だけ**——`IsAmendable`（取消・訂正の対象にできる種別）と同じ集合である。
期首残高・決算振替・繰越を元にすると、**複製でできるのは通常の伝票**なので、
「損益 → 繰越利益剰余金」を**期中に通常の伝票として計上できる**（I-10 が崩れる）し、
繰越の複製は翌期首の残高を二重に載せる（I-12）。

**取消伝票（種別が取消）も元にできない**（開発者の決定。2026-09-10）。
当初この ADR は取消伝票も元にできるとしていたが、それは**「取消済みの原仕訳」と「取消伝票」の取り違え**だった
——qa/04 の要件「取消済みでも押せてよい」は、**取り消された原仕訳（種別は通常）**を複製できれば満たす。
誤って取り消した伝票を戻したいときも、複製すべきは原仕訳であって取消伝票ではない
（取消伝票の貸借——原仕訳の反転——がそのまま写る。2026-09-09 の A-08 で観測した）。
**取消伝票を元から外す向きは保守的**なので、法税規則 55 ① を取消伝票にどう当てるかの未決
（[README の保留リスト](../README.md)）に立場を取らずに済む（Claude の見立て。開発者に諮っていない）。

**ドメインに「複製できる種別」という属性は置かない。** 複製の可否は `IsAmendable` を読む——
ドメインが持つのは会計コアの名前の属性だけで、補助はそれを読むだけである
（[ADR-0049](0049-会計補助はステートレスなものだけを作り会計コアのドメイン層には置かない.md) の決定 6）。

**可否は画面がサーバに聞く。** 取消・訂正と同じ `availability` に `canDuplicate` を足してある——
**押せるのに必ず断られるボタンを出さない**（[21 §1](../21_画面の原則.md)）。

### 7. 複製そのものには確認を挟まない。挟むのは「保存していない変更があるとき」だけ

**複製は帳簿を 1 行も動かさず、できるのは下書き 1 本で、削除できる。**
取消（帳簿に残る）・訂正（取消を計上する）・削除（下書きが消える）とは、
**戻せるかどうかが違う**——だから確認の有無も違う。

**ただし、直しかけたまま押すと変更は失われる。** 写るのは**保存済みの内容**で、
複製の画面へ離脱するからである。**そのときだけ確認を出す**（CLB の `IsModified`）。
**離脱の確認は 20 レイアウトすべて未配線**（[04 §1](../04_実装計画と現在地.md) の C）なので、
いまはここが唯一の受け皿である。

### 8. 何を写すかはサーバが決める

画面が欄を写して新規画面へ渡す形にはしない（[ADR-0008](0008-CLBとCSharpライブラリの責務分担.md)）。
画面に置くと、**写し漏れがあってもテストで捕まらない**——上の表を守るのはテストである。
**置くのはアプリケーション層（`AccountingCore.Server`）であって、ドメイン層ではない**
（[ADR-0049](0049-会計補助はステートレスなものだけを作り会計コアのドメイン層には置かない.md) の決定 5。写す欄の取捨選択はユーザビリティのためのもので、会計コアのドメイン知識ではない）。
ドメインから借りるのは、取消・訂正の対象にできる種別（`IsAmendable`）とその断り
（`AmendmentRules.NotAmendableTarget`）、自分が付けた接頭辞を落とした本文（`AmendmentRules.Body`）だけである。
**断りの文も借りる**——集合が同じなのに文が 2 通りあると、片方だけ直した日にずれる。

### 9. 権限は「伝票を起こす」と同じ

経理担当と経理責任者（帳簿閲覧は不可）。**取消・訂正と同じ集合だが、理由が違う**
——複製は計上済みを 1 行も動かさないので、「起票できるか」で決まる
（[ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md)）。

## 検討したが採らなかった案

- **画面側で欄を写して新規画面へ渡す**（サーバを通さない）。決定 8 の理由で採らない。
- **取引日も今日にする。** 複製がいちばん効く場面（訂正の下書きの作り直し）で必ず打ち直しになる。
  **毎月の家賃のように「同じ取引をもう一度」の用途では、利用者が取引日を直すことになる**が、
  そちらは 1 欄の書き換えで済み、取引日を消す側の代償（何日だったか調べ直す）より軽い。
- **消費税行も写す。** 本体行を直したときに、利用者が直せない税行だけが古いまま残る。
- **複製した伝票に「どれを複製したか」を持たせる。** `OriginalEntryId` は
  訂正・取消のためのもので（I-06 が「訂正・取消では必須」と定める）、
  **複製に流用すると「取り消された伝票」の逆引きが壊れる**。
  由来を残す必要が出たら、別の列として起こす。

## 帰結

- **利用者が打ち直しから解放される。** 訂正の下書きを消しても、原仕訳から作り直せる。
- **複製は「新しい取引」なので、制度値も取引先の写しも計上時に取り直される。**
  ここを写していたら、**古い税率のまま計上できる経路**ができていた。
- **同梱の証憑・投入元との関係は切れる。** 複製した伝票は、外部部品から見ると手入力である。
- **明細の「内容」（`ItemDescription`）に書いた制度の「旨」も、そのまま写る。**
  経過措置の適用を受ける旨（[11 §5](../11_消費税設計.md)）と回収特例の相手方の住所
  （[11 §8](../11_消費税設計.md)・[13 §1-4](../13_取引先設計.md)）は、
  **相手方の登録状況と課税仕入れの日から決まる事実**なので、複製先では成り立たないことがある
  ——**決定 4 が摘要で潰した「していない事実を帳簿に書く」形が、この欄には残っている。**
  いまは**利用者が手で書く自由文**なので、写して直させるほうが打ち直しより軽いと判断した。
  **旨の持ち方（列にするか計上時に生成するか）はフェーズ 3 で決める**
  （[11 の保留リスト](../11_消費税設計.md)）。
- **原仕訳との関係も切れる**（`original_entry_id` を持たない）。
  **訂正の下書きを作り直すのに複製を使うと、帳簿には「取り消されたきりの伝票」と、
  無関係に見える新しい伝票が並ぶ**——[ADR-0015](0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md) の
  「履歴は `original_entry_id` で辿れる」が、この経路では成り立たない。
  **訂正のやり直し（取消済み・未訂正の原仕訳に再計上の下書きだけを起こす）は、別の操作として要る**
  ——[04 §1](../04_実装計画と現在地.md) の C へ送った（2026-09-09 の自己レビュー）。
- **取引日が今日より後の伝票を複製すると、そのままでは計上できない。**
  計上日は今日なので `計上日 < 取引日` になり、計上の関門が断る
（[10 §2-1](../10_会計ドメイン設計.md)。違反コードは `E-DATE-ORDER`）。
  **取引日は画面にあって直せる**ので行き止まりにはならないが、
  **断りが出るまで気づけない**（[qa/03 L-30](../qa/03_テストで漏らした実例.md) の型）。
- **下書きを複製すると、一覧で見分けの付かない下書きが 2 本並ぶ。**
  一覧が出すのは会計年度・伝票番号（下書きは空）・状態・種別・取引日・計上日・取引先・摘要・借方合計と、
  取消・訂正の逆引き 2 列である。**通常の下書きを同じ日に複製すると、どの列も同じ**になる
  （訂正を複製したときは、種別と摘要が変わるので見分けられる）。**開いた先が複製なのでその場では迷わない**が、
  あとから一覧を見ると区別できない。**両方を計上すれば同じ取引が 2 回帳簿に載る**
  ——これは手で打ち直しても同じことが起きるので、**複製が作った穴ではない**が、
  **1 押しで起こせるようになった**。一覧に入力年月日を出す案は
  [04 §1](../04_実装計画と現在地.md) の C へ送った（2026-09-09 の自己レビュー）。
