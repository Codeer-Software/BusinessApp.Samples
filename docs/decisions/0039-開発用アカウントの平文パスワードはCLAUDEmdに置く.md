# ADR-0039 開発用アカウントの平文パスワードは CLAUDE.md に置く

## 状況

**[ADR-0031](0031-デモ用の利用者アカウントは開発用のseedに置く.md) の決定は、実装できなかった。**
あの ADR は「デモ用の利用者アカウントを `Designer/seed/dev/` に置き、そこに固定の平文パスワードを書く」
と決めていた（選択肢 A）。しかし **`hash` と `salt` は CLB の `PasswordHashHelper` が作るもので、
SQL では作れない**（CLB 仕様リファレンス `_specs/Authentication.md`）。

結果、実際に動いているのは **ADR-0031 が却下した選択肢 C** である——
`Designer/seed/README.md` の手順どおり、`admin` でログインして画面で 2 人を手作りし、
`dev/001_demo_user_roles.sql` は**役割を付けるだけ**。**パスワードはリポジトリのどこにも無かった。**

**それで困ることが起きた。** Claude は [CLAUDE.md](../../CLAUDE.md) §4-1 により、
実装したものを毎回ブラウザで操作して確かめる。**ログインが要る。値がどこにも書いていないので、
開発者に聞くしかなく、実際に何度も聞いた。**

**2026-09-05、開発者が「CLAUDE.md に明記せよ」と指示した**——
**Claude が実機確認のたびに聞き直さずに済むようにするため**である。

## 決定

**`soumu_bucho` と `soumu_ippan` の識別名とパスワードを [CLAUDE.md](../../CLAUDE.md) §3-5 に書く**
（開発者の指示。2026-09-05。**上の理由**）。**パスワードは識別名と同じ。**

### 1. ADR-0031 を置き換える。「書き先が変わっただけ」ではない

**ADR-0031 は例外の範囲を「`Designer/seed/dev/` に置く値」という*パス*で固定していた**——
決定の 1 行目が置き場所を指定し、理由の節が「**範囲を狭く固定する**」と述べ、
帰結が「除外は**パスごと**にして、値のパターンで緩めない」と書いている。

**リポジトリで最も読まれるファイルへ値を移すのは、その固定を解くことである。**
ADR-0031 自身が「**例外を広げるときは新しい ADR を起こす**」と定めているので、これを起こす。
**追記で済ませようとしたが、それは誤りだった**（2026-09-05 の自己レビューで指摘された）。

**捨てるものも書いておく。** ADR-0031 が選択肢 C の長所として挙げていた
「**パスワードがリポジトリに一切載らない**」を、この決定は捨てる。

### 2. `admin` は対象外である

**`admin` / `admin` は CLB の既定**で、**ユーザーテーブルが空のときサーバ起動時に自動生成される**
（`_specs/Authentication.md`）。**本プロジェクトが決めた値ではないので、
[CLAUDE.md](../../CLAUDE.md) §5 の「秘密を書かない」の*対象外*であって、*例外*ではない。**
ADR-0031 も同じ判断をしていた（「`admin` / `admin` は前例にならない」「本 ADR の対象外」）。

**§3-5 の表には 3 行あるが、この ADR が扱うのは下 2 行だけ**である。
`admin` が表にいるのは、**ログインしてよいアカウントの一覧としては 3 つとも要る**からで、
表の「値の出どころ」の列がこの区別を持っている。

### 3. 例外は localhost を出た時点で失効する

**この値が守っているのは開発機のローカル SQLite だけである。**
**DB を localhost の外へ出した時点で、この例外は失効する**——そのときは値を変える。

**書いておく必要がある**のは、失効の条件が自明ではないからである。
[05](../05_実装計画と現在地.md) のフェーズ 7（デモデータ・通しの体験シナリオ）と
[CLAUDE.md](../../CLAUDE.md) §1 の目的③（製品化）は、**この DB を外へ出す場面を将来作る。**
**CI は無いので、そちらの経路は無い**（[ADR-0012](0012-テスト方針とカバレッジのゲート.md)）。

### 4. `lint_secrets.py` は鳴らない。鳴らないことを登録して見えるようにする

`lint_secrets.py` が見ているのは接続文字列の `password` への代入と 20 文字以上の代入で、
**Markdown の表は当たらない。** **パターンを緩めない**——ADR-0031 の
「値のパターンで緩めない」は、この ADR でも維持する。

**代わりに `lint_secrets_allow.txt` へ `CLAUDE.md` を登録する。**
検査は素通りするので実害の抑止にはならないが、**例外がツールの世界に痕跡を持つ**。
**痕跡が無いと、同じ書き方が他所へ複製されても誰も気づかない。**

### 5. ADR-0031 から、生きている決定を引き継ぐ

**ADR-0031 の決定は 2 つあった。死んだのは片方だけである。**
**開発・デモ専用の初期データを `Designer/seed/dev/` に分け、
本番相当の投入手順（`001`〜`004`）に入れない**——これは**そのまま生きており、本 ADR が引き継ぐ。**

- **理由も引き継ぐ**——導入手順どおりに流した環境に、**デモ用の役割が構造的に入らない**
- `dev/001_demo_user_roles.sql` が付けるのは**役割だけ**。アカウント自体は画面で人が作る（§1）
- 依存している先: `DevSeedDataTests`・`TestDatabase`・[ADR-0032](0032-認証部品のapp_usersを正典に迎え入れる.md)・
  [ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md)・[05](../05_実装計画と現在地.md)・
  [`Designer/seed/README.md`](../../Designer/seed/README.md)

**引き継ぐと書かずに ADR-0031 を superseded にしたら、この 6 か所の参照先が消えていた**
（2026-09-05 の `lint_docs.py` が実際に鳴らした。**関門が仕事をした例である**）。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 値を `Designer/LocalEnvironment.md`（Git 追跡外）に置き、CLAUDE.md には許可だけ書く | **これが最も安全で、実際に迷った。** 却下したのは、**開発者の指示が「CLAUDE.md に明記する」だった**からである。追跡外のファイルは `clone` した人に無く、**開発者自身が新しい開発機で作り直すときに値が失われる**。**開発者がこの ADR を読んで採りたいと言えば、そちらへ移す**（そのときは本 ADR を superseded にする） |
| ADR-0031 に追記して済ませる | ADR-0031 が**例外の範囲をパスで固定し、広げるなら新しい ADR と定めていた**（§1） |
| 値を伏せ、聞かれたら開発者が答える | **これまでがそれで、実機確認のたびに止まっていた**（状況） |

## 帰結

- **[`Designer/seed/README.md`](../../Designer/seed/README.md) の 2 か所を直す**——
  「パスワードは開発者が決める」は値が固定されたので古い。
  「アカウントの作成とパスワードの設定は Claude が行わない領域である」は、
  **作成は依然として人がやる**（`hash` を作れないため）が、**値は Claude が知っている**
- **§3-5 に 4 行目を足すときは、この ADR に戻ってくる。** 足すこと自体が例外を広げる
- **ADR-0031 の「選択肢 A は実装できない」は、決め方の教訓でもある**——
  あの ADR は `PasswordHashHelper` の存在を確かめずに置き場所を決めていた。
  **「そこに置ける」を確かめてから置き場所を決める**
