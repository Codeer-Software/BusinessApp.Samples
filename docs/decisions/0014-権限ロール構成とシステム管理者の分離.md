# 0014: 権限ロール構成 — admin は経理ロールと同一（システム管理者ロールの分離はバックログ）

- 状態: 採用（現状維持）/ 日付: 2026-07-07 / 契機: ユーザー質問「admin と経理の権限は同一か？ admin 用ロールがあるべきでは？」

## 現状

ロールは general（一般社員）/ approver（承認者）/ accounting（経理）の3種。**「admin」はユーザー名であってロールではなく、権限は accounting と完全に同一**。ユーザー管理・制度閾値・承認テンプレート・会計年度などのシステム設定の書き込みも accounting に含まれる（B-8）。

## ベストプラクティスとの関係（質問への回答）

一般論では**職務分掌（Segregation of Duties）**により「業務ロール（経理）」と「システム管理ロール（ユーザー・権限・マスタ設定の管理）」は分離するのが望ましい。経理担当が自分の権限を変更できる構成は内部統制・監査上の弱点になり得る。

## 決定

**v1 は現状（3ロール・admin=経理）を維持**する。理由:

1. ペルソナ（30〜80名の中小）では経理と情シスの兼務が実態として多く、3ロールは「導入即日に理解できる」シンプルさの価値が大きい
2. 分離には UserReadCondition/UserWriteCondition の全ゲート棚卸し（70超モジュール）が必要で、最終日に回帰リスクを負うべきでない
3. CLB の条件ゲートは role 値の追加で自然に拡張できる設計になっており、後付けが容易

## 将来 sysadmin ロールを追加する場合の影響範囲（設計メモ）

- role 候補に `sysadmin` を追加（AppUser の Select）
- **sysadmin 専用に付け替えるゲート**: ユーザー管理（AppUser 書込）・制度閾値・承認フローテンプレート・会計年度・部門/共有マスタの書込
- **accounting に残すもの**: 仕訳・帳票・銀行・購買・締め等の会計業務すべて
- ホームの経理セクション出し分け（Home.mod.cs）と各 .mod.cs 内の `CurrentUser.Role.Value != "accounting"` 判定の棚卸しが必要（grep で列挙可能）
