# ADR-0007 会計コアの機能スコープ

## 状況

「対象ペルソナが使う機能を全て含み、使わない機能は含めない」を原則とする。
検討メモ（`LocalData/temp/検討メモ群/2026-08-20_会計コア機能整理.md`）が挙げた層 A〜F の機能群に対して、
含める／含めないを確定させる必要がある。

## 決定

含める／含めないの一覧は [03_機能スコープ](../03_機能スコープ.md) を正典とする。
本 ADR は**境界の引き方の判断とその理由**だけを記録する。

### 判断が割れた 8 点

| 論点 | 決定 | 理由 |
|---|---|---|
| ユーザー・権限管理 | **含めない** | 認証部品の責務。既存の `AppUser` を利用する。会計コアが自前のユーザー表を持つと二重管理になる |
| 固定資産台帳・減価償却 | **含める**（コード部品としては分離） | 決算整理に不可欠で、ペルソナは必ず使う。単独で使う利用者はいないのでアプリ部品は分けない（[ADR-0029 §3](0029-所有は相手抜きで存在するかで導き粒度は決断で決める.md)） |
| 証憑（実体の保存・スキャナ保存・電子取引） | **含めない**（参照キーのみ持つ） | 証憑管理だけを使う利用者が現実に存在する＝別のアプリ部品。ただし「帳簿間の相互関連性」のため、仕訳から証憑を特定する情報は会計コアが保持する |
| 銀行・カード明細の取込、OCR、自動仕訳ルール | **含めない** | 入力支援であって会計の責務ではない。外部連携の不安定さを会計コアに持ち込まない |
| 承認ワークフロー・定型仕訳・仕訳辞書 | **含めない** | 会計ではない。承認は別部品（社内で別途開発中） |

**2026-09-10 追記**——上の 2 行の理由は、**「入力支援だから」ではなく「新しい状態を要するから」**に読み替える
（[ADR-0049](0049-会計補助はステートレスなものだけを作り会計コアのドメイン層には置かない.md)）。
振替伝票の複製（[ADR-0048](0048-伝票の複製は取引の内容だけを写す.md)）を作った時点で
「入力支援は外す」が破れたので、**入力支援のうち新しい永続化を要しないもの（会計補助・ステートレス）は作ってよい**、
**要するもの（ステートフル）は原則作らない**、と線を引き直した。
取込・OCR・自動仕訳ルール・承認・定型仕訳・仕訳辞書は、どれもステートフルである——**含めないという結論は変わらない**。
表の字面は当時の判断として残す。
| 消費税申告書・付表の様式出力 | **含めない**（集計までは含める） | 申告は税理士が行う。会計コアの責務は「申告に必要な集計と根拠を正確に出すこと」まで |
| 電子申告（e-Tax / eLTAX）・XBRL | **含めない** | 申告者の提出行為であり、会計ソフトの法的義務ではない。税理士・申告ソフトへの標準出力で足りる |
| CSV による取込・出力 | **含める** | 「完全な出口」は会計ソフトの信頼の前提であり、部品として組み合わせるための連携点でもある |

### 消費税で実装する範囲

ペルソナ（本則課税・税抜経理・課税売上高 5 億円超）が使うものだけを実装する。

- **実装する**: 税抜経理／税率別集計／売上税額（割戻し・積上げ）／仕入税額（積上げ・割戻し）／
  課税売上割合／全額控除・個別対応方式・一括比例配分方式／免税事業者等からの仕入れの経過措置と
  相手方別の上限／帳簿のみ保存で控除できる類型（ペルソナが使う 5 つ）／税率ごとの端数処理／
  税額の手動上書き
- **実装しない**: 簡易課税／2 割特例／3 割特例／税込経理／**少額特例**

**全額控除を実装するのは、同じ会社が年度によって使い分けるから**である
（課税売上高が 5 億円以下になれば全額控除に戻る）。簡易課税等は課税事業者の届出で決まる別制度であり、
このペルソナは選ばない。

**少額特例を実装しないのはリサーチの結果である。** 対象事業者は「基準期間の課税売上高 1 億円以下
**または** 特定期間の課税売上高 5,000 万円以下」に限られ、年商 8.5 億円のペルソナはどちらも満たさない
（[消費税リサーチ](../research/2026-08-23_消費税インボイス制度.md) §2）。当初は実装対象に含めていたが、
一次情報で適用要件を確認して除外した。

### 決算で実装する範囲

- **計算機能を持つのは減価償却のみ。** 引当金繰入・経過勘定・棚卸・貸倒は
  **手動の決算整理仕訳**で行う（専用の計算画面を作らない）
- 決算書は**貸借対照表・損益計算書・株主資本等変動計算書・個別注記表**を作る
  （会社法上の計算書類。ペルソナは株式会社）
- **勘定科目内訳明細書・法人事業概況説明書・製造原価報告書は作らない**（申告側の書類、
  および製造業でないため）

## 理由

- 境界を引く基準を「機能の重要度」ではなく「**責務**」と「**単独で使う利用者がいるか**」に置いた。
  重要度で引くと必ず膨張する（重要でない機能は存在しないため）
- 「使わない機能は含めない」を機械的に適用すると、**同一の会社が年度・状況によって使い分ける機能**
  （控除方式の 3 種）まで削ってしまう。原則の適用単位は「ペルソナが使うか」であって
  「今年使うか」ではない

## 帰結

- スコープ外と決めたものについて、**会計コア側に「後で足せる隙間」を用意しない**。
  必要になったら別部品として作り、会計コアの公開された連携点を通す
- 唯一の例外は**仕訳の投入経路**である。他部品（経費精算・販売・証憑）から仕訳が入ってくることは
  最初から前提にし、元伝票を特定する情報を保持する
- 実装しないと決めた税額計算方式（簡易課税等）も、**戦略として交換可能な形**に設計する。
  実装しないことと、拡張できない設計にすることは別である
