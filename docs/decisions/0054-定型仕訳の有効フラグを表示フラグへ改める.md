# ADR-0054: 定型仕訳の「有効」フラグを「一覧への表示」フラグへ改める

- 日付: 2026-08-14
- 状態: 採用
- 関係: `docs/issues/2026-08-09_体験シナリオ執筆中に見つかった改善候補.md` C-2 ／
  ADR-0026（状態遷移の一元化）／`docs/tests/20_体験シナリオ/06_会計_仕訳と帳簿/04_定型仕訳と入出金起票.md`

## 背景: フラグが宙に浮いていた

定型仕訳には「有効」フラグ（`is_active`）があったが、**起票時に参照されていなかった**。
無効にした定型でも「この定型から伝票を起票」は普通に動く（改善候補 C-2）。

当初の対処案は「起票時に `IsActive` を確認する／一覧から隠す」だったが、
そもそもこのフラグに意味があるのかを問い直したところ、**名前と効き方が食い違っている**ことが分かった。

### このアプリの他マスタの「有効」とは効き方が違う

勘定科目・取引先などの `IsActive` は、参照フィールドの検索条件
（`SearchTargetVariable: "IsActive.Value"`）に埋め込まれていて、無効にすると**候補に出てこない＝選べない**。
「有効」という名前が実態と一致している。

定型仕訳は違う。`Designer/Design/` を全走査した結果、`JournalTemplate` を指しているのは

| ファイル | 参照のしかた |
|---|---|
| `JournalTemplate.mod.json` / `.mod.cs` | 自分自身 |
| `JournalTemplateLine.mod.json` | 子明細（親子関係） |
| `PageFrames/Accounting.frm.json` | サイドバーのメニュー項目 |

の 4 つだけで、**参照フィールドから候補として引かれている箇所はゼロ**。
入口が一覧しかないので、「候補から外す」という無効化本来の効き方が**構造的に存在しない**。

同じ「有効」という名前で効き方だけ違うのが混乱の正体で、
「チェックを外した人が誤用を防いだつもりになる」＝**安全の錯覚**が実害だった。

## 決定: 「表示」フラグに改め、起票はガードしない

**用途を二分する。一覧を整理したい＝表示フラグ／もう使わせたくない＝削除。**

| 変更 | 内容 |
|---|---|
| フィールド名 | `IsActive` → `ShowInList`（DB 列 `is_active` → `show_in_list`） |
| 表示名・一覧列 | 「有効」→「**表示**」。詳細のラベルは「一覧への表示」、チェックボックスは「一覧に表示する」 |
| 一覧の検索 | 定型名（部分一致）＋表示 の条件を新設。`Search_OnInit` で**既定は「表示中のみ」** |
| 詳細の案内 | 非表示の定型を開くと「この定型は一覧に表示されない設定です（この画面からの起票はできます）。」 |
| 新規作成の既定 | `ShowInList` を **ON** で作る |
| 起票 | **ガードしない**（非表示の定型でも、直接開けば起票できる） |

### なぜ起票をガードしないのか

「表示」フラグなら、非表示のものを直接開いて起票できても**嘘にならない**。
むしろ「廃止した契約の取消仕訳を、当時の定型で起こしたい」といった例外を救う逃げ道になる。
ガード分岐をひとつも増やさずに C-2 の「防いだつもり」問題が消える。

なお市販ソフトも同じ答えを出している。弥生会計の仕訳辞書・伝票辞書・摘要辞書には「非表示」チェックがあり、
効き方は「帳簿・伝票の取引を選択するドロップダウンリストに表示されなくなります」＝**選ぶ場所で効く**。
無効化は選択の場で効いて初めて意味を持つ、という裏付けになっている。

### 新規作成の既定を ON にしたのは修正でもある

旧仕様ではチェックボックスの初期値が未チェックだったため、`is_active = 0` の定型が作られていた
（実際にデモ DB の T01「事務所家賃の支払」が 0 のまま残っていた）。
旧仕様では挙動に出ないので誰も気づけなかったが、新仕様では**作った直後に一覧から消える**。
`Detail_OnAfterInit` で `IsNewData` のとき `true` を入れる。

## 採らなかった案

- **フラグを廃止して削除運用に一本化**: 年に一度しか使わない定型（決算整理など）を平時だけ隠せなくなる。
  共有マスタなので「他人が作った定型を消すのは怖い」も残る。市販ソフトが揃って持つ機能を落とすのは後退
- **起票時に `IsActive` を確認する（C-2 の当初案）**: 「有効」という名前のまま効かせる案。
  名前と効き方は揃うが、実務で必要な「非表示のまま例外的に使う」ができなくなる

## 実機検証（2026-08-14 / soumu_bucho）

| 確認 | 結果 |
|---|---|
| サイドバー経由の一覧 | 既定で表示中のみ（T03 を非表示にすると 3件 → **2件**） |
| クリア → 検索 | 非表示も出る（3件・表示列は「—」）。「表示」は 空／○／— の 3 択セレクト |
| 詳細の案内 | チェックを外した**その場で**出る（`OnDataChanged`）。戻すと消える |
| 非表示からの起票 | 成功（下書き伝票を生成・借貸 420,000 で一致）。検証後に削除済み |
| 新規作成 | 「一覧に表示する」が既定 ON・案内は出ない |

> **既知の挙動**: `OnSearchInitialization` は `?initialize_search=true` 付きの遷移でしか発火しない（CLB 仕様）。
> サイドバーのメニューから開けば既定が効くが、URL を直打ちすると全件（非表示を含む）が出る。
> 通知一覧の「未読のみ」既定と同じ性質なので、本アプリでは許容する。

## 移行

- `ALTER TABLE journal_templates RENAME COLUMN is_active TO show_in_list`（適用済み）
- 既存の `0` / `NULL` は `1` に寄せた（T01 の消し忘れを含む。旧仕様では「無効」に意味が無く、
  0 のまま持ち越すと新仕様で不意に一覧から消えるため）
- `ddl/170_journal_templates.sql` も新列名で作られるように更新
