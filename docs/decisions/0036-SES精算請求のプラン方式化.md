# ADR-0036: SES 精算・請求のプラン方式化

- 日付: 2026-07-27
- 状態: 採用
- 関連: ADR-0034（定期請求実行のプラン方式）— 本 ADR はその設計を SES 精算・請求へ横展開する

## 背景（問題）

SES 精算・請求（`SesBilling`）は「精算を計算」ボタンで**複数行テキストに結果を文字列で流し込む**
素朴なプレビューだった。定期請求（ADR-0034: プランテーブル＋状態列＋生成予定の黄色ハイライト）と
比べ UX が不統一で、状態（生成予定/生成済み/対象外）も一覧で判別できない。

## 決定

定期請求実行と同じプラン方式に載せ替える:

- **`ses_run_plan` テーブル（370_ses_run_plan.sql）＋ 行モジュール `SesRunPlan`** を新設。
  `recurring_run_plan` への相乗りは不可（あちらは再構築のたび全行洗い替えする共有一時領域のため、
  SES 行を混ぜると定期請求画面を開いた瞬間に消される）。
- `BuildPlan(対象月)` が唯一の判定ロジック: 実績集計（time_entries の型付き Year/Month 比較）・
  精算幅の計算・生成済み判定（invoice_source='ses' × 案件 × 対象月）を行い、全行洗い替えで書き出す。
- 状態: `planned`（生成予定・黄色ハイライト=既存 `row-planned` CSS 流用）/ `done`（生成済み）/
  `excluded`（対象外。理由を「内容」列に明示: 案件無効・契約条件未設定・請求額0以下・請求書void）。
  旧実装が黙って skip していた案件も「なぜ対象外か」を見せる。
- 「精算を計算」ボタンは**廃止**。対象月の変更で自動再構築（`TargetMonth_OnDataChanged`）。
- 「一括生成」は押下時点で BuildPlan を再実行し、`planned` 行を機械的に消費する（実行側は判定を持たない）。
- 一覧列: 案件 / 取引先 / 実績時間 / 請求額（税抜）/ 消費税 / 状態 / 内容（精算式）/ 請求書番号。
- 請求書明細の摘要は精算式＋実績時間（例: `基本 800,000（精算幅 140〜180h） − 控除 10h×5,000 = 750,000（実績 130h00m）`）。

## 会計処理は不変

請求書（invoice_source='ses'）＋売上仕訳（D 売掛金 / C SES売上高 4010 / C 仮受消費税）・
入金予定の自動作成・冪等ガードは従来ロジックをそのまま踏襲。変わるのはプレビューと状態表示のみ。
