# ADR-0040: 部品アーキテクチャと PageFrame 再編（ロール別 → 部品×対象者）

- 日付: 2026-08-02
- 状態: 採用（実装・実機検証済み）
- 関係: ADR-0028（ロール別ページフレーム）を supersede。ADR-0041（権限モデル刷新）と対で成立
- 正典: 部品の定義・依存ルール・削除手順は `docs/10_部品アーキテクチャ.md`

## 背景

上司レビューで「テンプレートとしての再利用性」を軸にした再編の指示を受けた:

- CLB の価値は「誰かが作ったアプリを企業ごとに一部改変して再利用できる」こと。本アプリもテンプレートとして再利用しやすくあるべき
- 再利用の単位は PageFrame。「会計だけ使いたい」「会計と経費精算だけ使いたい」という採用パターンに部品で応える
- 会計は法令で決まるためほぼ無修正、一般業務は各社カスタム前提 —— 修正されやすさで凝集する
- 各部品は高凝集・疎結合・依存明確に。マスタ管理は部品ロジックに依存しない独立 CRUD

現行（ADR-0028）はロール別 5 フレーム（Main＋General/Approver/Accounting/Sysadmin）で、この観点に合わなかった。

## 決定

### 1. 7部品のレイヤ構造（依存は下方向のみ）

```
レイヤ0 【基盤・マスタ】必須   … シェル・ユーザー・部門・部門メンバー・承認テンプレ／制度・会計・業務マスタ
レイヤ1 【会計】必須コア       … 仕訳・帳簿・銀行・固定資産・会計年度・財務帳票
レイヤ2 【営業業務】【購買業務】【経費精算】【工数管理】 … 任意・相互に原則独立
レイヤ3 【経営管理】任意       … 予算・案件損益・人件費配賦・資金繰り予測（全部品を読む最上位）
```

例外の「オプション連携」は 3 点のみ（docs/10 に除去手順つきで明文化）:
営業→購買（相殺入金）／営業→工数管理（SES 精算）／経費精算→会計（少額資産の自動登録）。

### 2. PageFrame = 部品 × 対象者の 14 枚

CLB の制約（PageFrame の入れ子は仕様上不可・リンク単位の可視条件も不可 = FB-009）から、
「階層 PageFrame」は **多階層メニュー（Title の `/` 区切り）＋フレーム切替リンク** で表現する。

| 部品 | フレーム |
|---|---|
| 基盤 | Main（IsApplicationRoot・RoleDispatch 転送専用） |
| 経費精算 | ExpenseStaff ／ ExpenseApprover ／ ExpenseAccounting |
| 工数管理 | Timesheet ／ TimesheetAccounting |
| 営業業務 | SalesStaff ／ SalesBilling |
| 会計 | Accounting |
| 購買業務 | Purchasing |
| 経営管理 | ManagementApprover ／ ManagementFull |
| マスタ | MasterBusiness（経理） ／ MasterAdmin（システム管理者） |

### 3. ワークスペース切替の導線（FB-009 の回避設計）

- **経理系 7 フレーム**（対象者が同質）: 静的な「ほかの業務」リンク群で相互接続（1クリック切替）
- **一般・承認者系フレーム**: 同一フレーム内の **RoleDispatch への「マイページ」リンク**で、権限に応じた自分のホームへ動的に戻る
- **部品別ホームのボタン**（ExpenseHome/SalesHome）: スクリプトが CurrentUser の権限キャッシュから行き先フレームの変種を計算（経理→SalesBilling・一般→SalesStaff 等）
- 旧 Home（全部品を参照する唯一のハブ）は廃止し、部品別トップ ExpenseHome／SalesHome／AccountingHome に分割。各ホームの参照は自部品内に限定（部品をまたぐ型参照ゼロ）

### 4. 受け入れ基準 =「部品を削除しても designcheck が通る」

実測結果（作業コピーで部品のフレーム＋フォルダ＋切替リンクを削除して designcheck）:
- 経営管理: **0 件**（完全独立）
- 購買: Sales/Receipt の相殺入金 4 箇所のみ（文書化済みオプション連携）
- 工数管理: SesBilling の工数参照 1 箇所のみ（同上）

想定外の結合はゼロ。「使いたい部品だけ組み合わせる」が実証された（デモの訴求材料）。

## 実装ノート（将来の保守者向け）

- 旧フレームからの deepcopy でリンクを生成（CommonMistakes #47/#52。ゼロから JSON を組んでいない）
- `NavigationService.GetModuleUrl(module)` は現在フレーム内で解決（ADR-0028 実測）。スクリプトの
  同一部品内遷移はそのまま動く。**フレーム跨ぎはボタン＋ `/{Frame}/Top` 遷移**（Top セグメントは全フレーム登録済み）
- 表示専用モジュール（ホーム類）を指すリンクは、複製元由来の `SortFieldVariable: "Id.Value"` を
  空にしないと designcheck が「変数が存在しない」と報告する（実測）
- 同一部品の役職変種フレーム間のメニュー重複は CLB の構造上不可避（FB-009）。機能追加時は
  docs/10 の「フレーム変種マトリクス」を見て全変種へ反映すること
- モジュール側 UserReadCondition は多層防御として維持（フレームゲートと二重）

## 影響

- E2E・体験シナリオ文書は旧フレーム URL・旧ロール前提 → `docs/tests/19_部品再編2026-08_読み替え表.md` で読み替え（全面改訂は後続）
- 旧 Home の仕入先請求書期限アラートは支払予定表（購買）へ、資金繰りアラートは資金繰り予測（経営管理）へ役割移譲（部品をまたぐ型参照を作らないため）
