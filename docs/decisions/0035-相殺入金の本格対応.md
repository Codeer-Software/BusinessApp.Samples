# ADR-0035: 相殺入金の本格対応（借方科目の入金方法別切替＋仕入請求の連動消込）

- 日付: 2026-07-27
- 状態: 採用
- 関連: ADR-0032（入金予定自動作成）/ ADR-0033（入金フローの一本化）/ docs/tests/11 の入金章

## 背景（問題）

入金確定（`Receipt.Confirm_OnClick`）の消込仕訳は、入金方法（`method`: bank/cash/offset）に
かかわらず **借方が普通預金(1020)にハードコード**されていた。

- **相殺（offset）**: 実際には現金が動かないのに帳簿の預金残高が膨らみ（銀行明細との残高照合が
  必ずズレる）、かつ相手の買掛金が過大なまま残る。B/S が二重に歪む明確なバグ。
- **現金（cash）**: 借方は現金(1000)であるべき。
- さらに相殺は**買掛側の消込とワンセット**でないと危険——仕訳だけ D 買掛金/C 売掛金 と直しても、
  購買側の仕入先請求（`vendor_invoices`）が「未払」のまま見え、FB エクスポートから
  **相殺済みの買掛を二重に振り込む**事故につながる。

## 決定

### 1. 借方科目を入金方法で切り替える

| method | 借方 | 貸方 |
|---|---|---|
| bank | 普通預金 1020 | 売掛金 1100 |
| cash | 現金 1000 | 売掛金 1100 |
| offset | 買掛金 2000 | 売掛金 1100 |

- 少額差額の「振込手数料等」自動処理（RECEIPT_DIFF_MAX）は **bank のみ**で発動する。
  現金・相殺の不足額は振込手数料ではない（現金の不足は一部入金として扱い、残額予定が自動再作成される）。

### 2. 相殺は仕入先請求を指定して買掛側も連動消込する

- `receipts.offset_vendor_invoice_id`（→ vendor_invoices）を新設。入金方法が「相殺」のときだけ
  「相殺する仕入請求」Select を表示し、**確定時に必須**とする。
- 確定時の検証:
  1. 仕入請求が存在し **状態が accrued（未払計上済）** であること
     （received は買掛金がまだ立っていない／paid は既に支払済みのため相殺不可）
  2. 仕入請求の取引先 = 売上請求書の取引先（**同一取引先間でのみ相殺可**）
  3. **入金額 = 仕入請求の税込額**（v1 は仕入請求の全額消込のみ。買掛側に一部支払の
     概念が無いため。仕入請求 > 売掛残額 の相殺は不可＝過入金ガードで弾かれる）
- 確定成功時、仕入請求を **paid に遷移**させる: `payment_entry_id` = 消込仕訳、
  `paid_date` = 入金日。消込仕訳は 1 本（source_type='receipt'）で AR/AP 両方の裏付けとなる。
- 入金額 < 売掛残額のときは従来どおり一部入金（残額の入金予定が自動作成され、
  2回目を銀行振込で確定 or 別の仕入請求と再度相殺、が自然に合成できる）。

### 3. 取消の経路は入金側に一本化する

- 入金の取消（`CancelReceipt_OnClick`）: 仕訳削除の**前に**仕入請求を accrued に巻き戻す
  （`payment_entry_id` が仕訳を FK 参照しているため、参照解除→仕訳削除の順序が必須）。
- 仕入先請求側の「支払取消」は、支払仕訳の `source_type` が `receipt` のとき**ブロック**し、
  入金画面へ誘導する（買掛側だけ accrued に戻すと、入金側の消込仕訳が残ったまま
  再支払できてしまい二重払いになるため）。

### 4. 選択 UI は select_label 方式を踏襲

`vendor_invoices.select_label`（番号 + 取引先名 + 摘要）を DB トリガーで保守し（ADR は
280_select_labels.sql の設計判断を踏襲）、Select の表示に使う。候補は accrued/paid に絞る
（paid を含めるのは、確定済み入金の表示時に選択値のラベルを解決するため）。

## 見送り（v1 スコープ外）

- **仕入請求の一部相殺**（買掛側の一部支払）: AP 側に消込残高の概念を足す大改修になるため見送り。
  実務上は「小さい方を全額相殺し、差額を振込」で大半をカバーできる。
- 複数仕入請求の同時相殺: 入金予定の分割（既存機能）で 1 対 1 を繰り返せば実現できるため見送り。
- 下請法上の相殺制限（下請代金からの相殺には書面合意等が必要）はアプリでは強制しない。運用注意。
