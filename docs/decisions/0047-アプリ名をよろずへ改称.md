# ADR-0047: アプリ名を「帳合」から「よろず」へ改称

- 日付: 2026-08-09
- 状態: **採用・実施済み（2026-08-09）** — 画面表示とドキュメントに反映済み。リポジトリ名は据え置き（下記 §実装）
- 関係: ADR-0040/0042/0045（会計アプリから業務基盤への射程拡大の経緯）

## 背景

「帳合（ちょうあい）」は**帳簿を突き合わせて計算が合うこと**を指す会計用語で、
フェーズ A（会計コア）の段階で付けた名前だった。

その後 フェーズ B/B'/C/D と部品アーキテクチャ再編（ADR-0040）を経て、
本アプリの守備範囲は会計コアだけでなく **経費精算・営業（見積〜入金・定期請求・SES）・購買と支払・
工数管理・経営管理・組織と権限のガバナンス** に広がった。7 部品 × 14 フレームで会社の業務そのものを
扱っており、「帳合」という名前が実態より狭い。あわせて、漢語の会計用語は
デモの聴衆（中小企業の経営者）に対して硬すぎる、という指摘があった（ユーザー 2026-08-09）。

## 決定

**アプリ名を「よろず」とする。**

表示形は **`よろず - 統合業務基盤アプリ`**（サブタイトル併記）を基本とする。

### 選定理由

- **万屋（よろずや）の「よろず」＝あらゆること・何でも扱う**。ミッションの芯である
  「全部入り」（CLAUDE.md §1）と意味が一致する。名前が機能範囲をそのまま説明している
- ひらがな 3 文字で読み間違いがなく、漢語よりも柔らかい
- 会計にも営業にも購買にも寄っていないため、今後さらに部品が増えても名前が古びない

### 表記のルール

- **ひらがな「よろず」を正表記とする。** カタカナ「ヨロズ」は自動車部品の上場企業
  （株式会社ヨロズ）と表記が衝突するため使わない
- 英字が必要な文脈では `Yorozu`

## 検討して退けた案

| 案 | 退けた理由 |
|---|---|
| 業合（ぎょうごう） | 「帳合」の直系で来歴を語れるが、漢語のままで硬さが解消しない・初見で読めない |
| 通貫（つうかん） | 一気通貫を体現するが同上（硬い） |
| 鼎（かなえ） | 三軸分離の設計と符合して意匠は良いが、読みが難しい |
| 要（かなめ） | **建設業向け原価管理ソフト「要～KANAME～」が既存**で、業務システム領域で衝突する |
| なりわい | 「生業」＝会社の営み全体を指し射程は理想的だが、「全部入り」の直接性で よろず に劣る |
| つむぐ / あわせ / すむ | それぞれ長所はあるが、意味の直接性で よろず に及ばない |

## 実装（2026-08-09 実施）

1. **画面表示** — サイドバーのブランドを **2 行構成**にした。1 行目がアプリ名、2 行目が小さく用途を説明する形。
   - `Designer/Design/Modules/Shell/PortalSidebar.mod.json`
     - `BrandLink`（ラベル・`GoHome_OnClick` 付き）のテキストを `帳合` → **`よろず`**。FontSize 18・白のまま
     - **`BrandSubLabel` を新設**（テキスト `統合業務基盤アプリ`・FontSize 12・`#b9c0d4`・クリック不可）。
       BrandLink 行の直下に配置し、BrandLink の下 padding を 16 → 0 に詰めて 2 行が組になるようにした
   - `Designer/Design/PageFrames/Main.frm.json` の `Left.Home.Text` を `よろず`
     （サイドバーはモジュール置換のため実画面には出ないが、食い違いを残さないため揃えた）
   - `Designer/Design/app.css` の見出しコメント
   - 検証: `designcheck` findingCount 0 / `check_navigation.py` errors 0・warns 0
2. **ドキュメント**: `docs/01_企画概要.md`（表題と名称の由来）ほか、体験シナリオでサイドバー表記に
   触れている箇所を更新
3. **リポジトリ名・ソリューション名**: 現在 `BusinessApp` の**まま据え置く**。変更コストが大きく
   ADR-0037 のソリューション移行と同規模になるため。必要になった時点で再検討する

商標の正式調査（J-PlatPat 等）は未実施。実運用・外部公開の前に確認すること。
