# ADR-0063: 固定資産台帳の計上科目を「固定資産科目」フラグで絞る

- 日付: 2026-08-16
- 状態: 採用
- 関連: ADR-0054（フラグは効く場所で名乗る）／ADR-0055（`is_cash_equivalent` の先例）／ADR-0062（規約）

## 背景（問題）

固定資産台帳の「資産計上科目」の候補が **`科目区分 = 資産` かつ `有効`** だけで絞られており、
**有効な資産科目 18 件が全部出ていた**。

| 表示区分 | 科目 | 台帳の対象か |
|---|---|---|
| 流動資産 | 現金／小口現金／普通預金／定期預金／売掛金／未収入金／前払費用／立替金／仮払金／仕掛品／仮払消費税／貸倒引当金（12） | すべて対象外 |
| 有形固定資産 | 建物附属設備／工具器具備品 | ○ |
| 無形固定資産 | ソフトウェア／ソフトウェア仮勘定 | ○ |
| 投資その他の資産 | 敷金保証金／長期前払費用 | 減価償却資産台帳の対象ではない |

この科目は **減価償却仕訳の貸方**になる（`FixedAsset.mod.cs` の `GenerateDep`）。
誤って「現金」を選ぶと毎年こうなる:

```
借 減価償却費 86,250
貸 現金       86,250   ← 現金が静かに減る
```

さらに減価償却は内部振替として税区分を対象外に上書きするので（ADR-0053）、
**消費税集計表にも出ず、気づく手がかりが翌期の残高照合まで無い。**

危険なのは**手入力での新規登録だけ**で、経費申請からの自動登録は `工具器具備品(1520)` 決め打ちのため安全。
現行データは 2 件とも工具器具備品で、まだ誰も踏んでいなかった。

## 選択肢

| 案 | 内容 | 判断 |
|---|---|---|
| A | 科目コード帯（1500〜1599）で絞る | ✗ 閾値のハードコード。CLAUDE.md §3「マスタ化してハードコードしない」に反する |
| B | 表示区分（`account_categories`）が有形／無形固定資産のものだけ出す | △ スキーマ変更不要だが、**表示区分は「財務諸表のどこに並べるか」であって「この画面で選ばせてよいか」ではない**。実際、台帳は非償却資産も持てる（償却方法に「非償却」がある）一方、投資その他の資産は台帳の対象ではなく、**区分と台帳の対象は一致しない** |
| **C** | 科目マスタに用途フラグを足して絞る（採用） | ◎ `is_cash_equivalent`（現預金科目・ADR-0055＝「入出金起票で選べる科目」）とまったく同じ型。会社ごとの線引きを設定で変えられる |

## 決定

1. **`accounts.is_fixed_asset_account`（固定資産科目）を新設**（`ddl/580`）。
   初期値は 建物附属設備(1500)・工具器具備品(1520)・ソフトウェア(1560)・ソフトウェア仮勘定(1570) の 4 件。
   - ソフトウェア仮勘定を含めるのは、完成前を「非償却」で台帳に載せ完成時に本勘定へ振り替える運用があるため
   - 敷金保証金・長期前払費用は投資その他の資産で、減価償却資産台帳の対象外なので外す

2. **名前は「償却資産科目」ではなく「固定資産科目」。**
   償却方法に「非償却」がある以上、このフラグが意味するのは
   **「固定資産台帳の計上科目として選べるか」**であって「償却するか」ではない。
   フラグは実態どおりに名乗らせる（ADR-0054 の教訓）。

3. **フラグは名乗ったとおり 2 か所で効かせる**（ADR-0054「効く場所が無いフラグを作らない」）:
   - `FixedAsset.AssetAccount` の候補条件（登録画面・検索画面の両方）
   - **減価償却仕訳の生成ガード** — 候補の絞り込みは「選ばせない工夫」であって関門ではない。
     旧データや、資産が参照したままフラグを外されたマスタはここでしか止められない。
     ADR-0059 でパスワードに対して採った「画面は通知・サーバが関門」と同じ考え方。

4. **経費申請からの自動登録にも先出しの検査を足す。**
   `工具器具備品(1520)` が固定資産科目でなければ、台帳に載せる前にエラーで止める
   （載せてから償却できないことに気づくより早い）。

## 影響

- 候補が 18 件 → **4 件**になった（実機確認済み）。
- **既存レコードの科目は消えない。** CLB は候補外でも現在値を選択肢に足して表示する（実測）。
- フラグを外すと、その科目を使っている資産の償却仕訳生成が**エラーで止まる**。
  これは意図的な設計判断で、「静かに壊れる」より「うるさく止まって直させる」ほうを選んだ。
  マスタを触るときの注意点として `docs/05` に記録する。

## 備考

- `ExpenseRequest` が科目コード `1520` を直書きしている点は残っている。これは
  「経費申請から上がる少額資産は工具器具備品に計上する」という**業務ルールの表明**であって
  閾値のハードコードとは性質が違うため、今回はそのままにした（変えるなら費目マスタ側に
  「資産計上先の科目」を持たせるのが筋）。
