# ADR-0039: データソース・DB ファイルの改名（AccountingSQLite → BusinessAppSQLite）

- 日付: 2026-07-31
- 状態: 採用
- 関連: ADR-0001（会計専用 DB の新設・旧名の由来）・ADR-0037（BusinessApp 移行）

## 背景（問題）

ADR-0037 でソリューション・リポジトリは AccountingApp から BusinessApp に改名済みだが、
データソース名 `AccountingSQLite` と DB ファイル名 `accounting_v1.db` は旧名のままだった。
アプリの実態は会計に加えて販売・購買・経費・工数原価まで含む業務アプリであり、
「Accounting」は実態を過小表現している。デモ・テンプレート製品として、
リポジトリ名／ソリューション名／データソース名／DB ファイル名の一貫性を保ちたい（ユーザー提案）。

## 選択肢

1. **`BusinessAppSQLite` ／ `business-app_v1.db`** ← 採用
2. `BusinessSQLite` ／ `business_v1.db` — 「Business」単独は汎用的すぎ、接続文字列やログで判別しづらい
3. 現状維持 — 初見者に旧名の由来説明が必要になり続ける

## 決定

- データソース名: `AccountingSQLite` → **`BusinessAppSQLite`**
- DB ファイル: `LocalData/db/accounting_v1.db` → **`LocalData/db/business-app_v1.db`**（ファイル本体をリネーム・中身は無変更）
- 全モジュール（約100 `*.mod.json`）・designer.settings（本体/Development/sample）・appsettings（同）・
  ddl ヘッダ・docs の現役参照を一括置換（154 ファイル）

## 温存（歴史的記録）

- ADR-0001 内の旧名・旧パス、docs/05 進捗台帳の過去ログ 3 件（ADR-0037 の温存方針を踏襲)
- `LocalData/backup/accounting_v1_*.db` のバックアップファイル名（当時の成果物。
  docs/09 等の復元手順は「旧名バックアップ → 新名 `business-app_v1.db` として戻す」の読みになる）

## 検証

designcheck 0 件／sql CLI で新データソース名の疎通（journal_entries 79 件）／
deploy.ps1 → サーバ起動 → HTTP でログイン E2E（antiforgery + admin ログイン + current_user 応答）まで確認。
デプロイ済みデザインのデータソース名解決 → 新接続文字列 → 新 DB ファイル照会の全チェーンが実機で動作。
