# 0002: 仕訳＝ヘッダ＋貸借区分付き明細行

- 状態: 採用 / 日付: 2026-07-05

## 背景
複式簿記の仕訳をどうテーブルに落とすかは会計アプリ最大の設計判断。複合仕訳（1:N・N:N）、部門・プロジェクト・税区分の行単位付与、帳票の導出しやすさを満たす必要がある。

## 選択肢
1. **伝票ヘッダ（journal_entries）＋明細行（journal_lines、1行1側 dc+正の金額）** ← 採用
2. 1レコード＝借方科目＋貸方科目＋金額（単一仕訳型。弥生の簡単入力風）
3. 明細行に debit_amount / credit_amount の2列を持つ（片方0）

## 決定
選択肢1。行は `dc`（D/C）と正の整数 `amount` を持ち、1行は片側のみ。伝票確定時に Σ借方＝Σ貸方をアプリ層で強制する。

## 根拠
- 単一仕訳型（2）は複合仕訳（給与仕訳・決算整理など実務頻出）を表現できず、「全部入り」の目標に反する。
- 2列方式（3）は「両方に値」「両方0」という不正状態が構造上あり得る。dc 方式は不正状態が型として存在しない。
- dc＋単一金額は集計 SQL が素直（`SUM(CASE WHEN dc='D' ...)`）で、元帳・試算表の導出が単純になる。

## 影響
- 簡易入力（単一仕訳）UI は「ヘッダ＋2行」を生成する入力糖衣として実装する（データモデルは常に選択肢1）。
- 貸借一致検証・行順（line_no）管理・DeleteTogether（伝票削除で行も削除）が実装必須。
