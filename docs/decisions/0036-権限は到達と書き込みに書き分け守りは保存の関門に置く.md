# ADR-0036 権限は到達と書き込みに書き分け、守りの本体は保存の関門に置く

## 状況

[ADR-0026](0026-画面は役割で分け玄関のページフレームを置く.md) の supersede の経緯と分割の決定は
[ADR-0034 の状況節](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md) にある。
本 ADR が引き継ぐのは **0026 の §3（権限の書き場所）と §5（権限は防波堤ではない）**である。
ただし §3 のうち「データを読めるか＝**原則として絞らない**」は
[ADR-0033](0033-読み取りはそのアプリの役割を持つ人だけに開く.md) が置き換えた——
0026 が `superseded` になった直接のきっかけである。

## 決定

### 1. 権限は 3 か所に書き分ける。同じ条件を 2 度書かない

| 何を守るか | どこに書くか |
|---|---|
| **画面に到達できるか** | 玄関モジュールの `UserReadCondition` ＋ フレームの `UserReadCondition`（二重） |
| **データを書き換えられるか** | 各モジュールの `UserWriteCondition` |
| **データを読めるか** | 各モジュールの `UserReadCondition`。**誰に開くかの既定と例外は [ADR-0033](0033-読み取りはそのアプリの役割を持つ人だけに開く.md)** |

**「画面への到達可否」と「データの読取可否」は別の関門として、それぞれの場所に書く。**
到達の条件はモジュールのデータ API を守らない——API を守るのは各モジュールの条件である
（[qa/01 F-18](../qa/01_CLB静かな失敗.md) の「条件が空＝全開放」。F-18〜F-24 は前回プロジェクト由来で、
1.3.20 では未確認）。

**CLB の権限まわりの性質（条件が空＝全開放・新規作成は読み取り権限を要求しない・
`AppUser` に読み取り条件を付けられない・リンクに可視条件を持てない・OR が書けない・
クエリモジュールに行条件が効かない・クエリモジュールの SQL が JOIN した先に条件が効かない・
スクリプトは守りにならない）は、
[qa/01 の F-18〜F-24・F-30](../qa/01_CLB静かな失敗.md) が正典である。ここには写さない**——
挙動を確かめたとき、直せるのは qa/01 だけで ADR は凍結される。

### 2. 権限は UI の交通整理であって、会計の正しさの防波堤ではない

計上済みの不変性（[ADR-0004](0004-優良な電子帳簿への準拠と仕訳の不変性.md)）・貸借一致・締めの検査は、
**権限とは独立に、保存の関門と DB が守る**。「権限があるから大丈夫」を理由に関門を緩めない。

あわせて、**`*.mod.cs` のガード（`IsVisible` / `IsViewOnly`）は守りに数えない**。
WASM 側で走るので URL 直指定と API を素通りする（[qa/01 F-24](../qa/01_CLB静かな失敗.md)）。

## 理由

- **玄関とフレームの二重は 0026 §3 の形を引き継いだ。** どちらか片方で足りるかは実測していない
  （Claude の見込み: サイドバーの出し分けは遷移先モジュールの `UserReadCondition` に連動する——
  [qa/01 F-21](../qa/01_CLB静かな失敗.md)——ので、玄関モジュールの条件だけでは
  フレーム内の他モジュールの入口は閉じない。1.3.20 では未確認）
- **同じ条件を 2 度書かない**のは、直すときに 1 か所で済ませるため。書き分けの表があるのはそのためである
- **保存の関門を本体にする**のは、前回プロジェクトで、条件を書いていないモジュールが
  API 直叩きで他人のレコードを 200 で返した実測があるから（[qa/01 F-18](../qa/01_CLB静かな失敗.md)）。
  `*.mod.cs` のガードが URL 直指定と API を素通りするのも同型である（F-24）

## 帰結

- 書き込み条件 12 本 ＋ アプリ全体のアクセス条件（`can_access_app`）は 2026-08-31 時点で実装済み。
  実機は [qa/04 §3-6](../qa/04_実機操作テスト.md) の P-08〜P-11・P-14 まで通し、**P-12・P-13 が残っている**
  （現在地は [05](../05_実装計画と現在地.md)）
- 読み取り条件をどの順で閉じるかは [05 のフェーズ 2.5 E](../05_実装計画と現在地.md) が持つ
- 権限の実機テストの観点は [qa/04 §3-6](../qa/04_実機操作テスト.md)（P-08〜P-16）
