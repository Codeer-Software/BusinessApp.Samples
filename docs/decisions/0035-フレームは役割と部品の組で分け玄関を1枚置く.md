# ADR-0035 フレームは役割と部品の組で分け、玄関を 1 枚置く

## 状況

[ADR-0026](0026-画面は役割で分け玄関のページフレームを置く.md) の supersede の経緯と分割の決定は
[ADR-0034 の状況節](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md) にある。
本 ADR が引き継ぐのは **0026 の §2（フレーム構成）・§4（フォルダとの軸の分離）・§6（跨ぎリンクの検査）**、
および理由節の「玄関を作り込まない」である。前回プロジェクトがフレームを 7 回作り直した教訓の詳細は
0026 の理由節に凍結されている。

## 決定

### 1. PageFrame は「役割 × 部品」で分け、玄関を 1 枚置く

| PageFrame | `IsApplicationRoot` | 玄関モジュール | 玄関・フレームの条件（決定。2026-08-28〜31） |
|---|---|---|---|
| `Portal` | **true** | `PortalHome` | 条件なし（全員。読み取りの扱いは [ADR-0033](0033-読み取りはそのアプリの役割を持つ人だけに開く.md) が持つ） |
| `Main`（会計） | false | `AccountingHome` | `accounting_role` が `staff` か `manager` |
| `Settings`（設定・マスタ） | false | `SettingsHome` | `accounting_role` が `manager` |
| `Partners`（取引先） | false | `PartnerHome` | `partner_role` が `editor`（**会計の役割は見ない**——[ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md) ③） |
| `Admin`（システム管理） | false | `AdminHome` | `is_sysadmin` |

- **`IsApplicationRoot: true` は `Portal` だけ**にする
- 閲覧の役割（`viewer`）を条件に入れる時期と入れ方はフェーズ 4——予定は [05](../05_実装計画と現在地.md) が持つ
- **サイドバーの階層は `Title` の `/` 区切りで作る**（`"帳簿/仕訳帳"`）。CLB が自動で階層メニューにする
- **フレーム名に旧三層の名前（会計設定・会計マスタ）を使わない**——マスタの区分とフレームは別の軸である
  （区分の現在形は [12_マスタ台帳](../12_マスタ台帳.md)）
- **玄関は当面リンクだけの薄いフレームにする。作り込まない**（[CLAUDE.md](../../CLAUDE.md) §1
  「会計コアだけを作る」。前回プロジェクトのタイル型の玄関は開発者レビューで否定された——
  「業務へは左メニューから行きたい」。「やること」を並べるのは通知や承認がある部品の話で、会計コアには無い）

### 2. フォルダ（アプリ）とフレーム（役割）は別の軸である。一致させない

`Design/Modules/` のトップレベルのフォルダは**アプリ（部品）**とする。**役割で分けない。**
現在形のフォルダ規約は [`Designer/Project.md`](../../Designer/Project.md) が持つ。

**開発者の整理**（2026-08-28。0026 §4 の記録の写し）をそのまま原則にする。

> PageFrame は利用者目線で、使いやすいように**柔軟に導線を引く場所**である。
> だから依存関係もやや緩やかでよい（取引先フレームから会計フレームへのリンクは相互参照になるが、
> ウェブサイトの「戻る」やパンくずと同じで、ユーザビリティから正当化される）。
> **モジュールは厳密に依存関係の方向があり、ここはアプリとして正しいものであるべきである。**

### 3. フレーム跨ぎリンクの登録漏れは機械で止める

遷移先フレームに同じモジュール × URL セグメントの登録が無いと、**画面が静かに真っ白になる**
（[qa/01 F-17](../qa/01_CLB静かな失敗.md)）。`designcheck` は検出しない。
**`lint_design.py` がこの検査を持つ**（実装済み。サイドバーの `Links`・`AnchorTagField`・
スクリプトの `GetModuleUrl` / `GetModuleDataUrl` の 3 経路を見る）。

## 理由

- **役割ごとに入口を分けないと「admin でログインしたら会計が見えない」が成立しない**
  （開発者の要件。2026-08-28。`Main` がルートのままだと admin もそこへ着地する）。
  「admin にも会計を見せる（読めるが編集できない）」案は開発者が却下した——「変だし、やるべきでもない」
- **フォルダとフレームを一致させようとした前回プロジェクトは、7 回作り直したうえに
  線引きの説明ができなくなった**（詳細は 0026 の理由節）

## 帰結

- フレームは 5 枚 ＋ 玄関 5 つ。2026-08-31 時点で実装し、[qa/04 §3-6](../qa/04_実機操作テスト.md) の
  P-08〜P-11・P-14 まで実機で通した（P-12・P-13 は残る。現在地は [05](../05_実装計画と現在地.md)）
- **玄関のトップページに何を置くかはフェーズ 4 で見直す**（[05 §5](../05_実装計画と現在地.md) の保留）
- メニューでの呼び名（「登録番号（インボイス）」等）の現在形は [13 §3-4](../13_取引先設計.md) が持つ
- 役割ごとの変種フレームを作らない（会計フレームは 1 枚）。
  CLB はリンク単位の可視条件を持てないため、変種を作るとメニューが重複する（0026 の教訓 5）
