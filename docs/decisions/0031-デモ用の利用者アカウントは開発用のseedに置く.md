# ADR-0031 デモ用の利用者アカウントは開発用の seed に置き、本番相当の投入手順から外す

## 状況

[ADR-0026](0026-画面は役割で分け玄関のページフレームを置く.md) が、役割ごとに画面を分けると決めた<!-- lint-docs:ignore 経緯 -->
（現在形は [ADR-0035](0035-フレームは役割と部品の組で分け玄関を1枚置く.md)）。
**分かれていることを実機で見せるには、経理担当と経理責任者の利用者アカウントが要る**
（ミッションの目的①＝CLB の技術デモに効く）。`admin` は情報システム管理者なので会計を触れない。

ところが **このリポジトリは公開する**。[CLAUDE.md](../../CLAUDE.md) §5 と
[00 §4-8](../00_ドキュメント規約/本文.md) は、どちらも留保なしに
**「秘密（接続文字列・API キー・パスワード）を書かない」**と定めている。
デモ用の固定パスワードを追跡ファイルに書くのは、字面のうえではこの禁止に触れる。

**`admin` / `admin` は前例にならない。** あれは CLB がユーザーテーブルの空のときに
サーバ起動時へ自動で入れるもの（CLB 仕様リファレンス `_specs/Authentication.md`）で、
本プロジェクトの初期データではない（`Designer/seed/` に `app_users` は無い）。

## 選択肢

### A. 開発用の seed に分け、本番相当の投入手順から外す

- **長所**: 導入手順（`001`〜`004`）どおりに流した環境に、既知パスワードのアカウントが**構造的に入らない**
- **短所**: 「秘密を書かない」という字面の禁止に、例外を 1 つ作ることになる

### B. 通常の seed に `005` として並べる

- **短所**: **導入手順どおりに流すと必ず残る。** 文書で「消してください」と頼む形になり、
  消し忘れがそのまま事故になる

### C. 初期データに入れず、`admin` で画面から作る手順を README に書く

- **長所**: パスワードがリポジトリに一切載らない
- **短所**: **実機確認のたび（DB を作り直すたび）に手作業**が要る。
  役割の分離は繰り返し確かめるものなので、確かめる回数が減る方向に効く

## 決定

**A を採る**（開発者の決定。2026-08-30。**理由は下の「理由」節**——
デモ用の固定値が守っているものが無いから）。

**開発者が決めたのは「分ける」ことである。** 以下は**その形を決めた Claude の判断**（2026-08-30）。

- 置き場所は **`Designer/seed/dev/`**。`001`〜`004`（新しく会計コアを立ち上げるときに要るもの）に**入れない**
- **固定の平文パスワードを書く。** ファイルと [seed/README](../../Designer/seed/README.md) に
  **「デモ・開発専用」「実運用に投入しない」**を明記する
- **実装はフェーズ 2.5 の C**（[05](../05_実装計画と現在地.md)）。
  役割の列（`is_sysadmin` / `accounting_role` / `partner_role`）が増えるのが C だからである

## 理由

**「秘密を書かない」が守っているのは、その値が守っている何かである。**
デモ用の固定パスワードが守るのは、開発機のローカル SQLite（`LocalData/db/`。Git 追跡外）だけで、
**本番を指す接続先も、外部サービスの資格情報も、他人のデータも守っていない**。
書いても失うものが無い。

**それでも例外は例外である。** 危ないのは「秘密でないから書いてよい」という判断が、
次の場面で**別の値にも当てはめられる**ことである。だから範囲を狭く固定する。

> **この ADR が認めるのは、`Designer/seed/dev/` に置く、デモ用の利用者アカウントの
> 平文パスワードだけ**である。他の値（接続文字列・API キー・トークン・本番のアカウント）は
> [CLAUDE.md](../../CLAUDE.md) §5 の禁止のままで、例外を広げるときは新しい ADR を起こす。

**分けるほうが、注意書きより強い。** 選択肢 B は「消してください」と頼む形になる。
[ADR-0026 §1](0026-画面は役割で分け玄関のページフレームを置く.md)<!-- lint-docs:ignore 経緯 -->（現在形は [ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md)。2026-09-01 注記）が
「無意味な組み合わせが**構造的に**作れない」形を選んだのと同じ理屈で、
**入らない形にする**ほうが確実である。

## 帰結

- **`lint_secrets.py` がこのファイルを鳴らさないか、着手時に確かめる。**
  鳴るなら、除外は**パスごと**（`Designer/seed/dev/`）にして、値のパターンで緩めない
- **同じ禁止が 2 か所にある**——[CLAUDE.md](../../CLAUDE.md) §5 と
  [00 §4-8](../00_ドキュメント規約/本文.md)。**正典は CLAUDE.md §5** とし、
  00 §4-8 はそこへのリンクにした。**片方だけに例外を書くと、もう片方を読んだ人が違う結論に達する**
- 初期パスワードの値そのものは、**実装のときに決める**（この ADR は置き場所と扱いを決めている）
- `admin` は `is_sysadmin` だけ（ADR-0026 の帰結。現在形は [ADR-0034](0034-役割は部品ごとの直交な軸で持ち軸の中は階段にする.md) の帰結——2026-09-01 注記）。**このアカウントのパスワードは
  CLB が決めるもので、本 ADR の対象外**である
