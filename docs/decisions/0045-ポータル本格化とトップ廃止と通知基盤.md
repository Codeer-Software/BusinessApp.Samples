# ADR-0045: ポータル本格化 — サイドバー直行・フレームトップ廃止・「やること」集約・通知基盤昇格

- 日付: 2026-08-05
- 状態: 採用（本 ADR 起票と同セッションで実装）
- 関係: ADR-0042（ポータル着地——着地の芯は維持し、中身と導線を再設計）・ADR-0043/0044 と同時決定。
  詳細仕様は `docs/13_ポータルと通知基盤.md`（本 ADR と対）
- 起点: ユーザーレビュー 2026-08-04〜05
  「業務へは左メニューから行きたい」「ポータルには自分あての通知・やることが並んでいてほしい」
  「『ホーム』と『トップ』の違いが分かりづらい。トップ自体なくしては」

## 背景

1. ADR-0042 のポータルは**業務への玄関**（タイルボタンのみ）で、ログイン直後に「今日やること」が見えない
2. 各フレームの着地（トップ）は実態がバラバラ: ExpenseHome/AccountingHome は件数・KPI を持つが、
   SalesHome は挨拶＋ショートカットのみ、購買・工数・経営管理はトップが無く業務画面に直接着地。
   「トップという概念」は既に半分崩れており、サイドバーの「ホーム」（→ポータル）との区別も分かりにくい
3. 個人向け情報（承認待ち・進行中申請・未読通知）が経費部品のトップに閉じており、ポータルから見えない
4. アプリ内通知（Notification）は経費部品の所有物だが、実質「唯一の全社通知基盤」

## 決定

### 1. Main サイドバーのモジュール化（業務へはサイドバーから直行）

- `Main.frm.json` の `Left.ModuleName` に表示専用モジュール `Shell/PortalSidebar` を指定し、
  標準サイドバー UI を置換する（CLB はリンク単位の可視条件を持たない= FB-009 のため）
- リンク構成: 経費精算／工数管理／営業業務／会計業務／購買・支払／経営管理／業務マスタ／システム管理＋ログアウト
- **表示条件は ADR-0043 の権限フラグのみ**で判定。変種フレーム解決（経理 > 承認者 > 一般）は
  従来 PortalHome のタイルが持っていたロジックを共通メソッド化して流用
- PortalHome 中央のタイルボタン群（Go*Btn）は**全廃**（導線はサイドバーに一本化）

### 2. フレームトップの廃止（着地は「一番使う業務画面」に統一）

- 全 13 業務フレームから「トップ」リンクと Top モジュールへの着地を廃止し、
  購買・工数型（業務画面に直接着地）に統一する
- `ExpenseHome`・`SalesHome`・`AccountingHome`・`AdminHome` は廃止（担っていた情報はポータルへ移設）
- サイドバー先頭の「ホーム」（→ポータル）は全フレームで存続（迷子防止）
- スクリプト遷移規約 `/{Frame}/Top`（docs/10 §7）は `/{Frame}/{既定業務画面}` に読み替える

### 3. PortalHome の全面改装（「権限→表示項目」の宣言的合成）

「この機能を使う権限があるなら、ポータルにこれを表示する」のマッピングを定義し、ログインユーザーの
権限フラグで合成して表示する。項目は 4 分類・この順で並べる（上ほど個人的・緊急）:

1. **自分あて**: 未読通知／進行中の自分の申請／あなたの承認待ち
2. **作業キュー**（経理）: 精算処理待ち／未起票銀行明細・下書き伝票／定期請求・SES の未生成
3. **アラート**: 支払期限（超過・7日以内）／期限超過の売掛／資金ショート予測／予算警告
4. **KPI**（経理）: 現預金・売掛・買掛・当月損益

- 各項目は**件数＋クリックで該当一覧へ**（権限別フレーム解決込み）を基本とし、リスト表示は通知のみ
- **部品独立性の維持**: ポータルは部品のモジュール型を参照しない。各部品が**ポータル用の集計 SQL
  （契約ビュー）を 1 本ずつ提供**し、ポータル所有の QueryField モジュールがそれを読む。
  マッピング表と契約ビューの仕様は docs/13 が正典
- 経営ダッシュボード（KPI）は表示する。重さの最適化は問題が顕在化してから（ユーザー判断 2026-08-05）
- 工数の「未入力リマインド」は**見送り**（アサイン概念が無く「入力すべき」が定義できないため。
  やるならアサインマスタが先で別案件）

### 4. 通知の全社基盤昇格

- `Notification` モジュールを `Modules/Expense/` → `Modules/Shell/`（基盤・レイヤ0）へ移設。
  どの部品からも 部品→基盤 の下方向参照で通知を送れる
- **送信 API を `Notification.mod.cs` の公開メソッド `Send(recipient, title, body, linkModule, linkId)` に一元化**。
  「他人宛 INSERT の Submit 戻り値が true にならない」既知挙動（2026-07-08 実測）の吸収と
  Slack/メール mock（Logger）もこの 1 箇所に封じ込める（将来の実連携の差し込み点）
- **リンクは論理のまま**（LinkModule + LinkId）。URL は保存せず、**閲覧時にポータルが受信者の
  その時点の権限でフレーム解決**する（権限は送信後に変わりうるため。送信時 URL 焼き込みは腐る）
- 読み取りは現行踏襲（DataReadCondition = 自分宛のみ）。ポータルに未読リスト＋既読化を置く
- 既読通知の自動掃除（保持期間）は今回スコープ外

### 5. 閾値のマスタ化

- 支払予定の「まもなく期限」7 日は SQL ハードコードを廃し `system_thresholds` へ
  （`PAY_DUE_SOON_DAYS`）。ハードコード禁止方針（CLAUDE.md §3）の徹底

## 検討して退けた代替案

- **Main.Left.Links（静的リンク）**: リンク単位の可視条件が無く（FB-009）、権限外リンクが全員に見える。
  変種フレーム解決も埋め込めない。却下
- **ポータルに一覧を並べる（第二の業務画面化）**: 各フレームと二重化し驚き最小に反する。件数＋リンクに限定
- **送信時に通知へ URL を焼き込む**: 受信者の権限変更で腐る。論理リンク＋閲覧時解決を採る

## 影響・注意

- ADR-0042 の「全員ポータル着地」「業務切替の一元化」は維持。変わるのは切替の UI（タイル→サイドバー）と
  ポータルの中身（玄関→やること集約）
- docs/10 §5（フレーム変種）・§7（遷移規約）・§6（カスタムポイント）を改訂
- `/{frame}/Top` を参照する全箇所（PortalHome・スクリプト遷移・docs）の追随が必要
- E2E 文書のトップ前提記述は docs/tests/19 の読み替えで吸収
