# ADR-0021: フレーム再編第2弾（経費精算/予算管理/案件管理）とロール別可視性の全面精査

- 日付: 2026-07-12
- 状態: 採用・実装済み（4ロール実機確認済み）
- 関連: ADR-0020（メニュー再構成第1弾）、ADR-0019（ページフレーム分割）、docs/12 FB-025

## 背景（ユーザーレビュー 2026-07-11 第2弾）

ADR-0020 実装後のレビューで 8 点の指摘を受けた。要旨:

1. 検索条件サイズ（経費申請）は完璧 → **このサイズを規約として全モジュールに横展開**してほしい（取引先一覧の取引先名・ふりがな・コードがまだ狭い）
2. Logout の分離・確認ダイアログは高評価（変更なし）
3. 経費精算は「ホームのショートカットからしか開けない」のはユーザビリティを下げる → **Main に経費精算フレームの入口**を出し、ショートカットとの二枚看板にする。申請中/承認待ち/通知のホームボタンはボタン過多なので廃止
4. 工数入力も同様 → **どこかのフレームの1アイテム**にする。ショートカットは「左メニューがそのフレームに切り替わり右画面が工数入力」という遷移であるべき
5. 経営管理は**予算管理と案件管理に分割**した方が座りが良い
6. 営業課長に定期請求・定期請求の実行が見える／使えない新規作成ボタンが見える → **全ロールの表示情報を再精査**してほしい
7. フレーム名の「Frame」は開発者の都合 → **URL から除去**（/SalesFrame/Quote → /Sales/Quote）
8. 確認ページ=販売管理・マスタ編集=会計の配置は意図か？（→ 意図。リンクの出し分けはフレーム隔離でしか制御できず、会計が唯一の経理専用フレームのため）

## 決定

### 1. フレーム構成（8フレーム・Frame 接尾辞なし）

| フレーム | URL | 入口が見えるロール | 中身（リンク） |
|---|---|---|---|
| Main | / | 全員 | フレーム入口のみ＋Logout（下端） |
| 経費精算 Expense | /Expense | 全員 | 申請（TOP）・申請中・承認待ち※・通知 |
| 販売管理 Sales | /Sales | 全員 | 見積・受注・検収・売掛残高・取引先一覧・案件一覧＋経理のみ: 請求書・入金・定期請求・定期請求の実行・SES精算・請求 |
| 購買管理 Purchasing | /Purchasing | 経理・sysadmin | （従来どおり） |
| 会計 Accounting | /Accounting | 経理・sysadmin | 仕訳・帳簿・帳票・銀行・設定・マスタ（取引先/案件の編集） |
| 予算管理 Budget | /Budget | 承認者・経理・sysadmin | 予実対比（TOP）・予算入力（経理のみ）・予算明細 |
| 案件管理 Projects | /Projects | 全員 | 工数入力（TOP）＋経理のみ: 案件損益・人件費配賦・人件費コスト・工数管理 |
| システム管理 Admin | /Admin | sysadmin | （従来どおり） |

※承認待ち（ApprovalInbox）は approver/accounting/sysadmin の読取ゲートによりリンク自動非表示。

- 旧 ManagementFrame（経営管理）は廃止し Budget / Projects に分割。TimeEntry は「ホーム専用画面」から Projects フレームの正式アイテムに昇格。
- フレーム間の遷移は「ホームへ戻る」→ Main → 各入口。ショートカット（後述）は直接他フレームに着地する。

### 2. ホームのショートカット＝「フレーム＋画面」への直行ボタン

- 全ロール共通: **経費申請**（→ Expense/ExpenseRequest）・**工数入力**（→ Projects/TimeEntry）。
- 経理・sysadmin のみ追加: 振替伝票・銀行明細取込・月次推移表・資金繰り予測（→ Accounting 内の各画面）。
- 旧「申請中・承認待ち・通知」ボタンは廃止（Expense フレーム内リンクに移動）。ショートカットは AnchorTagField の PageFrame 指定で「左メニューが遷移先フレームに切り替わる」挙動（ユーザー要望どおり）。
- ホームショートカットのユーザーカスタマイズ（「自分で設定できれば最高」）は CLB 側機能として FB-025 に提案。アプリ側は現状ロール別固定。

### 3. ロール別可視性の全面精査（リンク＝読取ゲート・ボタン＝スクリプト）

- **販売の経理専用化**: RecurringBilling / RecurringRun / SesBilling / Invoice / Receipt に UserReadCondition（accounting+sysadmin）を付与 → 営業・承認者の販売管理からリンク自動消滅。営業の請求書参照ニーズは売掛残高一覧（read=all の Query・ボタンなし）で代替。
- **検収（Acceptance）のボタン出し分け**: 確定・請求書を作成は経理/sysadmin のみ（`CurrentUser.Role.Value` 判定）。営業は下書き作成・保存まで＝「営業が検収を起票し、経理が確定・請求する」役割分担をボタン可視性で表現。
- 事前に grep で「非経理が通る画面の init がゲート対象モジュールを ModuleSearcher していない」ことを確認してから付与（ADR-0019 の権限エラー教訓）。

### 4. 検索条件レイアウトの全モジュール規約化

- ExpenseRequest（ユーザー承認済み）を原器として型別幅規約を策定し、**38 モジュールへスクリプト一括適用**:
  - Text=400 / DateTime=360 / Date=340 / Number=260 / Select=210 / Link=280 / Boolean=150 / Id=220（範囲系は開始・終了で同幅）
  - ラベル列 = 文字数×18+12px（最小60）・折り返し禁止。行の実効幅 1,280px でラップし行末に filler 列。
- 実装時の学び: 当初 文字数×15+14 で計算したところ実フォント（約16px/字）で折返しが発生。実機確認 → 18px/字に補正 → 再確認で解消。**ラベル幅の係数はフォント実測に合わせる**こと（原器の実測値は約 18〜20px/字）。
- Project / ProjectView は検索レイアウト自体が無かったため新設（コード・案件名・区分・状態）。

## 影響

- **URL 非互換**: /SalesFrame/... 等の旧 URL は無効になる（デモデータ・通知内リンクは相対遷移のため影響なし。docs は一括追随済み）。ブックマーク互換より「デモで見せられる綺麗な URL」を優先（ユーザー明示指示）。
- ドキュメント: docs/06・09・11 を追随更新。docs/12 に FB-025 追加。
- 旧 GoMyApp/GoInbox/GoNotification フィールドと Home.mod.cs の関連分岐を削除。
