# ADR-0057 制度要件は「済」と書いた項目だけを参照必須にし、条番号ではなく項目 ID で引く

## 状況

**[ADR-0054](0054-不変条件のIDはカタログの側から数えテストが触れていないものを報告する.md) で、
不変条件（I-nn）の側は済んだ。** 制度要件の側——[40](../40_優良な電子帳簿の対応表.md) の項目——は
未着手のまま残っていた（[qa/05 §5](../qa/05_観点網羅の計器.md)）。

**素材の形が不変条件と 2 つ違う。**

1. **全部が守られているわけではない。** 不変条件は**全部が今すぐ守られていなければならない**が、
   制度要件には**まだ作っていないもの**（フェーズ n）と**作らないと決めたもの**
   （依存しない・対象外）がある。
2. **テストが要件を引くときの書き方が条番号だった。** 着手前に数えたところ、
   **項目 ID からの参照は 0 件**で、代わりに「電帳通達 8-13」「電帳規則 5 ⑤一ハ(2)」のような
   **条番号の直書き**だけがあった（数は下の実測）。

**qa/05 の GO は「4 つの計器を作る」までで、細部は同 §8 に未決だった。**
本 ADR は、その細部のうち**この計器に関わるものだけ**を決める。
**ここに書いた決定は Claude のもので、開発者は未承認である**（[05 の Q-11](../05_開発者への問い.md)）。

## 決定

### 1. 参照必須にするのは「済」「一部済」の項目だけ

**状態はカタログの最後の列から機械が読む。** 「フェーズ n」「依存しない」「対象外」には参照を求めない。

**この計器が言うのは「できていると書いてあるのに、誰も見張っていない」だけ**である。
まだ作っていないものにテストが無いのは穴ではない。

**状態を人が二重に管理しない。** 行が「フェーズ 6」から「済」へ変わった日に、
**参照必須の母数が自動で増える**——手で持つと、状態だけ進めて母数を増やし忘れる。

### 2. 条番号ではなく項目 ID で引く

**優良な電子帳簿の要件は、現行は電帳規則 5 ⑤で、2027-01-01 以後は 5 ④へ移動する**
（[電帳法リサーチ](../research/2026-08-23_電子帳簿保存法.md) §0。同 §14 の 2 は
**この二重管理が既に実務上の混乱要因になっている**と書く——
国税庁の資料は改正後の番号で書かれているのに、基準日時点で適用されるのは現行番号である）。

**条番号を ID にすると、施行日にすべての参照が腐る。**
**[40](../40_優良な電子帳簿の対応表.md) の項目 ID を正とする。**
**条番号は消さない**——読む人が条文へ行けるように、ID と併記する。

### 3. 参照の書き方は「40 の \<ID\>」の 1 通り

**裸の `A1` を拾わない。** 1 文字＋数字は変数名にも型名にも出るので、
**緩く書くと存在しない参照を数えて上限が黙って甘くなる**
（不変条件の側が取引先の `R-Inn` で踏みかけた形。ADR-0054 の決定 3）。
**左にも境目を置く**——置かないと「140 の」が当たる。

### 4. 判定はディスクを見ない純関数に切り出す

カタログの読み取り・状態の判定・参照の抽出・差集合を、**入力を受け取って結果を返す形**にする
（ADR-0054 の決定 5 と同じ）。**混ぜると、中身を空にしても実物のリポジトリでは緑のまま**になる。

### 5. 母数に 2 つのラチェットを置く

**カタログの項目数**と、**「済」「一部済」の数**の両方に下限を置く。

**後者が要るのは、状態の読み方が壊れたときのため**である。
「済」を読めなくなった瞬間に**参照必須が 0 件になって全部緑**になる——
これが[「最良の報告を返す壊れ方」](../qa/02_自己レビュー記録.md)のいちばん静かな形である。

### 6. 未参照は「ちょうどこの数」で持つ

**増えても減っても赤くする**（ADR-0054 の決定 6 と同じ）。
**「この項目は数えなくてよい」という許容リストは持たない**——
**許容リストは必ず腐るので、持たなくてよい設計を選ぶ**（[ADR-0012](0012-テスト方針とカバレッジのゲート.md) §4 の指針）。

### 7. カタログの拾い方は、本体より緩い形を必ず添える

**プライムは 0 個以上で受ける。** 書いた日に踏んだ——プライム 1 個までで書いたら、
**プライム 2 つの項目が黙って母数から落ちた**。**読めなかった行は未参照にも出てこない**ので、
**関門は緑のまま**である。

**緩い形の頭文字は、本体より広く取る。** 本体と同じ字の集合で書くと、
**カタログに新しい頭文字が入った日に、本体も緩い形も同時に見落とす**——
**緩い形が緩くないなら、それは緩い形ではない**（自己レビューの指摘。2026-09-14）。

### 8. 計器は自分のソースを走査せず、自分のソースに ID を字面で書かない

ADR-0054 の決定 4 と同じ。**説明を書くほど検査が甘くなる**形を避ける。

**走査の列を関数として出す。** 出さないと、**「自分のソースを走査しない」ことを確かめるテストが、
参照を出したファイルの一覧としか突き合わせられない**——計器のソースには ID の字面が無いのだから、
**除外を丸ごと消してもその一覧には現れず、テストは緑のまま**になる（同上）。

### 9. 走査は不変条件の側と同じものを使う

`InvariantTraceabilityConvention.TestSources` を共有する。
**2 つ持つと、片方だけ範囲が狭くなったときに気づけない。**

## 実測（2026-09-14）

| | |
|---|---|
| カタログの項目 | **20**（うち「済」「一部済」が **11**） |
| 着手前の項目 ID からの参照 | **0 件** |
| 着手前の条番号の直書き | `JournalBookQueryTests` に **12 件**（テストプロジェクト全体では 22 件） |
| 入れた日の未参照 | **11 件**（「済」「一部済」の全部） |
| ID を書いたあとの未参照 | **1 件** |
| ID を書いたファイル | 5 本（`JournalImmutabilityTests`・`JournalBookQueryTests`・`GeneralLedgerQueryTests`・`SeedDataTests`・`JournalPartnerGuardTests`） |

**10 項目に ID を書いた。内訳は、条番号から ID へ併記を足したのが 5 項目**（検索の 3 つと、
課税期間の初日、対象帳簿の全て）**で、条番号すら無かったところに要件を名指ししたのが 5 項目**
（訂正・削除の事実、記載事項、入力年月日、一連番号、見読可能性）である。
**「張り替え」ではない**——半分は新しく名指しした。

**残った 1 項目は「最初の記録段階から一貫して電子計算機で作成」である。**
**製品の外の運用の性質**（上流で利用者が何を使うか）なので、テストの書きようが無い。
**カタログは「一部済」で、残りの「明細データで」の側はフェーズ 6 に持っている**——
**その回に別のテストが付くので、この 1 件がそのとき 0 件になるとは限らない**。

**それでも許容リストに入れず、数として残す**——**次に読む人が「これは機械で守れない」と知る**ことに、
リストから消すより価値がある。

## 測れないこと

**「参照」は「テストされている」ではない。** 測れるのは**テストのソースにその ID が書かれているか**までで、
**書いてあるのに中身を検査していない**ことは見えない（[qa/05 §5](../qa/05_観点網羅の計器.md) が最初からそう断っている）。
**実際、入れた日の 1 回目は 3 項目を「守っていないテスト」に付けていた**（自己レビューで直した）。

**粒度も測れない。** 「一部済」は**一部でもできていれば参照 1 つで緑**になる。
**継続行（1 列目が空の行）は母数に入らない**——いま 3 行が独立した「できている」主張を持つが、
状態が変わっても母数は増えない。**[40](../40_優良な電子帳簿の対応表.md) §4-1 の記載事項の表も、
ID 列が無いので母数の外**である。

**カタログ自体が完全かも測れない。** [40](../40_優良な電子帳簿の対応表.md) に項目を書き落としていれば、
この計器は何も言わない。**そこは人が読むしかない。**

## 検討したが採らなかった案

- **全項目を参照必須にする。** **未参照が定数になるだけ**で、
  **「できているのに見張っていない」と「まだ作っていない」が混ざる**——報せの意味が消える。
- **条番号のまま突き合わせる。** 2027-01-01 に条番号が動くので、**その日にすべての参照が腐る**。
- **許容リストで残り 1 件を外す。** ADR-0012 §4 の指針に反する。**数として残すほうが、読む人に伝わる。**
