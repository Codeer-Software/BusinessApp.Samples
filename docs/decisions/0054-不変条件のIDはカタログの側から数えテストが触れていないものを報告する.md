# ADR-0054 不変条件の ID はカタログの側から数え、テストが触れていないものを報告する

## 状況

**カバレッジは「コードの網羅」しか測れない。** 本当に知りたいのは**観点（仕様）の網羅**で、
それは**仕様の側から数えるしかない**（[qa/05 §5](../qa/05_観点網羅の計器.md)）。
素材は既にある——不変条件には [10 §1](../10_会計ドメイン設計.md) の **I-nn** という ID が振られている。

**一方向の突合は既にあった**——`JournalViolationCodesTests` は
「コードが使う I-nn が文書の表にあるか」を見る。
**逆方向（カタログ側から見て、誰も触れていない ID を列挙する）が無い。**

[qa/05](../qa/05_観点網羅の計器.md) は 4 つの計器を挙げ、**ID トレーサビリティを 2 番目**に置いた
（開発者の方針の GO。2026-08-26。**GO の対象は「この 4 つを作る」までで、細部は同 §8 に未決**）。
本 ADR は、その細部のうち**この計器に関わるものだけ**を決める。
**ここに書いた決定は Claude のもので、開発者は未承認である**。

## 決定

### 1. カタログは [10](../10_会計ドメイン設計.md) の行頭の `|` で縛る。節では絞らない

**同じ文書の地の文にも I-nn は出てくる**ので、`^\|\s*I-(\d{2})\s*\|` で表の行だけを拾う。
**節では絞らない**——見出しを頼りにすると、§1 を分割・改番したときに黙って 0 件になる。
**いま I-nn の表は §1 にしかなく、他の節に増えたならそれも数えるべき**である。

**区切りの空白は 0 個以上にしてある。** 最初は空白 1 つで縛っており、
**表を整形し直すだけで行が落ち、その番号が未参照からも消えて緑になる**状態だった（qa/02 の R90-05）。

**0 件は緑ではない。** 母数そのものにラチェットを置き（`MinimumCatalogEntries`）、
**「番号の行に見えるのに読めなかった行」が 0 件であること**も見る
——読めなかった行は母数からも未参照からも落ちるので、**件数の下限だけでは気づけない**。

### 2. 「参照」はテストのソースに ID が書かれていることで、テストされていることではない

**測れるのはそこまで**である（qa/05 §5 が最初からそう断っている）。
参照は**コメント・XML コメント・文字列リテラル**の 3 通りで書かれるので、
**ソーステキストを走査する**（`lint_docs.py` がコード内の文書参照を突合しているのと同じ発想）。

**それでも「カタログに載っているのにテストが 1 本もない」は機械が言える。**
**残る人力は「カタログ自体が完全か」と「触れているテストが中身を見ているか」に縮む。**

**「参照済み」の側を安心材料にしない。** 入れた時点で、**まだ作っていない機能の不変条件が 2 つ、
別の機能のテストの説明文に名前が出ているというだけで参照済みに数えられていた**（2026-09-14 の実測）。
**だから参照元のファイルも返す**（`ReferencesByFile`）——**数だけでは人がそれを見つけられない**。

**見るのはテストプロジェクトの `.cs` だけ**とする。**末尾が `.Tests` の階層で決め、名前を並べない**
——プロジェクトが増えたときに、走査の側を直し忘れて黙って狭くなるのを避ける。
**`Designer/ddl/*.sql` の注記は数えない**——DDL は守りであってテストではなく、
「見張られているか」の証拠にならない（数えると、守りを書いただけで観点が埋まったことになる）。
**テストの土台（`BusinessApp.TestSupport`）も入らない**——**道具を書いただけで観点が埋まったことにしない**。

### 3. 取引先側の `R-Inn` と桁で縛る

[14 §5](../14_適格請求書発行事業者の登録.md) に `R-I1`〜`R-I9`（取引先側の不変条件。**ゼロ詰め無し**）があり、
**名前空間が衝突する**。`(?<!R-)\bI-(\d{2})\b` で、**`R-I5` を `I-5` と読まない**・**2 桁だけを拾う**。
**緩く書くと、存在しない ID を「参照済み」に数えて上限が黙って甘くなる。**

### 4. 計器は自分のソースを走査しない。ただし本体の守りは「字面を書かない」ほう

**上限の理由を説明する注記に番号を書いた瞬間、その番号が「参照済み」になる。**
**入れた回に実際に踏んだ**——3 つの番号を説明に書いたら未参照が 3 件から 1 件に減った
（[qa/02 のラウンド 90](../qa/02_自己レビュー記録.md)）。**説明を書くほど検査が甘くなる。**

**走査から自分のファイルを外す。ただしその除外はファイル名で決まっており、改名や分割で崩れる。**
**崩れた日に気づけるよう、守りを 2 枚にする**——
**①この 2 ファイルには番号を字面で書かない**（検体は `#` を接頭辞に化かして組み立てる）、
**②「自分のソースに番号が 1 つも無い」ことを中身で確かめる。**
**名前で外す仕掛けと、名前で確かめるテストは、同じ日に一緒に壊れる**（qa/02 の R90-04）。

### 5. 未参照の数え方は純関数に切り出す

**判定とディスク読みを混ぜると、中身を空にしても実物のリポジトリでは緑のままになる。**
**入れた回に実際にそうなっていた**——`Unreferenced` の中身を空にしても 5 本とも通った（qa/02 の R90-01）。
**`CSharpStyleConvention` が注記で明記して避けている形**を、**同じ `Conventions/` で踏んだ**。

**検体は「ちょうど 1 件だけ未参照になる」形を置く。** 0 件でも全件でもない形でなければ、
**「何も返さない」実装と「全部返す」実装の両方を落とせない。**

### 6. 未参照の持ち方は「ちょうどこの数」。許容リストを持たない

[ADR-0012 §8](0012-テスト方針とカバレッジのゲート.md) の Stryker、
[ADR-0053 決定 6](0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md) の制約ノックアウトに揃える。
**「この ID は数えなくてよい」という表を作らない**（同 §4）。
**値の正典は `InvariantTraceabilityTests.UnreferencedCount`。**

**上限（`<=`）ではなく、ちょうどの数にする。** 上限だと**テストを足して減らしても誰も値を下げず、
緩いまま残る**——ノックアウトの生き残りと違って、**この数は 0 に向かって減っていくべきもの**である。

**いまの 3 件（I-08・I-09・I-15）は、まだ作っていない機能の不変条件である**
（帳票の再現・部門別 P/L の合計・税集計のドリルダウン）。
**帳票と税集計はフェーズ 3 以降**（[04 §3](../04_実装計画と現在地.md)）なので、
**触れるテストが無いのは穴ではなく、まだそこに来ていない**。**その回に 0 へ落ちる。**

**「参照済み」の 14 件が全部見張られているという意味ではない。**
**同じく未実装の I-10・I-12 は、別の機能のテストの説明文に名前が出ているだけ**である（決定 2）。

### 7. 普通のテストとして毎回流す

**走査は 1 秒もかからない**（制約ノックアウトは桁が違う。所要は
[ADR-0053 の実測](0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md) が持つ）。
**コミット前フックの `dotnet test` に自然に乗る。** 別建ての手順を作らない。

### 8. この回は不変条件（I-nn）だけを対象にする

[qa/05 §5](../qa/05_観点網羅の計器.md) は**制度要件の ID**（[40](../40_優良な電子帳簿の対応表.md) の A1〜G2）も
同じ形で数えよと書いているが、**この回では入れない**。
**いまテストが要件を引くときの書き方が「電帳通達 8-13」のような条番号の直書き**で、
**§5 自身がそれを禁じたい**と言っている——**書き方を変えるのは別の判断**である。
**A1〜G2 を数え始めるなら、先に参照の付け替えが要る**（[qa/05 §8](../qa/05_観点網羅の計器.md) の保留）。

## 実測（2026-09-14）

| 測ったもの | 値 |
|---|---|
| カタログの ID | **17**（I-01〜I-17。欠番なし） |
| 走査するテストのソース | **116 本**（`.Tests` で終わる **6 つ**のプロジェクト。`Fixtures/` を含む） |
| 入れた時点の未参照 | **4 件**（I-02 と、フェーズ 3 以降の 3 件） |
| テストを 1 本足したあと | **3 件**（I-08・I-09・I-15。記録した数をこれに置いた） |
| うち「名前が出ているだけ」で参照済みになっていたもの | **2 件**（I-10・I-12。いずれも未実装） |
| 走査の所要 | **1 秒未満** |

**I-02（計上済み仕訳の全体でも貸借一致）はテストを書いて落とした**——
**I-01（伝票ごと）の帰結だが、明細が伝票をまたいで動いた・計上済みの行が消えた、という
別の壊れ方では I-01 を見るテストが 1 本も赤くならない。**

**ただし最初に書いたテストは何も見張っていなかった。** 反対仕訳を足して合計を数える形だったが、
**足した伝票に明細が 1 行も無く**、しかも**貸借一致に DB 側の担保が無い**
（[ddl/README](../../Designer/ddl/README.md) の二重防御の表）ので、**自分で入れた行を自分で数え直すだけ**だった。
**「断られたあとも帳簿ぜんたいの合計が動いていない」形に付け替えて、
関係する 6 本のトリガを 1 本ずつ外し、全部赤くなることを実測した**（qa/02 の R90-02・R90-03）。

| 外したトリガ | 付け替え前 | 付け替え後 |
|---|---|---|
| `trg_journal_lines_no_move_into_posted` | 緑 | **赤** |
| `trg_journal_lines_posted_no_update` | 緑 | **赤** |
| `trg_journal_lines_posted_no_delete` | 緑 | **赤** |
| `trg_journal_lines_posted_no_insert` | 緑 | **赤** |
| `trg_journal_entries_posted_no_delete` | 緑 | **赤** |
| `trg_journal_entries_posted_no_update` | 緑 | **赤** |

## 検討したが採らなかった案

- **カタログに「いつから守れるか」の列を足し、`いま` の行だけを要求する。**
  未実装の不変条件を上限から外せて厳密になるが、**正典（10 §1）に運用の都合の列が増える**。
  **本数の上限で足りる**——フェーズが来たら下がる
- **`Designer/ddl/*.sql` の注記も参照に数える。** 未参照は減るが、
  **守りを書いただけで観点が埋まったことになる**。数えるのは**見張る側**だけにする
- **参照ではなく「テストされているか」を測る。** 測れない（qa/05 §5 の断り）。
  **測れないものを測ったふりをしない**
- **番号が地の文に続けて書かれている形（`不変条件` の直後など）も拾えるようにする。**
  `\b` は日本語の文字も語の文字として扱うので、いまは拾えない。**拾えないのは安全側**
  （未参照が減らない）だが、**知らずに書くと「テストがあるのに未参照」になる**。
  **緩めるほうが危ないので、いまの形のままにして検体で見えるようにした**

## 帰結

- **カタログに不変条件を足した人は、テストを書くまで赤いままになる。** 記録した数が 3 で止まっているので、
  **新しい ID は必ず 1 件ぶん外れる**
- **テストを足して未参照が減った人も、赤くなる**（決定 6）。**値を下げるのが作業の一部**になる
- **計器が自分を数える形**（決定 4）と、**判定を空にしても緑のままだった形**（決定 5）は、
  どちらも**関門が緑で失敗する**型である——
  [`self-review` スキル §9](../../.claude/skills/self-review/SKILL.md) の観点がそのまま当たった。
  **§9 は「関門を作った回は関門をレビューに掛ける」と言っており、その 1 波で重大が 5 件出た**
- **制度要件の ID（40 の A1〜G2）は未着手**（決定 8）。**qa/05 §8 の保留に残る**
