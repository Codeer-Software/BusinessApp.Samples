# 0009: 案件損益＝管理会計レイヤ（配賦仕訳は作らない）・工数は分単位・B'-3〜5 の整理

- 状態: 採用 / 日付: 2026-07-06

## 背景
フェーズ B'（プロジェクト別損益）で、人件費の案件配賦を財務会計（仕訳）に反映するか、管理会計レイヤ（帳票のみ）に留めるかを決める必要がある。あわせて工数の持ち方と、B'-3〜B'-5 の残スコープを整理する。

## 決定
1. **人件費配賦は管理会計レイヤ**（QueryField 帳票でのみ算出。配賦仕訳・振替仕訳は作らない）
   - 財務会計の給与仕訳は月次の給与計上（人件費科目×部門）が正であり、案件別の按分は意思決定用の見せ方の問題。配賦仕訳を切ると仕訳帳が機械仕訳で汚れ、工数の入力遅れ・修正のたびに赤黒が必要になる（B2/B4 で確立した「元票→仕訳は確定イベントのみ」の原則に反する）。
   - 案件損益 = 売上（journal_lines.project_id 集計）− 直課費用（同）− 配賦人件費（工数比率×月次人件費コスト。リアルタイム計算）。
2. **工数は分単位 INTEGER**（time_entries.minutes）。0.25h 等の小数丸め誤差を避け、金額同様「整数のみ」の規律を貫く。表示は時間換算。
3. **月次人件費コストはマスタ**（monthly_salaries: user×年度×月×コスト）。給与そのものではなく「配賦用の標準コスト（法定福利込み概算）」として経理が設定する。**機微情報のため経理ロール専用**（配賦・案件損益帳票も同様にゲート）。
4. **B'-3〜B'-5 の整理**:
   - B'-3 検収基準売上 → **B-4 で実装済み**（acceptances 確定＝検収基準）。前受金・仕掛品の厳密化はバックログ。
   - B'-4 SaaS 繰延収益 → **B-5 の月次計上で実務要件を充足**（毎月請求・毎月計上のため繰延残高が発生しない前提。年払い前受には未対応＝バックログ）。
   - B'-5 SES 精算幅（140-180h 等の超過/控除単価）→ **バックログ**（v1 は月額固定の検収で代替。需要が明確になった時点で time_entries 実績と接続して実装）。

## 根拠
- ペルソナ（IT 受託）の意思決定に必要なのは「案件が儲かっているか」であり、日次で動く配賦を仕訳化しても監査証跡としての価値はない（むしろノイズ）。
- 弥生・freee 等の市販ソフトはこの領域が弱く、「工数×人件費×案件」を同一アプリで持てるのは CLB 一体型の強み（デモの訴求点）。

## 影響
- ddl/150_effort.sql: time_entries / monthly_salaries。TimeEntry は全社員入力、MonthlySalary・配賦・案件損益は経理専用。
- 案件別売上・費用は B4-2（検収仕訳）・B-7（経費仕訳の部門/案件引継ぎ）で JournalLine.ProjectRef に載る経路を確立済み。経費申請に案件フィールドが無い点は将来課題（バックログ: 経費申請へ案件選択を追加）。
