# ADR-0049 会計補助は、ステートレスなものだけを作り、会計コアのドメイン層には置かない

## 状況

**振替伝票の「複製」（[ADR-0048](0048-伝票の複製は取引の内容だけを写す.md)）を作ったら、
[ADR-0007](0007-会計コアの機能スコープ.md) と矛盾した。** 0007 は「銀行・カード明細の取込、OCR、自動仕訳ルール」を
「**入力支援であって会計の責務ではない**」、「承認ワークフロー・定型仕訳・仕訳辞書」を「**会計ではない**」として外している。
複製は、素直に読めば入力支援である——打鍵を減らすための機能で、無くても帳簿は作れる。

ADR-0048 は当初「**何を写して何を写さないかが会計の判断**だから内側」と理由づけたが、
**その論は「何が定型かは会計の判断」とも言えてしまう**（開発者の指摘。2026-09-10）。
線引きの根拠になっていなかった。

**この基準を厳密にしておかないと、他の機能を作るかどうかの判断がすべてぶれる**
（開発者。同日）。[03](../03_機能スコープ.md) は「判断の基準そのものを変えるときだけ新しい ADR を起こす」と定めており、
これはその場合に当たる。

## 決定

**以下は開発者の決定である**（2026-09-10 の往復。分類・段階・置き場・ドメインとの関係）。
**Claude の提案を開発者が採った部分は、それぞれの節で分けて書く。**

### 1. 機能を 3 つに分ける

| 区分 | 定義 | 例 |
|---|---|---|
| **会計コア機能** | 記帳・帳簿作成など、会計に必須の機能群。**この定義は 0007 から不変** | 仕訳の計上、取消・訂正、帳簿、締め |
| **必須の周辺機能** | 会計コアを実現するために必須のもの | 取引先、認証（他部品の利用） |
| **会計補助機能** | 会計コアではないが、**会計コアの入力（起票・計上・訂正）を容易にするもの** | 伝票の複製、既定税区分の自動入力 |

**会計補助の定義を「入力を容易にするもの」に限る**のは、帳簿を**読みやすくする**側（逆引きの表示・残高の照会・帳簿の検索）を
補助に含めるかが決まらなかったからである。当面それらは**会計コアの照会機能**として扱い、困ったときに分ける
（開発者。「答えが出ない」ので暫定）。

### 2. 会計補助を、状態の有無で 2 つに分ける

| 区分 | 定義 |
|---|---|
| **会計補助（ステートレス）** | その機能の実現のために、**新しい永続化（マスタ・テーブル・列・状態）を要しない**もの |
| **会計補助（ステートフル）** | その機能の実現のために、**新しい永続化を要する**もの |

**「ステートレス」は HTTP の意味ではない。** 新しい永続化を要しない、の意味であって、
**画面上の一時状態や入力中の値は含まない**（Claude の提案を開発者が採用。公開リポジトリなので後から読む人が HTTP の語と混同しないため）。

### 3. 概念の置き場は「属性か、仕組みか」で決める

- ある概念が**会計コアのマスタの性質・属性**であるなら、それは**会計コアの一部**である
  （既存の表に**列を足す**形になる。列を足すのは会計コアの変更なので、設計文書と ADR を通す）
- **表を足す**必要があるなら、それは会計コアではない

**意味（属性か仕組みか）が主基準で、構造（列か表か）は検算**である
（Claude の提案を開発者が採用。**列なら会計コア**と機械的に読むと、
`accounts.template_json` のような「補助のための列」まで会計コアになってしまう——
逆に「表を足す＝会計コアではない」のほうには、ほぼ反例が無い）。

**例：勘定科目の既定税区分。** 「その勘定科目は通常この税区分」は、科目区分や「取引先を要する」と同列の
**勘定科目の属性**であり、自動入力の機能が無くても持っている値である（開発者。2026-09-10）。
だから `accounts.default_tax_category_id` は会計コアの列である。
一方、**仕訳の入力時にその値を自動で入れる機能**は会計コアではなく、会計補助（ステートレス）である
——会計コアのマスタが持つ値から判定して入れているだけで、自分のための表を持たない。
売掛金の伝票で取引先を必須にするのと同じく、**マスタの属性を使って動くステートレスな機能**である。

### 4. 本プロジェクトで作る対象

| 区分 | 作るか |
|---|---|
| 会計コア機能 | **作る** |
| 必須の周辺機能 | **作る**（既にある部品で足りるもの——認証——はそれを使う） |
| 会計補助（ステートレス） | **必要性が高いものだけ作る**（下の段階で判定） |
| 会計補助（ステートフル） | **原則作らない。** 必須級に必要性が高いものは、具体例が出た段階で検討する |

**ステートレスの必要性は、無いとどうなるかで測る**（Claude の提案を開発者が採用）。

| 段階 | 無いとどうなるか | 作るか |
|---|---|---|
| **②** | **既に画面にある情報を、もう一度打つ** | **作る候補。頻度 × 量で判断する** |
| **③** | 打鍵・操作が減るだけ | **原則作らない**。極めて頻度が高いものだけ例外 |

**「①：正規の経路では結果に到達できない」は、この表に無い。** それは補助ではなく、
会計コアか必須の周辺機能の**欠落**である（開発者が同意。2026-09-10）。
複製は ②（打ち直しを避ける。訂正の下書きを消したとき・同じ取引をもう一度起こすとき）、
既定税区分の自動入力は ③ だが**毎明細で効き、税区分の選び違いを減らす**ので作った。

### 5. 置き場

- **会計補助（ステートレス）は、会計コアモジュールの中に実装する。**
  その機能は会計コアと深く関連しており、UX 上 UI を分けることが困難または不適切だからである。
  サーバ側の実装が要る場合でも、会計コアに新たなマスタ・テーブル・状態を足す必要は無く、
  **会計コアのドメイン層を侵さない**。
  本書で「ドメイン層」は `AccountingCore`、「アプリケーション層」は `AccountingCore.Server`
  （[ADR-0013](0013-機能単位のモジュール分割と依存方向.md) の会計コアの層のうち、採番・保存・関門・API を置く側。`.Application` を割るまではここが兼ねる）を指す。
- **会計コアのドメイン層には置かなくてよいはずである。ドメイン層に置きたくなったら、本当に会計補助（ステートレス）かを再検討する**（開発者。2026-09-10）。
- **会計補助（ステートフル）は、会計コアの DB に表を足す**（原則作らない）**か、別部品として分ける。**
  どちらかは [ADR-0029](0029-所有は相手抜きで存在するかで導き粒度は決断で決める.md) の「相手抜きで存在するか」で決める。
  承認ワークフローは後者である（0007 がそう決めている）。

### 6. ドメインとの関係

> **会計コアは、会計コア自身のドメイン知識としてマスタやテーブル、属性を持つ。**
> **それらが実際には補助機能で使われるものであっても、補助機能で使う名前ではなく、会計コアドメインとしての名前を持つ。**
> （開発者。2026-09-10）

会計補助は、ドメインに**不変条件・実体・状態を足さない**。ドメインが持つ属性や手段を**読む**だけである。
逆に言えば、**ドメインの側に「複製」「補完」のような補助の語が現れたら、置き場を間違えている**。

**例：複製できる種別。** 伝票の種別のうち期首残高・決算振替・繰越は複製の元にできない
（通常の伝票として写すと残高の前提が崩れる。[ADR-0048](0048-伝票の複製は取引の内容だけを写す.md)）。
この線は**取消・訂正の対象にできる種別**（`IsAmendable`。通常と訂正）と一致するので、
複製はその既存の属性を読む。**ドメインに `IsDuplicable` を置かない**——
「複製」はドメインの概念ではない。

## 実例

### 会計補助（ステートレス）——既にあるもの

| 機能 | 段階 | どこにあるか |
|---|---|---|
| 伝票の複製 | ② | [ADR-0048](0048-伝票の複製は取引の内容だけを写す.md) |
| 勘定科目を選ぶと税区分が既定で入る | ③ | 決定 3 の例 |
| 計上日から会計年度を自動で選ぶ | ③ | 振替伝票の画面のスクリプト |
| 貸借合計と一致の印を入力中に見せる | ③ | 同上 |
| 明細の行番号を自動で振る／借方から始める既定 | ③ | 同上 |

**訂正の再計上の下書きに原仕訳を写して開くのは、補助ではない。** 当初この表に「訂正の仕組みは会計コア、事前入力は補助」と
載せたが、その写しは `JournalCorrection`（ドメイン層）が組み立てている——決定 5 の「ドメイン層に置きたくなったら再検討する」に当たる。
再検討すると、**訂正の下書きの中身が原仕訳の写しであることは訂正モデルの一部**
（[ADR-0015](0015-訂正は取消と再計上の組で表し更新履歴方式を採らない.md)、[10 §5](../10_会計ドメイン設計.md)）で、
写さなければ訂正は「何を直したか」を失う。**ドメイン層にあるのが正しい**（Claude の当てはめ。2026-09-10 の自己レビュー）。
決定 5 の再検討が実際に働いた最初の例である。

### 会計補助（ステートレス）——候補

| 機能 | 段階 | 備考 |
|---|---|---|
| 明細行のコピー（同じ伝票の中で 1 行を複製） | ② | 複製の行版 |
| 貸借を反転した下書きを作る（前払・未払の振替戻し） | ② | 取消ではなく通常の伝票として。取消と混同させない文言が要る |
| 先月分の伝票を今月分として一括複製 | ② | 「定期的な伝票作成」の**ステートレス版**。スケジュールを持たない |
| 複数の下書きをまとめて計上 | ③ | 既存の下書きに対する操作。打鍵は減るが打ち直しは無いので ③ |
| 摘要の入力履歴からの補完（過去の伝票の摘要を候補に出す） | ③ | **辞書を持たない辞書** |
| 同じ取引先の直近の伝票から、科目の組み合わせを候補に出す | ③ | **登録しない定型仕訳** |
| 取引先・科目のコードや名前の前方一致補完 | ③ | マスタを引くだけ |
| 条件つき必須の印の出し分け | ③ | [21 §1](../21_画面の原則.md)。[04 §1](../04_実装計画と現在地.md) の C にある |

### 会計補助（ステートフル）

| 機能 | 新しい状態 | 置き場の見立て |
|---|---|---|
| 定型仕訳・仕訳辞書 | 雛形の表 | 会計コアの DB（**原則作らない**） |
| 摘要辞書（登録式） | 辞書の表 | 同上 |
| 自動仕訳ルール（条件 → 仕訳） | ルールの表 | 同上 |
| 定期仕訳のスケジュール実行 | スケジュールの表・実行履歴 | 同上。「定期的な伝票作成」の**ステートフル版** |
| 伝票へのメモ・付箋・タグ、お気に入り、利用者ごとの画面設定 | 小さな表・利用者ごとの状態 | **小さいがステートフル**——境界の感覚をつかむ例 |
| 承認ワークフロー | 承認状態・承認者・経路 | **別部品**（[ADR-0007](0007-会計コアの機能スコープ.md)） |
| 銀行・カード明細の取込と消込、OCR・証憑からの起票 | それぞれの業務データ | 別部品 |

**予算管理・予実比較、部門別の配賦、債権債務管理は、この表に入れない。** 入力を容易にするものではなく（決定 1）、
周辺業務である——別部品（[ADR-0029](0029-所有は相手抜きで存在するかで導き粒度は決断で決める.md)）。承認ワークフローは計上の入口に関わるので表に残すが、置き場は別部品。

### 境界がよく見える 3 対

| ステートレス | ステートフル | 違い |
|---|---|---|
| 摘要の履歴補完 | 摘要辞書 | 候補の出どころが「過去の伝票」か「登録した辞書」か |
| 直近の伝票から科目の組み合わせを候補に出す | 定型仕訳 | 「学ぶ」か「登録する」か |
| 先月分の一括複製 | 定期仕訳のスケジュール | 「押したときに写す」か「予定を持つ」か |

**UX がほぼ同じでも、状態の有無で分かれる。** この 3 対が、この分類が本当に線を引けていることの証拠である。

## 検討したが採らなかった案

- **「入力支援だから外す」を 0007 のまま維持する。** 複製を作った時点で破れた。
  **除外の理由は「入力支援だから」ではなく「ステートフルだから」**に変わる（0007 に注記した）。
- **「何を写すかは会計の判断だから会計コアの内側」。** 「何が定型かは会計の判断」とも言えてしまい、線にならない。
- **「UI が主役かどうか」で補助を判定する。** 複製は写す欄の選択をサーバでしている（画面で欄を写すと写し漏れがテストで捕まらない。[ADR-0008](0008-CLBとCSharpライブラリの責務分担.md)）ので、当てはまらない。開発者が撤回した。
- **①（行き止まり）を補助の段階に置く。** 到達できない結果があるなら、それは補助ではなく欠落である。

## 帰結

- **0007 の除外の理由が変わる**——取込・OCR・自動仕訳ルールの行の「入力支援であって会計の責務ではない」は
  「会計補助（ステートフル）である」に。承認・定型仕訳・仕訳辞書の行の「会計ではない」はそのまま（承認は別部品。
  定型仕訳・仕訳辞書も新しい状態を要する）。入力支援そのものは排除されない
- **[03](../03_機能スコープ.md) の ○ に「会計補助（ステートレス）」が現れる。** 備考に段階（②／③）を書く
- **ADR-0048 の位置づけが変わる**——「会計の判断だから内側」ではなく、「会計補助（ステートレス）として最初に名前を付けたもの」
- **複製の写す欄の選択は、会計コアのドメイン層からアプリケーション層へ移す**（決定 5・6）。
  ドメインが持つのは「取消・訂正の対象にできる種別」とその断り、「自分が付けた接頭辞を落とす手段」までで、
  どれも会計コアの名前で呼ぶ
- **次に補助を作りたくなったら、決定 2 → 4 → 5 の順に当てる**：状態が要るか → 要らないなら段階は ②か③か →
  ドメイン層に置きたくなっていないか。**ドメイン層に置きたくなったら、補助ではない可能性を疑う**
- **UI が複数のサーバ側モジュールを横断してよいか**は、この ADR では決めていない。UI の責務は UX の最大化であり、
  横断は許されうるが、**部品の分割性と衝突する**（取引先の UI の置き場で既に悩んだ形）。悩み続ける（開発者。2026-09-10）
