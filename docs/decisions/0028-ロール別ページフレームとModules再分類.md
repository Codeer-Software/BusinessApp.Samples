# ADR-0028: 1ロール1ページフレームへの再編と Modules フォルダ再分類

- 日付: 2026-07-19
- 状態: 採用・実装済み（4ロール実機検証済み）
- 関連: ADR-0019〜0022（旧・機能別フレーム編成——本 ADR が supersede）、ADR-0026/0027

## 背景（ユーザー指示 2026-07-19）

CLB のコモンプラクティスは「**ロールごとに1ページフレームを用意し、当該ロールでログインしたらそのフレームしか見えない**」方式。機能（メニュー項目）はフレーム内でカテゴライズ・階層化し、一度に多くを見せない（段階的開示）。従来の機能別10フレーム（Main/Expense/Sales/…/Admin）は、この方式に合わせて作り直す。各ロールで見える機能は従来と変えない。

## 決定

### 1. フレーム構成（10枚 → 5枚）

| フレーム | 対象 | 内容 |
|---|---|---|
| **Main**（ルート・ゲートなし） | 全員（一瞬だけ） | **振り分け専用**。TopPage の表示専用モジュール `RoleDispatch` がロールを判定し `/{RoleFrame}/Home` へ即時転送。サイドバーはリンクなし（ログアウトのみ） |
| **General** | role=general | ホーム＋4グループ（経費精算・販売・案件） |
| **Approver** | role=approver | General＋承認待ち＋予算（予実対比・予算明細） |
| **Accounting** | role=accounting | 全業務12グループ51リンク（経費精算/販売/購買/仕訳/帳簿/銀行/財務帳票/予算/案件/マスタ/設定） |
| **Sysadmin** | role=sysadmin | Accounting＋システム管理グループ（制度マスタ11画面） |

- ロールフレームの `UserReadCondition` は**当該ロール1つとの等値**（OR なし）。「自ロールのフレームしか見えない」を文字通り実現し、他フレームは直 URL でも「ページフレームへのアクセス権限がありません」
- **Main を振り分け専用にする理由**: CLB は「`IsApplicationRoot: true` のルートフレームがちょうど1枚・全員アクセス可能」が前提（ゲート付きルートは着地事故になる）。ルートに実体を置かず転送に徹することで制約と「1ロール1フレーム」を両立
- 各ロールフレームの TopPage は従来どおり **Home ダッシュボード**（TopPage セグメントは `Top`、サイドバーの「ホーム」リンクが `Home` セグメント——同一セグメント重複は designcheck が検出するため分離）
- サイドバーは `Title` の `/` 区切りによる**折りたたみ式階層メニュー**（実測: 既定は折りたたみ表示）。これが「必要な情報を徐々に見せる」の実装
- 経理系リンクの読み取りゲート（モジュール側 UserReadCondition）は**多層防御としてそのまま維持**

### 2. フレーム名に依存しないナビゲーション

- スクリプトの一覧戻り `NavigateTo("/Sales/Quote")` 等8箇所を `NavigateTo(NavigationService.GetModuleUrl("Quote"))` に置換（現在フレーム内で解決）
- Home ショートカットの `PageFrame` 指定を撤去（各ロールフレームに全対象モジュールが登録されているため現在フレーム解決で動く）
- 詳細遷移は従来から `GetModuleDataUrl(module, id)`（フレーム非依存）なので変更なし

### 3. Modules フォルダ再分類（機能カテゴリ＝旧フレーム分類に一致）

`ホーム／経費精算／販売／購買／会計（仕訳・帳簿・設定）／財務帳票／銀行／予算／案件／マスタ（経理）／マスタ（システム）` の11フォルダ。移動の要点:
- 旧「会計コア」を **会計**（仕訳・帳簿・年度・固定資産）と**財務帳票**（8帳票+資金繰り）に分割
- 旧「マスタ」を **マスタ（経理）**（取引先・案件＋購買から取引先口座・銀行から自社口座）と**マスタ（システム）**（ユーザー・部門・承認テンプレ/ルート・費目・科目・税・閾値・AdminHome）に分割
- 経費精算フォルダの承認**テンプレート**系（ApprovalFlowTemplate 一族・ApprovalRouteRule・ExpenseCategory）は制度マスタなのでマスタ（システム）へ（実行時フロー系 ApprovalFlow 一族は経費精算に残す）
- PartnerView→販売、ProjectView→案件（閲覧ビューは使われる場所へ）

## 検証（2026-07-19 実機）

- 4ロール（kaihatsu1_ippan／kaihatsu1_bucho／soumu_bucho／admin）でログインし、`/` からの自動振り分け先・サイドバー構成・グループ展開・画面遷移（予実対比ほか）を確認
- 一般ロールで `/Accounting/JournalEntry` 直 URL → アクセス権限エラーを確認
- designcheck 0件・フォルダ再分類後のデプロイ＆再起動後も正常

## 影響・追随

- **URL が全面変更**（/Sales/… → /General/… 等ロール別）。docs/tests/06・09・11 の URL 表記は docs 総点検で追随
- 旧フレーム名は ADR-0019〜0022 の記述にのみ残る（歴史記録として改変しない）
