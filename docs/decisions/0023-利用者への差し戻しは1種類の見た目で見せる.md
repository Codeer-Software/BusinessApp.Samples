# ADR-0023 利用者への差し戻しは 1 種類の見た目（トースト）で見せる

## 状況

計上の関門（`CustomizedModuleDataIO.SubmitAsync`）と取消・訂正の Web API
（[ADR-0016](0016-画面から呼ぶサーバ処理はWebAPIに置く.md)）は、どちらも**利用者の操作を差し戻す**。
差し戻しの理由は 1 件とは限らない（貸借不一致と部門未設定が同時に起きる）。
**複数の違反をどう見せるか**を決める必要があった。

CLB 側の事実は 2 つある（[qa/01](../qa/01_CLB静かな失敗.md) D-12・D-13。2026-08-26 実測 1.3.20）。

- **トーストの文言に改行を入れても表示に出ない。** LF でも CRLF でも同じ
- **`MessageBox.Show()` の本文は `MarkupString` として描画される**ので、改行・強調・箇条書きを出せる。
  ただし利用者が入力した文字列を埋め込むと HTML として解釈される

## 選択肢

| | 内容 | 問題 |
|---|---|---|
| **A. トースト 1 種類** | 差し戻しは全部トースト。複数件は 1 行に畳んで見せる | 改行が使えないので、文言の作り方に規律が要る |
| B. 件数で使い分ける | 1 件ならトースト、複数件は `MessageBox` | **計上の差し戻しは CLB 自身が表示する**ので、スクリプトから見た目を選べない |
| C. 独自のエラー表示を作る | `ProCodeField` で違反の一覧を描く | 作る量に対して得るものが小さい。画面ごとに作り直しになる |

## 決定

**A を採る。利用者への差し戻しは、経路によらずトースト 1 種類で見せる。**

文言は**件数と番号**で区切る（`計上できません（2 件）。①…②…`）。
文言の規則そのものは [09_画面の原則 §2](../09_画面の原則.md) が持つ。

決め手は **B が選べない**ことである。計上の差し戻しはスクリプトが表示しているのではなく、
**保存の失敗として CLB が表示している**。ここだけトーストで、取消・訂正だけ `MessageBox` にすると、
**同じ種類の知らせ（あなたの操作は通らなかった）が 2 つの見た目に割れる**。
利用者から見れば同じ「計上できなかった」なのに、経路によって見え方が変わる。

## 帰結

- **利用者に見せる文言に改行を入れない。** 入れても効かず、改行コードの管理だけが増える
- **独自のエラー表示（一覧・ダイアログ）を作らない。** 違反が増えても文言の作り方で吸収する
- `MessageBox` を使うのは**確認を取るとき**（「取り消しますか」）だけ。
  そこに利用者の入力した文字列を差し込むなら**エスケープしてから**入れる（qa/01 D-13）
- 差し戻しの本文は Web API 経路では `status: rejected` の本文で返す（ADR-0016）。
  **表示の形を決めるのは画面ではなくこの ADR**であり、返す側は違反コードと文言だけを持つ
