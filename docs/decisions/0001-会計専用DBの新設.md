# 0001: 会計専用 DB／データソースの新設

- 状態: 採用 / 日付: 2026-07-05

## 背景
ワークスペースの既定データソースは `SampleSQLite`（`sqlite_sample_auth.db`）で、認証サンプルの DB を指している。会計アプリのデータをどこに置くか決める必要がある。

## 選択肢
1. **新データソース `AccountingSQLite`（新規 DB ファイル）を作り、認証テーブルも新 DB に移す** ← 採用
2. 既存 `SampleSQLite` に会計テーブルを相乗りさせる
3. 認証は `SampleSQLite` のまま、会計だけ新 DB（2データソース並存）

## 決定
`AccountingSQLite`（`C:\Codeer.LowCode.Blazor.Local\Data\accounting_v1.db`）を新設し、**認証（app_users）を含むアプリの全データを1つの DB に置く**。`AllowCliSqlAccess: true`。既存 `SampleSQLite` はワークスペースの設定から撤去する。

## 根拠
- 本アプリは「テンプレートとして持ち帰れる」ことが訴求点。**単一 DB で自己完結**している方が導入提案として綺麗で、配布・バックアップも単純。
- サンプル DB への相乗りは、他サンプルのテーブルと混ざり「どこまでが本アプリか」が濁る。
- 認証分離（選択肢3）はデータソース2本の管理コストがかかる割に、このアプリでは分離のメリット（別システムとのユーザー共有等）が無い。

## 影響
- `designer.settings.json` / `designer.settings.Development.json`（ワークスペース）と、`AccountingApp.Server` の `appsettings.json` / `appsettings.Development.json` にデータソース追加・接続文字列追加が必要（サーバは要再起動）。
- `app_users` テーブル（PasswordCheckUserTableInfo の契約に合う列: id / user_name / hash / salt）と `temporary_files`（FileField 用）を新 DB に作成し、初期ユーザー admin を投入する。認証の実配線（AppUser モジュールのデータソース変更を含む）はフェーズ A 冒頭に検証する。
- DB ファイル名に `_v1` を付け、スキーマ破壊的変更時は新ファイルに切り替えられる余地を残す。
