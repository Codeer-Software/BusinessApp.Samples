# ADR-0003 対象ペルソナ

## 状況

「対象ペルソナを限定し、そのペルソナが使う機能を全て含む（逆に使わない機能は含めない）」を
スコープ決定の原則とする。したがってペルソナの確定が全機能判断の前提になる。

前回プロジェクトは「IT 受託ソフトハウス（従業員 55 名・年商 8.5 億・3 月決算）」をペルソナに置いた。

## 決定

**前回と同じ会社像を踏襲する**（詳細は [02_ペルソナ](../02_ペルソナ.md)）。ただし 3 点を調整する。

1. **アプリが担う範囲を「その会社の会計」に限定する。** 前回ペルソナが挙げていた痛点のうち、
   案件別損益・工数原価・経費精算・SES 精算・資金繰り予測は**本プロジェクトのスコープ外**である
   （[ADR-0001](0001-会計コア単体を部品として作る.md)）。ペルソナ文書には「本アプリが解決するもの」と
   「他部品に委ねるもの」を分けて書く
2. **顧問税理士の関与を明示する。** 「他の会計ソフトの代替になる」ためには、決算・申告で
   税理士にデータを渡せることが必須条件になる。前回ペルソナはこの記述が薄かった
3. **免税事業者の外注先が数名いる**という前提は維持する。インボイスの経過措置を必ず通るため、
   会計コアの中核テストケースになる

### 会計コアの設計に直結するペルソナ属性

| 属性 | 値 | 設計への影響 |
|---|---|---|
| 法人格 | 株式会社・非上場・単一法人・単一拠点 | 連結・多通貨・EDINET は非対象 |
| 決算期 | 3 月決算（会計期間 4/1〜3/31） | 期首日を可変に持つ。4/1 固定にしない |
| 年商 | 約 8.5 億円 | **課税売上高が 5 億円を超える** → 仕入税額控除に全額控除を使えない |
| 消費税 | 課税事業者・本則課税・**税抜経理**・適格請求書発行事業者 | 簡易課税・2 割特例・3 割特例・税込経理は既定経路ではない |
| 控除方式 | **個別対応方式**（既定） | 課税売上対応 / 共通対応 / 非課税売上対応の用途区分が必須 |
| 会計基準 | 中小企業の会計に関する基本要領 | IFRS・収益認識基準・新リース基準は非対象 |
| 組織 | 5 部門（総務・営業・開発 1・開発 2・SaaS 事業） | 部門別損益の集計軸が要る |
| 電子帳簿 | **優良な電子帳簿**を選択（届出済み） | [ADR-0004](0004-優良な電子帳簿への準拠と仕訳の不変性.md) |
| 決算 | 顧問税理士に依頼 | 申告そのものは非対象。税理士へ渡すデータ出力は必須 |

## 理由

- CLB の買い手はソフトを作る会社であり、**デモの聴衆とペルソナが一致する**。前回この理由で選定した
  ものであり、目的（技術デモ）が変わっていない以上、変える理由がない
- 55 名・単一法人・3 月決算・本則課税・税抜経理は**日本の中小企業として極めて典型的**で、
  会計コアが備えるべき機能を過不足なく引き出せる
- 検討メモ（`LocalData/temp/検討メモ群/01`・`09`）が推奨する初期対象
  （単一法人・従業員 5〜50 名・経理 1〜3 名・円建て・税理士関与）ともほぼ一致する

## 帰結

- **課税売上高が 5 億円を超えるため、全額控除の要件を満たさない。** 個別対応方式（または
  一括比例配分方式）が既定経路になり、仕訳明細に**用途区分**（課税売上対応／共通対応／
  非課税売上対応）を持たせる必要がある。これは会計コアのデータモデルに直接効く
- ただし課税売上高は年度により変動し、5 億円以下になれば全額控除に戻る。したがって
  **全額控除・個別対応方式・一括比例配分方式の 3 方式すべてを実装し、課税期間ごとに選べるようにする**。
  「使わない機能は作らない」の例外ではなく、同一の会社が年度によって使い分ける機能である
- 簡易課税・2 割特例・3 割特例は**このペルソナが使わない**ため、本プロジェクトでは実装しない。
  ただし税額計算を交換可能な戦略として分離し、後から足せる構造にする
- 税込経理も同様に実装しない（ペルソナは税抜経理）。データモデル上は経理方式を設定として持つに留める
