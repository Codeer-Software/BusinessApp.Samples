# 0006: 年次繰越＝翌期 opening_balances 生成方式（損益振替仕訳は生成しない）

- 状態: 採用 / 日付: 2026-07-05

## 背景
docs/04 §6 の当初案は年次決算で「損益振替仕訳（収益費用→繰越利益剰余金）を自動生成し、翌期の期首残高を作る」だった。実装にあたり、導出主義（decisions/0004）の下で振替仕訳が本当に必要か再検討した。

## 選択肢
1. **翌期 opening_balances の生成のみ**（BS 科目=期末残高、繰越利益剰余金=旧残高＋当期純利益。損益振替仕訳は作らない） ← 採用
2. 損益振替仕訳を自動生成し、期首残高も作る（当初案）

## 決定
選択肢1。年次繰越ボタンは「翌期の opening_balances を SQL 一発で生成」する。全帳票（試算表・BS・元帳）は「当年度の期首残高＋年度内仕訳」で導出するよう SQL を更新する。

## 根拠
- 本アプリの帳票はすべて**期間フィルタで導出**するため、PL 科目は翌期に自然にゼロスタートし、振替仕訳がなくても整合する。
- 振替仕訳を作ると「期末日の PL がゼロに見える」「仕訳帳に大量の機械仕訳が並ぶ」という副作用があり、それを避ける特殊フラグが増える。opening_balances が繰越の監査記録を兼ねる。
- SQL 一発（INSERT SELECT）で完結し、スクリプトの反復処理（N+1）を避けられる。

## 影響
- docs/04 §6 の記述を本 ADR に合わせて更新する。
- TrialBalance / BalanceSheet / GeneralLedger の SQL に opening_balances の合算を追加（試算表は「繰越残高」列）。
- 期首残高の貸借一致（符号付き合計=0）は FiscalYear 画面の保存時に検証する。
