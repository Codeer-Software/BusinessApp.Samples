# ADR-0064 稼働 DB のスキーマは migrate.ps1 だけで動かし、適用の記録はコミットごとに突き合わせる

## 状況

**[ADR-0020](0020-スキーマは現在形の正典で持ち変更は差分で配る.md) は「適用済みファイルは編集禁止（チェックサムで機械強制）」と決めていた。**
その強制は `migrate.ps1 -Apply` の中にしかなく、**コミット前フックが流す `-Verify` はスキーマの同値と未適用の有無しか見ていなかった**。

**2026-09-16 に穴を踏んだ**（[qa/03 の L-51](../qa/03_テストで漏らした実例.md)・[qa/04](../qa/04_実機操作テスト.md) の 2026-09-17）。
0038 を稼働 DB へ当てたあと、同じ回の自己レビューで郵便番号のトリガの断りの文言を変え、
**それを DDL の正典だけでなく適用済みの 0038 にも書いた**。稼働 DB のトリガは手で作り直され（`DROP`＋`CREATE`。`sql.ps1 -File` と推定——`LocalData/temp/` にその SQL が 1 本残っていた）、
**その記録はどこにも残らなかった**。コミット時に 0038 は「新規」だったので `check_frozen.py`（既存の配達物の変更を拒む）は通し、
`-Verify` は緑だった。**気づいたのは次の配達物を `-Apply` しようとしたとき**で、それまで 4 コミットが素通りしていた。

**穴は 2 つある。** ①**「適用してからコミットするまで」の窓**を見る機械が無い。②**稼働 DB のスキーマを、マイグレーションの外で動かす経路**（`sql.ps1` で DDL を流す）が開いていて、通っても記録が残らない。

Claude は 4 案を [05](../05_開発者への問い.md) の旧 Q-35 に置いた——
1 `-Verify` にチェックサム検査／2 記録の訂正の条件と、Claude が確認なしに行える条件を README に／3 `sql.ps1` が DDL を止める／4 `-Apply` の直後に `git add`（入れない）。

## 決定

**開発者は 1〜3 を採り、4 は入れない**（2026-09-17。逐語は「**あなたの提案内容で問題ないと思います。その方針に沿って、また個別具体的詳細に関してはあなたの判断に基づき実施してください**」）。

1. **`migrate.ps1 -Verify` は、適用済みの記録（`schema_migrations`）と手元のファイルのチェックサムを突き合わせる。**
   `-Verify` はコミット前フックが毎回流すので、**適用したあとに編集した配達物は、コミットの時点で赤になる**
2. **`schema_migrations` の記録の訂正は、条件を満たせば Claude が確認なしに行う。** 条件は「`-Verify` がスキーマの同値を言い、
   差分がコメントか `RAISE` の文言だけ」（それまでは「コメントだけ」）、手順は「退避を取る・差分の種類を確かめる・qa/04 に記録する」
   ——**旧 Q-35 の対策 2 の字のまま**。現在形は [migrations の README](../../Designer/migrations/README.md) が持つ
3. **`sql.ps1` は DDL（`CREATE`・`DROP`・`ALTER`）を流さない。** 通すのは `-File Designer/ddl/*` と、
   `<git-dir>/allow-ddl` に理由を書いて置いたときの 1 回だけ

**以下は「個別具体的詳細」として Claude が決めた**（開発者が委ねた範囲）。

- **DDL の判定は、文字列リテラルとコメントを落としてから語で見る。** 語彙は `CREATE`・`DROP`・`ALTER` の 3 つで、
  `PRAGMA writable_schema` のような裏口は見ない（過大に表明しない）。判定は純粋関数で、`sql.ps1 -SelfTest` が撃つ
- **逃げ道は `check_frozen.py` の `allow-frozen-edit` と同じ形**——印は読んだら消す（1 回しか効かない）。
  環境変数にしない理由もあちらと同じ（主シェルにはインライン前置が無く、セッションに残って次からも無言で関門を消す）
- **`-File` で通す正典は `Designer/ddl/` 直下と配下の `.sql` だけ。** `Designer/migrations/` は通さない——適用の経路は `migrate.ps1` だけである
- **`migrate.ps1` 自身は `sql.ps1` を通らない**（`_designer.ps1` を直に呼ぶ）ので、決定 3 の影響を受けない
- **記録の訂正で差分の種類を確かめる手**——`git diff` で見る。旧版が git に無ければ退避の DB の `sqlite_master` と比べる（DB に載らない差はその方法では見えないので、そのときは種類を言い切らない）
- **印は `sql.ps1 -AllowDdlOnce -Reason "<理由>"` で置く。** `.git/` への書き込みはコマンド文字列では `guard_delete.py` が拒む（[33 §1](../33_失わないためのルール.md)）ので、道具が自分で書く。理由の無い印は置けない。空の印は消して拒む
- **`-File` で通す正典は、git に追跡され HEAD から変わっていないものだけ**——`Designer/ddl/` に追跡外の `.sql` を置いても通らない
- **判定は 1 パスで字句を消す**（`'…'`・`"…"`・`/* */`・`--`）。2 パスにするとコメント中の `'` が後ろの DDL を隠す（自己レビューで実測）
- **判定の本体は純粋関数**（`Resolve-DdlDecision`）で、`-SelfTest` が配線ごと撃つ——部品だけ縛っても、分岐を消せば緑のまま通るから
- **4 を入れない理由**——1 で窓は閉じる。道具が索引を触ると、[30 §7](../30_作業のルール.md) の「索引は 1 つしかない」の形に近づく

## 理由

- **毎回流れる入口に置いて初めて「毎回」である**（[qa/03 の L-51](../qa/03_テストで漏らした実例.md)）。
  `-Apply` は配達物を足した人しか流さない
- **記録が残らない経路を閉じないと、`-Verify` の同値は「何を当てたか」を保証しない**——
  同値は結果の一致であって、経路の一致ではない。2026-09-16 の差し替えは同値のまま記録を欠いた
- **止まる理由を規則に書けば、Claude は止まらない**（[34 §0](../34_開発者とClaudeの分担.md)）。
  記録の訂正を「改ざん」と読んで止まったのは、条件が字になっていなかったからである

## 検討したが採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| `-Apply` の直後に `git add`（旧 Q-35 の 4） | 1 で足りる。道具が索引を触る副作用のほうが重い |
| `sql.ps1` に `-AllowDdl` スイッチ | 印と違って**毎回同じ字を打てば通る**ので、意識して外す形にならない。理由も残らない |
| DDL を止めずに記録だけ取る（`sql.ps1` が DDL をログに書く） | 記録は残るが、`schema_migrations` と食い違う経路が残る。**止めて、正規の経路（配達物）へ戻すほうが安い** |

## 帰結

- **壊して赤くなることを確かめた**（2026-09-17。[qa/04](../qa/04_実機操作テスト.md) の同日）。0038 の末尾にコメントを 1 行足して `-Verify` を流すと
  「0038_text_length_remaining.sql が適用後に編集されている（チェックサム不一致）」で exit 1。ファイルは元に戻した。
  `sql.ps1 -Query "DROP TABLE accounts;"` は拒んで exit 1。`-AllowDdlOnce` で印を置くと `SELECT` は印を食わず、次の DDL が 1 回だけ通り、印は消え、2 回目は拒む。
  `Designer/ddl/` に置いた追跡外の `.sql` も拒む。「`-- don't` の次の行の `CREATE`」も拒む（2 パスの判定では素通りしていた）
- **`sql.ps1 -SelfTest` をコミット前フックの「失うことを止める道具の自己検査」の段に足した**
- **DB を捨てて作り直す経路は残っている**——`-File Designer/ddl/*` は通る。**ただし稼働 DB を空にする手は `DROP` である**ので、
  作り直すときは `allow-ddl` の印を置く（理由「正典からの作り直し」）。手順は [33 §2](../33_失わないためのルール.md)
- **この関門が拾えないもの**——`sql.ps1` を経ない経路（デザイナ GUI の SQL・別の SQLite クライアント）。
  **語彙の外の DDL**（`PRAGMA writable_schema`・`VACUUM INTO` は見ない）。**`schema_migrations` への `UPDATE`・`DELETE` は DML なので通る**——記録の訂正の経路として意図した穴で、`-Verify` の 3 つめはこの表を信じる。
  **`git` の無い作業コピー**では印の置き場が無く、DDL は常に拒む（印の場所は道具の在処から `git -C` で引くので、呼び手の cwd には依らない）
- **[33 §2](../33_失わないためのルール.md) の作法 2・3 が「機械が止める」と言えるようになった。** 現在形はそちらが持つ
