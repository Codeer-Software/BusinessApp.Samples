# ADR-0058: CLB 1.3.18 への更新（テンプレート差分の取り込み方針）

- 日付: 2026-08-15
- 状態: 採用
- 関連: ADR-0037（BusinessApp ソリューション移行と CLB 1.3.16 対応）

## 背景（問題）

CLB が 1.3.18 まで進んだため、ユーザーが素の状態のソリューション
`C:\Users\dukkha\DEV\Codeer\BusinessApp-1-3-18\`（プロジェクト名だけ `BusinessApp_1_3_18.*`）を新規生成し、
そこから必要なものを取り込んで本リポジトリを 1.3.18 化することになった。

ADR-0037（1.3.4 → 1.3.16）と違い、今回は**プロジェクト構成・ファイル構成の変化はゼロ**。
新旧テンプレートをプロジェクト名の差だけ正規化して全ファイル比較したところ、
差分は「パッケージ参照のバージョン」と「テンプレート由来 7 ファイルの中身」に限られた。

### パッケージ参照の差分

| パッケージ | 1.3.16 | 1.3.18 |
|---|---|---|
| `Codeer.LowCode.Blazor` / `.Designer` | 1.3.16 | **1.3.18** |
| `Codeer.LowCode.Blazor.Extras` / `.Designer` / `.Server` | 0.4.0 | **0.5.0** |
| `Codeer.LowCode.Blazor.Designer.Standard` | 0.5.0 | **0.6.0** |
| `Codeer.LowCode.Bindings.Blazor-ApexCharts`（+ `.Designer`） | 0.25.3 | 0.25.3（据置） |
| `Codeer.LowCode.Blazor.DbAccess` / `.Licensing` | 0.1.0 / 1.3.0 | 同（据置） |

### テンプレート本体の機能差分（＝取り込む理由）

1. **CSRF トークン発行の方式変更**
   - 1.3.16: `CookieAuthentication` の**ミドルウェア**が「GET かつ `Accept: text/html`」のリクエストに
     便乗して `X-ANTIFORGERY-TOKEN` cookie を付けていた。
   - 1.3.18: 専用エンドポイント **`GET /api/account/antiforgery`** が唯一の発行元になり、
     WASM は起動時（`Client/Program.cs`）に、`login.html` はログイン試行のたびに明示的に取りに行く。
   - HTML の配信経路（キャッシュ・静的ファイル・フォールバック）とトークン発行が分離され、
     「index.html がブラウザキャッシュから返るとトークンが無い」という暗黙の依存が消える。

2. **スクリプトからの一括ファイル入出力 API（`BulkFileReader` / `BulkFileTransferService`）**
   - 1.3.18 のスクリプトカタログに追加された機能で、**サーバ側の対応実装が前提**:
     `POST /api/module_data/parse_file`（ファイル解析のみ・DB 非書込）・`list_file_by_data`（加工済みデータのファイル化）・
     `bulk_submit`（加工済みデータの一括保存）と、`ServiceInitializer` でのエンドポイント URL 登録。
   - 併せて `CustomizedModuleDataIO` に `BulkAddThreshold = 100`（純 Add が 100 行以上なら multi-row INSERT）と
     `BulkAddAsync` の override が入った。**一括 INSERT は行ごとの `AddAsync` を通らない**ため、
     override でパスワードハッシュ加工を同じように適用している。

## 決定

1. **テンプレート由来で自作カスタムを一切含まない 7 ファイルは、1.3.18 版で全面差し替える**
   （プロジェクト名 `BusinessApp_1_3_18` → `BusinessApp` の正規化のみ実施）:
   `Client.Shared/Services/ServiceInitializer.cs`・`Client/Program.cs`・`Client/wwwroot/login.html`・
   `Server/Controllers/AccountController.cs`・`Server/Controllers/ModuleDataController.cs`・
   `Server/CookieAuthentication.cs`・`Server/Services/CustomizedModuleDataIO.cs`。
   手で差分を当てるより、**テンプレートを正とし、カスタムが無いファイルは丸ごと追随させる**方が
   次回以降のバージョン更新でも差分が読みやすい。

2. **自作カスタムを含むファイルは触らない**（1.3.16 → 1.3.18 でテンプレート側に変更が無いことを確認済み）:
   - `Server/Program.cs` — AI/NTA 設定のバインド、`.html` を常に再検証させる `htmlNoCache`
   - `Server/Services/SystemConfig.cs` — `AppAISettings` / `NtaInvoiceSettings`
   - `Server/Controllers/AITextAnalyzeController.cs` — 自前 `Services/AI/` へのディスパッチ
   - `Client/wwwroot/index.html` — Blazor エラー UI の日本語化
   - `Server/appsettings*.json` — データソース `BusinessAppSQLite`・`active_app_users` ほか

3. **`app.clprj` の `Versions[]` を 1.3.18.0 / 0.5.0.0 に更新**（ApexCharts は 0.25.3.0 のまま）。

4. **`Designer/ClaudeCodeForDesigner/` は `ai-refresh` で 1.3.18 版に再生成する**（生成物・Git 追跡外）。

## 結果

- `dotnet build`（Debug 全体 / Designer Release）0 警告 0 エラー。出力 DLL が
  `Codeer.LowCode.Blazor 1.3.18.0` / `Extras(.Server) 0.5.0.0` を参照していることを確認。
- 1.3.18 のデザイナで `designcheck` → **findingCount 0**（デザイン側の移行作業は不要だった）。
- `ai-refresh` 実行済み。`_field_catalog.md` 429KB→437KB・`_script_catalog.md` 32KB→36KB
  （`BulkFileReader` / `BulkFileTransferService` の追加分）。
- 実機での起動・デプロイ・動作確認は**ユーザーが自身のデザイナビルドから実施**し、正常動作を確認。
- その際、デザイナが 5 モジュール（`JournalEntry` / `InvoiceLine` / `Receipt` / `ReceivableBalance` /
  `SalesOrderLine`）の `.mod.json` を**自動で書き直した**。中身は 1.3.18 のシリアライザ正規化のみで、
  意味的な変更はゼロ:
  - 1.3.18 で増えたプロパティが**既定値のまま書き出された** — フォーカス制御系
    （`InitialFocusField` / `NextFocusField` / `OnFocusMoving` / `IsFocusSkip` / `IsFocusWrap` /
    `FocusControlMode` / `AutoTab`）と、明細列の `IsMaxWidthFixed` / `IgnoreContentWidth` / `FixedColumnCount`
  - `Padding` の null メンバーが省略されるようになった（`{Left:8, Top:null, ...}` → `{Left:8}`）
  - プロパティの出力順の入れ替え・末尾改行なし
  - 書き直し後も designcheck 0 件

## 備考（将来の罠）

- **一括 INSERT はパスワードハッシュを素通りしうる**。`AppUser` を CSV 等で 100 行以上まとめて
  取り込むと `AddAsync` ではなく `BulkAddAsync` が走る。`CustomizedModuleDataIO.BulkAddAsync` の
  override（ハッシュ加工）を消すと**平文が DB に入る**。
- CSRF トークンは `GET /api/account/antiforgery` **だけ**が発行元。cookie が無いと POST 系が全て 400 になるので、
  ログイン画面や独自の静的ページを足すときはこの取得を必ず通す。
- **1.3.18 でフォーカス制御が入った**（`InitialFocusField`・`NextFocusField`・`IsFocusSkip`・`AutoTab` 等）。
  伝票入力のタブ順を業務に合わせて整える余地ができたので、UX 改善のネタとして覚えておく。
- テンプレート更新の比較手順（次回も同じ手が使える）: 新テンプレートを別フォルダに生成 → プロジェクト名を
  正規化した上で全ファイルを `diff --strip-trailing-cr` で突き合わせ → 差分を「テンプレートの進化」と
  「自作カスタム」に仕分ける。
