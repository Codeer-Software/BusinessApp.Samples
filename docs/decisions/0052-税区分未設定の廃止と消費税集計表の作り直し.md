# ADR-0052: 税区分未設定（NULL）の廃止と、消費税集計表の作り直し

- 日付: 2026-08-12
- 状態: 採用
- 関係: ADR-0003（消費税の持ち方）・ADR-0050（既定税区分のマスタ化）・
  `docs/issues/2026-08-09_体験シナリオ執筆中に見つかった改善候補.md` B-5 / B-6

## 背景

消費税集計表（`FinancialReports/TaxSummary`）に 2 つの欠陥があった。

- **B-6**: 貸借の符号を持たない単純合計だったため、赤伝で打ち消しても本体金額・消費税額が
  相殺されず、両方の絶対値が積み上がっていた。本アプリは「確定済み伝票は直接修正できない →
  赤黒訂正で直す」を仕様として強制しているので、運用すれば必ず踏む。
- **B-5**: `tax_category_id IS NOT NULL` の行だけを集計していたため、税区分の無い行が
  黙って落ちていた。仕訳インポートで取り込んだ税行（仮払消費税）が集計表から消えていた。

B-5 の根には**「税区分が無い」を `NULL` で表す一方、税区分マスタには `OUT_OF_SCOPE`（対象外）が
存在し、同じ意味を 2 通りで表現していた**という設計の問題がある。表現が 2 つあると集計を書くたびに
両方を意識する必要があり、実際にどちらかが落ちた。

## 決定 1: 税区分未設定（NULL）を廃止する

**貸借対照表科目の税区分は「対象外」とする。`NULL` は使わない。**
市販会計ソフトの流儀と一致する（2026-08-12 リサーチで確認。弥生・マネーフォワードとも
貸借科目の税区分は原則「対象外」）。

| 層 | 対応 |
|---|---|
| データ | `ddl/490`: BS 科目の既定税区分を「対象外」で埋め、既存 128 行を移行 |
| アプリ | `JournalLine.TaxCategory` / `JournalTemplateLine.TaxCategoryRef` / `Account.DefaultTaxCategory` を `IsRequired: true` |
| アプリ | `JournalImport`: 税区分コードが空欄の行を補完（通常行＝科目マスタの既定、税行＝同一伝票の本体行から継承）。推定できなければ伝票ごとスキップして指定を促す＝**B-5 の解決** |
| DB | `ddl/500`: `journal_lines.tax_category_id` を `NOT NULL` 化（SQLite のためテーブル再構築） |

**税行（`is_tax_line=1`）に「対象外」を入れてはいけない。** 税行は本体行に対する消費税なので
本体行と同じ税区分を持つ。対象外を入れるとその税額が集計表から消える＝ B-5 の再発になる。
移行でも同一伝票の本体行から継承させた（実測: 伝票 No.24 の仮払消費税 1,363 円が `PUR_10` を継承）。

### `NOT NULL` 化の検証（新旧 DB の突合）

サーバ停止 → DB バックアップ → 再構築 → `ATTACH` で突合、という手順で行った。

- 件数 201 = 201 / 全列 `EXCEPT` 双方向で差分 0 行
- 借方合計 = 貸方合計 = 27,302,555（不変）
- 最大 id 287 = `sqlite_sequence` 287（AUTOINCREMENT の採番を保持）
- インデックス 2 本を再作成 / `integrity_check` = ok / `foreign_key_check` = 違反 0
- 否定テスト: `tax_category_id` に NULL を入れる INSERT が拒否される

## 決定 2: 明示されなかった行は「対象外」にする（科目の既定で埋めない）

> **⚠ 2026-08-13 訂正（ADR-0053 決定 1）**: 以下で「科目マスタの既定で埋めたのが誤りだった」と
> 書いているが、**原因の特定が誤っていた**。減価償却の貸方に課税仕入 10% を付けていたのは
> `ddl/490` の穴埋めではなく、**`Lines_OnDataChanged` → `ApplyLineDefaults()` が
> スクリプト生成の伝票にも発火して科目の既定を入れていた**ことによる（実データで確認）。
> そのため本決定の前提「明示されなかった行は対象外になる」は成り立っておらず、
> `MarkRemainingLinesOutOfScope()` は実際にはほぼ no-op だった。
> **内部振替は `MarkAllLinesOutOfScope()` で明示的に上書きする**のが正しい対応。詳細は ADR-0053。

スクリプトから仕訳を作る経路は 11 モジュール 15 か所あり、いずれも売上・費用の本体行と
税行にだけ税区分を積み、相手勘定の行には積んでいなかった。`JournalEntry` に正典メソッドを置き、
**全経路が `Submit()` の直前に必ず呼ぶ**規約にした（例外なし＝監査可能）。

**当初この正典メソッドは「勘定科目マスタの既定で埋める」実装にしたが、これは誤りだった。**
科目の既定は「その科目の典型的な取引」に対する既定であって、その科目に触れるすべての仕訳に
当てはまるわけではない。実測で 2 件の実害が出た。

| 誤り | 症状 |
|---|---|
| 減価償却の貸方（工具器具備品）に取得時の既定 `PUR_10` が付いた | 符号付き集計で「課税仕入の戻し」として引かれ、課税仕入を 114,375 円**過少**にした |
| 前受収益の按分振替の貸方（SaaS売上高）に `SALES_10` が付いた | 年額請求時に計上済みの課税売上を、月次の振替でもう一度計上（月 100,000 円の**二重計上**） |

そこで **`MarkRemainingLinesOutOfScope()`**（明示されなかった行は「対象外」）に改めた。
前提は「各経路は税に意味のある行に必ず税区分を明示している。残る行は相手勘定か内部振替であり、
どちらも消費税の対象外」。減価償却も按分振替も前払振替も、消費税は元の取引の時点で確定している。

- 「対象外」はコードではなく課税種別 `taxation_type='out_of_scope'` で引く（コード変更に強い）
- 税行は意図的に触らない。税区分の無い税行が残れば `NOT NULL` で落ちる＝呼び出し側のバグとして早期に露見する
- `ddl/520`: 既存データの是正 5 行（減価償却 2・按分振替 2・保険料の前払振替 1）。
  対象は「内部振替の仕訳」×「申告に出てくる税区分」に限り、不課税・対象外は触らない

### 例外: 入出金起票（CashEntry）

この画面だけは**相手科目そのものが取引の経済的実体**なので、そこに科目マスタの既定を明示的に入れる。
一律に対象外へ倒すと**受取利息のような非課税売上を取りこぼし、課税売上割合の分母が狂う**
（実測: デモ DB に受取利息 500 円の入出金起票があり、非課税売上として正しく拾えている）。

## 決定 3: 消費税集計表を作り直す

| 変更 | 理由 |
|---|---|
| 勘定科目の正残側 `accounts.dc_normal` を基準に**差引**を出す | B-6 の解決。税区分から「自然な側」を決める案は、不課税・対象外に自然な側が無いため採らなかった。市販ソフトも科目の正残側で符号を決めている |
| **戻し（本体）／戻し（税）** 列を追加 | 赤黒訂正と売上返品・値引を DB 上で区別する情報が無い。差引に溶かすと申告で別掲すべき「対価の返還等」の存在が誰にも見えなくなるので、両方を出して別掲の要否は人が判断する |
| **税込対価** 列を追加 | 申告書は税込対価から課税標準額を逆算する様式のため |
| **控除率／控除対象税額** を追加し、経過措置は取引日で期間解決して**割合ごとに行を分ける** | 令和8年度税制改正で 80→70→50→30→0% の 5 段階になり、80%→70% の改定日が 2026-10-01。第18期（2026-04-01〜2027-03-31）はこれをまたぐので、年度合計に単一の割合を掛けると誤る |
| 最終行に**課税売上割合**と控除方式の判定 | この数字で控除方式が決まるため、表の使い方がこれ無しには決まらない。合計残高試算表の「合計（貸借検算）」と同じ UNION ALL + sort_key 方式 |

- 課税売上割合 = (課税売上＋免税売上) ÷ (課税売上＋免税売上＋非課税売上)。不課税・対象外は分母に含めない
- 表示は**切り捨て**。四捨五入だと 99.995% が「100.0%」になり、非課税売上があるのに全額が
  課税売上に見える（実測: 受取利息 620 円で発生した）
- 判定閾値（課税売上割合 95% 以上・課税売上高 5 億円以下）は `ddl/510` で `system_thresholds` へ。
  割合も扱えるよう `unit` 列（yen / percent）を追加した

### 実測（第18期・修正前 → 修正後）

| 税区分 | 本体金額 | 消費税額 | 戻し |
|---|---:|---:|---|
| 課税仕入 10% | 1,632,922 → **1,508,547** | 151,853 → **150,853** | 本体 5,000 / 税 500（会議費の赤伝のみ） |
| 課税売上 10% | 13,065,000 → **12,865,000** | 1,286,500 | 0（按分振替の二重計上を除去） |
| 課税仕入 10%(経過措置) | 10,200 | 800 | 控除率 80% → 控除対象税額 **640** |

課税売上割合 **99.99%（全額控除できます）**。

## 決定 4: 期間指定と、科目別税区分表の新設（同日の続き）

消費税集計表は年度単位だったので、**期間指定（日付 自／至）**を足した。中間申告や月次の税額把握に使う。
対象年度の内側を絞る形にし、未指定なら年度まるごと（既存の挙動を既定として保つ）。
最終行のラベルを「課税売上割合（表示期間）」に変え、**月次に絞るとその期間の割合になり、
申告に使う年間の割合とは別物**であることを画面上で示す。

あわせて **科目別税区分表（`TaxDetailByAccount`）** を新設した。消費税集計表が「税区分ごとの合計」なのに対し、
こちらは **科目 × 税区分** の内訳を出す。**実務の消費税の誤りは計算ミスより「税区分の付け間違い」が多く、
合計表だけでは発見できない**——B-6 の調査で、未設定（構造で塞げる）より誤設定（塞げない）のほうが
実務リスクが高いと分かったことへの対応である。

- 並びは科目コード順 → 税区分順。1 つの科目に複数の税区分が縦に並び、
  「この科目には本来どの税区分が付くはずか」を目で追える向きにした
- 絞り込みは 対象年度／期間／税区分／勘定科目。**税区分に「対象外」「不課税」を指定して
  損益科目が並んでいないかを見る**のが定石の使い方（給与に課税仕入が付いていないか、
  海外 SaaS の利用料が対象外になって控除漏れになっていないか）
- 列と金額の考え方は消費税集計表と同じ（`dc_normal` 基準の差引・逆側は「戻し」）
- 実測で **会議費／課税仕入 10% が本体 6,000・戻し 5,000** となり、
  E2E 07_特殊取引 の赤黒訂正（誤 5,000 → 赤 5,000 → 黒 6,000）の期待値と一致した

## 採らなかった案

- **税区分から符号の「自然な側」を決める**: 不課税・対象外に自然な側が定義できず、
  科目基準（`dc_normal`）のほうが全行に適用できる
- **「税区分未設定」の検証行を集計表に出す**: 当初案だったがユーザー指摘で取り下げ。
  `NOT NULL` 化で未設定が構造的に存在しなくなるため不要。また「対象外・不課税に分類された
  P/L 科目」を 1 行の金額で出しても、給与・法定福利費が常時載るので検査にならない。
  誤設定の発見は**科目別税区分表**（別タスク）で行う
- **DB の `NOT NULL` 化を見送る**: 当初はテーブル再構築のリスクを避けて提案したが、
  ユーザー判断で実施。新旧突合で安全性を担保した（上記）

## 今回も見送ったもの（意識的な判断）

| 項目 | 理由 |
|---|---|
| 用途区分（個別対応方式の課税売上対応／共通対応／非課税売上対応） | `journal_lines` への列追加と全入力画面への波及が大きい。IT 受託は課税売上割合がほぼ 100% で、実害が出るのは課税売上高 5 億円超のときだけ |
| 簡易課税の事業区分 | ペルソナが適用要件（基準期間の課税売上高 5,000 万円以下）を満たさない |
| リバースチャージ（特定課税仕入れ） | 課税売上割合が高い事業者には当分の間の経過措置があり実害が出にくい。ただし「海外 SaaS を対象外にすると控除漏れ」は改善候補に記録した |
| 消費税申告書・付表の出力／納税額計算モジュール | 本アプリの範囲は「経理担当が数字を検証する」まで。申告そのものは範囲外（2026-08-12 ユーザー判断） |
