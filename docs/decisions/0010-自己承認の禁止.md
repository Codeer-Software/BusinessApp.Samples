# 0010: 自己承認の禁止（承認者が申請者本人なら上位へ自動格上げ）

- 状態: 採用 / 日付: 2026-07-06

## 背景
承認ルートの動的解決（ADR-0007）は「申請者の部門の課長/部長」を機械的に割り当てるため、**課長本人が申請すると承認者が自分自身になる**ことが総合テストで実証された（申請 #8: 花子申請→▶承認 花子）。自己承認は内部統制上許されない。

## 決定
`ApprovalFlow.LoadFromTemplate` の承認者解決に自己承認禁止ルールを追加する:
1. 役職解決（manager/director）または固定指定の結果が**申請者本人**の場合:
   - `manager` → 同部門の `director` に格上げ
   - それでも本人（または director/固定指定が本人）→ **経理ロール（accounting）のユーザーのうち申請者以外で Id 最小の者**を代替承認者にする
2. 代替承認者も見つからない場合は申請をブロック（エラーメッセージで管理者に設定を促す）
3. 格上げが起きたことは承認フロー表示（承認者名の変化）で自然に可視化される

## 根拠
- 実務では「課長の申請は部長が承認、部長の申請は管理部門（経営管理・経理）が承認」が一般的。役員マスタを持たない本アプリでは「経理ロールの代表者」が最も自然な最終受け皿（会計処理の門番=経理、の本アプリの権限設計とも一貫）。
- テンプレートを役職別に増殖させる代替案は ADR-0007 で棄却済みの複製地獄に戻るため不採用。

## 影響
- 総務（固定指定）本人の申請（例: 総務三郎の交際費）も同ルールで経理の他ユーザーへ振り替わる。
- 同一人物が複数 Order に現れるケース（格上げの結果 director が2段に出る等）は v1 許容（2段目はスキップ相当の実害なし・監査上も同一人物の重複承認として判読可能）。
- 既存データ #8（花子→花子）は部長 次郎へ手当済み。
