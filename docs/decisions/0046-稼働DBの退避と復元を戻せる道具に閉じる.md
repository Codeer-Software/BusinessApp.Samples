# ADR-0046 稼働 DB の退避と復元を、戻せる道具に閉じる

## 状況

**開発者の問いかけ**（2026-09-08）——

> 今 LocalData フォルダ以下をあなたは触れない設定になっていると思いますが、
> SQLite の DB ファイルが置いてあるフォルダだけ触ってもいい気がしてます。
> だって自律自走作業をしているとき、DB ファイルのコピーを取っておいて、
> テストした後、前の DB に戻したりしたくないですか？

**そのとおりで、いまは複製を取ることすらできない。** [ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md)
の関門は「**保護対象の名前 ＋ 上書きにあたる語**」で拒むので、`cp LocalData/db/… <退避先>` は
`cp` に当たって止まる。**戻す側はもっと通らない**——復元は上書きそのものだからである。

**しかも同じ判定が、消す気のないコマンドまで拒んでいた**（この回に 4 回踏んだ）。
`>` を素で拾っていたため、`ls LocalData/ 2>/dev/null`・`cat LocalData/README.md 2>&1`・
Python の `'->'`・`len(sys.argv) > 1` が「上書き」と見なされ、**読むだけの操作が通らなかった。**

**開発者の指示**（同日）——「LocalData に関する修正はどんどんやっちゃってください」。

## 決定

1. **稼働 DB の退避と復元は、`tools/clb/db_snapshot.ps1` の 1 本に閉じる**（`-Save` / `-Restore` / `-List`）。
   **`LocalData` は保護対象に残したまま**にする。素の `cp` は今までどおり拒む。
2. **`db_snapshot.ps1` は、`trash.ps1` と同じ「戻せる道具」として `allow` を出す**
   （関門が判定する。**コマンド全体がその 1 本を呼ぶだけ**のときに限り、連結があれば通常の判定へ降ろす）。
   **確認を待たずに実行してよい。**
3. **写しは `VACUUM INTO` で取る。ファイルを複製しない。**
4. **この道具は何も消さない。** 復元で置き換える現物は `LocalData/backup/_superseded/<日時>/` へ**改名して残す**。
   本体だけでなく、SQLite が作る連れ（`-wal`・`-shm`・`-journal`）も一緒に退ける。
5. **復元の前に、いまの状態を必ず自動で退避する**（`before-restore_<日時>`）。戻しすぎたときの戻り先である。
6. **復元はサーバが止まっていることを求める。** 判定は 2 つで、**どちらか一方では足りない**——
   ① `BusinessApp.Server` のプロセスが居ないこと、② DB ファイルを排他で開けること。
7. **リダイレクトの判定を絞る**——矢印と比較演算子（`->`・`>=`・`> 1`）、捨て先（`/dev/null`・`$null`）は上書きではない。
8. **関門そのもの（`tools/claude/`・`.claude/settings.json`）は `ask` に載せない**（開発者の判断。2026-09-08。
   「これらは Git 追跡されていますよね？ よしとしましょう」——**戻せるので、[ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md)
   の載せる基準に当たらない**）。
9. **自己検査に残っていた 3 つの穴を塞ぐ**（下の「理由」）。

## 理由

**なぜフォルダを保護から外さないか。** 理由は 2 つある。

- **SQLite はファイルを 1 個複製しても一貫しない。** 書き込み中のページは本体の外
  （ロールバックジャーナル、WAL なら `-wal`）にあるので、本体だけを写すと**直前の更新が欠けた DB** ができる。
  しかも**読めてしまう**ので、壊れたことに気づくのは「戻したのに数字が合わない」ときである。
  **素の `cp` を許すと、この壊れ方を自分の手で作れるようになる。**
  `VACUUM INTO` は 1 つのトランザクションで完結した写しを書き出すので、稼働中でも一貫する。
- **保護を外すと、上書きの守りが全部消える。** 退避を取りたいだけなのに、`Write` の全上書きまで通る。

**「戻せる形に閉じて allow を出す」は [ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md) が
削除で採った形と同じ**である。削除を `trash.ps1` に閉じたのと同じ理由で、上書きを `db_snapshot.ps1` に閉じる。

**なぜプロセスとファイルロックの両方を見るか。** 2026-09-08 の実測で、
**`BusinessApp.Server` が動いていても DB ファイルは排他で開けた**（接続を握りっぱなしにしていない）。
**ロックだけでは「サーバが動いている」を検出できない。** 逆にプロセス名だけでは、
デザイナ exe が書いている最中を捕まえられない。**片方だけにすると、静かに壊れる経路が残る。**

**なぜ `ask` に載せないか。** 関門は Git 追跡下にあり、壊しても `git` で戻せる。
[ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md) の載せる基準
（「消えたとき、戻す操作が現実的か・戻し損ねたことに気づけるか」）に当たらない。
**載せると、関門を直すたびに確認が挟まって自律作業が止まる**——その対価に見合わない。

**塞いだ 3 つの穴**（どれも 2026-09-06 の自己レビューが実証し、期限を「次に関門へ触るとき」としていた）。

- **本番の形でフックを起こしていなかった。** 自己検査は `sys.executable` と絶対パスで呼んでおり、
  `shell: "bash"` から `python "$CLAUDE_PROJECT_DIR/…"` が解決されるかを見ていなかった。
  **`python` が PATH から消えれば、上書きの拒否は「確認」に落ちる**のに緑のままだった。
  → `settings.json` が書いている `command` と `shell` をそのまま使って起こす検査を足した。
- **`deny` に並べた削除の語が、正規表現の正典と切れていた。** 代表の 3 語しか見ておらず、
  **語を消しても鳴らなかった。** → 語彙を `DELETION_WORDS` の 1 か所に集め、
  正規表現・`deny`・検体の 3 つをそこから導く。突き合わせは**両方向**で見る
  （正典の語が `deny` に居るか／`deny` の 1 語の規則が正典に有るか）。
- **`cwd` 既定の検体が、プロセスの `cwd` と交絡していた。** repo の中から起こす限り、
  「repo 根で解決する」と「呼ばれた場所で解決する」は同じ値になり、区別できない。
  → **repo の外から起こす検体**を足した。

**「壊したら鳴る」を実証した**（2026-09-08）。複製した木を 10 通りに壊し、すべてで自己検査が赤くなることを見た
（本番の形の起動・`deny` の語の増減・語彙の削除・`cwd` の解決先・リダイレクトの判定を緩める／殺す・
戻せる道具から外す・保護判定を殺す・配線を外す）。**壊していない複製は緑である。**

## 帰結

- **自律作業で「取って・壊して・戻す」が回せる。** マイグレーションを稼働 DB へ当てる前に
  `-Save` を打っておけば、失敗しても `-Restore` で戻せる（[31 §1](../31_検証のルール.md) の検証ループ）。
- **復元にはサーバの停止が要る。** 止め忘れると関門が断る。**どのみち戻したあとに再起動が要る**——
  CLB は列定義を static にキャッシュするため（`migrate.ps1` と同じ理由）。
- **`LocalData/backup/` が育つ。** `_superseded/` も含めて**この道具は何も消さない**ので、
  溜まったものは**開発者が消す**（ごみ箱と同じ扱い。Claude は触らない）。
- **過剰検出は減ったが、無くなってはいない。** 変数どうしの比較（`if (a > b)`）は今も上書きと見なされる。
  **そちらへ倒したままにする**——見逃した上書きは戻せないが、過剰な拒否は書き方を変えれば済む。
- **戻せる道具を増やすときは、ここに足す判断が要る。** `allow` は権限判定そのものを飛ばすので、
  1 本増やすたびに確認の外へ出る面積が広がる。**「取り返しがつく」ことをスクリプト自身が
  保証している道具だけ**を入れる。
