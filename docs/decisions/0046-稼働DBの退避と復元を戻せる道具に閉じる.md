# ADR-0046 稼働 DB の退避と復元を、戻せる道具に閉じる

## 状況

**開発者の問いかけ**（2026-09-08）——

> 今 LocalData フォルダ以下をあなたは触れない設定になっていると思いますが、
> SQLite の DB ファイルが置いてあるフォルダだけ触ってもいい気がしてます。
> だって自律自走作業をしているとき、DB ファイルのコピーを取っておいて、
> テストした後、前の DB に戻したりしたくないですか？

**そのとおりで、いまは複製を取ることすらできない。** [ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md)
の関門は「**保護対象の名前 ＋ 上書きにあたる語**」で拒むので、`cp LocalData/db/… <退避先>` は
`cp` に当たって止まる。**戻す側はもっと通らない**——復元は上書きそのものだからである。

**しかも同じ判定が、消す気のないコマンドまで拒んでいた**（この回に 4 回踏んだ）。
`>` を素で拾っていたため、`ls LocalData/ 2>/dev/null`・`cat LocalData/README.md 2>&1`・
Python の `'->'`・`len(sys.argv) > 1` が「上書き」と見なされ、**読むだけの操作が通らなかった。**

**開発者の指示**（同日）——「LocalData に関する修正はどんどんやっちゃってください」。

## 決定

**開発者が答えたのは、次の 3 つだけである**（逐語）。

- 「**LocalData に関する修正はどんどんやっちゃってください**」——この工事に着手してよいこと
- 「**これらは Git 追跡されていますよね？ よしとしましょう**」——関門を `ask` に載せないこと（決定 8）
- 「**5085 ポートのサーバーは Claude の開発のためのものですから、開発者の確認を取らずに
  自由に開始・終了・再起動してかまいません**」——[31 §2](../31_検証のルール.md) の授権

**残りはすべて Claude の判断であり、開発者は個別に承認していない。**
とくに**決定 2 は「確認を待たずに実行してよい」という権限を新しく作るもの**なので、
[ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md) の同じ授権が開発者の逐語に依っていたのと、
**由来が違う**。**異論があれば、この決定から先を差し戻せる。**

> **2026-09-08 追記**: **決定 2 は開発者が追認した。** この節を読んだ開発者が
> [30 §10](../30_作業のルール.md) の `db_snapshot` の段を自分で「**開発者の指示。2026-09-08**」に
> 書き換えている。**追認されたのはその授権（確認を待たずに実行してよいこと）であって、
> ほかの決定ではない。**

1. **稼働 DB の退避と復元は、`tools/clb/db_snapshot.ps1` の 1 本に閉じる**（`-Save` / `-Restore` / `-List`）。
   **`LocalData` は保護対象に残したまま**にする。素の `cp` は今までどおり拒む。
   > **2026-09-10 追記**: 正典の `LocalData` 1 行を `db/`・`designs/`・`storages/`・`backup/`・`README.md` の 5 行に割った
   > （**`temp/` は守らない**——いつ消えてもいいものの置き場。開発者の指示）。稼働 DB と退避の守りは変わらない。
2. **`db_snapshot.ps1` は、`trash.ps1` と同じ「戻せる道具」として `allow` を出す**
   （関門が判定する。**確認を待たずに実行してよい**）。**Claude の判断である**（上の追記のとおり、後に開発者が追認した）。
   **`allow` を出す条件は 3 つ重ねる**（**現在形の正典は `guard_delete.py` の docstring**——
   識別子と実装が同じ場所にあるので、ここには写さない）。
   **3 つ要ったのは、先頭しか見ない判定だけでは後ろに何でも書けたから**である
   （2026-09-08 の自己レビューが実測。**どの条件がどれを塞ぐかは `guard_delete.py` の docstring**）。
3. **退避は `VACUUM INTO` で取る**（素の複製は使わない。理由は下）。
   **戻す側はファイルの複製である**——一貫した写しを、止まっている DB の場所へ置くだけだからである。
   **写しは、取ったときと、現物に触れる前の 2 回 `PRAGMA integrity_check` を通す。**
4. **稼働 DB とその連れ・退避は、何も消さない。**
   復元で置き換える現物は `LocalData/backup/_superseded/<日時>/` へ**改名して残す**。
   本体だけでなく、SQLite が作る連れ（`-wal`・`-shm`・`-journal`）も一緒に退ける
   （**一次情報が「本体を別のファイルで上書きするとき、元の DB の hot journal を消さないこと」を
   壊れ方に挙げている**。[リサーチ §1](../research/2026-09-08_使用中SQLiteの複製とフックのallow.md)）。
   **例外は `-SelfTest` が自分で作った一時フォルダだけ**（repo の外にあり、この道具が作ったもの。
   `trash.ps1` の同じ断りに倣う）。
5. **復元の前に、いまの状態を必ず自動で退避する**（`before-restore_<日時>`）。戻しすぎたときの戻り先である。
6. **復元はサーバが止まっていることを求める。** 判定は 2 つ——
   ① `BusinessApp.Server` のプロセスが居ないこと（**主**）、② DB ファイルと連れを排他で開けること（**保険**）。
7. **リダイレクトの判定を絞る**——上書きではない 3 種類（矢印と比較演算子・捨て先・数だけの右辺）を外す。**内訳の正典は `REDIRECT` の定義**であって、ここには写さない。
   **保護対象の名前を探すのは、当たり先をパスで受け取る形のときだけ**にする——
   `db_snapshot.ps1` は**パスを受け取る引数を持たない**ので、同じコマンドに `LocalData` が出ても
   それはこの道具の当たり先ではない（**この回に実測で踏んだ**——退避を取るのと同じコマンドで
   DB を読んだだけで拒まれた）。
8. **関門そのもの（`tools/claude/`・`.claude/settings.json`）は `ask` に載せない**（開発者の判断。2026-09-08。
   「これらは Git 追跡されていますよね？ よしとしましょう」——**戻せるので、[ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md)
   の載せる基準に当たらない**）。
9. **`db_snapshot.ps1` にも自己検査を置き、コミット前フックで流す**（`-SelfTest`）。
   **`allow` の根拠は「消さない・戻す前に必ず退避する」なので、それを機械で表明できないなら
   `allow` を出す前提が立たない。** 稼働 DB には触れず、一時フォルダで名前の検査と
   ファイルを動かす手順（連れも退けるか・途中で落ちたら巻き戻すか）を確かめる。
10. **`sql` CLI の呼び出しは `_designer.ps1` の 1 か所に置く**（`Invoke-DesignerSql`）。
    `migrate.ps1` と同じ処理を写すと、片方だけ直って古いまま残る（[20 §4](../20_実装の原則.md)）。
11. **自己検査に残っていた 3 つの穴を塞ぐ**（下の「理由」）。

## 理由

**なぜフォルダを保護から外さないか。** 理由は 2 つある。

- **使用中の SQLite をファイル複製すると、壊れた写しができる。**
  トランザクションの最中に複製すると**古い内容と新しい内容が混ざって壊れうる**こと、
  安全な方法の 1 つが `VACUUM INTO` であること、その出力が**一貫した写し**であることは、
  すべて一次情報が書いている（**逐語と出典は
  [リサーチ §1・§2](../research/2026-09-08_使用中SQLiteの複製とフックのallow.md)**）。
  **壊れた写しは読めてしまう**ので、気づくのは「戻したのに数字が合わない」ときである——
  **素の `cp` を許すと、この壊れ方を自分の手で作れるようになる。**
  **この開発機の `journal_mode` は `delete` である**（実測。同リサーチ §3）。
  **WAL でどう壊れるかは測っていない。**
- **`VACUUM INTO` 自身も、予期しないシャットダウンや電源断で中断されると
  壊れた出力を残しうる**（<https://www.sqlite.org/lang_vacuum.html>。確認日 2026-09-08）。
  だから**取った直後に `integrity_check` を通す**。
- **保護を外すと、上書きの守りが全部消える。** 退避を取りたいだけなのに、`Write` の全上書きまで通る。

**「戻せる形に閉じて allow を出す」は [ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md) が
削除で採った形と同じ**である。削除を `trash.ps1` に閉じたのと同じ理由で、上書きを `db_snapshot.ps1` に閉じる。

**なぜプロセスとファイルロックの両方を見るか。**

- **測ったこと**（2026-09-08）: `BusinessApp.Server`（PID あり）が動いている最中に、稼働 DB を
  `[System.IO.File]::Open(..., 'Open', 'ReadWrite', 'None')` で開いたところ**成功した**。
  **したがってロックだけでは「サーバが動いている」を検出できない**ので、プロセスの検査が主である。
  「接続を握りっぱなしにしていない」はこの観測からの**推測**で、他の説明を排除していない。
- **測っていないこと**: ロックの検査が何を捕まえるか。デザイナ exe が書いている最中では試していない。
  **保険として置いてある**、が正確な位置づけである。
- **どちらにも時間の穴が残る**——検査を通った直後に開かれたら検出できない。
  現物を退ける直前にもう一度検査して幅を狭めたが、無くしてはいない。

**なぜ `ask` に載せないか。** 関門は Git 追跡下にあり、壊しても `git` で戻せる。
[ADR-0044](0044-削除はごみ箱送りに一本化しrmを機械で止める.md) の載せる基準
（「消えたとき、戻す操作が現実的か・戻し損ねたことに気づけるか」）に当たらない。
**載せると、関門を直すたびに確認が挟まって自律作業が止まる**——その対価に見合わない。

**塞いだ 3 つの穴**（どれも [qa/02](../qa/02_自己レビュー記録.md) のラウンド 48（2026-09-08）の
R48-10 が実証し、期限を「次に関門へ触るとき」としていた）。

- **本番の形でフックを起こしていなかった。** 自己検査は `sys.executable` と絶対パスで呼んでおり、
  `shell: "bash"` から `python "$CLAUDE_PROJECT_DIR/…"` が解決されるかを見ていなかった。
  **`python` が PATH から消えれば、上書きの拒否は「確認」に落ちる**のに緑のままだった。
  → `settings.json` が書いている `command` と `shell` をそのまま使って起こす検査を足した。
- **`deny` に並べた削除の語が、正規表現の正典と切れていた。** 代表の 3 語しか見ておらず、
  **語を消しても鳴らなかった。** → 語彙を `DELETION_WORDS` の 1 か所に集め、
  正規表現・`deny`・検体の 3 つをそこから導く。突き合わせは**両方向**で見る
  （正典の語が `deny` に居るか／`deny` の 1 語の規則が正典に有るか）。
- **`cwd` 既定の検体が、プロセスの `cwd` と交絡していた。** repo の中から起こす限り、
  「repo 根で解決する」と「呼ばれた場所で解決する」は同じ値になり、区別できない。
  → **repo の外から起こす検体**を足した。

**「壊したら鳴る」を実証した**（2026-09-08）。複製した木を 1 か所ずつ壊し、
そのすべてで自己検査が赤くなることを見た。**壊していない複製は緑である。**

**関門で壊したもの**——本番の形の起動（`python` を存在しない名前に）／`deny` から削除語を落とす／
`deny` に語彙に無い語を足す／語彙から語を落とす／`cwd` をプロセスの作業ディレクトリで解く／
リダイレクトの判定を素の `>` に戻す／同じ判定を殺す／`CHAINED` から `<` `>` を落とす／
`allow` の条件から上書きの語の検査を落とす／パスを取る道具かどうかの別を反転／
戻せる道具から `db_snapshot.ps1` を外す／worktree の根を足すのをやめる／保護判定を殺す／削除側の配線を外す。

**退避の道具で壊したもの**——`Test-Path` の `-LiteralPath` を落とす／`Move-LiveAside` の巻き戻しを消す／
現物が無くても `_superseded` のフォルダを作る／連れの一覧を縮める／名前の検査をゆるめる／
空の写しを健全だと言う／`Restore-Aside` が何も戻さない。

**この実証そのものが、検体の足りない場所を 4 つ見つけた**——`send2trash` の枝、
`allow` の 2 つの新しい条件、そして**退避の道具の「連れを見なくする」変異**（検体が実装の
`$SidecarSuffixes` を読んでいて、リストを縮めると検体も一緒に縮む同語反復だった）。
**緑を確かめるだけでは、どれも見つからなかった。**

**復元は実機で通した**（2026-09-08）。サーバを止めて `-Restore` を実行し、次を確かめた。

- **`Get-FileHash` の SHA-256 が、戻した DB と退避で一致**した。
  ただしこれが示すのは**複製が働いたこと**までで、帳簿の中身が保たれたことは次の行が示す。
- **`PRAGMA integrity_check` が `ok`**、**仕訳と明細と科目の件数が戻す前と一致**（51 / 101 / 106）。
- **退けた現物が `_superseded/<日時>/` に残り**、`<live>.restoring` の残骸が無い。
- **`migrate.ps1 -Verify` が引き続き一致**（61 オブジェクト）。
- **サーバが動いている間は道具が断る**ことも、同じ日に確かめた。

## 帰結

- **自律作業で「取って・壊して・戻す」が回せる。** マイグレーションを稼働 DB へ当てる前に
  `-Save` を打っておけば、失敗しても `-Restore` で戻せる（[31 §1](../31_検証のルール.md) の検証ループ）。
- **復元にはサーバの停止が要る。** 止め忘れると**道具が断る**（`Assert-NotInUse`。関門ではない）。
  **どのみち戻したあとに再起動が要る**——CLB は列定義を static にキャッシュするため（`migrate.ps1` と同じ理由）。
  **さらに `migrate.ps1 -Verify` を打つ**——古い退避を戻すとスキーマが巻き戻り、適用済みの記録と食い違う。
- **`LocalData/backup/` が育つ。** `_superseded/` も含めて**この道具は何も消さない**ので、
  溜まったものは**開発者が消す**（ごみ箱と同じ扱い。`LocalData/backup/` は保護対象なので Claude には消せない）。
  **この回の検証で作ったものは `LocalData/README.md` が名指ししている**（一度片づけたら偽になる話なので、ここには置かない）。
- **開発サーバ（`http://localhost:5085`）の開始・終了・再起動に、Claude は確認を取らない**——
  **規則と理由の本体は [31 §2](../31_検証のルール.md)**（開発者の指示。2026-09-08）。
  ここで言えるのは、**復元がサーバの停止を求めるので、この授権と対になっている**という観察だけである。
- **`allow` を出す危険の大きさは測った。** `deny` はフックの `allow` より強い
  （[リサーチ §4](../research/2026-09-08_使用中SQLiteの複製とフックのallow.md)）。
  **ただし `ask` は同じ形で試せておらず、`deny` に載っていない当たり先は守られない**——
  この道具は `LocalData` を当たり先に取らないので、**守りは `allow` の条件の狭さだけ**である。
- **過剰検出は減ったが、無くなってはいない。** 変数どうしの比較（`if (a > b)`）は今も上書きと見なされる。
  **そちらへ倒したままにする**——見逃した上書きは戻せないが、過剰な拒否は書き方を変えれば済む。
- **戻せる道具を増やすときは、ここに足す判断が要る。** `allow` を返した当たり先が
  `settings.json` の `deny` に無ければ、**そのまま実行される**
  （`deny` があれば `deny` が勝つ。[リサーチ §4](../research/2026-09-08_使用中SQLiteの複製とフックのallow.md) で実測）。
  **1 本増やすたびに、確認の外へ出る面積が広がる。**
  **「取り返しがつく」ことをスクリプト自身が保証している道具だけ**を入れる。
