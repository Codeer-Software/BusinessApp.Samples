# ADR-0056 SQL ミューテーションは、クエリの SQL を 1 箇所ずつ壊し、行動テストだけで赤になるかを見る

## 状況

**Stryker が変異させるのは C# のソース（Roslyn 構文木）だけ**で、
**別ファイルにあるクエリの SQL はその外**にいる（[qa/05 §1](../qa/05_観点網羅の計器.md)）。
そこの漏れは人の注意力だけが頼りで、実際に起きかけている——
`>=` と `>` の取り違えも、空値検索の分岐名の綴り違いも、**例外にならず静かに 0 件を返す**。

**[ADR-0055](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md) は「行動テストがあるか」までしか測れない。**
**あることと、強いことは別**である——同 決定 3 がそう断っている。

[qa/05 §3](../qa/05_観点網羅の計器.md) は 2 つの案を置いた。
**A 案（実テストスイートで殺す）を先に入れる**。
**ここに書いた決定は Claude のもので、開発者は未承認である**。

## 決定

### 1. 対象はクエリモジュールの SQL だけにする

**`Designer/Design/Modules/**/*.Query.sql` を回す。**
**DDL は入れない**——制約とトリガは
[制約ノックアウト](0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md)が
**1 本まるごと外す**形で既に見張っている。
**「`CHECK` の中の `>=` を `>` にする」のような、外さずに歪める変異は
ノックアウトが見ていない**ので、**やる価値はある**——だが
**2 つの計器の担当が重なる**ので、[qa/05 §8](../qa/05_観点網羅の計器.md) の保留に送る。

**マイグレーションも入れない。** 適用済みのものは凍結されており（[ADR-0020](0020-スキーマは現在形の正典で持ち変更は差分で配る.md)）、
**壊しても誰も流し直さない**。

### 2. 変異点は「注記と文字列リテラルの外」だけを数える

**正規表現をそのまま当てると、注記の中の `date(` や `>=` にも当たる。**
当てても**振る舞いが変わらないミュータントばかりが増えて、生き残りの数が意味を失う**。

**伏せ字は長さと改行を保つ**ので、伏せた側で見つけた位置をそのまま原本に当てられる。
SQLite は二重引用符を**識別子の引用**にも使うので、そこも伏せる。

**演算子の表は汎用セットではなく、このリポジトリで実際に起きた壊れ方から起こす**
（[qa/05 §3-1](../qa/05_観点網羅の計器.md)）。**表そのものを検体で守る**——
**死んだ正規表現があっても、実物の SQL では「その形が無かった」と区別が付かない**ので、
`selftest` は**12 個の演算子が 1 つ残らず検体に当たり、当てると SQL が変わる**ことを見る。
**演算子ごとの小さな検体を別に持たない**——表の 2 つ目の写しになり、
**正規表現を書き換える人が写しも一緒に直してしまって、死んだ形が捕まらない**。

**伏せ方の裏取り（2026-09-14）**——追跡下の SQL **59 本**を走査し、
**注記と文字列リテラルの中に変異点が 1 つも立たないこと**を目で確かめた
（[qa/05 §8](../qa/05_観点網羅の計器.md) が求めていた確認）。
**閉じない引用符を含む注記・`--` を含む文字列リテラル・二重引用符の識別子**も検体に入れてある。

**`selftest` はコミット前フックに載せる**（掃引そのものは載せない。決定 7）。
**0.1 秒で済み、ここが壊れると掃引が「生き残り 0」という最良の報告を返す**からである。
**実データの母数にも下限を置く**——**掃引は毎回は流れないが、`selftest` は毎回流れる**ので、
**書き方が変わって演算子が当たらなくなった日に気づけるのはこちらだけ**である。

**数える側と読む側が同じ文字列を見ていることは、位置だけでは保証されない**（決定 3）。

### 3. 注入は環境変数で、ファイルを書き換えない

**掃引の途中で止めると、壊れた SQL が追跡下に残る。**
環境変数（`SQL_MUTATION`）なら、プロセスが終われば何も残らない。
**制約ノックアウトと同じ形**である（ADR-0053 決定 4）。

**位置で指す**——`<モジュール名>:<開始位置>:<長さ>:<置換後>:<原文>`。
同じ字面が何度も出るので、**字面では 1 つを名指せない**。

**位置だけでは足りない。** 数える側（`sql_mutate.py`）と読む側（`TestDatabase.Mutate`）が
**同じ文字列を見ている保証は無い**——**BOM が 1 つ付いただけ、改行が CRLF になっただけで
全部の位置が 1 文字ずれる**。ずれた置換は**構文として通ることがあり、結果が変わって赤くなり、
掃引はそれを「殺した」と数える**（道具が BOM を付けてコミットまで通った実例がある。qa/03 の L-24）。
**だから 3 つやる**——①**読み方を揃える**（python も `File.ReadAllText` と同じく
BOM を落とし、改行はそのまま読む）、②**原文まで運ばせて、そこに本当にその字があるかを確かめる**、
③**掃引がカナリアで、ずれていないことを毎回確かめる**（決定 5）。

**値を切り詰めない。** 最後の欄（原文）は `DISTINCT ` のように**末尾に空白を持つことがあり、
切り詰めると照合が必ず外れる**——**環境変数の空白に強くしようとして `Trim()` を入れた回に、
カナリアがそれを捕まえた**（qa/02 のラウンド 92）。
**空白だけの値を「立っていない」と読むのはよい**が、**値そのものには触らない**。

**形が壊れていたら黙って素通ししない。**
**注入が届いていないのに緑を返す**のが、この道具で最も危ない壊れ方である
——掃引はそれを**「テストが見張っている」と数えてしまう**。

### 4. 回すのは、そのモジュールの行動テストだけにする

**`<モジュール名>QueryTests` に絞る**（[ADR-0055 決定 1](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md) が名前で対応づけている）。
**全部のテストを回すと、関係のないテストが代わりに赤くなって穴を隠す**
——ノックアウトが `Schema.Tests` に絞ったのと同じ理由（ADR-0053 決定 3）。

### 5. 判定は「赤になったか」だけを見る

**何が赤になったかは見ない。** 理由はどうあれ、
**壊したことに気づいたテストが 1 本でもあれば、その箇所は見張られている。**

**この判定は「赤い理由」を区別しないので、赤くなる経路を先に全部塞ぐ。** 3 つ置いてある。

- **母数の下限**（モジュールごと）。**変異点は静かに痩せる**——閉じない引用符が 1 つ入れば
  伏せ字が以降を全部飲み、キーワードの大文字小文字が変われば演算子が当たらなくなる。
  **痩せると生き残りも減り、上限だけの関門は緑になる**
- **対照実験**（モジュールごと）。何も壊さずに 1 巡して緑でなければ、
  **以降の赤は「テストが見張っている」証拠にならない**。**まとめて 1 回にしない**——
  行動テストが 1 本も無いモジュールでは `--filter` が 1 件も当たらずランナーが非 0 で終わり、
  **全点が「殺した」に化ける**
- **カナリア**（モジュールごと）。**「原文を原文で置き換える」変異**を 1 つ当てる。
  位置と原文が合っていれば SQL は 1 文字も変わらず緑のまま、
  **ずれていれば注入が投げて赤くなる**。**ずれた赤を「殺した」と数えると、
  そのモジュールは生き残り 0 になってラチェットを通る**——
  **当たったかを確かめる守り（決定 3）が、そのまま最良の報告を作ってしまう**。
  **文言では見分けられない**——`dotnet test -v q` は例外の本文を印字しない（実測）

**そして「赤になった」は「アサーションが違いを見分けた」ではない。**
**WHERE が丸ごと潰れて 0 件になり、検体の取り出しが例外になっただけ**でも赤くなる。
**殺した数はアサーションの強さを何も言っていない**——読むのは生き残りのほうである。

### 6. 生き残りの持ち方は本数の上限。許容リストを持たない

[ADR-0012 §8](0012-テスト方針とカバレッジのゲート.md) の Stryker、
[ADR-0053 決定 6](0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md) の制約ノックアウトに揃える。
**「この変異点は数えなくてよい」という表を作らない**（[ADR-0012 §4](0012-テスト方針とカバレッジのゲート.md)）。
**値の正典は `tools/clb/sql_sweep.ps1` の `$ratchet`。**

**上限はモジュールごとに持つ。** 全体で 1 つだと、
**`-Only` で 1 本だけ回したときに全体の上限が当たって、生き残っても成功で返る**——
逆に、**直している最中のモジュールを回すたびに必ず赤くなる**と、
**exit code を読まない習慣ができる**。
**同じ表に母数の下限も置く**（決定 5）。**モジュールを足したら表にも行を足す**——
表に無いモジュールは「点 1 以上・生き残り 0」で判定するので、**足した日に必ず赤くなる**。

**生き残りには等価ミュータントが混ざる。**
**仕分けの表を持つ前に、生成の段階で外せるかを先に見る**——
[ADR-0055 の実測](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)で出た 4 件は
**どれも「スキーマを読めば等価と分かる」形**だった（外部キー・`NOT NULL`・日付の正規化）。

### 7. 実行は区切りごとの手動にする

**流す回は、クエリの SQL か行動テストに触れた回。** コミット前フックには載せない。

**理由は速さではない**（掃引は 5 分。下の実測）。**生き残りが多いうちは、
毎回流しても上限を通るだけで誰も読まない**からである。
[ADR-0012 §8](0012-テスト方針とカバレッジのゲート.md) の Stryker も、
当初「フェーズの区切りで」としたものを**実測の速さを見て開発者の判断で毎回実行へ変えた**前例がある。
**減らしてから、載せるかを開発者に諮る。**

### 8. B 案（行セットの差分比較）はこの回では入れない

[qa/05 §3-2](../qa/05_観点網羅の計器.md) の B 案は**入力コーパスを 1 箇所に定義し、
行動テストとハーネスの両方が同じ表を読む**形を要求する。
**4 本の行動テストの検体の持ち方を揃える作業が先**で、**これは別の判断**である。
**A 案が測るのは「実際のアサーションで殺せるか」で、こちらが本来知りたいこと**でもある
（B 案が測るのは上界）。**qa/05 §8 の保留に残す。**

## 実測（2026-09-14。入れた日）

| 測ったもの | 値 |
|---|---|
| 変異点 | **276**（クエリモジュール 4 本） |
| 1 回目の生き残り | **86** |
| **仕訳帳の表明を直したあと** | **81**（上限をこれに置いた） |
| 掃引 1 回 | **5 分 2 秒**（対照実験を除く。**1 点あたり約 1.1 秒**） |

**1 点が速いのは、そのモジュールの行動テストだけを回すから**である（決定 4）。
`--no-build` と併せて、**制約ノックアウトの 1 点 10 秒前後とは桁が違う**
（[ADR-0053 の実測](0053-制約ノックアウトはDDLを1つずつ外し振る舞いのテストだけで赤になるかを見る.md)）。

| モジュール | 変異点 | 1 回目の生き残り | 直したあと |
|---|---|---|---|
| `GeneralLedger` | 93 | 18 | 18 |
| `JournalBook` | 81 | 9 | **4** |
| `JournalEntryList` | 80 | **56** | 56 |
| `PartnerRegistrationList` | 22 | 3 | 3 |

**`JournalEntryList` は 80 点中 56 が生き残った。**
この一覧の行動テストは**取引先名の出し方 3 本だけ**で、
**SQL の 11 本のパラメータ（8 つの軸——会計年度・状態・種別・取引年月日・計上日・伝票番号・取引先・摘要）を
1 つも撃っていない**。**入れた日の報告としては、これが一番大きい。**

**`JournalBook` は 9 から 4 に落ちた。** 空値検索のテストが**件数しか表明しておらず、
条件を反転しても件数が偶然一致していた**（qa/03 の L-46）。
**返った行を名指しで突き合わせる形に直し**、勘定科目の絞り込みと日付の 4 通りを足した。
**残る 4 件はどれも `date()` の剥がしで、証明できる等価である**（下）。

**演算子の表は、SELECT 句にほとんど届いていない。** 最上位の `FROM` より前に立つ変異点は
**276 点中 21 点だけ**（`GeneralLedger` 5・`JournalEntryList` 16・`JournalBook` 0・`PartnerRegistrationList` 0）。
**列の取り違えは `QueryModuleTests` が別名しか見ないので行動テストだけが唯一の砦**なのに
（[ADR-0055 の実測](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)）、
**この計器はそこを撃てていない**。**「190 殺した」は、最も無防備な場所について何も言っていない。**
**同じ型の列どうしの置換**を演算子表に足すのは [qa/05 §8](../qa/05_観点網羅の計器.md) の保留である。

**生き残りの演算子の内訳**（1 回目の 86 件を演算子名で集計したもの。**全件**）——
`date-strip` 26・`and-or` 23・`or-and` 17・`boundary-ge`／`boundary-le` 合わせて 9・
`desc` 4・`is-null`／`is-not-null` 合わせて 5・`distinct` 2。

### 生き残りのうち、いま等価と証明できるもの

**2 つの型だけ**である。**合わせて 11 点前後**で、**残りはテストの穴**である。

- **型 A: 範囲比較の片側の `date()`。** 値が ISO に正規化されていれば（011 のトリガが入口で保証）、
  `date(列)` は列の先頭 10 文字なので、**`>=` では列側、`<=` では検索値側**が結果を変えない。
  **225 組の総当たりで差が 0 であることを確かめた**（[ADR-0055 の実測](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)）。
  **残り半分（`>=` の検索値側・`<=` の列側）は等価ではない**——
  **いまの検体が裸の日付しか持たないので区別が付いていないだけ**である
- **型 B: `ORDER BY` の `date()`。** `date()` の下では同じ日が必ず同着になり、順序は次のキーが決める。
  **ただしこれは DDL からは証明できない**——011 のトリガは 5 書式を受理するので、
  「格納形が一様」の根拠は**「CLB が唯一の書き手である」という運用の事実**だけである

**`PartnerRegistrationList` から一般化してはいけない型が 2 つある。**

- **`LEFT JOIN` → `JOIN` は移らない。** あちらで等価だったのは `partner_id` が `NOT NULL` の外部キーだからで、
  `GeneralLedger` と `JournalEntryList` の `LEFT JOIN` は**すべて NULL 可の列**に対するもので、落ちる行が実在する
- **空文字の分岐を落とす変異も移らない。** あちらで等価だったのは `registration_no TEXT NOT NULL` で
  `LIKE '%%'` が全件に当たるからで、`description` や `item_description` は NULL 可なので
  **`NULL LIKE '%%'` が NULL になり、摘要の無い伝票が落ちる**

**`and-or` 23・`or-and` 17・`boundary` 9・`desc` 4・`distinct` 2 には、
証明できる等価が 1 つも含まれていない。**

**なお `PartnerRegistrationList` の生き残りが 3 件で、
[ADR-0055 の実測](0055-クエリモジュールには行を入れて読み戻すテストを必ず置く.md)の等価が 4 件なのは、
数え方が違うからである**——あちらは**手で作った 18 個**の結果で、
`JOIN` → `LEFT JOIN` と「空文字の分岐を落とす」は**この演算子表が生成しない形**である
（表にあるのは `LEFT JOIN` → `JOIN` の向きと `OR` → `AND` で、どちらもその 2 つとは別物）。

### 計器そのものを壊して確かめた

- **注記の伏せ字を殺す**と `sql_mutate.py selftest` が赤くなる
- **演算子の正規表現を 1 つ殺す**と、同じく赤くなる（検体に当たらなくなる）
- **置換を骨抜きにして掃引すると、`PartnerRegistrationList` の結果が
  「19 殺した / 3 生き残り」から「0 殺した / 22 生き残り」に変わる**——
  **注入が本当にテストまで届いていること**と、
  **届かなくなったときの壊れ方が「全部生き残り」という安全側に出ること**が同時に分かる
- **`-Only` に無い名前を渡す**と 0 本で止まる（「生き残り 0」を報告しない）

## 検討したが採らなかった案

- **SQL を書き換えて掃引する**（ファイルを直接いじる）。道具は要らないが、
  **途中で止めると壊れた SQL が追跡下に残る**。**環境変数なら何も残らない**
- **字面で変異点を指す**（`date(` の 3 つめ、のように）。読みやすいが、
  **SQL を 1 行直すと番号がずれる**。位置なら、**ずれた瞬間に「外を指している」で落ちる**
- **全テストを回して赤を数える。** 殺し手が増えて生き残りは減るが、
  **減った理由が「その SQL を見張っている」ではなくなる**

## 帰結

- **クエリの SQL を直した人は、掃引を流す回がある**（決定 7）。**フックには載らない**
- **生き残りは、そのまま「次にやること」の一覧である。**
  **`JournalEntryList` の 56 件が最大の塊**で、
  **この一覧には絞り込みの行動テストが 1 本も無い**——
  **行き先は [qa/05 §8](../qa/05_観点網羅の計器.md) の保留に積んだ**
- **上限は下げるためにある**（決定 6）。**入れた日の値は目標ではない**
- **等価ミュータントの持ち方は、まだ決めていない**（決定 6）。**生成の段階で外す道を先に見る**
- **DDL の中の演算子は、まだ誰も見張っていない**（決定 1）。
  **制約ノックアウトは 1 本まるごと外す形しか見ない**ので、
  **`CHECK` の中の境界の取り違えは 2 つの計器のあいだに落ちている**——[qa/05 §8](../qa/05_観点網羅の計器.md) の保留
