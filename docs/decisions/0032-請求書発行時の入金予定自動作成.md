# 0032: 請求書発行時の入金予定（未確定入金）自動作成

- 日付: 2026-07-25
- 状態: 採用・実装済み
- 起点: ユーザーレビュー第8弾（「請求書を発行済みにしたら自動的に入金モジュールにもアイテムができる機能はどう思うか」→ 価値ありと判断し実装）

## 決定

請求書が**発行済み（issued）になった時点で、入金（receipts）に「未確定」の入金予定を1件自動作成**する。

- 金額 = 税込請求額、入金日 = 支払期限（予定日として仮置き）、方法 = 銀行振込、備考に自動作成の旨を明記。
- 「未確定」は従来どおり「消込仕訳が無い状態」——新しい状態列は追加しない。
- 経理は入金一覧の「未確定」を消込 ToDo として使い、入金日・金額を実額に直して「確定」するだけになる。
  消込漏れ（発行したのに入金記録が無い請求書）が構造的に見えるようになるのが最大の価値。

### 採用理由

- 売掛の消込経路は Receipt モジュールが唯一（銀行明細の一括起票は source_type='bank' の仕訳のみで
  請求書・売掛残高に触れない）ため、二重経路の衝突が無い。
- 入金一覧（ReceiptList）には消込状態フィルタが既にあり、「未確定」がそのまま作業キューになる。

## 実装

対象経路（請求書が issued になる全経路）:

| 経路 | 実装 |
|---|---|
| 手動「発行する」／「取消を戻す」 | `Invoice.CreatePendingReceipt()`（二重作成ガード付き） |
| 定期請求の実行（月額・年額） | `RecurringRun.CreatePendingReceiptFor()` |
| SES 精算の一括生成 | `SesBilling.CreatePendingReceiptFor()` |
| 検収からの請求書作成 | 下書き生成（2026-07-21 決定）のため対象外——発行ボタン経由でカバー |

整合のための同時変更:

1. **`Receipt.SumReceipts` は消込済み（仕訳あり）のみ数える**。未確定は「予定」であってまだ入金ではない。
   含めると残額自動セット・過入金ガードが未確定分だけ狂う。
2. **請求書の「下書きに戻す」「取消にする」のガードは消込済み入金のみブロック**
   （`HasConfirmedReceipts`）。未確定の入金予定は遷移時に**自動削除**する（`DeletePendingReceipts`）。
   「取消を戻す」では作り直す。下書きの削除ガードは従来どおり全入金でブロック（孤児予防）。
3. **既存データ**: 発行済みなのに入金記録ゼロの請求書 5 件に入金予定をバックフィル
   （`Designer/temporary/backfill_pending_receipts.sql`。新規 DB では全請求書がアプリ経由で発行されるため不要）。

## 割り切り・注意

- 部分入金の2回目以降は従来どおり手動で入金を新規作成する（自動予定は「請求書に入金記録が1件も無い」
  ときだけ作る）。
- 入金日は支払期限の仮置きなので、**確定時に実際の入金日へ直すのが運用前提**（備考にも明記）。
- docs/tests/11（E2E シナリオ）の入金章は「入金を新規作成」する手順・期待値で書かれているが、
  本変更後は発行済み請求書に入金予定が既に存在する。手順は「未確定の行を開いて確定」に読み替えが必要
  （台帳の仕訳期待値自体は不変。シナリオ文書の改訂は次回に持ち越し・docs/05 に記録）。
