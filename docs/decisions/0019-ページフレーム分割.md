# 0019: ページフレーム分割による業務ドメイン別ナビゲーション

- 日付: 2026-07-09 ／ 状態: 採用・実装中 ／ 起票: ユーザー要望（「全モジュールが並列に並んでいて分かりにくい。カテゴライズしてページフレームを分けてほしい。設計から任せる」）

## 決定: 6 フレーム構成

| フレーム | 表示名 | アクセス（UserReadCondition） | 内容 |
|---|---|---|---|
| Main | ホーム | 全ロール（ルート・IsApplicationRoot） | ホーム／経費精算（申請・申請中・承認待ち・通知）／工数入力／各業務フレームへの入口 |
| SalesFrame | 販売管理 | 全ロール | 見積→受注→検収→請求→入金→売掛残高／定期請求（契約・実行）／SES精算・請求／取引先・案件マスタ |
| PurchasingFrame | 購買管理 | 経理・sysadmin | 仕入先請求書／支払予定表／振込データ作成／取引先口座 |
| AccountingFrame | 会計 | 経理・sysadmin | 仕訳（振替伝票・定型・入出金・インポート・固定資産）／帳簿（仕訳帳・元帳・出納帳）／帳票（試算表〜資金繰り予測）／銀行（取込・照合・口座・ルール）／会計年度 |
| ManagementFrame | 経営管理 | 承認者・経理・sysadmin | 予実対比・予算明細（承認者以上）／予算入力・人件費コスト・配賦・案件損益・工数管理（経理） |
| AdminFrame | システム管理 | sysadmin | ユーザー・部門・承認フローテンプレート・費目・勘定科目・科目表示区分・税率・税区分・経過措置・制度閾値 |

## 検討の経緯（ユーザーが挙げた論点への回答）

1. **経費精算は単独フレームにするか** → **Main に同居**させる。経費申請・承認・通知・工数入力は「全社員が毎日開く入口」で、ログイン直後のフレームに置くのが最短動線。フレームを分けると全社員が毎回 1 クリック余計に払う。逆に販売・購買・会計は「その業務の人が腰を据えて使う世界」なので独立フレームが適切。
2. **販売と経費精算を同居させるか** → させない。使う人が違う（営業 vs 全社員）し、販売は見積→入金の一連のワークフローで 9 画面あり、単独フレームの厚みがある。
3. **「財務」と「会計」を分けるか** → **分ける**。会計（AccountingFrame）＝記帳・帳簿・決算という「過去の記録」、経営管理（ManagementFrame）＝予算・予実・案件損益・原価配賦という「計画と分析」。業務としても担い手としても別物（記帳は経理、予実は部門長も見る）。ただし「財務」という名前は資金調達を連想させるため「経営管理」とした。資金繰り予測・月次推移は迷ったが、帳票群と同じデータ源（仕訳）の出力なので会計フレームの帳票に残した。
4. **マスタは 1 フレームに集中か、業務文脈に分散か** → **折衷**。法令・会社ルール由来の制度マスタ（ADR-0018 の sysadmin 管理群）は「システム管理」フレームに集中（触る人＝sysadmin が 1 箇所で管理）。業務マスタは使う文脈に配置（取引先・案件→販売、取引先口座→購買、会計年度・銀行口座・仕訳ルール・定型仕訳→会計）。「マスタはどこ？」には「その業務のフレームにある。制度はシステム管理」と答えられる構造。

## メニュー可視性の実現方式（①-3 と一体）

- **入口リンクの自動出し分け**: サイドバーのリンクは「遷移先モジュールの読取権限」に連動して自動非表示になる（実測済みの CLB 挙動）。Main に置く各フレーム入口リンクの Module を「そのフレームの代表画面」にすることで、**入口自体がロールに応じて消える**（例: 会計入口→振替伝票（経理+sys のみ）→ 一般・承認者には入口が見えない）。
- **フレーム直 URL のブロック**: フレーム自体の UserReadCondition で防ぐ（リンクが見えなくても URL を叩けば入れる、を防止）。
- **システム管理の入口**: 全員が読める AppUser 等を入口 Module にすると全員に入口が見えてしまうため、**表示専用モジュール AdminHome（読取= sysadmin）を新設**して入口とする（PatternShowcaseAuth の AdminFrame と同構図）。
- **予実対比・予算明細の閲覧範囲を「全ロール」→「承認者以上」に変更**: 旧 B-7 の「予算の透明性（全員閲覧）」を改め、一般社員には見せない（ユーザー指摘「一般に予算が見えるべきではない」）。部門長（承認者）の予算消化管理は業務なので承認者には残す。
- **予算画面の「No permission to read module」修正**: 原因は検索セレクトの参照先が権限ゲート付きモジュール（予実対比・予算明細の年度セレクト→ FiscalYear（経理専用）、予算明細の科目セレクト→ Account（経理専用））であること。**読み取り専用の Lookup モジュール（FiscalYearLookup・AccountLookup。読取ゲートなし・名称/コード程度の非機微列のみ）を新設**し、承認者以上が使う画面の検索セレクトはそちらを参照する。機微情報（期首残高・科目の設定詳細）は本体モジュールに留まり守られる。

## 影響・注意

- URL が変わる（例: `/Main/JournalEntry` → `/AccountingFrame/JournalEntry`）。docs/tests/06・09・11 の画面パス表記はタスク②で全面更新
- ホームのショートカット（振替伝票等）はフレーム跨ぎになるため AnchorTag に PageFrame を明示
- フレーム跨ぎのスクリプト遷移（NavigationService）は同一フレーム内に閉じるよう配置を設計済み（検収→請求書＝販売内、定型→伝票＝会計内、承認待ち→申請＝Main 内）
- 新規 PageFrame は IsApplicationRoot=false（Main のみ true）— CommonMistakes #54 の事故防止
