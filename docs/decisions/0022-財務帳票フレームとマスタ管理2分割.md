# ADR-0022: 財務帳票フレーム分離とマスタ管理の2フレーム化

- 日付: 2026-07-13
- 状態: 採用・実装済み（admin・一般ロールで実機確認済み）
- 関連: ADR-0021（フレーム再編第2弾）、ADR-0020（メニュー再構成第1弾）、ADR-0019（ページフレーム分割）

## 背景（ユーザーレビュー 2026-07-13 第4弾）

レビュー第3弾（7/12〜13・権限エラー根治ほか）の後、続けて 3 点の指摘を受けた。

1. **マスタが各フレームに散在して分かりにくい**（取引先/案件=会計、取引先口座=購買管理、制度マスタ=システム管理）。「マスタ管理（経理）」「マスタ管理（システム）」の 2 フレームに集約したい。マスタ管理（システム）は現「システム管理」の改名でよい
2. **取引先口座が admin でも新規作成できない**のはどうなっているのか（作成画面が別にある？）
3. **会計フレームが 24 項目と肥大**。帳票グループだけ毛色が違う（他は経理の作業メニュー、帳票は結果の閲覧）ので「財務帳票」フレームとして独立させたい

## 調査結果（指摘 2 への回答）

**取引先口座（PartnerBank）の新規作成不可はバグではなく設計**。PartnerBank は独立テーブルではなく、取引先マスタと同じ `partners` テーブルを見る別モジュール（口座列だけを編集する画面）で、`CanCreate: false` を明示している。行の作成は「取引先」マスタで行い、口座情報はその行に追記する形式。ただし画面上にその説明が無く「作成できない不具合」に見えるため、HeaderTitle に「口座は取引先マスタの行に追記する形式のため、この画面に新規作成はありません。取引先の追加は「取引先」から行ってください」を追記した。

## 決定

### 1. フレーム構成（8 → 10 フレーム）

| フレーム | URL | 入口が見えるロール | 中身（変更点のみ） |
|---|---|---|---|
| 会計 Accounting | /Accounting | 経理・sysadmin | **仕訳・帳簿・銀行・設定のみに縮小**（24→15 リンク）。帳票 8 本とマスタ 2 本を分離 |
| **財務帳票 Reports（新設）** | /Reports | 経理・sysadmin | 合計残高試算表（TOP）・貸借対照表・損益計算書・月次推移表・キャッシュ・フロー・株主資本等変動・消費税集計表・資金繰り予測。グループ接頭辞「帳票/」は廃止 |
| **マスタ管理（経理） Masters（新設）** | /Masters | 経理・sysadmin | 取引先（TOP）・案件（←会計から移設）・取引先口座（←購買管理から移設） |
| マスタ管理（システム） Admin | /Admin | sysadmin | 「システム管理」の**表示名のみ改名**（フレーム名/URL は Admin のまま）。中身は従来どおり |
| 購買管理 Purchasing | /Purchasing | 経理・sysadmin | 取引先口座が抜けて 3 リンク |

- Main のメニュー順: 経費精算・販売管理・購買管理・会計・**財務帳票**・予算管理・案件管理・**マスタ管理（経理）**・**マスタ管理（システム）**
- 新フレーム 2 枚の UserReadCondition は会計フレームと同一（accounting+sysadmin）。一般・承認者には入口ごと非表示（実機確認済み）

### 2. 分離・集約の線引き

- **帳票と帳簿は区別する**: 帳簿（仕訳帳・総勘定元帳・出納帳）は起票作業中に参照する道具なので会計に残す。帳票（財務諸表・集計表・予測）は結果の閲覧なので財務帳票へ
- **会計年度はマスタ管理に移さない**: 締め・再オープン・翌期繰越という決算「操作」を伴うため、純粋なマスタではなく会計の設定として残す
- **銀行の口座マスタ・仕訳ルールも移さない**: 明細取込ワークフロー（取込→明細→照合）と密結合のため銀行グループの一部として残す
  - **追記（同日レビューで一部変更）**: 口座マスタは「自社の銀行口座を編集する機会は実務上ほとんどない」というユーザー指摘を受け、**「自社口座」に改名してマスタ管理（経理）へ移設**した（取込ワークフローからは参照されるだけで、編集頻度はマスタ並みに低いため）。仕訳ルールは「明細を取り込みながら育てる」運用のため銀行グループに残置
- **勘定科目・税率等の制度マスタはマスタ管理（システム）のまま**: ユーザー指示どおり改名のみ（経理マスタとの再配分はしない）

### 3. 追随修正

- ホームのショートカット「月次推移表」「資金繰り予測」の遷移先を Accounting → Reports に付け替え
- Home.mod.cs の資金ショートアラート文言「帳票 > 資金繰り予測」→「財務帳票 > 資金繰り予測」
- AdminHome のタイトル・説明文を改名に追随（業務マスタの所在案内も「マスタ管理（経理）」に更新）
- docs/05・06・11 の旧メニューパス表記を一括更新（docs/decisions の過去 ADR は記録として旧表記のまま）

## 実装メモ

- PageFrame JSON の再編は PowerShell + System.Text.Json（JsonNode）のスクリプトで実施（既存 Link の DeepClone 改変・CommonMistakes #47 準拠）。ToJsonString(WriteIndented + UnsafeRelaxedJsonEscaping) が既存ファイルとバイト一致することをラウンドトリップで確認してから適用
- designcheck findingCount 0 → deploy → サーバ再起動（mod.cs 変更のため）→ ブラウザ実機確認（admin で 5 フレーム巡回・一般で入口非表示とホーム正常描画）

## 影響

- URL 追加のみで既存 URL の非互換なし（/Accounting/TrialBalance 等の旧 URL は消えるが、ブックマーク互換より整理を優先する方針は ADR-0021 で確立済み）
- フレーム数 10 枚。「リンクの出し分けはフレーム隔離でしか制御できない」という CLB の制約（ADR-0021 §8）のもとで、マスタの所在が「経理のものはマスタ管理（経理）、制度のものはマスタ管理（システム）」と一意に説明できるようになった
