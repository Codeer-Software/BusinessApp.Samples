# 0033: 自動生成請求書の「発行を取り消す」と入金フローの一本化

- 日付: 2026-07-25
- 状態: 採用・実装済み
- 起点: ユーザーレビュー第8弾の追加検討（「定期実行で作った請求書の取り消し方が赤黒訂正しかないのは仕様としてどうか」
  「入金の手動新規作成・削除はもう不要では」）。仕様は問いかけ→回答→ユーザー GO の手順で確定

## 決定1: 定期・SES 生成請求書に「発行を取り消す」（生成物の一括削除）

定期請求・SES 精算で自動生成された請求書（invoice_source = recurring / recurring_annual / ses）に、
経理向けの「発行を取り消す」を新設する。**下書きに戻すのではなく削除**——「定期請求の実行」の
冪等ガードは「契約×対象月の請求書の存在」で判定しているため、削除すれば正しく「未生成」に戻り、
再実行で作り直せる。

- **ガード**: 消込済み入金なし／関連仕訳（月額・SES=売上仕訳、年額=前受計上＋**全按分振替**）の期間が
  すべて未締め。1つでも締め済みなら拒否し、赤黒訂正＋「取消にする」（決定2）を案内する。
- **動作**: 関連仕訳（明細→親の順に物理削除）→ 未確定の入金予定 → 請求書本体（明細は DeleteTogether）
  の順に削除し、一覧へ戻る。
- 生成分では「下書きに戻す」を非表示にする（常にエラーになるボタンを見せない）。
  手作成・検収由来（draft 生成→手動発行）の請求書は従来どおり「下書きに戻す」。
- 未締めなら仕訳ごと消してよい、という判断は入金の取消・検収の確定取消と同じ流儀（アプリ内で一貫）。

## 決定2: 按分振替は「アンカー請求書が void でない」ことを生成条件に追加

按分振替（recurring_defer）は「年額請求書レコードの存在」をアンカーに毎月生成されており、
従来は**請求書の状態を見ていなかった**（void にしても按分が止まらない）。生成条件に
「アンカーが void でない」を追加し、**期間が締め済みで決定1が使えない場合の停止手段**として
void を位置づける（過去分は赤黒訂正、以後の按分は void で停止）。

## 決定3: 入金の手動新規作成・未確定削除の廃止

入金予定は「請求書の発行時」（ADR-0032）と「一部入金の確定時」（決定4）に自動作成されるため、
手動の新規作成が担う実務ケースが消えた（過入金・請求書前の前受金は振替伝票の領分、
相殺・現金は予定行の「方法」を編集すれば足りる）。

- 入金一覧の「新規作成」ボタンを撤去。新規 URL 直打ちは一覧へリダイレクト。
- 未確定の削除ボタンも撤去。予定の削除が正当に必要なのは請求書側の巻き戻し・取消だけで、
  それはスクリプトが自動で行う（モジュールの削除能力は温存・UI だけ廃止）。
  「誤って予定を消して復活できない」問題も根本から消える。

## 決定4: 一部入金の確定時に残額分の入金予定を自動作成

確定の結果 partial になったら、残額（税込請求額−消込済み合計）の未確定入金を自動作成する
（未確定行が残っている場合は作らない）。これにより不変条件
**「未回収の発行済み請求書には、常に残額分の未確定予定がちょうど1件ある」**が成立し、
入金一覧の「未確定」＝消込 ToDo が漏れなく完全になる。

- 既存データ: partial の INV-26-002 に残額 820,000 円の予定をバックフィル
  （`Designer/temporary/backfill_partial_remainder.sql`）。

## 追補（2026-07-26）: 入金取消時の入金予定の統合

決定4の導入で「確定は残額予定を作るが、取消は残額予定を畳まない」という非対称が残っており、
確定→即取消で未確定が2行（取消で戻った行＋残額予定）に割れることがユーザー実測で判明。
「入金を取り消す」の仕訳削除・請求書ステータス再計算の後に統合ステップを追加した:

1. 同じ請求書の**他の**未確定予定をすべて削除
2. 取消で未確定に戻った**本人の行の金額を現時点の残額**（税込請求額−消込済み合計）に更新し、
   備考を「取消により残額の入金予定に戻りました」に差し替え
3. トーストで「入金予定を残額 N 円に統合しました」と明示

これで確定・取消をどの順で繰り返しても「未確定はちょうど1行＝残額」に収束する（不変条件の完全化）。
複数確定（10M＋20M 消込済＋3M 予定）から1本目を取消 → 3M 削除・本人が 13M（33M−20M）に統合、
消込済み 20M と partial 状態は不変、を実機検証。統合機能導入前に発生していた INV-26-014 の
2行状態は SQL で統合済み（`Designer/temporary/consolidate_inv014_pendings.sql`）。

## 検証（DB バックアップ→復元方式・デモデータ無汚染）

発行取消（月額）→仕訳・予定・請求書の全削除、定期実行での再生成（年額=前受計上＋按分＋予定）、
年額 void →翌月実行で按分スキップ（有効な他契約の按分・月額は正常生成）、
部分確定（165,000→100,000）→残額 65,000 の予定自動作成＋partial 遷移、
入金一覧の新規作成なし・未確定詳細の削除ボタンなし、を実機確認。
