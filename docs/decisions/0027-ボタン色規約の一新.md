# ADR-0027: ボタン色規約の一新（青=前進／赤=取消・削除の2色体系）

- 日付: 2026-07-19
- 状態: 採用・実装済み（全83ボタンへ一括適用）
- 関連: ADR-0021（旧・型別幅規約）、docs/tests/13 U4-1（ボタン色の初見指摘）

## 背景（ユーザーレビュー 2026-07-19）

「灰色ボタンと青色ボタンの使い分けが分からない。灰色は押してはいけないのかと思う。使い分けをユーザーが理解できないなら分けるべきでない」との指摘。実態調査でも Primary 46 / Secondary 19 / Info 6 / Success 5 / Danger 3 / Warning 2 と6色が混在し、同じ「保存」が見積では青・検収では灰という不整合があった（歴史的経緯の堆積で体系なし）。

## 決定: 3値だけの規約

| Variant | 意味 | 例 |
|---|---|---|
| **Primary（青）** | 前進アクション。押すことが業務の前進として期待される操作すべて | 保存・登録・確定・起票・生成・申請・承認・複製・出力・開く |
| **Danger（赤）** | 元に戻しにくい/巻き戻す操作。削除・却下・取消・状態の巻き戻し | 削除・却下・申請キャンセル・プレビュー取消・確定取消（ADR-0026 の逆遷移ボタン群） |
| **Secondary（灰）** | **ダイアログのキャンセル・閉じるのみ**（業務アクションには使わない）。現状の画面ボタンでは未使用 | （MessageBox 内など将来用） |

- Info / Success / Warning / Light / Dark / Link は**廃止**（今後も新設時に使わない）
- 「操作の重要度」や「主・副」の区別は色で表現しない。1画面に青が複数並ぶことは許容する（ユーザーが判断に迷わないことを優先）

### 押せないボタンの表現

- 条件未達で無効なボタンは、原則 **(a) 非表示にして理由をラベルで示す**か、**(b) アクション色のまま半透明で無効化**する
- (b) の視覚は app.css で統一: `opacity: .45` + `cursor: not-allowed`（Bootstrap 既定の .65 より薄くし、ソリッドな灰色＝キャンセルとは別物に見せる）
- 「押せるのに必ずエラーになる」状態を作らない（例: 検収の請求書作成済みなら、ボタンを消して「作成済み＋リンク」を表示する。ADR-0026）

## 適用結果（2026-07-19 一括適用）

- 全 83 ボタンを Primary 79 / Danger 4（この下書きを削除・却下・申請キャンセル・プレビュー取消）に整理
- 一括適用スクリプト: temporary/apply_variants.ps1（Text をアンカーに Variant を書き換え・冪等ではないので再実行不可、以後は本規約に従って手で設定）
- AppUser の SubmitButton 表記 "Submit" → 「登録」も同時に是正

## 却下した代替案

- **主ボタン=青／副ボタン=灰の従来型**: 「灰=押すべきでない」という誤解をユーザーに与えることが実地で確認されたため不採用
- **Success/Warning による意味分け**: 「緑=完了系」「黄=注意系」は作り手の意図であってユーザーの読解と一致しない（初見UXテストでも読解されなかった）
