# ADR-0051: 帳票の入金集計は「消込済み」だけ・手入力の消費税額を検算する

- 日付: 2026-08-12
- 状態: 採用
- 関係: ADR-0032（請求書発行時の入金予定の自動作成）・ADR-0033（入金の手動新規作成の廃止）・
  ADR-0003（消費税の持ち方）・`docs/issues/2026-08-09_体験シナリオ執筆中に見つかった改善候補.md` A-2 / A-3 / A-4

## 背景

体験シナリオ執筆時のコード精読で見つかった 3 件（A-2 / A-3 / A-4）を、ユーザーと仕様を合意したうえで修正した。
A-2 は帳簿の数字が誤って見える不具合、A-4 は誤った税額がそのまま仕訳になる穴で、いずれも
「市販の会計ソフト以上」を掲げる以上は看過できない。

## 決定 1: 帳票の入金集計は「消込済み（消込仕訳がある）入金」だけを数える

**「入金が確定したかどうか」の唯一の表現は `journal_entries(source_type='receipt', source_id=receipt.id)`
の存在である**（`receipts` に状態列は無い）。この規約自体は ADR-0033 で確立済みで、
`Receipt.mod.cs` の `SumReceipts()` と `ReceiptList.Query.sql` は元からこの流儀だった。
取り残されていた 3 帳票を同じ流儀に揃える。

| 直した箇所 | 症状（修正前） |
|---|---|
| `Sales/ReceivableBalance.Query.sql` | 発行しただけの請求書が「入金済・残額 0」。既定フィルタ（入金済を除く）から消える |
| `Management/CashFlowForecastData.Query.sql` | 未回収額が常に 0 になり、**入金予定が構造的に 0 円** |
| `Shell/PortalAlertData.Query.sql`（2 か所） | 「期限超過の売掛」が常に 0 件・資金ショート判定も入金を織り込まない |

原因は共通で、**請求書の発行時に税込全額の未確定入金＝入金予定が自動作成される**（ADR-0032）ため、
`receipts` の単純合計が「請求額と同額」になってしまうこと。

デモ DB での実測（修正前 → 修正後）:

- 売掛残高一覧（既定検索＝入金済を除く）: **0 件 → 9 件**（未回収 8,432,000 円）
- INV-26-002: 「入金済」→ **一部入金・入金済 500,000・残額 820,000**
- 資金繰り予測の入金予定: **0 円 → 2026-08 に 5,957,000 円・2026-09 に 2,475,000 円**

### 付随: インデックスの追加

存在判定（EXISTS）が 3 帳票に増えるため `journal_entries(source_type, source_id)` に
インデックスを追加した（`Designer/ddl/480_journal_source_index.sql`）。
スクリプト側の「この伝票から生成された仕訳」検索にも同じインデックスが効く。

### 採らなかった案

- **売掛残高に「入金予定」列を足す**: 足さない。売掛残高一覧は帳簿の売掛金残高と一致すべきで、
  予定は入金一覧の「未確定」で見るのが筋（2026-08-12 ユーザー判断）
- **`receipts` に状態列を持たせる**: 確定・取消のロジック全体が二重管理になる。得るものが無い

## 決定 2: 経費申請の件名を必須にする

`ExpenseRequest.Title` を `IsRequired: true` にする。空件名は承認依頼の通知本文・仕訳摘要・
固定資産の自動登録名にそのまま流れ、帳簿と台帳に穴が残るため。
見積・請求書の件名は元から必須で、**経費だけが例外だった**——揃えるだけの変更である。

- CLB の `IsRequired` は保存全般に効くので、**下書き保存の時点から件名が必須**になる（合意済み）
- スクリプトから `IsRequired` は変更できない（CommonMistakes #5）ため、状態別の出し分けはしない
- 既存 14 件に空件名は無く、データ移行は不要（実測）

## 決定 3: 手入力の「うち消費税」を検算する

経費申請の「うち消費税」は、入力があれば税率からの計算値より優先される（レシート記載額を尊重する設計）。
この設計は維持しつつ、**明白な誤りだけ止め、疑わしいものは警告して通す**。

| 条件 | 挙動 |
|---|---|
| 負値 | エラー（申請・実費確定を止める） |
| 税額 ≧ 金額（税込） | エラー（同上） |
| 税率からの計算値と **±10%** を超えて乖離 | 警告のみ（申請は通る） |
| 上記以外 | 何もしない |

- **許容幅を ±10% にした理由**: 桁ミス（10 倍・1/10）は確実に捕まえ、軽減税率や非課税品が
  混ざった実レシートの端数ブレは通す帯だから。固定額（±10 円など）では誤警告が多発する。
  理論値が小さい少額レシート向けに、許容幅の下限を 1 円としている
- **閾値をマスタ化しない理由**: 利用者が調整する類の値ではないため、スクリプト内の
  `GetTaxDiffTolerancePercent()` に置く（2026-08-12 ユーザー判断）
- **判定するタイミング**: 「うち消費税」入力時・金額変更時・AI 読み取り完了時（気づかせる）と、
  申請時（`ValidateForApply`）・実費確定時（`ConfirmActual_OnClick`）（止める）。
  仕訳になるのは実費なので、事前申請の実費確定も対象にする
- **不課税・非課税の費目では「うち消費税」欄を隠し、入力済みの値もクリアする**。
  隠すだけだと仕訳では無視される値が DB に残るため。値が消えることは通知する（驚き最小）。
  **費目が未選択のうちは欄を出す**——入力順を縛らない

## 実機検証（2026-08-12・soumu_bucho）

| 確認項目 | 結果 |
|---|---|
| 売掛残高一覧（入金済を除く） | 9 件表示・INV-26-002 が一部入金/残額 820,000 |
| 資金繰り予測 | 入金予定 5,957,000（2026-08）/ 2,475,000（2026-09） |
| ポータルのアラート | 期限超過の売掛 0 件（デモ DB の支払期限は全件が未到来のため正しい） |
| 経費申請の件名 | 必須マーク表示・空のまま申請すると「必須項目です」で止まる |
| うち消費税 10,000 円（税込 11,000 円・10%） | 「計算値 1,000 円と離れています」と警告（申請は可能） |
| うち消費税 1,000 円（同上） | 警告なし |
| うち消費税 11,000 円 ≧ 金額 10,000 円 | エラー表示・申請が進まない（DB に行が作られないことも確認） |
| 費目を「諸会費」（不課税）に変更 | 欄がラベルごと消え、入力済み 11,000 円のクリアを通知 |
