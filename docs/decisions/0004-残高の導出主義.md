# 0004: 残高は仕訳から導出（残高キャッシュを持たない）

- 状態: 採用 / 日付: 2026-07-05

## 背景
元帳・試算表・BS/PL のために科目別残高をどう得るか。残高テーブルを更新し続ける方式は高速だが、仕訳とズレるリスク（二重管理）を抱える。

## 選択肢
1. **導出主義**: 残高＝期首残高（opening_balances）＋期中仕訳の都度集計。残高テーブルなし ← 採用
2. 残高キャッシュ: account_balances を仕訳保存のたび更新
3. 月次サマリテーブル: 締め時に月次残高を確定保存

## 決定
選択肢1。残高が必要な帳票はすべて SQL（QueryField）で journal_lines を集計して導出する。唯一の保存残高は年度の期首残高（opening_balances、符号付き: 借方残=正）。

## 根拠
- **正しさが構造的に保証される**（仕訳が唯一の真実。キャッシュ不整合というバグクラスが消える）。
- 規模的に十分速い: ペルソナは年間仕訳 3,000〜4,000件×行数倍程度。SQLite の単純集計で余裕（インデックス: journal_lines(account_id), journal_entries(entry_date, status)）。
- 実測で遅ければ後から月次サマリ（3）を「締め済み期間のみ」追加する逃げ道があり、その場合も締め済み期間は不変なので整合が壊れない。

## 影響
- 帳票 SQL は常に `status='posted'` のみ集計、期首残高との合算を含む共通パターンを確立する。
- 大量データデモ（2期分）でパフォーマンス実測を行う（進捗台帳のフェーズ A 検証項目）。
