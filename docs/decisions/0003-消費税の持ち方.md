# 0003: 消費税＝明示税行方式＋期間管理マスタ

- 状態: 採用 / 日付: 2026-07-05

## 背景
税抜経理方式（ペルソナの実務）では、費用/収益は本体額で計上し消費税は仮払/仮受消費税で持つ。税をどうデータに持たせるかで帳票の複雑さが大きく変わる。また 2026-07 時点のリサーチで、インボイス経過措置の4段階化（80/70/50/30%）や食料品税率1%案など**税制が動き続ける**ことを確認済み。

## 選択肢
1. **明示税行方式**: 保存時に仮払/仮受消費税の仕訳行をシステムが自動生成（is_tax_line=1、parent_line_no で元行に紐付け） ← 採用
2. 行内包方式: 明細行に税込金額＋税額を持ち、帳票側で毎回本体/税を分離計算
3. 転記時分離方式: 入力は税込のまま、月次でまとめて税振替仕訳を起こす

## 決定
選択肢1。ユーザー入力は「金額（内税/外税）＋税区分」で、税行はシステム管理（直接編集不可・元行変更で再生成。端数調整は税額上書き→再生成で対応）。税率・税区分・経過措置控除割合は期間付きマスタ（tax_rates / tax_categories / invoice_transition_rates）。

## 根拠
- 明示税行なら**元帳・試算表・BS/PL が「行の単純合計」だけで常に正しい**。行内包方式（2）は全帳票に税分離ロジックが漏れ出し、バグの温床になる。
- 月次一括（3）は月中の試算表が不正確になり「リアルタイムに見える」という訴求に反する。
- 期間付きマスタは、経過措置の 2026-10 切替（80→70%）をデータだけで越えられることをデモで示せる（「税制改正に設定で追随」の実証）。

## 影響
- 税行の生成・再生成・削除追随のスクリプトが仕訳入力の中核ロジックになる（フェーズ A-4 の最重要実装）。
- 免税事業者からの仕入は「控除可能分のみ仮払消費税、残りは本体上乗せ」を自動計算（取引日で控除割合を期間解決）。
- 端数処理は切り捨てを既定とし、丸め方法をマスタで変更可能にする。
