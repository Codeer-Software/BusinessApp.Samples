# 0013: 銀行明細の取込 UI＝CSV 貼り付け方式（ファイルアップロードは将来拡張）

- 状態: 採用 / 日付: 2026-07-06

## 背景

D-2（ADR-0012）の取込の入口として、銀行 CSV をどう受け取るかの選択。CLB の実事実として: ①CLB に CSV 取込機能は存在しない（一括入出力は Excel 専用・列形式も CLB 独自）②`FileField` のアップロード内容をスクリプトから汎用にパースする経路も無い ③スクリプト（C# ライク）は文字列操作・ループ・`int.Parse` 等が使える。

## 選択肢

1. **複数行テキストフィールドに CSV を貼り付け → CLB スクリプトでパース**
2. FileField アップロード → サーバ C# 拡張でパース（Shift-JIS 対応可）
3. Excel 一括アップロード（CanBulkDataUpdate）に載せる

## 決定

**選択肢1（貼り付け方式）を採用。** パースは `BankImport.mod.cs` のスクリプトで行う（引用符内カンマ対応の CSV 分割・日付/金額の正規化・ヘッダ行自動スキップ）。

## 根拠

- ミッション §2「C# に逃げる前に CLB で本当に無理か確認する」——貼り付け＋スクリプトパースは**完全に CLB の土俵内**で成立し、「ノーコード率」の訴求を守る。サーバ C# は AI 科目推定（LLM 呼び出し＝正当な C# 領域）だけに限定できる
- 文字コード問題の回避: 銀行 CSV は Shift-JIS が多いが、ユーザーがエディタ/メモ帳で開いてコピーする時点でテキスト化されるため、貼り付けなら文字化けしない（ファイル UL だとサーバ側で SJIS/UTF-8 判定が必要）
- 明細は月あたり数十〜百行程度で、貼り付け UI の実用性は十分

## 影響

- ファイル UL（サーバ C# で SJIS 判定＋パース）は**将来拡張としてバックログ**（実装する場合も ステージング以降の流れは共通）
- 列形式は「日付, 摘要, 出金額, 入金額, 残高」を標準とする（主要行の CSV と同型。列マッピング設定のマスタ化は将来拡張）
- **既に帳簿計上済みの取引（入金消込・経費支払など他機能が起票したもの）は、明細側を「対象外」にする運用**。既存仕訳との自動突合（マッチング消込）は v1 スコープ外＝バックログ
