# ADR-0053: 内部振替の税区分を明示する／入出金起票で消費税行を生成する

- 日付: 2026-08-13
- 状態: 採用
- 関係: ADR-0052（税区分未設定の廃止と消費税集計表の作り直し。**本 ADR で原因分析を訂正する**）・
  ADR-0003（消費税の持ち方）・`docs/issues/2026-08-09_*.md` B-7

## 決定 1: ADR-0052 の原因分析を訂正する

ADR-0052 決定 2 で「減価償却の貸方に課税仕入 10% が付いた原因は `ddl/490` の穴埋め」と書いたが、
**これは誤りだった。** 実データで確認したところ:

- 移行前に税区分が `NULL` だった 91 行の一覧に**工具器具備品は含まれていない**
- `FixedAsset.mod.cs` は税区分を一切セットしていない

つまりその税区分は移行の前から入っていた。**真因は `Lines_OnDataChanged` →
`ApplyLineDefaults()` が、スクリプトで作った `JournalEntry` にも発火して
勘定科目マスタの既定税区分を自動で入れること**である。

この訂正には実務上の意味がある。ADR-0052 決定 2 は「各経路は税に意味のある行に税区分を明示し、
**明示されなかった行は対象外になる**」という前提に立っていたが、その前提が成り立っていない。
`MarkRemainingLinesOutOfScope()`（NULL を対象外で埋める）は**実際にはほぼ no-op** で、
`ddl/520` で既存データを直しても**新しい減価償却仕訳を作れば同じ誤りが再発する**状態だった。

### 対応

**内部振替の仕訳は、科目の既定に任せず明示的に「対象外」で上書きする。**

- `JournalEntry.MarkAllLinesOutOfScope()` を新設（全非税行の税区分と入力区分を上書き）
- 使うのは減価償却（`FixedAsset`）と前受収益の按分振替（`RecurringRun`）。
  どちらも消費税は元の取引の時点で確定しており、常に対象外が正しい
- `MarkRemainingLinesOutOfScope()` は**保険**として全経路に残す
  （税区分は `NOT NULL` なので、万一 NULL のまま来たときに DB エラーで落ちるのを防ぐ）

**実機検証**: 検証用の固定資産を作って第18期の償却仕訳を生成 →
減価償却費・工具器具備品とも「対象外」（工具器具備品の科目既定は課税仕入 10%）。
修正前ならここに課税仕入が入り、消費税集計表を狂わせていた。

> **一般化した教訓**: CLB では `OnDataChanged` がスクリプト生成のモジュールにも発火する。
> **「値をセットしない」は「既定が入らない」を意味しない。** 既定と違う値にしたいなら明示的に代入する。

## 決定 2: 入出金起票で消費税行を生成する（改善候補 B-7）

入出金起票は「税行なし・課税取引は振替伝票から」という設計だったが、**相手科目の候補は全科目**で、
有効 73 科目のうち **28 科目（課税仕入 22・課税売上 6）が課税科目**。会議費 3,300 円を現金で
払って入力すると `会議費 3,300 / 普通預金 3,300` になり、以下が同時に誤っていた。

| 誤り | 影響 |
|---|---|
| 会議費（費用）が 300 円過大 | 損益計算書・試算表 |
| 仮払消費税が 300 円不足 | **納税額が 300 円過大**（払いすぎる） |
| 課税仕入の本体が税込で載る | 消費税集計表 |

**この誤りは入出金起票が作られたときから存在していた**（ADR-0052 で税区分が付くようになり、
消費税集計表にも現れるようになって顕在化した）。案内文だけが唯一のガードという状態だったので、
見せ方ではなく**記帳そのものを正す**。

- 相手科目の既定税区分が課税（`taxable_sales` / `taxable_purchase`）なら、その行を**内税**として扱い、
  `Submit()` の直前に `je.GenerateTaxLinesOnce()` を呼ぶ
- **外税は使わない**。外税だと本体行が税込のまま税行が増えて貸借が崩れる。
  この画面の金額は「実際に動いた現預金の額」＝税込なので内税が正しい
- 非課税・不課税・対象外の相手科目は従来どおり 2 行のまま（`RegenerateTaxLines` が課税種別で弾く）
- 結果表示とトーストに「うち消費税 n 円」を併記する。費用の金額が入力額より減るのは驚きになるため

### 採らなかった案

- **相手科目の候補を非課税・不課税・対象外に絞る**: 「会議費を現金で払った」というごく普通の取引が
  この画面で永久に処理できなくなる。CLB の SearchCondition は関連先の関連先
  （`accounts` → `tax_categories.taxation_type`）を条件にできず、導出列の追加も要る
- **課税科目を選んだら警告を出すだけ**: 止めないので誤った仕訳が残る。
  ADR-0051 で「明白な誤りはエラーで止める」を選んだのと同じ理屈で、警告だけのガードは効かない

### 網羅チェックで確認したこと（デグレ・仕様漏れ）

| 観点 | 結果 |
|---|---|
| 貸借バランス | 税行は本体行と同じ側に付き、本体は税抜に減るので合計は不変（実測 3,300 = 3,300） |
| 税行の二重生成 | `RegenerateTaxLines` は**入力額のまま 1 回だけ**呼ぶ前提。`SaveEntry` が「税行の生成は確定時のみ」にしているのと同じ理由（税抜化済みに再適用すると二重税抜化）。入出金起票は下書きを経ずに確定するので順路は 1 本 |
| 定型仕訳（同型の疑い） | **問題なし**。下書きを作るだけで、税行は利用者が確定した時点で `SaveEntry` が生成する |
| 経過措置 | 控除できない分は本体に残る形で `RegenerateTaxLines` が処理する。なお経過措置を既定にしている科目は 0 件 |
| 非課税科目 | `RegenerateTaxLines` が課税種別で弾くため 2 行のまま。受取利息（非課税売上）は従来どおり拾える |
| 既存データ | 影響なし（新規起票のみに効く。移行不要） |

## 補足: 改善候補 B-1〜B-4（ADR 不要の小修正・同日実施）

- **B-1**: 起票をブロックする締め済みメッセージを「{日付項目名}の期間は締め済みです」に統一
- **B-2**: 経費精算のトーストに、費目名ではなく実際に記帳される勘定科目名を出す
  （異なるときだけ「消耗品費（費目: 印刷製本費）」と併記）
- **B-3**: 外税の行があるとき、差額欄の右に「（確定時に消費税 n 円が追加されます）」を出す
- **B-4**: 領収書未添付の警告文から、実行できない「後から添付するか」を削る
