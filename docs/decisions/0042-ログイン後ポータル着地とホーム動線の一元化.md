# ADR-0042: ログイン後は業務ポータルに着地 — 権限別自動転送と「ほかの業務」リンクの廃止

- 日付: 2026-08-02
- 状態: 採用（実装・全権限プロファイルで実機検証済み）。
  **導線の UI は ADR-0045 が改訂**（ポータル中央のタイルボタン → Main 左サイドバー PortalSidebar へ一本化。
  「全員ポータル着地」「業務切替の一元化」の芯は本 ADR のまま）
- 関係: ADR-0040/0041（部品アーキテクチャ・権限モデル）の上に載る導線刷新。ADR-0028（ロール別ホーム転送）を置換

## 背景

部品アーキテクチャ再編（ADR-0040）後のログイン導線は「ルートフレーム Main に着地 → `RoleDispatch` が
管理者→経理→承認者→営業→一般 のハードコード優先順位で 1 フレームを選んで自動転送」だった。
ユーザーレビュー（2026-08-02）で次の指摘を受けた:

1. **非直感的**: ログイン直後は「自分が見られる業務（部品）へのリンクが並ぶ」姿を期待する。
   複数権限者がなぜそのフレームに落ちたのか説明されない
2. **階層の抽象度が混在**: サイドバー第 1 階層に「仕訳」等の*ページ*と「ほかの業務/会計」等の
   *フレームそのもの*が同居し、粒度が揃っていない
3. **「ほかの業務」が分かりにくい**: 他部品への入口がサイドバーの一項目に埋まっている

P6 で「全部品参照ハブ Home」を解体した理由は*モジュール型参照*による部品依存違反であり、
**URL 遷移のみのリンク専用ポータルには適用されない**（Go*Btn 方式は docs/10 §4-6 で容認済み）。
自動転送を維持する積極的理由は消えていた。

## 決定

1. **全員が業務ポータルに着地する**（折衷案＝単一権限者の直行はユーザー判断で不採用。挙動の一様性を優先）。
   `RoleDispatch` を `PortalHome`（Shell 部品）に改名し、自動転送をやめて
   **アクセスできる部品のタイル（ボタン）だけを表示**する。判定は AppUser のキャッシュ列のみ・遷移は URL のみ
2. タイルの単位は **7 部品＋システム管理**（14 フレームではない）。クリック時に変種を解決する
   （経理 > 承認者 > 一般 の順。例: 経費精算 → 経理は ExpenseAccounting／承認者は ExpenseApprover／他は ExpenseStaff）
3. **Main 以外の全 13 フレームのサイドバー先頭に「ホーム」リンク**（→ Main/PortalHome）を置く。
   既存の部品トップリンク「ホーム」は「トップ」に改名（第 1 階層 = 業務の選択、第 2 階層 = 業務内のページ、と抽象度を統一）
4. **「ほかの業務/○○」リンクは全フレームから撤去**。ExpenseHome / SalesHome の「ほかの業務」切替ボタン群も撤去
   （業務の切替はポータルに一元化。分散していた変種解決ロジックの重複も解消）

### タイルの表示条件（PortalHome.mod.cs が唯一の正）

| タイル | 表示条件 | 遷移先（変種解決） |
|---|---|---|
| 経費精算 | 管理者以外（全社員機能・admin には導線を出さない） | ExpenseAccounting／ExpenseApprover／ExpenseStaff |
| 工数管理 | 管理者以外（同上） | TimesheetAccounting／Timesheet |
| 営業業務 | 営業 or 経理 | SalesBilling／SalesStaff |
| 会計 | 経理 | Accounting |
| 購買・支払 | 経理 | Purchasing |
| 経営管理 | 承認者 or 経理 | ManagementFull／ManagementApprover |
| 業務マスタ | 経理 | MasterBusiness |
| システム管理 | システム管理者 | MasterAdmin |

## 実装上の実測知見（回避策込み）

- **表示専用モジュールの Detail ではボタンが `pointer-events:none` で描画されクリック不能になる**
  （エラーなしの静かな失敗）。`Detail_OnAfterInit` で `IsViewOnly = false;` を明示して解除（FB-035）
- **`IsVisible=false` のフィールドは固定幅カラムが空のまま残り、タイル間に 150px の空白が生じる**。
  app.css の `[data-module="PortalHome"] .grid-column:not(:has(.field-layout)) { display: none; }` で
  空カラムを畳んで解消（FB-037）
- `rename-module` は PageFrame の `TopPageModuleDesign.Module` は追従するが**レガシー併記の
  `TopPageModule` プロパティを追従しない**（designcheck では検出されず、手修正した。FB-036）
- タイルは ADR-0027（ボタン 2 色規約）に従い Primary（青）。灰色はボタンに使わない

## 影響

- E2E・体験シナリオ文書の「ほかの業務/○○」経由の遷移手順は「ホーム → ポータル → ○○」に読み替え
  （docs/tests/19 読み替え表に追記。文書本文の全面改訂は持ち越し）
- docs/10 §2（着地）・§5（相互接続）・§6（カスタムポイント）・§7（実装規約）を本 ADR に追随
- 新フレーム追加時の手順が「7 フレームの『ほかの業務』に追記」から
  「PortalHome にタイル 1 個（＋新フレーム先頭にホームリンク）」に簡素化
