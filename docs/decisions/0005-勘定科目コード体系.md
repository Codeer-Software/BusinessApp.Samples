# 0005: 勘定科目コード＝4桁・フラット＋表示区分

- 状態: 採用 / 日付: 2026-07-05

## 背景
科目マスタの構造（階層 vs フラット）とコード体系を決める必要がある。BS/PL の組み上げ、ユーザーの科目追加、市販ソフトからの移行感覚に影響する。

## 選択肢
1. **フラットな科目＋表示区分マスタ（account_categories）参照、4桁コード** ← 採用
2. 科目自体を親子階層にする（集計科目レコードを持つ）
3. 弥生互換のコード体系をそのまま採用

## 決定
選択肢1。科目はフラット、BS/PL の見出し・並び・小計は account_categories（表示区分マスタ）が持つ。コードは 1000=資産〜9000=税金等 の4桁帯域制（詳細は `04_会計ドメイン設計.md` §2.1）。

## 根拠
- 階層科目（2）は集計科目への誤仕訳防止・移動時の再帰処理などコストが高い。帳票の見出しは「帳票の関心事」であり、表示区分マスタに分離する方が責務が明確。
- 4桁帯域制は中小の実務・市販ソフトの慣行（数字帯で資産/負債…が直感的に分かる）に沿い、間に科目を挿入する余白も十分。
- 特定製品互換（3）に縛られる必要はない。デモの説明しやすさを優先。

## 影響
- 帳票の段階利益（売上総利益・営業利益・経常利益…）は区分の並びから機械計算するため、account_categories の section_order 設計が帳票仕様を兼ねる。
- プリセット科目（100科目前後を想定）の seed SQL をフェーズ A-1 で作成する。
