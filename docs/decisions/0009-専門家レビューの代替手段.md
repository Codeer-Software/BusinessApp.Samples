# ADR-0009 専門家レビューの代替手段

## 状況

検討メモ（`05_会計コア・正確性・品質保証`）は品質ゲートに「税理士・公認会計士が承認したゴールデンケース」
を置いている。しかし本プロジェクトでは**専門家のレビューを受けられる見込みがない**。

一方で目標は「他の会計ソフトの代替として通用する会計コア」であり、正しさの根拠は必要である。

## 決定

専門家レビューの代わりに、**公表されている一次情報の設例を期待値の根拠とする**。
根拠のない期待値をテストに書かない。

### 期待値の根拠として認めるもの（優先順）

1. **国税庁が公表する設例・記載例・パンフレット・一問一答の計算例**
   （消費税の端数処理、経過措置の計算例、少額特例の判定例など）
2. **法令・告示の条文そのもの**（e-Gov）から機械的に導ける値
   （税率、控除割合の段階、閾値、保存期間）
3. **会計基準・適用指針の設例**（企業会計基準委員会、中小企業の会計に関する基本要領）
4. **複式簿記の公理から導ける不変条件**（貸借一致、残高＝仕訳の集計、繰越の整合）
5. **算術的に検証可能な性質**（集計順序を変えても結果が変わらない、取消と再計上で元に戻る）

### テストの書き方の規約

- **ゴールデンテストには必ず出典を書く。** 期待値のそばに「どの資料の何番の設例か」「確認日」を残す。
  出典を書けない期待値は、その場で考えた値である可能性が高い
- **不変条件は性質テストで網羅する**（1 〜 5 のうち 4・5）。個別の設例で拾えない組み合わせは、
  性質テストが受け持つ
- **差分テストを併用する。** 同じ帳簿を 2 通りの経路で計算して突き合わせる
  （例: 試算表の合計 ↔ 仕訳の総額、B/S の当期純利益 ↔ P/L の当期純利益、
  税区分別集計 ↔ 個々の仕訳の税額の合計）。実装が独立しているほど検出力が高い

### 限界の明示

- **「法令完全準拠」を謳わない。** 本プロジェクトの成果物には、対応範囲・確認日・
  未確認事項を明示する。専門家の確認を経ていないことも隠さない
- 製品として販売する段階では、**専門家のレビューを必ず入れる**。本 ADR は
  それまでの開発段階の運用を定めるものである

## 理由

- 「専門家がいないから精度を落とす」ではなく「**検証可能なものだけを根拠にする**」に置き換える。
  国税庁の設例は公表されており、条文から導ける値は機械的に確かめられる。
  実は専門家の頭の中にしかない知識は、その多くが「例外の存在を知っていること」であり、
  それはリサーチ（一次情報の網羅）で相当程度は代替できる
- **不変条件と差分テストは、専門家レビューより強い部分がある。** 人間のレビューは
  「この設例が合っている」ことしか確認できないが、性質テストは「あらゆる入力で成り立つ」ことを検査する
- 前回プロジェクトの実測（`BusinessApp_old/docs/qa/`）が示すとおり、実害を出したバグの多くは
  **会計知識の不足ではなく、実装上の静かな失敗**（型・書式・イベント発火）だった。
  そこは専門家レビューでは検出できず、機械検査でしか防げない

## 帰結

- テストプロジェクトに `Golden/` を設け、**設例 1 件 = ファイル 1 つ**（入力と期待値と出典）で管理する
- リサーチ結果（`docs/research/`）が期待値の根拠になるため、
  **出典 URL と確認日のない記述をリサーチ文書に書かない**（[00_ドキュメント規約](../00_ドキュメント規約.md) §4-9）
- 「この計算が正しいと言える根拠は何か」を説明できない実装を残さない。
  説明できないものは、リサーチが足りていない
