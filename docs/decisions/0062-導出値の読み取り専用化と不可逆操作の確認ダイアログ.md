# ADR-0062: 導出値は読み取り専用にする／不可逆操作には確認ダイアログを出す（規約）

- 日付: 2026-08-16
- 状態: 採用
- 関連: ADR-0027（ボタン色 2 色規約）／ADR-0049（検収の明細化）／ADR-0056（確定伝票の一部編集）

## 背景（問題）

ユーザーから 2 件の指摘があり、どちらも「1 画面の不具合」ではなく**横断の規約が無いこと**が原因だった。

### 1. 検収額を入れても消費税額が再計算されない

ADR-0049 で検収額・消費税額は明細から導出する値になったのに、
ヘッダの項目は `IsUpdateProtected: true`（＝**更新時のみ**保護）が付いているだけで、
**新規作成時は編集できた**。しかも `OnDataChanged` が無いので消費税は再計算されず、
明細に触らなければその手入力値がそのまま保存される。
つまり「反映されない」だけでなく、**明細合計と一致しない検収が作れる**状態だった。

`IsUpdateProtected` は「更新時の保護」であって「導出値である」という意味ではない、
という取り違えが原因。

### 2. 「確定」に確認ダイアログが無い

振替伝票の確定は下書きへ戻す導線を持たない（訂正は反対仕訳）のに、押した瞬間に走っていた。
一方で仕入先請求書の取消・削除にはダイアログがある。**画面ごとに扱いが違う**状態で、
利用者から見ると理不尽。棚卸ししたところ、`_OnClick` ハンドラ 49 本のうち
ダイアログありが 24 本、なしが 25 本で、線引きの根拠が無かった。

## 決定

### 規約 1: 導出値はレイアウトで読み取り専用にする

**他の項目から計算される値は、`IsUpdateProtected` ではなく
レイアウト要素の `IsViewOnly: true` で読み取り専用にする**（新規・更新の両方で編集不可になる）。
`IsUpdateProtected: true` はサーバ側の更新防止として併用してよいが、それだけでは足りない。

判断基準: **その項目を人が入力する業務が存在しないなら導出値**。
Placeholder に「〜から自動計算」と書いてあるのに入力できる、は矛盾なので直す。

適用: 検収の `Amount` / `TaxAmount`（今回）。
今後、明細から導く合計・残額・税額を画面に出すときは最初からこの形にする。

### 規約 2: 確認ダイアログは「不可逆」か「一括」のときだけ出す

次のどちらかに当てはまる操作にだけ確認ダイアログを出す:

- **(A) 取り消す導線が無い**（＝押したら戻せない）
- **(B) 1 回の操作で複数件のデータを作る／消す**（＝一括）

逆に、**同じ画面に取消・巻き戻しのボタンがある単票操作には出さない**。
押し直せるものにダイアログを出すと、利用者はダイアログを読まなくなり、
本当に危険な操作の確認が効かなくなる（ダイアログ疲れ）。

実装の作法:
- `MessageBox.Show(本文, "肯定ボタン", "キャンセル")` で、**肯定ボタンの文言は操作の動詞**にする
  （「OK」ではなく「確定する」「起票する」「取り込む」）。
- **`LoadingService.StartLoading()` はダイアログより後に開始する**
  （オーバーレイがダイアログを覆ってボタンが押せなくなる・実測）。
- 順序は「安いガード → ダイアログ → `using loading` → 本処理」。
- 本文には**何が起きるか**と**戻せないこと／件数**を書く。

#### 今回ダイアログを足したもの

| 操作 | 該当 |
|---|---|
| 振替伝票 確定 | (A) 下書きへ戻す導線が無い |
| 入出金起票 一括起票 | (B) 下書き N 件が一度に確定仕訳になる |
| 仕訳 CSV 取込 | (B) まとめて取り消す導線が無い |
| 銀行明細 取込を確定 | (B) 確定後は「取込をやめる」で戻せない |
| 定期請求の実行 / SES 一括生成 | (B) 生成予定 N 件が一度に請求書＋仕訳になる |
| 固定資産 償却仕訳の生成 | (A) この画面に取消が無い |
| 経費 仕訳生成 / 精算 | (A) この画面に取消が無い |
| 承認 / 却下 / 申請の取り下げ | (A) 取り消せない |

#### 出さないと決めたもの（理由つき）

| 操作 | 理由 |
|---|---|
| 請求書 発行 | 同じ画面に「発行を取り消す」がある（ADR-0033） |
| 入金 確定 | 同じ画面に「入金を取り消す」がある |
| 受注 完了にする | 同じ画面に「進行中に戻す」がある |
| 各種「下書きに戻す」「取消を戻す」 | 前の状態へ戻す方向の操作 |
| 銀行明細 ルールの再適用 | 推定の上書きだけで、いつでも押し直せる |

## 影響

- 検収の新規作成で検収額・消費税額を手入力する経路が無くなった（明細から導出のみ）。
  既に保存されている不整合データがあれば、明細を 1 度触れば再計算される。
- ダイアログを足した操作は 1 クリック増える。**増やす基準を上に固定した**ので、
  今後の新機能では実装時に判断できる（レビューで毎回議論しない）。
