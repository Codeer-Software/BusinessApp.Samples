# 0031: 販売伝票の部門必須化と経理限定編集（ADR-0029 の運用変更）

- 日付: 2026-07-25
- 状態: 採用・実装済み
- 起点: ユーザーレビュー第8弾（「経理以外は自分の部以外を選べないほうがいい」「部門は必須・空欄なしでいい」）
- 変更対象: ADR-0029 の「運用」節（任意入力・NULL=全社/共通）を置き換える

## 決定

見積・受注・請求書・定期請求契約の部門（`DepartmentRef`）について:

1. **必須入力にする**（`IsRequired: true`。空欄=NULL の状態は作らない）。
2. **経理（accounting）・sysadmin 以外は読取専用**。一般・承認者は作成時に自部門が自動セットされ、変更できない。
   部門の付け替え＝損益の付け替えなので経理業務とする。「全社共通」も経理のみ選択できる
   （非経理は自部門固定なのでそもそも選択の余地がない）。
3. **SES 精算の自動生成請求書は「全社共通」(code=00) を既定にする**（ADR-0029 では「部門ソースが無いため未設定」
   だった穴を閉じる。案件が部門を持たない設計は維持）。

## 実装

- JSON: 4伝票の `DepartmentRef` に `IsRequired: true`。**`EmptyCandidateType` は `Null` のまま残す**——
  検索フォームは同じフィールド定義を共有しており、`NotExist` にすると検索の「指定なし（全部門）」まで
  消えるリスクがあるため。編集側の空欄は「必須検証＋非経理は読取専用＋初期値=自部門」の3点で実質防止する
  （実測: `IsRequired: true` でも検索ドロップダウンの空選択肢は残る）。
- スクリプト: 各 `UpdateButtons`/`UpdateUi` の先頭で
  `if (!isAccounting) { DepartmentRef.IsViewOnly = true; }`（Quote / SalesOrder / Invoice / RecurringBilling）。
- 既存データ: 販売4テーブルの department_id は ADR-0029 のバックフィルで既に NULL ゼロ（追加移行なし）。
- 部門なしユーザーは admin（sysadmin）のみ＝経理相当で編集可能なためロックアウトは起きない。

## 影響・割り切り

- サーバ側の強制（UserWriteCondition 等）までは行わない——クライアントの IsViewOnly ベース
  （受注ロック・定期請求契約と同じ割り切り。ADR-0016 の既知の限界と同系統）。
- 組織変更耐性・スナップショット思想は ADR-0029 のまま。
