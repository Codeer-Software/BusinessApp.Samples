# ADR-0041 法令の略称と条項の記法を強制し、機械で拒む

## 状況

[80 §2](../80_参照法令一覧.md) は法令の略称を、[80 §3](../80_参照法令一覧.md) は条項の書き方
（条＝アラビア数字・項＝丸数字・号＝漢数字）を持っていた。**どちらも「こう書いてよい」という許可**で、
「これ以外を書かない」とは書いていなかった。

結果、同じ規定が何通りにも書かれた。実測で——同一ファイルの中に
`消税法 30 ⑧一` と `消税法30⑦` と `消費税法30⑨三` が並び、
`電帳規則 5 ⑤` と `電帳規則5条5項` と `電帳規則第5条第5項` が混在した。<!-- lint-docs:article-ok 記法そのものの説明 -->

**これは読みにくさの問題ではなく、機械が引けなくなる問題である。**
2027-01-01 に電帳規則の条番号が 5 ⑤ → 5 ④ へ動くので、その日に全文を洗う必要がある。
その手順は**表記ゆれで 2 回落ちた**（[qa/02](../qa/02_自己レビュー記録.md) の R22-02・R41-01）。

## 決定

**略称と記法を強制し、`lint_docs.py` が error で拒む**（開発者の指示。2026-09-06）。

1. **一覧で略称を定義した法令等は、常に略称で言及する。** 定義していない法令等は正式名称で言及する
2. **条項は 80 §3 の記法で書く。**「5 条 1 項」「第 5 条第 1 項」と書かない<!-- lint-docs:article-ok 記法そのものの説明 -->
3. **条番号だけを裸で置かない。** 直前に法令名か「同法」「同」を添える
4. **書いてよい 4 つ**（法令番号・正式名称の一部・逐語引用・記法そのものの説明）は
   [80 §3-1](../80_参照法令一覧.md) が持つ。1 つ目は検査が形で外し、残りは行末の印で外す

**機械で拒むのは 2 だけである。** 1 と 3 は人が守る。

## なぜ

**揃っていないと grep が効かない。** 施行日に一斉置換する運用を選んだ以上
（[電帳法リサーチ §0-1](../research/2026-08-23_電子帳簿保存法.md) が「併記しない」と決めている）、
**表記の揺れがそのまま取りこぼしになる。**

**許可のままでは腐り続ける。** 揺れは 4 回のレビューで見つかっており、そのたびに手で直してきた。
[30 §9](../30_作業のルール.md) の表は「機械の関門（成果物）」を最も強い置き場としている。

**逐語引用を書き換えない**（開発者の指示。2026-09-06）。国税庁の原文が「規則」「第5条第5項」と<!-- lint-docs:article-ok 記法そのものの説明 -->
書いている以上、揃えると逐語でなくなる。だから**強制と免除は必ず対で要る。**

## 帰結

- **`check_article_notation`** が `.md` とコードの両方を走査し、**走査行数と除外行数を毎回印字する**
  （0 に落ちたとき「違反が無い」ではなく「配線が死んだ」と読めるようにするため）
- **専用の印 `lint-docs:article-ok`** を使う。汎用の `lint-docs:ignore` は
  節への参照の検査まで黙らせる（実際に 3 行が黙った）。**ただし機械はこの 2 つを区別しない**——
  区別は人が守る
- **1 と 3 に機械の関門は無い。** 法令名の言及は普通名詞と見分けが付かず、
  錨を下ろす実装は**実測で 9 割が誤検出**になった（「この方法 3 条件」「命名規則 5 項目」）。
  **降りた理由をここに書いておく**（[30 §9](../30_作業のルール.md) の作法）
- 適用の実績と、捨てた設計は [qa/02](../qa/02_自己レビュー記録.md) のラウンド 41・42 が持つ
