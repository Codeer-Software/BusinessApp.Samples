# ADR-0050: 税額計算を明細の税区分ベースにする（税率ごと 1 回の端数処理）

- 日付: 2026-08-11
- 状態: 採用
- 関係: ADR-0003（消費税の持ち方）・ADR-0049（検収明細）・`docs/issues/2026-08-09_体験シナリオ執筆中に見つかった改善候補.md`

## 背景（不具合）

見積・請求書の明細は `tax_category_id`（税区分）を持ち、画面でも選べるのに、
**税額の計算に一切使われていなかった**。

```csharp
// Invoice.mod.cs（修正前）
decimal pct = GetSalesTaxRatePercent();   // 常に SALES_10 の税率
int tax = total * pct / 100;              // 明細合計に一律で掛ける
```

売上側で選べる税区分は 5 種類ある。

| 税区分 | 課税種別 | 税率 |
|---|---|---|
| 課税売上 10%（SALES_10） | taxable_sales | 10% |
| 課税売上 8%(軽減)（SALES_8） | taxable_sales | 8% |
| 非課税売上（SALES_EXEMPT） | exempt_sales | — |
| 免税売上(輸出等)（SALES_EXPORT） | export_exempt | — |
| 不課税（NON_TAXABLE）／対象外（OUT_OF_SCOPE） | non_taxable / out_of_scope | — |

したがって **8% の行・非課税の行・不課税の行が 1 行でも混ざると税額が狂う**。
請求書の `tax_amount` は売上仕訳の仮受消費税・売掛金・入金消込・消費税集計表まで波及するため、
帳簿全体が誤る。「市販の会計ソフト以上」を掲げる以上、看過できない。

IT 受託の実務でも、印紙の立替（不課税）や海外向け開発（免税）が 1 行混ざることはある。

## 決定

**税額は明細行の税区分から計算する。端数処理は「税率ごとに 1 回」とする。**

1. 明細を**税率でグループ化**し、グループごとに本体金額を合計する
2. グループごとに `税額 = Σ本体 × 税率 ÷ 100` を計算し、**そこで 1 回だけ切り捨てる**
3. グループの税額を合計したものが伝票の税額

課税種別が `taxable_sales` の行だけが対象。非課税・免税・不課税・対象外の行は税額 0
（本体金額には算入するが税は付かない）。

### 税区分は必須にする（2026-08-11 ユーザー指摘により追加）

当初は「未設定は従来どおり課税売上 10% とみなす」としたが、**そもそも未設定を許すべきではない**。
税額の根拠になる項目を空のまま通せば、どちらの既定を選んでも「入力漏れが黙って会計上の判断になる」
という状態が残るため。

- 見積明細・受注明細・請求明細の **税区分を必須（`IsRequired: true`）にする**
- 必須にするだけでは毎行選ぶ手間が増えるので、**明細を追加した時点で `課税売上 10%` を既定でセット**する
  （数量が 1 で補完されるのと同じ扱い）。非課税・免税・不課税の行は明示的に選び直す
- スクリプトが書き込む行（定期請求・SES の自動生成）は従来どおり税区分を明示的にセットしている

なお計算側には**未設定なら課税売上 10% とみなす保険**を残す。`IsRequired` は画面入力のガードであって、
スクリプトや外部からの書き込みまでは縛れないため、黙って過少計上にならないようにする。

適用前に実データを確認し、見積明細 15 行・受注明細 15 行・請求明細 20 行のいずれにも
**未設定が 1 行も無い**ことを確認済み（既存レコードが必須化で保存できなくなる事故は起きない）。

### なぜ「税率ごとに 1 回」なのか

インボイス制度（適格請求書等保存方式）では、**一の適格請求書につき、税率ごとに 1 回の端数処理**と定められている。
行ごとに切り捨ててから合計する方式は認められない。本アプリはこの規定に従う。

なお**仕訳側（`JournalEntry.RegenerateTaxLines`）は行単位で税行を作る**設計で、これは伝票 1 行が
1 つの取引を表すため別の話。伝票の税行は「その行の税額」であり、請求書の税額は「その請求書の税額」。
両者の端数がわずかにズレることはありうるが、請求書は取引先に出す書面、仕訳は自社の帳簿なので
それぞれの規則に従うのが正しい。

## 適用範囲

| 箇所 | 変更 |
|---|---|
| `Invoice.RecalcTotal()` | 明細の税区分ベースに（**DB に保存される税額**なので影響が最大） |
| `Invoice` の帳票出力（Excel/PDF） | 同上。税率ごとの内訳を出せるようにする |
| `Quote` の帳票出力 | 同上（見積は税額を DB に持たないため表示のみ） |
| `Acceptance` の税額自動セット | 検収明細の税区分ベースに（ADR-0049 と同時） |
| 定期請求・SES の生成 | 単一税区分（SALES_10）の 1 行明細なので実質不変。ただし同じヘルパを通す |

## 補足・限界

- 税率の期間解決（`tax_rates.valid_from/valid_to`）は行わず、税区分に紐づく税率をそのまま使う。
  現在の seed は STD10 / RED8 の 2 行で期間の重複が無いため実害がない。
  将来、税率改正で同一コードの期間違いを持つときは、伝票日付での解決が必要になる
- 税抜経理（ADR-0003）は不変。明細金額は税抜で保持する
