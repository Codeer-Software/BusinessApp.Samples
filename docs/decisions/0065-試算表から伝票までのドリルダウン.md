# ADR-0065: 試算表 → 総勘定元帳 → 振替伝票のドリルダウン

- 日付: 2026-08-16
- 状態: 採用
- 関連: `docs/14_市販ソフト比較レビュー.md` §2.3（この問題を見つけた比較レビュー）／
  `docs/issues/2026-08-16_市販ソフト比較レビューの改善候補.md` A-1

## 背景（問題）

**残高 → 明細 → 伝票を降りられなかった。**

- 合計残高試算表（`FinancialReports/TrialBalance`）の科目行をクリックしても何も起きない
- 総勘定元帳（`Accounting/GeneralLedger`）の「伝票No」列はただの数値で、振替伝票へ飛べない

これは経理が月次で必ず行う動作で、勘定奉行クラウドは
「**会計数字の根拠をクリックで確認できます**」を確認業務の看板機能として掲げている
（[機能一覧](https://www.obc.co.jp/bugyo-cloud/kanjo/function/list)）。
市販ソフトからの乗り換えで最初に不満が出る場所であり、逆にデモで最も効く改善でもある。

## 決定

**2 本のリンクを足す。**

| どこから | どこへ | 実装 |
|---|---|---|
| 試算表の科目行「元帳」 | 総勘定元帳（**科目と期間を引き継ぐ**） | AnchorTagField の `OnClick` で URL を組み立てて `NavigateTo` |
| 元帳の行「開く」 | 振替伝票の詳細 | AnchorTagField の `Module` + `IdVariable`（`JournalEntryList` の「開く」と同型） |

### 期間を引き継ぐこと（重要）

試算表は `date_from` が NULL だと繰越残高が 0 になる（`yr` CTE が空になるため）。
一方、元帳は期間未指定だと当年度の期首から拾う。**期間を渡さないと両者の残高がズレる**。

そこで `?drill_account={id}&drill_from={yyyy-MM-dd}&drill_to={yyyy-MM-dd}` を付け、
元帳の `Search_OnInitialization` が `NavigationService.GetUniqueQueryParameters()` で読んで検索条件に移す。
`?initialize_search=true` を併せて付けることでこのフックが発火する
（サイドバーのリンクに CLB が自動で付けるのと同じパラメータ）。

**実測（2026-08-16）**: 普通預金の残高が 試算表 7,321,020 = 元帳の最終残高 7,321,020 で一致。
外注費は 試算表 500,000 = 元帳 1 行 500,000 で一致。

## 実装上の発見（CLB の挙動・すべて実測）

この 3 つは他のクエリ一覧に行アクションを足すときに必ず効くので、ここに残す。

### 1. 読み取り専用のクエリモジュールでは ButtonField の OnClick が発火しない

`CanCreate/CanUpdate/CanDelete` がすべて false のクエリモジュール（試算表・元帳・仕訳帳など）では
**ButtonField がグレーアウトし、クリックしても `OnClick` が呼ばれない**。
最初 ButtonField で作って動かず、`Toaster` を仕込んで発火していないことを確認した。

→ **AnchorTagField の `OnClick` は発火する。**
しかも `Module` と `Url` を空にしておけば既定のナビゲーションが走らないので、
スクリプト側の `NavigateTo` がそのまま効く。
**クエリ一覧に行アクションを足すときはこの形を使う。**

### 2. ListLayouts の `OnAfterInitialization` は行ごとに発火し、その行のクエリ結果が読める

クエリモジュールでも行単位でフックが動き、`AccountIdRaw.Value` のような
その行のカラム値が読める（診断で 1 行ごとに別の値が出ることを確認）。

### 3. リスト内のアンカーは `IsVisible = false` では消えない

合計（貸借検算）行にリンクを出さないために `DrillButton.IsVisible = false` を試したが**効かなかった**。

→ SQL 側に `drill_label` 列（科目行は `'元帳'`・合計行は `''`）を足し、
アンカーの `TitleVariable` にバインドしてリンク文字ごと消した。
**このとき `TitleText` は空文字にすること。** `TitleVariable` の値が空だと `TitleText` にフォールバックし、
合計行にも「元帳」が出てしまう（実測）。

### 4. QueryField の `Parameters` に出力列を宣言しないと designcheck が落ちる

SQL に `SELECT` 列を足しただけでは
`カラム 'entry_id' が 'GeneralLedger' に存在しません` になる。
`QueryFieldDesign.QuerySetting.Parameters` に `IsParameter: false` のエントリを足すこと。

## 退けた案

| 案 | 退けた理由 |
|---|---|
| アンカーの `Module` + `IdVariable` で元帳へ飛ばす | `/Accounting/GeneralLedger/{id}` という詳細 URL になる。クエリモジュールに詳細は無く、科目も期間も渡せない |
| 右クリックのコンテキストメニュー（`ContextMenuField`） | 発見しづらい。経理が毎月使う導線を右クリックに隠すのは「驚き最小」に反する |
| 科目名セル自体をリンクにする | CLB では列に紐づくリンクを別フィールドとして置く必要があり、結局アンカー列と同じ。列が増えないぶん見た目は良いが、リンクだと分かる手がかりが減る |

## 残件

- **試算表に部門・案件の絞り込みが無い**（A-2）。元帳には既にあるので非対称。ドリルダウンで部門も引き継げるようになる
- **仕訳帳（JournalBook）にも同じ「開く」を足す**余地がある。今回は A-1 のスコープ（試算表→元帳→伝票）に絞った
